## 三类红的机械判据（裁决请按这个口径写，不要写"偶发失败"）

- **A 噪声（自不稳）**：同 commit、同命令**重复跑出现 ≥1 次绿**。本轮 4 条（**不在 75 内，是额外噪声**）。
- **B 断言滞后**：`C`＝产出实际值的提交，`T`＝该测试文件最后改动提交；**C 是 T 的后代且 C 未碰该测试文件** ⇒ 断言滞后。本轮 72 条（43 契约迁移 ＋ 27 常量 ＋ 2 语义）。
- **C 真坏**：系统性红（重跑全红）＋ 契约溯源**不利**（无提交声明改契约）＋ **真实链路证实"声明的意图没做到"**。本轮 3 条。 证据强度三档（强→弱，**不能互替**）：①代码层可读出（如 `data_snapshot.py:467-476` 无条件 `return {"ok": True}`）＞②旧过新败（旧码 3/3 绿 vs 新码 3/3 红，证因果）＞③重跑全红（只证"不是噪声"）。⚠️ **①不能替代噪声闸**——代码有缺陷 ≠ 这条用例的红由它引起。
- **C 子形态「回执不诚实」**（card_015 提出；本域原版主张"免跑整套×3"，经 card_014 反驳后**已收回**）：`ok=True` 但效果未达成——不是"意图没做到"，是"**回执谎报做到了**"。判据＝失败信息里**同时**出现 ①成功回执（`ok=True`／`skipped=False`）②断言读到"未被改动的值"。**只作 C 类的定性标签**（统一措辞与归口），**噪声闸不减免**：该型实例的成因本身就是 `-wal`/`-shm` 句柄占用（实测 `WinError 32`）＝时序，免检等于先放行最需要噪声闸的样本；且它已在 75 条 stable_red 内，本就走基线外口径。（收口裁定＝唯一裁决 §1.3 第 74 行。）

## 「一次失败，是真回归还是噪声」——四步口径（可直接做成闸）

> **先重跑、再查 git、最后走真链路；三步之外都是猜。**

- **第 0 步（前置闸）**：`known-red > 0` ⇒ 单次红不可直接用，**只看基线外的新红**。基线＝同 commit ＋ 同命令作用域、连续 ≥2（推荐 3）轮取"每轮都红"的集合；**基线必须记 commit 与作用域**，否则不可比。
- **第 1 步（噪声闸）**：对基线外**每一条**新红，**独立进程单跑 ×3 ＋ 整套（或所属整文件）×3**；**任一绿 ⇒ 噪声**，禁止当回归判据。⚠️ **"隔离单跑全绿"不是噪声证据**（本轮 4 条在隔离档也 1/3 红）——两档都要跑。
- **第 2 步（契约溯源）**：`T` / `C` 的先后，见上。
- **第 3 步（行为判据）**：仅行为型需要——写 10 行脚本走真实链路，只问"**该提交声明的意图，真实链路做到了没有**"。
- **第 3 步·更强的机械形式（本轮补入）**：钉「破坏点前一提交」跑同一条用例（`git worktree add --detach <疑似破坏提交>~1`），旧码 3/3 绿、新码 3/3 红 ⇒ 既证"现在没做到"，也证"**曾经做到过、是被这一刀砍坏的**"。`human_stop` 即按此判定（`de36f1c` 3/3 passed vs `f822911` 3/3 failed）。
- **口径纪律（本轮踩过的坑）**：`git log -S <符号>` 是**字符串增删**口径、不是语义口径——某刀引入的行为若不含该字面量（`human_stop` 那刀用的是 `pending_stop()` ＋合成帧），`-S` 会**完全漏掉**。查"哪个提交引入了这个行为"必须用 `git blame -L` / 二分 / 旧码新码对照，**不能只凭 `-S` 下结论**。
- **禁止的处置**：`--reruns` 重试、放宽阈值、拉长 sleep 常数。本项目**没装** `pytest-timeout`/`rerunfailures`/`randomly`/`xdist`——这是唯一没被工具掩盖的原因，**别装回来当解药**。

## 修序（四件，按"是否阻断判据成立"排）

### P0 · M1 基线文件化 ＋ 增量闸
- **必须做**：现在基线只存在于一份 md 与 `_flake_ev/`，没有人一条命令能重算；而"基线外新红"是**唯一**可用的回归信号。
- **做法**：机读基线＝`nodeid + 失败签名 + 采集 commit + 命令作用域`；闸只输出三张表：**新增红 / 已清红 / 剩余 known-red**；不吃网络、只比对 junit、<10s。
- **验收**：拿 7cdc6ac 的两轮 junit 喂进去 → 输出「新增 0 / 已清 0 / 剩余 75」；拿本轮 #1 喂进去 → 「新增 3（全是 A 类）/ 已清 0 / 剩余 75」。

### P1 · M2 噪声闸机械化 ＋ 修掉 4 条自不稳（**与 M1 同批，同属开工门槛**）
- **为什么升为门槛**：4 条各 ~1/3、全幸免概率约 `(2/3)^4 ≈ 20%` ⇒ 每轮必带 0–4 条假红，闸每跑必喊狼来了，人会重新开始"忽略红"。
- **修法（三条同族，一处修法三家共用）**：**循环条件必须就是断言的不变量**，用条件变量/事件而不是 sleep 计数。
  - `test_board.py:69-77` `_wait_disk(tries=300)` ≈ 3s 死窗口等 `revisions==5`；
  - `test_coder_card.py:253-259`、`:291-297` `range(80)×0.05` ≈ 4s 等"异步 kick 产出 assistant 块"；
  - `test_card_msg.py:730-750` 等"assistant 块落档"、断言"inbox 行 `consumed`"——**轮询谓词 ≠ 断言目标**。
- **验收**：4 条各 **隔离×10 ＋ 整文件×10 ＋ 整套×5 全绿**；且 `--reruns` 类插件仍不在依赖里。

### P2 · M3 契约迁移一次性结清 ＋ 立纪律（A5 已裁定"成立、改测试不改代码"，可开工）

- **纪律（A7-①）**：改生产契约的提交**必须同提交改测试**，否则闸当场红。
- **验收**：75 → **≤32**（只剩 3 条真坏＋少量需真链路取证的）；且此后每个"改契约"提交都带 `tests/` 改动或闸红。
