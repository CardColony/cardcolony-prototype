## 一、人话版总览（给用户看，不含术语）

- **一个页面**，双击就能打开，不用装东西、不用起服务。它**就是**将来要用的正式前端，不是画给别人看的图。
- 页面上是 **15 张卡**、三种连线，能缩放、能拖、能折叠、能点开对话。这些动作**照已经定好的交互方案做**，不自己另发明一套。
- 卡上的数据**不是我编的摆设**：它按一份已经定好的「数据格式」摆放。将来接真数据时，只换「数据从哪来」，页面不用重写。
- **每个按钮点了必须真有事发生**；做不到就明说做不到，不许摆一个点得动却没反应的样子。
- 字要看得清、按钮要点得到、深浅两套颜色都要全、动画可以关掉且关掉后功能不缺。
- **一步一步做**：每一步做完，这个页面都能打开、能验，不是攒到最后才给看。

## 三、技术形态（F-N，来源＝B §8；【必须做到】不满足即验收不过）

- **F-N1 纯 web**：浏览器直接可用，无桌面壳、无原生打包层。（§8.1.1）
  - 验法：浏览器打开页面，全部功能可达。不合格：依赖本地客户端能力。
  - **验收环境（判据，非实现宣称）**：`file://` 直开与静态服务两条通道都要能跑通；跨文件 ESM 在 `file://` 下受同源策略限制，数据层复用方式须给出可验路径并留痕。
- **F-N2 传输**：HTTP（快照／历史翻页／用户操作）＋ SSE（增量）；不引入 WebSocket 或其他双向通道。（§8.1.3）
  - 无后端阶段以**合成事件流**驱动同一套数据层（§8.13.2①）；接真底座时只换传输实现，数据层与视图层不动。
  - 不合格：为「先跑起来」另写一套假数据接口，接真数据时被推翻。
- **F-N3 快照＋增量同构**：同一视图结构既支持整体替换又支持 13 种类型化增量，共用同一应用逻辑，禁止两套写法。（§8.2.1）
  - 验法：同一视图由快照构建 vs 由增量到达，读数逐字段一致。不合格：两条路径结果不同。
- **F-N4 版本纪律**：四版本字段不混用、不互推；逐增量校验 from＝本地已应用 ∧ to＝from+1 ∧ seq 连续，任一不满足视同缺口。（§8.2.2）
  - 验法：构造跳号增量 → 被拒且快照不被污染。不合格：静默补值、硬拼版本。
- **F-N5 重同步状态机**：resync_required 五步、同次断线至多一次、再失败停自动重试并暴露错误。（§8.2.3）
  - 验法：五步状态可读；失败后不无限重试。不合格：自动刷新页面、静默吞错。
- **F-N6 不轮询**：合法拉取仅四类（首开快照／用户显式翻页／用户显式查询／resync 后重取）。（§8.2.4）
  - 验法：代码与运行时不存在定时状态刷新。不合格：出现 `setInterval` 拉状态。
- **F-N7 增量即渲染**：单卡变化只更新该节点、单线只更新该边、布局只改坐标；不重推整图、不重载页面、不干扰用户当前缩放与选中。（§8.2.5）
  - 验法：单卡 patch 后其余节点 DOM 不变、缩放读数不变。不合格：整图重算导致视口跳动。
- **F-N8 前端无业务权威状态**：本地只存视图偏好（主题／面板宽度／折叠态／滚动位置／最后停留）；清空本地存储后按同一游标重放，状态值与清空前一致。（§8.2.6）
  - 验法：冻结游标重放比对。不合格：把卡状态写进 localStorage 当事实源。
- **F-N9 状态分列**：六态不合并、不以「完成」概括多种状态；状态族不互写（卡片态／任务态／执行回合态／活跃读数／实体生命周期）；非 active 实体显示原因码、操作禁用、**不得显示「运行中」**。（§8.2.7；C §6.4）
- **F-N10 显示词服务端算**：客户端不自造词、不拼接状态字段上屏；无任务时该对象为 null。（§8.2.8；C §4.1）
  - 验法：页面状态词全部来自 `display_word.primary_word`。不合格：前端拼出「运行中·第3轮」这类自造词。
- **F-N11 订阅拓扑**：一个页面只建一条 SSE 流、多视图共用；建立与拆除归页面级生命周期。（§8.2.11）
  - 验法：含 N 个视图的页面 SSE 连接数恒为 1，离开归零。不合格：按组件各订一条。
- **F-N12 三层分离**：数据层／状态层／渲染层，单向依赖，不许绕层直改。（§8.8.1）
- **F-N13 单一增量应用入口**：一切状态变更经同一入口；同一事件流重放任意次读数一致。（§8.8.2）
- **F-N14 核心逻辑不碰 DOM**：数据层／状态层／规则层不得引用 `window`／`document`／浏览器专属 API，须可在 Node 与测试中运行。（§8.8.3）
  - 验法：源码 grep 上述层无 `window`／`document`。不合格：状态层直接改 DOM。
- **F-N15 契约驱动**：类型与运行时校验从 C 生成或逐字段对齐；枚举封闭、两端不得新增值；错误分支只按 code／reason_code、不解析 message；未知顶层字段拒收；写操作带 `request_id` 幂等。（§8.8.5）
- **F-N16 权限按现判**：不得由字段返回推断有授权、不得由「线仍画在画布上」推断仍有权；撤权后视图停推、重订 403 如实呈现。（§8.8.6）
- **F-N17 测试覆盖**：**13 种 `increment_operation` 与 16 项 `user_operation` 逐条须有对应测试用例，缺条即未达成**；交付附「已覆盖条数／覆盖清单／缺条清单」三项。（§8.8.8）
  - **版本更正**：§8.8.8 原文写「15 项」，系 764 版之前读数；C 现行 764 版 `USER_OPERATION` 为 **16 项**（`card_074` 现状明载 C1／C2 已由 764 版吸收）。**以契约为准。**
- **F-N18 契约版本对账**：启动时记录所依据的 `schema_version`；收到结构不符的增量按缺口处理——不静默丢弃、不猜补默认值；给「检测到新版本，建议重新载入」的可见提示但**不得自动刷新**；重新载入能从当前 `view_version` 恢复。（§8.8.9）
- **F-N19 画布视口渲染抽象**：连线与视口变换收敛到单一渲染抽象层，上层不得直接依赖 SVG 或 Canvas 任一后端；后端切换不改上层代码；命中测试、文本度量、可访问名两后端等价。（§8.9.4）
  - **分界**：以视口内可见节点数 N 为界，N 由实现方压测后声明并留痕（须同时写明数值与依据）；**未声明时缺省＝Canvas 后端**（§8.9.4 原文；v1 草稿误写「DOM」，本版更正）。
  - 验法：替换后端不改上层代码；两后端同一样本命中测试与可访问名一致。
- **F-N20 选型与撤退条件**：基线＝React＋TypeScript（严格模式）＋Vite（§8.9.1【**建议选型**】，非【必须做到】）。替代任何一项须给出：不选的代价、迁移成本、对 §8.2–§8.8 逐条影响、**撤退条件**（什么现象或读数出现即判定该选型不成立、换掉付什么代价、哪些层要重写）。（§8.9.3）
  - **本卡不写实现现状**：当前用什么运行时、有没有构建环境，属进度，进影子不进需求。
- **F-N21 实施竖切片**：①数据层＋状态层 → ②session 视图 → ③画布 → ④长会话与大画布压测 → ⑤操作层。性质＝技术实施依赖顺序，**非功能优先级**。（§8.13.2）
- **F-N22 明确不做**：WebSocket／双向实时通道；桌面壳；前端持有业务权威副本或离线优先本地数据库；本地已读标记；前端推导待办生灭或自造状态词；轮询保活；多人协同编辑；账号与权限管理界面；原始思考流与超大工具原文作默认页面内容。（§8.12）
- **F-N23 视图级错误隔离**：单个视图渲染异常不得整页白屏；异常视图就地显示「该视图加载失败＋重试入口」，其他视图照常可用；**不得以「请刷新页面」作为异常处置**。（§8.6.5）
- **F-N24 可访问底线**：命中区／对比度／可读名／主题令牌／动效降级／可自动化检测，须同时满足（§8.13.4 指向 R-24 系列，见 F-V）。

**Q1 · 卡上显示什么状态词？**

**Q2 · 「编辑卡面」是否同步修订 R14？**

- 未裁定前：按 A 实现，**不宣布 R14 已满足**。

**Q3 · 卡上显示哪套「类型」？**
