## 一、改造清单（四件，锚点给条件原文，不给行号）

### §1 工具结果信封

**意图**：模型与系统之间建立规范契约——结果有信封、成败读字段、错误可分类。

**机制**：
1. `card_tools.py` 新增公开辅助 `err(code: str, message: str) -> dict`，返回 `{"ok": False, "error": {"code": code, "message": message}}`；新增 `ok_(data) -> dict` 返回 `{"ok": True, "data": data, "error": None}`。
2. 错误码固定枚举（新增模块级常量 `TOOL_ERROR_CODES`）：`denied`（权限/越权拒绝）、`not_found`（目标不存在）、`locked`（423 锁超时）、`validation`（参数缺失/非法）、`internal`（其余一切）。
3. 既有 handler 内全部 `{"error": "..."}` 返回点机械替换为 `err(<对应码>, "...")`——**错误文案一字不动，只补 code**；分类映射：权限判定失败→denied；卡/影子/work 不存在→not_found；锁超时→locked；参数缺失/类型错→validation；未捕获异常→internal（execute_tool 的兜底 except 统一包 internal）。
4. `execute_tool` 出口统一信封：handler 成功返回统一过 `ok_(原返回dict)`。既有返回结构（含 card_id/title 等键的成功 dict）原样进 `data`。
5. `message_runner.py` 的成败判定锚点 `ok = "error" not in tool_result` 改为读信封 `ok = tool_result.get("ok") is True`。
6. **回灌模型的文本由信封投影**（`message_runner.py` append_tool_result 处与 tool_full_texts 累积处，同一投影函数 `render_tool_result(result) -> str`，定义放 card_tools.py）：
   - 成功：`json.dumps(result["data"], ensure_ascii=False)`
   - 失败：`"[tool_error code=<code>] <message>"`
   - 投影函数单一来源，两处调用点（slot 入槽、tool_full_texts）都走它，禁止各自拼装。

**判据**：
- `grep -n '"error" not in' src/` 零命中。
- `grep -n 'return {"error"' src/api/card_tools.py` 零命中（全部改 err()）。
- 新增契约测试 `tests/test_tool_envelope.py`（见 §5）：信封结构、五码全覆盖、投影文本两种形态钉死。

### §2 tool_call_id 唯一化

**意图**：遵守配对协议——id 在一份 messages 内全局唯一，消除 B-07 风险面。

**机制**：
1. `message_runner.py` 两处 `f"call_{i}"`（assistant 消息 tool_calls 构造处、tool 消息 tool_call_id 处）改为 run 级唯一：`call_{run_tag}_{state.rounds}_{i}`，其中 `run_tag = pair_id 短串`（取 pair_id 前 8 位，无 pair_id 时退 `state.work_id[:4]`）。同一 tc 的 assistant 侧与 tool 侧用同一 id（配对不变量不动）。
2. RunState 不加字段（rounds/i 现成，run_tag 在 build_context 或循环首次使用时由 pair_id 现算，局部变量即可——若需跨函数传递才考虑入 state，执行方如实报告取值）。

**判据**：
- `grep -n 'call_{i}"' src/` 零命中。
- 契约测试：两轮各 2 个工具调用，断言 4 个 id 互不相同且 assistant/tool 侧配对一致。

### §3 通道收敛（裁定项·已放行）

**意图**：一个动作一条正式通道——create_card 只走工具通道；文本协议块降 rescue 兼容层。

**机制**：
1. `card_proposal.py` / `message_runner.py` create_cards 段：文本通道解析**保留**（防旧习惯模型），但每次从文本通道成功建卡时计数，`prompt_log` 追加键 `text_channel_create_count`（无则 0 不写）。跨通道去重逻辑（exclude_titles）保留不动。

3. BASE_PROMPT 新增「工具错误码」小节（位置：工具使用说明末尾，文案下附 §6）。
4. `BASE_PROMPT_VERSION` `t13-1` → `t14-1`；`TOOL_TABLE_VERSION` **不动**（schemas 的 name/description/parameters 一字未改，工具面零变化）。

**判据**：

### §4 指引单源化（文本维护规矩，不动模型行为）

## 工具错误码

工具执行失败时，你会收到形如 `[tool_error code=<码>] <说明>` 的结果。

- internal：系统内部错误。不要重试同一调用，改用其他路径或如实说明。

3. **断言翻译规则（逐条 before/after 对照表进回传报告）**：
   - `"error" not in r` → `r["ok"] is True`；
   - `"越权" in r["error"]` 等 → `r["ok"] is False and "越权" in r["error"]["message"]`，**必须同时断 code**（按对应场景钉 denied / not_found / locked / validation 中实际那一个）；
   - `r["card_id"] == c` → `r["data"]["card_id"] == c`（**禁止**改写为 `r.get("card_id")` 之类弱化形式）；
   - `out.get("error","").startswith(...)` → `out["error"]["message"].startswith(...)`。
4. **断言力自检（强制）**：翻译后每条**负例必须仍红**——执行方须至少对一条 success 断言做反证验证（把 handler 强制返回失败，断言必须失败），并在报告中给出该验证输出。理由：信封恒有 `error` 键（成功为 None），若实现或翻译走偏成"成功时无 error 键"，`not in` 型断言会**恒真不红**，比显性红更坏。
5. **版本号裁定：沿现行族谱 → `BASE_PROMPT_VERSION` 升为 `tc-3`**（非 t14-1）；`TOOL_TABLE_VERSION` 保持 `tools-tc-2` 不动（工具 schemas 未变）。对应两条断言更新：`test_create_card_tool.py:50` 与 `test_t12_memory.py:343` 改钉 `tc-3`。
