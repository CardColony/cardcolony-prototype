## 2. 设计基准（照此施工，不走样）

1. **注册表单点定义**：每个工具一处注册——schema 字面量、handler、readonly 标志住在一起。schema 字面量从 `build_tool_schemas()` 现有 14 段**逐字搬运**（含段内 [T12-R3]/[建卡工具化] 等注释一并随段迁移，注释不重述不丢失）。
2. **handler 拆分**：现 if 链每个分支抽为独立函数（签名建议 `async def _h_<tool>(work_id, current_id, arguments, cards) -> dict`），函数体＝分支体原样搬运。`web_search`/`fetch_web`/file_tools 四件的 handler 在注册时经 `asyncio.to_thread` 包装（或在 handler 内保持现有 `await asyncio.to_thread(...)` 调用形态——二选一，但并发语义必须与现状一致：同步函数不得直接在事件循环里跑）。
3. **execute_tool 瘦身为查表**：保留 try/except 三层兜底（CardNotFoundError／ChapterNotFoundError／Exception→error，文案逐字不动），中间改为 `handler = TOOL_REGISTRY.get(tool_name)` 查表调用。
4. **file_tools 四件**：schema 仍由 `file_tools.build_file_tool_schemas()` 产出（不动 file_tools.py），注册表中这四条的 schema 字段在模块加载时调用该函数取件填入；handler 指向 `file_tools.list_files` 等原函数（经 to_thread 语义包装）。
5. **不改的文件**：`file_tools.py`、`tool_fold.py`、`prompts.py`、`search_tool.py`、全部 tests/——一行不动。
