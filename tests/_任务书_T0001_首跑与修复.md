### 6-3 【必挂死｜获准直接改】端到端替身网关不是"一次性"，会让工具循环无限转

`tests/test_offline_e2e.py::test_tool_loop_closes_with_tool_result`。替身当前是：

```python
tool_calls = list(self.tool_script) if (self.tool_script and tools) else []
```

即**每一轮**只要传了 `tools` 就返回同一批工具调用；而主链路 `src/api/routes.py::_run_message` 的工具循环**不设轮次封顶**（"模型停止调用工具即自然结束"）→ 模型永远在调工具 → **死循环**。这不是红，是挂起（若直接全量跑，pytest 不返回）。

**修法**（只动替身，测试断言一字不改）：

```python
    def __init__(self, tool_script=None, proposal=None):
        ...
        self._tool_issued = False          # 新增：脚本只发一次

    async def call(self, ...):
        ...
        tool_calls = []
        if self.tool_script and tools and not self._tool_issued:
            tool_calls = [self.tool_script[0]]
            self._tool_issued = True
        ...
```

`_content` 保持不变：第二轮 `tool_script` 仍在（非空）→ 末轮回复仍是 `"先读一下这张卡。"`，所以原有断言（`main_calls == 2`、`prior_len == 3`、`reply == "先读一下这张卡。"`、观点席 `tools == []`）**全部照旧成立**。

修完后必须把 §4 的 `--deselect` **去掉**，实跑证明不再挂（这条是验收项，不是可选项）。

### 6-4 【必红｜获准直接改】两条快照用例与"内容指纹去重"冲突

`src/storage/data_snapshot.py::snapshot_sync` 有既有行为：**内容指纹与上次相同 → 整个 work 跳过**，此时 `files = 0`、`skipped = True`，而 `dir` 字段仍按新 stamp 拼（指向一个**并未创建**的批次目录）。

而用例里"先有 `work` 夹具（`create_work` 内部已拍过一次快照并记指纹），再显式拍一次"→ 内容未变 → 被跳过。于是：

- `tests/test_snapshot_roundtrip.py::test_snapshot_batches_are_per_work`：`assert r["files"] > 0` **红**（实际 0）。
- `tests/test_snapshot_roundtrip.py::test_snapshot_restore_roundtrip`：`stamp = Path(r["dir"]).name` 指向未创建的批次 → `assert src.exists()` **红**。

**修法**（保持"往返一致"与"按 work 分批"的原意，只是先让快照必然真实执行）：

```python
async def test_snapshot_batches_are_per_work(work):
    wid = work["work_id"]
    # 指纹去重是既有行为：清指纹，确保本次快照真实执行（不是断言放宽）
    if data_snapshot._FINGERPRINT_FILE.exists():
        data_snapshot._FINGERPRINT_FILE.unlink()
    r = data_snapshot.snapshot_sync("batch-check")
    assert r["ok"] is True and r["files"] > 0 and r["skipped"] is False
    ...   # 其余断言不动
```

`test_snapshot_restore_roundtrip` 同样：在 `snapshot_sync("roundtrip-A")` 之前加同一段"清指纹"，并把该行断言补成
`assert r["ok"] is True and r["files"] > 0 and r["skipped"] is False`；`stamp = Path(r["dir"]).name` 与后续 `batch = SNAPSHOT_ROOT / wid / stamp` 的写法**保持不变**（它正是在钉住"`dir` 字段与真实批次路径不一致"这个既有事实）。

若清指纹后仍被跳过（说明 `_FINGERPRINT_FILE` 未被重定向，见 §6-5），先补 §6-5 再重跑。

### 6-5 【必改｜获准直接改】`conftest` 隔离漏网一处：指纹文件写到真实仓库

`src/storage/data_snapshot.py` 里：

```python
_FINGERPRINT_FILE = BASE_DIR / ".snapshot_fingerprints.json"
```

这是**模块级常量**，而 `tests/conftest.py` 的 `sandbox` 只改写了 `data_snapshot.BASE_DIR` 与 `SNAPSHOT_ROOT`，**没有改它** → 每个用快照的用例都会**读写真实例的** `D:\AI_station\推演agent\.snapshot_fingerprints.json`：

- 违反铁律一（"不碰真实数据目录"）；
- 会污染正式实例的指纹库 → 正式实例后续快照可能被误跳过（静默失效）。

**修法**（`tests/conftest.py`，紧跟快照根那两行之后）：

```python
    monkeypatch.setattr(data_snapshot, "BASE_DIR", base)
    monkeypatch.setattr(data_snapshot, "SNAPSHOT_ROOT", tmp_path / "snapshots")
    # [T-0001] 指纹文件是模块级常量，漏改会让用例写进真实仓库（铁律一）
    monkeypatch.setattr(
        data_snapshot, "_FINGERPRINT_FILE", base / ".snapshot_fingerprints.json"
    )
```
