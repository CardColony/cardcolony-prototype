## 1. 阶段一 · 金样本抓取（先证后拆，不过此关不动骨架）

**目的**：拆分前抓真实请求的完整响应当金样本——这是"编排行为不变"的唯一判据，pytest 绿数证不了编排等价。

**做法**：
1. 以 **MockGateway 离线模式**起服务（同 test_offline_e2e 的 mock 路径，保证确定性；若离线模式无法起真实 HTTP 服务，停手回报说明，不许改用真实模型——真实模型输出不确定，金样本失效）。
2. 设计 **3 条剧本化请求**，覆盖 `_run_message` 全部编排分支：
   - S1：纯文本回复（无工具调用，一轮交付）；
   - S2：工具循环（read_card → 工具结果回填 → 末轮交付，含 tool_events）；

3. 每条剧本抓**三件套**，落 `tests/_golden/`（新目录）：
   - `sN_sse.log`：SSE 事件流**完整原文**（事件类型序列＋payload 逐字）；
   - `sN_body.json`：最终响应 body 全字段（reply／tool_events／viewpoints／建卡结果等）；
   - `sN_side_effects.json`：落盘侧效应清单（涉及的卡文件路径＋内容 hash）。
4. 每条剧本**连跑 2 次**，确认三件套逐字节一致（确定性验证）；不一致则先查不确定源，解决不了停手回报。
5. 产出 `_t0009_golden_manifest.md`：三剧本×三件套的 hash 清单。
