### 3.1 card_store.py：新增 `_validate_write` 挂点函数

在 `_normalize_update_keys` 函数定义之后（约 L290 附近，T-0007 新增的 `cards_dir` 之前或之后均可，保持模块内函数布局整洁即可），新增：

```python
def _validate_write(
    work_id: str,
    card_id: Optional[str],
    op: str,
    payload: dict[str, Any],
) -> Optional[dict[str, Any]]:
    """写路径唯一门·统一写前校验挂点（T-0007-P1 立门）。

    create/update/delete_card 三个写函数在写盘前各调一次本挂点。
    本挂点是「写路径唯一门」的校验归口：后续所有写前校验
    （card_type 闸、版本校验、字段完整性等）一律挂在这里，
    不再散写进三个写函数体内。

    参数：
      work_id  —— 目标剧本
      card_id  —— 目标卡（create 时为 None，卡号尚未发放）
      op       —— 操作类型："create" / "update" / "delete"
      payload  —— 操作载荷（create: 含 title/source/card_type/parent；
                         update: 归一后的 updates；delete: 空 dict）

    返回：
      None        —— 校验通过，放行
      {"error":…} —— 校验拒绝，写函数原样返回该错误（不抛异常，与现有错误风格一致）

    [T-0007-P1 现状] 本挂点当前为空操作：不校验、不放行拦截，恒返回 None。
    现有校验（source/根卡保护/防环/类型降级）仍原位散落在三函数体内，
    本补丁不搬动它们（零行为变化）。T3 的 card_type 闸将挂在此处。
    """
    return None
```

**注意**：`Optional` 与 `Any` 模块顶部已 import（三写函数签名在用），无需新增 import。
