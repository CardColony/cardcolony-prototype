## 0. 一句话

一个**用卡片树组织工作、每张卡是一个能自主跑的智能节点**的 agent 系统：
人只对卡说话，卡自己拆活、建子卡、干活、向上汇报；系统负责三件事——
**把上下文喂对**（每张卡看到该看的）、**把权限卡死**（能做什么由树和类型机械决定）、
**把过程全留痕**（说过的、做过的、改过的都能三方对账）。

它跑在本机 `http://127.0.0.1:5700/`，单进程 FastAPI（`main.py:116`）。

---

## 1. 它要解决的问题

复杂项目的失败不在单轮模型能力，而在过程里**丢结论、复活错误、吞掉判断**。产品用四件事防：

| 机制 | 落地形态 | 锚点 |
|---|---|---|
| 结论跨卡流动、过程留在卡内 | 卡面三块是卡与卡之间**唯一接口**；卡内推理留在各自会话里 | `src/api/prompts.py:163`（系统结构段） |
| 权限机械决定 | 读侧放行、写侧限子树、建卡只能建自己的子卡 | `src/permissions/policy.py:1`、`src/storage/card_store.py:611` |
| 全量留痕 | 卡面入 SQLite＋会话文件＋事件 jsonl＋每次模型调用全文日志 | `src/storage/event_log.py:1`、`logs/prompt_*.json` |
| 机械兜底 | 工具调用以文本形态泄漏时由代码解析并真执行；各类异常在代码层接住 | `src/api/text_tool_rescue.py` |

## 2. 概念模型

### 2.1 卡：唯一的内容单位

一张卡＝一个 `cards` 表行（`src/storage/card_db.py:93`），卡面正文分**三块**：

| 块 | 字段 | 谁写 | 语义 |
|---|---|---|---|
| 使命 | `mission` | **只有用户** | 立项定稿，一句话目标；模型无写入口 |
| 现状 | `status_block` | 卡自己（`update_status`） | **只写已发生的事实**（做成了什么、在哪、卡在哪），不写打算 |
| 第三块 | `rulings` | 总裁（`append_ruling`）/ 用户 | 研发树与其余树当前都叫「需求文档」（`card_store.py:315` 骨架） |

三块的分工不是风格问题，是**验收链**：目标 → 需求文档（把目标翻译成可交付规格）→ 交付物，
链条断哪一环都不算做成（`src/api/prompts.py:179` `_SEC_ROLE`「做事的方法与顺序」五步）。

同一行还挂着：坐标（`pos_x/pos_y/pinned`）、权限快照（`perms/perms_version`）、
自动模式与目标（`auto_mode/goal/goal_state/goal_rounds/goal_await_children`）。

### 2.2 三种线

| 线 | 字段 | 干什么 |
|---|---|---|
| parent | `parent` | 父子＝任务树（谁拆给谁） |
| links | `links` | **通信线**：建了才能 `read_linked` 沿它读对方、才能 `send_card_message`；线双向通用 |
| relations | `relations` | **依赖关联线**：只记依赖/关联与说明，**不参与通信** |

卡间通信的边界是**通信线，不是父子树**（`policy.py` 的 `SCOPE_LINKED`：两卡间已有线即通过，
方向不限）。父子线只决定"谁能改谁、谁向谁汇报"。

### 2.3 卡的类型体系（L0 / L1 ＋ 四道写闸）

`config/card_type_registry.json` 是唯一词表来源，两层：

- **L0 `project_class`**（只挂根卡，同树子卡继承）＝工牌：`rd_project`（研发）／`research_project`（研究）
- **L1 `card_type`**（非根卡）＝本树词表里的类型：
  - 研发树：`sub_project`（子项目卡，可长树）／`tool`（工具卡，必须有 owner，不可长树）／`coder`（编程卡）／`rule`（规则卡）／`role`（角色卡，离树）／`function`（职能卡，离树）
  - 研究树：`topic`（课题卡，可长树）／`rule`／`role`／`function`
  - 根 scope：`project`（项目根卡，只由 `create_work` 产生）＋ `function`

写路径四道闸，顺序固定（`card_store._write_gate:611`）：
闸1 非法值拒绝 → 闸2 词表归属（子卡类型必须属于本树词表）→ 闸3 工具卡必须有 owner →
闸4 状态迁移（`active ↔ completed`，`state_machine` 段）。读路径对历史遗留值宽容。

### 2.4 影子卡

每张卡建卡时自动派生一张影子（`shadows` 表，`card_db.py:149`），四节固定：
**进度 / 待协作事项 / 产物清单 / 迭代历史**。它写**过程**（模型自己 `update_shadow`），
正卡写**事实与需求**，两者不得混（`prompts.py:238`）。产物路径指针落在影子的「产物清单」节。

### 2.5 离树的两种卡

| 类型 | 是什么 | 锚点 |
|---|---|---|
| `role` 角色卡 | 离树的观察者/顾问：不挂 parent、不可有子卡；工作卡用连线订阅它；它在回合收口时收到同步，自己判断**发言还是沉默** | `src/api/role_room.py:1` |
| `function` 职能卡 | **人类团队里真实存在的岗位**（不是任务卡）：不进画布、不进卡树统计，在 `cards` 表里有一行只为复用"权限/上下文/回合/建卡"这套基础设施 | `config/card_type_registry.json`、`src/api/function_room.py:1` |

### 2.6 goal（目标）

目标不是提示词，是**带版本的状态机**（`src/goal/`，从外部项目（dsh 一系）逐条移植）：
每次变更落一条 `goal/change` 会话事件（全量快照），DB 列只是投影；比较并交换（`GoalRef{id,revision}`），
过期 ref 一律拒；**activation 永不落盘**——进程重启/会话开始一律 disarmed，只有 `create`/`resume` 会 arm
（`src/goal/service.py:1`）。"停"的权威在模型：完成/暂停/卡住都必须显式 `update_goal` 声明。

## 3. 一轮对话怎么跑

### 3.1 六段链

人发一条消息 → `POST /api/works/{w}/cards/{c}/messages`（`routes.py:1645`）→ `_run_message`（2543）
→ `_run_message_inner`（2736），六段：

| 段 | 做什么 | 锚点 |
|---|---|---|
| ① | 读卡、`pair_id` 去重、落用户条 | `routes.py:2748` |
| ② | 上下文组装（21 区）＋工具列（按 perms 过滤）＋轮槽 | `routes.py:2870` |
| ③ | **工具循环**：单步推进（每轮一个显式状态点） | `routes.py:2878`、`message_runner.step:683` |
| ④ | prompt 日志（无论成败都写） | `routes.py:2891` |
| ⑤ | 交付拼接（分析在前、回执在后） | `routes.py:2897` |
| ⑥ | 建卡：工具通道＋文本通道并存，跨通道去重 | `routes.py:2901` |

### 3.2 step 循环（编排内核）

`RunState` 只装数据不做决策（`message_runner.py:76`），`step()` 推进一次状态，四种出口：
`continue`（继续轮）／`seats`（进三席，当前关）／`deliver`（可交付）／`error`。

每轮顺序：**中止缝** `check_control` → （coder 卡可被委派给外部执行体）→ 插话入槽 `_apply_steer`
→ 判断协议注入 → 现状任务注入 → 消息注入 → 模型调用（`_call_model_resumable`，断连同位置重发）
→ 解析工具调用 → 执行 → 落事件。**轮次上限：无**（拆闸铁律：不设轮次/墙钟/token 闸）。

### 3.3 事件序（前端能看到的）

```
run_start → context → round_start → (tool_call → tool_result)*
          → [收口后 seats_enter → seat_*]  ← 当前关闭
          → deliver → proposal → done
```

三路 SSE：单卡事件流（`/cards/{c}/stream`）、整 work 事件流（`/events`）、token 流（`/tokens`）。

### 3.4 收口

`finish()` 落 assistant 条、关轮、发 `done`，然后 `routes._run_message` 在 **finally 里、互斥体释放之后**
调 `auto_driver.notify_idle` —— 这是自动续轮的唯一接线点（`src/api/auto_driver.py:1`）。

## 4. 数据与留痕

### 4.1 库（唯一真相）

`works/<work_id>/cards.db`（SQLite，每 work 一库）。主表与用途：

| 表 | 内容 |
|---|---|
| `cards` | 卡本体（卡面三块＋meta＋坐标＋权限快照＋goal） |
| `shadows` | 影子四节 |
| `card_history` / `card_revisions` | 修改历史 / 版本快照 |
| `session_blocks` | 会话块（V2 结构化） |
| `events` | 卡级事件（与 jsonl 双写） |
| `work_events` | **全 work 事件汇总**（跨卡一次 SQL 可查，`src/infra/event_hub.py`） |
| `inbox` / `messages` | 卡间消息：待处理队列 / 消息账本（移出不删行） |
| `memory` / `memory_archive` | 凝练记忆条目与归档 |
| `role_*`（6 张） | 角色卡的职责书/判断簿/警报簿/同步队列/指令簿 |
| `function_*`（5 张） | 职能卡的职责书/观点簿/警报簿/同步队列/判断簿 |
| `trash` | 软删回收站 |

### 4.2 会话文件

`works/<work_id>/sessions/session_<card_id>.md`，V2 格式（`src/storage/session_facade.py:1`）：
`---SESSION---` 头 ＋ `---MSG---` 块（九字段：seq/actor/from/turn/pair/model/behavior/end/ts）。
`actor` 可为 `human` / `assistant` / `card:card_NNN` —— 卡间消息以 `card:` 落块，
**不冒充用户说的话**（前端据此渲染消息块而不是用户气泡）。轮界＝`turn` 相同的连续块，
轮末块 `end` 闭合（`model_done/policy_stop/human_stop/error`）。

### 4.3 事件

每卡一条 append-only jsonl：`works/<w>/events/<card_id>.jsonl`，七键定死
`{seq,card_id,run_id,round,type,data,model}`（`src/storage/event_log.py:1`）。
事件类型**统一登记**在 `config/event_catalog.json`（当前 66 类），未登记类型 fail-loud。
revoke 也是追加一条标记（软删，不物理删字节）。

### 4.4 日志与备份

- `logs/prompt_*.json`：每次模型调用的 system/user/response/tool_events/error 全文
- `logs/server.log`：服务端日志落盘（此前只在控制台 ⇒ 排障靠猜，`main.py:26`）
- `_backups/<原路径>/<时间戳>/`：文件工具覆盖写前的原文备份

## 5. 治理层：总裁制与五职能

### 5.1 组织（`prompts.py:357` `_SEC_ORG_TEXT`）

- **总裁**＝项目根卡（兼职能卡）：对用户唯一的汇报口、全局决策收口点、需求文档（引导块）的执笔人
- **职能卡**＝产品经理 / 技术总监 / 测试验收总监 / 涌现守门：**只在阶段任务的头尾介入**
  （头＝需求首次填完、总裁调 `stage_open`；尾＝子卡最终汇报 `report_up kind=done`），中间零介入
- **阶段任务＝新建子卡**：一件阶段性的活建一张子卡，需求与验收判据写清；自己卡是管理者视角

目录唯一事实源＝`config/function_catalog.json`（5 条：`ceo/pm/cto/qa/emergence_keeper`），
每条含 charter（职责书）、jurisdiction（管辖域）、watch（盯哪些卡）、speak_contract（何时开口/沉默）、
toolface（工具面 allow/deny）、perms、face_blocks、ledgers。播种在 `function_room.seed_work`。

### 5.2 唯一向上通道：report_up

`report_up(kind=done|phase|blocked|ask)`。系统按**连线**算收件人（父卡＋相关职能＋总裁），
**模型不能选也不必选**。它的投递不经用户通道：直接 `deliver_now(text=...)` 起父卡一轮，
不落 user 块、不进 inbox（`tests/test_report_up_contract.py` 钉三条）。

### 5.3 系统消息（2026-10-26 新建的基础设施）

三层，各管一件事：

| 层 | 文件 | 职责 |
|---|---|---|
| 登记＋汇总 | `src/infra/event_hub.py` | 所有事件按 `(work,card,seq)` 落 `work_events`；四个 store 的状态变更也收 |
| 规则 | `src/infra/harness_rules.py` | 读 `config/harness_rules.json`，**每次现读**（改文件即生效）；坏条目只标 invalid |
| 投递 | `src/infra/harness.py` | 规则命中 → 解析目标（self/parent/ancestors/links/card:x）→ 渲染模板 → 防重 → 投递 |

设计口径（用户裁定）：**不自造第二套体系**——落信走 `append_inbox`、消息块走 `emit_message_event`、
唤醒走 `deliver_now`，与卡间通信同一条路，消息天然挂在两卡连线上、可被 `read_inbox` 与事件流追溯。
判据**只用状态、不用墙钟**；「难以判断的情景不写规则」＝不机械兜底。

当前只有一条规则启用：`turn_end_without_report`（done 事件 ＋ 本轮无 `report_up` 成功 ＋ 本卡曾被父卡
`msg_directive` 派过活 ⇒ 提醒本卡去汇报）。第二条（建子卡未写使命）留作示例、`enabled=false`。

### 5.4 消息类型（`config/message_type_registry.json` v4）

7 类：`msg_ask`（询问，须作答、自动回发）／`msg_answer`（应答）／`msg_notify`（通知）／
`coder_done`（编程卡完工回报，系统发）／`msg_directive`（角色下指令，须执行或说明）／
`msg_sync`（横向同步事实）／`msg_report`（向上汇报，**系统判「是否已汇报」只认这条**）。
加类型＝加条目零代码。

## 6. 自动模式

三层咬合：

1. **目标**（`src/goal/`）：`create/edit/pause/resume` 需直接人类回合；`complete/blocked` 自动轮也允许；
   `blocked` 须同一阻塞条件连续 ≥3 轮（`_SEC_AUTO`）
2. **续轮驱动**（`src/api/auto_driver.py`）：`auto_mode=1` ＋ `goal_state=active` ＋ 有 goal ＋
   **无未终止子卡** ⇒ 起下一轮。父卡让位规则：子卡目标未终止则父卡不起轮（防空转烧额度）。
   **不设任何上限**
3. **点火调度**（`src/api/scheduler.py`）：建卡不再立即起跑，入队按容量点火
   （容量＝`models.yaml` 的 `concurrency.default`，缺省 3）；同卡在队列里只排一次

另有 `src/api/serial_gate.py`：串行模式（同 work 同时只一卡在跑，其余 await）；
当前 `config/exec_mode.json` ＝ `parallel`（不启用）。

自动模式的子卡**继承父卡 auto_mode**（`card_store.py:964`）——根卡一开，整树新建卡都自动跑。

## 7. 编程卡与外部执行体

`card_type=coder` 的卡可以把回合**委派**给 WorkBuddy 执行体干活（`src/api/wb_exec/`）：

- 钩子在 `message_runner.step()` 顶部：`maybe_delegate(state)`，**不命中返回 None，原路径逐字不变**
- 后端三态：`system`（自己跑）/ `auto` / `wb-*`（委派）；`config/wb_exec_switch.json` 当前 `enabled: true`
- 委派完结果回灌卡面，完工走现成的 `report_done`（系统自动发回执给 owner 主卡并调起验收）
- 内部有配比器（平滑加权轮询）＋fallback 链、ACP JSON-RPC 客户端、三种"死法"分开判的 watchdog

## 8. 模型面

`config/models.yaml` 是唯一真源，三层：**providers（供应商）→ models（模型）→ bindings（角色→模型）**。
全项目只经 `src/api/model_config.py` 读它。

- 席位绑定：`default` / 步类型（思维链用，当前关）/ 三席 / `condense`
- 并发：`concurrency.default` ＋ `concurrency.per_model`（信号量语义是**排队不是拒绝**）
- **层内兜底已取消**（2026-10-26 用户令）：`layer_fallbacks()` 恒返回 `[]` ⇒ 网页选哪个模型就只跑哪个，
  失败只抛该站的错；同模型内部仍有 3 次重试（那是重试不是换模型）
- 协议适配：`llm_openai_compat` / `llm_anthropic` / `llm_deepseek`；鉴权三态
  （`api_key_env` / `auth: none` 免鉴权 / `auth: broker` 动态租约）

## 9. 权限与上下文

### 9.1 权限（`config/permissions.json` ＋ `src/permissions/policy.py`）

两级定位：`project_class`（工牌，根卡承载、同树继承）→ `card_type` → 开关列表（17 个开关）。
**建卡时算一次写进卡的 `perms`**，运行时只读卡上的快照，不读配置文件；改配置＝version+1 ＋
跑 `scripts/refresh_perms.py`。默认关门（没配到＝空列表＝全拒）。

每个开关同时决定两件事：这件工具**看不看得见**（工具面）＋这次调用**允不允许**（执行关口）。
树类开关（edit/delete/link/unlink/create_child）追加「操作者是否在目标上游」判定。

### 9.2 上下文（`config/context_regions.json`，21 区）

按 order 装配，逐区可全局启停：使用说明(0) → 规则(85) → 卡职责(90) → 团队职能说明(91) →
卡能力(92) → 职能名册(93) → 类型思维(95) → 卡清单(100) → **职能自述(145)** → **当前卡(150)** →
目标(152) → 区域说明(155) → 子卡状态(170) → 记忆(200) → 依赖关联(250) → 对话历史(300) →
工具轮(900) → 用户消息(999)。

两条刻意的设计：卡清单只取 `id/title/parent`（正文一律经 `read_card` 拉，防"上轮写的卡面变成下轮常设输入"）；
145/93 区让职能卡知道"我是谁、我盯谁"。

### 9.3 工具面

`TOOL_REGISTRY` 单点注册表（`src/api/card_tools.py:2862`）：字面量 35 件 ＋ 后置追加 31 件 ＋
文件四件（`_register_file_tools`）＝ **70 件在用**；思维链七件因 `ENABLED=False` **不注册**。

按用途分族：卡（读/建/改/删/重挂父/唤醒）· 沿线与消息（link/unlink/read_linked/send_card_message/read_inbox）·
汇报与治理（report_up/scene_report/sync/direct/review_request/submit_review/record_verdict/raise_alarm…）·

## 附：一句话把整机串起来

人建一张根卡（总裁）→ 根卡写需求文档、按阶段建子卡（子卡继承自动模式）→ 每张卡在自己回合里
被喂 21 区上下文、拿到按权限裁剪过的 70 件工具 → 干活、写现状、留事件 →
收口时 `report_up` 沿连线把结果交给父卡与职能 → 职能在头尾表态、总裁收口、向用户汇报 →
全程落卡面/SQLite/会话/事件/日志，任何一句"已完成"都能三方对账。
系统消息层只在"该提醒却没人提醒"的少数情景沿连线补一条提醒——**消息本身也是这张智能网里的一个节点**。
