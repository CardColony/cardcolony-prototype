│    ⑤ card_tools.build_tool_schemas()（工具列，op 回合追加专用工具）

├─【段③ 工具循环】routes.py while True → message_runner.py: step()  (L494)

│    ① check_control()（中止缝：入口/出口两挂点）——control.check() 消费 stop 置位

## 二、上下文六区（REGION_TABLE，context_regions.py L91）

区 = {order, name, channel, seats, source, delivery, profiles, render}；装配只按 order 收区拼接，
**不评价、不裁剪、不截断**；「没有来源就不出现这个区」（空 payload 不进 join，user 位除外）。

| order | key | 名 | channel/delivery | 来源 |
|---|---|---|---|---|
| 0 | instruction | 使用说明 | system | prompts.BASE_PROMPT 常量（逐字指针，不复制） |
| 85 | rule | 规则注入 | system | 规则卡正文按 `## ` 切区，取当前卡 card_type 对应区 |
| 90 | card_duty | 卡片职责 | system | card_store.load_type_registry（类型级，每类一行） |
| 95 | type_thinking | 卡片思维 | system | config/type_texts.json 的 thinking[本卡 card_type] |
| 100 | card_list | 卡片清单 | system | 全库卡索引（id·title·parent） |
| 150 | current_card | 当前卡 | system | 当前卡 id·标题（正文不推送，经 read_card 拉取） |
| 155 | region_guide | 卡片区域说明 | system | 静态文案，按树×卡种择套（正卡三块＋影子四节） |
| 170 | child_status | 直接子卡现状 | system | 直接子卡 status_block（SQL 不递归） |
| 200 | memory | 记忆（condense_fold） | system | memory_store 凝练归拢 entries（仅 main） |
| 250 | relations | 依赖关联 | system | 双向依赖关联线（正向＋反向，profiles=main only） |
| 300 | history | 对话历史 | messages/prior | session_facade.read → 统一投影 |
| 900 | tool_turn | 本轮工具轮 | messages/prior | ToolTurnSlot.wire_messages（与 history 互斥让位） |
| 999 | user_message | 用户消息 | user | 用户原文（出口 user 位，排最后） |

join 规则（compose_model_context，L499）：
- **system(main)** ＝ 使用说明（BASE_PROMPT 指针）＋ 上述内容区（neutral）
- **system(viewpoint)** ＝ 卡片清单＋当前卡（职责分离：三席零指令）
- **messages** ＝ 对话历史＋本轮工具轮（prior 槽两区互斥：prior_key=tool_turn 时 history 让位）
- 请求契约顺序：system → prior → user → turn_once → turn_tail
- 控制面：config/context_regions.json 可逐区启停/改 order（fail-open，读不到用注册表默认）

## 三、SSE 事件序（event_stream，前端实时反馈）

```
run_start → context → round_start → (tool_call → tool_result)* →
(收口后) seats_enter → seat_* → deliver → proposal → done
```
另有：judgment（首轮机械推断 plan/direct）、rescue（文本泄漏抢救）、plan_created、
step_start、step_advanced、context_preamble、context_injection、judgment_protocol、
status_update_task、context_seat_identity、error。
进度查询：GET /api/works/{work_id}/cards/{card_id}/progress（纯展示层，只读内存态，不是闸）。

## 四、关键机制速记

1. **六段链**（routes.py 模块头注释）：读卡 → 取历史 → 追加用户消息 → context_assembler
   组装 → prompts.build_system_prompt → 带工具的工具循环 → parse_proposals →
   apply_proposals → 写 prompt 日志 → 追加 assistant 消息 → 返回。T-0009 拆分后
   _run_message_inner 只做三件事：① 装配 → ② 循环步进（step/state）→ ③ 落盘与返回；
   编排语义逐字不变（判据＝tests/_golden/ 三剧本金样本逐字节回放）。
2. **RunState**（message_runner.py L73）：显式状态对象，只装数据不做决策；字段与原
   局部变量一一对应便于对账。StepOutcome 四值：continue / seats / deliver / error。
3. **中止缝 check_control**（L208）：step 边界入口/出口两挂点；串行两问——工具卡驱动
   （on_step_boundary 只读指针）＋控制面 stop 置位（consume-once）；共存禁令：
   「看到了进度」≠「按进度判停」。
4. **无闸工具循环**：不设轮次封顶（[无闸改造 2026-10-02]），模型停即收。
5. **三席触发条件**：仅提交轮（board 全部 done 后、交付前）；直答回合零三席。
6. **T14 拼接**：分析在前、回执在后；落位在日志写之后、parse_proposals 之前。
7. **落盘时机**：用户条在装配前；assistant 条在全部交付段之后；prompt 日志无论成败都写。
8. **会话原子落盘**（[工具结果落会话 2026-10-17]）：工具轮块 A（assistant+tool_calls）
   与块 B×N（tool 结果）内存收齐后一次性 append_many，杜绝「A 已落、B 未落」中间态。
9. **pair_id 配对协议**：用户条与回复条逐字相同 pair_id；tool_call_id ＝
   `call_{pair_id 前 8 位}_{rounds}_{i}`，assistant 侧与 tool 侧同值。
10. **卡间调起**：A 回合收口时对 pending 目标异步起 B 回合（激励文 append_user=False
    不落档）；快速通道（create_task）＋持久保证（收件箱）两层分工——丢任务不丢信。
11. **自动回发**（迭代五 S4）：B 的调起回合成功结束后，流程按注册表自动回发应答
    （reply_expected_of/reply_type_of），模型全程不碰发信工具；被停/出错/被顶回合不回发。
12. **错误收口**：checkpoint 落 data_snapshot 定格现状，下条消息从现状续走而非全链重跑。
