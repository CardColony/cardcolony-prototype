## 一、项目定位（一句话）

**推演agent 是一个处理复杂项目的通用型 agent 系统**：把复杂的事拆成一张张卡片，沿卡片树逐层推进，多模型协作收敛成结论，每一步留痕、可对账、可翻案。系统本身不绑定任何领域——处理什么项目取决于搭什么卡片树、给什么任务。【README】

要解决的痛点：复杂项目的失败不在单轮能力，而在过程中丢掉的结论、复活的错误、被吞掉的判断。四条防错机制【README】：
1. 结论是卡片间唯一接口（卡内推理留各自对话，只有沉淀结论跨卡流动）
2. 权限由卡片树机械决定（读侧全盘可读，写侧限自己子树，建卡只能建自己的子卡）
3. 全量留痕可对账（logs/ 每次模型调用全文、卡片改动入 git、tool_events）
4. 机械兜底接住模型缺陷（工具调用文本泄漏五种形态、日志/解析异常在代码层接住）

## 三、启动方式【README】

```bat
start.bat          :: 启动服务（后端 5700）
stop.bat           :: 停止服务
```

**重启只走 `restart_safe.py`**（唯一许可的重启方式）：先判定「有无调用在跑」（progress 活跃态＋连接信号复核），有则拒载，绝不杀正在执行的调用。
```bat
python restart_safe.py --check   :: 只判定，不重启
python restart_safe.py           :: 判定通过后重启
```
访问：**http://127.0.0.1:5700/**

## 七、边界与已知限制【README】

- **慢**：一轮复杂任务 1–8 分钟，适合「把事想透」，不适合「快点干完」。
- **输出质量＝模型的分析质量**：卡片、权限、留痕只保证错误不扩散、可回溯，不保证推理本身正确。
- **文件能力不设删除**：模型没有删文件工具；不需要的文件由人或系统外清理。
- **模型自述不是状态依据**：任何「已完成 X」的声称，以 logs/、磁盘、git 三方对账为准。
