## 一、卡片＝系统的数据单位（cards.db 是唯一真相）

每 work 一个库 `works/<work_id>/cards.db`（WAL＋每库一条长活连接＋可重入线程锁＋`BEGIN IMMEDIATE`）。
**盘上有 `cards/*.md` 却没有 `cards.db` ⇒ 抛 `CardsNotMigratedError`**，绝不静默建空库/返空。

### 1.1 cards 表（一张卡一行，各区域各占独立列）

| 组 | 列 | 说明 |
|---|---|---|
| 身份 | card_id / work_id / title / source / parent | parent 构成卡片树 |
| 分类 | card_type / project_class / owner_card_id | project_class **只在根卡**；owner 仅工具卡必填 |
| 状态 | state | active → completed（completed 终态、正文不可再编辑） |
| 线 | links / relations | **两种线**：links＝通信线（read_linked / 发信沿它寻址）；relations＝依赖关联线（不参与通信） |
| 正文三块 | mission / status_block / rulings | 使命／现状／第三块（名按树：rd_project→「需求文档」，其余→「定论」） |
| 工具卡 | toolcard_script / toolcard_step / toolcard_round / toolcard_final | 工具卡运行时在卡面上的重建依据 |
| 思维链 | thinkchain_final | 板子收口结果 |
| 权限 | perms（JSON 列表）/ perms_version | **建卡时算一次写死，运行时只读卡上这份** |
| 画布 | pos_x / pos_y / pinned | 位置是卡片自身属性（layout.json 已退役） |
| 自动模式 | auto_mode / goal / goal_state / goal_rounds | 2026-10-17 新增四列（active/paused/blocked/complete） |
| 时间 | created_at / updated_at | |
| 留痕 | card_history(card_id, seq, ts, text) | 逐行修改历史 |
| 影子 | shadows(owner_card_id, progress, coordination, artifacts, iterations) | 影子四节各占一列，**本卡私有** |
| 其它 | meta(key,value) | rev、编号序列；inbox(msg_id…status) | 卡间消息待处理队列，pending→consumed（置位不删行） |

### 1.2 正文三块的产品语义（模型被告知的原文口径）

- **使命（mission）**：≤5 行说清要做成什么；立项定稿，**只有用户能改，模型没有写通道**。
- **现状（status_block）**：别的卡读这张卡先读的就是它——当前确定状态／接口与约定／依赖与影响范围；
  整块覆盖只留最新一份，不写过程与流水账。→ **这是「结论是卡片间唯一接口」的物理落点**。
- **第三块（rulings / 需求文档）**：按树择名。研发树＝需求文档（确定版需求＋验收标准）；
  研究树＝定论（只追加不改、失效标「被 Dxx 取代」）。
- **影子四节**：产物清单（路径＋用途指针）／待协作事项／迭代历史（系统记）／进度（不必维护）。

### 1.3 卡类型注册表（config/card_type_registry.json）

- **L0 project_class**：`rd_project`（研发）／`research_project`（研究），只挂根卡。
- **L1 card_type**：研发树＝sub_project／tool／coder／rule；研究树＝topic／rule；root scope＝project。
- **四道写闸**（顺序固定，落点 `card_store._write_gate`）：
  ① 非法值 → 报错不写库（原「静默降级为线索」已废）；② 子卡类型必须属本树词表；
  ③ `tool` 必须带 owner 且 owner 是 sub_project 或 project；④ 状态迁移必须在 allowed_transitions 内。
- legacy 六型（剧本/线索/世界观/行为体/节点/假设）**写路径拦截、读路径宽容**。

## 二、权限：类型分权 × 树作用域（两级、机械判定）

1. **算一次**：建卡时按 `config/permissions.json` 的 `[project_class][card_type]` 取开关列表，
   写进卡的 `perms` 并记 `perms_version`。配置里没配到的组合＝空列表＝**全拒（默认关门）**。
2. **运行时只读卡上 perms**（`policy.has_perm`），不查配置文件——改配置须 version+1 并跑
   `scripts/refresh_perms.py` 刷新。
3. **统一关口** `policy.check(actor, target, switch, cards)`：先查**目标卡**是否有该开关；
   若属树类开关（TREE_SWITCHES）再叠 `_is_in_subtree`（沿 target 的 parent 链上溯找 actor，
   自指直真，visited 防环，悬空 parent 断链）。两级失败文案各自独立，便于模型分辨。
4. **工具面与执行层同源**（`TOOL_SWITCH` 映射表）：没这个开关 ⇒ 模型**看不见**对应工具 ∧ 调了必拒。
5. 关键分布：根卡无 delete；`tool` 无 create_child／tools_file／tools_web／manuscript／invoke_tool；
   `coder` 只有 9 码（不长树、留档不可删、回执由系统发）；`rule` 仅 read。

## 三、工具面：单点注册表 + 四段过滤 + 两段追加

- 每件工具**一处注册**（schema 字面量＋handler＋readonly 住在一起），三处下游从 `TOOL_REGISTRY` 派生：
  `build_tool_schemas`（可见面）、`execute_tool`（查表调用）、`READONLY_TOOLS`（只读白名单）。
- **四段过滤**（顺序固定，各一个 helper）：
  ① `_filter_by_role`（工具卡底座）→ ② `_filter_by_category`（按卡 perms；**无卡上下文＝默认关门返空**）
  → ③ `_filter_by_card_type`（`report_done` 只对 coder）→ ④ `_filter_root_only`（`draft_rule_edit` 只对根卡）。
- **两段追加**（在四段之后，故常规工具面逐字不变）：
  `auto_mode=1` ⇒ 追加 `update_goal` ＋ 给 `create_card` 补 `goal` 参数；
  `op=update_status` 回合 ⇒ 追加 `propose_status`。
- **实跑统计（2026-10-17）**：注册表 27 件，只读 14 件。
  卡片系：read_card／read_memory／create_card／edit_card／delete_card／update_shadow／read_shadow／
  link_cards／unlink_cards／read_linked／link_rel／unlink_rel／create_coder_card；
  资料 3（manuscript）；文件 4；联网 2；run_tool_card；report_done；draft_rule_edit；propose_status；update_goal。
  → `thinkchain.ENABLED=False` 时**计划六件不注册**（当前即此态），开启则 33 件。
- `send_card_message` **不在注册表**：2026-10-11 裁定改为流程专用基础设施（模型不碰发信工具）。

## 四、上下文装配：区表 + 五槽位

- **区表 REGION_TABLE**（context_regions.py）：区＝`{order, name, channel, seats, source, delivery, profiles, render}`，
  装配**只按 order 拼接，不评价、不裁剪、不截断**；没有来源就不出现这个区（user 位除外）。
- 13 个区（order 0→999）：instruction(0)／rule(85)／card_duty(90)／type_thinking(95)／card_list(100)／
  current_card(150)／**goal(152，auto 卡)**／region_guide(155)／child_status(170)／memory(200)／
  relations(250)／history(300)／tool_turn(900)／user_message(999)。
- **五槽位**：system → prior → user → turn_once → turn_tail。
  `main` 的 system＝BASE_PROMPT＋内容区；`viewpoint`（三席）的 system＝**只有卡片清单＋当前卡（零指令）**。
  prior 槽两区互斥：`tool_turn` 出现时 `history` 让位。
- 控制面：`config/context_regions.json` 可逐区启停/改 order（fail-open，读不到用注册表默认）。

## 五、留痕与对账（四条链，互相独立）

| 链 | 落点 | 记什么 |
|---|---|---|
| 模型调用 | `logs/prompt_*.json` | 每次调用的 system/user/response/tool_events/error **全文**（成败都写） |
| 卡片改动 | `card_history` ＋ git auto-commit（`[auto][work_xxx]` 前缀） | 逐行修改历史＋代码仓库留痕 |
| 工具调用 | 会话内的 tool 块 ＋ `tool_events` | 调用与结果结构化信封（成败读 `ok` 字段） |
| 数据快照 | `D:\AI_station\推演agent_data_snapshots\`（**与代码仓库物理分离**） | 每 work 最近 200 批次＋日备 30 天；error 时 checkpoint 定格现状 |
| 文件覆盖 | `_backups/<原路径>/<时间戳>/` | 文件工具写前强制备份原文（不依赖 git 的兜底） |

**会话文件格式（V2）**：`---SESSION---` 头＋`k: v` 行；块 `---MSG---` … `---END---`，
块头白名单九字段 `seq/actor/from/turn/pair/model/behavior/end/ts`；**轮界与结束合一**
（turn 相同连续块＝一轮，轮末块 `end` 闭合：model_done/policy_stop/human_stop/error）。
白名单外字段保留原值＋`unknown_field` 标记（前向兼容）；必字段缺失或未闭合 ⇒ 块标 `damaged`（占位不吞并）。

## 六、工具卡底座：代码只做执行/存储/渲染，判断归模型

`src/toolcard/driver.py` 的**七不**（最高原则的落地）：不判环节对错（step 是模型自报，照落）／
不判产出空满（根本不看产物）／不判终态（收下 verdict 即结束）／不查轮数（round 只计数不设限）／
不回边（不阻止跳步退步循环）／不拒绝／不判账空。
**只有两种结构性拒绝**：无运行时、目标步不存在（＝「找不到」的事实回话，不是判断）。
运行时 `CardRuntime{card_id, script_name, step_id, round, artifacts}` 存进程内存 Map，
跨请求续跑靠**卡面字段重建**（内存只是快路径，卡面才是真值源）。
