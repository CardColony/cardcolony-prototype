## 2. 权限与三条线 `[亲读 policy.py 全文]`

### 2.1 唯一作用域判定 `can()` 六条规则（`policy.py:407`）

```
① 目标卡须存在
② 类型分权：**目标卡**须持有该开关

④ 根卡：对本项目任何卡通过

```

`check()` 只做两件事：记打点、把 False 变 `PermissionError`；树类开关（edit/delete/link/unlink/create_child）再过一道作用域，`scope` 三档 `subtree/linked/any`。

### 2.2 通信边界是**独立关口**，不是 `check(scope=linked)`

`check_linked`（`policy.py:506`）注释写明了原因：树作用域那段只在 `switch in TREE_SWITCHES` 才跑，
而发信开关是 `read`/`send_card_message`，**不在树类里** ⇒ 硬塞 scope 会被整体跳过（5713 首版实测踩到）。
所以线边界单独成关口，判据只有一条 `_linked_between`（任一侧有 links 边即通）。

## 5. 一轮的完整链路 `[亲读 routes.py:2543-2917]`

```
_run_message
  ├ halt 闸（halted 的卡拒内部唤醒；human 可解除）
  ├ silenced 闸（沉默卡拒内部唤醒，human 可达但不解除）
  ├ set_stream_context（逐字流归属卡）
  ├ turn_try_acquire（同卡在途 ⇒ 409，不排队）
  ├ bind_turn_task（停止端点直接 cancel 协程）
  ├ serial_gate.acquire（serial 模式排队；当前 parallel＝no-op）
  ├ set_turn_source（human 回合 ⇒ notify_human_input 让自动轮让位）
  └ _run_message_inner
       ├ ① 读卡 / goal 预留校验 / pair_id
       ├ ①b take_pending 拼进 user_prompt
       ├ ①c 历史＝origin_store.read_blocks(mark)（只读未凝练段）
       ├ ①d append 用户条（pair 复用判定：事件流优先，回落会话块）
       ├ ② build_context（22 区）+ 工具面
       ├ ③ while: step()  ← 单步推进
       ├ ④ write_logs（成败都写）
       ├ ⑤ compose_delivery
       ├ ⑥ create_cards（工具通道+文本通道）
       └ ⑧ finish
  finally
       ├ flush_pending_reasoning
       ├ emit turn_end（成功/异常/取消三条路径都发）← 必须在 notify_idle 之前
       ├ discard_stop / discard_steer
       ├ turn_release（释放互斥体）
       ├ notify_idle + notify_parent_idle  ← 自动续轮唯一落点
       ├ 摘牌后 deliver_now 接续队列（仅 outcome=ok）
       └ will_continue ⇒ 保留 serial_gate
  finally 之后：role_room.after_turn
```

`step()` 四种出口：`continue`（继续轮）/`seats`（三席，当前关）/`deliver`（可交付）/`error`。
**轮次上限：无**。每轮顺序：中止缝 → wb_exec 委派分支 → 插话入槽 → 判断协议 → 现状任务 → 注入 → 调模型 → 工具执行。
模型调用经 `_call_model_resumable`（`message_runner.py:637`）：`_RESUME_MAX_ATTEMPTS=3`，**按次数不按时间**，每次失败发 `model_resume` 事件。

- **一轮的收口顺序是硬约束**：`turn_end` 帧必须早于 `notify_idle`，`turn_release` 必须早于 `notify_idle`，否则自动续轮会 409 空转。
- 笔记在**方向与结论上基本可信**，但在**数字与「是否已实现」上不可信**——今天核出的 8 处全是这类。
