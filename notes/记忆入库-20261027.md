# 记忆入库：所有以一个事实源（2026-10-27）

> 用户：「那就落实，所有都以一个事实源啊，否则还是会混乱。」

改前记忆存在 **JSON 文件**（`works/{wid}/memory/{card}.json`），而会话块已经进了 sqlite。
两份存储、两套读法，正是"混乱"的结构来源。

---

## 一、改了什么

| 函数 | 改前 | 改后 |
|---|---|---|
| `load_memory` | 读 JSON 文件 | **读 `memory` 表**；表里没这行时从文件**懒迁移一次** |
| `save_memory` | 写 JSON 文件 | **只写 `memory` 表** |
| `ensure_watermark` | 判"文件存在吗" | 判"表里有行吗" |

表结构（已存在，之前没人用）：`memory(card_id PK, chain, condense_mark, fold_mark, batch_starts, updated_at)`

映射：`entries → chain`（JSON）、`mark → condense_mark`、**其余状态 → batch_starts**（JSON）。

## 二、过程中修的一个真 bug

第一版只存了 `entries` + `mark`，跑测试立刻报 `KeyError: 'batch_count'`。

**记忆状态不只有这两个字段**：`batch_count` / `last_fold_check` / `folded` 也存在同一个 dict 里。
只存两个 ⇒ 批循环与去重直接失效。已改成「其余字段打包进 `batch_starts`，读时并回顶层」。

## 四、顺手暴露的两个既有缺陷（不在本轮范围）

**① 解析器把「【依据】」也当成独立条目**

模型返回 `【结论】X\n【依据】块0`，解析产出 **2 条**（gist = "X" 和 "块0"），且 **seq 相同** ⇒
违反不变量 `I1: gist 身份重复`。

改前这个缺陷被**盖住**了：测试读的是文件里的旧数据（只 1 条），永远走不到"新解析"那条路。
记忆改存 sqlite 后（表空 → 真解析）才暴露。

修它要动解析器（把依据并回结论条目），属另一轮。测试里已用 `xfail` 标记并写清原因。

**② 条目字段名两套**

新解析产出 `gist`，旧数据是 `conclusion`。测试原来只认 `conclusion`，改后两者都认。

## 五、现在的规则

> **所有记忆状态只存在 sqlite 的 `memory` 表。**
> JSON 文件降级为历史备份，只在表里还没有该卡时被读一次（懒迁移）。

`memory_path()` 仍保留（迁移读、测试用），但**生产路径不再写它**。
