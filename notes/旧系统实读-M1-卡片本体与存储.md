### 4.5 基线校验 / 乐观锁判定

- **改已有卡正文三列，只有一条通道**：`UPDATE cards SET ...`（card_db.py:1264）只由 `card_db.update_card_row` 发出；该函数两个调用方——`card_store.update_card:1345`（传三块）与 `card_store._append_relation:1875`（body 传 `{}`，`update_card_row` 对空 body 不生成 SET，card_db.py:1250-1261）⇒ **正文写入的唯一函数入口是 `update_card`**。建卡/解档/回收站恢复走 INSERT，不算改。
- **除 draft→commit 一条外，无版本/etag 前置比对**：`src/storage/` 与 `card_tools.py` 全量检索 `optimistic|etag|if_match|expected_version|base_version|content_hash`，无一处用于写前置判定；`content_hash` 只在渲染时回填（hash_utils.py:43-61；shadow_store.py:96），是**结果**不是**条件**。
- `_write_gate`（card_store.py:611）不是并发闸：文档自述「只校验、不落盘、不改 payload」（card_store.py:624-628），实做闸 1 非法值/闸 2 词表归属/闸 3 工具卡 owner/闸 4 状态机（card_store.py:614-619）。挂点：create 1007、update 1284、delete 1491。
- **唯一的基线比对在 draft→commit 一条支线**：`card_draft.commit`（api/card_draft.py:209）比对 `base_hash` 与当前块哈希，不一致返回 `hash_mismatch`（api/card_draft.py:234-239），通过后才 `update_card`（api/card_draft.py:252）。属**读-比-写**，`read_card` 与 `update_card` 不在同一事务内，存在 TOCTOU 窗口，不是原子 CAS。
- 并发串行化只有一层：`card_db.run_write` → `_write_sync` 持 `_lock_for(db_path)` + `BEGIN IMMEDIATE`（card_db.py:1132-1150）。`update_card` 在事务内重读整行（card_store.py:1323）取旧值做版本留档与缺省块填充 ⇒ 块级 last-writer-wins。`card_store._get_lock/_acquire`（card_store.py:96/103）是遗留死代码，无调用点。

## 5. 读影子权限实现

### 5.1 handler 原文（card_tools.py:1654-1676，摘 1659-1670）

```python
    target_id = arguments.get("card_id", "") or current_id
    if target_id.startswith("shadow_"):
        target_id = target_id[len("shadow_"):]
    if target_id not in cards:
        return err("not_found", f"卡片不存在: {target_id}")
    try:
        policy.check(current_id, target_id, policy.SWITCH_READ, cards)
    except PermissionError:
        return err("denied", f"越权：无权读取 {target_id} 的影子")
    raw = await shadow_store.read_shadow_raw(work_id, target_id)
    if raw is None:
        return err("not_found", f"影子卡不存在: {target_id}")
```

### 5.2 结论：接受 `card_id`，且真拦

- **接受 `card_id` 参数**：`arguments.get("card_id","") or current_id`（card_tools.py:1659）；传 `shadow_xxx` 会去前缀归一（1660-1661）。
- **有调用方校验**：`policy.check(current_id, target_id, policy.SWITCH_READ, cards)`（card_tools.py:1665），target 是影子所属**正卡**。
- 判定语义（permissions/policy.py:449-490）：
  - `allowed = has_perm(target, switch)`（policy.py:463-464）——查**目标卡**上固化的 `perms` 列表，不是查当前卡（policy.py:288-307）；
  - 通过后再判树作用域 `can(actor, target, switch, cards)`（policy.py:475-486，`can` 在 481），不在子树/无通信线 → 抛 `PermissionError` → handler 转 `denied`。
- **分发层还有一道前置闸**：`execute_tool` 在 handler 之前跑 `_exec_perm_gate(current_id, tool_name, cards)`（card_tools.py:7662-7665），按 `TOOL_SWITCH` 查**当前卡**是否有 `read`（`TOOL_SWITCH["read_shadow"] = SWITCH_READ`，card_tools.py:172；实现 card_tools.py:7562-7625）。生产主链 `message_runner` 传 `perm_gate=True`（api/message_runner.py:1007-1010）。
- `cards` 字典含影子条目：`_collect_card_meta`（card_tools.py:7447-7457）= `iter_card_metas` ∪ `iter_shadow_metas`，影子键为 `shadow_{正卡id}`；因此 1662 的存在性检查对 `shadow_` 前缀与去前缀两种写法都能命中。
- 顺序是**先存在性后权限**（1662 → 1665）：无权但存在的卡返回 `denied`，不存在返回 `not_found`，两者可区分。

## 6. 版本与恢复

- 历史版本表：`card_revisions`（card_db.py:426-436），字段 card_id/version/ts/block/content/note；PK(card_id,version,block)；索引 idx_rev_card(card_id,version DESC)。
- 写入时机：`update_card` 事务内调 `card_db.append_revisions`（card_store.py:1340-1344）；只存**变了的块**的旧值（card_db.py:1313-1317），一次改动共用一个 version，保留最近 `_REVISION_KEEP=20` 版（card_db.py:423、1332-1335）。建卡/解档/回收站恢复**不产生**版本（只走 INSERT）。
- 查看：`card_db.list_revisions`（card_db.py:1339，只回块字节数摘要）；取全文：`card_db.get_revision`（card_db.py:1365）。
- restore 入口：`_h_edit_card` 的 `restore_version` 分支 → `_edit_card_versions`（card_tools.py:1286-1310）→ `card_store.update_card(work_id, target_id, blocks, "从版本 {ver} 恢复（回退）")`（card_tools.py:1304-1305）。回退先按当前值记一版（update_card 内 append_revisions），可再退；**不校验 ver 是否为最新**，也不校验卡在此期间是否被他人改过。
- 删卡恢复：`delete_card` 把整行+历史+会话正文写入 `trash`（card_db.py:627-642；card_store.py:1505-1521，同一写事务）；`restore_card`（card_store.py:1755）按原 card_id 插回（restore_card_row，card_db.py:660-673），幂等（已存在返 `already`）。
- 归档恢复：`card_archive` 存三块+影子+历史+整行 meta（card_archive.py:32-51、124-149）；`unarchive_card`（card_store.py:1635）重建 cards 行（insert_card:1665）+ 影子重建 + 删归档记录（card_store.py:1692）。
- 留痕：每次 `update_card` 追加一行 `card_history`（card_db.py:1285-1293）；建卡写「卡片创建」（card_store.py:940）。版本/回退/解档/恢复都留痕。
