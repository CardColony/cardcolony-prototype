## 一、一条陈述长什么样

```python
Claim(
    key      = "parent_is_permission_line",
    section  = "系统是什么",
    text     = "**parent（权限管理线）**：管「我能管谁」……**不承载通信**。",
    evidence = "`_h_send_card_message` 的连线校验段（card_tools）",
    verify   = _v_parent_no_comm,      # 可执行检查
)
```

- `render_claims()` **只输出 `text`**——说明书里每一句都有归属
- `verify` 检查的是**代码现状**，不是文字
- 无法机械验证的（「过程不进卡面」这种写作纪律）`verify=None`，登记进 `MANUAL`，
  **显式承认它靠人**，不假装有机制

## 二、机制第一次跑就抓出两条真实不符

```
- parent_is_permission_line：
  `_h_send_card_message` 里仍有 `_is_in_subtree` 退路
  ⇒ 父子之间不建线也能发信，parent 实际上在承载通信

- functions_head_tail_only：
  这些函数也在召集职能：['_h_review_request']
  ⇒ 「只在头尾介入」不成立（旧评审 handler 残留）
```

**这就是"用机制保证"和"写一册说明书"的区别。** 前者能发现说明书在撒谎，后者不能。

### 这两条为什么登记进 `UNMET` 而不是照实写

| 类型 | 例子 | 怎么处理 |
|---|---|---|
| 行为**事实** | `report_up` 不落任何存储 | **说明必须照实**——不写，模型会以为汇报被保存了 |
| 行为**约束** | parent 不该承载通信 | **说明写目标态**，差距登记 `UNMET`——照实写"父子不建线也能发信"会引导模型去用这条退路 |

`UNMET` 双向约束：不成立且没登记 ⇒ 红；登记了但已经修好 ⇒ 也红（防止表烂掉）。

## 三、17 条陈述（四节）

| 节 | 陈述 | 验证方式 |
|---|---|---|
| **系统是什么** | 卡面是权威事实源 | `MANUAL`（写作纪律，无机械判据） |
| | parent 是权限线，不承载通信 | AST：发信入口里不许有 `_is_in_subtree` ← **UNMET** |

| **卡片是什么** | 三块各回答一个问题 | 从 `hash_utils` 派生，恰好 mission/status_block/rulings |
| | 过程不进卡面 | `MANUAL` |
| | 影子记过程、正卡记结论 | `shadow_store` 里能找到四节名 |
| **一轮怎么运作** | 谁让你跑起来 | `deliver_now` 签名里有 `source` |
| | 你看到什么 | 点名的五个区都在 `REGION_TABLE` |
| | 一轮在不再调工具时结束 | `message_runner` 里有「没有 tool_calls 就退出」 |

| | 错误码齐全 | 代码里每个 `err("...")` 都在 `ERROR_CODES` |
