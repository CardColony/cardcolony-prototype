## §0 面命名与边界（先决，下游命名以此为准）

| 面 | 代号 | 权威内容（一句） | 作用域／分区键 | 顺序源（具名） | 写者单位 |
|---|---|---|---|---|---|
| 对话存储 | **C 面** | 完整消息、run／turn 结构、工具调用与结果、thinking、模型字段、会话分支 | `session_id`（分支＝新建 session，见 R-7） | `conv_seq`（**session 内**单调） | session |
| Agent 局部事件流 | **L 面** | Agent 私有运行事实（投递、运行状态、租约、结果回执等） | **`session_id`**（`agent_id` 仅作归属与索引标签） | `local_seq`（**session 内唯一、单调、串行**） | session |
| 全局共享事件日志 | **G 面** | 卡树、连线、权限面等共享事实 | 全局（无 session 维度） | `global_seq`（**全库唯一**单调） | 全局单分配器 |

- C/L/G 为全文与代码统一词表；不得出现「对话库／事件库／共享日志」别名并存。
- **本卡只负责记录**：不解释业务含义、不做上下文投影、不做记忆叙事、不做权限判定（判定归 S4；本卡只按判定结论落盘或拒绝）。
- C 面存正文；L/G 面只存引用 ID，不复制正文（H3）。
- **agent 与 session**：agent 是归属主体（一张卡＝一个 agent），session 是执行与并发单位；**序号分配与写者互斥一律落在 session 上，`agent_id` 只作查询与索引标签**，不作序号分段、不作写者互斥（R-6）。

## §1 对外接口契约（待评审批）★优先节 —— 供 S2／S3／S4／S5／S6／S7／S8 直接引用

本节只定**语义与不合规判据**，不定 Go 签名（签名冻结见 §11-T5）。

### IC-1 写入入口语义

**要什么**

1. 本卡对外**只开三条写入口**：`WriteConv`（C 面）、`WriteAgentEvent`（L 面）、`WriteShared`（G 面）。面与入口一一对应；**一次调用只写一个面**，不得跨面混写一帧；不存在第四条写入口。
2. **写入必带 `session_id`**：
   (a) C 面与 L 面写请求**必带 `session_id`**，缺失或空 ⇒ `rejected / invalid_request`（#1）；**不得**回默认 session、不得由 `agent_id` 反推默认 session；
   (b) 声明的 `session_id` 必须属于声明的 `agent_id`（同一 agent 可有多个 session），不属于 ⇒ `rejected / session_scope_mismatch`（#9）；
   (c) G 面写请求**不带 session 维度**（共享事实无会话归属）；若载荷带了 `session_id`，必须显式回显「G 面无 session 维度」并拒收 `forbidden_field`（#3），不得静默吞掉。
3. **什么算一条记录**：一次成功写请求＝该面**一条记录**（不可再分的记录单元）。
   C 面记录＝一条消息／一条 run-turn 结构记录／一条工具调用或结果／一条 thinking／一条模型字段块（以 `record_type` 区分）；
   L 面记录＝一条**session 内局部事实**（`kind` + 引用 ID + 载荷）；
   G 面记录＝一条共享事实（`kind` + `subject` + `payload` + `audit`）。
   每条记录自带：`record_type`、面内顺序号（由本卡分配，调用方填 0 占位）、`idem_key`、`session_id`（C/L 面）、载荷、时间戳、引用字段（只放被引用记录 ID）。
4. **写入的边界单位**：**一次写请求＝一条记录＝一个 commit batch**；**不提供跨记录批量写入口**（调用方自行 N 次单写，各自独立提交边界）。理由：批量合并会把一次 fsync 摊到多条记录并产生「半批」，无法满足 R-11 的无半条判据。
5. **谁可以写（写者单位＝session）**：
   - **C 面**：只有本卡写。S8（Runtime）只能经协议读写（S8→S3→S4→S1），不得直连持久层；S6 只读投影。
   - **L 面**：只有本卡写。**同一 session 的 L 面只有一个写者（本卡），且该 session 内写入串行**：同一 session 的并发写请求由本卡按到达顺序串行化（固定策略，不提供配置开关）；仅当出现**两个不同写者进程**同写一 session 的异常情形才返回 `session_write_conflict`（#21）。**不同 session 可并行写、互不争序号**。写请求发起方可以是 S2 等，但必须经 S4 执行闸与权限判定后进入本卡写入口；本卡不自行判定「谁该写」。
   - **G 面**：只有本卡写。B4 裁决点「权限面（卡类型／连线类型）变更」的**受理与落盘归本卡**（写 G 面、取 `global_seq`）；合法性与生效检查归 S4；可见/可调用面归 S6。
   - 任何模块不得有本卡之外的第二条持久层写入口（含同进程路径、内部包、测试钩子）。
6. **原子性承诺**：返回 `accepted` ⇒ 记录已持久化，且「记录 + 幂等账 + 审计」在**同一提交边界**（一次 flush + 一次 fsync，R-11）。
7. **本卡不判定 run 互斥**：「同一 session 同一时刻只跑一个 run」由 S2 决定与执行；本卡只保证「同一 session 的局部事件流只有一个写者、`local_seq` 在 session 内单调串行」。互斥的执行归 S2，事实落盘与序号归本卡。

**什么算不合规**

- 出现跨面写的一帧、第四条写入口、或跨记录批量写入口。
- C/L 面写请求缺 `session_id` 仍被接受（回默认 session，或由 agent 反推默认 session）。
- `session_id` 与 `agent_id` 归属不符仍被接受。
- 同一 session 的 L 面出现两条并行序号流，或跨 session 争同一条 `local_seq`。
- 以 `agent_id`（而非 `session_id`）作序号分段或写者互斥单位。
- 未持久化即返回 `accepted`；`accepted` 时无法证明「记录+幂等账+审计」同一边界。
- 本卡自行判定权限合法性，或自行判定 run 互斥。

**可引用方**：S2（投递/运行/租约事实落点、session 内串行）、S3（信封须带 session）、S4（落盘不得旁路）、S5（已提交事实来源）、S8（对话与工具结果落点）。

### IC-2 读取与游标语义

**要什么**

1. **游标分面、具名、带 session 维度**：
   `ConvCursor{session_id, conv_seq}`、`SessionEventCursor{session_id, local_seq}`、`GlobalCursor{global_seq}`。
   三类游标**互不可赋值、不可比较、不可转换**；**不存在统一大游标**。
2. **续读承诺（不重不漏）**：`ReadFrom(cursor, limit)` 返回位置严格大于游标的记录；不回退、不跳号（显式 gap 错误除外）；游标 0＝从起点；`limit` 用尽须回「还有更多」；区间内有物理缺口 ⇒ `range_gap`（#17）并回填缺口上下界。
3. **跨 session／跨 agent 局部序号比较必拒（三道闸，缺一不成立）**：
   - **类型闸**：`local_seq` 与 `global_seq` 为不可互换类型；两个 `SessionEventCursor` 之间不存在「先后」比较算子；跨 session 比较在类型层不可构造。
   - **签名闸**：任何接受两个 `SessionEventCursor` 并给出先后的对外接口**一律不存在**；排序接口只接受 `GlobalCursor`，或接受 `(SessionEventCursor, GlobalCursor)` 但只按 global 序解释并回显所依据的 `global_seq`。**跨 agent 比较同样落在本闸内**（跨 agent 必然跨 session 或跨作用域，不得比较）。
   - **写入闸**：G 面记录**禁止携带私有序号**（`local_seq`／`conv_seq`），出现即 `forbidden_field`（#3）拒收；C/L 面记录禁止携带外部自造的 `global_seq`。
   - 违反任一条 ⇒ `rejected / cross_session_local_seq`（#15）。**一码一因**：本码唯一语义＝「跨 session（含跨 agent）比较会话内局部序号」；cross-agent ⊂ cross-session，不另设同义码。
4. **游标与请求作用域必须同源**：游标的 `session_id` 与请求 `session_id` 不一致，或跨面游标，或订阅续读未给游标且作用域非「从头」⇒ `rejected / cursor_domain_mismatch`（#14）。本码单一语义＝「游标与本次请求的作用域不同源／缺失／非法」，不拆同义码。
5. **游标回退**：提交的游标**严格小于**该读者已消费位置 ⇒ `rejected / cursor_regressed`（#16），不得静默从头重读、不得静默截断。重复提交**同一**游标属合法重读（结果幂等），不算回退。
6. **读取可见性**：只返回**已提交**记录；读到未提交尾部 ⇒ `tail_not_committed`（#18）并给出已返回前缀；**不得**静默截断后声称「已到末尾」。
7. **读取粒度**：按面 + 作用域 + 区间 + limit；支持按 ID 精确取单条、按 `record_type` 过滤（过滤不改变顺序语义）。

**什么算不合规**

- 存在统一大游标；任一面游标可赋给另一面；游标可缺 session 维度。
- 任一对外接口接受跨 session／跨 agent 的 `local_seq` 并给出先后；或以「数值更大」为由跨 session 排序。
- G 面带私有序号不被拒；C/L 面带外部自造 `global_seq`。
- 区间有缺口时返回成功＋空集／静默截断；把未提交尾部当记录返回；读取失败返回空集冒充「没有内容」（H4）。
- 游标回退被静默接受。

**可引用方**：S2、S3、S5、S6、S7、S8。

### IC-3 幂等键落盘判定口径（去重边界＝session）

**要什么**

1. **键作用域＝（面, session, `idem_key`）**：
   C 面＝`(session_id, idem_key)`；L 面＝**`(session_id, idem_key)`**（即便同一 agent 的另一个 session 用同一 `idem_key`，也**不视为重复**）；G 面＝**全局**（共享事实无会话维度，`(global, idem_key)`）。
   **跨 session 同键不视为重复**：不同 session 之间不互相抑制、不误杀。
2. **判定点是落盘判定**：判定以持久化账为准，不以内存为准；键账与记录在**同一提交边界**（R-11），不存在「记录落了键没落」或反之的中间态；判定与提交在同一临界区，同一 session 同一键的并发请求只可能一成一 drop。
3. **重复提交的三种落态必须可分**：
   - 首次 ⇒ `accepted`，回显本面顺序号与记录 ID。
   - **同 session 同键且载荷等价** ⇒ `idempotent_dropped`，**必须回显首次落盘位置**（面、session_id、顺序号、记录 ID、首次时间戳、载荷指纹），不得只回「已丢弃」。
   - 同 session 同键但载荷**不等价** ⇒ `rejected / idem_key_payload_mismatch`（#6），**不得**当作 `idempotent_dropped`（否则键复用会掩盖真实写失败）。
   载荷等价依据＝规范化序列化后的内容指纹（序列化口径须写入契约文档并与实现判等）。
4. **「只处理一次」的边界＝session**：跨 session 重复投递同一逻辑消息**不保证一次**（那是 session 归属问题，不属本卡去重承诺）；同一 session 内同一 `idem_key` 至多落盘一次，此为 H13-2③「同一消息重复投递两次只被处理一次」的记录侧保证。
5. **键索引可否重建**：幂等**账帧**是权威数据一部分（同提交边界，不可删）；为它服务的**查询索引与内存缓存是可删派生物**，删除后必须能由权威帧重建，且重建后的判定结果与删除前**逐条等价**。
6. **`dedupe=none` 模式（待审批 T2）**：若提供，键仍必填并照常落账，但判定恒为 `accepted`（不产生 `idempotent_dropped`）。**默认关闭**（默认严格去重），因其会使「重复投递只处理一次」失去保证。

**什么算不合规**

- 键作用域写成「全局面包一切」；跨面互相抑制；跨 session 被误当重复。
- 同键不同载荷被判为 `idempotent_dropped`。
- `idempotent_dropped` 不回显首次位置，或回显不足以对账。
- 幂等账与记录不同提交边界。
- 删索引/缓存后重建判定结果不等价；索引失效时返回 `accepted`（假成功）。
- 判定以内存为准（重启后同键又被接受一次）。

**可引用方**：S4（闸内校验口径引用本条 1／2／3，不另立去重口径）、S3（协议幂等键与 session 字段）、S5（只传键）、S8（工具重试不得二次落副作用事实）。

### IC-4 写回执三分类与稳定原因码清单（64 码→本稿 24 码初表）

**要什么**

1. **回执恒为三类且互斥**：`accepted` / `idempotent_dropped` / `rejected`；每笔写请求恰收一条回执；**无 `pending`／`partial`／`unknown` 对外态**。
2. **一码一因、稳定、可机器判定**：每码只对应一种失败原因；语义失败不得与存储故障共码；码表封闭、版本化；同因同码跨版本不变；改义须升大版本；新增原因＝新增码。
3. **可重试性必须标注**，不由调用方猜。
4. **不得泛码兜底**：不得用 `internal_error`／`error` 作为 `rejected` 的唯一原因；内部故障必须落到具体码（如 #22）并附诊断引用。
5. **`accepted` 只在持久化完成后返回**；`rejected` 必须显式声明「未落盘任何数据字节」（审计除外，审计必须与拒绝结论同批落盘）。

| 23 | `permission_denied` | 全 | S4 判定为拒绝；本卡只回传该码与审计引用，不自判 | 否 |
| 24 | `version_mismatch` | 全 | 契约版本不一致；不做静默降级兼容 | 否 |

**什么算不合规**

- 出现第四种回执态或无回执路径；对外呈现 `pending/unknown`。
- 一码覆盖两种以上原因（如用 `invalid_request` 承担「引用未就绪」「权限拒绝」「游标混用」「游标回退」）。
- 同一原因跨版本换码；语义失败与存储故障共码。
- 出现 `internal_error`／`error` 泛码作为唯一拒绝原因。
- 缺可重试性标注。
- 本卡自造与 S3/S4 同义的拒绝码（如另一个 `permission_denied` 别名）。

**可引用方**：S3（错误语义一致性）、S4（回执码表同词表）、S2/S5/S8（按码分派重试）。

### IC-5 引用未就绪的错误分类（四类必分，绝不返回空集）

**要什么**

| 类 | 判定条件 | 码 | 必带内容 |
|---|---|---|---|
| ① 目标不存在 | 该 ID 在权威中**从未出现过** | `ref_not_found`（#10） | 已检索的面与作用域清单 |
| ② 未提交 | 该 ID 仅出现在**未提交尾部**（崩溃残留/在途） | `ref_not_committed`（#11） | 所在提交边界不可用这一诊断；`retryable=true` |
| ③ 在另一 session／分支 | 已提交，但**当前 session/分支不可见** | `ref_session_mismatch`（#12） | 实际所属 `session_id`（分支） |
| ④ 索引未就绪 | 权威已有该记录，但解析所需**派生索引/投影未就绪** | `index_not_ready`（#13） | 未就绪的索引名、当前水位/进度 |

- **判定顺序固定**：先判 ②（是否只在未提交尾部）→ 再判 ①（权威是否可见）→ 再判 ③（session/分支可见性）→ 再判 ④（索引就绪）。**索引未就绪时不得返回 `ref_not_found`**（那是把「暂时没准备好」伪装成「从来没有过」，H4 明禁）。
- **禁止空集冒充**：任何解析失败必须报错；返回空集/空对象/零值/`found=false` 而无错误码 ⇒ 不合规。
- **四类互不兜底**：不得用 `range_gap`／`tail_not_committed` 顶替 ①②③④（后两者是读取区间语义）。
- 引用只带 ID；C 面正文由本卡按需解析。

**什么算不合规**

- 任一情形返回成功＋空／默认值／`found=false` 无码。
- 索引未就绪被归为不存在；分支不可见被归为不存在。
- 四类中任两类共码；用区间错误冒充单条引用错误。

**可引用方**：S5／S6／S7（锚点与投影读取遇未就绪须透传具体码，不得转空）、S8、S2。

### IC-6 订阅语义

**要什么**

1. **订阅粒度＝（面，session 作用域，域过滤）**：C 面作用域＝某 `session_id`；L 面作用域＝某 `session_id`（**不得按 `agent_id` 无界订阅其全部 session**——那会退化为跨 session 读）；G 面作用域＝全局但必须带起始 `global_seq`。**无界／全库超级订阅一律拒绝**（`invalid_request` #1，同因不另立码）。域过滤：L/G 面记录带 `domain`（`persistent`／`live`／`policy`）；**C 面无此域字段**（对话不是事件，H3）。
2. **订阅与读取一致**：相同参数下订阅推送内容与 `ReadFrom` **逐条相等**（含顺序号与 session_id）；订阅只是「免轮询」的读取通道。
3. **断线按游标续读**：必须从调用方持有游标原值续读，不得全量重拉；续读承诺同 IC-2.2；断线期间超出保留窗口 ⇒ `subscription_gap`（#19）并**显式给出缺口前后游标**，不得静默跳号，也不得「全量重来」冒充续读；未给游标且作用域非从头 ⇒ `cursor_domain_mismatch`（#14）。
4. **订阅与读取同一权限面**：是。二者共享同一读取授权判定（S4 判定、本卡执行）；订阅作用域必须是读权限范围的子集；不存在「能订阅不能读」或「订阅面更宽」的特权差；权限面变更（卡类型／连线类型）后**下一次订阅建立/推送即按新权限面判定**，本卡不缓存权限面。
5. **推送是尽力即时、权威在记录**：推送丢失不构成数据丢失，但**必须可被游标缺口检出**（不得出现「推送丢了、游标却像没漏」的假象）。
6. **本卡不负责任何投递语义**：订阅＝读活动流，不是投递消息；入箱与唤醒归 S2。

**什么算不合规**

- 无界订阅、按 agent 无界订阅其多 session、订阅不带具名游标类型。
- 订阅与同参 `ReadFrom` 不一致（含顺序号/ session 不同）。
- 断线全量重拉；保留窗口不足静默跳号或不给缺口区间。
- 订阅具备读取没有的额外可见面；权限面变更后仍按旧面推送。
- 推送丢失后游标看似连续无缺口（不可检出）。
- 订阅路径绕闸或绕审计。

**可引用方**：S2（勿把订阅当投递）、S6（产品壳读取）、S7（记忆区读取）、S4（权限一致性）。

## §2 三记录面权威与引用（R-1…R-5）

**R-1 三面各自唯一权威（H1）**
- 要：C/L/G 三面各只有一个权威存储与一个写者（本卡）；索引、投影、凝练、归拢、上下文缓存、观测视图全部是可删可重建派生物，不得反向成为权威。
- 判据：①删除每个派生物后仅由权威重放重建，与删除前**全量指纹逐字节相等**；②静态扫描所有可写持久层入口，输出「入口→归属面」清单，每面恰一个写者；③任一派生物不参与任何成功/失败判定。
- 不合规：派生物删后不可重建；存在不经本卡写入口；判定以派生物为准。

**R-2 派生物可重建且可删（H1／V-5）**
- 要：游标定位索引、引用解析索引、fork 链索引、观测投影、游标/订阅进度账均在 `derived/`；可整目录删除后重建。
- 判据：删除 `derived/` 全目录 → 冷启动重建 → 与删除前、在线路径产物**三方指纹相等**；重建**无人工干预**（一条命令或冷启动自愈）。
- 不合规：需手工修数据；三方指纹不等；重建需第三方服务或网络。

**R-3 引用只带 ID（H3）**
- 要：C 面被引用时 L/G 面只携带引用 ID（含 `session_id` 等定位字段）；普通对话不逐条复制为事件。
- 判据：写含工具调用与 thinking 的对话后，对 L/G 面**全文检索对话正文与工具输出片段 ⇒ 零命中**；由事件内引用 ID 能解析回 C 面记录（四类错误各自可复现）。
- 不合规：正文片段命中事件面；事件携带正文；引用不可解析且未报错。

**R-4 引用未就绪显式报错（H4 局部）**
- 要：同 IC-5。
- 判据：四类各注入 ≥1 次，逐类核对码与 §IC-5 映射一致；且「索引未就绪 + 记录其实存在」不得归为 `ref_not_found`。
- 不合规：返回空且无码；索引未就绪归为不存在；两类共码。

**R-5 三面不强求统一事务，但引用须一致**
- 要：C 面与 L/G 面各自独立提交，不要求跨面同一事务；同一面内「记录+幂等账+审计」必须同一边界。
- 判据：构造「先写 C 面再写 L 面引用」与「先写 L 面引用再补 C 面」两种时序：前者解析成功；后者补写前为 `ref_not_found`、补写后解析成功且旧记录不被改写；对外无「半事务」呈现。
- 不合规：把三面塞进一个跨面事务（违反面独立原则并使 L/G 写阻塞 C）；或跨面弱到「写了引用就假装正文已在」。

## §3 顺序域与 session／分支（R-6、R-7）

**R-6 顺序域不得伪造（H2）**
- 要：
  (a) `conv_seq` 只在**同一 session 内**有效；`local_seq` 只在**同一 session 内**有效且单调串行；`global_seq` 全库唯一单调；
  (b) **`agent_id` 不是序号域**：不得按 agent 分配或比较序号；同一 agent 的多个 session 各自独立序号流；
  (c) 跨 session／跨 agent 判断只能依据 G 面事实（`global_seq`）或显式关联记录。
- 判据：①「三面顺序源类型 vs 唯一写者单位（session）」逐条比对通过；②对**每一处**跨 session/跨 agent 判定路径，列出实际依据顺序源（须为 global 或显式关联）；③构造「跨 session 比较 `local_seq`」的调用 ⇒ 必拒 `cross_session_local_seq`（#15）；④构造跨 agent 比较同一 agent 两 session 的 `local_seq` ⇒ 同样必拒；⑤G 面注入私有序号载荷 ⇒ `forbidden_field`（#3）。
- 不合规：任一跨 session/agent 判断使用局部序号；任一 API 接受跨 session 比较并给先后；同面出现第二个顺序源；以 agent 为序号单位。

**R-7 分支与 session 的关系（本卡定：分支＝新建 session）（H10、V-2）**
- **定义**：分支**不是** session 内的一个维度，而是**新建一个 session**。`Fork(parent_session_id, fork_record_id) → child_session_id`；child session 记录带 `origin`（父 session + 起点记录 ID + 契约版本）。
- **理由**（三条，缺一不成立）：
  1. 若分支留在同 session 内，同一 session 的两个分支若并行跑 run 就必须争同一条 `local_seq`（或退化为「session 内再分序列」，把 session 拆成第二层序号域），正好复现本轮要消除的争用问题；
  2. 分支＝新 session 时，每支自动获得独立写者与独立序号流，`local_seq` 在**每支内部**单调串行，与并发口径天然一致；
  3. 与父卡 A3-6「按会话／分支／run／turn 构建」的并列口径一致：会话与分支都是可寻址单位。
- **要**：
  (a) 任意**已提交**的 C 面记录可作为 fork 起点；起点必须属于所声明的父 session（否则 `fork_origin_mismatch` #8）；
  (b) **旧 session 字节零变化**：fork 不改写、不致删任何旧字节（H10）；
  (c) **session 隔离是硬约束**：所有读必须带 `session_id`；跨 session 引用 ⇒ `ref_session_mismatch`（#12）；**不存在默认 session 兜底**（缺 `session_id` ⇒ `invalid_request` #1，不得取「最近 session」或「该 agent 主 session」）；
  (d) 1.0 无分支合并、无分支删除（只能新建方向）；「全历史」＝沿 `origin` 链逐段读取，**禁止跨段比较序号**（R-6 c）；
  (e) `Fork` 本身是一次 C 面结构写（写一条 fork 记录 + 新 session 首条记录），必须带 `idem_key`（同父同起点的重复 fork 请求按幂等处理）。
- **判据**：
  ① fork 前后导出父 session 全量记录做 sha256 ⇒ **逐字节相等**；
  ② 父子两支交叉写 + 交叉读 1 万条 ⇒ 读回集合**零串支**（每条只在所属 session 读取结果里出现）；
  ③ 子 session 的 `local_seq` 从 1 起独立单调，与父 session 无交集、无重号；
  ④ 读缺 `session_id` ⇒ `invalid_request` #1 且有审计；
  ⑤ fork 到不属于父 session 的起点 ⇒ `fork_origin_mismatch` #8。
- **不合规**：旧记录被改写/覆盖/删除；交叉读到另一 session 记录；缺 session 回默认；子 session 与父 session 共用一条序号流；fork 无 origin。

## §4 读取与订阅（R-8、R-9）

**R-8 读取与游标（V-1、A3-1）**
- 要：同 IC-2；支持按 ID 取单条与 `record_type` 过滤；每次返回携带「本次区间游标」以便续读。
- 判据：①每面每 session 从 0 全量读到尾，累计集合与直接全量导出**逐条相等**；②分段续读（limit 取 1／7／100）读回集合一致、无重无漏；③区间内注入物理缺口 ⇒ `range_gap` #17 且缺口上下界可读；④游标回退 ⇒ `cursor_regressed` #16。
- 不合规：分段读不一致；缺口静默跳过；limit 用尽仍声称到底；读取失败返回空集。

**R-9 订阅（A3-1、H9 记录侧）**
- 要：同 IC-6。
- 判据：①订阅推送与同参 `ReadFrom` 逐条相等；②断线于游标 c，断线期间写入 N 条，重连恰取回 N 条且不含断线前已读记录；③保留窗口不足 ⇒ `subscription_gap` #19 且给缺口前后游标；④「能读不能订」用例两侧判定必须一致。
- 不合规：推送与读取不一致；续读重复或漏读；缺口静默；订阅与读取权限面不同源。

## §5 快照、崩溃恢复与失败显式（R-10、R-11、R-12）

**R-10 快照（V-5、A3-1）**
- 要：可对某面某 session 在某一游标处取**一致快照**；快照必带所依据的**契约版本**与**游标**；不完整快照必须标注 `incomplete`（读时为 `snapshot_incomplete` #20）。
- 判据：①取快照后继续写 N 条，快照内容与写入前全量导出**逐字节相等**；②快照游标可继续用于 `ReadFrom`；③中途崩溃的快照 ⇒ 冷启动识别为 incomplete 并返回 #20，不得当完整快照。
- 不合规：快照随之后写入变化；快照无游标/无契约版本；不完整快照被当完整返回。

**R-11 崩溃恢复与提交边界（G1 崩溃恢复项）**
- 要：
  (a) 一次写＝一个 commit batch，次序为「记录帧 → 幂等账帧 → 审计帧 → commit 边界帧」，**同一 flush + 同一 fsync**，不引入第二持久点；
  (b) 崩溃后只信任最后一个 commit 边界帧之前的完整帧；其后的完整帧属未提交，**必须可分辨**，分类为「未提交尾部」并写修复事件（不静默丢弃、不静默采用）；
  (c) 恢复须产出三分类：`未提交尾部` / `已提交未建索引`（对外表现为 `index_not_ready` #13）/ `无残留`；
  (d) 序号分配器恢复＝`max(seq)+1 over committed`，**不重用**已确认序号；**per session** 恢复（各 session 独立取 max）；
  (e) 结果不确定的动作不得盲目重执行。
- 判据（G1）：每面写入定点各注入 kill ≥10 次（写入中／fsync 后未返回／返回后建索引前，覆盖多 session 并行场景）→ 重启后：**已 accepted 记录 100% 可读且逐字节相等；未提交半条记录 0 条以记录身份可读；各 session `local_seq` 集合无重号无丢号**；每次恢复的未提交尾部均有可读诊断。
- 不合规：kill 后出现半条记录被当完整记录；已 accepted 记录丢失或内容变化；同 session 内 `local_seq` 重号；静默丢弃尾部无记录；需人工介入恢复。

**R-12 失败显式（H4、V-9）**
- 要：本卡所有读/写/配置/索引/投影/重建路径禁止「错误→空／默认值／成功」；禁止静默截断；坏配置**不回落默认**；降级（索引未就绪、投影落后、保留窗口不足）必须落成可读的降级或错误条目；禁止私有恢复路径。
- 判据：①静态扫描本模块内「错误→空/默认/成功」模式，命中清单**必须为 0**；②五类路径各注入一次失败（缺文件／坏行半帧／存储不可读／索引未就绪／保留窗口不足），逐类核对返回必须报错且码在 IC-4 词表内；③坏配置（未声明 store_root、未声明上限）⇒ **拒开或拒写**，不回默认；④降级清单 vs 观测面逐项对上。
- 不合规：任一路径返回成功＋空/默认；坏配置回默认；降级不在返回结构或观测面；存在「坏了自动重建不告知」的私有路径。

## §7 本模块验收判据（V-1／V-2／G1／V-5）

**V-1 记录正确**
- 判据：①L/G 面全文 vs 对话正文 ⇒ 零命中；②三面顺序源清单 ⇒ 每面恰一个，单位＝session；③跨 session/agent 判定路径逐条列出实际顺序源 ⇒ 全为 global 或显式关联；④构造跨 session 比较 `local_seq` ⇒ 被拒 #15 且留审计；⑤构造同一 agent 两 session 比较 `local_seq` ⇒ 同样被拒。
- 不合格：正文命中事件面；出现第二个顺序源；任一跨 session 比较放行。

**V-2 分支正确**
- 判据：①fork 前后父 session 记录逐字节一致；②父子交叉读零串支；③子 session 从指定记录续、父 session 不受影响、子 session `local_seq` 独立从 1 起；④缺 `session_id` ⇒ 拒（#1）且有审计；⑤「全历史」沿 origin 链逐段读出与各段各自导出一致。
- 不合格：旧记录被改写或丢失；读到他支记录；缺 session 回默认；跨段比较序号。

**G1 记录与执行底座（本卡参与的四个比对项）**
1. **并发写入**：N 个 Writer × M 条 × 三面混合并发，且**含「同一 agent 多 session 并行 run」场景**（≥2 session 并行写 L 面）；比对「`global_seq` 集合」与「**每个 session 的** `local_seq` 集合」与期望集合 ⇒ 全等、零串支、零重号零丢号。
2. **崩溃恢复**：R-11 判据（多点位 kill，含多 session 并行）。
3. **分支读取**：父子 session 交叉读回消息集合 ⇒ 零串支。
4. **事件重放**：重放前后投影指纹 ⇒ 相等（R-2）。
- 不合格（沿用父卡口径，本卡按 session 收紧）：任一 **session** 局部序号重号或丢号；全局序号重号或丢号；kill 后出现半条记录；交叉读到他支消息；重放指纹不等。

**V-5 机制可重放（本卡部分）**
- 判据：删除 `derived/`（含投影与各类索引）后两次独立重建，三方指纹相等；重建无人工干预。
- 不合格：任一方指纹不等；需人工干预；重建需读派生物（循环依赖）。

**证据形态**：每判据须提交「用例清单 + 可复跑命令或脚本 + 原始输出 + 结果摘要」，落 `evidence/card_011/<YYYYMMDD>/`；只有文字结论视为未取证。

**收口语义**：本模块上述判据全部通过 ＋ 已按 S10 要求到场参与 G1 取证 ⇒ 使命达成；G1 是否通过由 S10 判，不由本卡判。

## §10 方案提案（本卡自决项，报 card_007 审批；不是需求，但定义阶段须定案）

**P1 存储引擎**：自研 append-only 分段日志（标准库帧格式，零第三方依赖，不用 SQLite/嵌入库）。理由：①三面独立提交，单库会耦合；②commit 边界帧可精确回答「未提交尾部」（R-11 (b)），数据库 WAL 语义难以逐帧区分半批；③零依赖利于三形态打包与装配审计；④读取可按帧偏移建派生物。代价：自建段滚动、压缩归档边界（P6）。参照旧仓 `persist` 的「分片＋commit 帧＋单分配器＋恢复截断」形状，但**不继承实现、不继承数据**。

**P2 事务粒度**：一次写＝一个 commit batch（记录帧＋幂等账帧＋审计帧＋commit 帧，一 flush 一 fsync）；不提供跨记录批量写入口（IC-1.4）。

**P3 物理布局（session 化）**：
```
<store_root>/
  conv/<session_id>/seg-<k>.log          # C 面，一 session 一族（分支＝独立 session 目录）
  sessionevt/<session_id>/seg-<k>.log    # L 面，一 session 一族
  global/seg-<k>.log                     # G 面
  derived/ locator/ idemidx/ forkidx/ subprogress/ projections/
  snapshot/batch-<n>/                    # 含 .incomplete
  repair/                                # 修复事件
```
`store_root` **必须显式配置**，未配置即拒开（R-12③）；运行数据与源码分离。命名小写 ASCII、日期 `YYYYMMDD`、版本显式。session 化布局使「串支」在物理层不可能，`derived/` 可整删以验 R-2。写入 `agent_id` 仅作目录内索引字段与查询标签。

**P4 包组织**：本模块＝Go module（路径待 S9/007 定），唯一导出包 `api/`（面、游标、写请求/回执、24 码常量、错误类型）＋内部包 `internal/{conv,sessionevt,global,fork,snapshot,derived,recover,storeio,probe}`；内部包禁止被跨组件导入（项目规则第 4 条）；契约常量与 G0 契约文档**判等**。

**P5 索引与算法**：
- 索引三件：区间定位索引（游标→帧偏移，按 session 分文件）、引用解析索引（ID→帧位置，含 `session_id`）、fork 链索引（`session_id`→origin 链）；全部落 `derived/`，懒建且有**具名 ready 记录**（未 ready ⇒ `index_not_ready` #13，不得 `ref_not_found`）。
- 索引更新＝权威提交后追加，**禁止写侧双写权威与索引**（旧系统双写双轨教训，A5-5）。
- 顺序分配：per session 分配器（C 与 L 各一）＋G 面全库单分配器；恢复＝per session `max+1 over committed`；分配与提交同临界区。
- 路由：写路由**只按 `session_id`（G 面按 global）**，永不读地址、不按 seq 轮转、不按 agent 路由。
- 段滚动：达声明上限即 seal（rename + 父目录 fsync），**滚动不引入新持久点**；上限未声明 ⇒ 拒写并审计。
- fork：写时复制，父链引用旧记录，**绝不重写旧段字节**。
- 快照：staging（`.incomplete`）+ 完成后 rename + 父目录 fsync；残留被下次识别为不完整。
- 恢复截断三分类可复现（R-11 c）。

**P6 恢复与并发**：同一 session 写入口持 session 级写锁；不同 session 无共享锁；G 面分配器全局锁仅覆盖取号＋追加。读侧无锁（依赖 commit 边界帧截断）。

**P7 参数与阈值（须 007 审批；未批前按显式配置运行，**未配置即拒写/拒开**，不回默认）**：段上限（提案 64 MiB）、单帧载荷上限（提案 8 MiB，与协议帧上限对齐由 S3 定）、读取默认 limit（提案 200）、订阅保留窗口（提案 200k 记录／session 维度）、索引懒建水位、快照保留份数。另 `dedupe=none` 是否提供（T2，提案不提供）。

**P8 自验与取证工具**：`cmd/recordprobe` 提供可复跑子命令：`concurrency-multisession`（同 agent 多 session 并行写）、`killmatrix`（多点位 ≥10 次）、`forkcross`（父子交叉读）、`replayfp`（三方指纹）、`negativescan`（错误→空/默认、跨 session 比较、第二写入口三类扫描）；证据落 `evidence/card_011/<YYYYMMDD>/`。
