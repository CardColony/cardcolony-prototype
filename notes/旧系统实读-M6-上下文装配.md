## 3. 每一区注入内容怎么取（查库/读文件/拼接，关键函数带行号）

装配层纪律：**IO 全在 `context_assembler.build_ctx` 之前完成一次**，渲染器 `context_regions` 保持纯函数、不自己取数（`context_regions.py:17,33-35`；`build_ctx` `context_assembler.py:330-385`）。

## 4. 截断与上限（payload_cap）：阈值 / 按字符还是 token / 超限处理 / 截断标记（逐项带行号与默认值）

> 重要定位：`payload_cap.py` 是**响应层（event 记录）载荷裁剪**，**不属于上下文装配区**，也不作用于上下文区本身。上下文区（§1）均无截断（除 history 按 `mark` 切片，非截断）。以下为 payload_cap 自身事实登记。

常量与默认值（`payload_cap.py:44-49`）：
- `DEFAULT_CAP = 64 * 1024` —— 单个字符串上限 **64KB**（`:45`）。
- `MAX_NODES = 5000` —— 结构规模：节点数上限（`:48`）。
- `MAX_CHARS = 256 * 1024` —— 结构规模：字符串总长上限 **256KB**（`:49`）。

**按字符还是按 token**：按**字符**（不是 token）。`_measure` 遍历计数：`chars += len(cur)`（对 str，`payload_cap.py:58-59`），外加节点数 `nodes += 1` 每元素（`:57`）。注释明言「节点数（dict/list 的元素总数）与字符串总长，**一次遍历、不序列化**」（`:53`）。无任何 token 分词逻辑。

**超限处理**（`cap_record`，`payload_cap.py:102-128`）：
1. 结构规模超限：`if nodes > max_nodes or chars > max_chars:`（`:107`）→ 把 `data["result"]` **整块换成摘要**（丢弃原结果），摘要含 `_capped:True` 与 note「结果过大已省略（原始 {nodes} 个节点 / {chars} 字符）」（`:108-116`）。外层 `tool/target/ok` 不动（`:26-27`）。
2. 单串超长：循环最多 8 次，`_find_longest` 找最长串，若 `length > cap` 则截断为 `old[:cap] + f"…（已截断，原 {length} 字节）"`（`:119-125`）。注释说明这是兜住「就一个超长字符串」的情况（`:117-118`）。
3. 阈值可调：函数签名 `cap_record(rec, cap=DEFAULT_CAP, max_nodes=MAX_NODES, max_chars=MAX_CHARS)`（`:102-103`），`cap_records(items, cap=DEFAULT_CAP)`（`:131`）。

**是否有截断标记**：有。
- 整条记录级：`if changed: rec["_truncated"] = True`（`:126-127`）——「记录上标 `_truncated: true`」（文件头注释 `:32`）。
- 结构规模整块替换时，结果内嵌 `"_capped": True`（`:112`）。
- 单串截断时，串尾追加「…（已截断，原 N 字节）」提示（`:124`）。

**其它口径**：
- 只裁响应、不动落盘（事件日志保持完整，审计/回放不受影响）（`:31`）。
- 超长但单串载荷仍按字符串截断带提示（`:33`）。
- 已通过 `tests/test_payload_cap.py`（文件头 `:37-38`）。

> 上下文装配侧**无等价 cap**：区渲染器全部「零加工、不裁剪、不判断」（模块头 `context_regions.py:4-6`）；history 区仅按凝练水位 `mark` 切片（`project_history_messages` `:741-742`），非上限截断。

## 5. 父卡看子卡：子卡现状注入实现（是否递归 / 取几个子级 / 单卡取多少字符 / 有无上限）

**是否递归**：**否，SQL 不递归**。
- 取数：`_load_direct_child_status`（`context_assembler.py:82-104`）执行
  ```python
  "SELECT card_id, title, status_block FROM cards "
  "WHERE work_id = ? AND parent = ? ORDER BY card_id"
  ```
  （`context_assembler.py:97-101`）。注释原话（`:85-86`）：
  > 「SQL 不递归（`WHERE work_id=? AND parent=?`，只一层）⇒ 孙级在结构上取不到——「父卡只看直接子级」不靠过滤逻辑保证，靠查询本身。」
- 渲染：`render_direct_child_status_region`（`:1461-1486`）遍历传入的 `children`（即上述直接子卡），**不递归**；注释（`:1464`）：「上游 SQL 只按 `parent=?` 取一层 ⇒ **结构上不可能含孙级**」。

**取几个子级**：全部直接子卡（无数量上限 / 无 `LIMIT`）。SQL 无 `LIMIT`（`context_assembler.py:97-101`）。渲染逐条处理（`:1473`）。

**单卡取多少字符 / 有无上限**：**全文注入，无字符上限，无 slice / [:n] / max_**。
- 取数层直接返回整列 `status_block`（`:96`），未做任何 `[:n]` / `max_` 截断。
- 渲染层原样拼接：`sections.append(f"### {card_id} · {title}\n{status}")`（`:1483`），`status` 为整段。
- 显式纪律（`:1469-1470`）：
  > 「[2026-10-24 · 用户令「不允许截断,截断不如不发」] **全文注入,不截断**: 现状块是覆盖写·单一最新,块本身有界;coder 卡没有现状块(不进本区)。」
- 过滤逻辑（非截断，是「跳过」）：`_child_status_body`（`context_regions.py:1450-1458`）用 `_is_placeholder` 判定空/占位符 → 当「未写」跳过该子卡；`render` 内 `if not status: continue`（`:1475`）且 `coder` 类型整体 `continue`（`:1481`）。全空则该区整体不出现（`:1484-1485`）。

**截断标记结论**：**无任何截断标记**（不存在截断，故也无标记）。注释「截断不如不发」→ 选择「不注入」而非「截断注入」（`context_regions.py:1469`）。

> 行号锚点：取数 `context_assembler.py:82-104`（核心 `:97-101`）；占位判断 `:1450-1458`；渲染主循环 `:1461-1486`（关键 `:1469, :1473, :1475, :1481, :1483, :1485`）。

## 6. 类型级指令/思维区：是否存在按卡类型注入的文本区（数据存哪 / key / 未配置时处理）

**存在，两类按 `card_type` 取文本；另有类型级职责（非自由文本）。**

### 6a. `type_thinking`（卡片思维，order 95）—— 按卡类型挂的文本区
- 数据存**文件**：`config/type_texts.json`（`context_assembler.py:154-156`，`_type_texts_path()`）。
- 加载：`load_type_texts()`（`context_assembler.py:159-188`）→ 返回 `{维度: {类型code: 文本}}`，跳过下划线前缀键（如 `_meta`），只保留非空字符串条目（`:181-187`）。**fail-open**：读不到/坏 JSON/结构不对 → 空表（`:168-179`）。
- key 叫什么：
  - 维度 key：`"thinking"`（`render_type_thinking_region` `context_regions.py:1158-1166` → `dim = type_texts.get("thinking")` `:1166`）。
  - 子 key：当前卡的 `card_type`（`render` 调用传 `str((ctx.cur_meta or {}).get("card_type") or "")`，`context_regions.py:430`）。
- 未配置时怎么处理：取 `dim.get(card_type)`（`:1169`），空串/无该维度/无该类型 → 返回 `""`（`:1167-1171`），即「没有来源就不出现这个区」（`:1163`）。正文原样呈现、不加工不截断（`:1164`）。
- 渲染仅取**本卡那一类**那一段，不并列别类（`:1160-1162`）。

### 6b. `rule`（规则注入，order 85）—— 按 card_type 取规则区
- 数据存：work.json 的 `rules` 字段（优先，`context_assembler.py:211-226`）；legacy 兜底读 `card_type='rule'` 卡 mission 按 `## {区名}` 切区（`split_rule_sections` `context_regions.py:1274-1298`）。
- key：规则区名 = 当前卡的 `card_type`（render `render_rule_region`：`rule_sections.get(card_type)`，`context_regions.py:1301-1313`）。
- 未配置/无对应区：返回 `""`（`context_assembler.py:1308-1312`）。合法分区名集合＝类型注册表全词表 codes（`rule_section_names` `:1316`，角色卡 `role` 不计入 `:1337`）。

### 6c. `card_duty`（卡片职责，order 90）—— 类型级职责（来自注册表，非自由文本）
- 数据存：类型注册表 `l1_vocabularies.*.types[]`（`card_store.load_type_registry`，`context_assembler.py:377`），每类卡一行 `label/code/description`（`context_regions.py:902-932`）。
- 未配置：注册表空/无类型 → 空串（`context_regions.py:914-916,930-931`）。

> 配置纪律统一：「配置是控制源，不是可用性依赖」——绝不因配置缺失阻断装配（注释 `context_assembler.py:160-166,192-194`）。
