# 工具说明 · 唯一源机制（2026-10-27）

> 目标（用户原话）：「工具说明要做一次梳理和整合，而且要成为**唯一**，且**不可逾越**的机制」
> 以及：「要改成**添加工具就必须触发一系列改动**，且改动必须**对照事实**，且能确保模型知道工具的**使用场景及如何使用**」

---

## 一、改前的病：三份说明，互相矛盾

| 份 | 规模 | 谁在看 |
|---|---|---|
| schema `description` | 8592 字 / 73 件 | `tools` 参数 |
| `prompts._SEC_TOOLS` | 2086 字 / 25 件 | 普通卡 system prompt |
| `prompts._SEC_TOOLS_AUTO` | 3916 字 / 35 件 | 自动卡 system prompt（整段复制 ＋ 10 件） |

实测 `card_061`（sub_project, auto）：

```
提示词列 35 件 / 实际下发 43 件
实际有、提示词没提（19 件）：sync direct report_up open_review stage_open wake_card …
提示词列了、实际拿不到（11 件）：bash write_file edit_file edit_card python report_done …
```

**提示词告诉一张作业卡「你有 bash / write_file / python」，它一件都没有。**
**提示词对 sync / direct / report_up 一字不提，而这三件是线上调用最多的通信工具（446 / 147 / 151 次）。**

还有一处说明在撒谎：`sync` 的 description 写「只入收件箱」，实现早已改落会话块（`messages` 表 `msg_sync=0` 即证）。

## 二、机制：四条

### ① 唯一源：`ToolDoc`

`src/api/tool_doc.py`。四个字段**全必填**，构造期就校验：

| 字段 | 内容 | 谁保证 |
|---|---|---|
| `group` | 能力域（12 组，决定工具节里排哪组） | 构造期校验必须在 `GROUP_ORDER` |
| `scene` | **什么时候该用** | 构造期校验非空 |
| `usage` | **怎么用、坑在哪** | 构造期校验非空 |
| `effect` | 落哪 / 唤不唤醒 / 要不要线 | **AST 校验对照实现** |

### ② 唯一渲染：`_schema_of` 是唯一出口

`card_tools._schema_of()` 里：注册项带 `doc` ⇒ 用 `render_description()` 覆盖
`description`。tools 参数与提示词工具节都经这里取，**结构上不可能不一致**。

### ③ 覆盖真实工具面：`render_section(names, docs)`

输入是 `build_tool_schemas()` 的结果（模型**真能用**的那批），按能力域分组渲染。
「列了拿不到的」在结构上不可能发生。

### ④ 对照事实：AST 扫 handler

`verify_effect()` 用 `inspect.getsource` ＋ `ast` 扫 handler 的调用名，比对声明：

| 声明 | 必须在 handler 里找到 |
|---|---|
| `sink="session_block"` | `append_card_message` / `session_facade.append` |
| `sink="inbox"` | `append_inbox` |
| `sink="card"` | `update_card` |
| `wake=True` | `deliver_now` / `_spawn_tracked` |
| `wire=True` | `check_linked` / `_require_wire_switch` |

**说明不能撒谎**：声明落会话块、代码里找不到对应调用 ⇒ 测试红。
壳函数（`scene_report` → `report_up`）用 `effect.delegate` 标，跳过本层。

## 三、加一件工具，必须触发的改动清单

| # | 必须做 | 漏了会怎样 |
|---|---|---|
| 1 | `TOOL_REGISTRY[name] = ToolDef(...)` | 工具不存在 |
| 2 | `TOOL_SWITCH[name] = 权限开关` | `_filter_by_category` 判 `unmapped`，**静默不下发** |
| 3 | 归属：哪个卡型能拿到（类型闸 / 末段追加） | 工具存在但没人看得见 |
| 4 | `ToolDoc(group, scene, usage, effect)` | **构造期报错**（`scene`/`usage` 空即 `ValueError`） |
| 5 | `effect` 与实现一致 | **AST 校验红** |
| 6 | 从 `tests/test_tool_doc_facts.py::PENDING` 删掉该名字 | **`test_pending_list_is_honest` 红** |

第 4、5、6 条是这次新加的强制项。第 4 条是**结构强制**（构造期），第 5、6 条是断言。

## 四、当前进度

**已填 5 件**（覆盖四种 sink ＋ 两种 wake，用来验证机制本身）：

| 工具 | group | effect |
|---|---|---|
| `read_card` | 读卡 | sink=none（纯读） |
| `link_rel` | 依赖 | sink=none（只写卡上字段） |
| `sync` | 通信 | session_block / wake=False |
| `direct` | 通信 | session_block / wake=True |
| `report_up` | 通信 | **sink=none / wake=True**（现状，见下） |

**未填 68 件**，登记在 `PENDING` 里，**只能减不能增**。

### `report_up` 的声明是照实写的，所以它现在很难看

```
**效果**：**会叫起对方跑一轮**；但**不落任何存储**——正文只活在它这一轮的输入里，下一轮就查不到了
```

这是**当前实现的真话**。校验器逼着说明说真话，所以它把这个缺陷摆到了模型面前。
改完之后（落会话块），声明改成 `sink="session_block"`，这句话自动变成「落对方上下文」。

**这说明机制在正常工作**：它不允许说明比实现好听。

## 五、还没做

**① 提示词工具节还没切到 `render_section`。**
`_SEC_TOOLS` / `_SEC_TOOLS_AUTO` 两个手写字符串还在。原因是：现在只有 5 件有 `doc`，
切过去会让其余 38 件工具从提示词里消失——比现在更糟。
**等 73 件填完再切**，切的时候一并升 `BASE_PROMPT_VERSION` / `AUTO_BASE_PROMPT_VERSION`
并更新 `test_auto_mode.py` 的 SHA256 断言。

**② 73 件内容没填完。**
每件都要读实现才能填准 `effect`（不能猜）。按能力域分批：读卡 10 件 → 写卡面 7 件 →
通信 9 件 → 依赖 2 件 → 组织 6 件 → 治理 7 件 → 评审 5 件 → 目标 5 件 →
职能 10 件 → 文件 9 件 → 执行 2 件 → 联网 2 件。

**③ AST 校验只做了单向**（声明了必须有）。
反方向（没声明却做了）会误报壳函数与间接调用，等声明全填齐后再收紧。
