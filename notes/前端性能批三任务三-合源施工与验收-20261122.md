## 1. 施工落地（全部已进工作树）

### 1.1 `/api/nav/running` 两读合并 + 部分缺失三态

| 点 | 改动 | 文件 |
|---|---|---|
| 合源 | `getNavRunning()` 裸 `request` → `call()` 共享在途读（`{silent:true}`，周期探测语义不变） | `static/esm/api.js` |

| 三态 | `probeRunning`：null=失败保留现状；`coverage.missing` 非空=部分缺失→`mergeRunningSet` 只并入不清；完整(含空集)→`setRunningSet` 覆盖 | `static/esm/nav_render.js` |
| 存储 | `mergeRunningSet(list)`：把响应里 `work_id:card_id` 确认的条目并入 `temp.running`，未出现条目不删（缺失分片真相不明） | `static/esm/state_layers.js` |

附带修复的既有 bug：旧 `probeRunning` 在 `r=null`（查询失败）时也会 `setRunningSet([])`
清掉运行指示——瞬时失败会把真在跑的卡转圈抹掉。现失败保留。

**mergeRunningSet 的保守性边界**：并入只增不删；属主 runner 已确认缺失的卡
将保留到下一次完整响应才清除。客户端不掌握 卡→runner 属主映射，
无法做「分片内替换」；如需消除该残留，须在扇入条目上带属主标（后续可议）。

## 八、状态正确性收尾（两处显示缺口修复，2026-11-22 收口）

### 8.1 扇入覆盖按「可用响应」计算（`src/infra/procs.py`）

旧实现把 HTTP 200 一律计为已覆盖——`200 text/html` 报 `ok=1/2` 却给
`missing=[]`（吞掉该片运行态），坏 JSON 的 `r.json()` 抛错会把整次
扇入带崩。修复：`_usable()` 逐片校验——非 200、非 JSON Content-Type、
`json()` 解码失败、载荷非 dict/list 一律不计覆盖并进 `missing`，
且计入日志 `runnerN:unusable(http=…,ct=…)`；仍可用的分片照常合并，
全片不可用才 502。pytest 用例补齐 text/html/坏 JSON/标量三形态（7/7）。

### 8.2 画布按属主合并（`static/canvas.js` → `static/esm/state_layers.js`）

旧 `pollPulse` 对 `running` 整表覆盖——部分空快照（`missing:[1]`）把
失联 runner 的卡一并误清。修复：合并逻辑提为纯函数
`mergeCanvasRunning(prev, running, missing)`（state_layers 导出，
与 nav 侧 `mergeRunningSet` 同一契约的 Map 版）：
已应答属主名下由快照替换（含完成清除），失联属主/本地乐观/无属主标
条目保留待校准；完整覆盖仅额外保留乐观项。
