## 三、五个死结（前四个是代码 bug，已修）


### 1. 看不到别人发言（已修）

`_prior_messages` 里 `session_facade.read()` 返回 **list**，代码按 dict 取 `.get("blocks")`
⇒ AttributeError ⇒ 被 `except` 吞成空 ⇒ **"共用现场"这条一直是空的**。

### 2. 从不按职能卡配置的模型跑（已修）

`_model_of` import 的是 `model_config.resolve_card_model` —— **这个函数不存在**
（真名是 `pick(role, work_id=, card_id=)`）。异常被吞后回落 `pick_model("default")`，
所以「每次调用都对应职能卡上配置的模型」这条需求**从来没生效过**。
本次测试碰巧全局默认就是 minimax，所以看不出来。

### 3. 每一次正确的 approve 都被拒（已修）

网关返回的 tool_call 是**扁平**结构：

```json
{"name": "approve", "arguments": {"review_card_id": "card_003"}}
```

代码按 OpenAI 嵌套形态取 `tc["function"]["name"]` ⇒ 恒为空串 ⇒ 走到
「只允许 approve」分支 ⇒ **approve 永远不成立**。两种形态现在都认。

### 4. 模型把批次号当评审卡 id（已修）

上下文里到处是批次号（`rv_xxx`：现状块、发言首行、事件），**评审卡 id 一次都没出现过**。
实测三次调用里，模型两次把 `review_card_id` 填成 `rv_66eed51aaa` ⇒ 被拒。
修法：system prompt 里明写「## 评审卡 id = card_003」，RULES 里点明"不是批次号"。

### 5. 查阅工具一调就「越权」（已修）

你要求「每个角色都能调查阅工具」——工具在册了，但**一调就拒**：

```
list_files → {"ok": false, "error": {"code": "denied", "message": "越权：无权访问 ..."}}
```

原因：评审角色是**职能**，`function_store.create_function` 不建 cards 行 ⇒
`cards.get("fn_001")` 为空 ⇒ `check_file_access(card_meta=None)` 恒 False。
模型以为工具坏了，换个路径再试，于是同一件事连查几十次——**那 57 次不是我一开始以为的
"通读代码库"，是在撞门**。

修法：`review_runner` 给职能补一份 card_meta（按 `policy.perms_for(pc, "function")` 取权限）。

### 5b. 顺带：沙箱里没有代码可读

测试实例把 `file_tools.BASE_DIR` 指到沙箱，沙箱里本来是空的。要让角色真读代码，
把 `src/` `config/` 复制进 `沙箱/推演agent/`（23MB）。生产实例不需要这一步——它本来就能读自己。

### 5c. 收口后状态读不出来（已修）

`close_batch` 把 `batch` 清空，`status()` 照旧拿空批次查 approvals ⇒ `all_passed=False`、
`pending=全体`。实弹收口后读出来就是这样。改成：无进行中批次时以**正稿**为准。

## 三、一个正面证据：共享上下文确实起作用

实弹①的会话里，第 2、3 轮模型自己写了：

> 「本轮卡面与上一轮**逐字相同**」「所以这不是『我还没看到修复』，而是**修复没有发生**」
> 「按上一轮承诺，本轮不再复述四条论证，只记『本轮无进展』」

——它们确实看到了别人的发言、并且认了上一轮的意见（"撤销两条旧意见"）。这条链路通了。

## 五、这轮实测推翻了什么

我原先以为「全员通过」的瓶颈在状态机（版本绑定、收口条件）。实测证明状态机是对的，
**瓶颈在工具链**：approve 的调用名解析、评审卡 id 是否在上下文里、职能能不能真的读到文件。
这三处任何一处断，评审就变成「模型想通过但通不过」。

还有一个更值钱的数：**第一个角色 35 次调用，第二个 6 次**。差距不是模型强弱，
是**共享现场**——第一个人的工具结果留在评审卡会话里，后面的人直接引用。
这正是你要的「一次查证、四人引用」，它在实测里省掉了 80% 的重复查证。
