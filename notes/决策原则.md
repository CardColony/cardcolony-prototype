# 决策原则（2026-10-26 立）

> 用途：**遇到需求没写清的地方，按这八条推，不拍脑袋、不补全、不问人。**
> 用法：每个决定后面标 `[Pn]`，说明依据哪条。用户只需审原则，不必审每个决定。
> 原则冲突时，序号小的优先。

---

## P1 卡面是唯一权威事实源

事实只有一份，存在卡面。会话只记过程，不承载事实。

**能推出**：卡面三块各司其职（使命＝为什么／需求文档＝应然／现状＝实然）；过程不进卡面；评审产出正稿但不写别人卡面。

## P2 机制只管状态，不管内容

系统不判断"对不对"，只记录"有没有 / 是什么"。

**能推出**：不校验语义；不设字数闸、不设墙钟、不设机械闸；`approve` 是工具（二值），理由让模型写文本。

## P3 关键变更走工具，理由走文本

工具调用留痕、可查、可撤；文本不可信。

**能推出**：`approve` / `set_criteria` / `revoke_approve` / `decide` 都是工具；"我改了"是文本，不算数；写卡面也是工具（块级）。

## P4 不防模型，防失真

要防的是「说做了没做 / 做了没留痕 / 留痕了没人能撤」，**不防**「模型会理解错 / 会不自觉」。

**能推出**：不给模型的话加选择条、不要求模型声明或自觉、不用阈值兜底；但要求动作必须留痕。

## P5 结构上不可能 ＞ 断言检查 ＞ 人工检查

能用结构堵死的，不做检查；能自动断言的，不靠人看。

**能推出**：临时卡 `off_tree` 且不设 parent ⇒ 天然不进 nav，而不是在 nav 里加过滤；判据写成 pytest，不靠"我看过了"。

## P6 换上下文，不压缩上下文

不摘要、不截断、不折叠。旧内容不进新上下文，但**完整留在磁盘上**。

**能推出**：批次结束只带正稿（完整文本），过程归档；禁止"压成【结论】＋【依据】"这类做法；正稿是长文本，不因长度被裁。

## P7 结构跟着生命周期走

伴生就一对一、同生共死；一次性就评完归档。名字和结构必须一致。

**能推出**：评审卡是子卡的**伴生卡**（建子卡时自动建、随子卡归档），不是"临时卡"；影子卡与评审卡同族。

## P8 只实现明说的，不补全

用户给一句，就实现那一句。需要补充的地方，按 P1–P7 推；推不出来的，停下来问。

**能推出**：动手前先复述"我要做什么"；不把"用户没说的"当成"我该定的"；小步交付，一步一否。

## 用它们推过的决定（示例）

| 决定 | 依据 |
|---|---|
| 评审卡不设 parent、用 `review_of` 关联 | P5（结构上不进树）＋ P7（伴生≠下级） |
| 画布上它是节点，用 `relations` 连 | P1（节点就是节点）＋ P7 |
| 正稿是长文本，不结构化、不压缩 | P2（不管内容）＋ P6（不压缩） |
| 改判据/改草稿 → 已通过作废 | P3（通过是留痕动作，绑版本） |
| 评审通过后不写子卡卡面 | P1（卡面归主人）＋ P3 |
| 旧工具从工具面物理移除 | P5（结构上不可能被调）＋ P4（不靠模型自觉） |
| 判据写成 pytest，不靠人看 | P5 |
