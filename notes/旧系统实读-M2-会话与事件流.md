### 1.6 事件写入路径与开关

`emit()` 对每条事件做三件写入（顺序固定）：

```python
        journal = _journals.setdefault(key, [])
        evt = _attach_anchors(key, {
            "seq": _next_seq(key),
            "ts": time.time(),
            "type": ev_type,
            "data": _jsonable(data or {}),
        })
        journal.append(evt)
        _persist_frame(work_id, card_id, evt)
        # [消息底座能力对齐 · 件2] 过程事件同步落 events jsonl（裁定 C1）
        _persist_log(work_id, card_id, ev_type, evt["data"], ts=evt.get("ts"))
```
`event_stream.py:476-486`

- `_persist_frame` 受 `_PERSIST_PROCESS` 开关控制，默认 off（`event_stream.py:176-207`，配置位 `config/session_base.json` 的 `persist_process`）；
- `_persist_log` **无条件**写 events jsonl（`event_stream.py:276-295`）；
- `emit_work` 自 2026-10-26 起也落盘到伪卡 `_work`（`event_stream.py:599-615`，`_WORK_EVENT_CARD = "_work"` 于 `event_stream.py:580`）；
- 落盘走 `event_log.append_bg`（有事件循环 → `create_task`；无 → 同步写，`event_log.py:300-320`），落盘失败只 `logger.warning`，不回滚、不抛（`event_stream.py:293-295`）。

## 2. SSE 实现

### 2.1 三条 SSE 端点

| 端点 | 用途 | 订阅源 | 建立位置 |

| `GET /api/works/{work_id}/events` | 工作级（画布） | `event_stream.subscribe_work` | `routes.py:1466-1535` |

三者共同的响应头与首帧：

### 2.2 连接建立与起流游标

- `/stream`：`work_store.read_work` 不存在 → 404（`routes.py:1426-1427`）；`start = frm if frm > 0 else event_stream.journal_last_seq(...) + 1`（`routes.py:1434`）——**from=0 不重放整卡**，游标落在当前末帧之后。
- `/tokens`：`frm>0` 用 `frm`；`replay=1` 时回溯到本 run 的 `run_start` 分段帧 seq；否则 `token_journal_last_seq+1`（`routes.py:1561-1573`）。
- `/events`：无存量重放（`routes.py:1485`、`event_stream.py:626-631`）。

### 2.4 断线重连

- 浏览器侧：`EventSource` 按 `retry: 3000` 自动重连；`es.onerror` 置 `st.esDead = true` 并**只回调一次** `onFail`（`static/stream.js:1512-1519`），由 `workspace.js` 回退轮询（`static/stream.js:39` 注释）。
- 重连 URL 在 `start()` 时一次性拼好，含当时的游标：`const sFrom = st.lastSeq > 0 ? st.lastSeq + 1 : 0;` / `new EventSource(.../stream?from=${sFrom})`（`static/stream.js:1497-1499`）——**重连复用同一 URL，不重算游标**。

### 2.5 推送函数（fanout）

```python
def _fanout(subs: Any, evt: dict[str, Any], work_id: str, card_id: str, channel: str) -> None:
    for q in list(subs):
        try:
            q.put_nowait(evt)
        except asyncio.QueueFull:
            dropped = None
            try:
                dropped = q.get_nowait()          # 丢最旧中间帧，腾位
            except Exception:
                dropped = None
            try:
                q.put_nowait(evt)                 # 保最新帧
            except Exception:
                pass
            logger.warning(
                "[flow] %s 订阅队列满：丢最旧中间帧(seq=%s) 保最新(seq=%s) work=%s card=%s",
                channel, _seq_of(dropped), evt.get("seq"), work_id, card_id,
            )
```
`event_stream.py:331-361`

- 队列容量：主通道 `maxsize=1000`（`event_stream.py:522`）、逐字流 `maxsize=1000`（`event_stream.py:761`）、工作级 `maxsize=200`（`event_stream.py:633`）；
- 满了的处置＝**丢最旧中间帧、保最新帧、打 warning**，后端不补帧（`event_stream.py:338-341`）；
- 单订阅者异常不影响其它订阅者（`event_stream.py:360-361`）。

### 3.2 跨重启是否失效

- **内存游标失效**：`_seq_counters` 是模块级 dict，进程重启后为空 ⇒ 新回合 seq 从 1 起（`event_stream.py:162-165`）；内存 journal 同样为空 ⇒ `journal_last_seq` 返回 0（`event_stream.py:650-657`）。
- **落盘游标不失效**：`event_log` 首次写该卡时 `_tail_seq(path)` 读文件尾 seq 续号（`event_log.py:202-208`、`101-142`）；`/timeline` 返回 `last_seq`（`routes.py:1400`）供前端 `diskSeq` 播种。
- 恢复统一走 `/timeline`（events jsonl），不走 SSE 重放（`routes.py:1420-1424`、`1366-1368`）。
- 已打开的 `EventSource` 在服务重启后自动重连：URL 里的 `from` 是重启前的 `lastSeq+1`，而新 seq 从 1 开始 ⇒ 服务端 `if evt["seq"] <= last: continue`（`event_stream.py:531-532`）会跳过 seq 尚未追上旧游标的帧。**此为按代码推导的行为，本任务未实测**（登记为「未解·待实测」，见 §8）。

### 3.3 journal 裁剪不重置 seq

`_trim_journals` 只删内存 list 头部，`_seq_counters` 不动（`event_stream.py:406-448`，四条铁律注释 `397-405`）；默认保最近 50 轮（`FLOW_JOURNAL_MAX_RUNS`，`event_stream.py:406-419`），`0` 或负＝不裁。

### 4.2 `steer_tail` 在哪些条件下才固化

`_apply_steer` 的分流（`message_runner.py:567-590`）：

```python
    msgs = steer.take_steer(state.work_id, state.card_id)
    if not msgs:
        return 0
    prepared = [{"role": "user", "content": steer.STEER_MARK + t} for t in msgs]
    if into_slot or state.rounds > 1:
        if state.slot is not None:
            for m in prepared:
                state.slot.append_plain(m)
    else:
        state.steer_tail.extend(prepared)
```
`message_runner.py:578-587`

⇒ **rounds==1 且 `into_slot=False`** 时进 `steer_tail`（暂存），否则直接进轮槽。

`steer_tail` 只有 3 个固化出口：

| 出口 | 条件 | 位置 |
|---|---|---|
| `_engage_slot` 内 `for m in state.steer_tail: state.slot.append_plain(m)` | 被调用时 | `message_runner.py:561-564` |
| 工具轮分支内联固化（在用户原文之后） | 本轮**有 tool_calls** 且 `rounds==1` | `message_runner.py:908-913` |
| （`_engage_slot` 的三个调用点） | ① 有活板且本轮空手（催作业）`853`；② 文本抢救回注 `870`；③ 工具轮 `915` | `message_runner.py:853`、`870`、`915` |

`_engage_slot` 自身有幂等闸：`if state.turn_tail_engaged: return`（`message_runner.py:554-556`）。

### 4.3 结论：无工具调用的纯对话轮，插话是否被取用？

**分三种到达时机，结论不同（不是一句话能答完的）：**

**① 插话在本轮模型调用期间到达 → 会被取用（生效）**

模型返回、判定「无 tool_calls」之后，代码先查一次待投插话：

```python
    if not tool_calls:
        # [5715] 插话优先于收口：模型这一轮没调工具、正文已定（**正要收口**），
        # 但用户在模型跑的时候插了话 ⇒ 不收口，把插话插进轮槽、继续下一轮。
        # 否则那句话会被丢掉（回合收口即清扫残留）——用户说了话，却没人听见。
        if steer.pending_steer(state.work_id, state.card_id) > 0:
            _apply_steer(state, into_slot=True)
            state.user_prompt = "用户在你回答时插了话。先读那条插话，再继续。"
            return StepOutcome("continue", "steered")
```
`message_runner.py:856-863`

`into_slot=True` ⇒ 直接 `slot.append_plain`（绕过 `steer_tail`），下一轮 `rounds=2` 走 `wire_messages()` 装配（`message_runner.py:770`、`776-779`）⇒ 插话在上下文里。**这是「无工具轮插话生效」的唯一代码路径，行号：`message_runner.py:860-863`。**

**② 插话在 round1 的 `_apply_steer` 之前到达（回合刚起、模型还没发请求）→ 不生效，且被丢弃**

此时 `state.rounds == 1` ⇒ 进 `steer_tail`（`message_runner.py:586-587`）。纯对话轮（无 tool_calls、无活板、无文本抢救）不会走到 `_engage_slot` 的三个调用点（`853`/`870`/`915` 都不执行），也不会走 `910-913` ⇒ `steer_tail` **永不固化**；而 `_pending` 已被 `take_steer` pop 掉（`steer.py:89`），所以也不会被下一次 `pending_steer` 查到。代码注释直接写明这一条：

```python
    - ``into_slot=True``（**收口时**插话）：直接进轮槽 ⇒ 下一轮 prior 立刻带上它。
      收口时的插话是「模型这轮没看到、用户又补了一句」⇒ 必须真的进下一轮上下文。
      （若走 steer_tail，无工具轮的 steer_tail 永远不被固化 ⇒ 插话丢失——实测踩过。）
```
`message_runner.py:570-573`

**③ 插话在收口判定之后到达（模型已返回、`pending_steer` 检查已过）→ 不生效，被清扫**

回合 `finally` 里 `steer.discard_steer`（`routes.py:2533`）；`discard_steer` 的 docstring 明确「不能留给下一回合」（`steer.py:100-109`）。

**④ 补充事实：提交轮（三席/统合）期间到达的插话不会被取用**

`run_seats`（`message_runner.py:1155-1257`）全文无 `_apply_steer`/`pending_steer` 调用 ⇒ 该窗口内投递的插话只能等回合 `finally` 被 `discard_steer` 清掉。

### 4.4 其它登记事实

- 插话**不写会话块**：只进轮槽 + 事件日志（`steer.py:32-33`），所以下一回合的 `prior` 里没有它；`user_message` 事件只是界面可见（`steer.py:69-74`）。
- 无在途回合 ⇒ 不投递（`steer.py:63-66`）；在途判定＝`session_facade._active_turns`（进程内存 dict，`session_facade.py:1167-1188`），登记发生在 `_run_message` 入口（`routes.py:2457-2458`），释放发生在 `finally`（`routes.py:2534`）。
- 插话消息的 role 是 `user`（`message_runner.py:581`），带 `〔用户插话〕` 前缀（`steer.py:48`）。

### 6.3 跨卡串台风险 — 代码依据（只登记事实）

1. **主通道不串**：所有 `emit` 都带 `(work_id, card_id)` 且入表用 `_key()`（`event_stream.py:217-218`、`459`）。

3. **发信事件写在收件方键上**：`_h_send_card_message` 的 `emit_message_event(work_id, target_id, ...)`、`emit(work_id, target_id, "card_message", ...)`、`emit_work(...)`（`card_tools.py:3919-3929`、`3939-3941`）——发件方自己的事件流里没有这条（`ops_log("card_msg_send")` 记在发件方，`card_tools.py:3896-3897`）。

5. **contextvar 继承**：`_stream_ctx` 由 `_run_message` 设置/还原（`routes.py:2453`、`2537`）；`asyncio.create_task` 创建的子任务会继承创建时的上下文值（Python 语义）。子任务里若调用 `model_service.call_main` 而自身未重设上下文，逐字流会落到**父回合的卡**上。当前代码里起轮的子任务都经 `_run_message` 入口（`message_runner.py:1837-1839`、`1946-1948`；`goal/driver.py:259-261`）⇒ 入口即重设。**未找到未重设的调用路径；此为按代码推导，未实测。**
6. **ACP 侧确有跨会话混流**（已过滤）：`wb_exec` 注释记「同一 ACP 连接上别的会话的事件会串进来」，按 `sessionId` 过滤（`bridge.py:874-877`）。

## 10. 结论速览（供 report_done 引用）

1. 事件类型：命名空间去重 **63** 类（`EVENT_TYPES` 29 + 表外 emit 19 + 逐字流 1 + 工作级 2 + 消息块 8 + 无发点 4 的重复计入关系见 §1.0），其中**有真实发点 59 类**；另 8 类只落盘不进 SSE。
2. 无工具轮插话：**在「本轮模型调用期间」到达会生效**（`message_runner.py:860-863` 的 `pending_steer>0` → `_apply_steer(into_slot=True)` → `continue("steered")`）；**在 round1 首次 `_apply_steer` 之前到达则不生效**（进 `steer_tail`，纯对话轮无固化出口，`message_runner.py:586-587` + `561-564`/`908-913` 均不执行）；**收口后到达被 `discard_steer` 清掉**（`routes.py:2533`）。
3. SSE 三条流（`/stream` 15s、`/events` 15s、`/tokens` 10s 心跳），均为 `text/event-stream` + `retry: 3000` + 注释帧保活，心跳不占 seq。
4. 游标两套空间：前端 `lastSeq`（内存 journal，重启归零）与 `diskSeq`（落盘 events，文件尾续号），严禁互写（`stream.js:1032-1035`）。
5. 流式无截断（8KB/5000 条闸均已删），截断只存在于 `/timeline` 响应层（`payload_cap`：64KB/5000 节点/256KB）与若干日志/回执字段。
