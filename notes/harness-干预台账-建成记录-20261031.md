## 顺手修了一个真 bug（死规则）

`review_all_passed` 发射时带 `need_promote`/`target`，但 catalog 只声明了 `batch`/`members` 零件 ⇒ `flatten_parts` 丢弃 ⇒ `where:{need_promote:true}` 永不命中 ⇒ **`review_all_passed_need_promote` 策略自写进配置起一次都没真正触发过**。已把两字段补进零件表，端到端测试（`test_feed_promote_chain_e2e`）钉住。

这类"合法但永远不响"正是 S0 要清的病根之一。后续应给校验器加"where 引用的键必须在 catalog 零件里"的静态检查（未做，记入遗留）。

## 定稿试点现在的行为链

1. `review_all_passed{need_promote:true}` 落盘 → feed → 命中 → **同步**立案（matter b1）+登记 continue 动作 → 后台投递。
2. 投前 `action_skip` 复核：批已收口 ⇒ 关事项、动作 stale、不叫醒。
3. `continue` 叫醒评审卡 → 模型调 `promote_draft` → 正稿写入 + `finalize` 收口 → `review_batch_closed` 事件 → `on_fact` 复核：批次清空+verdict ⇒ **resolved（带证据）**。
4. 重启：`resume` 复核事项（已解决→关）→ pending/failed 动作先查 facts.db 里 `harness_message.action_id`（已送过→标 delivered 跳过）→ `action_skip`（事项关→stale）→ 才重投。

## 遗留与边界

- `harness.db` 不进七天保留（运行责任，非事实缓存）；暂无清理策略，事项量大后可加归档。

## 增补：``then.deploy`` 派差事（第四手段，2026-11-01）

### 一句话

harness 现在除了"送话"（message/inject/continue）还会"派人"：策略命中 →
落一行差事账（`function_deployments`）→ 职能带着差事文进场跑一轮。
**机制层只有通用件；派谁、什么时候派，全是策略文件里的字。**

### 一条 deploy 走完的路

1. `record_fired`（feed 同步段）：`then.deploy` 形状 → 场（`deploy.venue`）
   走 `resolve_targets(allow_self=True)`——场可以是触发卡本身（QA 就在报
   完工的卡上跑验收）；职能 `event:`/code 解析、`function_exists` 实存校验
   （`identity_for` 对查不到的会回显输入，不校验会"解析成功"假象）；
   职能/场型/ctx/退出规格全落 `actions.spec`（重启恢复不依赖当时 ctx 重算）；
   mandate 按场渲染进 `message`；`fire_key` 缀职能（同触发同一场派不同
   职能是两笔账）。
2. `deliver_fired`：deploy 走**独立 dispatch**——不送进话管线。从动作行
   取 spec+mandate 调 `deploy_runner.execute`；receipt 整 dict 落台账。
3. `deploy_runner.execute`：`identity_for` 取人格 → `grant_for` 场授面 →
   `create_deployment` 落账（**幂等**，同键在派差事返回既有行）→
   `activate_deployment` → `routes._run_message(act_as, act_meta, ctx_card,
   tool_allow)` 唤起（与评审席位同一条路）→ `harness_message{mode:deploy,
   action_id, deployment_id}` 回执事件（重启查重锚）。
4. 两段式回执同 message+wake：账建了但场叫不醒（halted/锁冲突/模型挂）
   ⇒ `ok=False` 记 failed → `resume` 重派时 `create_deployment` 幂等返回
   既有行、只补唤起不重建账。
5. 差事的"办完关账"由 deployments 账自己管（`close_deployment` +
   `deployment_closed` 事件，已登记 catalog，triggerable——后续策略可拿
   它做关账依据）；干预台账只保"这一派发没发出去"，不平行再造一套差事账。

### 修掉的两个契约坑（与 need_promote 同型）

- `msg_report` 的 `kind`：`_h_report_up` 发射时 `extra={"kind":…}` 带它，
  零件表没声明 ⇒ `trigger_data.kind` 永远空 ⇒ 验收策略死规则。已补 optional。
- `harness_message` 的 `action_id`/`mode`/`queue_len`/`started`/`reason`：
  投递回执实发这些字段，零件表只剩 `wake`/`seq` ⇒ **重启查重锚
  （action_id）整批被丢**——resume 的"已送过跳过"实际查不到任何行。
  已补全，另加 deploy 用的 `deployment_id`/`error`。
- `deployment_created`/`deployment_closed`：差事账已发射，补登记进目录。

### 配置侧（策略文件写字，零代码）

`harness_policies.json` v3：`staff_qa_on_stage_done`——
`msg_report{kind:done}` ⇒ 给 QA 在报完工的卡上派验收差事
（venue_kind=deploy、exit=explicit、内联 mandate）。
按用户草图落地，三处契约修正：`venue_kind "acceptance"→"deploy"`
（VENUE_KINDS 白名单内）、`venue "event:target"→"event:card"`（msg_report
没有 target 零件，场＝报完工的发卡方）、`mandate_template` 目录无此项
→ 改内联 mandate。撤岗＝active:false。

### 新增测试（tests/test_deploy_runner.py，9 例）

落账形状（场=target、spec 全量、mandate 渲染、fire_key 缀职能）｜
职能未解析仍记账｜执行全链（差事 active、act_as/ctx/授面、回执事件）｜
幂等重派不双开｜解不出零副作用｜叫不醒记 failed 留账｜deliver_fired
独立 dispatch｜resume 重派走部署执行器｜feed 端到端（kind=done 命中、
kind=blocked 不命中）。

### 边界与遗留

- `function_ledger` 仍是 triggerable=false——「写分歧→总裁看到」用专用
  `divergence_written` 事件还是翻开关，留给用户裁定（避免台账自触发循环）。
- `resolve_targets` 新增 `allow_self` 参数（默认 False，旧调用方逐字不变）；
  只 deploy 传 True。
- `get_deployment` 存量 bug 顺手修：读路径里做 DDL（`_ensure_deployments`）
  撞只读连接——按 `_query_deployments`/`has_prior` 同一口径改成
  OperationalError 兜底。
- deploy 差事的"办完关账"判定靠派遣方/关账事件，不由台账自动判完成——
  想加"差事长期不关"巡检可后续用 deployment_created/check_on 写策略。
- `deliver_fired` 台账缺席回退路径按 `then.deploy.venue` 解场（同
  record_fired 口径）。
- 真实模型跑一遍 QA 验收差事的现场验证未做（链路已测通，需真模型环境）。

### 增补：QA 差事改为「交活即关账」（2026-11-01，配合职能线 sweep）

职能线补完差事生命周期后半段：`deliverable` 核对器（exit_spec=
``ledger:<code>``——职能往指定台账落笔即办完）、`sweep_deployments`
（惰性判完持久关账：status=done+closed_at+deployment_closed 事件，
挂进 create_deployment/add_ledger_entry 两个写路径）、`identity_for`
补 `resolved` 位（幽灵职能从源头消掉，我们的 function_exists 校验
保留作双保险）。

``staff_qa_on_stage_done`` 相应从 ``explicit`` 改 ``deliverable`` +
``ledger:criteria``：验收差事的本义是"去核、写结论"——结论落进判据
与验收台账（criteria）即交活关账，不留"开给 QA 盯到用户确认"的
常驻在派。mandate 同步点名台账（不写清写哪本，核对器认不到）。

**已知边角**：核对器按 ``ledger_code+ts`` 判，不看写给谁——QA 若同
时挂着多张验收差事，一条结论会把它们全判完。并发验收差事真实出现
时再让职能线给 exit_spec 加按场匹配。

**deployment_closed 事件走 append_bg 异步落盘**——读侧立即断言会空，
测试用 wait_until；策略侧无所谓（本来就吃异步事实）。

## 错误台账（2026-11-01 · 用户令「错误的收集和记录先立住」）

### 定位

错误定义的完整模型（四层：事实/义务/行为/机制）尚在讨论中——本轮只做
**最小有用层**：让所有出错环节进一本可查的账，不再只留日志。

### 建成的件

| 件 | 落点 | 语义 |
|---|---|---|
| ``errors`` 表 | ``harness.db``（与 matters/actions 同库） | 一行一个错误签名：stage+kind+policy/action/matter/card 归属+key |
| 去重累计 | ``record_error`` UPSERT | 同一签名反复发生不刷行数：count++、last_ts/最新凭据刷新 |
| 读面 | ``list_errors(limit)``；``status()`` 加 ``errors`` 段 | 一个查询面看全部错误 |

### stage 口径（环节，不是错误分类学）

``resolve``（目标解析）/ ``record``（落账）/ ``deliver``（投递、含
skip_check_exc/dedup_exc/delivery_failed/deploy_failed）/ ``check``
（解除判定异常）/ ``ingest``/``dispatch``/``resume``/``config``
（策略加载错——dispatcher() 原本丢弃 load() 返回，现留在
``PolicySet.load_errors``，首个 feed 按清单指纹补记一轮，不重复计）/
``bootstrap``（回溯各阶段）。

### 接入的失声点（原来只进日志）

record_fired：resolve 异常、立案落空、登记动作失败；
deliver_fired：no_targets、投前复核异常、deploy 失败、整 fired 异常；
mark_receipt：投递失败；resume：重投异常、deploy 重投失败；
feed：ingest/dispatch/record/check 各环节；bootstrap：三个阶段。

### 明确没做

- 判不出三态（check 仍兜底 open，错计入账但状态不标 unknown）
- failed 重试上限/abandoned 终态
- 死规则静态校验（field 引用 vs 零件表）
- 行为层信号（用法盘点/习惯计数）——判定语义待议
- errors→事件流/分析卡消费口（现在的消费面是 status()）

check 异常累计、投递失败、加载错指纹去重、status 含 errors）。
