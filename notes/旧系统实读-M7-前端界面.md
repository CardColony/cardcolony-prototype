## 3. 滚动与渲染（重点）

### 3.1 结论：新事件到达**不会**无条件滚到底

- 原 `scrollBottom(st)`（每帧强制滚底）已删除，代码里只剩退役说明：`stream.js:145-147`
  ```js
  /* [对话流照抄 dsh v3 · §三 退役清单] 原 scrollBottom(st)（每帧强制滚到底）
     已删除：滚动跟随改由 flow/chat-view 的 24px 阈值 ＋ 读者滚动台账负责 */
  ```
- 现役跟随逻辑全部在 `esm/flow/chat-view.js`：
  - 阈值 `const FOLLOW_THRESHOLD = 24;`（`chat-view.js:22`）
  - 判据：`movedByReader = Math.abs(stTop - Math.min(observedTop, floor)) > 0.5`，只有"读者真实滚动"才改变跟随权（`chat-view.js:212-215`）
  - `toBottom()` 只在四种时机被调用：
    1. 首屏首次落位 `if (!opened) { opened = true; toBottom(); … }`（`chat-view.js:338-344`）——**打开卡时无条件到底**
    2. 新用户节点追加 `appendedUser` 或 `tipMoved && atBottom`（`chat-view.js:358-363`）
    3. `handleScroll` 中"程序写入未偏移且仍在底"（`chat-view.js:216`）
    4. 用户点回底按钮（`chat-view.js:264-275`）
  - `ResizeObserver` 仅 `atBottom` 时钉底（`chat-view.js:419-428`）
- 例外（确实无条件滚到底的两处，但都**不在** SSE 新事件路径上）：
  - `canvas.js:6442` `if (body) body.scrollTop = body.scrollHeight;` —— 位于 `renderWatchLayer()` 逐窗口初始化末尾，窗口增删/切全文/折叠时整层重建才触发；SSE 新帧走 `loadWatch→updateWatchBodies`，那里有 48px 判据（`canvas.js:6339-6341`）。
  - `canvas.js:3247` `if (log) log.scrollTop = log.scrollHeight;` —— `loadCell()` 每次重载就地对话后无条件到底（打开/发送后触发）。
- 另有一处"假滚动"：`workspace.js:1891-1893`
  ```js
  function scrollChatBottom() {
    chatArea.scrollTop = chatArea.scrollHeight;
  }
  ```
  `#chatArea` 的 class 是 `.chat`，而 `.chat { overflow: hidden; }`（`style.css:1446-1451`、`ui.css:590-598`），真实滚动口已下沉到 `.flow-view-scroll { overflow-y: auto; }`（`style.css:1472-1478`）。因此该函数对其目标元素是空操作。三个调用点：`workspace.js:368`（切卡后）、`491`（新卡草稿）、`528`（新项目草稿页）。
