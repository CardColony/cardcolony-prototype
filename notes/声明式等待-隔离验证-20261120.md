## 核对契约（机械判据）

放行＝四件全过：类型合 expect ∧ reply_to 逐字等 task_id ∧ 来源卡等
登记 from ∧ 回执 target_rev（若有）等等待版本。任一不符 ⇒ 不解除；
看得见回执证明不了归属 ⇒ unverified。重复回执幂等（satisfied 只记
一次，by_seq 不复写）。人工停止硬闸：is_halted 非空 ⇒ 回执到了也不
点火，显式 unhalt 才恢复。

## Python 原型收口

`ECO_GOAL_WAIT_WORKS` 按逗号分隔的 work ID 启用等待机制。默认关闭。观察日志由 `ECO_SHADOW_WORKS` 单独开启，示例隔离试点可以给两个变量填同一个 work ID。

跨 runner 转发保留回执类型和派工引用。试点派工写入发件方目标 ID 与版本，按派工双方校验。worker 创建返回 `task_id`，首轮完工沿原派工落结构化回执。旧派工缺少目标 ID 时标为待核实。等待恢复权由目标驱动在首个实际模型调用前消费。无新待办时停在可见状态并释放串行执行锁。影子账的 `model_request` 在 `call_main` 边界记录，每次重发单独计数。

复跑隔离回归用 `PYTHONPATH=tests python -m pytest tests/test_goal_waits.py tests/test_goal_shadow.py tests/test_forward_ctl.py tests/test_goal_reactivate.py -q`。用例覆盖真实模型工具派发、汇报入账、worker 完工、属主请求模型与实际请求数。模型服务替身只用于隔离计数与给出可控结果。
