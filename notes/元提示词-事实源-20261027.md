# 元提示词 · 事实源机制（2026-10-27）

> 用户要求：「系统元提示词部分，也需要用机制去保证内容的准确性，而不是靠模型遵守迭代规范，
> 在迭代后主动修改，而且这也有风险」

---

## 一、元提示词里混着两种东西

| | 例子 | 会变吗 | 该怎么处理 |
|---|---|---|---|
| **事实** | 有三条线、三块叫什么、有哪些工具／消息类型／错误码／卡类型 | **会变** | **不许手写**——从源头渲染 |
| **判断** | 过程不进卡面、汇报写证据不自述成功、改之前先读 | 不会变 | 手写，但断言必须提到关键事实 |

一句话：**事实不许手写，判断不许自动生成。**

改前的问题不是「写得不好」，是**事实全在手写**——加一个工具、改一个字段、加一种消息类型，
提示词不知道。靠"改代码时记得同步改提示词"＝靠自觉，而自觉会漏。

## 二、实测的 8 类不一致（可复算）

跑 `scripts/prompt_audit.py` 的输出：

```
1. 错误码      代码 7 种，提示词漏 2 种：invalid、ambiguous
2. 消息类型    注册表 7 种，提示词漏 4 种：msg_sync、msg_directive、msg_report、coder_done
3. 幽灵工具    run_tool_card —— 提示词写着，注册表里没有（handler 在，从没注册）
4. 按卡型      card_061 实际 43 件，提示词列了 12 件它拿不到的
              （bash / write_file / python / edit_file / report_done / send_card_message …）
              fn_004 实际 37 件，列了 9 件拿不到的
```

`invalid` 是通信工具最常用的码（「不能给自己发消息」就是它），`ambiguous` 是精准编辑
多处命中的码——**模型收到这两个码，提示词里查不到是什么意思**。

`msg_sync` / `msg_directive` / `msg_report` 是线上真实在传的三类消息（330 / 79 / 113 条事件），
模型收到时提示词里同样没有它们的说明。

还有一处：`hash_utils.py:186` 的注释还写「新区名…## 定论」，而 106 行早已统一为「## 需求文档」。
**注释、代码、提示词三处各写一版**——这正是"没有事实源"的样子。

## 三、机制：先有源，再谈准确

### ① `src/api/prompt_facts.py` —— 每类事实只有一个源

| 事实 | 源 | 谁保证与代码一致 |
|---|---|---|
| 三条线（管什么／**不管什么**） | `LINES`（新建声明） | `test_three_lines_declared` |
| 卡面三块 | 从 `hash_utils.NEW_SECTION_MAPPING` **派生** | `test_blocks_come_from_source` |
| 错误码 | `ERROR_CODES`（唯一枚举） | 扫源码 `err("...")`，**新增未登记就红** |
| 消息类型 | `card_msg.type_codes()` | 直接取注册表 |
| 卡类型 | `card_type_registry.json` | 直接取 |
| 职能 | `function_catalog.json` | 直接取 |
| 工具 | `tool_doc.ToolDoc`（上一轮已建） | AST 对照 handler |

**三条线原本根本没有源**——职责散在注释、提示词、字段名三处。这次把它写成声明，
并且**每条线必须写「不管什么」**：`parent` 不承载通信、`links` 不管权限、`relations` 不通信也不管权限。
只写「管什么」，混用就是这么来的。

### ② `scripts/prompt_audit.py` —— 随时可查

四类检查，输出不一致清单，退出码非 0 即有不一致。改提示词前后各跑一次。

### ③ `tests/test_prompt_facts.py` —— 12 条钉住

**硬断言**（现在就必须成立）：
- 代码里每个 `err("...")` 的 code 都在 `ERROR_CODES` 里
- 每个 code 都有「收到该怎么办」
- 提示词里提到的工具名必须在注册表（幽灵检测）
- 三条线各有 duty 与 cannot
- 三块从 `hash_utils` 派生

**待补清单**（`PENDING_CODES` / `PENDING_MSG_TYPES` / `PENDING_GHOSTS`，**只能减不能增**）：
- 新加一种错误码／消息类型而提示词不写 ⇒ 红
- 修好一条要从 PENDING 删掉，否则「表烂掉」也红

### ④ 判断段仍然手写，但要求它提到关键事实

「做事的方法与顺序」「自动模式」这些是判断，不自动生成。它们的准确性靠另一条：
**每段判断必须提到它依赖的事实**（例如「过程不进卡面」必须提到三块的名字）。
这一条还没做成断言，是下一步。
