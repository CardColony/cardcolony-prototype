## 1. 一个结构性提案：字段分两类

现在的字段是平铺的，分不出"这是零件"还是"这是原文"。建议契约里把字段分成两类：

- **零件（part）**：可作条件维度，短、可枚举、可比较。如 `tool` / `ok` / `from` / `msg_type` / `kind` / `block` / `by` / `cause`。
- **载荷（payload）**：原文全文，供人看、供事后分析。如 `content` / `text` / `result` / `old` / `new`。

> **这个分类只用来说明「哪些字段不许拿来当条件」，不是寿命约定。**
> 原文一律不动（见第 0 节）。早先把它当"7 天清理的对象"是错的。

### K. 思考流

| 事件 | 现有零件 | 说明 |
|---|---|---|
| `reasoning` | text | **这才是「思考块」**：每轮一条，把该轮的逐字思考合并成全文后落盘（20,679 条） |

## 4. 字段契约草案

catalog 每条加一个 `fields` 块：

```json
"tool_result": {
  "label": "工具结果", "group": "工具", "source": "message_runner.step",
  "channel": "card", "triggerable": false,
  "fields": {
    "part":     ["tool", "ok", "target", "tool_call_id", "step_id", "round"],
    "optional": ["status", "summary", "error_code", "elapsed_ms"],
    "payload":  ["result"]
  }
}
```

三条规则：

1. **`part` 缺一个 ⇒ 测试红**。这就是"报备"的实质：报的不只是类型名，是它必须带的零件。
2. **`payload` 不进条件面**，但照收、**永不清**（它是原文，见第 0 节）。
3. **`optional` 允许缺**，但缺了要在测试里说明为什么（比如错误路径上 `status` 天然没有）。

`card_block_edited` 可以直接照现状写成契约，不用改代码：

```json
"card_block_edited": {
  "fields": {
    "part": ["card_type", "block", "by", "cause"],
    "payload": ["old", "new"]
  }
}
```

### 6. 顺带修掉一个通道用错

`wb_exec/bridge.py` 把外部执行体的思考用 `event_stream.emit` 发（主通道，**逐帧落盘**），

独有的 `step` 字段，集中在跑过外部执行体的两个 work（work_027 122 万 / work_025 8.6 万）。

已改回 `emit_token`。**思考不丢**（仍合并成 `reasoning` 全文落盘），只是不再逐帧占盘。

## 二、第 2 步：条件组合机制

### 换掉了什么

旧机制：`GUARD_KINDS` 白名单（只两种）+ `where` 只认顶层键 + 只能"等于"。
新机制（`src/infra/harness_cond.py`）：**条件是一棵 JSON 树**，任意嵌套。

```
{"all": [...]}  {"any": [...]}  {"not": c}
{"event": spec}                          选中至少一条事件
{"count": spec, "cmp": ">=", "value": 2} 选中事件条数
{"field": "state", "cmp": "eq", "value": "blocked"}

spec = {"types": [...], "where": {...}, "within": "turn|card|all|{last:N}"}
where 键支持点号路径（result.ok）；值可写 {"gt":5} 等比较器；$ 开头取本卡字段
比较器：eq / ne / gt / ge / lt / le / in / contains / exists / matches
```

**旧写法自动翻译**（`no_event` / `has_event` 逐字等价），现役规则不用改。

### 修掉一个窗口缺陷

旧 `scope=turn` 的窗口算法是「跳过第一个 turn_end、遇第二个才停」。但生产顺序是
**done → turn_end**（done 在 finish 发、turn_end 在 finally 发），所以 `done` 触发那刻
本轮的 turn_end **还没写**——往前遇到的第一个 turn_end 其实是**上一轮**的，被当成
"自己的"跳过后，窗口就跨进了上一轮。

后果：上一轮汇报过 ⇒ 本轮被判成"已汇报" ⇒ 该提醒的不提醒。旧测试没抓到，是因为它
按 turn_end → done 的**假顺序**造事件，正好绕过了这个缺陷。

改用 `run_start` 作锚（一轮＝一个 run，顺序上必然在触发事件之前），不再受
done/turn_end 先后影响。

### 零墙钟的边界（已写进规则表 `_meta`）

- 禁的是**由时间驱动系统**：定时唤醒、超时兜底、轮询补漏；
- 不禁**把 ts 当事实查询**：条件在触发那一刻求值，没有任何东西在等。
  所以 `ts` 就是普通字段，可以 `gt/lt` 比较。
