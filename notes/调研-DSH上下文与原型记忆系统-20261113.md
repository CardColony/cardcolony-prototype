## 一、一页结论

**DSH 本仓可直接采用的机制**（v2.0 Context Line 侧）：

1. **"模型可见 ⟺ 已记录"的结构性保证**：`request/header` 全量规范快照（system+tools+config）落 append-only 日志、折叠可复原任一请求的头部；`deriveEventMessage` 是投影的唯一规则函数；surface 遮蔽（`surfaceOp: replace`）只动投影不动原日志（`packages/core/session/src/request-header.ts:21-71`、`surface.ts:35-83`；根 AGENTS.md 明令此纪律）。原型只有文件级 `prompt_log`（`src/api/prompt_log.py:75-140`）＋ `origin_store` 双写，达不到"任一历史请求可复原"的强度。
2. **compaction 三段式留痕**：`compaction/start`（未配对的 start 即持久锁）→ `summary` → `end`；替换写进 surface、原文全留；失败区分取消/模型错/区间错（`packages/compaction` README）。原型的 mark 只存一个数，无锁记录、无崩溃检测语义——崩溃后分不清"在凝"还是"凝完了"，靠 `_FLYING` 台账+900s 超时放锁补救（`memory_store.py:2696-2755`）。
3. **session 表面投影与原文分层**：surface = 日志→LLM 消息的派生视图，原文日志是真相（`surface.ts:1-10`）。原型的 `context_board` 是同一思想的物化板（`context_board.py:1-30`），但它是为修"四层筛子 bug"而生的补丁层，v2.0 应把"写时维护的投影板"作为一等设计而不是补丁。
4. **信任分层**：`session-reference` 把别的会话快照标注为**不可信、非指令**注入；`agent-instructions` 记录 typed source（谁写的、基线还是动态）。原型记忆区对模型没有任何信任标注。

**必须重设计的部分**（v2.0 Memory 子系统）：

- 原型记忆系统整体方向可用（因果链 + coveredSeqs 机械追溯 + 降层归拢 + 水位+板同事务），但有四处不能照搬：① fold 提交侧"代码不裁判模型产出"（`memory_store.py:2534-2536`，2026-09-24 裁定拆掉所有代码校验），归拢是全文幻觉风险最高的点，只剩 I1–I5 体检只记不阻断（`memory_store.py:2643-2649`）；② 记忆多形态存储（memory 表 chain + entries 双写 + memory_nodes 物化 + memory_archive 冻结）有"链覆写丢件"前科（`memory_domain.py:425-431`）；③ `memory_expand` 的 degraded 再描述**只标记不调模型**（`memory_expand.py:25-27,116-120`），降级条目不会自愈；④ 前端"点开记忆看原文"**未实现**（static/ 全仓无 memory UI，仅 `nav_system.js:383` 一处无关注释），模型侧 `memory_expand` 工具是唯一回溯口。

**原型补丁不应继承**：

- `context_board` 的懒自愈+60s 节流是"写路径曾经静默失败"的善后（`context_board.py:148-177`；`origin_store.py:150-162`）；
- `_read_origin` 只读 sqlite 的裁定附带"库写失败不再静默"补丁（`origin_store.py:150-162`、`memory_store.py:2805-2816`）；
- wire 投影四道闸是"工具轮折叠被裁定删除"后的体积补救（`tool_fold.py:39-78`）；
- `review_scope` 评审蒸发是产品策略硬编码（`review_scope.py:1-27`），不应进通用记忆架构。

## 二、DSH 本仓：上下文插件与内核机制全景

> 本仓是"一切即插件"的 Cordis 架构（根 `AGENTS.md`；`docs/architecture.md`）。以下逐条已在源码/README 核实。

### 2.1 上下文贡献者（context plugins）

- `packages/context/` 下的插件（`agent-instructions`、`session-reference`、`time-context`、`tmux-context`）是**请求上下文扩展**：向 `ctx.systemPrompt` 注册段落/动态变量/工具 schema，不必自带工具（`packages/context/README.md`）。
- `ctx.systemPrompt.assemble()`：合并全局层+作用域层、按 scope 过滤、解析动态变量、连同工具 schema 一起产出单一 `PromptAssembly`；段落按数值带排序，"complete section" 可抑制其它段；provider/listener 失败与 dispose 属插件生命周期语义（同 README）。
- 卸载：注册皆经 `ctx.effect()`/`ctx.on()`，`register()` 返回 disposer（根 AGENTS.md「Registrations are effects」；`packages/AGENTS.md` 要求注册可 dispose 的 HMR 测试）。

### 2.2 会话日志 → 模型可见 surface

- append-only 日志是真相源；surface 是"产生 LLM 消息的事件的有序视图"（`surface.ts:1-10`）。
- `isSurfaceEvent`：仅 `user/message`、`assistant/message`、`tool/result` 三型可进 surface（`surface.ts:15-38`）。
- `surfaceOp`：`append`（自身位置进场、从未是替换副本）vs `replace`（遮蔽既有区间）。**append-origin 才是给人看的持久转录**，replace 副本只存在于模型视野（`surface.ts:41-68`）。
- `deriveEventMessage`：单事件→Message 的**唯一投影规则**，live surface 与离线重放共用（`surface.ts:70-83`）。
- "模型可见 ⟺ 已记录"：任何到达模型请求的内容必须能从 session 日志重建；新模型可见输入 = 新 session 事件（根 AGENTS.md 明令）。

### 2.3 request/header 快照

- `request/header` 事件存**全量规范快照**（config + system + tools + adapterDefaults），`canonicalHeader` 归一（空 system/tools 变 absent），`headerEquals` 去重（只在变化时落新快照），`foldRequestHeader` 折叠任一日志前缀得当时头部（`request-header.ts:21-71`）。⇒ 任一历史请求的"模型当时看到了什么头"可复原。

### 2.4 compaction

- `CompactionEngine`：`compactIfNeeded`（token 压力）、`compactNow`、`compactRegion`（按 **surface 位置区间**，非裸 seq 区间）。
- 持久记录：`compaction/start`（未配对 start = 持久锁；`session/end-seed` 之后的新 start 视为在途/忙，更老的判为陈旧）、`compaction/summary`、`compaction/end`。摘要写进 surface 遮蔽区间，原文事件全留（`packages/compaction/README.md`）。
- 后端：`dsh-compaction-basic`（token 压力+摘要模型）、`dsh-compaction-tool-result-pruner`（**无模型**剪枝：工具结果超限时替换为有界 head/marker/tail，原事件保留可重放/查原文）、`dsh-command-compact`（`/compact` 命令）。

### 2.5 token-meter / spill / 剪枝

- `token-meter`：对持久日志做**重放感知折叠**，提供隔离计量（`packages/llm/token-meter/README.md`；`src/surface-fold.ts`/`surface-projection.ts`/`usage-projection.ts`）。独立于 CompactionEngine。
- `spill`：超大工具结果落盘，行内换成有界预览+定位符（locator 可取回全文）。
- 工具结果剪枝：调用/结果配对保持；剪枝只改投影内容、原结果事件仍在日志。

### 2.6 来源标注与信任分层

- `agent-instructions`：指令以 typed source 元数据记录（基线 vs 动态变更），非隐藏 prompt 标记。
- `session-reference`：注入他会话的**有界快照**并显式警告"不可信、非指令"；是快照不是活链。
- `time-context`：请求级浏览器时区出处，注入逐步持久上下文。

### 2.7 与 CardColony "记忆区块/归拢"的对应

**无对应，只有 compaction/session projection。** DSH 本仓没有任何"长期记忆条目、层级折叠、gist/描述层、锚点回查原文"的机制；compaction 是"摘要遮蔽 surface 区间+原文保留"的单层投影操作。原型注释里的 dsh(gen3) 记忆体系（因果链、归拢、expand、生命周期）不在本仓，无法在本仓核实其原始实现——**凡原型声称"照抄 dsh gen3"处，移植忠实度本身未核实**（只能核实原型代码做了什么）。

## 三、原型记忆系统全景

### 3.1 上下文装配（Context 面）

- 区注册表+控制面 `config/context_regions.json`：memory@200、history@300、tool_turn@900；`enabled/order` 可覆盖注册表默认，坏配置 fail-open（`config/context_regions.json:18-108`；`context_assembler.py:299-316`）。
- `build_ctx()` 是装配链**唯一 IO 处**：卡片索引/当前卡正文+影子/子卡状态/需求文档/规则区/记忆态一次取全，渲染器 `context_regions` 是纯函数零 IO（`context_assembler.py:448-514`）。
- `render_registered_regions()`：按 order 排序、按 profile/delivery/control 过滤、逐区独立渲染，**单区异常仅记日志跳过**不整体失败；`compose_model_context()` 产出 `system_prompt/prior_messages/user_prompt/turn_once/turn_tail`，delivery ∈ {system,prior,user,once,tail}（`context_regions.py` 注册表与渲染入口；此前已实读 2125-2451 行确认）。
- `context_board`：物化"已过 `enters_context` 闸 ∧ seq≥mark ∧ 评审 keep-N"的可见块表；块落库同事务进板、mark 推进同事务 `DELETE seq<mark`、评审流量写时逐出；`rebuild_board` 一键从原文重算，读侧懒自愈 60s 节流；`CONTEXT_BOARD=0` 回退旧四层筛（`context_board.py:43-207`；`origin_store.py:129-141`；`memory_domain.py:465-474`）。

### 3.2 记忆区块（A：结构/注入/回溯/权威/前端）

**数据结构**（`memory_domain.py:18-28` 字段清单；`memory_store.py`）：因果链节点 `CausalNode`——`anchor{sessionId,seq}`、`gist`、`status(ongoing|done)`、`kind(fact|decision|todo|exclusion|assumption)`、`coveredSeqs[]`、`process/lesson/start/result`、`docPaths[]/docRefs[]`、`level`、`role(gist|description)`、`upper[]/lower[]`、`lastUsedAt`、`sunk`、`degraded`、`timeline{from,to}`、`batchNo`、`fingerprint`、`supersededBy`。
五条不变量：I1 互链（含身份唯一：gist 按 seq 唯一）、I2 层级差=1、I3 同父 gist 子条 coveredSeqs 不重叠、I4 level=1⟺upper 空、I5 |upper|≤1（`memory_domain.py:30-38,114-193`）。

**注入**：记忆是 order=200 的一个 context region；`_render_memory_l1` 渲染日期/timeline、gist、可选栏（起因/经过/结果/教训）、锚点行 `@锚点{card_id,seq}`、doc 引用；批次分段、L1 顶层+下层条目分层；区头下挂 `_MEMORY_EXPAND_HOWTO` 教模型调 `memory_expand`（`context_regions.py:2125-2175` 附近实读）。**预算：无条目数/token 上限**（渲染全量可见链，未见截断逻辑）。

**回溯**：锚点 `anchor.seq` = 该条覆盖区间的**首块 seq**；`coveredSeqs` 由代码机械计算（模型不给坐标）；`memory_expand(seq)` → `_find` 命中节点 → gist → archive/节点 `process`（描述层）→ `origin_store.read_origin_span(min(covered), max(covered))` 逐字原文 + children（L2 子条随组）（`memory_expand.py:45-137`）。`origin_store.trace_entry` 提供同一链（`origin_store.py:248-255`）。`session_blocks` 表 = 原文副本（`origin_store.py:115-141`）。

**锚点失效**：expand 找不到 ⇒ 明确回"未找到"（"没查到"本身即结论，`memory_expand.py:16,59-61`）；原文区间缺失 ⇒ 渲染"原文表里没有这段"提示（`memory_expand.py:165-166`）。

**权威关系**：原文 = `session_blocks` 库副本 + md 文件（写路径真相源）；记忆是派生投影。`sunk`/`supersededBy` 只影响可见性不删数据（`memory_lifecycle.py:195-201`）；mark 推进不删原文只裁板（`context_board.py:107-115`）。**记忆不能覆盖原文**；但存在反向污染通道已修：凝练产出剥 `【结论】/【依据】/【记忆】` 标记防回流教假调用（`condense_two_layer.py:411-418`）。

**前端契约**：**未实现**。`static/` 无记忆区块 UI（canvas.js 零命中）；模型侧 `memory_expand` 工具已注册（`card_tools.py:210-213,1181-1208,4440-4461`，权限=父子线，关系线不给）。

### 3.3 凝练（B）

**触发**：`CONDENSE_ENABLED` 总开关（"1"/"true"）；仅 condense 进程可凝（`_condense_home()`，web/runner 闸退）；K token 触发线 `trigger_k_tokens()`——**当前默认 100,000**（代码注释后段），**文件头历史注释写 800,000**（两处冲突，如实记录未归一）；回合末异步 `maybe_schedule_turn_end`（不阻塞对话）；后台扫盘 `start_condense_sweeper`（默认 300s、`max_cards=8`）；排水 `condense_before_send` 循环凝到 `MODEL_WINDOW_TOKENS`(默认 1M) 的 90% 以下、最多 8 批（`memory_store.py:2785-3074`）。评审型卡豁免。

**并发/恢复**：同卡互斥 `_CONDENSING`；全局有界并发 `_FLYING`（默认 3，`CONDENSE_PARALLEL`）——card_154 单飞饿死实案后改有界；挂死判定 900s 无帧**只放锁不杀任务**（`CONDENSE_FLYING_RELEASE_SEC`）；失败记账 `condense_debt` 30min 退避（`CONDENSE_FAIL_BACKOFF_SEC`）、成功清账；fatal（key/模型/额度类）报用户，retryable 记账重试（`memory_store.py:2659-2755,2891-2918`；`condense_two_layer.py:54-77`）。

**三段管线**（`condense_two_layer.py:93-627`）：S2a 定界（`{"groups":[{"end":N}]}`，end=窗口下标严格递增界内，**G-1 闸**：解析不出/越界/非递增 ⇒ 带机械错误报告重试 1 次，二次失败整批作废 mark 不动，静默降级已处死）→ L1 全量三栏（低格式【块N】优先、JSON 回退；组数不符重试 ≤3 次）→ L2 细节子题（◇ 子题；超限只丢细节结论照常）。`CondenseTruncated`（finish_reason=length）= 终态透传整批作废。

**模型 vs 机械边界**：模型只产叙事文本与定界下标；**覆盖范围/锚点/消耗段全部代码机械算**（`assemble()`：coveredSeqs=组内块号区间；L2 子题区间从上一子题 end+1 机械切，锚点取子题区间首块防与父撞号）（`condense_two_layer.py:421-486`）。产出剥标记（`_scrub_marks`）。

**幂等/重凝**：`_merge_recondensed()` 同锚原位替换、并集 coveredSeqs、保留原发生时刻、不动无关 seq 条目、不物理删旧节点；同批重复锚点 warn（`memory_store.py` `_merge_recondensed`，已实读）。`sync_nodes()` 以 `(anchor_seq,role)` 为身份键重建 `memory_nodes` 派生表，新条目入新批次，ID 形如 `{work}/{card}/B{batch}/{ordinal}`（下级 `/d`）；`upper_id` 由首父锚推出、后修记录全层 seq→ID 映射防孤子（`memory_store.py` `sync_nodes`）。

**原文保留**：凝练只推进 mark、裁 context_board；`session_blocks` 与 md 原文不删；归档卡会话文件永留（`memory_store.py:2953-2959`）。可从原文重建：`rebuild_board` 演示了"原文→视图"重算；链本身也可从覆盖范围+原文重凝（幂等设计支持）。

**幻觉风险**：防护 = G-1 闸+组数+锚点认领+coveredSeqs 机械算+prompt 保真红线+全景去重头（F4 memory 全景注入三段，防重复/碎片，`condense_two_layer.py:521`）。残留风险：**凝练文本内容本身无核对器**（模型写错事实，系统不判语义真假）；评审噪音经 review_scope keep=0 全蒸发不进凝练池（`memory_store.py:2674-2686`）。

### 3.4 归拢/折叠（C）

**触发**：批间隔或顶层条数阈值 `fold_top_trigger()`（默认 40，min 2）；`last_fold_check` 游标；归拢在凝练管线尾部异步跑。

**两段模型调用**（`memory_store.py:2300-2656`）：Step1 分组（严格终格式 `结论：有合并/无合并` + JSON `groups`；`_parse_fold_groups` 机械校验：结论存在、JSON 可解、成员在顶层 seq 集内、组≥2、跨组去重）→ Step2 每组综合出一条 L1 digest（标题/起因/全局重组过程/最新结果/教训；组内按时间序、超 `fold_group_cap()`=25 只合最老段）；可按 `【需展开：seq N,M】` 请求一次有界展开（`_expand_for_fold` 回灌深材料）。**产出按指纹缓存**（stage tag = 组指纹），重试免重付已成功的调用；并发闸 3。

**提交 = 降层建边**（`memory_store.py:2534-2656`）：成员 `upper=[新digest锚]`、沿 lower 子树 level+=1；新锚取 **1e9 保留段** `_fresh_synthetic_seq`（防与成员锚撞号 I1）；digest 按 timeline `insertByTimeline`；`coveredSeqs`=成员并集、`docPaths/docRefs`=成员并集、`fingerprint`=成员锚集哈希。**认领冲突：先认领者得**——多组重叠 covers 时后组剔除已认领成员，<2 不产空壳；同锚复本随成员归 digest（脏链修复 card_fn_005/007）。
**关键裁定**："代码不裁判模型产出"——字段缺省补空、kind 缺省 fact、covers 原样透传，不做成员存在性/数量拒绝（`memory_store.py:2534-2544`）。Step1 的机械校验仍在（解析层），但 Step2 的 digest **语义零校验**：只跑 I1–I5 体检、违例只记不阻断（`memory_store.py:2643-2649`）。

**无合并**：judge-empty 全组弃权 ⇒ `last_fold_check` 推进；管线失败（有组机械失败且零提交）⇒ 游标不动、缓存留待续跑（`memory_store.py:2625-2638`）。

**去重/淘汰/复活**：去重靠 I1 身份唯一 + 认领去重 + coveredSeqs 并集；淘汰 = `sunk`（深层 level≥2 7 天未用沉没整树；顶层 done 3 天未用且不在最近 6 条退常驻；无 `lastUsedAt` 一律豁免）——纯机械零 LLM（`memory_lifecycle.py:35-192`）；复活 = expand 命中 sunk 条目即 `sunk=false`+父链 `lastUsedAt` 刷新（`memory_expand.py:88-98`）。**时效回收不受 CONDENSE_ENABLED 闸**（回合末 `maybe_schedule_reclaim` 照跑，`memory_store.py:3077-3091`）。

**可逆/重放**：成员与原文全保留，digest 是加边不是删点——**结构上可逆**（把 upper/lower 边拆掉即还原单层森林）；指纹账 `state.folded`/`supersededBy` 标记可过滤。但**无重放接口**：没有"从历史 fold 记录重建链"的工具；`log_fold` 只留观测 JSONL（`memory_store.py:2650-2652`）。

**冲突裁决**：digest `result` 取**最新成员**（prompt 硬约束：旧态不得充当现状）；同锚复本=同一逻辑身份；`_merge_recondensed` 同锚原位替换保留原时刻。**无版本链**——superseded 成员无 `supersededBy→digest` 的显式指针（`visible_chain` 靠 fingerprint 账标记，`memory_domain.py:432-434`）。

**第二套事实**：存在**三处**易分裂的并行事实——memory 表 `chain` 列 vs `entries` 双写（同一行两用，曾有"链覆写丢件"bug）、`memory_nodes` 物化表 vs chain、`memory_archive` 冻结表 vs 节点 process 字段（archive 已冻结 F17 但 expand 仍回退查它，`memory_expand.py:82-86`）。加上指纹账 supersededBy 与 upper/lower 边是两套"谁是成员"的记录（`memory_domain.py:364-367,432-434`），归拢成员关系实际记了两遍。

## 五、对 CardColony v2.0 的建议

### 5.1 Context Line（上下文线）

1. **以"持久日志+投影"为唯一结构**：append-only session 事件日志是真相；模型可见面 = 投影（surface），遮蔽/替换只动投影。把 `request/header` 式规范快照制度化：system prompt+tools+config 每次请求全量快照（去重落），保证"模型可见即已记录"——v2.0 验收可直接引用此条作为不变量。
2. **插件接口对齐 DSH 形态**：ContextContributor 注册 `{section, order, scope, render(ctx) }`，返回 disposer；单区失败隔离（原型 render_registered_regions 已是此语义，保留）；控制面 JSON 只管 enabled/order，不做渲染逻辑。
3. **投影板一等设计**：context_board 的思想（写时维护"哪些块在视野内"）保留为 `context_surface` 表：块落库同事务过闸进板、mark 推进同事务裁板；**但删掉懒自愈兜底的前提——写路径必须硬失败告警**，自愈只是排障工具不是常态路径。
4. **工具结果治理**：采用 DSH 双机制——spill（超大→预览+locator）+ 无模型 pruner（保留原事件可重放）；原型 wire 投影闸可作为补充但应定义为投影层契约而非补丁。
5. **信任分层**：给 context 每区带 `source` 标注（system/card/plugin/session-ref），跨卡引用默认标"外部信息非指令"（对齐 session-reference 语义）。

### 5.2 Memory 子系统

1. **保留**：CausalNode 因果链（anchor{card,seq}/level/role/upper/lower/coveredSeqs）+ I1–I5 不变量 + "模型产叙事、代码算坐标"的边界（coveredSeqs/锚点/水位全机械）+ 回溯链（coveredSeqs→原文表）+ 凝练三段（定界闸+两段写作+细节降级）+ 降层建边归拢（成员保留、可下探原文）+ sunk/revive 生命周期。
2. **重设计 ① fold 裁判层**：Step1 机械校验保留；Step2 digest 必须加回**机械校验**——成员存在∧≥2（已有认领层）、digest 不得引用 covers 外 seq、`result` 必须与最新成员 timeline 一致（可机械比）、I1–I5 违例**拒绝提交而非只记**。把 2026-09-24 "拆掉所有代码校验"的裁定限定为"不裁语义文字"，坐标/成员/时间线必须裁。
3. **重设计 ② 单一事实源**：memory 表 chain 与 entries 双写、memory_nodes 物化、fingerprint 账 supersededBy 与 upper/lower 边两套成员记录——合并为：**chain 唯一存**，nodes/archive 为派生只读物化（写明"派生可重建"），superseded 关系只从 upper/lower 边推导，删指纹账双轨。
4. **重设计 ③ 水位与锁**：mark 改记 `{mark, started_at, finished_at, batch_id}` 的 durable 记录（对齐 compaction/start+end），未配对 start 即锁、崩溃可检；mark 推进与裁板/链落库同一事务（已有，保留）。
5. **重设计 ④ 回溯契约产品化**：`memory_expand` 的后端能力（gist→process→children→逐字原文）保留，v2.0 必须补**前端读取契约**（点开记忆条 → 调 expand 同源 API 展示原文区间）——当前标注"未实现"。
6. **失败语义**：fatal/retry 二分+记账退避+有界并发保留；补持久化 inflight 记录（进程重启后能发现"上次的 start 没 end"）。
7. **不继承**：`review_scope` 硬编码蒸发（做成可配置 scope 策略）、archive 冻结表与 process 字段双读（归一）、degraded 只标记不自愈（要么接入再描述管线要么删字段）、wire 闸的 env 散件（收进预算配置层）。

## 七、未解问题与需决策的取舍

1. **fold 机械校验恢复到什么程度**：坐标/成员/时间线必须裁（建议已给）；digest 文字是否加"引用 seq 必须存在于 covers"的文本级校验，需要产品裁定（越严越少幻觉，越松越少拒批）。
2. **记忆多形态归一的迁移路径**：chain 唯一存+派生重建需要一次存量迁移与灰度，是否带历史卡迁。
3. **mark 持久化记录的兼容**：现有 mark 是裸整数，改 durable record 需迁移或双读。
4. **前端回溯契约的形态**：点开记忆看原文是做成独立 API+UI 面板，还是复用 expand 工具回执通道——交互决策。
5. **评审/噪音流量治理是策略还是机制**：建议机制化（scope 策略注册），但"哪些流量算过程噪音"需产品逐类裁定。
6. **DSH gen3 移植源是否还要对齐**：若 gen3 代码可得，建议核对一次归拢/凝练的原始语义；若不可得，v2.0 应以本仓 DSH 的 compaction/surface 语义+原型已验证的因果链为设计基线，不再追溯 gen3。
7. **token 计量**：cl100k_base 近似 vs 接入各执行体真实计量（DSH token-meter 式 fold）——影响触发线精度，需取舍。
