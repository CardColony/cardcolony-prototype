## 1 模块定位与边界

负责：收件箱与持久消息、投递／唤醒／续接、租约与崩溃接管、运行体生命周期、有界队列与背压退避、监督（不擅杀、不猜完成）、取消（含用户介入停止的执行侧）、观测与失败显式、三形态同一语义、生产闭环证据与 G2 取证参与。

不负责：策略求值与派生事实定义（S5）；权限合法性判定、动作表与审计字段（S4）；产品壳可见面实现（S6／L6）；执行循环与模型—工具语义（S8）；记录权威与序号分配（S1）；卡侧业务完成判定（card_009）。

硬边界：不写卡面；不建第二套事实源与第二套生产装配；不按运行时长／轮数／字数／沉默终止任何 run；不设驳回动作与独立授权记录。

互斥粒度（产品所有者裁定，见父卡 A3 头部）：一张卡片＝一个 agent，一个 agent可有多个 session（会话／分支）。互斥单位是 session，不是 agent：同一 session 同一时刻至多一个活跃 run；不同 session 之间允许并行 run。每个 session 的局部事件流只有一个写者，local_seq 在 session 内单调串行；同一 agent 的不同 session 之间不得比较 local_seq。幂等键的「只处理一次」以 session 为边界，跨 session 同键不算重复。活运行体（进程／资源）与活跃 run（执行）是两个维度：运行体每 agent至多一个（资源维度），run 互斥在 session 维度。

## 2 不变量

- I1 单权威：收件箱、投递回执、租约与运行体事实全部经 S1 唯一写者落盘；本模块内存只是可由事件重建的缓存。
- I2 顺序域：本模块不分配全局序号；写者单位＝session，local_seq 在 session 内单调；跨 agent／跨 session 判定只依据全局共享事实或显式关联，禁止比较不同 session 的 local_seq。
- I3 投递生命周期五态不合并：投递生命周期五态＝「已生成 / 已送达 / 已运行 / 已产出结果 / 已解决」，五者互不推出。该五态与 A6 的崩溃恢复点①–⑤ 是两套独立枚举：不得混用、不得互相编号、不得互相替代。收件侧另有四态枚举（见 §3.1 R-IN-2），与本节五态各自独立命名。
- I4 失败显式：来源不可用必须返回具名错误或「暂缓」，绝不返回空集／默认值冒充成功。
- I5 互斥维度不得串用：不得以 agent 级资源维度否决 session 级并行；不得以 session 级互斥否决同 agent 不同 session 的并行。

## 3 需求条目（要什么｜验收判据｜上位条款）

### 3.1 收件箱与持久消息（IN，7 条）

- R-IN-1 持久收件箱：每 Agent 一个持久入箱，消息在消费前不得因重启／崩溃丢失，且可由权威事件重建。判据：灌入 N 条（含重复幂等键）后杀进程，重启读箱得到与崩溃前同一集合（逐条内容指纹比对）；重建结果与崩溃前逐字段相等。｜A3-2、H1、G1
- R-IN-2 收件四态可分：入箱／已投递／已运行／已产出，四者各有独立记录与时点，不得压成一个状态字段。命名说明：本条「收件四态」与 §3.2 R-DL-2「投递生命周期五态」是两套各自独立的枚举（四态含「入箱」、五态含「已解决」），不得互相替代、不得合并计数、不得互相编号。判据：导出一条消息的生命周期，四态各有一行且时刻不同；构造「目标 session 不运行」用例，状态停在已投递，不得出现已运行或已产出。｜§4.5、H3
- R-IN-3 持久消息 vs 一次性注入：唯一区别＝一次性注入只进入目标下一轮上下文、不写入永久对话历史。判据：注入一条后按会话检索权威对话记录零命中，且该轮可见输入集合含它并标来源「系统注入」；持久消息可在权威对话读回且下一轮仍可见。｜A3-2、H9、V7
- R-IN-4 幂等去重以 session 为边界：同一 session 内同一幂等键只处理一次、副作用不增长；②跨 session 同键各自独立处理，不算重复（不得因另一 session 处理过而丢弃）。判据：①同一 session 同一消息投两次 → 处理次数 1、副作用（消息／写入／工具调用）各 1，第二条留「幂等丢弃」记录并带具名原因；②同一 agent 的两个不同 session 各投同一幂等键 → 两次均被处理，处理次数各为 1，副作用各 1，无「幂等丢弃」记录。｜B4、H13-2③
- R-IN-5 有目标不广播：投递只到解析出的地址／连线目标；无路由即显式丢弃并留可读原因，不得向第三方泄漏。判据：向未绑定地址投递 → 任何第三方箱子与事件流无该帧；丢弃原因与目标可查。｜A3-2、B2
- R-IN-6 注入不唤醒＋一次性生效：注入默认不唤醒（除显式唤醒）；只对目标 session 的下一次运行生效，用后即清，不得跨多轮或跨 session 存活。判据：注入后无外部输入、无显式唤醒 → 新 run 启动数为 0；目标 session 下一次运行后，其后续轮可见输入不再含该注入；另一 session 的轮次从未出现该注入。｜H9、V7
- R-IN-7 session 级消费隔离：同一 session 的消息按序被该 session 的 run 消费，不串到另一 session；不同 session 的消息互不阻塞。判据：向 session A 与 session B 交错灌入消息 → A 的消息全部由 A 的 run 消费且顺序保持、B 亦然，零串 session；阻塞 A 的消费后 B 仍能推进。（收件箱结构由方案 P19 定，需求侧只要求上述行为）｜A3 头部并发口径、A3-2

### 3.2 投递／唤醒／续接（DL，6 条）

- R-DL-1 四类干预语义不互冒充：消息（留永久消息，≠已执行）／注入（只影响下一轮）／唤醒（请求叫醒该 session 一轮）／继续（围绕未完成事项继续）。判据：四类各一条用例，逐列比对「是否写对话历史／是否启动 run／是否只在该 session 下一轮生效／回执字段」，任一列混同即不合格。｜§4.5、A3-2
- R-DL-2 投递生命周期五态回执与「送达≠解决」：五态＝已生成／已送达／已运行／已产出结果／已解决，各有独立字段与时间线，互不推出；送达后若无新权威事实，事项仍为待处理。判据：构造送达后目标 session 不运行 → 事项状态不变（不得出现已运行或已解决）；构造已运行但无结果 → 不得出现已解决；完成只在出现新权威事实后发生。｜§4.5、H7、V4
- R-DL-3 无有效租约即暂缓＋事件型再检查：目标 session 无有效租约时结果必须是「暂缓」而非送达，且给出事件型再检查信号（指向一个具体事件，不是定时轮询）；该事件到达后同一意图被再求值且只执行一次。判据：目标无租约 → 暂缓＋事件型信号；构造租约激活事件 → 该意图被执行且计数恰为 1；出现定时轮询或伪造送达即不合格。｜H4、H13-1
- R-DL-4 禁定时、永久失败不得暂缓：判据：扫描全部暂缓分支，再检查信号均为事件型而非定时；构造永久失败（目标已删／身份不存在）→ 稳定拒绝＋具名原因码，不得进入人工待办队列。｜§4.8、H4
- R-DL-5 唤醒／续接执行权唯一：启动 run 的入口只有本模块；S5 只发请求。判据：代码扫描「启动 run／拉起运行体」的调用点集合＝本模块公开入口，无第二个驱动路径。｜B4
- R-DL-6 每 session 单活跃 run（不同 session 可并行）：同一 session 同一时刻至多一个活跃 run，多出来的唤醒请求按方案合并或排队，不得静默丢弃；不同 session 的 run 可并行存在。判据：①对同一 session 并发唤醒 K 次 → 该 session 活跃 run 数 ≤1，且未丢失的请求在回执中各有可见落态（合并或排队）；②同一 agent 的两个不同 session 各唤醒一次 → 两个 run 同时存在（活跃 run＝2），各自局部序号独立单调且互不比较；③构造跨 session 比较 local_seq 的调用 → 被拒。｜A3 头部并发口径、§4.10、B7

### 3.3 租约与崩溃接管（LS，8 条）

- R-LS-1 迁移非法即拒、两种终止可分、未知状态名重建报错：判据：非法迁移用例全部被拒且有具名原因码；正常交回与强制召回各构造一次 → 事件类型、原因码、下游账本变化均不同，不得一方记成另一方；注入带未知状态名的记录 → 重建显式报错，不得跳过、不得返回空视图。［六态枚举与迁移表→P10］｜A3-2、H4
- R-LS-2 可由事件重建、不可重建即拒启动：启动必须重建；无法重建（坏记录／不自增序号／身份不成对）时拒绝启动并报具名错误，不得返回空视图继续跑。判据：重启快照与重启前逐字段相等；注入坏事件 → 启动失败且错误具名。｜H1、G1
- R-LS-3 接管记录先于外部效应：顺序固定为 ①接管记录落盘并成功 ②产生外部效应 ③运行体记录写入；接管记录未落盘时不得产生外部效应，回执只能为「不确定」且注明无外部效应。判据：三点各注入崩溃一次：①在接管记录落盘前崩溃 → 恢复后无外部效应，回执为不确定；②在接管记录已落盘、外部效应发出前崩溃 → 恢复后该发送恰好一次（发送计数＝1，不得为 0、也不得为 2）；③在外部效应已产生、运行体记录写入前崩溃 → 恢复后运行体记录补写完成，且不重复产生外部效应。［「已发送标记」属实现方式→P21］｜§4.8、G1/G3 恢复点③
- R-LS-4 运行体身份可判定、判定不成立不得进运行态、对账不得把「查不到」当活或死：判据：注入身份要素缺失／不可读 → 不得进入运行态（拒绝或暂缓＋具名原因）；三种情形（原实例仍在／原实例已消失／原身份标识被另一实例占用）各构造一次，对账结论与注入事实一致；外部事实不可读 → 结论只能是「查不到」，且不得据此放行新发放。［四元组绑定→P14，三分支命名→P17］｜§4.8、G1
- R-LS-5 两个维度分离：每 agent 至多一个活运行体（进程／资源维度，非 run 互斥维度，见 P22）＋每 session 至多一个活跃 run：判据：同一 agent 两个不同 session 并行时，读数为活跃 run＝2、活运行体＝1，且两 session 各自只跑一个 run；构造「活运行体只允许一个」的实现若同时否决了第二个 session 的 run → 判红（负例检测）；构造「同一 session 第二个 run 启动」→ 被合并或排队，不得并行。旧运行体处于收尾态且仍有在途 run 时申请新运行体 → 暂缓并给事件型再检查信号（指向该运行体退出事件）；在途 run 结束后再申请即放行且只放行一个。｜A3 头部、A3-2、§4.10
- R-LS-6 时钟可复现：运行期用单调时钟、重启后用持久时间戳；不得用进程内读数在重启后伪造剩余时长。判据：重启后读到期剩余与冷却剩余，均由持久时间戳算出且与关闭前推算一致。｜H4、§4.8
- R-LS-7 心跳单一采集点：活性载体只有一个读取实现，租约活性与父进程存活判定共用同一函数。判据：代码扫描读口唯一、两处消费者调用同一入口；载体缺失返回「采集未命中」而非「已死亡」判定。｜§4.8、H4
- R-LS-8 两种终止的落账不得合并或替代：判据：正常交回与强制召回各一次 → 落账时点与各自事件同刻，不得延缓合并；不得以任一方落账代替另一方。｜H4

### 3.4 生命周期（LC，4 条）

- R-LC-1 生命周期相位与租约状态正交：两者不得互相推导，同一时刻可同时成立并分别读出。判据：构造「租约有效＋生命周期处于收尾中」→ 两维度同时可读，任一维度缺失不影响另一维度判读。［相位枚举→P11-附］｜A3-2
- R-LC-2 读取面只读：查询不产生系统效应、不改账本、不触发权限判定。判据：连续 K 次查询 → 事件数与账本序号不变。｜A3-2、H5
- R-LC-3 无租约必须能回答「为何未动」：给具名原因＋所等事件＋起始时刻三要素；持有效租约时该字段恒空（反向断言）。判据：无租约时三要素齐全、原因可机器读取（非自由文本）；多种未动成因下原因两两可分且各带事件型所等事件；持租约时字段为空。［成因枚举→P11］｜A3-2、H4
- R-LC-4 收尾事实如实暴露：收尾中的运行体须在查询面如实暴露（收尾中、起始时刻、已持续时长），不得隐藏；无释放事实时不得宣称已释放；不得把收尾中的运行体当作可承接新 run。判据：收尾中 → 三项可读；负例检测（把收尾事实隐藏的实现）必须被判红；无释放事实却出现「已释放」声明即不合格。［账目口径→P15］｜H4

### 3.5 背压（BQ，6 条）

- R-BQ-1 每目标投递有界、超额显式拒绝并可见：判据：灌满某目标 → 出现拒绝计数与最近拒绝原因，目标可查；静默丢弃即不合格；结构扫描不存在无界投递路径，负例（无界缓冲实现）被判红。［帧与动作共队列／同阈值／无优先级→P13］｜§4.10、H7
- R-BQ-2 预算为声明值，未声明即拒入队：深度与占用预算由部署注入，实现不得自选；未声明时拒绝入队并返回具名原因，不得回落到实现自选默认值。判据：注入生效（读回容量＝注入值）；不注入 → 一律拒绝入队＋具名原因；源码中不存在作为生产默认值的自选数字。｜H4、§4.10
- R-BQ-3 归因独立、解绑即回收：拒绝与丢弃按目标独立归因，不得跨目标混淆、不得只增不减；目标解绑即回收其全部归因与观测项。判据：压满 A → 仅 A 增长、B 为零；解绑后该目标归因与观测项消失（内存与观测面均不残留）。［桶字段→P16］｜§4.10、H4
- R-BQ-4 背压显式可见：拒绝与丢弃必须在观测面读到（原因＋目标＋时刻），不得静默丢帧。判据：超额灌流后观测面出现拒绝计数与最近丢弃原因，对应错误字段非空。｜H4、V9
- R-BQ-5 有界退避与显式放弃：本模块 worker 重启退避有界（起点与上限为声明参数），达上限显式失败＋告警＋上报；禁止无限重试与静默中止；该上限只作用于本模块自身 worker，绝不终止任何 Agent run。判据：连败注入 → 退避序列有界并封顶后显式失败、告警项可读；同期被观察 run 未被杀死。｜H7、总规则 4
- R-BQ-6 高频与低速分道：普通递话与私有唤醒不占全局共享写入队列，只有改变共享事实的动作才走全局写者。判据：大量递话灌入 → 全局写者队列长度不增长、共享事实写入时延不被拉长。｜§4.10、B1

### 3.6 监督（SV，4 条）

- R-SV-1 不判业务完成、不写卡面：不改卡面、不判事项已解决、不按时长／轮数／字数／沉默猜完成。判据：静态扫描「按轮数／字数／时长／沉默判完成」路径命中数为 0；卡面写入者清单不含本模块。｜H7、V4
- R-SV-2 四类极端 run 存活：长时、多轮、大输出、工具反复失败四类 run 均存活至自然结束或被显式取消；因监督而终止的 run 数为 0。判据：四类各跑一次，终止原因 ∈{自然结束, 显式取消}。｜H7、V3/G4
- R-SV-3 监督事实是派生投影：重启次数、异常计数、存活集合、限制状态均可由事件重建，不得反向成为判定依据。判据：删除投影重建后与删除前指纹相等。｜H1、V5
- R-SV-4 保护性限制有界、达上限显式失败、绝不擅杀、输入不可读不得默认放行：判据：连败 → 重试有界、封顶后显式失败且告警可读；被保护目标 run 存活至自然结束或显式取消，因监督而终止数为 0；输入不可读 → 降级项出现在观测面且新申请不放行（非默认放行）。［相位名与试探张数→P12］｜H6/H7、§4.9

### 3.7 取消与用户介入（停止）（ST，14 条）

两级作用域（全文固定命名）：
- 停这一轮（session 级）＝中止该 session 当前 run 的剩余步骤，该 agent 的其他 session 不受影响，该 session 之后仍可被正常唤醒。
- 停这个 Agent（agent 级，覆盖其全部 session）＝中止该 agent 全部 session 的当前 run，且不再自动唤醒，转人工推进。

- R-ST-1 单入口、过闸、无旁路：停止只有一个动作入口，经公开动作表＋执行闸判定并审计；本模块只承担执行侧；同进程不得走捷径。判据：动作入口数为 1；绕闸尝试（同进程直调、私有通道）全部被拒且留审计。｜H5、A3-10、B4
- R-ST-2 即时生效（二元计数断言）：生效时点＝立即，不等当前 turn 结束。判据：停止裁决落盘后，在途调用返回时四类步骤计数（模型请求／工具调用／投递／派生事实）相对停止时刻不再增长（增量必须为 0，二元断言）；出现任一增量即不合格。｜H13-1
- R-ST-3 两级作用域可分且即时可见：用户侧状态至少三态可分（进行中／已停止·可续／已终止）；同用例集在两级作用域下状态与后续行为不同；按下按钮无状态变化即不合格。判据：同用例集跑两遍，被停作用域状态分别落在「已停止·可续」（停这一轮）与「已终止」（停这个 Agent）；同一 agent 构造两个活跃 session 时，停这一轮后仅被停 session 状态改变，另一 session 状态仍为进行中。｜A3-10 产品壳最小呈现
- R-ST-4 后果 a（不销毁已完成部分）：已落盘结果与记录按权威记录保留，用户侧只读可见。判据：停止后读权威记录，停止前已完成的消息／工具结果／事件仍在，且与停止前快照对应部分逐字节相等；用户侧可读到。｜A3-10-a、H13
- R-ST-5 后果 b-①（停这一轮：零新 run＋启动原因可见＋并行 session 不受影响）：无新外部输入（用户发言／他卡消息／已批准的续接请求）时被停 session 零新 run 启动（二元断言）；有新的外部输入方可启动新一轮，且启动原因在用户侧可见（「因收到 X 而继续」），不得呈现为自启。判据：①观察窗口内被停 session 的 run 启动数＝0；②施加一条具名外部输入后启动数＝1 且原因字段等于该输入的可读标识；③反向断言：停这一轮时必须同时构造该 agent 的另一个活跃 session，其 run 状态不受影响（继续运行至自然结束或按自身输入推进），且该 session 的 run 启动或推进不受本次停止影响——若该 session 也被停或也被阻塞，本条不合格（防「停这一轮」被实现成「停这个 Agent」仍通过）。｜A3-10-b①、A3 头部、H13
- R-ST-6 后果 b-②（停这个 Agent：除显式恢复零新 run，覆盖其全部 session）：他卡消息、续接请求、策略唤醒均不得启动；该 agent 全部 session 均不得启动新 run。判据：观察窗口内该 agent 全部 session 的 run 启动数合计＝0（二元断言）；施压后仍为 0；用户显式恢复后＝1 且来源可读。｜A3-10-b②、H13
- R-ST-7 后果 c（一句「继续」可接续且副作用各一次）：判据：接续后三类副作用计数仍等于停止时的值（消息／写入／工具调用各恰好 1，不得翻倍）；同一 session 内同一幂等键被再次实际执行即不合格。｜A3-10-c、H13
- R-ST-8 后果 c 之接续起点可观察：用户侧可读出「从第几步继续」，步序＝该 session 停止时记录的最后完成步＋1；接续后第一条模型请求的上下文＝停止点的持久化状态，停止点之前已完成的步骤不得重新发起模型请求。判据：读出的接续起点步序＝最后完成步＋1（按 session 计）；接续后该 session 模型请求的步骤索引集合与停止前已完成集合交集为空；首条请求上下文快照与停止点持久化状态逐字段相等（防「整轮重跑＋副作用去重」伪装）。｜A3-10-c、H13
- R-ST-9 后果 d（已投递未执行动作取消并留记录）：判据：构造 N 条已投递未运行动作（分布于被停作用域内的各 session）→ 停止后各条为已取消；用户侧取消记录可读（动作标识、session、时刻、原因）；出现「既不执行也无取消记录」即不合格。｜A3-10-d、H13
- R-ST-10 后果 e（不得标为已完成）：判据：停止后事项／卡状态 ∈{已停止·可续, 已终止, 未完成}，绝不为「已完成」；构造丢弃后续用例 → 显式标未完成且可读；不得出现「被停 session 标为已完成而另一未参与 session 实际仍在跑」这类错标。｜A3-10-e、H13
- R-ST-11 在途调用返回不驱动后续且留痕：返回结果仍落盘供审计回放，但不得再发起模型请求、不得触发工具调用、不得产生投递、不得产生新派生事实；该返回记录须带可判读标记（停止前已发出／到达于停止后、不驱动）。判据：构造在途调用在停止后返回 → 记录落盘且标记可读，此后作用域内四类计数不增长；无标记或驱动了下一步即不合格。｜A3-10、H13
- R-ST-12 停止状态由权威记录派生、不缓存：用户侧视图字段可逐项回溯权威记录，不得另存展示副本；不得缓存停止状态，每次判定读持久事实（按 session 与 agent 两粒度分别判定）。判据：视图↔权威字段一一回溯；存在独立展示副本即不合格；重复判定结果随取消事实立即改变（无缓存窗口）；停这一轮后另一 session 的判定不受影响。｜H9、H13、B4
- R-ST-13 权限面变更的在途处置（执行侧）：变更前已提交未开始的动作不再开始；已在途调用不可撤回但留痕且不驱动后续；变更后第一个新动作按新权限面判定。判据：变更时刻前后各构造一次调用，逐句核对；无「下次刷新生效」窗口（对该 agent 全部 session 一致）。｜H13-3（主责 S4，本卡承担执行侧）
- R-ST-14 不设驳回：用户对结论的否定走对话（权威输入），本模块不设驳回状态字段、不设驳回抑制规则、不设「事项判为已解决」的否定语义；该对话消息的三条投递保证：①权威对话记录可读回且与原文逐字相等；②所在 session 下一轮可见输入集合含它；③同一 session 内同一消息重复投递只处理一次、副作用不增长。判据：三断言各一条用例（③不依赖并发门槛，可独立实测）。｜A3-10 末段、A4-H13

### 3.8 崩溃恢复（RC，4 条）

- R-RC-1 三点逐点分类正确（点集以 A6「五个崩溃恢复点」唯一枚举为准，本卡不改写；本卡承担②干预已生成未投递、③已投递未运行、④已运行结果未提交）：判据：三点各注入一次崩溃：②重启后仍在待投递且分类正确；③重启后仍为「已投递未运行」，不重投也不丢弃；④重启后为不确定态，不得盲目重执行。｜A6、G1/G3
- R-RC-2 不确定态不盲目重执行：不确定动作须显式落「不确定」＋具名原因码，并由对账消解为完成或拒绝之一，消解记录可审计。判据：注入写在途崩溃 → 不确定＋原因码；对账后状态唯一且留痕。｜§4.8、H4
- R-RC-3 启动对账不得把「查不到」当确定结论：须与外部真实事实比对并如实暴露结论；外部事实不可读时结论只能是「查不到」，不得据此放行新发放。判据：三种情形各构造一次（结论与注入事实一致）；外部事实不可读 → 未命中＋新发放暂缓。｜§4.8、H4［分支命名→P17］
- R-RC-4 未追平前发放约束：持有恢复项的 session／agent 置降级，新发放暂缓并给事件型信号；追平事件到达后自动退出。判据：未追平 → 暂缓且降级可读；追平后一次申请即放行。｜§4.8、§4.9

### 3.9 观测与失败显式（OB，3 条）

- R-OB-1 机器可读观测面：覆盖上位要求的观测项（队列深度与占用、拒绝、在途未确认、最近活动时刻、滞后、降级、告警、活跃 run 数、活运行体数、保护性限制状态）；活跃 run 数与活运行体数两量各自独立可读、可区分（不得由一量推算另一量、不得合并为一格）；三形态下字段语义一致。判据：每项可追到值来源；两量在同 agent 两 session 并行且采用单运行体方案时读数为活跃 run＝2、活运行体＝1（若方案改为每 agent 多运行体，则只保留「两量独立可读可区分」断言，数值随方案）；同一用例集三形态读出语义一致。｜A3-9、A3 头部、B7、G6
- R-OB-2 唯一读口：同一指标不得由第二个对外查询面暴露。判据：全局仅一个读路径导出该值；出现第二面即不合格（负例检测）。｜H4、B4
- R-OB-3 fail-closed 而非 fail-empty：五类故障（日志不可读／外部事实不可读／参数未核准／预算未声明／投影落后）注入下返回具名错误或暂缓，且降级项出现在观测面。判据：注入清单逐条比对返回分类；任一在失败时返回成功或空集即不合格。｜H4、V9

### 3.10 并发与三形态（CC，3 条）

- R-CC-1 三形态同一语义：同用例集在单进程／单 exe／多进程高并发结果一致，禁止同进程捷径绕闸。判据：三形态逐用例比对判定值、回执状态、审计字段。｜B7、G6
- R-CC-2 并发无破坏：全局序号集合与期望集合相等、成功写入计数＝落盘计数、外部副作用计数＝期望次数、无失控重复执行；同 agent 多 session 并行时各 session 局部序号各自单调且无重号。量化门槛按 S10 分档、007 审批、根卡确认；门槛确认前本项不得判通过。判据：集合与计数逐项比对；门槛未定即标「未判过」。｜G1/V8、B6/B9-3
- R-CC-3 跨 session／跨 agent 判断不伪造顺序：判据：构造「比较不同 session 的局部序号」的调用 → 被拒；审计全部跨 session／跨 agent 判定路径的顺序源类型。｜H2、V1、A3 头部

### 3.11 生产闭环与取证参与（PC，2 条）

- R-PC-1 生产闭环证据（A4-H12）：本模块每项能力（收件箱／投递／唤醒／续接／租约／生命周期／背压／监督／取消／观测）须有真实生产路径证据链「声明→权限面确认（卡类型／连线类型）→装配→可见→调用→执行→结果→下一轮」。判据：逐能力取真实 run 的事件与快照引用，链上每环节有可查记录；只有类型／单元测试／文档证据的能力不计完成；出现「测试通过但生产零调用」即不合格。｜H12、V10
- R-PC-2 参与 G2 取证（A6-G2、V6）：本卡须在 G2 用例清单承担项到场并有原始输出——内外参与者同级用例下收件箱／投递／唤醒结果一致；越权请求在真实执行路径被拒且有审计；权限数据故障下放行数为 0。判据：上述各项在 G2 记录中各有本卡真实执行路径的原始输出与可复跑命令；仅文字结论视为未取证。｜A6-G2、V6

## 4 方案提案（P1–P22，均属本卡自决项；列选择与理由，待审批定案；不构成验收判据）

- P1 队列参数：每目标双约束（深度＋全局占用预算），均为部署注入的声明值；深度给一个声明默认值（参照旧仓 16，作为声明而非实现自选），预算未声明即拒入队。理由：H4 禁「未声明回默认」，而「声明默认」与「实现自选」必须在代码上可区分（注入入口是唯一改变途径）。
- P2 租约参数与心跳：心跳期限、续期聚合窗口、回执等待上限、每运行体内存上限一起作为发放前置参数；缺任一 → 暂缓＋事件型信号，不作终态拒绝。心跳刷新周期取远小于期限（旧仓 40ms 对 1500ms 的比例经验）。理由：fail-closed 应表达为「等事件」而非「拒绝请求」。
- P3 退避与频控：worker 重启退避 50ms→2000ms 封顶、5 次后显式失败告警；保护性限制阈值与冷却时长作声明参数，未核准即禁用并留降级项（不默认放行）。理由：与 H7 相容——上限只作用于本模块自身 worker，不触碰任何 Agent run。
- P4 内部结构与包组织：单目录内七单元（inbox／inflight／lease／supervise／backpressure／cancel／observe），对外四门面（运行接力、租约、停止执行侧、观测）；持久写入只经 S1 事件面。截止点用每租约最小堆＋世代号（不扫全表），归因桶随解绑回收。理由：旧仓实测教训——全表扫描与只增账都是判据里的雷。
- P5 幂等索引是派生结构：可由权威日志重放重建；索引不可服务时回落权威读，不得把「索引未命中」当「从未见过」。键空间以 session 为前缀（session_id＋幂等键）。理由：H1、H4，且幂等边界已由产品所有者定为 session。
- P6 消费位语义：出队即盖「最近出队时刻＋在途未确认＋消费位被占」（消费位按 session 分），确认后递减；发送失败不算确认（保持未确认至解绑回收并在观测如实暴露）。理由：能区分「我的帧没发出去」与「别的投递占着消费位」。
- P7 停止实施落点：判定与审计在 S4；本卡执行侧只做三件事——①置持久取消事实（不缓存、每步入口读一次；含作用域字段 session／agent）②run 循环每步入口检查取消令牌，命中即停发起 ③批量把已投递未执行动作置已取消并落取消记录。接续起点从 S1 持久 run 记录读取，不由内存推测。理由：判定权与执行权分离可同时保 H5 与 H13-1/3。
- P8 负例检测开关：只允许以构建标签存在于测试产物内，不进生产二进制、不构成第二条生产装配路径。理由：判据须能被反证，反证装置不得成为生产回退开关（H11）。
- P9 语言与仓位：Go；仓位置与 module 组织按 S9 提案→007 审批→根卡备案，本卡不自建仓、不自定路径。理由：规则「唯一项目根」与 B9-2。
- P10 租约状态六态枚举与迁移表：requested／granted／active／expired／revoked／released，迁移表可机器导出，未知状态名拒绝解析、不静默扩宽，released（正常交回）与 revoked（强制召回）永久不可互换。理由：六态区分「已授未启／运行中／到期／被召回／正常交回」五种不同事实，混同会破坏 H4 的可判读与下游账本。
- P11 无租约「未动」成因枚举：预算暂缓／保护性限制开启／被停止阻塞／排队中，各对应一条可观测等待来源。理由：闭集才能让「为什么没动」被机器回答而非自由文本。
- P11-附 生命周期相位枚举：starting／running／stopping／stopped／crashed，与租约状态正交（R-LC-1 的枚举落点）。理由：收尾中与已停止必须可分，否则 R-LC-4 无法如实暴露。
- P12 保护性限制相位与试探：closed→open→cooldown→half_open 单探（半开期只发一张试探许可），在途 run 不受影响，输入不可读时禁用并留降级项。理由：单探避免恢复瞬间雪崩；四相位可分以便与瞬时错误区分。
- P13 每目标单出向队列、帧与动作共用、同阈值、无种类优先级。理由：两条队列会出现种类间饿死与优先级寻租，且动作侧极易被写成无界；单队列天然满足「每目标有界」，负例检测更简单。
- P14 运行体身份四元组绑定（runtime_id／pid／process_start_time／generation）：四元组不完整不得进入运行态。理由：单 pid 会在系统重启后被复用，必须叠加启动时刻与世代号才能判同一实例。
- P15 收尾账目口径：在线数不含收尾、单列收尾计数、起始时刻与已持续时长。理由：收尾期既要「不再计入可承接」又要「不谎称已释放」，必须两套计数并存；只用一个在线数必然二选一失真。
- P16 归因桶字段与回收：拒绝数、首次超限时刻、最近出队时刻、在途未确认数；解绑即删桶。理由：只增账会污染长期观测；桶随生命周期回收是热路径内存可控的唯一办法。
- P17 对账三分支命名与结论映射：同一实例／已消失／标识被另一实例占用 → 分别映射为「延续租约／判死并接管／不得接管」；第四种「查不到」明确不映射为任一确定结论。理由：闭集才可判等，第四态必须是显式的「不知道」而不是猜测。
- P18 再检查信号命名与格式（事件名＋参数）：统一形如「事件名:参数」，禁止定时型。理由：统一命名后「是否存在定时分支」可被扫描证明（R-DL-4）。
- P19 收件箱归属（选定）：每 agent 一个收件箱＋按 session 分消费位。理由：①租约与运行体资源本就是 agent 级（运行体每 agent 至多一个），入箱若按 session 拆箱，session 生灭会带来箱生灭与迁移，崩溃接管与对账面显著变复杂；②单箱＋消费位分区的顺序保证与「跨 session 不串」等价（R-IN-7 只要求消费侧的 session 隔离）；③幂等键前缀已带 session，单箱不会把跨 session 同键误判为重复；④投递面只解析到一个箱子，无地址二义性。代价：箱内需按 session 建分区索引（作为 P5 的派生结构，可重建），且箱深度预算须按 session 分配（并入 P1 的声明参数）。
- P20 session 级活跃 run 唯一性：每 session 一张活跃 run 登记表（唯一键 session_id），世代号随首次启动递增；并发唤醒按「先到先占、其余合并或排队」处理；锁按 session 分片，不跨 session 共用一把锁。理由：满足 R-DL-6 的 ≤1 与并行不互斥，并避免全局锁把不同 session 串行化。
- P21 接管「已发送」标记（实现方式）：外部效应发出前后各写一条持久事实（发出意图／发出确认），恢复时读到「发出意图但无确认」才补发一次；若「发出确认」已存在则不再补发。理由：R-LS-3 的「恰好一次」只能由持久化两阶段标记提供，纯内存计数在崩溃点必然失效；标记本身走 S1 权威写入，不另建事实源。
- P22 运行体维度与 run 维度的读面口径：活运行体按 agent 计（进程／资源）、活跃 run 按 session 计（执行），两量在观测面分列、各有独立来源字段，禁止由一量推算另一量。理由：两维度混读会让「同一 agent 两 session 并行」被误判为资源超限，或反向掩盖真实的 run 重入。
