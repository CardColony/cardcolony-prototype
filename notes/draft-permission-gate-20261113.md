## 一、模块定位与边界

使命（对齐父卡 B3-S4）：负责两类权限的执行点检查（能力面＋管理权）、连线动作表的机械判定、统一执行闸与审计、三分类回执与稳定原因码、fail-closed、权限面变更的合法性与生效检查、停止与取消介入的合法判定与审计，到 G2／G6 相关验证点通过为止；不定义卡侧业务动作语义。动作表数据来源与缓存策略由本卡提案。

边界（B4 裁决表唯一 owner）：
- 归 S4：干预是否合法（S5 不得绕过）；权限面（卡类型／连线类型）变更的合法性与生效检查（作为管理动作经公开连线动作表判定、经执行闸、留审计，无任何缓存延迟）；两类权限执行点；连线动作表机械判定；统一执行闸（唯一入口）；三分类回执与稳定原因码；审计格式；fail-closed；停止／取消介入的合法性判定与审计（实施归 S2）。
- 不归 S4：权限面变更的受理与落盘（归 S1，留 global_seq）；可见与可调用面（归 S6）；停止／取消的实施（归 S2 牵头）；证据归口（归 S10）；卡侧业务动作语义定义（card_009 提供业务动作类别清单，S4 只机械判定）；run 归属与并发调度（归 S2，S4 只以 session 标识作判定与审计的作用域单位）。
- 任一模块不得自行受理权限变更请求、不得各自实现一套生效判定、不得私自缓存权限面、不得把变更动作绕过闸或作为特权路径。
- 收口语义：到 G2／G6 相关验证点通过为止＝模块自身验收通过＋已参与该验证点取证（验证点结论由 S10 出）。

## 二、需求条目（逐条：要什么＋可验证判据）

判据三要素：核验方式｜比对对象｜不合格判据。

### R1 依赖方向合规（B5，禁环）
要什么：S4 只依赖 S1 记录能力（卡类型声明、连线类型、共享事实的权威读取）与卡侧动作类别契约（输入）；S1 不反向依赖 S4；S5 依赖 S4（干预是否合法）不得绕过；S6 依赖 S4 权限判定一致性；S4 不依赖 S5／S6／S8／S9 内部实现。
判据：核验——读依赖清单与 import 图、静态扫描反向引用｜比对对象——依赖方向 vs B5 表｜不合格——任一反向依赖；S4 经私有接口访问他模块内部包；S5 存在不经 S4 的干预放行路径。

### R2 能力面执行点：判定依据＝卡类型声明的能力面（A3-3、A3-4）
要什么：能力权限回答「能调用什么能力」。执行点判定依据＝该参与者所属卡类型声明的能力面（共享事实，经 S1 权威读取）。能力面回显＝回显卡类型声明的能力面；管理动作面由连线类型另行决定，不在同一回显里合并；session 不进入能力面回显。内置卡的默认声明不构成特权（默认声明经同一判定，无特殊放行）。1.0 不引入「部署许可」这一中间量；部署侧若确需裁剪，只能是白名单裁剪、不构成第三个权限面，且须先在 A3-4／A4-H6／G2 三处同步定义（父卡批准）后方可引入。
判据：核验——构造能力调用请求，比对判定结果与卡类型声明；读回显字段｜比对对象——判定结果 vs 卡类型声明（S1 权威记录）；回显字段 vs 卡类型声明｜不合格——判定结果与卡类型声明不一致；回显含管理动作面、部署许可或 session 维度；裁剪构成第三个权限面；内置卡默认声明产生特权放行。

### R3 管理权执行点：判定依据＝连线类型决定的动作面（根卡 §7.2）
要什么：管理权限回答「能对哪个对象实施什么管理动作」。判定依据＝主体、目标、连线类型、动作规则四元组共同判定：父子线形成组织管理关系、通信线只提供约定的通信能力、依赖／影响线只登记关系；动作规则来自公开连线动作表。管理动作面由连线类型决定，不在能力回显合并，session 不参与判定依据。
判据：核验——管理动作逐条构造调用，比对四元组与判定结果｜比对对象——判定结果 vs 主体-目标-连线类型-动作规则四元组｜不合格——无连线或连线类型不符仍放行；动作不在动作表中仍放行；管理动作面混入能力回显；session 参与管理权判定。

### R4 两权限互不推导（H6）
要什么：能力面（卡类型决定）不蕴含管理权（连线类型决定），管理关系不蕴含能力面；两侧独立判定、独立数据源，判定代码分别只读对应事实源——能力判定不以连线类型为放行依据，管理判定不以卡类型声明为放行依据。
判据：核验——能力面×管理权四象限交叉用例（R11，每象限≥3 条）逐条比对判定值；扫描判定代码路径的事实读取面｜比对对象——判定结果 vs 卡类型声明与连线类型两侧独立事实｜不合格——任一交叉用例放行；管理判定把「存在卡类型声明」当作放行依据；能力判定把「存在管理关系」当作放行依据。

### R5 1.0 不设独立授权类操作（根卡 §7.1、父卡 A3-4、A5）
要什么：①无独立授权记录——权限面由卡类型＋连线类型直接承载，系统内不存在授权单／授权记录实体类型；②无授权审批流程、无扩权申请动作、无撤销授权动作；③权限扩大必须通过卡类型变更或安装变更重新确认（安装／创建时展示能力声明，用户看到后同意即安装、不同意即不安装或卸载），普通编辑不得静默扩大；④权限面要变，改的是卡类型或连线类型（其变化即时反映到执行点），不是操作一份授权单；⑤第三方自由智能体接入时的授权撤销机制留待该阶段通盘设计，仍守「权限永远跟卡片」原则。
判据：核验——全库扫描「授权记录／授权审批／扩权／撤销授权」类型与动作表条目；构造「扩权申请」「撤销授权」「普通编辑扩权」三类调用｜比对对象——动作表条目全集 vs 授权类动作清单（应为 0）；代码类型清单 vs 授权记录类型（应为 0）；普通编辑前后权限面判定结果｜不合格——存在任何授权记录类型；动作表含授权类条目；存在扩权／撤销授权调用路径；普通编辑（不经安装确认或类型变更）改变权限面判定结果；任何模块实现「授权单」语义。

### R6 连线动作表为唯一真源（B8 版本原则）
要什么：①管理动作判定的唯一依据＝公开连线动作表：版本化、单一真源、文档与代码一致性可机械校验（判等命令）；②条目结构＝动作名、适用连线类型、判定规则（主体／目标／连线类型／动作）、返回码；③条目内容归属卡侧（009 提供业务动作类别清单），S4 只做机械判定、不定义动作语义；④版本不一致默认拒绝并给出稳定原因码，不做静默降级兼容。
判据：核验——判等命令（文档 vs 代码常量）返回一致；扫描是否存在第二份动作表；版本化文档存在｜比对对象——动作表文档条目 vs 执行点实际判定条目集合（须相等）；判定记录所依据版本 vs 动作表版本｜不合格——判等不一致；任一条目只有文档无代码或反之；存在第二份动作表；版本不一致被静默兼容放行。

### R7 统一执行闸（H5）
要什么：①唯一入口——所有改变事实的动作经同一闸入口，闸入口集合＝1；②四类动作全覆盖——Harness 干预、Runtime 工具调用、内置卡写入、外部参与者写入全部经同一闸；③无特权旁路——无任何动作类特权路径，同进程路径不绕闸（B7-2）；④权限面变更动作本身也经闸（管理动作，非特权路径）。
判据：核验——扫描全库改变事实的动作入口，统计闸入口数量；四类动作各构造一次绕过尝试（直调写者、绕过闸入口）；同进程与跨进程调用走同一判定路径｜比对对象——闸入口集合 vs 动作种类全集；绕过尝试结果 vs 拒绝＋审计｜不合格——存在第二个生效入口；任一动作类无审计戳；同进程路径绕过闸；四类绕过尝试任一放行。

### R8 三分类回执与稳定原因码（A3-4）〔依赖 IC-3／IC-4〕
要什么：①回执三分类——accepted（接受，带 seq）／idempotent_dropped（幂等丢弃）／rejected（拒绝＋稳定原因码）；②每次请求必有且仅有一条回执（accepted 与否都有，拒绝与丢弃同样有回执）；③稳定原因码——enum 词表、机器可判定、版本化，机器判定以 status 分类为准、不依赖自由文本，原因码含义变化须升版本；④幂等口径＝S1 落盘判定＋S4 闸内校验口径（B4，依赖 card_011 IC-3 的幂等键作用域定义）；同一目标地址下同一幂等键至多落盘一次，事件与幂等键记录在同一 fsync 边界内提交；原因码词表以 card_011 IC-4 为根，本模块只补充与权限／闸相关码，不另立平行词表。
判据：核验——原因码词表存在且版本化；三类结果各构造请求比对回执分类；同一失败场景重复构造比对原因码稳定性；幂等键重复提交比对落盘次数｜比对对象——回执 status／reason_code vs 词表（及其与 IC-4 的包含关系）；重复提交落盘次数 vs 1｜不合格——回执分类缺一；任一回执缺失或多条；同一场景原因码不稳定；出现词表外原因码；与 IC-4 词表冲突或另立平行词表；幂等键重复落盘大于 1；事件与幂等记录不在同一提交边界。

### R9 审计格式同一（H5、V6）〔依赖 IC-1〕
要什么：①所有动作类（含同进程路径）审计字段集合同构、同一格式；②字段至少含：主体、动作目标（须能区分到 session：agent 标识＋scope_type＋scope_id）、动作、判定依据（卡类型声明版本／连线类型版本／动作表版本）、判定结果、原因码、幂等键、时点（global_seq 关联）、契约版本；③审计由 S4 生成、经 S1 记录能力落盘（依赖 card_011 IC-1 写入入口，属闸路径一部分，不构成独立生效入口）；④审计可随动作事实重放重建，不成为第二套权威，不存私有存储；⑤同一 agent 不同 session 的停止／拒绝记录不得混同（可按 session 唯一定位）。
判据：核验——四类动作审计记录逐字段同构比对；同进程与跨进程格式比对；删除审计后由动作事实重放重建；同 agent 两 session 各构造一次停止与一次拒绝，比对四条记录的作用域字段｜比对对象——四类动作审计字段集合；三形态审计格式；重建结果 vs 原审计；四条 session 记录的可唯一定位性｜不合格——字段不同构；任一动作类无审计；审计存于私有存储；审计不可重建或与动作事实不一致；任一记录只能定位到 agent 而不能定位到 session；四条记录作用域字段相同或混淆。

### R10 fail-closed（H6、父卡 4.9）
要什么：①事实不足或权限数据不可读时拒绝并报警；②「查不到≠空集」——数据不可读＝错误（拒绝＋报警＋显式暴露，不得当作「未授权」静默处理）；数据可读但无授权＝显式否定（拒绝，非错误，两者原因码不同、可区分）；③任何情况下不得放行一个无法证明合法的动作（可暂缓或拒绝一次干预，绝不放行）；④判定所需事实未就绪时按 card_011 IC-5 报显式错误，不得返回空集。
判据：核验——权限数据故障注入矩阵（卡类型声明缺失、连线类型缺失、权限数据存储不可读、动作表不可读、版本不一致、判定索引未就绪）下逐一构造动作请求｜比对对象——故障注入清单 vs 各请求结果（放行计数）与报警记录｜不合格——任一故障下放行；故障被静默（无报警／无显式错误）；数据不可读与显式否定不可区分（原因码须不同）；未就绪返回空集。

### R11 四象限交叉用例（H6、G2、V6）
要什么：能力面×管理权四象限交叉用例，每象限不少于 3 条：①有能力面＋有管理权——能力动作放行、管理动作放行（合法场景）；②有能力面＋无管理权——能力动作放行、管理动作拒绝（能力面不蕴含管理权）；③无能力面＋有管理权——能力动作拒绝、管理动作放行（管理权不蕴含能力面）；④无能力面＋无管理权——全拒绝。
判据：核验——G2 中内部与外部参与者各跑同一用例集、逐条比对判定值；V6 真实执行路径比对拒绝记录＋审计｜比对对象——判定值 vs 卡类型声明与连线类型两侧独立事实｜不合格——任一交叉用例放行；内外判定值不一致；越权用例无拒绝记录或无审计。

### R12 权限面变更的合法性与生效（B4、H13-3、A8-H13-3）〔依赖 IC-1〕
要什么：①合法性——权限面变更（改卡类型／改连线类型）作为管理动作，经公开连线动作表判定、经执行闸、留审计；变更本身是一次共享事实写入（受理与落盘归 S1，经 card_011 IC-1 写入入口留 global_seq），S4 不自行受理变更请求；②生效无缓存延迟——变更后第一个新动作即按新权限面判定，无重连、无下一刷新延迟窗口、无缓存残留；③在途处置（与停止在途语义同构）——变更前已提交但尚未开始的动作（session 级：该 session 的 run）不再开始；已在途的调用不可撤回、结果照常落盘并留痕标明「变更前已发出」，但不得驱动任何后续调用（不再发起模型请求、不触发工具调用、不产生投递、不产生新的派生事实）；④变更后首个新动作按新权限面判定（被拒或按新判定放行）；⑤在途处置粒度为 session run——同一 agent 其他 session 不受影响，各自按自身提交版本判定。
判据：核验——变更时刻前后各构造一次调用，比对：a) 未开始动作是否开始；b) 已在途动作的留痕与时点标注、后续四类步骤计数（模型请求／工具调用／投递／派生事实）是否增长；c) 变更后首个新动作判定结果；d) 同 agent 两 session 中仅一个被变更时另一 session 的行为｜比对对象——介入时刻与后续事件时间序列（global_seq）；未开始动作启动计数；在途动作后续步骤计数；变更前后判定结果｜不合格——未开始动作被启动；在途调用无留痕或驱动后续；变更后存在任何延迟窗口（含「下次刷新生效」）；任一模块私自受理变更请求或缓存权限面；变更动作绕过闸；无关 session 被牵连中止。

### R13 管理动作（含用户验收、改卡类型／改连线类型）经动作表判定并留痕（V6）
要什么：①管理动作全部经公开动作表判定、经闸、留审计，无不经动作表的管理动作；②用户验收作为管理动作经动作表判定（V6、V10），不存在绕过闸的验收路径；③改卡类型／改连线类型作为管理动作经动作表判定（B4 权限面变更执行点归属）。
判据：核验——管理动作清单 vs 动作表条目全集一一对应；验收、改卡类型、改连线类型各构造一次调用，比对执行记录与审计｜比对对象——管理动作调用记录 vs 动作表判定结果；审计留痕｜不合格——存在不经动作表的管理动作（含验收）或无留痕；存在绕过闸的验收路径。

### R14 与相邻模块的接口与依赖（B2、B4、B5）
要什么：①依赖 S1——卡类型声明、连线类型经 S1 权威读取，不建第二份权限事实源；②服务 S5——干预是否合法由 S4 判定，S5 不得绕过；③服务 S6——可见工具面与实际可调用集合同步（S6 可见面＋S4 权限判定＋S9 装配自检三方一致）；④服务 S9——装配自检包含权限判定一致性（H11）；⑤S3 只提供协议承载、不做权限判定本身（交 S4）；⑥向 S2 交付停止／取消的作用域参数契约与判定输出（见 R19）。
判据：核验——接口契约版本化；四类动作经闸证明（R7）；装配自检含权限判定一致性项｜比对对象——S4 公开接口清单 vs 各模块实际调用面；自检项 vs 权限判定一致性｜不合格——接口无版本化契约；S5／S6／S9 存在不经 S4 判定接口的放行路径；装配自检不含权限判定一致性项。

### R15 G2／G6 集成验证点参与（H12）
要什么：①G2——内部与外部参与者各跑同一用例集、逐用例比对结果；越权用例比对真实执行路径的拒绝记录＋审计；四象限交叉逐条比对判定值；通过＝内外结果一致、越权全部被拒且有审计、交叉用例全部被拒；②G6——同一用例集在单进程、单 exe、多进程高并发三形态各跑一遍，逐用例比对结果与审计格式；无同进程捷径绕闸；S4 声明的组件图与实际运行组件图一致；③证据形态＝用例清单＋可复跑命令或脚本＋原始输出与结果摘要，只有文字结论而无原始输出视为该点未取证。
判据：核验——S10 组织的验证点取证记录（可复跑命令＋原始输出，落 evidence 目录）｜比对对象——用例集 vs 三形态逐用例结果与审计格式；组件图声明 vs 实际运行｜不合格——只有单元测试或文档证据、无真实运行路径证据（H12）；任一形态结果不同；存在未声明组件。

### R16 契约版本与错误语义（B8）
要什么：①权限动作表、回执与审计字段作为独立契约族版本化，文档与代码一致性机械判等；契约文档须标注「已互通验证／仅契约依据」，禁止把未验证契约写成已交付；②版本不一致默认拒绝并给稳定原因码，不静默降级兼容；③每次判定与审计记录所依据的契约版本；④错误码 enum 化、机器可判定、可复现。
判据：核验——判等命令全绿；构造版本不一致调用｜比对对象——契约文档 vs 代码常量；版本不一致调用的结果 vs 拒绝＋稳定码；审计与回执的契约版本字段 vs 实际版本｜不合格——判等不一致；未标注验证状态；版本不一致被静默兼容并执行；审计或回执缺契约版本字段或与实际不符；出现枚举外错误码。

### R17 session 并发口径与停止作用域两级（产品所有者并发口径 2026-11-13，父卡 A3 头部）
前提口径：一张卡片＝一个 agent，一个 agent 可有多个 session；互斥单位是 session——同一 session 同一时刻只跑一个 run，不同 session 并行。
要什么：①停止／取消作用域两级：停这一轮＝停该 session 的当前 run（该 session 之后可被新外部输入唤醒：用户发言／他卡消息／已批准的续接请求）；停这个 agent＝停该 agent 全部 session 的当前 run 且不再自动唤醒（除用户显式恢复外零新 run）；两级语义不共用一条断言。②S4 职责段：停止／取消介入作为管理动作经动作表判定、经闸、留审计；实施归 S2，S4 不实施；介入合法性的判定输入含作用域参数（session 级给 session 标识，agent 级给 agent 标识）。③两级在判定与审计上可分：审计记录含作用域类型与目标标识，不能只记 agent 而不记 session。④同一 agent 不同 session 的停止／拒绝记录不混，可按 session 唯一定位。⑤作用域参数缺失或非法时拒绝（fail-closed，不猜默认作用域）。
判据：核验——a) session 级停止：仅该 session 当前 run 中止，同 agent 其他 session 的 run 不受影响；该 session 无新外部输入时零新 run（二元断言），施加一条新外部输入后可唤醒且启动原因在用户侧可读；b) agent 级停止：该 agent 全部 session 当前 run 中止，且除显式恢复外全部 session 零新 run（二元断言，与 a 分列、不共用）；c) 同 agent 两 session 各一次停止与一次拒绝，四条审计记录作用域字段互不相同且可唯一定位｜比对对象——介入时刻与后续事件时间序列；按作用域分列的零新 run 启动计数；审计作用域字段｜不合格——session 级停止波及同 agent其他 session；agent 级停止后未显式恢复却出现新 run；同一 session 同时跑两个 run；任一记录不能定位到 session；两级在判定结果上不可区分；参数缺失被兜底成某一级。

### R18 session 不引入新的权限维度
要什么：权限面判定不变——仍按卡类型声明的能力面＋连线类型决定的动作面；session 不是第三个权限面，不得作为授权单位、授权记录或权限面字段，不参与能力面与管理权判定；session 只承载并发互斥与运行作用域语义；同一 agent 的判定结果不因 session 数量或 session 归属而改变。
判据：核验——同一 agent 下多 session 各构造同一能力动作与同一管理动作，比对判定值（须一致）；扫描权限判定数据结构与动作表条目，检查是否出现 session 字段｜比对对象——各 session 判定结果 vs 卡类型声明与连线类型两侧事实｜不合格——同一 agent 不同 session 对同一动作判定结果不同；动作表含 session 维度条目；权限判定读取 session 作为放行或拒绝依据；体系内出现以 session 为单位的授权记录或权限字段。

### R19 与 S2 的对接：停止作用域参数两级传递（B4、父卡 A3 头部）
要什么：S4 判定介入是否合法并审计，S2 实施停止与取消。作用域契约：停止请求携带 scope_type ∈ {session, agent} ＋ scope_id（session 标识或 agent 标识），两级分别传递；缺失／空值／非法取值即拒绝（不猜默认值、不按 agent 级兜底）；S4 返回判定结果与审计标识，S2 按同一作用域参数执行；三处（S4 判定记录、审计记录、S2 执行记录）作用域参数逐字段一致；S4 不实施停止，S2 不改换或推断作用域、不得把 agent 级降为 session 级或反之。
判据：核验——构造缺 scope_type、scope_id 为空、scope_type 不在枚举内、scope_id 与该 agent 不匹配四类非法请求；合法请求逐字段比对三处参数｜比对对象——非法请求结果 vs 拒绝＋稳定码且不执行；三处作用域参数的一致性｜不合格——缺失或非法参数被兜底成某一级执行；三处参数不一致；S2 存在自行解释或改写作用域的路径；S4 与 S2 各实现一套作用域语义；S4 实施停止。

## 三、方案提案（本卡自决项：定义阶段内提案、007 审批定案；B3-S4「动作表数据来源与缓存策略由其提案」、B6 子卡定项）

### P1 动作表数据来源与缓存策略
选择：数据来源分两层。(a) 动作表条目内容（动作名／适用连线类型／判定规则／返回码）＝卡侧（009）业务动作类别清单＋本模块机械判定框架，作为「权限动作表」契约族版本化、单一真源落盘（版本化文档与代码常量同源，判等命令可校验）。(b) 运行时判定事实（卡类型声明的能力面、连线类型决定的动作面）经 S1 权威记录读取。
缓存策略：闸内只维护可重建的只读投影（卡类型声明视图、连线类型视图、动作表条目），每条带 global_seq 版本标记；每次判定前必做版本比对——投影版本与 S1 权威当前版本不一致即失效重载（重载失败按 R10 fail-closed 拒绝并报警）；权限面变更提交（经 S1 留 global_seq）触发订阅失效（IC-6）。硬约束：任何路径不得引入「下次刷新生效」窗口（H13-3 是二元断言）；若某路径无法做到判定前必比对，则整体放弃缓存、直读 S1。缓存是纯性能优化，整体移除不改变任何语义。
理由：H13-3 要求无延迟窗口，缓存的唯一合法形态是「带版本校验的投影＋判定前必比对」；H1 要求派生物可删可重建、不得成为权威。
分级：子卡自决项，007 审批定案。

### P2 判定索引结构
选择：能力面索引 card_type → capability set（回显与执行点共用同一集合，避免两处不一致）。管理权索引两级：一级 动作 → 适用连线类型集合（动作表匹配）；二级 主体＋目标＋连线类型 → 允许动作集合（连线实例匹配）。两级均为只读投影、可重建、带版本标记，不落第二份事实。所有跨 Agent 时点比较只用 global_seq，不用墙钟（H2）。
理由：管理动作判定本质是四元组查找，两级索引避免每次扫全表；可重建投影不违反 H1。
分级：子卡自决项。

### P3 闸内并发控制
选择：判定（读）与写入（经 S1）分离——闸入口并发判定互不阻塞（只读投影、无写锁），事实写入全经 S1 唯一写者留 global_seq。互斥单位为 session：同一 session 同一时刻至多一个 run（run 归属由 S2 记录；S4 以 session 标识作判定与审计的作用域单位，不承担调度）；不同 session 并行、不受 S4 阻塞。在途处置机械实现：动作提交时快照判定依据版本（卡类型／连线类型 global_seq）；权限面变更事件到达后对该动作后续推进做版本比较——提交版本早于变更版本且未开始则不开始；已在途则结果落盘并附「变更前已发出」（记录提交版本与变更版本），且不驱动后续。幂等键校验与审计写入在同一提交边界内（经 S1）。
理由：H2 禁止跨 Agent 局部序号与墙钟比较；session 粒度是产品所有者并发口径，S4 只承载作用域标识与判定，不重复实现调度。
分级：子卡自决项。

### P4 包组织
选择：S4 独立模块、独立子目录（源码仓位置与 module 组织由 S9 提案、007 审批，S4 在其框架内）；模块内至少四块——动作表契约（版本化＋判等命令）、判定（能力面执行点＋管理权执行点）、闸入口（唯一入口＋三分类回执＋审计生成＋幂等校验）、预检面（可选，只读查询判定快照）。预检面 DATA-ONLY：预检答案只是查询时快照，不得替代执行时判定、不得作为放行依据；预检「查不到」不得返回空集当无权限（继承旧系统 preflight「DATA ONLY—NEVER A PASS」「查不到≠空集」教训，仅作机制参照；旧系统以授权记录为中心的判定方式不继承，1.0 不设独立授权记录）。只依赖 S1 公开契约与卡侧动作类别契约；禁止跨组件导入内部包。
理由：模块边界即架构边界（B3 一对一拆卡）；预检面为 S5／S6／S9 提供只读查询而不制造第二生效入口。
分级：子卡自决项（仓与 module 归 S9 提案）。

### P5 作用域契约
选择：停止／取消与审计的作用域参数统一为 scope_type ∈ {session, agent} ＋ scope_id；缺失或非法即拒（R19）；审计同时带 agent 标识与（scope_type=session 时的）session 标识，保证同 agent 不同 session 记录唯一可定位。
理由：两级作用域须在判定、审计、S2 执行三处同构；用显式枚举替代「默认 agent 级」兜底，符合「禁止以兜底掩盖错误」。
分级：子卡自决项（与 S2 的接口形态需 S2 确认，契约族归 S10 基线）。
