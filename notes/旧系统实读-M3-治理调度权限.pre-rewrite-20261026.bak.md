## 1. 调度

### 1.1 建卡点火调度器 `src/api/scheduler.py`
- 队列结构：模块级 `_queue: Optional[asyncio.Queue]`（懒建，`_get_queue()` L48-52）+ 去重集合 `_pending: set[tuple[str, str]]`（L41），key=(work_id, card_id)。
- 入队：`enqueue(work_id, card_id)` L55-78；`_workers` 为空时退回到直点 `auto_driver.kick`（L61-67）；已在 `_pending` ⇒ 返回 False（L69-70）。
- 出队/worker：`_worker(index)` L81-103，`await q.get()`（L87）→ `_pending.discard`（L89）→ `auto_driver.kick`（L92）→ 若 task 非 None 则 `await task`（L98），**等整个回合结束才释放槽位**。
- 容量：`max_turns: int = 3`（L45）；`start(limit=3)` L105-114 创建 `max(1, int(limit or 3))` 个 worker task（L108, L112-113）。
- 优先级：**无**。文档 L24「不做优先级：先到先得」；代码 FIFO（Queue 默认 FIFO）。
- 停 worker：`stop()` L117-122 取消所有 worker task + `_pending.clear()`。
- 诊断：`stats()` L125-133 返回 queued/pending/max_turns/workers。

原样：
```python
# scheduler.py:81-103
async def _worker(index: int) -> None:
    ...
    while True:
        work_id, card_id = await q.get()
        try:
            _pending.discard((work_id, card_id))
            ...
            if task is not None:
                try:
                    await task
                except Exception:
                    pass
        finally:
            q.task_done()
```

### 1.2 每 work 串行执行闸 `src/api/serial_gate.py`
- 模式：`MODE_SERIAL="serial"` / `MODE_PARALLEL="parallel"`（L30-31）；`exec_mode()` L42-54 读 `config/exec_mode.json`，缺失/损坏 ⇒ `MODE_PARALLEL`（fail-open，L51-52）。
- 状态：`_locks: dict[str, asyncio.Lock]`（L38）、`_holder: dict[str, str]`（L39），每 work 一把锁。
- `acquire(work_id, card_id)` L74-90：并行模式直接 False；同卡已持有 ⇒ False（no-op）；否则 `await lock.acquire()`（拿不到＝排队等待，不是 409）。
- `release(work_id, card_id)` L93-102：仅持有者能放。
- `release_work(work_id)` L105-110：停止路径无条件释放（锁可能挂在本卡或后代）。
- 持有期：**一张卡的整个目标生命周期**（L10-14）；拿锁在 `routes._run_message` 起回合前，放锁在回合末按 `auto_driver.will_continue` 判定/目标终止/手动停止。

原样：
```python
# serial_gate.py:74-90
async def acquire(work_id: str, card_id: str) -> bool:
    if not is_serial():
        return False
    if _holder.get(work_id) == card_id:
        return False
    lock = _lock_for(work_id)
    await lock.acquire()
    _holder[work_id] = card_id
    ...
    return True
```

### 1.3 同时能跑几轮
- 全局：scheduler 默认最多 3 个回合并发（L45, L108）。
- 每 work：serial 模式下同一 work 同一时刻只有一张卡在跑，其余 await acquire 排队（serial_gate L3-9）；parallel 模式直接放行（等同旧行为）。

## 2. 停止与暂停

### 2.1 停止入口
1. HTTP：`routes.post_work_stop` `POST /works/{work_id}/cards/{card_id}/stop` L1828-1845 → 调 `control.halt`（L1838）+ `control.stop_auto`（L1840）。
2. 卡面工具：`card_tools._h_stop_card` L4851-4914，两档 `interrupt`/`halt`（L4863, L4892-4899）；权限=祖先（root 全树），`_is_in_subtree` 判定（L4881）；target 不可为 root（L4876）。
3. scheduler 停 worker：`scheduler.stop()` L117-122（关停时）。
4. 控制面函数：`control.request_stop` L118-159、`control.halt` L46-55、`control.cancel_turn` L99-116、`control.stop_auto` L263-349、`control.discard_stop` L174-188。

### 2.2 能否打断正在跑的那一轮
能。`control.request_stop` L118-159：
- 在模型流里（`model_service.in_stream` 为真，L145-146）⇒ 置停止信号 `stop_event_for(...).set()`（L140），与下一个 chunk 赛跑，立刻收口，已产出字保住（L123-125）。
- 不在流里（工具执行/上下文装配）⇒ 直接 `cancel_turn` 取消协程（L149-150）。
- `cancel_turn` L99-116：取 `_turn_tasks` 里的 task，非 None 且未 done 且非当前协程 ⇒ `task.cancel()`（L113）；同协程返回 False 退回置位（L109-112）。

原样：
```python
# control.py:126-150
holder = session_facade.turn_holder(work_id, card_id)
if not holder:
    return {"stopped": False, "reason": "no_inflight_turn", ...}
_stop_requests.add((work_id, card_id))
stop_event_for(work_id, card_id).set()
...
if not _waiting_on_stream:
    cancel_turn(work_id, card_id)
```

### 2.3 停止粒度
- 轮内可中断：信号在流里立刻收口；不在流里直接 cancel 协程（L123-150）。
- 步边界消费：`check()` L162-171 consume-once；`_stop_requests` 在步边界被消费（L165-168）。
- `discard_stop()` L174-188：回合收口时清扫残留置位，避免下一回合误消费（T124）。
- `halt()` L46-55： zusätzlich 置 `_HALTED` 标记（L50-54），拒绝内部唤醒，仅用户发话/resume_child 解除（`unhalt` L58-60）。
- 结论：**不是纯轮边界**——有比步边界更细的协程取消/流内信号；但 `request_stop` 的置位本身在 `check()` 步边界消费，且 `discard_stop` 在回合收口清理。

### 2.4 停止后状态记录
- `_stop_requests` / `_stop_events` / `_turn_tasks` 进程内（control.py L36, L74, L84）。
- `_HALTED` 进程内 dict（L43）。
- `session_ops.ops_log("human_stop", ...)`（L151-153）。
- `stop_auto`：目标 `active → paused` 走 `goal.service.pause()`（L297-302）写 goal/change 事件+重投影；legacy 卡退回写投影列 `goal_state=paused`（L305-308）；级联子树内 auto 卡（L286-287）；清 `goal_await_children`（L327-329）；`serial_gate.release_work` 释放锁（L339）；留痕 `session_ops.ops_log("auto_stop", ...)`（L341-344）。
- `_auto_subtree` L236-260 沿 parent 链收集后代。

### 2.5 暂停能否只做轮边界（事实基础）
- `request_stop` 已支持轮内立即中断（信号赛跑 + cancel 协程）（L123-150），`halt` 叠加 goal pause + `_HALTED`。
- `stop_auto` 走 goal 服务 pause 事件（L297-302），跨重启有效（L277-278）。
- 因此「暂停能否只做轮边界」——现有停止机制**不止轮边界**，已具备更细粒度中断与持久 pause。

## 5. 权限模型

### 5.1 数据结构
- 卡上固化字段：`PERM_KEY="perms"`、`PERM_VERSION_KEY="perms_version"`（policy.py L172-173），存 card meta（`card_store`）。
- `perms` 为开关字符串列表；`perms_version` 为配置 version（auto 卡专用 -1，L273）。
- 配置源：`config/permissions.json`（`PERMISSIONS_PATH` L168），结构 `{"version": int, "permissions": {project_class: {card_type: [switch...]}}}`（`perms_for` L198-224）。

### 5.2 发权时机
- 建卡时算一次：`compute_perms(project_class, card_type)` L227-229 → `perms_for` + `config_version`（L198-224, L189-195）。
- 自动模式卡：`auto_perms()` L276-281 ⇒ `sorted(AUTO_SWITCHES), AUTO_PERMS_VERSION(-1)`；但 backfill 注释称 2026-10-19 后 auto 不再全开、走类型分权（backfill.py L98-99）。
- 运行时只读卡上 perms，不读配置（`has_perm` L288-313）。
- 刷新：`scripts/refresh_perms.py`（backfill 模块 L9-10）；offline 回填 `permissions.backfill` L1-38。

### 5.3 校验函数
- `policy.has_perm(card_meta, switch)` L288-313：switch 不在 SWITCHES ⇒ False；卡 meta 无 perms ⇒ False；含 `_SWITCH_IMPLIES` 隐含（tools_file ⇒ tools_read_file，L308-313, L138-140）。

- `policy.can(...)` L398-447：唯一作用域规则表（目标存在→类型分权→自己→root→role/function→子树）。
- `policy.check_linked(...)` L497-521：通信线边界，`_linked_between`。

## 6. 写范围校验

- 本仓库 `src` 全树检索（grep `WriteScope`/`effective_write_scope`）**未找到**对应符号定义；所读 6 个文件内也无此实现。

- 结论：`WriteScope`/`effective_write_scope` 在本系统**不存在**（登记为未解/不存在，不猜）。

## 7. 多用户/多实例

- 所读文件与 `src` 全树检索：**不存在用户ID、会话隔离、登录态相关代码**（面向多用户/租户/cookie/jwt/auth 中间件均无）。
- `work_id`/`card_id` 是工作空间/卡片标识，不是用户身份（`scheduler._pending` key=(work_id, card_id) L41；control._stop_requests key=(work_id, card_id) L36）。
- `wb_exec` 的 auth/login 仅指外部 codebuddy CLI 登录（`acp_client.is_auth_required` L63；`registry.mark_unauthenticated` L390），非本系统多用户。
- 会话存储 `session_facade`/`session_ops` 以 work+card 为键，无用户维度（`session_facade.turn_holder(work_id, card_id)` 被 control 调用 L133）。

## 关键发现
1. 调度两层：全局 FIFO 队列最多 3 并发（scheduler.py L45,L81-103）+ 每 work 串行锁（serial_gate.py L38-90）；serial 默认开启由 config/exec_mode.json 决定（L42-54）。
2. 停止不止轮边界：request_stop 在流里信号赛跑、不在流里 cancel 协程（control.py L123-150），halt 叠加 goal pause 与 _HALTED 标记（L46-55,L297-302）。
3. 权限运行时只读卡上 perms，建卡时算一次；auto 卡专用 version -1；SWITCHES 共 17 项（policy.py L69-131）。
4. WriteScope/effective_write_scope 在本系统不存在；文件路径锁是 FILE_SCOPE+check_file_access（file_tools.py L108-206）。
5. 多用户/登录态代码不存在；标识维度为 work/card，外部 CLI 登录不算本系统用户。
