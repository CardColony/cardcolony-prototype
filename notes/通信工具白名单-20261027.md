# 通信工具白名单（2026-10-27）

> 用户：「只说通信」

按你定的两个接口收：**同步（进上下文、不叫醒）／唤醒（进上下文、叫起来）**。

## 一、通信只有两个接口，工具是它们的两个方向

| 接口 | 工具 | 调用量 | 方向 |
|---|---|---|---|
| **同步** | `sync` | 459 | 任意（沿通信线） |
| **唤醒** | `direct` | 147 | **向下**（对子树内的卡派活） |
| **唤醒** | `report_up` | 153 | **向上**（父卡＋总裁，收件人由系统算） |
| **唤醒** | `report_done` | 2 | 向上，coder 专用（模型只报，回执系统发） |

**注意：`direct` 和 `report_up` 不是两种接口，是同一个"唤醒"的两个方向。**
一个往下派活、一个往上汇报——差别在收件人怎么算，不在效果。

## 四、退役 3 件

| 工具 | 调用量 | 为什么 |
|---|---|---|
| **`read_inbox`** | **121** | **死工具**。消息已落会话块（进上下文），`messages` 表不再写；它读的正是那张表。121 次调用全读空，还让模型误以为"没人给我发消息" |
| **`scene_report`** | 3 | `report_up` 的壳——实现只有一行 `setdefault("kind","done")` 然后转过去。语义零区别，白占一个选择位 |
| **`send_card_message`** | 208 | **零下发**（作业卡被 lateral 闸摘、职能被 `_ROLE_FACE_DROP` 摘、总裁面按目录替换）。那 208 次是 10-23~25 的历史。函数保留作内部薄壳（`report_done`/`issue_directive` 在用），**模型侧退役** |

## 五、边界：这几件不是通信

| 工具 | 为什么不算 |
|---|---|
| `wake_card` / `stop_card` / `silence_card` | **改对方状态**（叫起来／停／沉默），不是"发一条消息" |
| `stage_open` / `continue_task` | 业务流程动作（开阶段／续派），副作用里带发消息，但本身不是通信 |
| `open_review` / `approve` / `set_criteria` / `revoke_approve` / `decide` | 评审机制（伴生评审卡），另一套 |
| `issue_directive` / `verify_directive` / `record_verdict` / `write_ledger` | 职能台账 |

**它们会间接产生消息，但工具语义不是"发话"。** 混进通信面会让模型把"改状态"和"发消息"当成一回事。
