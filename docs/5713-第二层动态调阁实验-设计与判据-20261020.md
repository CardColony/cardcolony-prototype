## 一、被验的对象：一条「调阁」生命线，不是一个「部门表」

第二层＝由根卡组阁、持**排他责任域**的离树角色卡集合。它的价值不在"设得对"，
而在**能改**：局面变了，CEO 能随时设/改/并/撤，且每一步都不烂账。

因此实验不验"3–5 个职能跑得好不好"，只验这条线逐环是否机械成立、是否有账可查：

| 段 | 动作（CEO 的经营动作） | 要机械成立的事 |
|---|---|---|
| A | 组阁一个角色，声明排他键 + 关注卡 + 信号 + 契约 + 升级线 | 角色建成为离树卡；关注连线＝关注集合；排他键落档 |
| A' | 同排他键再组一个 | **机械拒**（同域只能一个角色，占域者明示） |
| A'' | 巡检 | 起回合；真模型**必须落判词**（speak/silent 都落账）；互斥事实应触发警报 |
| B | 改档：职责书换版 | 版本 +1；**v1 原文留在版本史**（改档不覆盖历史） |
| B2 | 改档：换关注集合 | 连线随声明走（摘掉的解线、挂回的接线） |
| C | 停职 | 巡检**不点火**（started=false）；但期间的新事实**要进队列**（事实不丢） |
| D | 复职 | 立即补巡检 ⇒ **停职期间的新事实被看见**并落新判词 |
| E | 撤岗 | 关注连线全解；**判断簿/警报簿/职责书版本史全部保留**（撤岗留痕，不物理删） |
| F | 顶空域：新角色占同一排他键 | 成功（archived 不占域）；再撞域**又被拒** |

## 二、验的边界（如实标注，不含糊）

- 组阁/改档/停复撤的**决策**由实验场景预置——验的是**机械通道与台账**，不是根卡模型
  的组阁判断力。根卡模型的组阁质量是另一件事（见五）。
- 组阁通道走 HTTP 面 `POST /works/{wid}/roles`，与根卡工具 `create_role` **同一执行体**
  （`src/api/routes.py:1320` 注释原文），故通道等价；差别只在没有真模型根卡做决策。
- 真模型只用在**判词段**（A''、D）——这是第二层唯一真正需要模型的地方：读材料、判断、开口或闭嘴。

## 四、排他键纪律（从机制事实直接推出，非发明）

1. **一域一角色**：同一时刻同一 `exclusive_key` 只允许一个非 archived 角色（机制已机械拦截）。
2. **archived 不占域**：撤岗即释放排他键，可由新角色顶替（故"撤"是安全动作，不必怕占死）。
3. **改域＝改档，不是新设**：责任域漂移时改 `jurisdiction.exclusive_key`，
   但改域同样受唯一性校验——若要搬到别人占着的域，必须先处理占域者（撤或改）。
4. **空域要在案**：机制只保证"不重叠"，不保证"不留空"。留空是 CEO 的账——
   组阁清单里没有对应排他键的责任域，就是没人盯的域。

## 五、组阁纪律（写成指导，不硬编码）

- **何时设**：出现没人认领的责任域，或同一类事故重复≥2 次且没有角色会为它开口。
- **何时改档而非新设**：域没变、只是范围/关注/契约要调 ⇒ 改档（版本史留痕）；
  域变了（责任对象换人）⇒ 改 `exclusive_key` 或撤旧设新。
- **何时撤**：域消失（如该议题已闭环）；或连续多轮全 silent 且写不出触发线（说明它没有判断对象）。
- **何时停而非撤**：短期无材料但要保留判断连续性（撤岗虽留账，但关注会全解，复职要重挂）。
- **防重叠**：设之前先 `GET /roles` 看现有排他键。
- **防空域**：每次调阁后扫一遍"当前在乎的事"与"已组阁域"的差集。
- 组阁时**必须写清"什么算触发"**——机制只保证"若不开口也要落账"，不保证它判断得准。

## 六、边界

- 全部只在 5713 分支/worktree/沙箱内；5700 生产目录/数据/进程全程不碰。

- 撤岗不物理删卡（台账即证据链）。
