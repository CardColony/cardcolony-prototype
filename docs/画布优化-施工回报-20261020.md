## 二、做了什么

### 2.1 信息更新：工作级事件广播（新增能力）

**病根**（逐条核实，不是推测）：

- 卡片结论／待裁定数／work_state／最新对话**只写在 `createNode` 里** ⇒ 只有全量
  `renderAll` 才生效；而 `renderAll` **只由用户自己的操作触发**（建卡、删卡、
  重命名、拖动落定…）。后台真实发生的变化——模型写卡、裁定被记下、自动模式推进
  ——**没有任何通道能通知画布**。
- 既有 SSE 是**单卡**的（订阅表 `key=(work, card)`），**没有工作级广播**。
- `canvas.js` 订阅的是 `card_id=WORK_ID`（根卡）那一条 ⇒ 别的卡的 `card_message`
  收不到。
- `/works/{w}/pulse` 的 running/recent **不驱动卡面重绘**（`applyLiveStates` 只写
  `dataset.live` 与一行消息条，conclusion/pending_count/work_state 一个都不碰）。

**修法**（三层）：

| 层 | 文件 | 内容 |
|---|---|---|
| 事件 | `src/api/event_stream.py` | 新增工作级广播：`emit_work` / `subscribe_work` / `work_subscriber_count`。与主通道**完全隔离**（不进 `_journals`、不占主 seq、不写 works 文件、不进模型输入），零阻塞零抛出 |
| 写路径 | `src/storage/card_store.py` | 新增 `_notify_card_changed(work_id, card_id, kind)`，挂在 create／update／delete／restore 四处。**延迟 import**（storage 不在导入期依赖 api，与既有 `from ..api import scheduler` 同手法），失败零阻断 |
| 载荷 | `src/storage/canvas_store.py` | 新增 `card_projection(work_id, card_id)`：从**刚重建过的**画布投影里取那一张卡 ⇒ 事件里的 card 对象与首屏 `/canvas` 返回的**字段完全同源**，不会出现"事件里少个字段导致卡面缺零件" |
| 端点 | `src/api/routes.py` | `GET /api/works/{work_id}/events`（SSE，帧形态与既有 `/stream` 同构，15s 心跳） |
| 前端 | `static/canvas.js` | 订阅 + **就地更新那一张卡**（不重建整棵树） |

**前端为什么是"换卡面"而不是"换节点"**：

初版实现是 `old.replaceWith(fresh)`——后台一次更新就把用户**正要点的**那张卡换掉了，
那个 click 落在一个已脱离文档的节点上 ⇒ **点了没反应**。现改为**保留节点身份**：
只把卡面内容（innerHTML + dataset + aria）搬到老节点上 ⇒ 监听器、焦点、拖拽态、
展开的对话单元全都在。配套把**卡面子元素**的监听（子卡徽章／↗／待裁定条目）从
**节点级**监听里拆成 `bindCardFace`——换卡面后要重绑子元素，而节点级监听**不能**
重绑（重绑＝重复绑定：单击跳两次页、展开翻两次）。

**实时更新必须同时改两张表（这条是踩出来的）**：

`state.data.cards`（原始列表）与 `state.index`（派生索引）**必须同步**。
初版只改了 `state.index`，而**布局算法读的是 `state.data.cards`**
（`collectProjectionInput` → `computeLayout(input.cards…)`）——两张表一分裂，
布局算出来的位置里就没有这张卡 ⇒ 增量渲染写不回坐标 ⇒ 节点永远停在占位坐标 (0,0)
且带 `.entering` ⇒ **整片画布的卡片全部不可见**（只剩连线）。
这是"索引是派生数据、原始列表才是真相"的典型：只改派生数据 = 制造不一致。

配套加了一道**半渲染自检**（`_assertNoGhostNodes`）：增量渲染之后若还有节点
"既是 (0,0)、又带 .entering" ⇒ 说明坐标没落到位 ⇒ **退回全量重绘**。
全量重绘慢一点，但一定对；半渲染错一点点，就是整片看不见。

**新卡的插入位置也必须与服务端同口径**：

服务端投影是 `ORDER BY card_id`；若把新卡 `push` 到列表末尾 ⇒ `childMap` 顺序变了
⇒ 同层卡排布变了 ⇒ **实时更新过的画布与刷新过的画布长得不一样**（肉眼不一定
看得出，但按坐标点击会落到不同的卡上——e2e 的差异就是这么暴露的）。
现在新卡按 `card_id` 升序**插入到正确位置**，两条路径产出同一布局。

**可执行不变量**（加进 `tests/canvas_live_update.mjs`）：

> 建一张卡再删掉它（触发两轮实时更新）之后，DOM 顺序必须与**重新加载页面**之后的
> DOM 顺序**逐字相同**。实测 `invariant_liveEqualsReload = true`。

**SSE 健康度要单独记**：`EventSource` 对象存在 ≠ 连接可用（企业代理会"接受连接
但不投递"）。兜底轮询按**健康度**（`onopen`/`onerror`）接管，而不是按对象在不在；
兜底命中时走**静默重拉**（`reloadCanvas({silent:true})`）——画布上已经有内容了，
再弹一次骨架屏就是一次"白一下"。

### P0-4 的两条失败模式（都实测过，改法不是拍脑袋）

| 机制 | 症状 | 为什么"改成 transition 就行"是错的 |
|---|---|---|
| `@keyframes` 起始帧 `opacity:0` | 动画不跑 ⇒ 停在起始帧 ⇒ 卡片永远透明 | — |
| `@starting-style` + `transition` | transition 不跑 ⇒ **starting-style 一直挂着** ⇒ 卡片同样永远透明 | 探针实测：`animation` 关掉后 p3 仍是 `opacity=0` |

⇒ 唯一可靠的口径：**入场的起始态里不能有 opacity**。改成只动 transform 后，
起始态即便钉住，卡片也**照样看得见**（只是没有淡入）。退化方向必须是
"少个动画"，不能是"看不见"。

> 这条缺陷**基线也有**（dev 原样跑，在内置浏览器里打开画布同样只剩连线）。
> 它之所以长期没被发现：绝大多数时候窗口在绘制、动画能跑 ⇒ 卡片正常；
> 一旦窗口未绘制/标签页在后台，就出现"画布空白"，且**没有任何错误信息**。

### 2.5 「从画布进对话」的入口（产品层）

用户 2026-10-20 问的第一句话是产品问题，不是代码问题：**"我现在怎么通过画布，
进入对话界面？"** 盘清后的结论是：路有 4 条，但**没有一条是明确可发现的**——
单击是 220ms 静默延迟后整页跳走、↗ 是 opacity .45 的暗色小箭头、
"就地展开对话"（用户 10-19 反复要的那个）是**纯隐藏手势**、右键与 Enter 要先知道。

**改后的手势矩阵（一个语义一个入口，没有任何一个手势有两种结果）**：

| 输入 | 结果 |
|---|---|
| 单击卡 / 单击标题 | 打开完整对话页（对**所有**卡一致，**含有子卡的**） |
| ↗ | 打开完整对话页 |
| 💬 | **就地展开对话**（不离开画布，可直接回复） |
| Enter | 就地展开对话 |
| 空格 | 展开/折叠子卡 |
| ▸N 徽标 | 展开/折叠子卡 |
| Shift+单击 | 多选（不跳走） |
| Alt+单击 | 画布内下钻（不跳页） |
| 拖拽 | 移动卡片 |
| 右键 | 菜单（打开对话 / 在此展开对话 / 展开子卡 / 建子卡 / 重命名 / 删除…） |

三处具体改动：

1. **撤除双击手势**。单击要跳走就得留 220ms 的双击判据窗口，而普通人双击间隔是
   150–300ms —— **超过 220ms 时第一次 click 已经把页面跳走了，双击永远到不了**。
   ⇒ "就地展开对话"在真实使用中时灵时不灵，而且它和单击是**同一手势的两个互斥
   结果**。撤除后单击**立即**跳走（"点了没反应"的 220ms 也没了），就地展开对话
   改由 💬 / 右键 / Enter 三个**明确入口**承担。
2. **新增卡上的 💬「在此展开对话」**（hover 显形，卡左下角）：把"就地展开"从
   隐藏手势升级为**看得见、点得到**的入口——这正是用户 10-19 要的
   "在画布上同时看几个对话的进程并随时回复"。右键菜单同步加同一条。
3. **↗ 由 opacity .45（hover 才显形）提到 .78**：画布上唯一显式的"进对话"入口
   不再隐形。单击后立刻亮出"正在打开对话…"，消除"点了没反应"的静默等待。

### 2.6 第二轮全量排查（2026-10-20 晚）：套件从 160 例扩到 175 例，又抓出 5 个真问题

用户批"验收不够合格"之后，第二轮把套件从 160 例扩到 **175 例 / 11 组**
（新增 T11「手势与锚点」组），**扩的过程本身又挖出 5 个此前完全没看见的问题**。
其中三个是**产品层说错话/做错事**，两个是**测试自己骗人**。

#### 2.6.1 P1：拖拽锚点判据用错了 key ⇒ 下钻后"拖了又弹回"

- 病根：`computeLayout` 钉在原点的是 **viewRoot**（`collectProjectionInput` 传的就是
  `state.nav.viewRoot`；下钻 `setViewRoot` 会改它），而拖拽分支判的却是
  **workCardId**（项目根卡，全生命期不变）。**下钻之后两者不是同一张卡**：
  - 当前视图根（标着 `.is-root` 的那张）走**普通拖拽**分支 ⇒ 落库坐标后 `reflowAll`
    又被 `computeLayout` 拉回 `(0,0)` ⇒ **拖了又弹回**（而且卡跟着鼠标动过，
    落空感极强）；
  - 真正该"拖根卡＝平移"的项目根卡此时**不在可见集**里 ⇒ 下钻后没有任何卡能用来
    平移视图。
- 改法：判据改成 `state.nav.viewRoot`。默认视图行为**逐字不变**
  （viewRoot === workCardId），下钻后由当前视图根承担"拖＝移动视图"，
  与 `.is-root` 样式、布局口径完全一致。
- 守护用例 T11.2 同时验两件事：视图被平移（world transform 变）＋
  锚点自身位置不变 ＋ **不写坐标记录**（没有落库副作用）。

#### 2.6.2 P1：同层排序把"存过坐标的卡"一律提到前面 ⇒ 第一次拖某张卡时落点被忽略

- 病根：`layoutTree` 的同层排序是"按存储的 y 排；**没存过 y 的排在有 y 的后面**"。
  而"存过 y"只对**被拖过的卡**成立 ⇒ **同层里第一次拖某张卡时，它会被提到该层最前面**，
  用户的落点被完全忽略。
- 实测（沙箱 work_002，探针留证）：把 `card_017` 拖到 `card_010` 下面
  （落点 y=50，介于 card_010 的 20 与 card_016 的 108 之间），
  结果它跑到**第 3 位** —— 想插中间，却插到了最前面。
  只有"以前拖过的卡"之间才比得公平。
- 改法（不碰布局纯函数、不改存储格式）：落子那一刻，把**同层所有卡**的 y 统一写成
  "它们当前占的位置"（被拖的那张写成落点 y）——一层人的顺序被显式记下来，
  布局按 y 排序即可**原样复现用户的意图**。
  为什么不写进布局：布局是纯函数（card_045 E1 纪律），不该读 DOM；
  而"同层当前次序"是运行时信息，只有落子那一刻才确定。
- 守护用例 T11.4 用**一次性脚手架工程**（根卡 + 3 张子卡，坐标记录随卡删除而消失）
  ⇒ 每次跑都在"同层从没拖过"的干净前提下验，**不受上一轮残留影响**。

#### 2.6.3 P1：右键菜单的快捷键提示在骗人（三条）

菜单里的 `.cv-kbd` 芯片是**用户看得见**的。三条提示与真实手势对不上：

| 菜单项 | 原提示 | 真实手势 | 后果 |
|---|---|---|---|
| 打开对话 | `↵` | `↵` 实际是**就地展开对话** | 按 ↵ 期望跳整页，却就地展开了 |
| 在此展开对话 | `双击` | **双击手势上一轮已撤除** | 按双击什么都不会发生 |
| 下钻到此卡 | `Alt+双击` | 实际是 **Alt+单击** | 照着做按双击，永远下钻不了 |

⇒ 改法：↵ 只标在它真正对应的动作上（就地展开），"打开对话"不标，
下钻改写 `Alt+单击`。同时清掉代码里描述"已撤除的双击"的陈旧注释（死件纪律：
注释说的不是代码在做的事，等于骗人）。
守护用例 T11.1 机器可验：菜单里**不得出现"双击"**、`↵` 只能挂在就地展开上。

#### 2.6.4 P1：新建卡弹窗是另一套自制小面板（顺带一个真 bug）

"新建卡片"原来用的是**inline style 拼的右上角小面板**，与"重命名/删除"的
`cvDialog` 是两套交互语言；而且它有两个实打实的问题：
① 它的 Escape 只 `node.remove()`、**事件继续冒泡** ⇒ 画布的全局 Esc 处理器跟着执行
⇒ **关弹窗的同时把选中的卡也清了**（一个动作干了两件事）；
② 没有遮罩、没有焦点陷阱、没有 `aria-modal` ⇒ 读屏/键盘用户完全没提示"弹窗开着"。
⇒ 并入 `cvDialog`（捕获阶段拦 Escape/Enter、Tab 焦点陷阱、初始焦点在输入框）。

#### 2.6.5 P2：关键控件命中区补到 WCAG 2.2 最小目标尺寸（24×24）

审计探针把 22×22 / 18px 高的控件列进 `smallHits`。三处都在 `canvas.css` 的
**画布专属作用域**内，视觉零变化：

|---|---|---|---|
| 💬 在此展开对话 | 22×22 | **24×24** | 与 ↗ 同一档；`/var(--z)` 补偿照旧 |

#### 2.6.6 测试自己的两个缺陷（本轮自查出来的）

1. **T10.1 的断言口径是错的**：它断言"拖完坐标变了"。但画布的产品口径是
   **"拖拽＝调顺序，绝对坐标仍由布局算"** —— 同层顺序没变时，落点后坐标回到同一个
   槽位（**坐标不变是设计，不是没生效**）；而且原用例选中的第一张非根卡常常
   **没有同层兄弟**，拖了也不可能改顺序。⇒ 改成断言真正该成立的那件事：
   **拖过同层卡之后，它排到了落点指定的那一位**。
2. **T10.10 在自我饿死**：它去画布上找一张"没有子卡的叶子卡"当删除对象，
   **而且真的把它删掉** ⇒ 每跑一次套件就少一张叶子卡。沙箱 work_002 被吃空后
   （实测 37 张 → 35 张，叶子归零），本用例开始**假红**（"找不到"），
   而画布其实没有任何问题。⇒ 改成**自给自足**：自己建一张叶子卡、只删自己建的那张。

> **两条都记在这里，因为它们和被我修掉的画布 bug 是同一类东西**：
> 测试自己会骗人，不是因为测试写得差，而是因为**断言写的是"我想看到什么"，
> 而不是"系统承诺了什么"**。口径错了，红的绿的都是假的。

### 2.7 第三轮：端到端 e2e 复跑，又挖出 1 个 P0 + 1 个 P1

#### 2.7.1 【P0】画布**永久空白**：出图的关键路径上挂着一个网络往返

- 症状：画布页**卡在骨架屏、0 张卡**（页面标题栏的数据都出来了，只有画布是空的）。
  复现路径：画布 → 点卡进对话页 → **重新导航**回画布 ⇒ 永久空白。
- 病根（三条证据串起来）：
  1. 画布"找根卡"是 `await API.listWorks()` —— 一次**在出图关键路径上**的网络往返；
  2. 浏览器对同一源有 **6 条并发连接**的上限（HTTP/1.1），而画布页**常驻**着 SSE
     长连接（工作级 `/events` ＋ 单卡 `stream`）⇒ 页面加载时的并发请求把连接槽占满；
  3. 于是那条往返被**排队、永远发不出去** ⇒ `await` 悬着 ⇒ `reloadCanvas` 停在半路
     ⇒ `renderAll()` 根本没跑 ⇒ 骨架屏永远不撤。
- 决定性实验：探针打印网络层 ⇒ `/api/works` 只有 `[REQ]`（发出去了）**没有 `[NET] 200`**；
  同一时刻在页面里手动 `fetch('/api/works')` **秒回 200**（服务端没问题、连接池也没满）；
  再用 `Network.setBlockedURLs` **屏蔽工作级 `/events`** ⇒ 画布**立刻正常出卡**。
  ⇒ 三件事同时成立才定位到它：**一条常驻长连接 + 一个关键路径往返 + 6 连接上限**。
- 修法（两条一起）：
  1. **根卡不再等网络**：画布数据里 parent 为空的那张**就是**项目本体
     （`card_store._normalize_parent`：剧本卡 parent 强制 ""）⇒ 直接用它出图，**零往返**；
     `/api/works` 退化成异步补充（只核对权威 `work_card_id` 与补标题），拿不到也不影响出图。
  2. **画布页的常驻长连接从 2 条降到 1 条**：原来还有一条
     `/api/works/{w}/cards/{w}/stream` —— **card_id 那个位置传的是 work_id**（不是卡号）
     ⇒ 订阅的是一条**永远不会有帧**的键 ⇒ ① 未读角标的增量通道**从来没活过**
     （只剩 60s 轮询）；② 却长期白占一条连接。删掉它，并把 `card_message` 帧
     改由**工作级**流广播（后端 `card_tools.py` 多广播一帧）⇒ 一条连接收全，
     顺带把那条死了很久的增量通道**修活**。
- 守护用例 **T12**（3 例）：① 让项目列表端点**永不 settle**（模拟"被排队"）⇒ 画布仍出图；
  ② 画布页不订阅那条"把 work id 当 card id"的流；③ 常驻长连接恰好 1 条。
  ⚠ 第一条一开始写成"让请求**失败**"——那是**假守护**：旧实现有兜底（退回 `cards[0]`），
  照样出图。改成"永不 settle"才真正复现症状。

#### 2.7.2 【P1】根卡上的控件（💬 / ↗ / ▸N）点了没反应

- 病根：平移态的 CSS 是
  `.page-canvas #viewport.panning .card-node { pointer-events: none; }`
  —— **平移中所有卡片都不可点**。而**根卡**（视图根）的 mousedown 会进"拖根卡＝平移"分支
  ⇒ 按下的瞬间 viewport 就进了 `.panning` ⇒ **鼠标抬起的落点变成 viewport**
  ⇒ 浏览器合成的 `click` 的 target 是 viewport ⇒ 控件的 click 处理器**根本没被调用**。
- 症状：**根卡上的 💬（在此展开对话）／↗（打开对话页）／▸N（展开子卡）点了没反应**
  —— 而根卡恰是打开画布看到的第一张卡、最显眼的那张。
  （其它卡不受影响：它们的 mousedown 只起拖拽、不加 `.panning`。）
- 修法：控件上的按下**不抢**——mousedown 落在卡内控件（button / 徽标 / 输入框）上时，
  节点级 mousedown **直接返回**，让控件自己处理这次点击。
- 守护用例 **T11.6**：必须用**真实鼠标事件**（CDP `Input.dispatchMouseEvent`）验——
  只有真实的"按下→抬起"才会让浏览器合成 click，而 click 的落点取决于"抬起时指针下面是谁"；
  用 `el.click()`（直接派发）永远命中按钮 ⇒ 假通过。

#### 2.7.3 测试自身：命中矩阵的探针假设了"标题左对齐"

`canvas_hit_matrix.mjs` 的"点标题文字"探针取的是**标题盒**的左边缘 + 12px。
而**根卡的标题是居中的**（`style.css .card-node.is-root{text-align:center}`），
标题盒比文字宽得多 ⇒ 那个点落在**空白**上（正好落在 💬 上）⇒ 报"点标题命中的是 cv-chat" ⇒ **假红**。
⇒ 改用 `Range.selectNodeContents` 量**文字的真实矩形**再取点。
（同一条实探针也顺手验了"短卡会不会被压"：造了一张只有标题的紧凑卡实测 ⇒
💬 落在卡片的左侧留白里，与文字**不重叠**、点文字命中标题 ⇒ 产品本身没问题。）

#### 2.7.4 顺带修好的两支陈旧 e2e

- `canvas_crud.e2e`：它断言的是**旧的自制新建卡面板**（`#newCardTitle`）⇒ 我把弹窗并入
  `cvDialog` 之后它必然挂 ⇒ 改成新选择器（`.cv-modal-input` / `[data-role=ok]`）；
  顺带修掉它一个**空跑断言**：删除那步写的是 `JSON.stringify('${delBox.id}')`
  —— 单引号把插值表达式包成了**字面量** ⇒ 卡号根本没进表达式 ⇒ 断言恒为 false
  ⇒ "删除卡生效"一直是**恒真的假通过**。现在它真验了（并补了"删除前弹确认框"一条）。
- `canvas_journey.e2e`：它整条路径是按 10-19 之前的交互写的（单击＝选中不跳页、
  小地图点击导航——小地图早被产品删了）⇒ 在 dev 线与本分支上**都是崩的**（崩点不同）。
  ⇒ 按当前产品语义重写：单击＝进对话页、Shift+单击＝选中且不跳页、
  小地图那步换成"💬 ＝就地展开对话"、"整理布局"要先展开「更多」菜单再点
  （旧写法直接点隐藏元素的坐标 ⇒ 崩在 5700 上）。

## 五、是不是补丁

**不是补丁**。判据三条：

1. **不是绕过，是补上缺失的机制**：工作级事件广播是**新增的一层**（事件层＋写路径
   挂钩＋端点＋前端消费），不是给既有路径打补丁绕过。
2. **不是特例处理，是一次性把口径对齐**：浮层显隐收回 `.active`（对齐
   `style.css` 的语义）、可见集改读投影（对齐 V3 不变量）、存档读写两侧对齐、
   版本戳与测试基线同步——都是**把两套口径并成一套**。
3. **新增的验收工具会长期在网**：`canvas_live_update.mjs` 是"信息更新"这条诉求的
   **可执行定义**；`canvas_audit.mjs` 是画布的体检清单。两者都进版本库。

**遗留的债（如实登记）**：

- ~~工作级事件**只覆盖写卡路径**~~ —— **本轮已核清并改写**：真正会**显示在画布上**的
  变化，全都在覆盖范围内：① 卡片行的增删改（`card_store` 四个入口）② 一轮对话收口时的
  结论回写（`message_runner` 走的是 `card_store.update_card`）③ 卡间信落信（新增的
  `card_message` 工作级广播）。**不在覆盖范围内但也不需要覆盖**的三条：影子卡
  （存在**独立的影子表**里、根本不是画布上的卡）、记忆凝练（写的是记忆/会话，不改卡面）、
  工具卡的内部推进（卡面的"运行中"由既有的 `/pulse` 轮询带，5 秒级）。
- 事件流是**单进程内存态**（继承 `event_stream` 的既有约束 A44）：进程重启后
