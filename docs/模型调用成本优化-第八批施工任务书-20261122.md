# 模型调用成本优化 · 第八批施工任务书

**目标**　用第七批台账补齐第三至六批的证据，完成三条组合回放，交一张逐项放行表。本批施工范围是取证、隔离试点、回退验证和发布准备。第一、二批沿用现有行为与已核实证据。 [第七批任务书](模型调用成本优化-第七批施工任务书-20261122.md) · [前六批验收报告](模型调用成本优化-第一至六批验收报告-20261122.md)

**顺序**　固定基线 → 独立复跑待补证项 → 组合抽查与回退 → 逐项给结论。台账部署验证单列，有已批准的窗口时执行。隔离工作可独立完成。生产发布、重启 5700 整组、调整生产开关及新增付费模型调用均按项目规则单独请示。 [项目规则](../AGENTS.md)

## 一、基线与证据口径

1. 开工先登记源码版本、隔离副本路径、模型座与实际线路、开关值、任务入口、材料版本及业务通过条件。可复用既有隔离用例和出站证据。证据需能定位到具体样本、A/B 开关、实际请求及业务回执。缺一项就补该项。
2. A、B 各自从同一固定快照恢复。两组使用相同权限、材料、用户输入和故障注入。单项对照每次只改一个待验开关。运行时生成的 `pair_id`、评审批次、缓存窗口可能不同，使用清单中的样本号将 A/B 对齐，保留原始会话号、`pair_id` 和 `attempt_id` 供追溯。独立任务可用宿主回执核验后按清单对照。
3. 每案交 A、B 两组绝对值。按实际发送边界统计物理尝试、确认发送、终帧、总请求字节和相关分区字节。续跳、重试、换座、补读与额外唤醒计入同一任务。输入总量、缓存读写、净输入和输出各附字段覆盖数。掉线和缺字段如实保留。零出站的控制收口单列。
4. 用独立 CLI 读副本台账，核对文件中的检查点、写失败、丢行和请求关联。`complete=true` 只覆盖检查点所证实的范围。`false` 或 `null` 时，该范围的差值只作观察。端点字段覆盖不足时，该字段的节省量记未知。替身回包的用量只作为计量对照，自然会话的端点回执单列。

```powershell
$env:PYTHONPATH = 'tests'
python -m pytest tests/test_batch7_cost_accounting.py tests/test_model_resume.py -q
python -m src.infra.cost_ledger report $ledgerA
python -m src.infra.cost_ledger report $ledgerB
python -m src.infra.cost_ledger diff $ledgerA $ledgerB
```

`$ledgerA`、`$ledgerB` 指向各组已记录的沙箱台账。多文件任务在清单中列出全量输入，再用 `report` 汇总。`diff` 按可信任务键配对，遇到 A/B 实例生成的任务键不同时，保留原始报告，按样本清单对齐两份汇总并逐项核对业务回执。 [实际出站探针](../tests/outbound_probe.py) · [台账读取](../src/infra/cost_ledger.py)

## 二、逐项补证

优先做同跳重试预算与凝练阶段复用的隔离试点。各项独立交结论。

| 项目与开关 | 最小对照 | 放行所需的业务证据 | 取数 |
| --- | --- | --- | --- |
| 同跳重试预算 `COST_HOP_RETRY_BUDGET` | 先做。两座连续 503、401、已输出后断流，另验退避期间真实停止及下一逻辑跳 | 确定性拒绝不换座重发，额度覆盖同跳的内外层重试和换座，断流保已有正文，停止后零新增发送，下一跳独立 | 实际尝试与确认数、失败分类、退避、各跳额度 |
| 唤醒合并 `COST_WAKE_COALESCE` | 同事项重复超限、解除后迟到事实、同异常换事件号、重启恢复。与同跳预算做两开关四组对照 | 同一事项只生效一次，解除后零落信，已落待确认的消息仍只有一条且编号可读 | 登记数、实际落信数、额外首跳、任务总尝试 |
| 评审缩量 `REVIEW_CONTEXT_PHASES` | `confirm` 与 `vote_nudge` 各做一次开关对照。加入改稿、插话和材料定位失败 | 评审批次、稿次、席位和票态逐项一致，旧材料不落新票，定位失败能回完整材料，权限一致 | 每步总请求数、全包字节、补读次数及票回执 |
| 工具证据投影 `TOOL_EVIDENCE_WIRE` | 搜索后回读、同区间重复读、写后读新版、真实拒权 | 读回行段和版本准确，引用完整或提供可回读坐标，调用与结果配对，拒权状态保留 | 工具结果区字节、总请求字节、追加取证次数 |
| 凝练和归拢阶段复用 `COST_MEMORY_STAGE_CACHE` | 两开关都关对比只开阶段缓存。复跑 L2 截断恢复、跨批恢复、归拢展开、在途改写与同座换端点 | 只重发失效或未完成阶段。旧候选拒发布，水位、节点索引、缓存板及归拢游标一致，原文可逐字找回 | 各阶段出站数、请求字节、跳过阶段、发布与回读证据 |
| 凝练提示缩量 `COST_MEMORY_COMPACT_PROMPTS` | 在阶段缓存开启的同一基线上单独对照缩量。优先复用已获准的真实模型样本 | 逐项核对裁定、证词、变更原因、未完项与原文锚点。检查截断及重试变化 | L2 和整条任务的出站、字节及用量覆盖。真实语义证据未齐时，结论为待补证，维持关闭 |

评审的 `confirm` 与 `vote_nudge` 两类样本各自满足总出站字节下降、请求次数无增加。工具证据的搜索后精读样本须同时降低续跳工具结果总字节和全任务请求总字节，模型请求次数保持不增。沿用相应批次的其他放行条件。 [评审放行条件](模型调用成本优化-第三批施工任务书-20261120.md#五交付与放行) · [工具证据施工任务书](模型调用成本优化-第四批施工任务书-20261121.md)

复用 [评审回放](../tests/test_batch3_review_phases.py)、[工具证据回放](../tests/test_batch4_tool_evidence.py)、[唤醒与预算回放](../tests/test_batch5_cost_coordination.py)、[阶段复用回放](../tests/test_batch6_memory_reuse.py)。先读已有的逐请求记录，可从本机 `D:/Temp/b3_evidence/batch3_phases.json` 核对既有评审 A/B 证据。历史回报只给百分比或测试通过数时，补齐绝对读数与业务读回。

## 三、三条组合回放与回退

| 路径 | A、B 配置与操作 | 通过条件 |
| --- | --- | --- |
| 普通卡工具续跳 | A 保持批二现有设置，关闭批四与批五候选项。B 只加入已通过单项回放的候选开关。更新一次当前任务材料，执行搜索和回读，再在一个逻辑跳注入一次断连 | 续跳见到新材料，工具证据能回读，每跳的重试与换座归原任务，真正的执行结果与 A 一致，额外补读和唤醒如实计数 |
| 评审版本变更 | 从同一评审批次和稿次恢复。仅切 `REVIEW_CONTEXT_PHASES`。在首跳后、同位置重试发送前换稿，再跑一个材料稳定的正例 | 旧材料零落新票，过期请求零新增发送，实际票态可读回。稳定正例按原条件完成 |
| 后台失败恢复 | A 全关。B 只开 `COST_MEMORY_STAGE_CACHE`。隔离注入 L2 截断，恢复后再验一次原文变更导致旧产物失效 | 只重付失效阶段，发布和原文找回通过。后台任务账按窗口和阶段归属，前台请求单列 |

每组再回到原开关值复跑一次。核对后续请求恢复基线行为，已落信、票与已发布记忆保持可读，回退过程零重复执行。报告记清回退命令、作用进程和生效条件。当前环境变量按进程读取，小范围先用独立实例或经批准的进程范围，并记录实际覆盖范围。

## 四、单列台账部署验证

这一步只在已批准窗口执行，可先提交隔离验收。记录 Web、相关 runner 和凝练进程的部署标识及开关状态，分清旧进程产出的日志和本次版本。部署台账时保持已验收的业务行为配置。

选一条批准窗口后的自然会话，优先使用已有的首跳和工具续跳样本。按可信任务身份核对实际尝试、确认发送、终帧、原始用量、业务回执，并用独立 CLI 查检查点。再看验证窗口内 5700 探活及新写入者的丢行、失败和待清账。遇到只有文字答复、没有可机械核验业务条件的样本，仍可验计量，业务等价性保留未知。无窗口或合格样本时将这一项标为待部署或待补证。

## 五、结项判据与交回材料

- 每个开关给一行结论。**可申请启用**要求业务判据通过、至少一项已验证收益、组合抽查与回退验证通过。**待补证**列明缺的具体样本或字段。**需返工**给最小反例、实际结果和预期结果。挂起的项可单列，不拖住其他项的验收。
- 交样本清单、A/B 原始台账与独立 CLI 输出、逐案业务证据索引、三条组合与回退结果，以及一张逐项放行表。表中包含开关、模型与任务范围、已测绝对值、结论、回退触发条件和生效方式。证据存沙箱，报告只引用坐标、摘要与指纹。
- 回归先跑批七计量，再按变更面跑批二至六相关用例。登记实际完成、失败或未跑，慢测试拆组复跑。交回报告保存为 `docs/模型调用成本优化-第八批验收报告-日期.md`，附可复跑命令与证据路径。
