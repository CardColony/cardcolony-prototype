# 卡片底座 · 第一步实现方案 v4（2026-10-14 · 沿关系的数据访问与通信）

> 性质：实现方案（未施工）。承 `docs/卡片生态-架构定义-20261014.md`。
> 核心认知（今晚收敛）：第一步＝"沿关系"这一个机制的两个方向——**读（沿连线访问数据）** 与 **写（卡间通信，消息进模型视野）**。
> 铁律沿用：底座给能力，资格归权限管；只定机制不定形态。

---

## 一. 目标

底座补上"沿关系"这件事的两个方向：

1. **读**：A 沿一条通信线，读到 B 的正文／影子／对话；
2. **写**：A 沿关系向 B 发消息，消息**进入 B 模型的视野**，B 读到并回复。

两者共用同一套关系机制、同一个权限关口、同一条留痕账本。

## 二. 能力一：沿通信线读（read_via）

```
read_via(source, relation, target, part) -> value
```

- `relation`＝一条通信线（relations 边）；沿边找到 target，读其数据。
- `part`＝读哪部分（正文／影子／对话），复用现状已统一的读卡工具（read_card 一次返回三块、read_shadow、对话经 timeline）——**不重做读工具，只加"沿边寻址"这一步**。
- 纯机制，不含权限判断。

## 三. 能力二：卡间通信（通信的本质是"进视野"，不是"存哪"）

**核心认知**：通信＝消息进入 B 模型的处理流程，让它读到并回复。事件流是账本、不是通道。现状把三件事混在一处，本方案分离成三件套：

| 件 | 是什么 | 现状 | 改后 |
|---|---|---|---|
| **待处理收件箱** | 消息的"待处理"队列——**进模型视野的通道** | 消息塞进对话块，靠 `find_pending` 从对话顺序推导"待处理"（脆弱约定） | 显式的待处理队列，待处理是**显式状态** |
| **对话块** | B 自己的对话历史（B 跟用户/外界的往来） | 混进了消息 | 只放 B 自己的话与回复，干净 |
| **事件流** | 留痕账本（可回溯、对账、前端重放） | 已有 | 照旧（消息仍记事件，账本不变） |

**通信闭环五步**：

1. A 沿关系向 B 投递消息 → 进 B 的**待处理收件箱**；
2. 检测到有待处理消息 → 调起 B 的回合（复用现状 `schedule_card_message_triggers` 机理）；
3. 装配 B 的上下文时，把**待处理消息**作为明确素材注入（模型明确看到"B 收到 A 的消息：…"）；
4. B 模型读到、处理、回复 → 回复落 B 的**对话块**，须答型再投递回 A；
5. 待处理消息**从收件箱移出**（已处理），事件流照旧留痕。

**价值**：待处理从"靠对话顺序推导"变成"显式队列"——不依赖脆弱约定；消息与 B 自己的对话分离，不污染。

## 四. 权限：两个能力码，归权限管

- `read_via` → 能力码 `read_linked`（沿连线读）；
- 发消息 → 能力码 `send_card_message`（沿关系发）。

底座只提供能力与通道，**谁有资格读／发，归权限管**（能力码纳入词汇表，申请制＋代码层事实属权限迭代，第一步只对接能力码）。

## 五. 复用 / 重做账

| 件 | 动作 |
|---|---|
| 读卡工具（read_card 三块/read_shadow/timeline） | **复用**，不重做，只加"沿边寻址" |
| 发信六道门槛 / 收信调起机理（schedule_card_message_triggers） | **复用** |
| 事件流留痕 | **复用** |
| 消息落点：从"塞对话块"改为"待处理收件箱" | **重做**（通信通道的实质改动） |
| pending 推导（find_pending 从对话块扫） | **重做**（改为显式队列状态） |
| 权限：两个新能力码 | **新增**（词汇表常量＋配置） |

## 六. 验收（硬判据）

- A 沿通信线能读 B 的正文／影子／对话，断线即失效；
- A 发消息给 B → B 的模型回合被调起、在上下文明确看到消息、回复；回复落 B 对话，消息从收件箱移出；
- 未授权（能力码未授）时读／发被拒；
- 事件流照旧留痕（消息事件可回溯）；
- 现有 read_card/read_shadow/timeline 行为不变；pytest 全绿。

## 七. 红线与不做

**红线**：底座只给能力与通道，不判资格；权限只判资格不判形态；全量留痕；五铁律。

**不做**：权限申请制＋代码层事实提取（权限迭代）；上下文怎么组装（开发者自由，底座只提供"待处理消息"这个可组合素材，不进装配器内部规定区序）；任何形态规定。
