## 六、两条任务链路的验证要点（以协议参与者身份）

用户侧看界面，开发者侧看**协议帧**。同一件事在开发者路径上必须能被**观察并证明**：不是"界面上显示了"，而是"帧里出现了、日志里记下了、状态里落住了"。

### 6.1 链路 A：用户高度介入的闭环（参与者视角）

| 项 | 内容 |
|---|---|
| **验证对象** | 委托 → 拆解 → 授权 → 推进 → 用户中途介入 → 交付 → 验收 → 返工，这条链在**协议层**是否可见 |
| **必须观察到什么** | ①**拆解与分派可见**：拆解结果与任务分派以帧／状态形式出现，参与者能读到"分了什么、分给谁"；②**介入可见**：用户修改拆解或中途改变约束时，协议层有对应的变更帧，且后续执行按变更走；③**暂停与停止可见**：暂停／停止指令到达参与者，参与者状态随之改变，且在可观察时间内生效；④**越界被拒可见**：超出 `write_scope`／`capability`／`namespace` 的动作被 `gate` 拒绝，回帧带 `status=rejected` 与 `reason_code`（如 `write_scope_denied`／`capability_denied`／`namespace_denied`）；⑤**交付结果可核**：交付物可通过参与者读取，内容与验收要求对得上；⑥**返工可追溯**：返工请求与返工后的交付在帧序列里能对上 |
| **判据** | 六条全部满足。其中②③④各需至少一次真实触发，并有帧级记录（帧类型、关键字段、时间点） |
| **必须判不通过的情况** | ①拆解只存在于 UI 而不进协议（开发者无法验证）；②用户改动后协议层无变更帧；③暂停／停止指令被接受但状态未变；④越界动作被静默执行（无拒绝帧）；⑤拒绝帧无 `reason_code`；⑥交付物读取为空或与任务无关；⑦以模型自述"已完成"的文本帧作为交付证据 |

| 项 | 内容 |
|---|---|
| **验证对象** | 给定目标与权限边界后，参与者自主拆解执行、多步推进、暂停停止、越界处理、阻塞上报 |
| **必须观察到什么** | ①**自主推进可见**：连续多步的推进在帧序列里是连续的，中间没有"等用户点继续"的空档；②**多步推进而用户无需逐节点推动**：连续完成若干步后才需要用户介入；③**暂停与停止生效**：指令到达即生效，且停止后不再自行恢复（不出现停止后仍有新动作帧）；④**越界回到用户或被拒绝**：越界动作要么产生"请求授权"帧回到用户，要么被 `gate` 拒绝；两条路径都必须留下帧；⑤**阻塞如实上报**：卡住时上报阻塞原因与所需条件，**不得以"完成"帧掩盖失败**；⑥**失败可辨**：失败与完成在协议层可区分（状态字段不同），不能都表现为同一种成功帧 |
| **判据** | 六条全部满足；③④⑤各需至少一次真实触发；⑥须构造一次失败场景，确认失败帧与完成帧在机器可判定层面不同（以 `status` 为准，不以是否出现 `ok` 为准） |
| **必须判不通过的情况** | ①每一步都需用户推动（不构成自主推进）；②停止后仍出现新动作帧；③越界动作无任何帧记录；④阻塞上报为"完成"（**不许把失败包装成完成**）；⑤失败与完成使用同一状态值（机器无法区分）；⑥以 `ok` 字段是否出现作为成功判据（文档明确要求以 `status` 为准）；⑦以模型声明完成作交付证据 |

## 七、证据与判红要求

### 7.1 每条结论必须留下的五件套

| 序号 | 证据 | 要什么 | 怎么算做到 |
|---|---|---|---|
| ① | 制品与版本 | 检出的提交 SHA、构建产物的哈希、协议版本（文档声明值＋运行时 `peer_version`） | 可据此唯一确定被测对象 |
| ② | 环境 | OS、架构、Go 版本（1.27）、模块缓存是否干净 | 他人能复现 |
| ③ | 操作与结果记录 | 执行的命令原文、完整输出、时间点 | 命令可复制重跑 |
| ④ | 最终交付物 | 真实任务的产出物本身 | 可打开、可核对 |
| ⑤ | 关键事件／日志 | 握手帧、gate 拒绝帧、阻塞上报帧、错误原文 | 帧级可定位（帧类型＋关键字段） |

**外加**：**可复核路径**——证据存放位置，他人按路径能独立复查。

**判据**：五件套＋可复核路径齐全才算有结论；缺一件维持 `未验证`。

### 7.2 界面／日志显示与持久事实必须一致

开发者路径里对应的是**日志与状态**：日志说 `serve ready` 的，端点必须真能连；日志说握手接受的，参与者必须真能发下一帧。
**判据**：日志／状态与事实存在任何不一致，该条判不通过，并登记为判红样本。

### 7.3 至少一条判红样本（必须构造）

**要什么**：本路径必须留下至少一条**"日志或握手显示成功、事实未成立"**的判红样本。
**怎么算做到**：构造并记录：显示了什么、事实是什么、如何发现、差异在哪一层（协议层／存储层／进程层）。
**当前状态**：`未验证（未构造）`——本卡不做实测，此样本由执行验收的人补齐。
**判据**：样本存在且可复核，才说明这套验收**有能力抓到假成功**。

### 7.4 不得作为交付证据的四类材料

| 材料 | 为什么不算 |
|---|---|
| 模型声明完成 | **不得以模型声明完成作交付证据**。模型输出的"完成"是待核事实 |
| 日志文字 | 日志是主张，须由端点可连、帧可回、文件可读来核对 |
| 演示脚本 | 演示脚本走预置路径，绕开真实输入与真实失败 |
| 文档示例 | 协议文档 B.1/B.2 的命令自陈未运行过，照抄文档不构成证据 |

**判据**：任一条结论仅以上述四类之一为据，该结论回退为 `未验证`。
