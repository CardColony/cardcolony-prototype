## 一、共同口径

本目录下四份发布准备文档（含本索引）共用同一套口径。口径不一致时，以本文件为准。

### 1.1 信息状态与验证状态分开记录：未验证 ≠ 证据不足 ≠ 未通过 ≠ 就绪

状态分**信息状态**与**验证状态**两个维度，分别记录、不得互相顶替。

**信息状态（六值，不得自造第七种）**：`用户已明确`／`责任线已交付`／`本卡整理`／`待裁`／`待交付`／`已阻塞`。

**验证状态（六值，不得自造第七种）**：`未验证`／`验证中`／`证据不足`／`已通过`／`未通过`／`不适用`。

| 验证状态词 | 含义 | 边界 |
|---|---|---|
| 未验证 | 无证据：还没有任何人按判据跑过；或跑过但没有留下可复核记录 | 默认态；不得写成"没问题" |
| 验证中 | 正在跑，尚无结论 | 不得当作结论使用 |
| 证据不足 | 有证据，但覆盖不到目标发布形态或目标设备 | 不等于未通过，不等于就绪 |
| 已通过 | 按判据跑过且结果满足判据，证据已绑定具体制品标识 | 必须绑制品标识（制品哈希＋环境标识＋取得时间）；未绑制品或未约定回落规则的，一律按未验证计 |
| 未通过 | 有证据证明不成立：按判据跑过，结果不满足判据，且证据已登记 | 证据须可复核 |
| 不适用 | 该条对本发布物在定义上不成立 | 须写明理由与判定人：`不适用（理由：…；判定人：…）` |

**要什么**：任何一处提到某条要求的状态，信息状态落在六值之一、验证状态落在六值之一，两者分列、不得互相顶替。
**怎么算做到**：三词边界——**无证据＝`未验证`**；**有证据但覆盖不到目标发布形态或目标设备＝`证据不足`**；**有证据证明不成立＝`未通过`**。`已通过` 必须绑具体制品标识；制品或其内含底座提交发生变化即自动回落 `未验证` 并标注需复验。全文状态词只出现上表六种；不出现任何脱离词表的完成态结论词；不把"没人跑过"写成"没问题"。
**判据**：对本目录四份发布准备文档（`README.md`、`三方发布矩阵框架-v1.md`、`黑盒验收-用户侧-exe-v1.md`、`黑盒验收-开发者侧-开源版-v1.md`）逐份做字符串检索，越出词表的状态词与完成态结论词命中数为 0；非本卡产出的外来文件不适用本条——外来件中的同类字样不作命中、也不据以拦截任何交付；每处状态词均可回溯到上表六者之一；`已通过` 只作为词表条目名出现，不得用作任何条目的状态或结论——本目录当前所有条目的验证状态均为 `未验证`。

> **"就绪"不是可以随手写的形容词。** 它是"全部阻断项均判为不阻断、且证据齐全"之后的汇总判断。本目录**不下这个判断**，只登记"哪些项还缺、缺了会不会挡住发布"。

### 1.2 exe 用户路径与开源版开发者路径是两条独立路径，不得合并

| 路径 | 使用者 | 前提 | 验收文档 |
|---|---|---|---|
| 用户侧 exe | 普通用户 | 不接触环境与依赖，不装 Go／Git，不需仓库源码 | `黑盒验收-用户侧-exe-v1.md` |
| 开发者侧开源版 | 开发者 | clone → 读 README → 构建 → 运行 → 接入协议；Go 工具链等环境与依赖自理 | `黑盒验收-开发者侧-开源版-v1.md` |

**要什么**：两条路径各自有独立的步骤链、判据与不通过条件，互不引用对方的结果。
**怎么算做到**：任一路径的某一步在另一路径中没有对应步骤；一份文档的结论不得被当作另一份文档某步的依据。
**判据**：两份文档的步骤编号、判据条目无交叉引用；不存在"用户侧 S3 依据开发者侧 S2"这类跨路径引用。

**为什么不能合并**：两条路径的失败模式不同。exe 路径的典型失败是"装上了但跑不通"（依赖缺失、权限、模型配置）；开发者路径的典型失败是"文本不足以接入"（README 没有构建与接入信息）。合并会把两类失败互相掩盖。

### 1.3 不以模型声明完成作交付证据

**要什么**：任何一条"这条做到了"的判断，都必须能指向制品、环境、操作记录、最终交付物、日志与可复核路径。
**怎么算做到**：证据五件套齐（见各验收文档"证据与判红要求"节）；缺任意一件即为未验证。
**判据**：模型自述完成、界面文字、演示脚本、录屏剪辑，四者均不得单独作为某条判为满足判据的依据。出现即以该条判不通过处理（若已据此登记为满足，须回退为未验证）。

### 1.4 对外名称

- 对外名称一律写 **CardColony**。
- **Cardlo** 只允许出现在两处：①"已弃用候选"的说明；②工程标识（仓库目录名 `D:\AI_station\Cardlo`、go module 名 `cardlo`、协议文档标题 `# Cardlo protocol v0`）。
- 不得把 Cardlo 写成产品当前名称，也不得写成"暂定名"。

### 1.5 值不得编造

矩阵与验收文档中的字段值，在无来源时一律写 `待填`，并同时标注"无来源"。
**不许**为了让表格好看而填猜测值、示例值、占位数字、看起来合理的版本号。宁可空着，不许编。
