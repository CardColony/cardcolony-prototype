# 模型调用成本优化 · 第二批施工任务书

**对象**　推演agent 原型的普通主对话  
**目标**　让高频变化的清单和子卡现状离开主 system 的稳定前缀，再按任务减少重复送给模型的正文。保留任务判据、关系事实、当前状态和原文回读能力。  
**依据**　总方案第三节。先验收材料移位与续跳，再验收按任务缩量，各自提交前后对照。 [总方案](模型调用成本优化-方案与施工任务书-20261120.md#三-第二批-动态材料走当轮输入口)

## 二、第一步 · 移位和同一回合续跳

1. 用移位前相同的清单、子卡使命、现状和活性跑一组对照，逐段核对正文及可见卡集合。首跳在当轮事实消息中分别带 `〔卡片清单〕`、`〔直接子卡现状〕`，用户原话仍是独立用户消息。只保留现有可见范围。无直接子卡材料时不生成空块，管辖层级按现有入口判定。
2. 沿生产回合入口验证首跳、工具续跳以及同一位置的重试。每次模型请求中，同一个宿主分区的同一快照只出现一次。检查分区渲染和轮槽固化两条路径，沿用单一承载方式。保住真实用户话、工作规范、工具协议提示和插话的相对语义，原生调用及结果保持正确配对，续跳无需伪造用户占位。每次网络请求仍可能重送当轮材料，按每次实际发送计量。
3. 对任务所需卡片，以现有可信取数入口读取清单和子卡状态。使用已有版本，缺版本时按实际投影字段生成稳定指纹。同一位置重试复用原快照。相关事实改变后，在同一逻辑回合下一次需要它的请求中更新快照，并可对账新旧版本。模型侧只见一份当前有效的宿主事实。以真实子卡状态写入后继续同一轮槽的方式验收，无关变化不另启动模型回合。用户停止和插话沿用原有优先顺序。
4. 在实际适配器之后抓出站。对本批覆盖的主对话路由，逐个核对 HTTP 请求正文或 CLI 转录，至少覆盖生产在用的 ECO、GLM 座及实际兜底。若生产兜底走另一类序列化，就按该类转录复测。三席、起草共用分区注册表，分别验证原有材料和权限，留下实际消息位置。遇到回归先限定到已验收的主对话入口。

## 三、第二步 · 按可信任务范围减少正文

在调用入口用现有结构化字段确定范围。可用来源包括明确的任务目标卡、指令来源、活板当前步骤、评审目标和当前目标。指令来源只证明指令来自哪里，能绑定到验收对象才用于选材。正文里的卡号只供查漏。全局统筹、单卡专项和任务范围无法证明三种情况按下表执行。

| 场景 | 清单与子卡材料 | 依赖正稿 |
| --- | --- | --- |
| 单卡委派或专项验收 | 首跳给对象卡号、使命、必要的现状和相关依赖清单。保留执行者需要的父子及关系坐标。 | 任务判据有可校验条款定位时，给相关原文及定位。跨域接口验收、明确审阅全文、必需条款定位不可靠时，给目标的完整正稿。 |
| 全局统筹 | 首跳给现有管辖范围内全部子卡的简表，至少留卡号、标题及已有活性。展开宿主数据已标识的异常和当前处理对象。其他详情按现有权限读取。 | 每条关系保留方向、两端卡号、类型和说明。当前任务需要的判据随首跳给出，其他正稿可用版本和可回读坐标引用。 |
| 任务范围、版本或回读条件不明确 | 沿用第一步的完整材料。 | 所需正稿定位失效、工具在本轮不可用或必要原文无法按现有权限回读时，沿用原有可见的全文投影。 |

- 同卡同份正稿沿用第一批去重。保留正反向关系、关系说明和上游需求入口。提供片段时带目标卡号、块名、可复核的标题或行号，以及正文版本或指纹。行号从同一份正文计算。版本变动后重新取当前版本及坐标，避免把旧行号当成当前条款。
- 复用 `read_card` 的正稿回读，使用 `block="需求文档"` 和 `para_start`、`para_end`，行号从 1 开始，闭区间。用实际工具执行证明行段对应原文。沿关系线读到的仅是对外需求文档，父子、差事等权限仍由原入口判断。 [分段回执](../src/api/card_tools.py#L927) · [读卡权限](../src/api/card_tools.py#L949)
- 先完成清单、子卡现状和依赖正稿的选材。现状区、历史和凝练中出现的重复事实记为后续候选。本批沿用会话原文、缓存板、记忆、评审材料、传输重试和工具派发的现有契约。

## 四、验收矩阵

用隔离工作副本或测试库，经正常入口运行。可用受控模型回包与传输替身，不依赖长对话自然复现。旧 prompt 日志用于取材及验证旧装配事实。新证据以适配器实际发出的请求正文或转录为准。

| 用例 | 必须拿到的证据 |
| --- | --- |
| `card_057` 单卡委派 | 首跳、真工具续跳、一次同跳重试。目标、原话、任务判据完整；工具调用与结果整对；每次出站清单与子卡快照各最多一份。缩量后用原任务脚本复核执行结果及原文片段。 |
| `card_007` 全局管控 | 首跳仍能看全管辖子卡及已知异常。一次正常状态写入发生在首跳和工具续跳之间。对比同一个回合标识下的两份出站，核对已更新的相关状态、唯一有效快照、无额外唤醒。 |
| `card_009` 依赖重边 | 四条出边和六条入边保持，第一批同份正稿只展开一次。分别验证可信窄任务的行段回读、全文验收、改版后定位和缺失定位的全文回退。 |
| 空场景及权限 | 无子卡、无可靠任务范围、无读卡工具、越权目标、普通聊天及用户插话或停止。核对空块、完整回退、权限与控制优先级。 |
| 共用调用方 | 主对话、三席、起草和实际兜底座的最终载荷。核对宿主来源标记、用户原话、工具配对和各入口原有可见材料。 |
