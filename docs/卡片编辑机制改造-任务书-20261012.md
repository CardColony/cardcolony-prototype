# 卡片编辑机制改造 · 工程任务书（2026-10-12 · v1）

> 派工性质：**施工任务书**。自给自足规格，外部 agent 照此执行，不得自由发挥。
> 依据方案：`docs/卡片编辑机制改造-方案-20261012.md`（同目录，先读它，以它为准）。

## 一、背景（为什么做）

让「需求文档」在**卡内**产生、成为该功能「应该长什么样」的**唯一权威源**。两条主线：

1. **块集改造**：研发卡正文块从「使命/现状/定论」改成「使命/现状/需求文档」。
2. **写权限收回**：模型不再直接 `edit_card` / `update_shadow`，改成「模型起草 + 用户按钮确认写入」。

## 二、用户裁定条目（不可改，违反即作废）

1. **需求文档 = 该功能应长什么样的唯一权威源**，卡内产生、不需要子卡。
2. **模型只起草，写入必须经用户按钮确认**（收回 `edit_card` / `update_shadow` 的直改权）。
3. **使命块永远不经起草/确认通道**，只能用户界面改（立项定稿）。
4. **块集**：研发卡（`rd_project`）三块 = 使命/现状/需求文档；其他卡（`research_project`）= 使命/现状/定论。判据用 `card_store._root_project_class(work_id)`（现成函数，读根卡 `project_class`）。

## 三、语义（保持不变，只做实现）

- 卡片正文仍是「区头 + 内容」的 Markdown 结构，三块读侧返回序不变（需求文档块替换定论块的位置）。
- 影子卡机制不变；本任务**复用** `shadow_store.append_to_section`（落 `## 迭代历史`），不新写影子逻辑、不改影子模板。
- 模型主对话流程（`message_runner` 编排、三席、统合）零触碰；draft 是**独立路由、独立调用**，绝不进工具循环。

## 五、红线（违反即作废）

1. 只动 §四 白名单文件；其余（会话底座 / 卡间信 / 凝练 / 思维链 / toolcard / `card_store.py` / `shadow_store.py` / `policy.py` / `gateway.py` / `model_service.py` / `card_type_registry.json`）零触碰。
2. **不改任何现有函数签名**——`gateway.call`、`model_service.call_main`、`card_store.update_card`、`shadow_store.append_to_section` 一律照现有签名调用，不得为了 draft 加参数。
3. **使命块不可经 draft/commit 改**（只允许 `requirements` / `status_block` 两键）。
4. **草稿请求绝不进 `message_runner` 工具循环**。
5. 改前 E 盘备份；**禁止删除任何数据**；`works/` 运行数据零写入（draft 不落盘、commit 只写对应块）。
6. 生产 5700 若在跑，编辑在 worktree；重启只走 `restart_safe.py`。
7. 不新增依赖；`pytest -q MOCK_LLM=1` 全绿为关门条件。

## 六、分块（3 笔，逻辑内聚）

### 块 1 · 底账：块集改造

**任务**：
- `hash_utils.py` `NEW_SECTION_MAPPING`（约 L104）加一行 `"## 需求文档": "requirements"`。
- 读侧按 `_root_project_class(work_id)` 判据取块：`rd_project` → 需求文档块（`requirements`），`research_project` → 定论块（`rulings`）。
- 研发卡 `rulings` 不再作为写入目标；存量研发卡定论保留**只读**。

**硬判据**：
1. `NEW_SECTION_MAPPING` 含 `requirements` 键（grep 可验）。
2. `rd_project` 卡读侧返回 `requirements` 块、无定论写入目标；`research_project` 卡返回 `rulings` 块。
3. 存量卡读取不报错，缺失块返回空。
4. 旧键归一（`OLD_SECTION_MAPPING` / `OLD_KEY_TO_NEW`）零改动。

**交付**：`hash_utils.py` + 读侧相关改动 + 块集断言测试。

### 块 2 · 后端：draft + commit 接口

**任务**：
- 新建 `src/api/card_draft.py`，两个 handler：
  - `draft(work_id, card_id, kind, feedback, prev_draft)`：调 `model_service.call_main(system_prompt, user_prompt, tools 缺省 None)`——**不传工具、纯文本**；上下文 = 当前块现有内容（必带）+ 本卡对话相关段 + 上一版草稿 + 用户反馈；返回 `{draft, base_hash}`。草稿只存内存/会话态，**不落盘**。
  - `commit(work_id, card_id, kind, draft, base_hash)`：比对 `base_hash` 与卡内该块当前 hash → 不一致拒绝；一致则 `card_store.update_card` 只写对应键（`requirements` 或 `status_block`）；然后 `shadow_store.append_to_section` 往 `## 迭代历史` 记一行（时间、按钮类型、旧块 hash、新块 hash、反馈轮数）。
- `routes.py` 挂两路由：`POST /works/{work_id}/cards/{card_id}/draft`、`POST /works/{work_id}/cards/{card_id}/commit`。
- `prompts.py`：删 `edit_card`/`update_shadow` 使用说明（约 L47/L72），改「卡片内容由用户按钮确认后写入，你负责起草，不能直接改写」；`BASE_PROMPT_VERSION` t16-1 → **t17-1**。

**硬判据**：
1. draft 请求工具列表为空（不传 `tools`），返回 `{draft, base_hash}`。
2. commit `base_hash` 不一致 → 返回拒绝，卡面零改动。
3. commit 只写 `requirements`/`status_block`，传 `mission` → 拒绝（使命块不可经此口）。
4. 确认后影子 `## 迭代历史` 新增一行（含旧/新 hash）。
5. `BASE_PROMPT_VERSION == "t17-1"`（grep 可验）。

**交付**：`card_draft.py` + `routes.py` + `prompts.py` + 接口测试。

### 块 3 · 前端 + 收口

**任务**：
- `work.html`（`inputmeta` 行约 L74）：`sendBtn` 左侧加两按钮「需求确定/定论确认」「更新现状」；`</body>` 前加 modal 浮层结构（遮罩 + 面板 + 标题栏 + 草稿区 + 反馈框 + 底栏三键）。
- `workspace.js`：加一组函数（`openDraft`/`renderDraft`/`submitCommit`/`submitFeedback`/`closeDraft`）实现状态机：点按钮→draft→草稿态→三选一（确认→commit；反馈→重新 draft；关闭→丢弃）。
- `style.css`：加 modal/草稿区/反馈框样式（**严格照方案 §三.6 视觉规格**，复用现有设计令牌）。
- 测试同步 + 全量验证。

**硬判据**：
1. 研发卡显示「需求确定」、其他卡显示「定论确认」（按块集判据）。
2. 弹窗三态齐全；「关闭」「反馈」不发 commit 请求、不落卡；只有「确认」走 commit。
3. 视觉规格（§三.6）逐条落实：令牌复用、z-index 层级（toast 9999 > modal 1300 > notifyPanel 1200）、按钮用 `.btn` 基类不新造类。
4. draft 请求期间弹窗「加载中」灰字；提交中确认键 disabled；hash 冲突红字提示。
5. `pytest -q MOCK_LLM=1` 全量绿，绿数写回回报，与改动前基线零回退。

**交付**：`work.html` + `workspace.js` + `style.css` + 测试同步 + 验证报告（含绿数）。

## 七、验收（最终关门）

1. 研发卡无定论块、其他卡无需求文档块；存量卡读取不报错（P1）。
2. draft 返回草稿 + base_hash，工具列表为空；草稿不落盘（P2 接口侧）。
3. commit 整块替换成功；期间卡被改则确认被拒；反馈轮次上下文连续（P4）。
4. 弹窗关闭/取消后卡 hash 不变（P3）。
5. 两按钮各走一遍：起草 → 反馈两轮 → 确认；再走一遍取消，确认无落卡（P5）。
6. `pytest -q MOCK_LLM=1` 全绿，绿数写回。

3. 若测试里出现「非本机制」导致的既有失败，不归因、不顺手改，标出回报。
