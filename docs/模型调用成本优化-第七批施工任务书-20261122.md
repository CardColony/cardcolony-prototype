# 模型调用成本优化 · 第七批施工任务书

**交付目标**　给前六批各交一份可复跑的任务级对照，回答同样的事做成以后少发了几次请求、少发了多少字节、端点报告的用量如何变化。每项结论连到原任务、真实执行回执和实际发送证据。本批代码施工限于观测接线、离线对账与回放取证。 [总方案第八节](模型调用成本优化-方案与施工任务书-20261120.md)

**施工顺序**　固定快照和业务验收判据 → 打通逐次发送与用量对账 → 按批复跑 → 做组合抽查 → 给出逐项放行结论。回放走隔离副本，保留生产进程与配置现状。 [项目规则](../AGENTS.md)

## 一、先固定可比的任务

1. 每个样本建一份清单，记录源码版本、工作/卡/会话、任务入口与用户原话、可信任务身份、材料版本、模型座与线路配置版本、权限、应有业务结果。背景原文和异步队列取同一个快照。A、B 从同一基线各自恢复，使用相同路由、工具响应、注入故障和完成判据。没有独立开关的历史改动用可复查的改前快照或历史实现作对照。
2. 固定测试结束条件。普通任务从受理到真实执行及交付收口。评审以正确批次、稿次、席位和落票为终点。发信以接收方读回及投递状态为终点。后台凝练以水位、节点索引和缓存板发布为终点，归拢另对游标、节点与原文锚点。取消、拒绝、待核实和失败各有独立结果，保留它们的全部请求成本。
3. 以可信任务号与版本为主关联。普通对话使用工作、卡、会话与原 `pair_id`，评审补批次/稿次/席位/步骤，凝练补窗口身份与阶段，跨卡调度用已留档的 `action_id`、`msg_id` 或任务绑定串起来。无法证明归属的请求列入待归因清单。并行的后台任务按自身账目统计。 [请求与工具台账](../src/api/tool_receipt.py#L86) · [每跳对账](../src/api/message_runner.py#L329)

## 二、统一逐请求台账

### 1. 发送、响应和业务结果各自入账

- **逻辑跳次**沿原回合的首跳、工具续跳、评审步骤、协议补救、后台阶段标记。**物理尝试**以进入适配器实际发送调用为准，HTTP 对应 `client.send`，有可验证进程提交边界的 CLI 单列。为每笔物理尝试分配唯一编号，保留其 `trace_id`、原逻辑跳次、外层重试序号、网关尝试序号、实际座和线路模型。复用现有发送与观测入口，预算或权限在发送前拒绝时记录控制结果，物理尝试计零。 [发送边界](../src/model_gateway/llm/transport.py#L19) · [模型观测](../src/infra/observe.py#L68)
- 同一笔尝试依证据记录「进入发送」「实发确认」「真实终帧」「失败类别」和端点声明模型。连接失败仍保留本地尝试次数，提供方是否收到按回执记。重试、换座和补救请求计入原任务的总账。响应元数据或用量多次到达时沿原尝试编号补账一次。重复读取日志与重新运行汇总应得到同一结果。
- 真实派发、工具成功、接收方受理和任务完成各取对应宿主记录。正文表态、策略命中、缓存命中、已登记动作和模型成功响应都按各自事实状态展示。主回合、评审、协议补救、唤醒和后台阶段分别出分项，汇总时凭原任务证据合计。

### 2. 统一字段，保留端点原口径

| 字段 | 取数与汇总规则 |
| --- | --- |
| 实际请求字节 | 取适配器序列化后的请求体字节，注明传输类型与分区算法。首跳、工具续跳及全部实际尝试各报绝对量。分区分开记录 system、稳定历史、用户话语与动态材料、工具 schema、工具回执和编码结构开销。稳定前缀按相同序列化口径逐项对比。 |
| 输入 token | 保留端点原始输入字段与字段语义。总输入、缓存读、缓存写、未命中输入分列。可由明确端点口径推导的值标明公式与来源。缺字段记 `null`，显式 0 保留为 0。 |
| 输出 token | 按端点报告的完成/输出用量计，思考 token 保留为独立字段。端点已把思考计入输出总量时，汇总沿该总量。输出字符数和本地估算另列。 |
| 重试和断流 | 报总物理尝试、已确认发送、真实终帧、控制收口、截断与重试分类。缺用量的尝试仍进入次数和已知字节统计。用量汇总交已知合计、覆盖尝试数和未知笔数。 |
| 整条任务 | 按完成、失败、停止和待核实分组。对同样完成的 A/B 给出首跳和总量差异，附请求明细。失败与部分交付单列其成本，用业务回执检查是否实际少做了一步。 |

- **OpenAI 兼容与 DeepSeek**　当前适配器会从 wire `prompt_tokens` 扣除缓存读量，再写入内部 `input_tokens`。分别留原始总输入、缓存读和内部净输入。缓存字段缺席时，即使旧代码为计算使用了 0，报表仍保留缓存命中未知。 [OpenAI 兼容用量映射](../src/model_gateway/llm_openai_compat/translate.py#L87)
- **SIWC**　当前内部输入取 Responses 的总输入，缓存命中是其中一项。适配器对缺字段做过兼容补 0，取证须保留原始字段是否存在。套餐额度、端点 token 和货币费用各自列账。 [SIWC 用量映射](../src/model_gateway/llm_siwc/adapter.py#L290)
- **其他线路**　按实际端点分别登记原始字段及映射。Anthropic 兼容线路的缓存创建、缓存读与 `input_tokens` 用线路样本独立核对。CLI 只有已取得的受理证据和回执字段可入账。按相同路由与同口径比较。脚本化用量标记为回放读数，远端缓存收益用自然会话端点回执补证。 [Anthropic 兼容用量映射](../src/model_gateway/llm_anthropic/translate.py#L59)

计量验收可固定一个 DeepSeek 兼容回包样本，总输入 1,000、缓存读 600、输出 120。总输入回执保留 1,000，当前适配器净输入为 400，缓存写字段缺席则为未知。另加一次进入 `client.send` 后断连且无用量的尝试。该任务物理尝试为 2，已知输入合计为 1,000，用量覆盖 1/2。

## 三、前六批最小复跑矩阵

| 批次 | 回放与对照 | 业务放行条件 |
| --- | --- | --- |
| 一　依赖正稿去重 | 同一卡两条不同关系进入同一请求，再加同文异卡、无重复和换版对照。数实际请求里的完整正稿出现次数及依赖区、整包字节。 | 两条关系及说明均可读，同卡同版正文一份且逐字一致。异卡、换版与现有读权限各自成立。 |
| 二　动态材料与任务缩量 | 把材料移位与 `CONTEXT_SCOPE` 分开计。复跑单卡委派、全局管控、范围未知各一案。抓首跳、工具续跳、同位置重试与一次状态更新。 | 用户原话保留，动态事实在续跳可见且同版本单份，更新能取回新事实。范围无证时回完整材料。分别交稳定前缀与实发字节。 |
| 三　评审阶段缩量 | `REVIEW_CONTEXT_PHASES` 开关对照 `confirm` 与 `vote_nudge`。补旧材料拒投、真实插话和定位失败的完整回退。 | 逐案读回批次、稿次、席位和票态，权限一致，旧材料零落新票。两类任务各自给总请求数和字节，补读也计入。 |
| 四　工具证据回传 | `TOOL_EVIDENCE_WIRE` 开关对照搜索后精读、同区间重复读、写后回读、拒权。 | 行段可回读，引用代表项完整或已转回读坐标，call/result 配对和错误码一致，写后读到新版本。比较整条任务的工具结果字节与取证次数。 |
| 五　合并唤醒和同跳预算 | `COST_WAKE_COALESCE`、`COST_HOP_RETRY_BUDGET` 四组交叉。复跑超限恢复、重复异常、同层换座、止/插话、断流与已落信待确认。 | 同一异常只生效一次，同跳尝试不越额度。断流可读回已有正文，停止后零新增请求，接收方只读回原信及原编号。各开关分别列减少的启动或重试。 |
| 六　凝练/归拢阶段复用 | A 两开关关，B 只开 `COST_MEMORY_STAGE_CACHE`，C 另开 `COST_MEMORY_COMPACT_PROMPTS`。复跑 L2 截断、跨批续跑、归拢展开缓存命中、写锁间改原文、同座换端点。 | B 核对只补未完成阶段、旧候选拒发布、原文逐字可找回。C 需能从真实模型样本逐项核对裁定、证词、变更原因和未完项，再比较截断、重试与总用量。证据缺席时 C 保持关闭。 |

组合抽查选三条实际有交集的路径。普通卡用第二、四、五批组合跑一次有工具结果的续跳。评审用第三批候选配置跑一次版本变更和发送守卫。后台用第六批候选配置跑一次失败恢复，检查任务账能独立计数。各组合固定同一个基线并逐项对账，具体启用项写入样本清单。 [批二回放](../tests/test_batch2_outbound.py) · [批三回放](../tests/test_batch3_review_phases.py) · [批四回放](../tests/test_batch4_tool_evidence.py) · [批五回放](../tests/test_batch5_cost_coordination.py) · [批六回放](../tests/test_batch6_memory_reuse.py)

## 四、施工验收和放行

1. **先验计量。** 用受控替身跑一次首跳、一次工具续跳、一次同跳重试和一次换座，逐笔比对探针与台账。加连接未确认、预算前拒、流终帧缺失、明确 0 缓存、缺缓存字段、重复用量帧与重复归并的反例。使用至少一组 OpenAI 兼容和一组 SIWC 用量样本。验证总量、分项、未知覆盖和任务关联均与原始证据对上。
2. **再验业务与收益。** 每项先判业务，再比较总量。候选组须保住对应批次的业务判据，并给至少一个可复跑的实际请求数、字节或端点用量改善。覆盖不足、真实模型语义有缺项或出现业务回归时列待补证。仅有字节改善的项目注明已证实的收益口径。涉及真实模型的新增付费或生产试点单独申请，优先复用已有合格实录。
3. **逐项交付结论。** 给「可申请启用」「待补证」「需返工」三类。每项带开关、适用模型和任务范围、证据路径与回退条件。列明当前部署或试点状态的证据时点。5700 发布、生产开关调整和整组重启按项目规则单独请示。
