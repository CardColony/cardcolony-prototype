## 一 背景（为什么做）

### 1.1 沙箱上发生了什么

Cardlo 分支（`.worktrees/cardlo`，端口 6700）上完成了一次完整实验：把系统完全放权给模型——卡上一个 `auto_mode` 开关，开了就权限全开、挂一个轮次驱动器让它一轮跑完自动再起一轮（直到模型显式声明完成），子卡建卡时继承。在此基础上，`automode-6701` 分支又做了 12 笔提交，实现卡间自主协作（模型自己建子卡派活、子卡干完回报、问出去的信必有回音）。

### 1.2 为什么要搬

沙箱验证了机制可行性；生产需要这个能力——但不能直接合：

1. **5700 连底座都没有**：`auto_driver.py` / `serial_gate.py` / `exec_mode.json` 全不在；存储四列（`auto_mode`/`goal`/`goal_state`/`goal_rounds`）全不在；`update_goal` 工具不在。
2. **移交件混着三类不该进生产的东西**：全局拆思维链、单模型无角色、沙箱脚本（见 ND1–ND3）。
3. **基点落后 8 个提交**：cherry-pick 不可行，须按功能重放。

### 1.3 好消息

dev 已有卡间通信基建（`card_msg.py`、`_auto_reply_pending_letters`、`_watch_pending`、`schedule_card_message_triggers`、`_h_send_card_message`），不用重建只需改。

  ```python
  _exec_locks: dict[str, asyncio.Lock] = {}  # per work_id

  async def acquire(work_id: str, mode: str) -> None:
      """串行模式下起回合前调。拿不到则排队等待（非 409）。"""
      if mode == "parallel":
          return
      lock = _exec_locks.setdefault(work_id, asyncio.Lock())
      await lock.acquire()

  def release(work_id: str, mode: str) -> None:
      if mode == "parallel":
          return
      lock = _exec_locks.get(work_id)
      if lock and lock.locked():
          lock.release()
  ```

**硬判据**

1. **自主跑**：auto 卡目标 active 时，一轮结束自动起下一轮；模型声明完成 ⇒ 停。
2. **不空转**：父卡有未终止子卡时不起轮；子卡全终止后恢复。
3. **串行真串**：串行模式下建 N 张子卡 ⇒ 任一时刻执行锁只被一张卡持有（可断言）；拿不到锁是排队不是 409。

5. **停得住**：按停止 ⇒ 不再起新轮 ＋ 子卡也停 ＋ 执行锁释放（队列不饿死）。
6. **接线位置**：驱动器调用在互斥体释放之后（可用"连续两轮不被 409 拒"断言）。

## 七 验收纪律（从移交件提炼，生产照用）

1. **跑一次就下结论＝自证偏差**。自主性验收必须**多跑**（≥3）＋判据覆盖闭环。
2. **判读要等账本稳定**：`answer` 落库可晚于根卡收口；"根卡 complete"≠"故事讲完了"。
3. **闸的判据别用会陈旧的状态**（`status=pending` 依赖对方后续回合收口）——用实质事实。
4. **拒绝必须自带出路**，否则自主模型会换姿势重试，甚至去读源码，烧光预算。
5. **给对方造义务的消息要慎用**：确认类收尾用 `notify`（无回信义务），`ask` 会触发对向调起＋新义务。
6. **120s 工具上限**：等待用"单次快照＋拉大间隔"，别内嵌长睡眠。
