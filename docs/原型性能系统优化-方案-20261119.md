# 原型性能系统优化方案

在推演原型现有的 web、runner 和 condense 拓扑上，依次优化进程间转发、大卡读取和模型请求装配。优先解决多卡运行时开卡、切卡和查询状态的长尾。每批独立留基线和复测结果，便于确认收益落在哪一段。

## 第一批 进程间转发与运行状态

为同一进程、同一事件循环的内部回环请求复用 HTTP 客户端。客户端随服务循环初始化和关闭。按短请求与长流的并发特性分配连接，保障 SSE 或长跑请求占住连接时，状态读取仍能发出。回环用专用目标与配置，模型端点的连接配置继续由网关管理。

覆盖 web 普通转发、四 runner GET 汇总、工作级 SSE 和 runner 间控制转发。盘点各入口的调用线程和所属循环，按共用生命周期接线。普通转发透传现有路由、方法、查询参数、响应体和必要头。客户端取消或流断开时归还当次上游连接。控制调用可能承载完整模型回合，沿用既有完成语义，避免把短查询读超时套到长工作或 SSE 上。

现有运行状态已在活跃位变化时推送工作级事件。先测转发复用后的轮询负担，再核对哪些请求确有重复。同一页面同一路查询可合并在途请求，初始快照和重连校准仍按实际运行状态走。汇总遇到慢 runner、部分失败和全部失败时，观测能指出各片的读数和缺失，调用方按现有接口契约处理。

## 第二批 大卡时序与轻量读取

沿用原始事件文件作为事实源。让撤销读取先消费已经完整扫描的前缀，再从上次完整记录边界读取新追加的数据。记录位置和撤销区间是可重建的读侧缓存，遵循当前的条目上限。文件被替换、截断、前缀无法确认时，从现有原文安全重建。并发追加时只发布对应完整记录边界的结果。未写完整的行由下次补读。

首屏尾窗、按 `from` 增量和按 `before` 向上翻页分别计时。保持撤销后的可见集合、`(ts, seq)` 显示顺序、`before` 锚点、水位和附加会话隔离。优先让反复追加时的尾窗开销随新增字节和返回页增长。若翻页仍需全量扫描且影响尾延迟，再针对相同语义验证位置索引或分页读法。

会话标签列表只取标签所需列。时序接口针对主会话走可靠的存在性读取，指定附加会话时读取权威会话登记并保持相同校验。复用已有卡片读层的窄投影，保留完整卡面接口的返回契约。再按访问日志检查进度、对齐和评审状态各自实际等待在哪一段。

## 第三批 模型请求装配

从用户回合进入到收到正文首字，分别量化本地读取与分区生成、请求序列化、出站等待、首个提供方事件和首个可见正文。区分首跳、工具续跳、模型回退和凝练请求。使用回合与模型尝试标识关联，记录最终发送的请求字节；提供方报告缓存命中时，单列缓存读取量。打点只记录数值、标识与必要的指纹。

先消除同回合和同快照内的重复取数、分区渲染与序列化。只有事实源已有可靠版本时，才考虑跨回合复用相应稳定分区。变更事件或版本要覆盖卡面、线、记忆水位、身份和工具能力对应的数据。比较同样输入下主模型、席位与工具续跳的实际请求，核对当前轮提示、工具调用对、结果存根和可见历史完整。模型在真实超长会话里的工具表现，按已确立的实际使用观察口径记录。

## 验收与交付

三批分别使用匹配负载的前后对照，报告 P50、P95、失败及超时、响应体积和峰值资源。接口样本按入口统计，短查询与 SSE 单独看。页面至少核对开卡、切卡和首屏时序可用的实际耗时。模型端等待和本地装配分别出数。生产访问日志用于确认日常负载时的收益，提交前以隔离回归和轻量验证为准。

每批交付需有行为核对及性能证据，可单独复验。现网服务重启按项目规则另行请示。派工顺序和具体判据见 [工程任务书](原型性能系统优化-任务书-20261119.md)。
