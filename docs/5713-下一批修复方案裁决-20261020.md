**病4b 修法本卡独立复现（2026-10-20，沙箱 tempfile，未碰真实数据）**：同一场景（主库 WAL＋一个活连接持有，快照副本含「第一版」、主库现值「第二版」）下——方案 A（`copy2` 覆盖＋删旁挂）**删 `-wal`/`-shm` 均报 `WinError 32`，读回仍是「第二版正文」**（复现病4b）；方案 B（`src.backup(dst)`＋`wal_checkpoint(TRUNCATE)`）**读回「第一版正文」，且那个活连接自己也读到「第一版」**。

**旁挂落盘形态的三方实测（card_015 v6／card_016／本卡，结论已合流）**：

| 状态 | `-wal` | `-shm` | 读回 |
|---|---|---|---|
| 修复前（活连接持有，含待重放页） | 4,152B | 32,768B | 第二版 |
| **方案 B 后，有连接开着 / 或该库刚被进入过 WAL 读** | **0 字节，文件在** | **32,768B，文件在** | **第一版** |
| **全关**（关闭者具备该目录写权限） | 消失 | 消失 | 第一版 |
| **全关后仅 `open`／`SELECT 1`**（未进入 WAL 读） | 不出现 | 不出现 | — |
| **全关后进入 WAL 读**（`PRAGMA journal_mode`／读表） | **0 字节，重现** | **32,768B，重现** | 第一版 |
| **只读连接（`file:…?mode=ro`）关闭后**（无目录写权限，清不掉） | **0 字节，留着** | **32,768B，留着** | 第一版 |

⇒ **判据不得钉在「旁挂文件在不在」上，两个方向都不行**：断言"不存在"会在连接还开着时失败（`-shm` 恒 32,768B）；断言"存在"会在全关后失败。**性质要说准**：**旁挂只反映连接的簿记状态，与恢复成败无关**。本卡起初只提醒"别用旁挂不存在"，card_015 补了"`-shm` 一直在"，本卡复算又发现"全关后会消失"，card_016 再补两条机制——**三份实测各看到一部分，合起来才是全貌**。分歧根源有三重，缺一条都解释不了实测：①**还剩几个连接**；②**关闭者是否具备写清理权限**（只读连接关掉后旁挂留着不消失，这大抵就是 card_015「清缓存后 `-shm` 仍 32,768B」的真实成因，不是缓存没清干净）；③**是否真正进入过 WAL 读**（仅 `open` 或 `SELECT 1` 不碰库 ⇒ 旁挂根本不出现；`PRAGMA journal_mode` 或读表 ⇒ 重现）。

**第③条另有一个坑，必须写进给施工方的警告**：「我连上去了、文件没出现 ⇒ 没残留」是**假阴性**——与"文件在所以恢复成功"属同一类错。要判断有没有待重放页，只能按下方四条件里的第 3 条（`-wal` 0 字节或不存在）在**明确进入过 WAL 读之后**取样，不能靠"连了一下看文件在不在"。

**验收断言（正向可写版，施工方照此写，替代任何"旁挂不存在"式判据）**：
1. `card_store.read_card` 读回**快照态**；
2. **独立只读连接**读到同一状态（防"只有那个活连接看到了"的假象）；
3. **`-wal` 无待重放页——「0 字节或文件不存在」二者皆可**（TRUNCATE 之后「0 字节」正是"没有待重放页"的可验证等价物；容器全关时则文件不存在，两种形态同义）；
4. **回执诚实**：清不掉旁挂／内容校验不过即 `ok=False`。
**禁止**：对 `-shm` 做**任何**存在性断言（既不能断言存在也不能断言不存在）；以「目录里少了哪两个文件」当恢复成功的判据。

**能存／能恢复的口径照 card_015 的 D02 ＋ D04 一并引用——两句都不得省略**：D02 给**前提**（走库函数且 `SNAPSHOT_ROOT`/`BASE_DIR` 显式给定），D04 给**收紧**（「能恢复」只成立于**非 WAL／无 sidecar 残留**场景；**「WAL＋活连接」（＝生产常态）在病4b 修好前不能**）。**只引 D02 会把"能恢复"读成"只要走库函数就能恢复"——这正是本域明令禁止的表述**，也是本条曾经写错的地方（原稿"照 D02 原样引用"，已订正）。任何对外说"快照恢复可用"的表述都必须带这个限定。
