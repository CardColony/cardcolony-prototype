## 1. 历史可见性（event_log.py）✅

**根因（原样反例复现）**：「更大的文件替换 + 头 64B 与原扫描边界前 64B 保留 + 中段撤销记录改写」
——头/尾指纹全命中、size 增长 ⇒ 走增量 ⇒ 中段改写永不被发现 ⇒ 热读用旧 spans。
**修法（文件身份变化时重建）**：state 记录 **Windows `st_ino`（文件索引号）+ `st_ctime_ns`
（创建时间）**——追加写两者不变（delta 免费通过、性能不变）；替换（os.replace/重写改名）
两者必变且 `os.utime` 伪装不了创建时间 ⇒ 强制重建。POSIX 上 st_ctime 语义不同（追加也变），
**仅 win32 启用**（生产平台），其他平台回退指纹行为——已注释声明。

顺带修了第二个真 bug：**索引弃用状态在 delta 重扫时被重置**——「索引超限弃用后追加
普通事件」的下一次翻页会重新触发全量重建。现 `index_dropped` 跨扫描保持。

### 反例④⑤（`tests/test_event_log_incremental.py`，13 用例全绿）
- **复跑**：`PYTHONPATH=tests python -m pytest tests/test_event_log_incremental.py -q`（13 passed）
- **反例④**（用户原样构造）：旧文件 seq1..5 + revoke{from:2}（撤 2..5）；替换文件对
  revoke 行做**等长改写** `from_seq:2→3`（全部字节偏移不变 ⇒ 头/尾指纹原样命中）+
  尾部追加 rec7 使文件更大。
  - 预期：热读 == 冷读 == `[1,2,7]`（新 revoke 撤 3..5、追加行可见），已撤销的
    记录 2..5 不重现。
  - 实际：**PASS**——`hot == cold == [1,2,7]`；身份信号实测参与判定
    （`st_new["size_scanned"] > boundary` 且重建触发）。
  - 证据：pytest 输出；`src/storage/event_log.py::_scan_state` 的 `_identity_same`
    分支与 state 的 `ino/ctime` 字段。
- **反例⑤**（索引超限弃用 + 追加）：`_INDEX_MAX_ENTRIES=5 / BYTES=8KB` 下 40 行建
  索引 ⇒ 弃用；追加 1 行普通事件跑 spans delta ⇒ 弃用状态保持；再要索引 ⇒ **不再触发
  全量重建**（`full_rebuilds` 计数不涨），翻页回退全量路径语义与参考一致。
  - 实际：**PASS**（修复前此场景每次翻页都付全量重建——已被本反例钉死）。
- 全量回归：event_log_tail / revoke_scan_perf / incremental / card_sessions /
