# 工具线收拢 · 工程任务书（2026-10-12）

> 派工性质：**施工任务书**。自给自足规格，外部 agent 照此执行，不得自由发挥。
> 依据方案：`docs/工具线收拢-方案-20261012.md`（同目录，先读它）。

## 一、背景（为什么做）

工具线的七件事——清单、定义、文档、权限接线、下发、执行、生老病死——散在 `card_tools.py` / `file_tools.py` / `plan_tools.py` / `prompts.py` 四处，各写各的：工具清单没有唯一真源、说明书手写（与 schema 两份事实源）、`TOOL_SWITCH` 是独立第二张表、思维链六件混在工具注册表里、退役＝删行无记录。本次把「工具」收拢成「一处定义、其余派生」，并把思维链六件分出工具线。

**基线声明（施工前提）**：本任务书基于 **HEAD（`d0e1ce5`）干净基线**施工。工作区现有的未提交改动（`src/api/tool_catalog.py` 新增、`prompts.py` 的 t18、`search_tool.py` 的 B-11、`file_tools.py` 的 P-08 等）是**未经允许的擅动、一律作废**。施工前须确认工作区回到 HEAD 干净态（`git status` 无工具线相关残留），本方案不沿用擅动的任何代码。

## 二、用户裁定条目（不可改，违反即作废）

1. **工具 = 19 件**：卡片 9（read_card / read_memory / read_shadow / create_card / edit_card / delete_card / link_cards / unlink_cards / update_shadow）+ 本地文件 4（list_files / read_file / search_files / write_file）+ 资料 3（list_manuscript / read_manuscript / search_manuscript）+ 联网 2（web_search / fetch_web）+ 工具卡 1（run_tool_card）。**思维链六件（create_plan / plan_reorder / plan_insert / plan_remove / plan_modify / step_complete）不算工具**，归「思维链」线。
2. 一个工具的全部信息**只在一处写一次**，清单 / 说明书 / 权限 / 下发 / 执行 / 生死全部从这一处现算，不再手抄第二份。
3. 说明书工具段**从工具定义自动生成**，不再手写；「系统规矩」（错误码怎么读、卡间消息怎么办、卡片内容写入的两条路径）留在 BASE_PROMPT 手写，判据＝「这话是关于工具的，还是关于系统的」。
4. **`switch` 收进 `ToolDef`**，删掉独立的 `TOOL_SWITCH` 表。
5. **思维链六件分家**：`plan_tools` 自维护注册表，不再 `register_into(card_tools.TOOL_REGISTRY)`。
6. 退役工具**标 retired、留档不删行**。

## 三、语义（保持不变，只做实现）

- **模型最终收到的工具清单逐字不变**：仍是 19 工具 + 6 思维链 = 25 件，name / description / parameters 零改动（阶段四才动 description）。
- 工具执行语义、结果信封（`{ok, data, error:{code,message}}`）、五类错误码、`render_tool_result` 投影——全部不变。
- 权限语义不变：查**卡上固化的 perms**（`policy.has_perm`），默认关门。

## 六、分块（4 笔，逻辑内聚）

### 块 1 · 账本结构：ToolDef 扩字段 + 文件四件收进 + 生死归口

**任务**：
- `ToolDef`（card_tools.py 约 L195）加三字段 `switch` / `domain` / `status`。
- 删 `TOOL_SWITCH` 常量表（约 L93–120），把 switch 信息逐件写进各 `ToolDef` 的 `switch` 字段；`build_tool_schemas` 的 `_filter_by_category` 改读 `def_.switch`（不再查 `TOOL_SWITCH.get(name)`）。
- 文件四件（list_files / read_file / search_files / write_file）**直接登记进 `TOOL_REGISTRY`**（schema 保留 lambda 延迟求值，因 conftest monkeypatch `ALLOWED_ROOTS`）；`file_tools.build_file_tool_schemas` 收编或退役。
- 生老病死：`status` 字段 + 退役留档结构（`RETIRED_TOOLS`：退役工具从注册表摘除但留 `{域, 退役版本, 原因}`）。

**硬判据**：
1. `ToolDef` 含 `switch` / `domain` / `status` 三字段（grep 可验）。
2. `card_tools.py` 无 `TOOL_SWITCH` 常量定义（grep `TOOL_SWITCH` 零命中）。
3. `TOOL_REGISTRY` 含 `list_files` / `read_file` / `search_files` / `write_file` 四键。
4. 有退役留档机制（`RETIRED_TOOLS` 或等价结构，grep 可验）。
5. 19 件工具每件的 `switch` 值都落在 `policy.SWITCHES` 词汇表内。

**交付**：card_tools.py + file_tools.py。

### 块 2 · 思维链分家：移出注册表 + 下发合并 + 执行联合分派

**任务**：
- `plan_tools` 去掉 `register_into`（不再塞进 `TOOL_REGISTRY`）；`PLAN_TOOLS` 保留为思维链自己的注册表。
- `TOOL_REGISTRY` 只含 19 件工具，不含思维链六件。
- 思维链 schema 生成：新增 `plan_tools` 的出 schema 函数（从 `PLAN_TOOLS` 取，含权限过滤——思维链六件统一归 `plan` 开关，查卡上 perms）。
- 下发：`message_runner` 组装工具时合并「`build_tool_schemas()`（工具）+ `plan_tools` 出 schema（思维链）」。
- 执行：`execute_tool` 改为联合分派——先查 `TOOL_REGISTRY`（工具），未命中再查 `plan_tools.PLAN_TOOLS`（思维链）。`message_runner` 对 `step_complete` / `create_plan` 的编排特判（板快照、plan_created / step_advanced 事件、criteria_met 累积）**保留不动**，属思维链机制。

**硬判据**：
1. `TOOL_REGISTRY` 不含 `create_plan` / `step_complete` 等六键（grep 可验）。
2. `plan_tools` 不再有 `register_into` 被 card_tools 调用（grep `register_into` 零命中）。
3. 模型最终下发清单仍是 25 件（19 工具 + 6 思维链），`name` 集合与改前逐字一致。
4. `execute_tool("create_plan", ...)` 仍能正确执行（联合分派命中思维链）。
5. 思维链六件的下发按卡的 `plan` 开关过滤（无 plan 开关的卡看不到思维链工具）。

**交付**：card_tools.py + plan_tools.py + message_runner.py。

### 块 3 · 说明书生成：删手写工具段，改从注册表渲染

**任务**：
- 新增生成函数：从 `TOOL_REGISTRY` 渲染工具段——签名从 `schema.parameters` 取、描述从 `schema.description` 原文取、分组从 `domain` 取；按域分节（卡片 / 本地文件 / 资料 / 联网 / 工具卡）。
- `prompts.py` 删 `_BASE_PROMPT_TEXT` 里手写的「## 工具」段（六个 `###` 域），改调生成函数；「## 卡片内容写入」「## 工具错误码」「## 卡间消息处理」三段（系统规矩）**保留手写**。

**硬判据**：
1. `BASE_PROMPT` 里无手写工具行（grep `### 卡片（9 件）` / `### 思维链（6 件）` 等手写节头零命中）。
2. 生成函数产出的每件工具说明，与 `schema.description` 逐字一致。
3. 说明书不含思维链六件（思维链说明另走）。
4. 「工具错误码」「卡间消息处理」等系统规矩段仍存在（grep 可验）。
5. `pytest -q MOCK_LLM=1` 全量绿，绿数写回，与改动前基线零回退。

**交付**：生成函数 + prompts.py。

### 块 4 · description 补写 + 版本递增（改工具面）

**任务**：
- 把现状手写段里属于「工具」的丰富规则，写进对应工具的 `schema.description`（如 `edit_card` 的三块语法 + 条目语法、`update_shadow` 三节边界、`create_card` 只能建自己子树、`run_tool_card` 每次新建卡等）。
- `TOOL_TABLE_VERSION` 递增；`BASE_PROMPT_VERSION` 递增。

**硬判据**：
1. 说明书工具段（生成函数产出）与 `schema.description` 逐字一致（本轮补写后）。
2. 补写后每件工具的 description 能独立说清「怎么用」，不依赖 BASE_PROMPT 手写段。
3. `TOOL_TABLE_VERSION` 与 `BASE_PROMPT_VERSION` 均较 HEAD 递增。
4. 全量测试绿，绿数写回。

**交付**：card_tools.py（description）+ 两处版本号。
