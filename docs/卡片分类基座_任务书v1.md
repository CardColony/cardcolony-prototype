> 版本：v1（2026-05-13）
> 上游方案：《卡片分类基座_方案v1.md》（同目录）
> 管辖卡：card_041 卡片类型
> 基座三锚点：card_009（类型退役）/ card_016（卡实体事实源）/ card_035（写路径收口）

## 一、目标与范围

### 1.1 目标
搭建「卡片分类基座」：两层分类（L0 项目分类 / L1 子卡词表按树作用域），研发项目词表 v1 仅含 **子项目卡（sub_project）** 与 **工具卡（tool）** 两张，配套注册表、写路径闸门、存量迁移、回归矩阵。

### 1.2 范围
- **在范围**：字段口径、注册表、写路径三闸、工具卡状态机、类型不重叠划界、legacy 词表退役、存量归类、回归矩阵、文档落库。
- **不在范围**：研究项目词表（S3 收尾后另立任务）；工具卡子类（调研/文档，用标签扛）；布局/权限/根卡判据（那是 parent 的活，见 card_009）；影子卡类型体系（显式排除）。

### 1.3 退出守门（任一不过则整体不回滚，逐项修）
1. 回归矩阵 12 条用例全过。
2. 旧词表（剧本/线索等六值）零新增写入。
3. 与 card_009 / card_002 / card_040 三处明文划界签字。
4. 影子卡通道独立确认（shadow 不进入类型体系）。

---

## 二、字段口径（T1 定稿）

| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| `project_class` | string, 仅根卡可写 | `rd_project` / `research_project` / 可扩展 | L0 项目分类，决定本树 L1 词表作用域 |
| `card_type` | string | 由所属树的 `project_class` 决定词表 | L1 子卡类型；研发项目词表 v1 = {`sub_project`, `tool`} |
| `owner_card_id` | string, 可空 | 工具卡必填，指向调用它的子项目卡 id | 产物与过程永久挂载锚点 |

- 影子卡 `card_type: "shadow"` 走独立通道，**不进入**上述体系。
- 非法值处理：**显式报错**，废除现行静默降级为「线索」的闸（card_009 §五护栏⑤）。

## 三、任务分解（9 任务 / 3 阶段）

### S1 词表与数据规约

**T1 字段口径定稿**
- 产出：本任务书 §二 表格签字确认；`config/card_type_registry.json` 字段命名锁定。
- 验收：字段名、取值、可空性、读写权限（仅根卡可写 project_class）无歧义。

**T2 类型注册表落库**
- 产出：`config/card_type_registry.json`，结构含：
  - `project_classes`: { code, label, description, l1_vocabulary_ref }
  - `l1_vocabularies`: { scope: project_class_code, types: [ { code, label, can_have_children, requires_owner, default_template, allowed_transitions } ] }
  - `legacy_types`: { code, deprecated: true, migration_hint }
- 与 card_036 工具注册表同形态（独立配置文件，不进 DB）。
- 验收：JSON schema 校验通过；研发项目词表 v1 仅 `sub_project` / `tool` 两条。

### S2 闸门与生命周期

**T3 写路径三闸校验**
- 闸1 非法值显式报错：card_type / project_class 不在注册表 → 抛错，不写库。
- 闸2 类型/项目分类一致性：子卡 card_type 必须属于其根卡 project_class 的词表。
- 闸3 工具卡 owner 必填：card_type == "tool" 时 owner_card_id 非空且指向合法 sub_project。
- **依赖**：接 card_035（写路径收口），只加闸逻辑，不改收口结构。
- 验收：三闸各自触发/放行用例通过；legacy 值在写路径被拦，读路径宽容。

**T4 工具卡状态机**
- 状态：`active → completed`（终态，不删）。
- 产物挂载：工具卡运行期产物（文档、调研结果）以 `owner_card_id` 为锚点挂载；过程记录进工具卡自身影子。
- 验收：completed 工具卡不可再编辑正文；产物查询可按 owner_card_id 聚合。

**T5 类型不重叠闸门（明文划界）**
- 与 card_009：`_normalize_parent` 类型分支与根卡保护腿②的残留，**本基座不接管**，仅声明「类型不再兼任布局/权限/根卡判据」。
- 与 card_002：上下文治理（condense_fold、影子卡）**不读** card_type 做路由。
- 与 card_040：权限管理**不读** card_type 做鉴权。
- 产出：三处划界声明写入本任务书附录 A，并同步到 card_009 / card_002 / card_040 正文或影子。
- 验收：三处签字确认。

### S3 迁移与回归

**T6 legacy 词表退役**
- 旧六值（剧本/世界观/行为体/节点/假设/线索）标记 `deprecated: true`。
- 写路径：legacy 值抛错；读路径：原样保留可读。
- 产出：注册表 legacy 节 + 写路径闸1 联动。
- 验收：尝试写入「线索」→ 显式报错。

**T7 存量归类**
- 通道：快照（按 card_009 §六双通道约束，**不走 git**）。
- 规则：
  - 根卡（无 parent）→ `project_class = rd_project`（本树）/ `research_project`（另两树，待确认后标）。
  - 原「剧本」非根卡 → 人工逐张确认后归 `sub_project`。
  - 原「线索」→ 批量归 `sub_project`（当前实际语义即「没选」，归工作单元无害）。
- 产出：迁移脚本 + 迁移前后快照对比报告。
- 验收：迁移后全树 card_type 合法；无数据丢失。

**T8 回归矩阵（12 条用例）**
- 边界：根卡无 project_class 报错 / 子卡 project_class 只读 / 工具卡无 owner 报错 / 工具卡有子卡报错。
- 报错：非法 card_type / 非法 project_class / legacy 值写入 / owner 指向非 sub_project。
- 不变量：影子卡通道独立 / 类型不碰布局 / 类型不碰权限 / 类型不碰根卡判据。
- 回归：既有「剧本」根卡迁移后功能正常 / 既有「线索」卡批量归类后查询正常。
- 产出：`tests/card_type_base/` 测试文件 + 通过报告。
- 验收：12/12 通过。

**T9 文档与卡片簿**
- 产出：根卡（card_001）下新建《卡片分类基座·v1》说明卡（正文 = 本任务书 §一~§三摘要 + 注册表指针）。
- 影子：本卡（card_041）影子同步进度、产物清单、迭代历史。
- 验收：说明卡可读；影子三节合规。

## 四、关键裁断记录（已替你定的细节）

| # | 裁断 | 理由 |
|---|---|---|
| 1 | L1 不引入「调研/文档」子类，差异用标签扛 | 基座保持薄；子类是工具卡实例的元数据，不是类型 |
| 2 | 工具卡不可有子卡、不删（completed 即终态） | 防止工具卡变成第二棵项目树；产物已挂载 owner，工具卡本体可冻结 |
| 3 | 注册表独立配置文件，不进 DB | 与 card_036 工具注册表同形态；改词表不改 schema |
| 4 | 字段 snake_case，短码 `rd_project` / `sub_project` / `tool` | 与现有 `card_type` 风格一致；短码减少存储与传输噪音 |
| 5 | 闸门只拦截写，读路径宽容 | 兼容 legacy + 新词表并存期；迁移是渐进过程 |
| 6 | 任何任务动写路径前先读 card_035 | 遵循现有收口约定，不抢跑 |
