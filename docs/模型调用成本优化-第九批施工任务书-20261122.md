# 模型调用成本优化 · 第九批施工任务书

**目标**　验收生产台账，分别验证同跳重试预算和凝练阶段复用，交付两项独立的启用与回退结论。第八批两项均已具备申请启用的依据，生产效果留给本批实测。 [第八批验收报告](模型调用成本优化-第八批验收报告-20261122.md)

**顺序**　固定发布候选和基线 → 验生产台账 → 先验同跳重试预算，再验凝练阶段复用 → 逐项给结论。每项对照只改其对应的开关。已经验收通过的开关可以维持原值，并在后项 A/B 两侧保持一致。

**授权**　准备和隔离复验现在可做。生产发布、开关调整和 5700 整组启停按已获明确授权的窗口和范围执行。未获授权先交准备结果，逐项标待部署或待试点。生产优先取自然流量，新增付费取证另行请示。 [项目规则](../AGENTS.md)

## 一、固定发布候选与基线

1. 登记候选提交及实际部署的工作树差异，列明本次纳入的后端和配置文件。并行改动若一同部署，需列入清单，分别记录影响。保留当前启动参数、开关原值和可恢复版本。
2. 对账 Web、全部 runner 和凝练进程的角色、端口、PID、启动时间、可核实的版本标识、开关实际取值及来源。以运行中的进程和行为证据确认生效。用 Web 和 runner 的 `/api/live`、`/api/health` 及凝练健康端口核对整组状态，再看页面首屏、卡片读取和首个正常回合。记录重启到可用的耗时及异常，便于区分启动问题和试点问题。
3. 开关按进程环境读取。标明实际覆盖的进程和流量。需要缩小影响范围时用隔离实例或已确认可独立配置的进程范围。重启前确认在途回合和后台批次状态，按项目既有方式操作整组。评审缩量、工具证据投影、唤醒合并、凝练提示缩量都维持各自当前值。
4. 按模型、任务路径和故障类型挑选可比样本。固定隔离回放的来源快照，先记录当前值，再单开候选项并复跑，最后回退复验。对生产自然样本保留各阶段的时间窗和原始读数，样本条件有差异时注明。

## 二、先验生产台账

1. 优先核对现有台账的写入者和运行版本。若已能证明目标版本在运行，直接从该版本的有效窗口验收。需要部署时保持业务开关原值，部署后划定新写入者和取证窗口。
2. 至少取一条自然发生的普通卡首跳和工具续跳，按 work、card、session、pair、逻辑跳次和 `attempt_id` 逐笔核对。记录物理尝试、发送确认、终帧、错误类别和实际出站字节，用执行记录核对业务回执。若样本实际出现断连或停止，按真实状态对账。正文自述不作为业务完成证据。
3. 从同一取证窗口复制台账，记录各写入者及检查点所覆盖的范围。独立 CLI 重建报表，与请求和业务记录核对。`complete=true` 只证明检查点所覆盖的范围。丢行、写失败、范围不全或覆盖未知时，标出受影响样本，暂停用这些样本作放行依据。端点用量按字段给覆盖率，缺值记未知，显式零保留。只有同一字段在可比的两侧都完整覆盖时才报告其差量。
4. 核对窗口内服务和页面可用性、启动耗时及台账写入健康。若当前缺可核对的自然样本，把现网计量标为待补证。故障注入、写盘卡顿和强制停止的验证放在隔离环境。

在仓库根目录运行。变量指向本次取证副本。

```powershell
python -m src.infra.cost_ledger report @ledgerPaths
python -m src.infra.cost_ledger diff $ledgerA $ledgerB
```

`$ledgerPaths` 为本次清单中的 JSONL 文件路径数组，`diff` 两侧各接一个文件。A/B 任务键不同时，保留两套原始报告，用样本清单对齐同一任务剧本，并附各自的原键及 attempt 编号。无可比业务回执时将业务等价性标为未知。 [台账 CLI](../src/infra/cost_ledger.py)

## 三、逐项试点

### 3.1 同跳重试预算 `COST_HOP_RETRY_BUDGET`

- 记录适用的模型座、回合入口和生效额度。对照普通主对话的三类样本：可恢复故障后成功并完成工具续跳、持续故障后按额度收口、真实停止后无新增发送。前两类各查最终业务回执，失败类单列失败原因。补核确定性拒绝的出站数、续跳独立额度及当前路由是否具备换座路径。
- **通过条件**　同一逻辑跳内物理尝试受实际配置额度约束。可恢复任务及其工具回执等价，停止后无新增发送。额度耗尽如实收口，并给出可比失败样本的绝对尝试数。第八批正式入口持续 503 为 9→3、可恢复场景为 2→2，都是隔离基准。换座结论只适用于已证实存在换座链的入口。

### 3.2 凝练阶段复用 `COST_MEMORY_STAGE_CACHE`

- 从相同源快照分别走正式凝练入口及正常源校验。先确认失败批的水位和已发布链保持正确，再核对恢复时命中哪些阶段、实际重发哪些阶段，以及发布后的水位、索引、上下文板、覆盖集和原文逐字读回。隔离环境补查归拢展开后的原文改写、端点变更、待发布来源过期。核验复用记录的模型路由、输入版本和有效回执。
- **通过条件**　同一失败恢复剧本减少至少一次已核对的阶段出站，恢复后的发布及溯源结果等价。来源变化时失效或拒绝旧候选发布。成功发布后同窗跳过单列为水位幂等。关态旁路缓存，恢复到原有行为，已发布记忆可正常读回。凝练提示缩量维持关闭。

隔离复验可复用批七、批八的正式入口脚本。批八复跑应指向新建的独立证据目录，避免测试清理覆盖已有产物。

```powershell
$env:PYTHONPATH = 'tests'
$env:B8_EVID_DIR = Join-Path ([System.IO.Path]::GetTempPath()) ('cc-b9-evidence-' + [guid]::NewGuid().ToString('N'))
python -m pytest tests/test_batch8_evidence.py tests/test_batch7_cost_accounting.py -q
```

## 四、回退与交付

- **立即停止扩大试点**　业务结果出现回归、同跳越额度、停止后仍出站、旧产物被误用、发布或原文读回不一致、服务不可用，或所需台账反复残缺。登记首个反例与影响范围，按已批准的回退范围处理。
- **独立回退**　按启动清单把对应开关恢复到试点前的值。涉及 5700 整组启停时按已获授权执行。核对进程健康和后续请求恢复基线、消息无重复落账、已发布记忆仍可读。保留历史台账和缓存供核查，生产数据及水位按正常业务机制继续维护。
- **交回材料**　发布与回退清单、样本索引、原始台账副本、CLI 报表、业务回执与溯源坐标、整组可用性和启动耗时、逐项试点结论。每项标明取证环境、窗口、开关、覆盖进程、物理尝试／发送确认／终帧／请求字节、用量覆盖、业务结果及回退验证。报告正文只列证据位置、摘要和必要指纹。
- **放行结论**　台账单列「通过／待部署／待补证」。两个开关各给「维持试点／建议扩大／回退／待补证」，写清剩余缺口及实际作用范围。隔离证据与生产证据分开记录。自然故障样本未出现时，注明生产收益未测，保留隔离结论。其余待补证项继续沿第八批各自的判据推进。
