## 一、背景与定位

旧类型系统（剧本·世界观·行为体·节点·假设·线索）是小说 agent 原型的遗留，实际已名存实亡：全盘只用「剧本」1 张 + 其余全「线索」，「线索」的真实语义是「没选」〔card_016 §二·3、card_009 §二〕。

本方案重建分类体系，分两层：

1. **项目分类（大类）**：标识一棵卡片树的根卡是什么项目。项目分类决定该树内可用的子卡分类体系。
2. **子卡分类**：每个项目分类下有自己的一套子卡类型词表。

本期只落地：**项目分类框架** + **研发项目下的子卡分类（子项目卡 / 工具卡）**。研究项目的子卡体系后续单独立项。

## 二、核心概念

### 2.1 项目分类（根卡分类）

| 项目分类 | 说明 | 实例 |
|---|---|---|
| 研发项目 | 以构建/迭代软件系统为目标的工程 | 本树（card_001 项目管理agent） |
| 研究项目 | 以调研/推演/产出结论为目标 | 另外两棵卡片树 |

- 项目分类**只挂在根卡上**；子卡不重复标注，由所属树继承。
- 项目分类是可扩展枚举，新增分类 = 注册表加一行 + 定义其子卡词表。

### 2.2 研发项目 · 子卡分类（本期词表）

| 类型 | 语义 | 关键规则 |
|---|---|---|
| **子项目卡** | 研发项目下一个相对独立的工作单元（对应现有的各主题卡，如 card_002/006/010/016…） | 可有子卡；可调用工具卡；是产物与过程的挂载主体 |
| **工具卡** | 被某个子项目卡调用、执行专项任务（产出文档、调研等）的卡 | 其**产物与过程永久挂载在调用它的子项目卡上**；自身不独立成项目 |

### 2.3 工具卡的挂载规则（本期最重要的新机制）

1. **调用关系显式化**：工具卡被创建/调用时，记录 `owner = <子项目卡id>`。
2. **产物归属**：工具卡产出的文档/文件/结论，在子项目卡视角可见、可索引（产物清单汇聚到 owner）。
3. **过程归属**：工具卡的影子卡（过程记录）同样归 owner 管辖——上级（子项目卡）可读其影子。
4. **永久性**：挂载关系不随工具卡任务结束而解除；工具卡完成后进入「已完成」状态而非删除。
5. 工具卡**不可有子卡**（防止工具内再长树，产物归属链断裂）。

## 三、与既有机制的边界（约束条件）

1. **类型不再兼任布局/权限/根卡判据**。布局路由、根卡保护走 parent 主键（card_009 已定方向）。新分类只回答「这是什么卡、能干什么」。
2. **影子卡不属于类型体系**：`card_type: "shadow"` 走独立通道，不进入词表，显式排除。
3. **非法值处理**：现状是静默降级为「线索」（card_009 §五护栏⑤）。新词表上线时，此闸必须改为**显式报错或显式归入默认类型**，不得静默。
4. **数据迁移走快照通道，不走 git**（card_009 §六 双通道约束）。

## 四、存储与字段设计（草案）

### 4.1 字段

| 字段 | 位置 | 内容 |
|---|---|---|
| `project_class` | 仅根卡 | 项目分类：`rd_project`（研发）/ `research_project`（研究）/ … |
| `card_type` | 所有非根卡 | 所属项目分类词表内的子卡类型；研发项目下：`sub_project` / `tool` |
| `owner_card_id` | 仅工具卡 | 调用它的子项目卡 id（挂载点） |

### 4.2 类型注册表（逻辑形态，非代码）

```
项目分类 rd_project（研发项目）
  └─ 子卡词表：
       sub_project  子项目卡：可有子卡、可调用工具卡、可删（无子卡时）
       tool         工具卡：必有 owner、不可有子卡、完成后置 completed 不删

项目分类 research_project（研究项目）
  └─ 子卡词表：（后续立项定义）
```

### 4.3 校验规则（写路径）

- 根卡必须有 `project_class`；非根卡不得设 `project_class`。
- 子卡 `card_type` 必须在其树的项目分类词表内。
- 工具卡创建必须带 `owner_card_id`，且 owner 必须是本树内的子项目卡。
- 非法值 → 显式报错（替代现行静默降级）。

## 五、存量迁移策略

1. **不动旧词表数据**：存量卡的 `card_type`（剧本/线索）原样保留，视为 legacy。
2. **渐进归类**：本树（研发项目）根卡先标 `rd_project`；现有主题卡（card_002/006/010/016/017/019/040 等）批量归为 `sub_project`——建议用一次性快照迁移脚本完成，逐卡人工确认可后置。
3. **工具卡从零开始**：存量无工具卡，无需迁移。
4. 旧六值词表在迁移完成后退役（退役动作本身另立任务，不在本期）。
