# 任务书：判断协议从常驻 system 改为「首轮注入 · 后续清掉」

> 日期：2026-10-14
> 性质：实现任务书。只定义规格、边界、验收；不在本文写代码。
> 用户口径（2026-10-14 11:46/11:49，逐字要点）：
> - 「判断器怎么可能是常驻提示词？判断器也应该用注入才对啊」
> - 「判断协议只有每一轮的首次调用注入，而且后续就该从轮内上下文里清掉，以防止污染模型判断」

---

## 0. 一句话规格

**判断协议从 `BASE_PROMPT`（常驻 system）摘出，改为「本回合首次模型调用注入一次；后续轮从轮内上下文清掉」。**

---

## 1. 现状基线（代码实读）

| 件 | 现状 | 落点 |
|---|---|---|

## 2. 规格

### 2.1 从 BASE_PROMPT 摘出

- `BASE_PROMPT` 只保留**使用说明正文**（系统结构 / 工具 / 卡片内容写入 / 工具错误码 / 卡间消息处理）；
- 判断协议文本**一字不改**（同一份 `JUDGMENT_PROTOCOL`），只换承载通道；
- `BASE_PROMPT_VERSION` **递增**（文本变了，回归基准要对账）。

### 2.2 注入时机：**只在本回合首次模型调用**

- 一个回合内，判断协议**只在 `state.rounds == 1` 的那次调用出现一次**；
- 后续轮（`rounds >= 2`）**不得出现**。

### 2.3 清掉：后续轮不得见（**这是本条的核心**）

- 判断协议**不得被固化进轮槽**（`prior_for_gateway` / `slot`）；
- 即：round≥2 的 `wire_messages` 里**不得含**判断协议文本；
- 目的（用户原话）：**防止污染模型判断**——判断早已做完，后续轮再看到协议，可能让模型"重新判一次"、跟板打架。

**实现约束**：

- **不得走 `turn_tail`**（它会被 `_engage_slot` 固化）。须走**独立的"仅首轮"通道**；
- 具体机制由实现方定（例如：与 `turn_tail` 分开的字段 / `call_main` 加"仅本次"参数 / `_engage_slot` 按来源跳过）；
- **不得给消息 dict 加非标准键**——`gateway` 直接 `messages.extend(...)`，多余键会**透传给端点**。

### 2.4 载体：单独一类注入事件

- **建议新增事件类型 `context_judgment`**（不复用 `context_preamble`）。
- 理由：`context_preamble` 的语义是「工作规范」（工具卡/思维链流程用）；判断协议是「入口判断协议」，**两者语义不同**。复用会让前端把判断协议渲染成"上下文注入·固定总领"——**标签是错的**。
- 事件层沿用既有七键外壳与 `data` 结构化；`EVENT_TYPES` 25 → 26；前端 `renderEvent` 加一个 case（渲染为独立的"判断协议"行，不得渲染成用户发言/助手回复）。

### 2.5 三席不受影响

- 三席的 `vp_system_prompt` 本就**不含**判断协议（它只拿中性上下文）——**零改动**，但要**断言证明**。

### 2.6 注入形态（角色 / 话术 / 位置）

**角色 ＝ `assistant`**

沿用已定的注入口径（`context_preamble`／`context_injection` 都是 `assistant`）。判断协议是同类注入，**同一套，不另开一套**——否则模型对"注入"的识别会分叉。

**话术 ＝ 第一人称自述改写（只改人称，协议内容一字不动）**

| 改前（现常驻 system 原文） | 改后（注入形态） |
|---|---|
| 你是推演工作台的入口判断器。 | **我**是推演工作台的入口判断器。 |
| 对用户这条消息，**先**判断该… | 对用户这条消息，**我先**判断该… |
| **先**问自己：… | **我先**问自己：… |

- **抬头**：`〔判断协议〕`（与 `〔工作规范〕`/`〔当前流程〕` 同构）；
- **其余一字不改**：四种判据（①②③④）、直答/拆解条件、收尾句（"拿不准就拆——…"）。

**位置 ＝ 本回合首次调用（`rounds == 1`），追加在用户消息之后**

**连带（须实测，不得据未验证的担心自加机制）**：末条为 `assistant` ⇒ 模型可能"续写"（预填）。**对判断协议可能正好**（顺"我先判断…"直接给出判断并动手），但**本项目未实测**。若不要预填，需在它后面补收尾消息——而"合成 user 收尾"**已被用户否掉**，故本条**只登记为待实测风险**。

**备选（不采用）**：保留第二人称——与"注入＝自述"口径不一致，等于给判断协议单开一套。

## 3. 连带面与风险（如实报告）

1. **`BASE_PROMPT` 变短**：947 B 从每次调用的 system 里消失（round≥2 省得更多）。须报告改前/改后 system 字节数。
2. **回归基准**：`BASE_PROMPT_VERSION` 升号；凡以 `BASE_PROMPT` 全文做基准的测试/脚本须同步（如 `test_t11_regions` 的冻结副本、`test_t12_memory` 的版本断言）。
3. **前端**：新事件类型要加 case，否则收到即丢（`stream.js` 的 switch 无 default 渲染）。
4. **事件计数断言**：`test_token_stream_isolation` / `test_flowlane` 里 `len(EVENT_TYPES) == 25` 的断言要同步为 26。
5. **round1 与 round≥2 的 system 是否还相同**：本任务不动 system 的其余部分——但须确认"判断协议挪走后，两次调用的 system_prompt 仍然一致"（若实现方改成"round1 用带协议的 system"，那就是另一条路，须先呈报）。

## 4. 验收（严格版）

> **全绿只是最低门槛，不是验收。** 每条须有**可复现证据**；无证据＝未通过。

### 4.1 证据规则

1. 每条判据附证据：测试名＋断言原文／日志摘录／改前改后 diff／实测字节数。
2. 报告须给**改动前后对照**，不许只写"已通过"。
3. **未覆盖项必须显式列出**；用"全绿"掩盖未覆盖＝报告不合格。
4. 任一判据失败 → **停手如实报告**，不得"绕过去让它绿"。
