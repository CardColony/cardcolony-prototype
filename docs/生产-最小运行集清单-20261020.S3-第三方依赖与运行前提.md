## 1. 方法（可机械复核）

1. **模块级导入闭包**：以 `main.py` 为根，只追踪**模块级**（非函数体内）import，得到 83 个仓内模块 → 这一集合里出现的第三方＝"导入期即可能需要"的硬集；函数体内 import 记为延迟项。
   - 口径：AST 遍历，遇 `FunctionDef`/`AsyncFunctionDef` 即标记为 deferred；`from pkg import sub` 同时解析 `pkg` 与 `pkg.sub`。
2. **全仓 import 清点**：排除 `.venv`/`.worktrees`/`node_modules`/`_backup*`/`__pycache__` 后共 **839 个 `.py`**，用 `sys.stdlib_module_names` 剔掉标准库，剩下第三方候选。
3. **声明项 ↔ import 双向对账**（§2、§3、§4）。
4. **`.venv\Lib\site-packages\*.dist-info` 实装清单**（§附录 A）——用于回答"装了一堆没用"。

## 3. 声明了但代码里没有：`litellm==1.50.0` 是死钉

**证据链（三重）**

1. `src/`＋`main.py` 全量 AST：`litellm` **零 import**。
2. 文本检索仅命中注释/docstring，共 7 条：`src/model_gateway/gateway.py:25`（原文"旧 litellm 薄壳与按传输方式分的 llm_deepseek **均已退役删除**"）、`gateway.py:702`、`src/model_gateway/llm/types.py:220`、`src/model_gateway/__init__.py:1`、`src/storage/memory_store.py:277-278`（只作 token 口径对照说明）。

## 5. 可选依赖：`requirements.txt` 的承诺与代码不符（重点纠偏）

`requirements.txt:13-17` 原文承诺：「不装则联网两件不注册（`card_tools._prune_unavailable_plugins` 剪枝），其余 23 件工具照常。」

**核查结果：这个剪枝函数在代码里不存在。**

1. `_prune_unavailable_plugins` 在 `src/` 全部 99 个 `.py` 中**零命中**。
2. 工具注册表**无条件注册**：`src/api/card_tools.py:2572-2587` 的 `"web_search": ToolDef(...)`、`:2587-2601` 的 `"fetch_web": ToolDef(...)`；而 `ToolDef` 只有 `schema / handler / readonly` 三个字段（`card_tools.py:334-347`），**没有任何"可用性/依赖"字段** ⇒ 装没装 `requests`，这两件都出现在工具面里。
3. **不装 `requests` 的真实后果**：
   - 进程**正常启动**（延迟导入，见 §2）；
   - 模型一调用就失败：`_h_web_search`（`card_tools.py:1786-1794`）/`_h_fetch_web`（`:1795-1802`）第一行 `from . import search_tool` → `ModuleNotFoundError` →
   - 被 `execute_tool` 尾部 `except Exception` 兜成错误信封（`card_tools.py:4558-4603` 区间）：`{"ok": false, "error": {"code": "internal", "message": "No module named 'requests'"}}`。
   - 即：**坏在"第一次调用"，不是"不注册"**；模型看到一个 `internal` 错误（且响应对模型说明不了是缺包）。
4. **真正"软跳过"的层级是通道、不是包**（`src/api/search_tool.py`）：
   - `SEARXNG_URL` 缺省 `http://localhost:8888`（`:27`）；
   - `ALIYUN_TOKEN_PLAN_API_KEY` 为空 → 备用通道直接 `return None`（`:77-79`）；
   - 两通道皆不可用 → 返回 `{"error": "搜索失败：SearxNG 不可用且阿里云备用通道失败…"}`（`:117-118`），**函数永不抛异常**。

> 清单口径建议（不改代码）：要么把 `requests` 提为必需（一处延迟导入换来"功能在"），要么补一个真剪枝（`find_spec('requests')` 不成立时不注册）。现状是"注释承诺了代码没做的事"。
