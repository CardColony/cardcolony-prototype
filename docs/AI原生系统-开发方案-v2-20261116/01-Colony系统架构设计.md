## §一、终局全景总图：Colony 建成后的数字世界长什么样？

Colony 终局架构把整个数字世界重构为内外两个干净的半场——**对内是「多设备合一的个人主权领地」，对外是「无中心平台的自由公海」**：

## §三、L0 全光谱内核架构：为什么同一颗极小内核能撑起整个终局？

内核是整座大厦最不能返工的部分。在愿景架构中，L0 内核严格遵守**「只定自然法则，不装具体楼房」**的原则——凡是百元路由器或老电纸书跑不动的功能（大模型本体、重型数据库、复杂图形界面）一律不进内核；但未来十年所有高级场景需要的**底层接口与安全法则**，在 L0 里一次全部立齐：

```

│                          L0 全光谱内核的六大核心机制                                   │
│                                                                                     │
│  [1. 原生整机＋微外设收养]         [2. 统一账号与信任边界]                            │
│   • 原生一刀切：整机替换软件栈，     • 内网环：同账号自家设备，透明互调器官与借算力      │
│     主线/下游厂商内核皆可当硬件层   • 发布面：外人只能打你发布的节点（联机房/块交换）  │
│   • 刷不了机的出局；单片机被收养   • 节点授权线圈死可达范围，内网对发布面零暴露        │
```

### 内核设计最精妙的四个平衡点

1. **怎么兼顾「老旧封闭小设备」与「全新重型主机」？（原生一刀切 ＋ 能力自适应）**
   - **唯一形态＝原生整机**：任何设备要进圈，软件栈必须整个归 Colony——主线内核优先；像 Kindle 墨水屏驱动这种焊死在厂商内核里的，允许**保那颗内核纯当硬件抽象层**（postmarketOS 下游内核路线），但原厂软件一律清场，开机拉起的是 `colonyd`；
   - **刷不了机＝出局**：完全无法整机替换的锁死设备不进生态，不留寄生、不留后门——生态承诺就是"我管的机器，每一行用户态软件都姓 Colony"；
   - **微外设收养**：温湿度计、开关面板、串口模块这类跑不了 Linux 的硬件，由家里最近的 Colony 设备「收养」为器官节点——它们是器官，不是公民，本来就不需要装系统。
2. **怎么兼顾「傻瓜式一个账号全连上」与「绝对数据主权」？（自举密钥首发零服务 ＋ 官方服务随公海接入）**
   - 用户体感极其简单：新设备上线广播申请、主设备一键审批（无屏设备吐短码也行），不管在家里还是带出门，所有设备自动连成一张加密内网；
   - 底层权力极其清醒：账号＝**自举生成的根密钥**（`account_pub` 即 Colony ID，终生不变）——首发版零服务依赖，主设备当发证机关，恢复靠离线密语＋自家设备加密分片；第二阶段**官方账号服务随发现网络接入**——手机号＋实名 KYC 绑定 `account_pub`，接管绑定名录、吊销目录、公共信标和**零知识加密备份**（用你的密钥加密，它永远解不开）。**它知道你是谁，永远看不到你干什么**——画像、内容、调用记录一概不出设备圈；服务接管的是"目录与便利"，密钥始终是你的，v1 证书全数有效。其他设备拿到的只是受限「工作证」——路由只拿守门规则，音箱只拿语音权限，丢失设备可从名录吊销，资源端收到后终止其访问。
3. **怎么兼顾「轻巧省电」与「120 帧游戏、50GB 大吞吐」？（传话与搬货彻底分家）**
   - 两个模块传输画面、语音或游戏块时，先按用户的线核实双方，再建立高速数据通道。摄像头、麦克风的资源提供端保有随时停止后续采样交付的能力。画面可直达已授权的预览端，调用按钮、网络中继和普通日志均无需接触原始帧。
4. **跟外部节点互通时，家庭资源由谁放行？（内网 vs 对外发布面）**
   - 内核在网口最底层把连接分成死隔离的两半场：**自己人（内网织体）**互借算力、同步记忆；**一切外部世界（发布面）**只能打到你 work 里发布的节点——亲友联机房、共享屏、公海块交换节点都是其一，可达范围被那根节点授权线圈死，公开端口不提供内网节点目录。网络转发者可能看到流量元数据；私有数据只交给用户授权的接收端。设备身份、work 内节点身份与授权线的分工见[《安全架构与节点信任边界》](04-安全架构与节点信任边界.md)。

### 安装层：原生整机怎么落到每一台设备上（内核只管接缝，工厂在海关外）

安装层是「移植层」的下游——移植让"能支持"变便宜（AI 按契约填空写 BSP），安装让"用得上"变无脑（用户不该需要知道自己设备的型号）。它**不是内核的一部分**，但内核为它留死三个接缝；其余全部跑在海关外面（安装者机器、CardColony 智能体卡、社区 CI）。

- **最小包公式**：`【BSP 硬件包：匹配的内核+驱动+设备树+启动配置】＋【最小 Linux】＋【colonyd】→ 开机入圈后 →【按能力选装的 Colony 增量】`。不变的永远是中间两件（全世界同一份），变的全是"按指纹选好的包"——安装从系统手术降级为**选配方**。
- **用户侧四步**：① **探针**读硬件指纹（跑在旧系统里，与内核 HostCaps 同一份探测代码、编译两个化身）；② 撞**设备档案库**配对 BSP 与安装配方；③ 按配方刷入（全程可回滚）；④ 装完自动跑契约测试验收，才算装好。
- **两层档案库**（挂在开放索引上的社区数据）：**零件库**存单颗硬件配方（芯片指纹→驱动+固件+怪癖），是 AI 组合的原料；**整机库**存整台设备配方（设备指纹→BSP+配方+**可装性状态**）。未知设备几乎总是"已知零件的新组合"——零件库每厚一分，真正要新解的部分就少一块。
- **固件逆向流水线**（移植的标准工序）：探针指纹 → 拿原厂固件解包拆答案（设备树=硬件地图、内核配置=驱动清单、二进制 blob=闭源件成品）→ **主线优先、blob 兜底**组装 BSP → 虚拟靶场过契约 → 真机回滚装 → **配方（含失败情报）发表回社区**。法律红线：档案库只存配方与"从你自己设备现场提取"的指引，**不直接分发 blob 本体**。
- **可装性只分两态**：`可原生刷`（主线/下游内核）／`不可刷`（出局——不留观察、不留后门、不搞寄生）。
- **与内核的三个接缝**：① `HostCaps` 能力问卷（适配结果的形状）；② BSP 以 `.cext` 增量包过 K-4 海关（免费继承签名、A/B、原子装卸）；③ `colonyd` 原生运行前提（静态单文件、启动自探测）。
- **飞轮**：装成的未知设备自动变成整机库新档案——**第一千个同款冷门设备的用户直接一键**，因为前面的人已经趟过了。硬件支持不靠官方排期，靠安装行为长出来，越用越快。

## §四、心脏与大脑：L1 个人主权库 ＋ L3 织体级 AI 调度发动机

传统系统里，数据是死文件，算力是笨进程。Colony 把「懂你的记忆」和「替你思考的算力」做成了整片个人领地共享的两大中枢：

### 4.1 L1 个人主权心脏：整圈设备围绕「你」转，不再围绕 App 转

- **全生命周期个人资产归拢**：你的阅读批注、聊天记录、日程、音乐歌单、每一款游戏的存档与进度、每一次「喜欢/拉黑」的反馈，全部存在你自己的主权库里。应用只是被你请来处理这些数据的工具——今天卸载这个音乐软件换另一个，你的歌单和听歌品味分毫不损。
- **人话写成的「透明画像」——推断层与声明层分开**：画像＝你全部行为流水的聚合，经后台模型凝炼成**自然语言**（审美口味、决策偏好、时间规律……）。**没有"改画像"这个动作**——"用户声称的自己"往往和真实的自己不匹配，手改只会往真相里掺谎；你能做的是**看、导出、清空重凝炼**。你显式声明的东西（**硬避雷红线**：明确厌恶的题材/套路/诱导话术）属**声明层**——独立存放、人话可读、随时改，且**声明优先于推断**（红线一票否决）。系统甚至可以当诚实的镜子：把"你声称的"和"你做的"摆在一起照出矛盾。
  - 它不是锁在大厂服务器里的几万维黑箱数字，而是**你随时能翻开看懂、随时能动手增删改的一份人话档案**（你手动改的一句话，优先级永远压倒机器猜的一百次）。
  - 向量索引只是挂在旁边的检索字典，换模型随时重算，人话画像与原始资产才是永恒真相。
- **动脑与看屏分家**：匹配、凝炼、过筛这些"动脑子的活"是 work，实例化在够格设备上干（NAS 巡航粗筛、路由过滤、PC 凝炼画像）——它们按需经授权线读写主权库，干完结果汇聚回 L1；掌机/手机/Kindle 这类终端只做**展示器官**：呈现已被挑好的结果，要改画像时经线远程读写，本机不存画像副本、不跑匹配。**"终审在本地"的本地指你的领地，不指终端那台屏。**
- **数据只往需要它的器官流（CRDT 切片）**：主设备与家庭中心保存全量记忆；干活设备只同步它职责所需的那一小片（路由器只拿避雷黑名单，匹配节点只拿画像凝炼区）；终端只存自己要消费的东西（在玩的存档、已下载作品、展示缓存）。

- **模型槽＝开放契约接口族，出厂零模型**：系统**不预置任何模型、不设官方模型、也不绑死槽位类型清单**——`model.infer`/`model.embed`/`model.asr_tts`/`model.vision` 这类 `model.*` 契约全部由增量包注册提供、用户按需配置（向量/听说/视觉装不装、装什么全看自己，未来冒出的新模型类型同样走注册长出来，系统不预判）。默认全走本地算力；借不到算力就诚实报 `E_CAP_UNAVAILABLE`，降级是节点自己的事（音箱说"连不上脑子"、NPC 退回脚本台词），内核绝不偷偷换个小模型冒充。如果用户愿意把某个超重思考槽绑定到外部大模型（如 DeepSeek 远端接口），必须由用户亲手连上「出境放行线」，且密钥由系统保险箱代填，任何应用和节点都摸不到你的密钥。
- **织体分布式异步计算（拆→撒→汇）**：比「单次请求借算力」更进一步的形态——凡是不需要点亮屏幕才算的活（画像凝炼、内容过筛、作品索引巡航、游戏世界离线演化、向量重建……），发动机可以把任务**拆成子任务撒到圈内多台闲设备上并行干**：路由器抓源、NAS 过筛、PC 跑凝炼，各尽所能；干完的结果**汇聚回 L1 主权库**（CRDT 自动同步到各设备切片），你随手拿起哪个终端——Kindle、掌机、手机——看到的都是已经完工的成品。整个家庭设备群在此意义上就是**一台私人分布式计算机**：闲时全员上阵，忙时各自让路（K-6 电源与席位闸自动压制），干活期间每台机器仍然「休眠零内存」地按需唤醒。
- **节点平时「休眠零内存」**：领地里哪怕装了上百个智能体节点和自动化管线，没事件时进程全部退出，占 **0 内存**；定时到点、来消息或按了硬件按键时，毫秒级唤醒干活，干完落盘再次归零。
- **显存与沙箱总账平衡**：像多智能体开发或大型 AI 游戏这类既要跑模型、又要起一堆工具任务的场景，发动机与内核共管同一本内存总账——满了就井然有序地排队（回告「排队攒批中」），绝不把机器撑崩卡死。
- **第一版调度器刻意「笨」**：全部用确定性规则——交互级请求优先本机/局域网、攒批闲时活才织体外借、有席位先保席位、攒批设死线不死等。**可预测＞聪明**：笨调度最多低效，不会灾难；内核保底（不越权、不撞车、不饿死实时、撤权必断），聪明的启发式以后只改 L3、内核一行不动。

## §五、去平台化大闭环：去中心化分发 × 去中心化曝光（以游戏为先锋的全品类模型）

先钉死这个闭环是**两层都去中心化**（公海的具体形态——公共签名账本、实名准入、产权登记、真人性权重、辖区合规——属生态层下一阶段，详录于 `03-生态层-公共账本与治理（下一阶段）.md`）：
- **分发层（管道）**：作品登记进开放索引（公共签名账本，人人可镜像、无单点主人）、托管在哪都行，大文件走内容寻址分块由全网节点互助传输——**没有任何平台拥有管道，这是分发的核心**；
- **曝光层（被看见）**：去中心化世界没有热搜榜——「被看见」不能靠买量竞价，必须由机制本身解决：**每个用户自己领地里的匹配闸决定什么浮得上来**。这正是项目 B 要解的命题（Joker 正在验证的方向，协议本身尚未跑通——它是我们要做的事），Colony 把它从「内容」推广到「作品」：**开放 PSN 粗筛 ＋ 粗筛/精排分离 ＋ 端侧终审**。

```
  【 独立创作者端 】
   作品托管在哪都行（自建站/任何渠道）＋ 创作者实名签名「自述画像」登记进公共签名账本
                    │
  【 公信层：体验画像不靠作者自夸，靠真实受众凝炼 】
   全网真实消费过的受众口碑/评论 ──▶ AI 凝炼成多维「体验画像」
   （strong/weak signals —— Joker 已验证的 16 维结构）
   货不对板的作品在画像里自然沉底，标题党无处遁形
                    │
  【 开放匹配网络：任何人可跑 PSN（个人资料服务节点）】
   PSN 职责＝存画像、响应粗筛、中继操作日志；
   你的家用 NAS 完全可以就是你自己的 PSN
                    │
  ════════ 主权分界线：完整画像永远不出门 ════════
   你的设备只把「受限查询描述符」（要/不要的标签，不含画像权重）
   发给 PSN 做粗筛 ──▶ 候选集回来
                    │
                    ▼ 本地终审（全部在你的领地内完成，后台预计算）
   ① avoid_for 硬避雷（踩中即弃，避雷优先于命中）
   ② 全量画像语义精排（matching 打底＝满足感）
   ③ 发现机制三道门（质量好 strong_signals / 近期 / 不踩雷）
      ── 不用相似度主导发现，防信息茧房、保惊喜感
   ④ 剥成事实呈现（推信息不推推荐语）
                    │
                    ▼
   看上了 → 从作品所在处取件（大文件走内容寻址分块加速＝传输层优化，谁传都一样）
          → 一键点对点直付创作者（0 平台税）
```

这套架构回答了过去去中心化尝试最难的三个死结：
1. **没有热搜的去中心化世界里，作品怎么获得曝光**——靠匹配而不是靠榜：创作者的诚实自述画像＋真实受众凝炼的体验画像进公共签名账本；**内容发布后不是被推给你，是被你的模型主动找到的**——领地里的匹配器拿着行为凝炼的真实画像去公海里捞，捞回来再过本地终审闸。**「被曝光」从此不再是平台卖给你的资源，而是匹配的自然结果**——好作品到达该到达的人，烂作品无人可买量。
2. **没中心审核怎么防垃圾和标题党**：体验画像由真实受众口碑凝炼（strong/weak signals），不是作者自填；`avoid_for` 硬红线一票否决（避雷优先于命中）；发现机制用「质量好＋近期＋不踩雷」而非相似度主导，顺带防信息茧房。
3. **弱设备与创作者 0 成本**：家里 24h 在线的 NAS 既可以当你自己的 PSN 替你巡航粗筛，又能闲时把命中的大作品预载回家；取件走内容寻址分块，谁传都一样、验过哈希就行——创作者发表零门槛，爆款也不收天价服务器账单。

## §七、最上层的面孔：多形态体验壳与「超级交互入口」

大厦封顶的 L5 体验层可随硬件形态自由换壳，但旗舰主屏（电脑、平板、掌机、大屏）统一呈现为**「超级交互入口」**，严守四条纯粹体验铁律：

## §八、从这张终局愿景图倒推：我们怎么从最小的第一块砖长过去？

画清了整座终局大厦，回看从 0 到 1 的生长路径就一目了然了——**不是先盖个草棚拆了重盖，而是先把整座大厦通用的「L0 地契内核」一次浇筑到位，然后一格一格往上面插增量积木**：

1. **第一步（最小起跑点 · 第一阶段初始版）**：
   - 把 **L0 全光谱内核**（原生整机、统一账号组网、契约锚总线、安全笼子）做出来，配上**最薄的第一版跨设备模型调用与器官连线面板**；
   - **全程实录由 CardColony 驱动大模型全自动写出这套初始版 OS**，并现场演示把电脑、NAS、百元路由器、旧音箱、吃灰的 Kindle 登进同一个账号组成节点网，互相借算力跑模型、玩出跨硬件神仙组合——地基一次立正，同时引爆全网极客把常驻节点装进千家万户。
2. **第二步（轰开围墙的主战役 · 第二阶段）**：
   - 在完全不改 L0 内核的前提下，往上插齐 **L1 主权画像库、L2 去中心化分块分发与三道避雷城门、L3 波次攒批与游戏 AI 引擎、以及掌机/客厅主机游戏壳**；
