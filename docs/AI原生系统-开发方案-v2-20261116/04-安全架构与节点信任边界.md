# Colony OS · 安全架构与节点信任边界（v2）

**安全承诺**　即使一个普通节点由恶意代码控制，它通过 Colony 能取得的数据、调用的能力、交付的对象，仍受用户已生效的授权线约束。安装节点、签名通过、设备入圈、知道地址或线号，均不产生一根新线。摄像头、模型、应用和远端信源遵守同一条规则。

本章给出架构约束和应观察到的行为。K-2 认证设备，K-4 核验安装和更新，K-5 绑定通道，K-6 隔离节点并识别运行实例，K-7 的 `tbl_lines` 保存用户授权。设计依据见[总纲](00-理念与总纲.md)和[内核规范](02-Colony内核全景设计与契约规范.md)。以下判据有待实现及独立验证。

## 一、承诺成立的条件

| 场景 | 用户可以依赖的边界 |
|---|---|
| 陌生设备、同一 Wi-Fi 上的旁观者、网络中继 | 外部调用只到用户发布的端口。私有流的明文只交给获准端点。转发者仍可能观察到通信时间、流量大小等网络元数据。 |
| 已入圈设备上的普通节点被控制 | 在宿主隔离有效时，影响限于该节点原有权限。相邻节点、同一蓝图的另一个 work、同机其他进程各有独立身份。 |
| 已获准读取原始数据的节点被控制 | 该节点在授权范围内确实能读到数据。已交给它的画面可能被复制。授权前应区分原始数据、受保护的预览和经过裁剪的结果。 |
| 调用设备的底层系统或设备密钥失守 | 来自该设备的身份声明可能失真。资源设备继续执行设备范围与用户授权的上限。吊销设备后，按第四节的生效边界断开。 |
| 资源设备的底层系统、受信驱动或用户签线组件失守 | 资源可能被直接采集，或出现看似有效的新授权。宿主、可信运行时、签线组件及能替换它们的更新链属于可信基础。能力受限的旧设备按其实际隔离等级承载节点。 |

包签名说明来源和内容完整性。代码即使由已知作者签名，也可能有恶意行为。用户签线密钥、设备认证凭据和更新签名权限按用途隔离。普通节点需要新增权限时只可提交接线建议。用户确认的内容必须与实际签下的 work、节点、端口、方向及约束一致。节点更新后仍受既有授权上限约束；替换蓝图中的节点或扩大其权限，沿用用户重签接线图的规则。

## 二、一根线怎样绑定真正的调用者

以设备 A 上的「客厅通话」读取设备 B 的摄像头为例。

1. **确认设备。** A、B 的可信运行时建立经认证的加密通道。B 核验 A 持有有效设备凭据，凭据允许的范围构成上限。
2. **确认节点。** A 的运行时根据本机隔离的进程和通道，认出已启用的 work、节点实例及本次运行。跨机调用把这份身份绑定到获认证的连接及本次请求。B 校验该绑定。节点自报的名字、复制的线号和软件包签名都不足以证明运行身份。节点重新唤醒时由运行时重新绑定，已结束运行的通道不能继续使用。
3. **确认线。** 持有资源的 B 作最终判定。核对调用主体、work、资源端点、允许的动作、数据方向、接收端、有效期及当前代次。发起读取的是 A，画面流向也是授权的一部分，即从 B 的摄像头到 A 的指定接收节点。校验失败时，流不能打开，第一帧也不能交付。
4. **限制代办和派生。** 有权限的节点替别人办事时，沿可核验的委托链保留发起者、获准用途和结果接收端。独立的自动化按用户已签的 work 图执行。派生子线要核实父线持有人有权作此委托，并同时收窄或保持对象、动作、数据、受领方、期限和总额度。父线撤销覆盖其子线；为多个子任务拆线也不能放大总额度。

授权账只保存用户批准的关系；运行时把实际主体和通道绑定到这份关系。调度器换执行设备时重新核验授权范围，算力不足、同一账号或同一软件包都不能扩大去向。公开端口可以面向匿名读者，发布者须限定可公开的资源与操作；公共块交换端口只读已发布对象。

## 三、画面走点对点通道，源端始终有停止权

**摄像头默认私有。** 用户在「客厅通话」接好线后可以直接使用。B 只向获准接收端交付新帧。普通节点没有独立访问摄像设备、共享缓冲或任意外发的旁路。高速数据通道可以直达端点，B 仍须控制后续交付；无法收回或停供的设备句柄不得交给普通节点承担这项承诺。无法提供所需隔离的宿主不开放相应敏感能力。

同一摄像头可以按实际能力暴露不同端口。授予「有人经过」时，只在可信采集端处理画面，通知节点拿到约定格式的事件。授予「受保护的屏幕预览」时，画面只交给可信显示端，控制节点只能启动和停止。授予「原始视频」时，接收节点确实能读帧；若还给它一条外发线，数据可能沿两根线组成的路径离开设备圈。接线图应向用户显示这样的去向。

B 提供由可信运行时控制的使用指示和本地停用入口，显示正在采集的资源、使用它的 work 和接收端，无屏设备可使用本机指示灯及物理停用件。用户可以在自己的 work 里查到授权、起停、去向和结果。安全审计记录这些事实和关联标识；原始音视频进入记录需要单独授权。对宿主已失守仍要求停止采集的场合，由物理遮挡或硬件断电提供独立边界。

## 四、本机剪线、远端吊销和离线

- **在 B 上停用。** 本地停用立即阻断新采集的内容进入被撤销的流，无需等 A 确认。并发中的其他合法 work 只受自身授权约束；用户关闭整个摄像头则影响全部使用者。
- **从别处剪线或吊销。** 发起端记录请求，B 收到可信撤销后封住新调用、停止旧流、清理派生任务并回执。界面分别显示「待送达」与「资源端已生效」。内核规范的 10 毫秒目标从 B 接受撤销起计，衡量本机执行，不包含网络送达时间。
- **B 暂时收不到撤销。** 远程敏感流只在 B 可验证的有限授权期内持续，续期需有新的有效依据。失联不能无限续期；无法确认授权有效时停止供给。恢复连接先对齐撤销状态，再受理恢复、排队或重试的调用。撤销约束后续供给，接收方先前收到的数据仍可能存在。

## 五、独立验证观察什么

以下均为**设计判据**。使用同一台 B 摄像头和两个分属不同 work 的 A 端节点验证。观察源端实际采集、各接收端实际取得的内容和时间，以及授权状态。

| 场景 | 应观察到的结果 |
|---|---|
| 安装天气节点并批准 A 入圈，随后仅给通话节点接线；让天气节点知道通话节点名和线号 | 天气节点收到零帧；合法通话节点收到画面。 |
| 同一蓝图启用两次，或节点重新唤醒 | 两个 work 的节点身份可区分，旧运行通道不能复用；剪掉其中一条线，另一条获准的流可继续。 |
| 普通节点既没有有效线也没有委托，提交接线建议、引用他人的父线或让另一个服务代取画面 | 授权账没有新增有效线，原请求方收到零帧。另验证持有有效委托的子任务可以在受领范围内工作。 |
| 只接「有人经过」端口 | 通知节点得到约定事件，节点输入、可读缓冲和普通审计里均无原始帧。 |
| 只接受保护的预览端口 | 用户能在指定屏幕看到画面并停止预览；负责按钮和界面的普通节点只收到控制回执，无法读帧。 |
| 公开一个作品端口，同时运行一条私有通话流 | 外部读者能读作品；中继可转发密文；两者均得不到私有画面或内部节点目录。 |
| 本机停流、远端正常撤销、撤销通知暂不可达 | 分别验证本机停止时间、B 的生效回执、失联到期停止。以采集序号区分撤销后的新帧与在途旧帧。 |
| 恢复设备或重放旧任务记录 | 恢复记录可解释历史，已失效的凭据、已撤销线和过期接收端不能借恢复重新取得数据。 |

实施方案须为具体宿主写清节点身份如何绑定、敏感流授权期限及其依据、可停供的数据通道和测量方法。独立验证前，这些都是待兑现的安全承诺。
