# 03 · 生态层：公共账本与治理（下一阶段愿景）

> 代号：`E`（Ecosystem）。上位源头：`00-理念与总纲.md`、`01-Colony系统架构设计.md`。
>
> **本文档的定位**：这里记录的是 **OS 本体之外、长在 Colony 之上的生态层机制**——公共账本、实名治理、产权、口碑权重、辖区合规。**这是第二阶段及以后的内容，现在不是契约冻结对象**。
> 之所以现在记：这些机制决定了 OS 层（尤其 K-2 身份底座）必须为生态层预留什么接缝——接缝今天焊死，大楼以后再盖。
> OS 侧只负责：账号→设备绑定、器官池、对外发布节点、块仓与签名原语。本层的账本服
务器、验证者、索引、产权登记全都不是内核的事。

---

## §一、边界划分：哪一半在 OS，哪一半在本层

| | 归属 | 内容 |
|---|---|---|
| **OS 内核（K-2，现在就要定）** | `02` | 账号公钥作为身份锚、设备证书签发/吊销、申请→审批入圈、三层信任边界（内部织体 vs 外部发布面）、器官广告 |
| **生态层（本文档，下一阶段）** | `03` | 官方账号服务的业务实现（KYC/辖区）、公共签名账本、发表实名与可追溯链、产权 token、口碑真人性权重、合规执行点 |

一句话：**OS 提供"身份、设备、连线、签名"四种原语；生态层用它们搭出公海、产权与治理。**

---

## §二、官方账号服务：身份中心化，数据主权化

- **它的出场时机**：**随发现网络一起上线，不进首发 OS**——v1 开源系统走纯自举身份（本地根密钥＋离线密语＋自家分片备份），零服务依赖即可全网互联；账号服务存在的首要理由是为公海生态（实名发表、可追溯链、产权登记）提供问责锚点，所以它跟公共账本属于同一批货，一起上。
- **它是什么**：Colony 官方运营的账号服务——接入时把已有 `account_pub` 绑定到手机号＋KYC 实名账号（国内合规必需品，也是全球消费级产品的唯一现实形态）；**密钥本身永不上交**，服务接管的是目录与便利，不是你的身份本体。
- **它持有**：账号→设备公钥绑定名录、证书签发与吊销目录、公共信标/中继（跨公网打洞）、**加密备份托管**（用你的密语密钥加密的身份包，服务方永远解不开——它只是个保险柜）。
- **它永远看不到**：画像、内容、行为、存档、调用记录——**它知道你是谁，不知道你干什么**（Signal 模型：身份可问责，数据零可见）。
- **辖区分区**：协议全球统一，账号服务按司法辖区分段——国内区全量 KYC 实名；国际区轻量验证（手机号级）。跨区作品带"未验证来源"旗标过用户本地闸门。
- **它顺手解决**：恢复（手机验证重新发证，离线密语降级为兜底）、吊销（服务名录标死）、信标（官方跑公共路灯，自家常开设备优先）。

## §三、公共签名账本：公海的地基是公共设施，不是谁家服务器

- **形态**：**类区块链性质的公共账本**——签名追加、追加只增、人人可镜像、无单点主人。**明确无币**：不发代币、不 PoW/PoS、不可炒作（国内法律红线＋内容索引根本不需要金融共识）。
- **共识**：国内区由**持牌验证者集**记账（官方＋合规伙伴）——"谁出块谁担法律责任"，合规义务天然落在验证者身上，协议本身无罪。
- **记三本账**：
  1. **作品索引**：作品登记＋创作者签名自述画像（发表＝一笔签名交易）；
  2. **口碑信号**：受众真实评价与体验信号（评价＝绑着产权与经历凭证的签名记录）；
  3. **产权登记**：谁拥有什么作品（产权 token，见 §五）。
- **下架的正确姿势**：账本诚实追加不改历史——违法条目由国内验证者在**服务国内用户的索引视图**里过滤，下架的是视图不是历史，既不伪造公共账本又满足合规。

## §四、可追溯链与发表问责：开放传输，问责发表

- **前台化名，后台实名**：作品 → 创作者公钥 → KYC 账号 → 真人。读者只见笔名与作品画像；发表进索引必须带实名账号签名背书（密码学伪造不了）。
- **"隔离无法追溯"＝饿死不是堵**：传输层自由（裸块谁都能搬）；发现层 gated（进索引必须实名背书）。不可追溯的内容存在但等于不存在——没有索引入口、没有画像、默认闸门不信任。
- **强制在服务层，不靠自觉**：索引收录未验证＝运营者非法运营（面向国内运营索引是持牌义务）；官方客户端合规构建未验证不渲染；支付渠道天然实名。个人自编译客户端看未验证内容＝个人行为责任自负（等同今天的 BT 用户）——协议不管、也管不了个人机器，它只保证**没有合规渠道能把未验证内容放大给普通用户**。

## §五、产权 token：不是访问锁，是"拥有"的证据

- **它是什么**：账本上的产权记录（`作品哈希 → 持有者公钥 → 创作者签名转让`）。**不是代币、不增值、不拆分、不可炒作**——它只是一条"谁拥有什么"的登记。
- **它不是什么**：**不做"打得开"语义**——不是访问锁、不是 DRM（破解成本本来就低，产权的本职从来是证明拥有，不是防拷贝）。
- **它绑什么（真正的价值）**：
  - **发言/评价的依据**——你对作品的言论，后台押着产权证明验真；
  - **游戏经历**——时长、进度、轨迹绑在你的产权上、记在你自己的主权库里；
  - **成就**——成就凭证跟着你和产权走，平台倒了生涯记录一行不丢。
- **对 Steam 的本质差异**：Steam 卖许可（可下架、可收回、平台死则库亡），Colony 账本记**产权**（公共账本在，产权就在；作品哈希寻址，永远取得回）。**"Steam 租给你玩，Colony 把游戏卖给你。"**
- **选择性披露**：证明"我拥有且玩过 X" ≠ 暴露"我拥有什么、玩过什么"——前台匿名、后台可信，持有证明必须可局部出示。
- **合规红线**：第一版产权**只可持有不可转售**（可限定赠与）；二手交易市场涉及数字资产监管，等有合规通道再上。

## §六、真人性权重公式：口碑水源的防伪机制

> **信号权重 = 真人性（KYC）× 拥有（买了吗）× 经历（真消费了吗）**

| 信号来源 | 权重 |
|---|---|
| 匿名/未验证节点 | 0——只配搬数据，不配影响口碑 |
| 手机验证账号 | 低 |
| KYC 实名账号 | 高 |
| 实名＋持有产权＋真实消费记录 | 最高——只有它进"体验画像"凝炼水源 |

刷量经济就此破产：水军成本从"开假号"变成"买真身份证＋真买一份作品＋真玩30小时"。体验画像的水源是**真人消费行为的加权凝炼**，创作者自吹与刷榜在这套公式里无处容身。

## §七、给 OS 的接缝清单（这是本文档唯一要求现在落实的部分）

生态层要靠 OS 今天预留这些（都已列入 `02`）：

1. **账号→设备绑定**：账号公钥是全设备的身份锚，账号服务签发/吊销设备证书——公共账本的写入者公钥必须能被追溯到这个锚；
2. **对外发布节点**：生态层的"索引/口碑/产权账本交互"在用户侧落地为 work 里的节点，外人只能打到发布节点上；
3. **签名与哈希原语**：账本条目用的就是内核固定密码学套件（Ed25519/BLAKE3），作品本体就是 `b3://` 内容寻址——产权记录直接引用；
4. **选择性披露能力**：授权线与凭证系统要支持"局部证明"（证明拥有/玩过某作品而不暴露全量清单）——这是授权线"只减不增"派生机制的天然应用；
5. **辖区旗标**：作品/节点元数据要留出"辖区与验证等级"字段位——国内/国际区的标记与过滤都靠它。
