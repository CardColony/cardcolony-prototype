# 记忆找回与上下文凝练修复方案

2026-11-20 · 推演agent 原型

保留「会话原文 → 凝练记忆 → 锚点找回原文」的机制。记忆帮助模型定位早期决定、依据和未决问题。需要核对时，模型沿锚点逐字读取原文。常驻上下文继续使用记忆区和未凝历史，凝练与归拢在后台运行。水位推进的条件是该段历史已有可见、可追溯的记忆接替。 [凝练路线裁定](../CONDENSE_ROUTE_RULINGS.md) · [异常正文隔离方案](超长会话工具异常隔离与续接-修复方案-20261120.md)

## 二 第一批修找回原文和归拢回灌

### 1. 给 `read_memory` 接通可用的锚点索引

从 `_h_read_memory` 和注册表 schema 改起。保留 `card_id`、`from_seq`、`to_seq`、含端点的过滤语义和原权限检查。两种节点形态都从同一规则取锚点，先用 `anchor.seq`，旧条目用 `seq`，`0` 是合法块号。索引列出可由 `memory_expand` 展开的 `gist` 条目，包括已归拢或沉底的条目。日期优先使用原文时间范围，有的话再附记录日期，缺失则留空。 [工具入口](../src/api/card_tools.py#L1158) · [工具定义](../src/api/card_tools.py#L4459)

- **输入。** 新增可选 `cursor`，省略从第一页开始。按块号升序页读，单页最多 20 条。游标绑定目标卡、当前筛选条件、索引内容版本和上一页位置。数据变化时提示从第一页开始，参数或游标无效走工具的 `validation` 错误码。继续翻页需携带相同筛选条件。
- **输出。** 保留 `data.card_id`、`data.mark`、`data.entries` 和每项的 `anchor.seq`，每项附最多 200 字的 `gist` 预览、层级和可用的时间范围。新增 `has_more`、`next_cursor`，末页游标为空。工具说明给出 `read_memory` → `memory_expand` 的调用示例。
- **验收。** 在隔离库建 43 条，包含块号 `0`、旧 `seq` 形态和一个合成锚点。通过 `execute_tool` 实测分页行数为 `20 / 20 / 3`，页间锚点唯一，区间筛选含端点；每页至少抽一个锚点走展开。另测空记忆、游标串卡、翻页之间更新索引及原有权限拒绝路径。

### 2. 在 `memory_expand` 的真实回执中分页返回逐字原文

改 `memory_expand.expand` 的选块和分页实现，并接上 `_h_memory_expand`。复用原文库按卡寻址，同一套锚点解析规则在索引和展开双向可用。上线前供人核查的存档内容照原样保留。 [展开实现](../src/storage/memory_expand.py) · [工具入口](../src/api/card_tools.py#L1204) · [原文库](../src/storage/origin_store.py#L192)

1. **定范围。** 新节点按 `coveredSeqs` 去重并按 `seq` 升序读取，空洞保持为空洞。只有旧条目缺精确覆盖时，才按合法的 `seq_from`/`seq_to` 闭区间回查，或用单个真实原文锚点兜底。回执用 `coverage` 区分 `exact`、`legacy_range`、`anchor`、`unknown`。合成锚点缺少覆盖时显示范围未知。原文表缺块时报告缺失并返回找到的部分，缺块清单也分页。首批的工具入参继续围绕记忆锚点，邻块读取作为独立需求。
2. **定页。** 继续接受从 0 起的 `page`，省略取第 0 页。保留 `data.card_id`、`seq`、`found`、`revived` 和 `text`。缺省翻逐字原文，结论预览作为单独字段，调用者可指定 `section="details"` 分页查看完整结论、描述和子条目。返回 `has_more`、`next_page` 和 `revision`，续页可传上页给出的 `revision`。版本随影响分页的内容、顺序和范围变化；复活时间一类账目刷新可沿用原页。版本不匹配时提示回到第 0 页，旧调用只传 `page` 仍可请求当下页。负页码走 `validation`，页尽返回空页。两件工具以实际 `render_tool_result` 序列化后 **32 KiB** 为首轮上限，原文每页另以 6,000 字为上限，元数据也计入体积。
3. **保真和溯源。** `text` 只放本页内容，原文片段在页内只出现一份。附片段的块号、角色或发信卡、可用时间、隔离标记，以及在原文和 `text` 中的半开字符区间。排序按块号及块内偏移，超长单块可跨页读完，逐块拼接保持所有字符和换行。回执明确所带内容为历史引文。缺锚点保留 `found=false` 并带原因。存量降级、描述层回查和显式展开复活沿用现有语义，复活状态以写入结果为准。
4. **验收。** 用 `session_facade.append` 落隔离测试块。构造 `coveredSeqs=[0,2]`，其中 `0` 为超长隔离块，`1` 带唯一的范围外标记，`2` 含中文、换行及末尾空白。用注册入口逐页调用，再经 `render_tool_result` 检查实际回灌。第 0、1 页内容不同，拼接与两块存档逐字相等，范围外标记出现次数为 0，原文字段只有一份。另测旧范围、原文缺块、空页、沉底复活与权限。

### 3. 收口后台使用的展开入口

`_expand_for_fold` 调用与显式展开共用选块和分页规则，送入的是 `context_content` 及来源状态。复用凝练的原文判据与评审过滤，工具结果正文退出后台输入。沿现有每次最多 3 个锚点的上限，检查每锚点 6,000 字及整体拼装后的实际长度。归拢展开仅取材，使用复活语义留给显式工具调用。初次凝练将真实角色、发信方及可核对的宿主回执状态送入 S2a、L1、L2，保留原有 `[idx N]` 定界格式。助手正文创作的回执不生成宿主状态。 [归拢回灌](../src/storage/memory_store.py#L2079) · [三段模型输入](../src/storage/condense_two_layer.py#L497) · [原文视图](../src/storage/predicates.py#L145)

验收沿 `_maybe_fold` 路径，让模型回包先要求展开对应组内的锚点，再截获下一次 `_fold_call` 的输入。与显式工具对照，同一异常块的原始标记只在显式回执中出现，后台输入带隔离视图、来源标记并满足体积限制。验证 `card_017` 和 `card_007` 样本时用生产库的只读副本，样本缺失则用上述隔离用例证实行为，并在回报列出实录对照的缺项。

## 三 第二批修凝练结算和上下文发布

### 1. 按实际消费的连续前缀结算

从 `_condense_one_batch` 到 `_run_condense_pipeline` 传递明确的结果。结果至少带状态、已提交的新水位和失败阶段。下一批以已提交的 `mark` 重新定位首个待凝块。S2a 的下标属于当前窗口，持久化水位属于原文 `seq`。保持默认每个凝练任务一批，显式提高批上限时才在任务内连批。允许随窗口销账的空块及工具块沿用现有判据。日志中的已消费量按实际前缀统计。若改变批次返回类型，逐一检查生产调用、脚本和测试，按明确状态判断成功。 [批次结算](../src/storage/memory_store.py#L1507) · [批循环](../src/storage/memory_store.py#L1812) · [S2a 定界](../src/storage/condense_two_layer.py#L305)

大块按 `context_content` 的半开字符区间切片，每片保留原 `seq`。单行也必须切到预算以内。先在批内追踪片段覆盖，S2a 留下的部分从剩余片段继续；一次未消费任何片就退出该批并记录失败。大块全覆盖后才映回原块号并允许提交，批内候选在这之前留在内存中，重试从旧水位重新凝该大块。提交前对比待提交范围的来源版本及旧水位，隔离视图或覆盖版本途中变化时重算，范围之后有新追加仍可提交原先已完整处理的前缀。

把格式失败、截断及提交失败接到 `condense_turn_end` 的失败账。保留阶段、已提交的水位和现行退避时间。前批有效提交可以保留，当前未成功批次从失败位置续跑。到期重试成功后才清账。原有 L2 解析失败可仅提交 L1 的规则继续按当前契约验收。 [失败账](../src/storage/memory_store.py#L2885)

| 隔离复现 | 必须实测的结果 |
| --- | --- |
| 原文 `0..5` 共六块，首窗装三块。第一批 S2a 回 `{"groups":[{"end":0}]}`，第二批回实际窗口的完整范围，批上限为 2。 | 第二批首块是 `1`。提交后 `mark=4`，连续覆盖 `0..3`，原文 `4、5` 仍可见。 |
| 一块由四条可分片的长行组成。分别以原块号 `0`、`1` 测试，批上限为 1。让定界只覆盖首尾并让中段未能产生合法定界。另准备一条单行超过窗口预算。 | 中段缺失时原块仍可见，水位不越过原块。再次注入全覆盖回包后推进一块。截获的长单行分片在预算内，合并字符与可见视图相同。 |
| 连续两次返回非法 S2a 输出。另测第一批成功、第二批提交失败。 | 前例保留旧水位并记录失败与退避时间。后例保留已提交第一批，从第二批起点重试。用可控时钟越过退避期，成功提交后查账确认清除。 |

### 2. 把同一版记忆、水位和缓存板一起发布

1. **写事务。** `memory.chain` 承载事实，`memory_nodes` 承载派生索引。抽取接收同一 SQLite 连接的链和索引写入，复用 `card_db` 的 `BEGIN IMMEDIATE` 事务边界，提交链、索引、水位和缓存板变更。索引编号分配也用该连接读取旧索引。生产凝练删掉提交后再 `save_chain` 覆盖同一行的第二次写入。事务内部让任一写入失败上抛到回滚边界。旧条目只在需兼容时归一化，保留原有锚点、节点编号、指纹、来源及生命周期字段。 [现行双写](../src/storage/memory_store.py#L599) · [节点同步](../src/storage/memory_store.py#L491) · [链写口](../src/storage/memory_domain.py#L443) · [事务边界](../src/storage/card_db.py#L1408)
2. **其他写口。** 检查归拢、懒迁移、归档迁移、沉底和显式展开复活。以事务内当前链做局部生命周期更新，或比对旧链和旧水位再提交整链。遇到冲突时基于新链重算或返回待重试。进程内锁和秒级 `updated_at` 两者单独使用都无法挡住跨进程旧整链覆盖。缓存板重建也要在同一发布版本下取数和写板，避免旧水位重建结果覆盖新板。 [生命周期写口](../src/storage/memory_store.py#L951) · [板重建](../src/storage/context_board.py#L186)
3. **读快照。** 回合开场由 `build_ctx` 读取同一版本的水位、记忆节点和历史缓存板，用一条查询或同一连接上的显式 SQLite 读事务。一次普通 `read_sync` 回调含多条独立 SELECT 时仍需显式快照。板需自愈时在读事务外重建后再重读。把 `_run_message_inner` 用于读取历史的会话锚传入装配，水位、节点和板沿此锚读取。附加会话即使用同一张卡的身份，也只读取自己会话的三个来源。当前 pair 排除、历史存根和外部追加块沿用各自入口，`CONTEXT_BOARD=0` 也验证同一水位口径。 [历史寻址](../src/api/routes.py#L3896) · [回合开场](../src/api/message_runner.py#L331) · [上下文取数](../src/api/context_assembler.py#L448) · [历史渲染](../src/api/context_regions.py#L1106)

验收时在索引写和裁板处各注入一次失败，逐项比对链、索引、水位和板的冷读。模拟读完水位马上发布下一版，再完成装配，捕获的实际模型请求只能使用完整旧版或完整新版。另模拟 runner 依据旧链复活条目之前 condense 先提交新版，验证新版节点仍在且锚点稳定。附加会话、卡直聊分别落不同的唯一标记，确认预期会话的记忆及历史各自进入实际请求。存量缺索引先在副本对账，确认覆盖后用同一发布入口重建；覆盖无法证明的范围保留原文可见并记录待补窗口。

## 四 第三批定点核查存量，再优化后台

1. **先交只读清单。** 从确认隔离的块反查 `coveredSeqs`、L1/L2 及归拢父节点。`card_017/2914` 的 224,938 字符原文确曾进入三步凝练，当前隔离视图为 109 字符。先核对 `2913`、`2914` 及关联归拢条目，给出原块号、记忆锚点和支持或推翻该记忆的证据。确有污染的条目在副本定点重凝并按第二批接口验收，记录旧锚点到新解释的对应。整卡重凝脚本面向另一种作业，存量核查从只读定位开始。 [首次凝练输入](../logs/condense_call_work_073_card_017_batch1_20261120_100227_a1.json)
2. **计量先统一输入，再测实际请求。** `_context_meter`、`_truncate_window` 和送凝复用同一套原文筛选与 `context_content`。阶段请求另外测量记忆全景、分组头、来源标记和重试提示带来的总量。前台分别量记忆区、未凝历史和整次请求。以同一批历史和现行阈值做前后对照，读数明确后再判断调参。 [计量入口](../src/storage/memory_store.py#L706) · [记忆区渲染](../src/api/context_regions.py#L2387)
3. **发现候选与执行解耦。** 在独立 condense 进程内先收集到线候选，再用现有 `CONDENSE_PARALLEL` 有界调度。按等待时间分配就绪任务，同卡互斥。任务实际结束后释放名额，到线的卡按既有批限结算后可再次排队。退避卡继续留在待处理记录，扫描发现别的卡。重启后可由现有扫描和持久化失败账恢复。隔离验收设并发为 2，给慢卡和快卡都发任务、第三张卡处于退避。快卡在慢卡结束前完成，任一时刻至多两个同飞任务，退避到期后能重试。记录候选等待、阶段执行与实际水位推进。对话发送照常使用已发布快照。 [扫描与排水](../src/storage/memory_store.py#L2936)
