## 三、开关与默认值

| 开关 | 默认 | 含义 |
| --- | --- | --- |
| `TOOL_TURN_HINT` | 开 | 首轮请求紧贴用户消息注入一条随**实际端点协议**生成的短提示（原生端点讲"正文调用不执行"；wb-cli 端点讲按声明格式写正文块）；无工具轮不出 |
| `TOOL_RECEIPT_GATE` | 开 | 绑定动作回合（`op` 专用操作 / `directive` 指令唤醒）收口用 tool_events 核对；无匹配成功回执 → 交付文本追加〔系统回执〕行＋`action_not_executed` 事件。普通话术不判（系统无法凭自然语言判定口头完成声明） |

## 〇之三、返修：按明确任务触发补救（2026-11-20 上午 · 用户二次复核驱动）

用户复核三问题：①指令回合引用「已完成」/写「我没有说已发」都命中续跳条件；②专用操作
零调用但正文没用词表措辞 → 直接收口不补救；③要求发信时，成功修改无关卡也通过回执核对。

**裁定与修法（正文词表全部退役）**：

| 机制 | 返修后 |
| --- | --- |
| 续跳触发 | 只看**可信入口绑定 + 零派发**，不看正文：op 专用回合（动作=专用工具、目标=当前卡）零派发即定向补一次（无措辞也补）；**directive 通用指令零调用不续跳**（指令内容系统无法机械判别，允许零调用研判）；汇报/研判类卡间消息不绑定。本轮已派发过任何调用 ⇒ 不补（防重复写入/发信）。 |
| 回执核对 | 按**动作+目标**匹配本轮真实回执：op 要求专用工具成功；directive 要求发信类动作（SEND_TOOLS）且**目标=发令卡**（source.from，direct 机制级收口=report_up 汇报发令方）——无关写入（edit_card 别的卡）或目标不符（direct 发第三方）都满足不了任务核对，原任务如实标未完成。 |
| 待确认查证 | send 摘要 ok 但 msg_id 缺锚 ⇒「结果待核实」；delivered=false ⇒「已写入，投递未确认（msg_id …）」——msg_id 即原记录锚（append_card_message 成功才有），不判未完成、不重发。 |
| 词表 | DONE_WORDS/claims_completion 退役删除；tool_receipt.py 与 message_runner.py 零引用。 |
