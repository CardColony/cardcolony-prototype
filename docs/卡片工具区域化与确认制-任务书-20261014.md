## 一、用户裁定条目（不可改，违反即作废）

1. `read_card`：先给区域清单，按需读指定区域；不可读其他卡的 shadow（本就不返回，保持）。
2. `read_shadow`：先给节清单，按需读指定节；**只能读本卡**的 shadow。
3. `create_card`：建子卡**弹窗给用户确认**；工具描述写清楚「只有用户要求建子卡，才能建子卡」。
4. `delete_card`：只能操作自己的子卡；**弹窗给用户确认**。
5. `update_shadow` 改名 `edit_shadow`：一次只编辑一个节，按 shadow 节清单操作。
6. 技术三裁定（方案 §三）：区域清单＝单工具两态；确认制＝**同步等待**（pending_action + 10 分钟过期）；「用户要求才建」＝描述写死＋弹窗，不做读心闸。

## 二、语义（关口/权限不变，只改形态）

- 五件工具的权限开关与关口**全部不变**：read_card/read_shadow 走 `SWITCH_READ`、create_card 走 `SWITCH_CREATE_CHILD`（树作用域不变）、delete_card 走 `SWITCH_DELETE`（根卡护栏+树作用域不变）、edit_shadow 走 `SWITCH_SHADOW_WRITE`。
- `permissions.json` / `policy.py` **零改动**。
- 不碰 toolfold 分支。

## 三、块 1 · 读侧区域化（read_card / read_shadow）

> 基线订正（2026-10-14 19:06）：正卡正文＝**三块**（duty 已按用户 17:56 令整体取消、列已 DROP）。本块无「duty 透出」事项。

### 任务

**1. `read_card` 改两态**（schema + handler）：
- schema：增可选参数 `region`，enum `["mission", "status", "third"]`，description 注明「第三块对外名随树类：研发树＝需求文档、其余＝定论」。
- 缺省（不带 region）：返回 `card_id/title/parent/relations` + `regions` 清单：`[{region, name(对外名), desc(一句话), chars}]` **三项**——name/desc 取固定文案（与库列一一对应：使命＝要做什么做成什么／现状＝当前确定的状态与结论／第三块＝需求文档或定论），`chars` 为该块字数。
- 带 region：只返回 `{card_id, region, name, content}`。
- region 非法值 → `err("validation", ...)`。区域常量从**一处**定义（禁止 schema 与 handler 各写一份清单）。
- 删掉现返回体里的冗余键（`body`/`使命`/`现状`/第三块名四键并存形态退役）；history 不给（裁定 3 沿革）。

**2. `read_shadow` 改两态 + 收窄**（schema + handler）：
- schema：**删 `card_id` 参数**；增可选 `section`，enum `["progress", "coordination", "artifacts", "iterations"]`。
- 缺省返回本卡 `sections` 清单：`[{section, name(进度/待协作事项/产物清单/迭代历史), desc, chars}]`。desc 按各节职责中性描述（「进度」节职责悬案未定，按现状写「推进时间线」并在 description 不加断言）。
- 带 section 只返回 `{card_id, section, name, content}`；非法值 → validation。
- handler：删掉 card_id/target_id 分支与跨卡 `policy.check`，目标恒为 `current_id`（收窄在签名层焊死，同 update_shadow 先例）。

**3. shadow_store 增按节读原语**：`read_shadow_sections(work_id, owner_card_id) -> dict[列名, str]`（直接查库四列，非从 raw 渲染文本拆——取什么查什么，不引入第二份真值）。

### 硬判据

1. `read_card` 缺省返回 **3 项** regions 清单、每项含 chars；`region=mission` 只回使命块；`region=third` 回第三块（rd 树对外名＝需求文档）；`region=xyz` → validation；`region=duty` → validation（duty 已取消，非合法值）。
2. read_card 返回体无 `body` 冗余键、无 history 键。
3. `read_shadow` schema 断言无 `card_id`；缺省回 4 项清单；`section=artifacts` 只回产物清单。
4. 上级卡调 `read_shadow` 传 card_id（旧形态）→ 参数被忽略/schema 层就无此参数（以新 schema 断言为准）。
5. `pytest -q MOCK_LLM=1` 零回退。

**交付**：card_tools.py（两件 schema/handler）+ shadow_store.py（read_shadow_sections）+ 测试。

## 五、块 3 · pending_action 确认制（后端）+ create/delete 接线

### 任务

**1. pending 机制**（新模块 `src/api/pending_action.py`，进程内态）：
- `PendingAction{id, work_id, card_id, kind(create_card/delete_card), payload, created_at, event: asyncio.Event, result}`；进程内表 keyed by id（uuid4 前 8 位）。
- `await wait(action, timeout=600)`：挂起等 `event`；用户确认 → 执行回调 → 拿真实结果；拒绝 → 「用户已拒绝，未执行」；超时 → 「确认超时（10 分钟），未执行」。
- **同目标去重**：同卡同 kind 且 payload 相同（create 比对 title+parent、delete 比对 card_id）已有 pending → 复用同一 pending，不重复弹窗。
- 服务重启丢 pending＝可接受（回合中断，工具调用层按异常/超时兜底），注释写明。

**2. 事件流登记**：`event_stream.EVENT_TYPES` 增 `pending_action`（发起）与 `pending_resolved`（终态，data 带 outcome: confirmed/rejected/timeout）。**注意**：事件本体论数量有测试钉着（test_flowlane vt4 等）——同步数量断言，逐条列出改了哪个测试。

**3. 两端点**（routes.py，形态对齐既有 cards 端点）：
- `POST /works/{work_id}/cards/{card_id}/pending/{action_id}/confirm` → 置 event，返回执行结果。
- `POST .../reject` → 置 event，返回 `{ok: true, outcome: "rejected"}`。
- action_id 不存在/已终态 → 404/409 语义（自定，写回报）。

**4. create_card 接线**：关口照旧全过（存在性/CREATE_CHILD/树作用域）→ **不建卡**，落 pending（payload＝title/parent/content）→ emit pending_action → 挂起 → 确认后走 `card_store.create_card` 原路径（回执卡号形态不变）→ 拒绝/超时返回文案信封（非 error 码）。
**5. delete_card 接线**：根卡护栏 + DELETE 关口 + 树作用域照旧全过 → 不删，落 pending（payload＝card_id＋**卡标题**——弹窗要显示）→ 挂起 → 确认后走原路径。结构性护栏（带子卡拒删）在**确认执行时**由存储层照常兜底。

### 硬判据

1. 调 `create_card` 后立即查库：**卡行不存在**；confirm 后存在且回执 card_id；reject 后不存在且工具返回含「拒绝」。
2. delete 三态同上；根卡/越权在关口层即拒、**不产生 pending**（事件流无 pending_action）。
3. 同卡同 payload 二连调 → 只一个 pending、一次弹窗事件。
4. 事件流有 pending_action/pending_resolved 各至少一条（发起+终态），outcome 三值可复现（单测用短 timeout 覆盖 timeout 态）。
5. 确认执行走的是 card_store 原路径（回执键集与旧版一致）。
6. 零回退。

**交付**：pending_action.py（新）+ event_stream.py + routes.py + card_tools.py（两件接线）+ 测试。
