## 2. 方法与可复现性

### 2.1 静态穷举
遍历 `src/` 全部 99 个 `.py` + `main.py`，抽取每条 `Import` / `ImportFrom`，并按**作用域**分两类：
- 模块级（含 class 体、`if`/`try` 内）＝ **导入期执行**；
- 函数体内 ＝ **调用时才执行**（条件加载）。

相对导入按 `level + 包路径` 解析；`from pkg import a, b` 同时解析「子模块」与「属性」两种可能；**包 `__init__` 作为隐式边补入**（导入子模块必然执行父包 `__init__`）。产物：6710 条边，其中打向仓内模块的 1262 条。

### 2.2 为什么在本仓，静态穷举等价于运行时
以下全部经实测（精确正则，排除 `.worktrees/`、`node_modules/`）：

| 手法 | 命中数 | 位置 |
|---|---|---|
| `importlib.import_module(...)` | **0** | — |
| `__import__(...)` | 1，且是 `__import__("logging")` | `src/storage/model_override.py:33` |
| `exec(` / `eval(` | **0 / 0** | — |
| `pkgutil` / `walk_packages` / `entry_points` / `pluggy` / `stevedore` | **0** | — |
| `TYPE_CHECKING` 分支 | **0** | — |

⇒ 本仓不存在「按字符串 / 插件目录 / 类型检查分支」的隐式加载，静态图就是完整图。

### 2.3 运行时交叉验证（不碰主仓、不启动服务）
把 `src/` 与 `config/` 复制到临时目录，在子进程里用 `sys.addaudithook` 监听 `import` 事件，**只导入 `main.py` 在导入期导入的那三个根**（`src.api.routes` / `src.api.settings_api` / `src.api.asset_cache`），**不执行** `main.py` 的 `startup_init()`（避免写 `.server.pid`、git 初始化、孤儿板清扫）。

结果：
- 真实加载 **87** 个 `src` 模块名 = 静态 **86** + 命名空间包 `src.goal`（该目录无 `__init__.py`）；
- 只出现在静态 / 只出现在运行时的模块：**均为空**；
- 三个根全部导入成功，**0 异常**；
- 顺带拿到每条真实 import 事件的**发起模块与行号**——第 3 节表格「首次拉起它的位置」列是实测值，不是推定。

## 10. 复现方式（两条，均不改主仓）

1. **静态**：AST 遍历 `src/**/*.py` + `main.py`，按「模块级 / 函数体」分作用域，解析相对导入与包 `__init__` 隐式边，从 `main` 做 BFS —— 只走导入期边得 A 类；再放开函数体边得 B 类；余下为 C 类。
2. **运行时**：`shutil` 把 `src/` `config/` 复制到临时目录 → 子进程 `sys.path` 指向副本 → `sys.addaudithook` 记 `import` 事件（用 `sys._getframe` 回溯发起模块与行号）→ 只 `__import__` 那三个根 → 汇总 `sys.modules` 里的 `src*`。全程不导入 `main.py`，故不触发 `startup_init()` 的任何写入。
