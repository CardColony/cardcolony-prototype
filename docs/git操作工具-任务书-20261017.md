## 二、工具定义（2 件）

### 1. `git_exec(command, repo?)` —— git 通用执行

- schema：`command` 必填（git 子命令串，如 `checkout -b feature-x`、`clone <url> <dir>`、`log --oneline -5`）；`repo` 可选（仓库路径，缺省＝项目根）。
- handler：复用找回批的 `_run_subprocess` 执行器，三处定制——
  - **cwd＝repo 参数**（不钉死项目根，clone 到任意 `D:\AI_station` 内路径）；
  - **超时 600s**（git 语义：clone/fetch 慢是正常的，120s 会误杀）；
  - 非零退出码＝正常返回（git 的「nothing to commit」也是非零），输出截断同 bash（50KB）。
- description 写明：「git 命令的退出码语义按 git 本身理解，非零不一定是错误」。
- `readonly=False`，`switch=SWITCH_TOOLS_FILE`（跟 bash 同开关，权限线零改）。

### 2. `git_status(repo?)` —— 状态速览

- 只读便捷件：一次返回 `branch / ahead-behind / staged / dirty 文件数`（解析 `git status --porcelain=v1 -b`）。
- `readonly=True`，`switch=SWITCH_TOOLS_FILE`。
- 动机：模型高频要「先看状态再动」， porcelain 解析交给代码比让模型读原文省 token 且不出错。
