## 一、背景（为什么做）

权限机制现状 13 个问题点（根子四个：权限表散在代码里、每次现查是 bug 来源、类型还能被改、口径不一）。本次把"按卡片类型分配权限"重做成干净底座。

## 二、用户裁定条目（不可改，违反即作废）

1. 权限 = 按卡片类型分配，两级定位 = `project_class`（工牌）+ `card_type`（类型）。
2. **类型不可变**：建卡定死，`update_card` 改 card_type / project_class 一律拒绝。
3. **可配置**：加类型 = 改权限配置文件，代码零改动。
4. **权限固化 + 版本刷新**：建卡时算一次写进卡的 `perms`，运行时照读；配置带 `version`，改配置 version+1，跑刷新脚本更新旧卡（权限会随迭代变）。
5. **默认关门**：配置里没配到的类型 = 空权限（全拒）。
6. **开关可扩展**：开关词汇表在代码里定义成常量集合，配置里组合；加开关 = 代码加一个常量 + 配置用起来，改配置即可增删。
7. **未来方向**：卡片只读 + 建卡预置内容（`edit` 会收走），本次 `edit` 先保留、底座留余地。

## 三、权限语义（保持不变，只做实现）

- 每张卡一组权限开关（读它、改它、删它、建子卡、连线、解线）。
- 调工具（搜索/文件/联网/写影子）时，查**当前卡**的开关。
- 树作用域（防越界）：卡片操作在权限通过后，额外判断"操作者是否在目标上游"，独立函数，不再用权限开关表达。

## 六、分块（3 笔，逻辑内聚）

### 块 1 · 底账：配置 + 权限核心

**任务**：
- 新建 `config/permissions.json`：`version=1` + 两级权限表（值见方案 §二.2）。
- `policy.py` 重写：删 `POLICY` 表与 `Perm(Flag)` 位图；新增读配置函数 + `has_perm(card_meta, switch)` + 独立树作用域函数；开关词汇表常量集合。

**硬判据**：
1. `policy.py` 无 `POLICY` dict、无 `Perm(Flag)`（grep 可验）。
2. `has_perm` 能查开关，未配置类型返回 False（默认关门）。

4. 读配置能从 permissions.json 正确取到权限（根卡 `permissions[project_class]["project"]`、子卡 `permissions[project_class][card_type]`）。

**交付**：permissions.json + policy.py。

### 块 2 · 固化：类型不可变 + 建卡算 perms

**任务**：
- `card_store.py` `create_card`（L716）：建卡时查配置，算出 `perms` 写进 meta，同时写 `perms_version`。
- `card_store.py` `update_card`（L921）：updates 带 `card_type` 或 `project_class` → 返回 `{"error": ...}`（拒绝）。
- `card_store.py` 落盘循环（L1008-1022）：加 `perms`、`perms_version` 两键。
- 新建 `scripts/refresh_perms.py`：读每张卡的 card_type/project_class，查配置，算 perms+perms_version 写回（对存量卡 = 第一次刷新，幂等）。

**硬判据**：
1. `create_card` 后卡 meta 含 `perms` + `perms_version`，值 = 配置。
2. `update_card` 传 card_type/project_class → 返回 error，卡面零改动。
3. 落盘循环含两字段，建卡/刷新后卡面 front matter 有 `perms`、`perms_version` 行。
4. `refresh_perms.py` 幂等可跑，跑后 88 张卡均有 perms、perms_version=1。

**交付**：card_store.py + scripts/refresh_perms.py。
