### 1b. 并发回归：反例⑥（用户报的空页 bug）✅
**根因确认**（`_scan_state` 索引初始化分支）：`index_dropped=True` 时 `want_index`
调用走 delta 分支的 `elif want_index: index = []`——**空列表被扫描循环当索引用**，
只收集**新增行** ⇒ 返回增量片段 ⇒ 翻页锚（旧历史）不在片段内 ⇒ **历史页返回空页**
（用户实测：5 条历史页返回空）。
**修法**：弃用期间 delta 一律 `index = None`（**始终走完整回退**）。

- **复跑**：`PYTHONPATH=tests python -m pytest tests/test_event_log_incremental.py::test_fx6_paging_between_scans_no_empty_page -q`
- **预期**：索引弃用后，追加发生在翻页两次扫描之间（timeline 先 spans-only 扫描、
  再 want_index 扫描），历史页（`before=31 tail=5`）返回正确的 5 条且弃用状态保持。
- **实际**：**PASS**——`page` 与参考实现逐条一致；`index_dropped` 保持 True
  （want_index 不触发重建）。
- 证据：pytest 输出；`event_log.py` 索引初始化分支的「弃用期间始终回退」注释段。

回归：`tests/test_event_log_incremental.py` **15 passed**（反例①-⑥ + 语义网）。

## 2. 计时：卡片主链路接齐 ✅

**根因**：四段采集全在 `gateway._call_once`（gateway.call 路径），而卡片实际链路是
`model_service.call_main → gateway.stream_call → _stream_once`——**独立路径无采集**
⇒ 四项全空。另：gateway 里的 `json.dumps(options)` 是**测量专用、结果丢弃**的探针，
适配器随后才编码真正发出的请求。

**修法**：
1. **`_stream_once` 接齐四段**（与 `_call_once` 同口径）：
   - `serialize_ms`＝`_build_options` 计时（构建请求选项）；
   - `first_content_ms`＝首个非空 `text-delta` 帧（**同一台账基准**，见下）；
   - `first_chunk_ms`＝`_obs.first_chunk_ms(trace)`（端点首事件，既有台账）；
   - `log_model_call` 补全部字段（成功 attempt 读数）。
2. **实际发送编码采样移到适配器真实编码点**：`llm_openai_compat/adapter.py` 的
   `payload = json.dumps(body, ensure_ascii=False)`（真正发出的编码）处计时，经新
   **`SerializeTimingChunk`**（types.py，type="serialize-timing"）回传网关——
   `_stream_once` 消费时入账 `json_dumps_ms` 并**不透传**给消费者（对上层不可见、
   不计入端点首事件台账）。删除 gateway 里丢弃式的测量探针。
3. **同一次尝试时间基准统一**：`observe` 新增 `call_content_chunk(trace_id)` /
   `content_chunk_ms(trace_id)`——正文首帧与首事件帧记**同一台账**（call_begin 时刻）
   ⇒ `first_chunk_ms ≤ first_content_ms` 恒成立、可直接互比。修复前两者基准差
   `_build_options` 耗时（实测 first_chunk 114.9 > first_content 110.0 的倒挂即此）。
