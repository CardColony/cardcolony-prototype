## 0. 一句话

**自主建线 ≠ 协作发生。** 协作出没出现，看的是**结论有没有回流、双方状态有没有对齐**，而不是看有没有出现过线。

## 2. 判据（从上面那些事实里逼出来的）

### L0 — 涌现的最低形态：**无中心指派下自主建线**

- **可判定**：事件流里出现 `link_cards` / `link_rel` 的 `tool_call`，且**不是** CEO 或任何卡片指令要求的；对方也不在发件卡的子树内（否则是纵向汇报，不是横向协作）。
- **第二轮达标**（card_016 于 21:23:43 建两条线）。

### L1 — 有效协作（**这才是本使命真正要的那条**）

在 L0 之上再加三条**全部**满足：

1. **有内容**：线不是空挂的，`note` 或首条消息写清了「我为什么需要你」的具体交界（不是"我们可能有关系"这种）。
2. **有回流**：收方**实际回了**，且回的是实质内容（判定/证据/修法），不是「收到」。
3. **状态对齐**：协作完成后，**双方对同一件事的认知一致**——A 的裁决写进了 B 的现状，或 B 的判定被 A 引用并改了结论。**任何一方仍写着与对方相反的结论，就不算完成。**

- **第二轮：L0 达标，L1 未达标。** 唯一有回流的一段（016 指认 snapshot restore → 015 判为真坏、单列病4b、给两条实测修法）**符合 1、2**；但同时存在「016 说须上层裁定 / 014 说已裁定」的**认知相反**，且 015 的素材与 014 的产出**重复劳动**。⇒ 达标的是 form，未达标的是 **closure**。

### L2 — 明确不算涌现（记录在案，防止把设计内的行为算成涌现）

| 行为 | 为什么不算 |
|---|---|
| 按卡面明文要求做的事 | 那是执行，不是自发。观察员 21:26 判 silent 的理由就是这个（"016 自跑整套、读 authority.py 都是它自己卡面要求的"）——**它守住了这条** |
| 经父卡中转的消息 | 那是 centered 协作（D05），纵向汇报不是 peer 协作 |
| 「想过要联系」但只写进自己的交付 | card_015 就是这型：看清了接缝，但把依赖**告给了 CEO** 而不是对方 |
| 读别的卡留下的产物 | 读侧全项目可读，不算接触；除非有引用并据此改了自己的结论 |

## 3. 这份判据怎么被证伪

它必须能被下一轮推翻，否则就是图纸不是化石。**下一轮若出现下列任一，本文就得改**：

1. **有 L0 无 L1 却结果更好**：某轮出现了自主建线，但协作质量反而不如没有线的轮次 ⇒ 「线」不是协作的必要条件。
2. **有 L1 无 L0**：两卡从没建线，却通过读对方产物＋改自己结论达成了状态对齐 ⇒ 「建线」不是有效协作的必要条件（很可能的，因为读侧本来就全通）。
3. **任务不需要也照样建线**：在「各交各的」设计下仍有卡自主建线 ⇒ 触发条件不是「共同交付物只有一份」，是别的东西。
4. **建线但全是噪声**：建了线，消息内容是寒暄/重复/无实质 ⇒ L0 太松，得加"有内容"门槛到 L0。

## 4. 它不 claim 什么（如实）

- **不 claim「数量够了就涌现」**。两轮各 3 个节点，样本很小；第二轮是 1 次成功建线，不是统计显著。
- **不 claim 判据完备**。L1 的「状态对齐」是这一轮才想到的，下一轮很可能发现还有第三种缺口。
- **不 claim 换了任务类型还成立**。两轮都是「域判定」型任务（分析＋出结论），没测过「建造」型任务。
- **不 claim 与模型无关**。本轮节点钉 `ds-v41-flash-aliyun`；换模型可能表现完全不同（card_004 的记法是「不说配额耗尽，说某个单模型额度」）。

## 5. 下一轮该测什么（按优先级）

1. **专测 closure**：设计一份必须**互相签署**的交付物（每个域的一节要另一个域签字才生效），看状态对齐能不能被结构逼出来。这是 L1 的直接测试。
2. **测「不建线也能协作」**：故意把建线机制关掉（或在纯读侧全通的环境里），看它们会不会靠读别人产物达成对齐——这条能证伪 L0 的必要性。
3. **测节点数上限**：3 → 5 个节点，看观测质量会不会先烂（用户原本的猜测是「再多观测先烂」）。

## 7. 铁律（观测本身的方法论，比判据更容易被忘）

1. **观测必须走完才能下判据。** D16 记「0 次发信」在当时准确，但作为结论不成立——40 分钟后它们自己建线了。
2. **判据锚结构事实，禁关键词探针。** 判「B 有没有回信」不能靠"现状块里有没有 `msg_answer` 这三个字"（中文写作会误报，实测 2/3 误报）；要锚 msg_id、`ok` 字段、HTTP 码、集合成员。
3. **单测通过 ≠ 保护生效。** 凭证值闸的 11 条用例全绿，但真实目录布局下脱敏 0 处——用例把 BASE_DIR 清干净了，测的是机制不是覆盖。**新尺子必须在旧代码上失败，才算尺子。**
4. **注释不是实现。** 把「两卡同一棵任务树内」当实现，实跑兄弟 0/3。
5. **共用 worktree 里的单次失败不必然是回归。** 实测：撞上别人写到一半，报 `TypeError`；30 秒后复跑即绿。
