## 0. 目标与范围

【用户】做一次**实验**：把系统**完全放权给模型**（沙箱里），跑复杂任务，看它会不会犯错、
会不会越权，再据此收窄。自动模式＝让**一张卡（及其子树）完全自主把任务做完**的开关。

**做**：

1. 卡上一个 `auto_mode` 开关（任何卡、随时可切）。
2. 开关打开 ⇒ 该卡权限**字面全开**（模型可操作所有功能）。
3. 它建的子卡**自动继承**（递归）。
4. **轮次驱动器**：卡一轮跑完 → 目标没完成 → **自动再起一轮**，直到模型显式声明完成。
5. 手动停止（能真打断循环）。

**不做**：见 §9。

## 3. 落地设计

### 3.1 数据形态（cards 表新增四列）

走既有幂等列升级通道（`card_db._SCHEMA` ＋ `_COLUMN_UPGRADES`，照位置列/lifecycle 先例）：

| 列 | 类型 | 值 | 说明 |
|---|---|---|---|
| `auto_mode` | INTEGER DEFAULT 0 | 0/1 | 是否自动模式 |
| `goal` | TEXT | 目标文本 | 卡当前的目标 |
| `goal_state` | TEXT | `active`｜`paused`｜`blocked`｜`complete` | 目标推进态（照 dsh 四态） |
| `goal_rounds` | INTEGER DEFAULT 0 | 计数 | **只做可见性**（「跑到第几轮」）——**不参与任何判定，不构成闸** |

【起草】**目标态与卡的生命周期态是两个东西**：卡的 `state`（active→completed）说的是「这张卡活着没」；
`goal_state` 说的是「这个任务推进到哪」。混在一起会让「卡完成」与「目标完成」互相纠缠，故分开。

### 3.2 权限「全开」怎么落

- `policy` 加常量 `AUTO_SWITCHES = SWITCHES`（全部 16 码）。
- `policy` 加一个入口：算 auto 卡的 `(perms, perms_version)`。**`perms_version` 用一个专用值**
  （建议 `-1`，与配置版本空间隔离，一眼可辨「这张卡不是按类型分的权」）。
- **开关打开时**：把该卡 `perms` 重算为全开集。
- **子卡建卡继承**：`card_store.create_card` 里若父卡 `auto_mode=1` ⇒ 子卡 `auto_mode=1` ＋ 全开 perms。
- **不动 `permissions.json` 任何现有行**——自动模式不是「按类型分权」的一种，是**绕过**它。

★ **必改点（否则功能会被静默冲掉）**：`scripts/refresh_perms.py:61 refresh_one_work`
**必须跳过 `auto_mode=1` 的卡**。否则任何人跑一次刷新，就会把 auto 卡的全开权限
按配置重写回类型分权集——**权限会无声消失**。

### 3.3 轮次驱动器（新模块 `src/api/auto_driver.py`）

【业界】dsh 的做法：`goal-round-driver` 在 agent 空闲 + 目标 `active` 时自动起下一轮；
「停」由模型显式声明；异常结果一律不自动重试。

【起草】本系统的驱动器：

**接线点**：`routes._run_message`（`src/api/routes.py:1181`）。现有结构是
`try: return await _run_message_inner(...) finally: 释放互斥体`——**驱动检查必须排在
互斥体释放之后**（否则下一轮 `turn_try_acquire` 直接 409，驱动器等于空转）。
故此处需把结构改为「先取结果 → finally 释放 → 再调驱动器 → 返回」。

**规则**（全部读卡上字段，不猜）：

```
after_turn(work_id, card_id):
    meta = card_store._meta_of(work_id, card_id)
    if not meta.auto_mode:            return      # 非自动模式
    if meta.goal_state != "active":   return      # 已停/已完成/已卡住
    if not meta.goal:                 return      # 没有目标
    if 有未终止的子卡:                 return      # ★ 父卡让位（见 §3.8）
    → goal_rounds += 1
    → 起下一轮：_run_message(work_id, card_id, 目标提示文, append_user=False)
```

- 起轮手法**复用现有卡间调起**（`message_runner._spawn_tracked` ＋ `append_user=False`）——
  激励文只走当轮 user_prompt，**不落档案**（沿用「假人声混进档案」禁区口径）。
- **防重入**由既有回合互斥体保证（同卡同时只有一个在途回合）。
- **不设上限**（U5）。

**「停」的权威在模型**：模型必须显式声明完成/暂停/卡住（D3 工具），否则驱动器一直起下一轮。

### 3.4 目标从哪来 / 起跑（D2）

| 来源 | 触发 |
|---|---|
| 建卡时给（父卡派活） | `create_card` 加 `goal` 参数；建成后若 `auto_mode` 且有 goal ⇒ **起跑** |
| 你在 auto 卡上发第一条消息 | 该消息成为 `goal`、`goal_state=active` ⇒ **起跑** |

【起草】已有目标且 `active` 时，你再发消息 ⇒ **消息正常进对话（可中途引导），目标不变**。
（否则「中途纠偏」会被当成「换任务」。）

### 3.7 手动停止（U6 / D5）

【系统】现有停止**只停当前这一轮**（`control.py` consume-once）。

【起草】自动模式下的停止必须**同时做三件**（缺一即失效）：

1. **停当前这一轮**（现有 `request_stop`）。
2. **关掉自动继续**——`goal_state → paused`（否则驱动器立刻又起一轮）。
3. **级联停它的自动子卡**——否则按了停，子卡还在后台转。

前端**复用 `#runBtn`**（`workspace.js:1355`），不新增按钮；语义按「该卡是否 auto」分叉。

### 3.8 执行模式：串行 / 并行（用户 18:47 新增，U8/U9）

【用户】
> 「串行模式：因为我想用我的本地算力机跑测试，本地机器跑不了并行任务，所以你需要让整个自动模式能串行跑，
> 也就是它建多张子卡，子卡的任务不能同时自动开启，这样会卡死的，所以需要一个排队机制，
> 一张子卡的全部任务都完成，再下一个子卡。」
> 「当然，也需要并行模式，我额度足够的话，就不限制，让它肆意跑就行。」

【系统】现状：回合互斥体是**每卡一把**（`session_facade._active_turns[(work_id, card_id)]`，`:854`），
**不同卡可并行**；且拒绝时**不排队**（直接 409）。

【起草】两种模式，一个开关切换：

| 模式 | 语义 |
|---|---|
| **并行** | 不加限制，各卡各跑（＝今天的行为） |
| **串行** | **同一 work 内，同一时刻只有一个卡在跑**；其余排队 |

【起草】串行三要素：

1. **执行闸**：串行模式下，起一个回合前必须先拿到**每 work 一把的执行锁**；
   拿不到 ⇒ **排队等待**（**不是** 409 拒绝）——这是与今天行为的关键差别。
2. **排队单位＝卡**：一张卡从「起跑」到「目标终止（complete / blocked / paused）」全程**独占**执行锁；
   它跑完，才轮到下一张 ⇒ 满足「一张子卡的全部任务都完成，再下一个子卡」。
3. **父卡让位**（两种模式都适用，串行下更关键）：**父卡若有子卡目标未终止 ⇒ 父卡不起轮**。
   否则父卡的驱动器会在子卡还在跑时不停给自己起轮（空转、烧额度）。子卡全部终止 ⇒ 父卡重新可跑。
   —— 这不是闸，是「派活 → 等回报」的必然：父卡把活派出去后就该等，而不是自己接着转。

【起草】顺序：**深度优先**——一张子卡连同它自己的子卡全部跑完，再轮到下一张兄弟卡。

【起草】模式开关落点＝**全局配置**（新增 `config/` 条目）。
理由：串行的动机是「本机跑不了并行」，是**机器级**的，不是某张卡/某棵树的性质。

## 7. 验收标准

1. **自主跑**：一张 auto 卡领到任务后，**无人干预下连续跑多轮**，直到自己声明完成。
2. **子卡继承**：它建的子卡也是 auto，且**自动起跑**、干完回报父卡。
3. **停得住**：按停止 ⇒ **不再起新轮**，且**子卡也停**。
4. **可复原**：全过程可从 `logs/` 与 `cards/{cid}/timeline` 复原——每一步调了什么工具、
   有没有越权、有没有犯错（**这是后续「收窄」的依据**）。
5. **权限真的全开**：auto 卡的工具面＝全量（可断言 `build_tool_schemas` 输出件数）。
6. **回归**：非 auto 卡的工具面与行为**逐字不变**；全量 pytest 失败集与基线逐条同。
7. **不设闸**：全链无轮次/墙钟/token 上限（可 grep 断言）。
8. **串行真串**：串行模式下建 N 张子卡 ⇒ **同一时刻只有一个在跑**（任一时刻执行锁只被一张卡持有）；
   一张子卡目标终止后才轮到下一张。
9. **并行真并**：并行模式下 N 张子卡可同时跑（无执行锁限制）。
10. **父卡让位**：子卡未终止期间父卡**不起新轮**；子卡全部终止后父卡恢复。

## 8. 风险与边界

- **无闸 ⇒ 可能跑飞**（【用户】已知并接受）。兜底＝沙箱/纯净分支 ＋ 手动停止；**不设机制闸**。
- **`refresh_perms` 冲掉全开权限**（§3.2 必改点）——漏改则功能静默失效。
- **并发施工**（最高风险）：工作区多条线在改、行号实测漂移 ⇒ 阶段 0 闸门不放行不开工。
- **真实库列升级**：须先备份；走幂等通道，反复跑不出错。
- **驱动器 × 既有卡间调起**：两者都在收口触发，须确认**不互相顶掉**（同一互斥体、同卡单回合）。
- **串行排队死锁**（新增，U8）：执行锁的**持有期＝一张卡的整个目标生命周期** ⇒ 若某卡
  永久不终止（模型不声明完成），**队列后面全部饿死**。这是「无闸 + 串行」的固有代价，
  用户已知并接受；兜底＝手动停止（停止会释放执行锁）。
- **父卡让位判定成本**：每次起轮前要查子卡目标态，须走**已加载的卡 meta**（`_meta_of` 或
  `iter_card_metas`），**不得**逐卡开连接。
- **`BASE_PROMPT_VERSION` 升号**：影响面广，须同步守卫测试。
