## 一、目标

1. **三席思考取回展示**：三席（观点审议）的思考块像主模型一样以 think 流逐字展示——走 `/tokens` 通道、前端弱化区渲染，**不同模型的思考块形态逐家适配**
2. **拆雷①（主凶）**：`clean_viewpoint_text` 对未闭合 think 块整段作废 → 改为按开始标记切分，只丢思考区、保留正文
3. **拆雷②（次凶）**：非流式 `call` 兜底只认 `reasoning_content` 单字段 → 三席改走 `stream_call`（双路解包 `reasoning`/`reasoning_content`），绕开缺口，**gateway 一行不碰**
4. **逐家适配**：MiniMax（思考混 content 带标签）、qwen（`reasoning_content`）、glm-5.3（端点始终思考、现役唯一真实思考源）、deepseek（`reasoning_content`）——形态表驱动实现

### 步骤 2：三席切 stream_call + 思考增量转发（核心）✅
改 `src/api/simple_service.py` `_call_viewpoint`：

```python
result: dict[str, Any] = {}
splitter = ThinkStreamSplitter()
async for ev in gw.stream_call(seat, system_prompt, user_prompt,
                               temperature=..., tools=None,
                               prior_messages=prior_messages or None):
    if "chunk_type" in ev:
        text = ev.get("text") or ""
        if ev.get("chunk_type") == "reasoning":
            _emit_think(text, label)                      # 字段类思考
        elif ev.get("chunk_type") == "content":
            think_part, _body = splitter.feed(text)       # 内联类思考（正文丢弃）
            _emit_think(think_part, label)
    elif "content" in ev:
        result = ev
```

要点：
- `stream_call` 天然不做完成标记检测（等价原 `skip_completion_marker=True`，语义不变）
- **不传 max_tokens**（拆闸铁律）
- 思考增量**不计入** content（gateway.py:523），终帧 content 是纯正文
- 三席正文增量**一律不上 /tokens**（观点不是助手回复正文，绝不串进对话流）
- 终帧结构与 `call` 返回一致（content/tool_calls/latency_ms），`meta` 组装逻辑不动
- 失败重试/fallback 由 `stream_call` 内部处理（与 `call` 同款），异常仍被 `_call_viewpoint` 的 except 捕获

**产出**：三席思考经 `/tokens` 流到前端。

### 步骤 3：`clean_viewpoint_text` 未闭合处理改造（拆雷①）✅
```python
text = text or ""
for rx in _THINK_BLOCK_RES:      # 闭合块（两种标签写法）整段剥离
    text = rx.sub("", text)
idx = 最先出现的开始标记位置
if idx >= 0:
    text = text[:idx]            # 标记前正文保留、标记后思考区丢掉
clean, _proposals = parse_proposals(text)
return clean.strip()
```

**语义**：整段都是思考（开始标记在开头且无闭合）→ 仍返回空串（旧行为逐字不变，`tests/test_proposal_parse.py` 钉的就是这一条）；只要开始标记**前面有正文**，正文就留下。
