# 任务书：更新现状按钮改造（独立起草通道 → 本卡特殊回合）

> 上游：`docs/对话界面-更新现状按钮-方案-20261016.md`（方案稿）＋ `docs/对话界面-更新现状按钮-问题-20261016.md`（问题清单）。
> 背景：现「更新现状」走**独立 `/draft` 起草通道**（无工具、专用模型、点一下即弹窗）。用户 2026-10-16 定：
> 它是**本卡的一次特殊操作**，要**走主流程、用主流程模型、带卡内全部工具**；提示词**当轮注入**并**写清"现状该写什么"**；
> **只在最终提交时弹窗**做**原/新对比**。
> 状态：**任务书稿，未动任何产品文件**；第六节「待裁项」定完方可开工。

---

## 〇、目标（一句话）

把「更新现状」从独立 `/draft` 起草通道，改成**本卡的一次普通回合**（走 `message_runner` 主流程、主流程模型、卡内全部工具）：
用**当轮注入**把「现状更新任务 ＋ 当前现状」交给模型；模型调**只提议不落盘**的新工具 `propose_status(content)` 交出「新现状」；
前端据此弹**单面板行级 diff 对比窗**，用户同意后复用 `commit` 落盘。

---

## 一、现状（实证）

- **触发**：`static/workspace.js` —— `statusDraftBtn.onclick → openDraft("status") → _requestDraft → POST …/draft → submitCommit → POST …/commit`。
- **后端**：`src/api/card_draft.py` —— `draft`＝**无工具纯文本**调 `resolve("draft")`（不落盘）；`commit`＝`base_hash` 乐观锁 → `update_card` **整块替换** `status_block` → 影子记一行；`src/api/routes.py` 的 `/draft`、`/commit`。
- **注入底座**：`src/api/current_turn.py` —— 当轮注入事件族（`context_preamble` / `context_injection` / `judgment_protocol` / `context_seat_identity`），投影 **role=assistant、第一人称自述**。
- **现状的权威写法**：`src/api/context_regions.py render_card_region_guide`（**155 区**）——
  「现状＝当前确定的状态与结论；三类：**当前确定状态 / 接口与约定 / 依赖与影响范围**；写法：**整块覆盖、只保留最新一份**；只写已确定的结论；**不写过程、不写"做到哪"的流水账**」。
- **版本锚**（施工时以现值为准）：`BASE_PROMPT_VERSION = "t22-1"`、`TOOL_TABLE_VERSION = "tools-tc-7"`。
- **`propose_status` / 现状更新注入事件：当前不存在**（纯新增）。

## 二、任务清单

### T1 新增当轮注入事件（现状更新任务）

- `src/api/current_turn.py` 新增一类事件（暂名 `status_update_task`），在**本回合首次模型调用前**注入一条（沿现有注入机制，role=assistant、抬头〔现状更新〕）。
- 正文＝**现状更新指令（写清"现状写什么"三类）＋ 当前现状全文**；文本见方案 §二.2（已按 155 区口径写）。
- 注入条件：本回合带 `op="update_status"`（见 T2）。

### T2 `/messages` 认 `op` 标记 ＋ 编排轮首注入

- `POST …/messages` 请求体增可选字段 `op`；`message_runner` 识别后触发 T1 注入。
- 本轮**用户消息**＝固定触发语（可见、留痕）。
- 模型＝**主流程模型**（**不** `resolve("draft")`）；工具面＝按本卡 perms 下发（默认即主流程行为）。

### T3 新增工具 `propose_status(content)`（只提议不落盘）

- 进 `TOOL_REGISTRY`：schema（`content`＝新的现状正文）＋ handler（返回 `{proposed, old, base_hash}`，**零落盘**）＋ 只读标志。
- `TOOL_TABLE_VERSION` **递增**（tools-tc-7 → tools-tc-8）。
- 挂哪个开关、是否常驻工具面 → **待裁**（第六节 4）。

### T4 前端：按钮改走 `send(op)`

- `statusDraftBtn.onclick` 不再 `openDraft("status")`，改发起一次带 `op` 的发送。
- 对话流照常渲染（注入行可见）。

### T5 前端：回合收口扫 timeline 弹对比窗

- 收口后**扫本卡 timeline** 找 `propose_status` 的成功 `tool_result` → 开**对比窗**（**带本卡 card_id**，防串卡）——做法同规则卡审批的 `maybeOpenRuleEditModal`。
- 弹窗＝**单面板行级 diff**（原现状 vs 提议）；「同意」→ `POST …/commit`；「关闭」→ 不落盘。

### T6 起草通道收窄

- `/draft` 的 `kind="status"` 分支退役（或保留但 UI 不再调用）→ **待裁**（第六节 5）。

### T7 测试

- 新增：注入事件生成与投影；`propose_status` 只提议不落盘（`proposed/old/base_hash` 正确）；`op` 驱动的轮首注入；对比窗取数（old/proposed）；弹窗**绑卡不串**。
- 既有 `test_card_draft*` 等如有断言旧路径，随改。
