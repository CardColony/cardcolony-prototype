> 项目背景一句话：系统是一棵卡片树（每张卡一条独立对话线，结论沉淀在卡上）。本次需求是把卡与卡之间的"数据交互"从"点对点直塞"升级为"沿关系访问与通信"。

## 0. 需求总述（先看这段）

底座要补上"沿关系"的两个方向，共用同一套关系机制、同一权限关口、同一留痕账本：

1. **读**：A 卡沿一条通信线，读到 B 卡的正文／影子／对话；
2. **写**：A 卡向 B 卡发消息，消息**进入 B 模型的视野**，B 读到并回复。

铁律三条（贯穿全部施工）：
- **底座只给能力，不判资格**——资格归权限管（新增能力码，见 §3）；
- **只定机制，不定形态**——不规定卡该有哪几块、消息该有哪几型；
- **复用不重做**——现有读工具、发信门槛、调起机理、事件流留痕全部复用，只改落点与数据源。

## 2. 需求一：沿通信线读（read_via）

**要什么**：A 卡沿一条通信线（relations 边）读到 B 卡的正文／影子／对话。

**落点**：
- 新函数 `read_via(source_id, target_id, part)`：
  - 沿边寻址：校验 `source` 的 `relations` 里存在指向 `target` 的边；不存在 → 返回「无通信线」（明确错误，不静默）；
  - `part ∈ {正文, 影子, 对话}`：正文→复用 `card_store.read_card`；影子→复用 `shadow_store.read_shadow_raw`；对话→复用 `event_log.timeline`。**不重做任何读工具，只加"沿边寻址"这一步**。
- 模型工具面：注册新工具 `read_linked`（ToolDef，readonly），描述写明"沿通信线读对方卡"；`TOOL_TABLE_VERSION` 递增（项目纪律）。

## 3. 需求二：卡间通信（消息进模型视野）

**要什么**：A 发消息给 B → 消息进 B 模型的上下文视野 → B 读到并回复 → 回复落 B 的对话。

**核心改法：三件套分离**（现状把三件混在对话块里，本次拆开）：

| 件 | 是什么 | 改后 |
|---|---|---|
| 待处理收件箱 | 消息的"待处理"队列——**进模型视野的通道** | 新表 `inbox`（见 §4），显式 pending/consumed 状态 |
| 对话块 | B 自己的对话历史 | 只放 B 自己的话与回复，**新消息不再写进对话块** |
| 事件流 | 留痕账本 | 照旧（消息仍记 msg_* 事件，一字不改） |

**通信闭环五步**：
1. A 发消息 → 写 `inbox`（status=pending），六道门槛、权限、通知帧全保留；
2. 检测到 pending → 调起 B 回合（复用 `schedule_card_message_triggers`，仅数据源改变）；
3. 装配 B 上下文时，将待处理消息作为明确素材注入（模型明确看到"B 收到 A 的消息：…"；不规定装配区序，只提供素材）；
4. B 模型处理、回复 → 回复照旧落 B 对话块（assistant 块）；
5. 已处理消息 `inbox` 置 consumed（**只改状态不删行**，留痕可回溯）。

## 4. 数据与权限配套

**新表 inbox**（`src/storage/card_db.py`）：
```
msg_id TEXT PRIMARY KEY, work_id, target_card_id, from_card,
type, content, reply_to, status(pending/consumed),
seq, created_at, consumed_at
```
配套原语：`append_inbox`（投递）/ `list_pending(target)` / `mark_consumed(msg_id)`。

**两个新能力码**（`policy.py` SWITCHES 常量＋`permissions.json` version 3）：
- `read_linked` —— 沿连线读；
- `send_card_message` —— 沿关系发消息。
- 配置未授的组合默认关门（现状语义不变）。能力码的命名与"读正文/影子/对话是否细分授权"为待用户裁项，施工先用一个码打通。

## 7. 不做清单（越界即返工）

1. 不碰 parent（上下级线）；只动 relations（通信线）。
2. 不做权限申请制＋代码层事实提取（权限迭代独立推进，本次只对接能力码）。
3. 不规定上下文装配区序（只提供"待处理消息"素材，不进装配器内部）。
4. 不规定任何形态（卡块结构、影子节、消息类型——一律不定）。
5. 不重做现有读工具/发信门槛/调起机理/事件流。
