# 画布产品设计 · 从头梳理（2026-10-18）

> 起因：用户连续三次打回——"层级混在一起 / 双击才进去 / 谁还用渐变 / 你根本不验收 /
> 卡片无序摆放没有逻辑关系 / 视觉就是信息呈现 / 你根本没想清楚产品设计和理念"。
>
> 这份文档不是施工单，是**重新定义每个环节该是什么**。写完再动手。

---

## 一、这套系统到底是什么

不是"看板"，不是"白板"，不是"思维导图工具"。

**它是一个「用卡片承载长程推演」的工作台。** 一件超出单次对话容量的事，被拆成卡片；
每张卡里是一段完整的对话与实读；卡与卡之间只传**沉淀后的结论**。

三条机制决定了它的形态（读代码与真实数据得出，不是文档口径）：

1. **结论是卡片间唯一接口** —— 别的卡读这张卡，先读它的"现状/结论"块。
2. **权限由卡片树机械决定** —— 建卡时算一次写死，模型看不见没权限的工具。
3. **全量留痕可对账** —— 模型说的每句话、每个工具调用都可回溯。

## 二、用户在这个系统里做什么（用真实数据说话）

`real_work_002` 的真实状态：

| 指标 | 数值 |
|---|---|
| 卡片 | 43 张（1 根 + 42 子项目） |
| 跨时 | 10-03 → 10-08，5 天 |
| **含「待裁定」的卡** | **17 张** |
| **待裁定标记总数** | **74 处** |
| 有显式「结论：」的卡 | 3 张 |
| 现状块 3000 字以上的卡 | 多数（最大 40232 字） |

**用户唯一必须亲自做的事是「裁定」。** 模型去实读、去对码、去整理，然后标【待裁定】，
等用户点头。用户的时间全部花在：读一处提议 → 判断 → 给结论。

所以：

> **画布的第一性任务是让「哪里在等我裁定」和「这张卡想清楚了什么」一眼可见。**
> 不是"卡片好不好看"，不是"拖拽顺不顺"。

## 三、我之前的错误（逐条认）

| 我做的 | 实际是什么 | 为什么错 |
|---|---|---|
| 拖拽吸附 / 对齐参考线 | 白板功能 | 用户不摆卡片，他读卡片 |
| 框选 / 多选 / 整组拖动 | 白板功能 | 同上 |
| 小地图 | 白板功能 | 43 张卡不需要小地图，需要"待办清单" |
| ⌘K 命令面板 | 通用工具 | 该有，但不是第一优先级 |
| 单击进入（改对了） | 导航 | 对，但进去之后仍是一堆字 |
| 卡片显示"摘要" | 信息呈现错误 | 摘要取的是"状态：现状实测…依据：xxx.html(258行)"，是**记录格式**不是**内容** |
| 卡片第一行显示"子项目" | 信息呈现错误 | 42/43 张都是 sub_project，零信息量占最贵的位置 |
| 分组框 | 视觉装饰 | 表达"这是一组"，但用户要的是"这一组按什么顺序读" |
| 渐变 / 阴影 / 圆角 | 装饰 | 与信息无关 |

**一句话：我优化的是"画布工具的手感"，用户要的是"裁定工作的效率"。**

## 四、逐环节重新定义

### 环节 1：打开画布的第一眼

**现在**：一张卡片树，根卡在左、子卡在右，每张卡写着标题和一段记录格式的摘要。

**应该是**：一个**项目状态条** + **待裁定队列**。

```
┌──────────────────────────────────────────────────────────────┐
│ 项目管理agent   43 卡 · 74 处待裁定 · 3 已结论 · 2 未开始     │
│                 最近 5 天 · 最后动过：2 天前                   │
├──────────────────────────────────────────────────────────────┤
│ 等你裁定（74）                          按卡分组 ▾           │
│  ▸ UI交互（6）                                               │
│  ▸ 布局、信息视觉工程（4）                                    │
│  ▸ 影子卡机制（5）                                            │
└──────────────────────────────────────────────────────────────┘
```

用户打开就该知道：**有 74 件事等我，分布在 17 张卡上**。这是他现在完全看不到的。

### 环节 2：卡片

**现在**：标题 + 一段摘要 + 底栏（状态徽标 / 引用数 / 子卡数 / 时间）。

**应该是**：标题 + **这张卡的核心判断**（有结论就显示结论，没结论就显示"在讨论什么"）
+ **待裁定条目**（最多 2 条，可直接点进去）。

```
┌─────────────────────────────────────┐
│ UI交互                      ←7  6   │
│                                     │
│ 结论：先做布局引擎，UI 交互按事件表  │
│ 对齐，不做第二套状态机。             │
│                                     │
│ 待你裁定 6 处 ▾                      │
│  · 实时反馈该不该做（第五节）        │
│  · 端点清单是否补 /api/xxx          │
└─────────────────────────────────────┘
```

"待裁定 6 处"必须是**可展开的清单**，不是数字。用户要能直接在画布上读那 6 条。

### 环节 3：层级

**现在**：靠卡片尺寸 + 右侧位移 + 分组框。用户说"混在一起"。

**应该是**：**目录式的缩进 + 主干线**。父子关系用一条连续的主干表达，
像文件树一样从上往下读；子卡缩进一级，孙卡再缩进一级。

分组框（"一块区域"）不能替代"层级"——框只说明"这些是一组"，
不说明"谁是谁的子卡、读的顺序是什么"。

### 环节 4：卡片之间的关系

**现在**：relations / links 两列全是空的，所以画布上什么也没有。

**真实情况**：关系写在**正文**里。全库 115 条引用边，`card_002` 被 11 张卡引用
（它是地基），`card_005` 被 8 张引用，`card_006`/`card_016` 各被 7 张引用。

**应该是**：
- 卡片上标 `←11`（被 11 张卡引用）—— 一眼看出哪几张是地基
- 悬停/选中一张卡时，画出它引用了谁、谁引用了它（平时不画，115 条线会糊成一片）

### 环节 5：状态

**现在**：`state` 字段（37 张是 null，6 张 active），画布上几乎不显示。

**应该是**：从**内容**推断的工作状态，且用用户的语言：
- **等我裁定**（含【待裁定】）
- **已结论**（有显式「结论：」）
- **在讨论**（有内容无结论）
- **没开始**（现状块为空）

画布上只允许**一个颜色**喊"需要你动手"——橙色给"等我裁定"，其他一律中性。

### 环节 6：进入卡片

**现在**：单击进对话页，进去之后是一整段长文 + 聊天记录，要自己找"那处待裁定"在哪。

**应该是**：从"待裁定条目"点进去，**直接定位到那一段**（锚点到具体小节），
而不是从头读 3000 字。

### 环节 7：返回

**现在**：面包屑 / 浏览器后退。

**应该是**：返回时**保持离开时的视野与选中**，并且把刚裁定的那条从队列里划掉。

### 环节 8：导航

**现在**：左侧 44px 图标栏 + 悬停浮层树 + ⌘K 搜索。

**应该是**：左侧栏常驻显示**项目树 + 每张卡的待裁定数**，像收件箱一样。
用户不用打开画布也能知道哪里在等他。

### 环节 9：空态 / 加载态 / 错误态

**现在**：骨架屏 + 一行"这张画布还没有卡片"。

**应该是**：空态告诉用户"这个项目还没有卡片，第一步是建根卡"；
加载态不该出现（首屏数据应该秒回，本地 SQLite）。

### 环节 10：视觉本身

**用户原话："视觉他妈的就是信息呈现。"**

所以视觉规则只有四条：
1. **每一处视觉差异必须对应一个信息差异**（尺寸差 = 层级差，颜色 = 状态，位置 = 顺序）
2. **同一时刻只有一个颜色在喊"需要你动手"**
3. **不给"装饰性视觉"留预算**（渐变、阴影、圆角、图标装饰全部从简）
4. **文字按"用户读它的顺序"排**（标题 → 结论 → 待裁定 → 元信息）

## 五、改造优先级（按"对用户的价值"排，不按实现难度）

| 序 | 事项 | 为什么排这里 |
|---|---|---|
| P0 | 后端解析「待裁定条目」（每条：所在小节 + 那句话） | 没有这个，画布永远只能显示"记录格式" |
| P0 | 项目状态条（43 卡 / 74 待裁定 / 3 已结论） | 打开第一眼必须知道全貌 |
| P1 | 卡片显示「结论 + 待裁定条目」 | 用户读卡的核心内容 |
| P1 | 层级改目录式（缩进 + 主干线，去掉分组框） | 用户明确说"无序、没有逻辑关系" |
| P2 | 待裁定队列（按卡分组的清单，可点进去定位） | 把"裁定"变成可执行的工作流 |
| P2 | 悬停显示引用关系（115 条边，按需显示） | 用户说"看不出逻辑关系" |
| P3 | 从待裁定条目进入卡片并定位 | 省掉"从头读 3000 字" |
| P4 | 左栏常驻项目树 + 待裁定数 | 不打开画布也能知道哪里在等 |
| P5 | 白板功能（拖拽吸附/框选/小地图）降级或隐藏 | 它们不是这个产品的主路径 |

## 六、明确不做什么

- 不做"卡片自由摆放"（用户不摆，他读）
- 不做"多主题/浅色"（先把信息做对）
- 不做"动效炫技"（视觉预算全给信息）
- 不做"社交/分享"（这是个人推演工作台）
