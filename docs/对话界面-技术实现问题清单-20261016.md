## A. 运行中的「恢复轮询」无条件重跑整表重建 —— 打断实时渲染 ★最重

**现象/机制**
- `send()` / `resend()` 起一个 **15s** 定时器 → `tryRecover()` → **无条件**调用
  `EventFlow.resync()`（**没有任何「SSE 是否健康」的判据**）。
- `resync` 内部做三件事：`st.settled = true` ＋ `releaseText()` ＋
  `renderSnapshot()`（清空整列重建 ＋ 滚底）。

**代码依据**
- `static/workspace.js:1141-1168`（`tryRecover` / `pollTimer` 15s）
- `static/stream.js:710-721`（`resync`：置 `settled`、`releaseText`、重建）
- `static/stream.js:684-685`（`applyLiveFrame` 受 `settled` 早退）
- `static/stream.js:887-893`（`releaseText` 释放 live 正文引用）
- `static/stream.js:609-622`（`renderSnapshot` 清列重建 ＋ `scrollBottom`）

**影响（三条）**
1. 每 15s 整列重画（含历史轮组）＋ 滚底 → 闪烁/跳屏；
2. live 逐字气泡被 `releaseText` 释放、又被清列移除 → **流式正文每 15s 回退重来**；
3. 首次轮询后 `st.settled=true` → **此后 `/stream` 过程帧不再实时应用**
   （过程显示退化为「15s 一跳」）。

**命中面**：runs 常 1–8 分钟，15s 定时器几乎每轮都触发；仅短于 15s 的直答躲过。
**置信度**：高（纯代码路径可读）。
**待证**：一次长跑实测，看观感是否如推演。

## B. 事件流并存两套机制；真正生效的是「0.4s 轮询 + 全量复制」，pub/sub 那套是死码

**现象/机制**
- `event_stream` 内有一套完整 pub/sub（`subscribe` / `subscribe_tokens` / `_fanout`，
  含「队列满丢最旧帧、不静默丢」的处理）——但**全库无生产调用方**（仅测试触碰）。
- `/stream`、`/tokens` 路由实际各自 `while True` 轮询 `journal_of(...)`，
  每 **0.4s / 0.25s** 一次；`journal_of` = `list(_journals[key])` **全量复制**。

**代码依据**
- `src/api/routes.py:839-857`（`/stream` 轮询循环）
- `src/api/routes.py:883-900`（`/tokens` 轮询循环）
- `src/api/event_stream.py:248-278`（`_fanout`）
- `src/api/event_stream.py:357-359`（`journal_of` 全量复制）
- `src/api/event_stream.py:362-389`（`subscribe` 无调用方；grep 可证）

**影响**：每次轮询 O(N)，N＝该卡自**进程启动以来**的全部事件；随进程存活时间线性劣化
（每客户端、每 0.4s 一次全量拷贝）。
**置信度**：高（grep 可证）。

## C. 内存 journal 无上限（分段制 + 删环叠加）

**现象/机制**：`_journals` / `_token_journals` 只 append；`run_start` **不再清零**
（A5 分段制）；原环形上限（300 / 5000）已删 ⇒ 每卡 journal 随进程存活单调增长。

**代码依据**：`src/api/event_stream.py:131-135`、`:327-334`、`:444-458`。

**影响**：与 B 的 0.4s 全量复制叠加 → 长跑进程 CPU/内存随事件量劣化。
**置信度**：高（代码可证）；实际影响取决于部署时长与卡片活跃度。

## I. `lastSeq` 游标跨服务重启失效（低置信，窗口窄）

前端 SSE 游标 `lastSeq` 取自**内存 journal seq**；服务重启后 journal seq 归零，
若前端仍持旧游标（`from>0`），新事件会被全部过滤 → 实时过程断供至刷新。
**代码依据**：`static/stream.js:952`、`:975`；`src/api/routes.py:842`。
