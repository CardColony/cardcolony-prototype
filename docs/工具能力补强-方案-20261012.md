# 工具能力补强方案（2026-10-12 · 详细版）

## 一、目标

补全通用 agent 缺失的基础工具（第一优先 + 第二优先），让 agent 从「能读能写」到「能算能做」。共补 5 件工具：`bash`、`python`、`glob_files`（新增）、`delete_file` / `move_file` / `rename_file`（文件管理三件），并对现有 `search_files` 加正则能力。

## 二、范围声明（用户 2026-10-12 15:11 裁定）

- **只管工具本身**：实现、注册、下发、执行。
- **权限开关 / 安全边界 / 默认关门 = 权限线的活**。本方案**不碰** `src/permissions/policy.py`、`config/permissions.json`，也不设计「谁该授哪个开关」「bash 的 cwd 边界」「命令白名单/黑名单」。工具注册后，其权限开关的「接线 + 授给谁」由权限线（收拢）统一做，本方案在每件工具上只标注「归属开关」供权限线引用，不实现任何判定。
- **工具自身的健壮性**（超时、输出截断、编码兜底）属工具本身，本方案做。

## 三、共享执行器（bash / python 共用）

新建一个底层 helper（放 `src/api/card_tools.py` 内，或独立 `src/api/exec_runner.py`，以实现时是否引入 import 环为准）：

```
async def _run_subprocess(
    argv: list[str] | None = None,      # exec 模式（python 用）
    shell_cmd: str | None = None,        # shell 模式（bash 用）
    cwd: str = BASE_DIR,                 # 默认项目根
    timeout: float = 120.0,              # 秒
) -> dict
```

**行为契约（逐条）**：

1. **异步执行**：`asyncio.create_subprocess_shell`（bash，走系统 shell）或 `asyncio.create_subprocess_exec`（python，走 `sys.executable`），`stdout=stderr=PIPE`。参考 `src/storage/git_auto_commit.py` 的既有模式。
2. **超时**：`asyncio.wait_for(proc.communicate(), timeout=timeout)`，`TimeoutError` → 杀子进程（`proc.kill()`）→ 返回 `err("locked", "执行超时（>120s）")`。
3. **编码**：`stdout/stderr` 为 bytes，`decode("utf-8", errors="replace")`（与 git_auto_commit 同口径）。
4. **输出截断**：stdout、stderr 各自截断到 **50 KB**（51200 字节），超限时在末尾追加一行 `\n…（输出已截断，共 N 字节）`，并置 `truncated=True`。
5. **命令失败不是错误**：`exit_code != 0` 是**正常返回**，不是 error 信封——把 `exit_code/stdout/stderr` 原样返回，模型自己判断成败。只有「起不了子进程 / 超时」才是 error 信封。
6. **返回形态**：成功 `{"exit_code": int, "stdout": str, "stderr": str, "truncated": bool}`；异常 `err(code, message)`。

**超时与「零闸」的关系（必须写清）**：项目的「零闸」铁律针对**模型调用**（不设 max_tokens、无墙钟超时）。本执行器的超时是**代码执行的健壮性**（防子进程死循环把服务挂死），与 `git_auto_commit.py` 的 `timeout=60` 同性质，不违反零闸。

## 四、五件工具逐件定义

### 1. `bash`（终端执行）

**schema**：
```json
{
  "name": "bash",
  "description": "执行一条 shell 命令，返回标准输出、标准错误与退出码。命令失败（非零退出码）不是错误，会原样返回退出码与输出，由你判断成败。执行超时（>120 秒）会返回错误。",
  "parameters": {
    "type": "object",
    "properties": {
      "command": {"type": "string", "description": "要执行的 shell 命令（可含管道、重定向、&& 等 shell 语法）"}
    },
    "required": ["command"]
  }
}
```

**handler 要点**：
- 签名 `async def _h_bash(work_id, current_id, arguments, cards) -> dict`。
- 取 `arguments["command"]`（缺失/空 → `err("validation", "command 不能为空")`）。
- 调 `_run_subprocess(shell_cmd=command)`（shell 模式），原样透传返回值。
- `readonly=False`。

### 2. `python`（代码执行）

**schema**：
```json
{
  "name": "python",
  "description": "执行一段 Python 代码，返回标准输出、标准错误与退出码。代码在项目 venv 解释器下运行（能 import 项目已安装的库）。命令失败（非零退出码）不是错误。执行超时（>120 秒）会返回错误。",
  "parameters": {
    "type": "object",
    "properties": {
      "code": {"type": "string", "description": "要执行的 Python 代码（多行直接写，会写入临时文件后运行）"}
    },
    "required": ["code"]
  }
}
```

**handler 要点**：
- 取 `arguments["code"]`（缺失/空 → `err("validation", "code 不能为空")`）。
- **执行方式**：写入系统临时目录（`tempfile.NamedTemporaryFile(suffix=".py", delete=False)`），再 `_run_subprocess(argv=[sys.executable, tmp_path])`（exec 模式），`finally` 删除临时文件。写临时文件而非 `python -c`，规避 Windows 命令行多行字符串的引号/换行转义坑。
- `sys.executable` 即当前进程 python（项目 `.venv`），能用项目已装依赖。
- `readonly=False`。

### 3. 文件搜索补强：`search_files` 加正则

**改法**（改 `src/api/file_tools.py` 的 `search_files`）：
- schema 的 `parameters.properties` 新增 `pattern`：`{"type": "string", "description": "正则表达式；非空时按正则匹配每行（忽略大小写），与 keyword 二选一，pattern 优先"}`。
- `required` 从 `["keyword"]` 改为 `[]`（keyword 与 pattern 至少给一个，handler 内校验：两者都空 → `err("validation", "keyword 与 pattern 至少给一个")`）。
- 匹配逻辑：`pattern` 非空 → `re.search(pattern, line, re.IGNORECASE)`（编译一次，`re.compile`，异常 → `err("validation", f"正则非法: {e}")`）；否则沿用现有 `kw_lower in line.lower()`。
- 其余（剪枝、凭证排除、200 命中 / 2MB / 20000 文件上限）**逐字不变**。

### 4. `glob_files`（按文件名找文件，新增）

**schema**：
```json
{
  "name": "glob_files",
  "description": "按文件名模式（glob）查找文件，如 '**/*.py'、'*.md'。返回匹配的文件路径列表。",
  "parameters": {
    "type": "object",
    "properties": {
      "pattern": {"type": "string", "description": "glob 模式，如 '**/*.py'"},
      "path": {"type": "string", "description": "起始目录（相对项目根或绝对），缺省在项目根下找"}
    },
    "required": ["pattern"]
  }
}
```

**handler 要点**：
- `path` 缺省 → 项目根（`BASE_DIR`）；`pattern` 用 `pathlib.Path(path).glob(pattern)`（**不递归**，避免全盘扫描），`recursive=True` 仅当 pattern 含 `**` 时（用 `Path.rglob`）。
- 结果只收**文件**（`is_file()`），跳过剪枝目录（复用 `file_tools._is_pruned`），凭证文件跳过（复用 `file_tools._credential_excluded`）。
- 上限：最多返回 200 条，超出置 `truncated=True`。
- 返回 `{"pattern": ..., "scope": ..., "matches": [相对路径, ...], "truncated": bool}`。
- `readonly=True`。

### 5. 文件管理三件（新增）

**`delete_file(path)`**：
- schema：`path` 必填（字符串）。
- handler：`Path` 解析 + 越界校验（复用 `file_tools._resolve`）；只删**文件**（是目录 → `err("validation", "这是目录不是文件")`）；不存在 → `err("not_found", ...)`；`Path.unlink()` 删除。
- `readonly=False`。

**`move_file(src, dst)`**：
- schema：`src`、`dst` 必填。
- handler：两个路径都过 `_resolve` 校验；`src` 不存在 → `not_found`；`shutil.move(src, dst)`；返回新路径。
- `readonly=False`。

**`rename_file(path, new_name)`**：
- schema：`path`、`new_name` 必填。
- handler：`path` 过 `_resolve`；`new_name` 只取纯文件名（拒绝含路径分隔符 → `err("validation", "new_name 只能是文件名")`）；`Path.rename` 到同目录下新名；返回新路径。
- `readonly=False`。

## 五、注册方式

五件工具全部**登记进 `TOOL_REGISTRY`**（`src/api/card_tools.py` 的字面量注册表，追加在文件四件之后）。每件的 `ToolDef`：

| 工具 | readonly | 归属开关（供权限线引用，本方案不接线） |
|---|---|---|
| bash | False | 建议 `exec`（新开关，待权限线定） |
| python | False | 建议 `exec` |
| glob_files | True | 建议归 `tools_file` |
| delete_file / move_file / rename_file | False | 建议归 `tools_file` 或新开关，待权限线定 |

**权限接线说明**：本方案**不写** `TOOL_SWITCH` 映射、不新增 `policy.SWITCHES` 常量、不改 `permissions.json`。工具注册后处于「未授权、不下发」状态；权限线（收拢）统一接线后才对模型可见。上表「归属开关」仅是给权限线的引用建议，不是本方案的接线动作。
