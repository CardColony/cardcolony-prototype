## 3. 落地设计

### 3.1 卡面重构（createNode 重写）

**新 DOM（根卡与子卡同模板，内容差异由数据驱动）：**

```
.card-node[data-id][data-type][data-lifecycle]
  ├ .msg-badge                      （保留：未读角标）
  ├ .ccol                           （左列：内容区）
  │   ├ .tname   项目名/卡名         （根卡字号加大，无类型标签）
  │   ├ .summary 三行状况            （line-clamp:3）
  │   └ （meta2 删——更新时间从卡面退役）
  └ .rail                           （右列：计数轨，44px 通卡高）
      ▸N / ▾N                       （整块可点＝toggleExpand，两态底色自辨）
```

- **ttype 删**：类型不再以文字出现，由左条色＋色表表达（D1/D17）。
- **summary 三行**：根卡与 L2 档子卡取 `status_block` 前三行（各自行省略）；改造点＝canvas.js `getSummary`（快路径与回退路径同步改，`conclusion_summary` 契约不动、前端再切三行）；快照数据仍有 canvas.json 兜底。
- **rail 整块点击**＝现 kid-badge 语义（toggleExpand），复用 bindNodeEvents 既有 click 路径与 updateExpandBadge（L1105）两态翻面；**rail 两态视觉自持**（收起＝暗面、展开＝点亮卡色低透明底），不依赖子卡出现与否。
- **退役灰阶**：`data-lifecycle="retired"` 一处属性驱动（见 3.4），grayscale(0.88)＋亮度压低整组（含消息卡）。
- **LOD 适配**：.l0 现状只显 tname——新结构下 .l0 隐 .rail 以外全部；.l1 显名字＋状况；.l2 全量。rail 在所有档保留（它是展开开关，缩到最小也不能丢入口）。

**CSS**：style.css 卡片段重写为 `.card-node` 网格（左内容列＋右轨列）；色表绑定用纯 CSS——`.card-node[data-type="剧本"] { --cc: var(--c-work); }` 六条（D17 色表即此，新类型加一行选色）。卡面背景/边框**不吃 --cc**（D15）。

### 3.2 消息卡（独立卡、吸附、布局补偿）

**挂载方式（本方案唯一的结构性新决策）：**消息卡作为**宿主卡 DOM 的子元素**、`position:absolute; top:100%+6px; left:0`，样式上是独立完整卡（自有面板/边框/圆角/左条，同宽 320、缝 6px、左缘对齐——D4/D6）。

- 拖动/退役/删除/连线跟随宿主卡，零额外管理成本。
- **布局补偿**（防与下方子卡重叠）：`measureSizes`（L684）为挂消息卡的卡把 `h` 补偿为 `offsetHeight + 6 + MSGCARD_H`——避让算法与连线几何吃同一份 sizes，出口点自动下移，父子线不被消息卡压死。
- **LOD**：.l0/.l1 档隐藏消息卡（卡海保护，仅 L2 全档显示）；补偿随显隐同步开关。
- **范围**：可见卡全挂（原型验收形态含子卡消息卡）；L2 档之外自动退场。
- **卡内结构**：上行＝快照（一行截断，点击开弹窗）；下行＝内联输入（无占位、回车/➤ 发送——走既有 `API.postMessage` 真链路）；退役态输入禁用（D14）。

### 3.3 弹窗系统（新模块 `popup-manager`，canvas.js 内独立节）

- **形态**：640×640 正方、屏幕居中、消息流独立滚动（D7）；头部＝卡名＋⇥＋×(40×40)（D9）；无色无流光（D16）。
- **多窗秩序**（D8）：打开顺序错位 40px 纵深；重复点同卡聚焦不新开；Esc/遮罩关最上层。
- **吸附**（D10/D11）：⇥ → 右侧**实测 `#rulePanel` 左缘**为基线（不猜常量——原型教训：猜常量差 3px 压卡），同列纵排、吸附顺序自上而下、单窗 320 封顶、空间不足整列均分压缩永不溢屏、关中间自动上移；⇤ 反向弹回。吸附态无遮罩、画布全交互。
- **动效**（D12）：开窗 scale(0.82)→1 淡入；⇥/⇤ 中央↔右侧 transform 过渡。实现纪律：动效只用 transform/opacity（不触发布局重排），探针模式（#probe）注入禁动画不影响日常。
- **数据**：开窗拉最近 8 条（新端点，见 §4）；窗内发送走 `API.postMessage`（全链路模型调用，非假发送）。
- **z 层序**：弹窗层在 topbar 之下、画布之上；与规则卡（#rulePanel）互不遮（吸附基线即其左缘）。

### 3.4 两状态（运转/退役）

**退役（持久态）**：
- cards 表新增列 `lifecycle TEXT DEFAULT 'active'`（值：active｜retired）。迁移照位置列三路先例：DDL 单一真相（card_db._SCHEMA＋_COLUMN_UPGRADES）＋幂等迁移脚本（dry-run 默认/--apply 才落/any-fail-abort）。
- PATCH 白名单 `ALLOWED_UPDATE_KEYS` 加 `lifecycle`（带 history_note 既有审计链）。
- canvas.json 派生输出 `cards[].lifecycle` → 前端 `data-lifecycle` 属性驱动灰阶（3.1）。
- **后端拦截**：lifecycle=retired 的卡 POST messages 返 409（封存非删除＝视觉灰阶＋输入禁用＋发送被拒，三层一致；历史 GET 不拦——D14 历史可读）。

**运转中（瞬态）**：
- 信号源＝该卡会话正在跑（message_runner 运行态）。**阶段 0 补勘**：SSE 帧类型清单（stream.js＋后端 emit 点）与运行态查询端点——已有帧则复用，无则新增 `run_state` 帧（{card_id, running}，回合起止各发一次）。
- 前端：收到帧给对应卡挂/摘 `st-run` 类——绕框流光（颜色 `var(--cc)`，D13/D15）；探针可见断言：st-run 时 border-image/伪元素动画在、卡面背景色不变。

### 3.5 色表

`:root` 六色令牌已在（L22-27）。色表＝`[data-type] → --cc` 六行映射（3.1）；流光渐变取 `var(--cc)`；左条边框色既有 `[data-type]` 规则改引 `var(--cc)`（单一真相，两处不再各写）。**新卡类型**：色表加一行选六色之一，左条/流光/类型边框三处自动同色。

## 7. 验收标准

1. 根卡：项目名大字、无类型文字、三行状况；点 rail 整块展开/收起，两态底色自辨
2. 消息卡：独立完整卡、缝 6px、左缘对齐；快照无发送方、输入无占位；回车/➤ 发送走真链路（network 可见 POST）
3. 退役卡：灰阶、输入禁用、POST 被后端 409 拒；点快照仍可看历史、树仍可展开
4. 运转卡：绕框流光颜色＝该卡类型色；卡面背景色不变（探针断言）
5. 弹窗：640 正方居中可滚；两窗错位 40px、各标卡名；⇥ 吸附规则卡左侧同列、320 封顶不溢屏、关中间自动上移；⇤ 弹回
6. 吸附态：无遮罩、画布可拖卡/缩放/展开
7. LOD：L0/L1 档消息卡隐藏、rail 保留
8. 布局：消息卡不与子卡重叠；连线出口在补偿后高度之下（无压线）
9. 类型色：六类型左条/流光/边框三处同色同源（改一处全局生效）
10. 回归：pytest 失败集与基线逐条同、node 全绿、拖拽/pinned/缩放/平移/下钻/未读角标不回归

## 8. 风险与边界

- **并发施工**（最高风险）：三文件在飞——阶段 0 闸门不放行不开工；若外部线继续，协商文件归属或等其收口。
- **浏览器实测**：本仓无实测史；无头 Chrome 时好时坏——探针跑不通时静态核对兜底，但弹窗动效/吸附排布**必须**真实浏览器过 §7-5/6（人机配合）。
- **消息卡×卡海**：L2 档 30+ 卡全挂消息卡的首屏请求量——懒加载＋防抖（复用摘要懒加载模式），recent 端点单卡单查轻读。
- **lifecycle 后端拦截**是行为变更（退役卡发消息从"能发"变 409）——任务书里单列，施工时在提交信息注明。
- 流光动画性能：仅 border 伪元素动画（transform/opacity），多卡同跑不触发布局；退役/探针态零动画。
