## 2. 计时：统一两条网关路径采样、按尝试归账、think 过滤 ✅

### 修了什么
| 洞 | 修法 |
| --- | --- |
| **gateway.call 仍做两次 JSON 编码，日志取的是被丢弃的那次** | 删除 `_call_once` 里测量专用、结果丢弃的 `json.dumps(options)` 探针；`json_dumps_ms` 统一改由适配器 **SerializeTimingChunk 回传帧**供数（`_call_once` 流循环识别 timing 帧：入账后 `continue`，与 `_stream_once` 同口径）——**两条路径单一采样点**（适配器真实编码处） |
| **编码计时帧被算成端点首事件** | timing 帧在 `_call_chunk` **之前**识别并 continue（两路径）——不计入首事件台账 |
| **卡片侧把 `<think>` 内文本算成可见首字**（实测 first_content=140ms，正文 328ms 才出现） | 网关两路径的 first_content 采样过**流式 `<think>` 分流器**（复用 `api/think_strip.py::ThinkStreamSplitter`——跨帧拆裂的标签由其状态机处理，延迟 import 防 api↔gateway 环）：text-delta 经 `feed()` 分流，**正文增量非空**才记 first_content |
| **首试 503 时首事件沿用了失败尝试的记录** | observe 新增 **`reset_attempt_timings(trace)`**：每次 attempt 开始清首帧/首正文读数并记 **attempt 起点**；`first_chunk_ms`/`first_content_ms` 读数基准从 call_begin 改为 **attempt_started**（按尝试归账，两读数同基准可比） |
