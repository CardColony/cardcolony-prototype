## 二、问题清单（12 条，逐条挂证据）

### 2.1 A 组 · 子卡片不可见（机制已查明）

**用户 20:51 问的那件事。结论：不是丢卡，是可见集规则使然。**

**机制**（`static/canvas.js` 的 `renderCanvas` 可见集构造段）：

```js
const visibleIds = new Set([state.viewRoot]);        // ① 视图根恒在
for (const child of (state.childMap[state.viewRoot] || [])) {
  visibleIds.add(child.card_id);                     // ② 视图根的直接子卡恒在
}
while (grew) {
  if (!state.expanded.has(cid)) continue;            // ★ 不在 expanded 里 → 子卡不进
  ...
}
```

**关键**：除视图根及其直接子卡外，**任何卡要把自己的子卡带进画布，前提是它自己在 `state.expanded` 里**；而 `state.expanded` **只存内存、刷新即清空**（代码注释逐字）。

**实测数字**：

| work_001 | 根 ＋ 6 张（002/005/006/007/008/025）＝**7 张** | 深度 2 的 **16 张**（card_009～024，全挂 card_005 下） |
| work_002 | 根 ＋ 4 张（002/006/010/016）＝**5 张** | 深度 2 的 7 张 ＋ 深度 3 的 1 张 |

**数据侧干净**：两剧本卡片树完整（23/23、13/13 从根可达，零孤儿），`canvas.json` 与磁盘逐一对齐。

## 三、诸葛自定的设计决策（含被否备选）

**权限声明**：本节属**诸葛设计权范围**（用户 21:46 授权「界面的事你自己定」）。**标注为「诸葛设计决定，用户可事后推翻」**——按 17:54 立的边界（技术取舍我拍、留痕可推翻）。

### 3.1 「缩小档线消失」的来历与代价（已查清）

**它是原项目机制的移植，不是为这个项目设计的。**

LOD 三档按缩放自动切换：L0（<0.5）卡片缩成 160px 胶囊只留标题、L1（0.5~1.2）220px 标题＋3 行摘要、L2（>1.2）260px 标题＋10 行摘要。**线的隐藏写在同一个函数里**（注释逐字 `// L0 时隐藏关系线`）。

**来历**：`git log -S "edgesSvg.style.opacity"` 只有一条 `25781c9 [init]`——**搬运写作 agent 骨架时一起带过来的**；注释里还留着原项目的阶段标记 `[phase8.6-A]`／`[phase8.6-B]`。

**原设计的道理**：写作 agent 的画布是「一张大图全铺开」，缩到远景卡片密密麻麻、线叠上去成一团毛线——**藏线是为让远景干净**。

**今天为什么不对**：推演 agent 是**折叠树**（屏幕上只有展开部分和它的连线）——**用户缩小恰恰是想看结构，而唯一表达结构的东西正好被关掉**。且 T08 之前 relations 线本就 0 条（隐藏无影响），T08 之后父子线成了画布主要信息载体。

**代价：没有技术代价。** 三条依据：
1. 线一共二十几条，`edgesSvg` 是一次性 `innerHTML` 重建，不是每帧重算；
2. 用的是整层 `opacity="0"` 而**非移除元素**——DOM 节点还在，渲染器照样处理，**省不了渲染，只省了「看不见」**；
3. 真正的 L0 性能动作在**卡片侧**（胶囊化、藏摘要），线只是跟着一起藏，非独立决策。

### 3.2 线条体系（设计定案）

**现状**：两类线完全同款（`#30363d` / 1.5），只有形状不同（折线 vs 直线）。父子线带 `data-edge="parent-child"` 标记（机械验收依赖，**必须保住**）。

| 项 | 诸葛选的 | 被否的备选（含理由） |
|---|---|---|
| **父子线** | 颜色 `#58a6ff`（蓝）、宽 1.5、实线、**端点圆点**（父端实心／子端空心） | ①虚线（虚线语义是"待定"，结构是确定的，反了）②加箭头（父子是层级不是流向，且直角拐角处算切线很怪）③把父卡画大（那是改布局，动的东西太大） |
| **关系线** | 颜色 `#8b949e`（灰）、宽 1.5、**虚线** | ①保持同色只改粗细（还是分不清）②改成曲线（与折线的"结构感"打架） |
| **假设悬空红线** | **不动** | 红色虚线＋空心圆是既有语义（假设未兑现），改它就改了含义 |

**一句话**：**蓝实线＝层级骨架，灰虚线＝弱关联，红虚线＝假设悬空。**

### 3.3 缩小档显隐规则（设计定案）

| 档 | 父子线（骨架） | 关系线（弱关联） |
|---|---|---|
| **L0**（zoom<0.5） | **留**，宽降 1、透明度 0.55 | **收起**（`display:none`） |
| **L1**（0.5~1.2） | 留，宽 1.5、透明度 1 | 留，宽 1.5、透明度 1 |
| **L2**（zoom>1.2） | 留，宽 1.5 | 留，宽 1.5 |

**被否备选**：①全保留（远景会花）②全隐藏维持现状（关掉唯一的结构表达）③只保留指向当前视图根的线（下钻后视图根变了，线会忽明忽暗，不稳）。

### 3.4 横穿修法（设计定案）

**根因**：锚点写死「父右缘→子左缘」，不看两卡实际谁在左谁在右。

**改法**：按两卡中心横向相对位置**自动选边**——子在右走「父右缘中点→子左缘中点」，子在左反过来。折线路径函数本身已按两点中间算 `midX`，**改锚点即可，路径函数不动**。

**被否备选**：①绕行（从父卡上／下方兜一圈——在折叠树里会更乱，且锚点自动选边后横穿的根因本就消失）②限死子卡只能在右边（改布局规则，动的东西大得多）。

### 3.5 pinned 视觉标识（设计定案）

**现状**：`persistCardPos` 拖一下就 `pinned: true`；`reorganizeBtn`（整理画布）把所有卡重置为 `pinned: false`。**真实语义是「拖过的卡＝钉住＝不参与自动避让」，但界面上完全看不出来。**

**改法**：①钉住的卡改为「位置不动但参与分带」（别的卡给它让路，不再压一起）；②挂 `is-pinned` 类，`style.css` 加虚线描边＋右上角 📌。
