## 一、为什么做这件事

**S2 已把左侧边栏的渲染模型换成按需更新＋折叠即卸载＋diff＋虚拟滚动＋异步加载（五新模块热生效）——树能正确渲染出来了。但"树好用、好看、不迷路"是 S3 的活：**

- 点击一下发生什么（S2 只做了 toggle，点击语义分叉/已删卡灰态未定）；
- 怎么找卡（深树没有搜索/最近访问，只能沿树翻）；
- 在哪、怎么回去（无面包屑/吸顶/定位，深树即迷宫——宪法四"三问永远有答"）；
- 信息呈现（无引导线/徽章/唯一高亮/非正常态——深树标题被缩进吃光、多高亮等于没高亮）。

**S3 范围＝路线图 v3 排定的 13 条（L61-70 逐字）**：
R-20 点击分叉／R-21 已删灰态不跳／R-24 搜索独立层／R-25 最近访问／R-26 定位三件套／R-27 面包屑／R-18 吸顶路径条／R-28 一键收起+记忆／R-29 多项目并看／R-31 引导线／R-33 徽章≤2／R-34 唯一高亮／R-35 非正常态

## 三、设计（13 条逐条：落点/形态/被否备选/接缝）

### 〇、S3 架构总纲

**S3 与 S2 的边界**：
- S2 管「树能正确渲染出来」（数据装载/状态容器/行对象/渲染原语/可视区/异步加载）；S3 管「树好用、好看、不迷路」（点击语义/找通道/定位/信息呈现）
- **硬界线（不许为 S3 改 S2 已定结构）**：不改 store 四区 API 签名、不改 row_model 投影、不改 nav_render 渲染原语、不改 nav_virtual 可视区模型、不改 nav_async 加载语义。S3 只做四类动作：①workspace.js 事件层新增交互语义；②消费 store 的 temp/prefs；③新增模块；④style.css 新增样式

**S3 新增模块（3 个）**：
1. `static/esm/nav_find.js`（~200 行）——搜索独立层＋最近访问（共用面板）
2. `static/esm/nav_breadcrumb.js`（~120 行）——面包屑＋吸顶路径条（同一 UI 两态）
3. `static/esm/nav_badge.js`（~60 行）——徽章聚合纯函数（机械 max，可单测）

##### 活跃显示设计（2026-10-11 21:42 用户批评后修订）

> 用户批评（逐字）：「你真的一点都不想好好做，活跃卡片，就给我塞一个【活跃】两个字？稍微用点心设计一下呢？」——原设计把「多久前活跃」压成布尔文字标签（方案书初版「节点行＝活跃标记（branch_active_at 距今<48h 显示）」），本轮重做。

**信息主张**：行内「活」的真信息是「多久前」，不是「是不是」。相对时间是梯度的、与注意力决策直接挂钩；布尔标签（实测近 48h 有 14-17 张卡、约 1/5）等于满屏同词、无信息。故：常态「多久前」**不进行内**（B4 已定行内时间戳退役、走 tooltip——style.css L597 注释「活跃/分支活跃走 tooltip（腾 ~50px 还给标题）」），hover 行即得；行内唯一常驻「活」信号＝**分支活跃**（v4 L37「这下面有新东西」——branch_active_at > own 且 branch 距今<48h）——稀少、有行动指向（去点开）、配得上常驻。

**视觉规格**（可直接照做）：
- 分支活跃点 `.nav-branch-dot`：8px 圆点、`background: var(--c-branch, #d29922)`（琥珀橙，体系未占用的暖色；现有语义色 根=金/中=蓝/叶=灰/当前=蓝）、`box-shadow: 0 0 0 2px var(--bg)`（防滚动糊边）、默认 `opacity:0`＋`.on{opacity:1}`、`transition: opacity 0.2s ease`（无动画无脉冲，60s 探测不闪）
- 位置：行右端状态区（.nav-state 位，与 loading/error 同区）——**左=结构与身份、右=状态与信号**；与 loading/error 互斥（状态信号优先于提醒信号）；flex:none 不参与标题流（B4 腾出的 ~50px 还给标题，兑现）
- 相对时间：行 title＝标题＋own 相对时间（「X 分钟/小时/天前」，hover 现算，不依赖 60s 重算）；分支点自身 title＝「下面有新东西 · X 小时前」

**机械判据**（nav_badge.js `branchSignal(card)`，零语义）：`show = branch_active_at > own 且 branch_active_at 距今 < 48h`；tip 三档（分钟/小时/天）格式化。48h 阈值沿用 v4 参数（v4 L45「阈值是参数不是代码」，进配置，不新定）。

**数据事实（21:47 实测）**：77 卡中 own<48h 14 张（18%）、branch<48h 17 张（22%）、**branch>own 当前 0 例**——分支点在现有数据下不显示，是「将来语义」的预留设计（下层卡有活动而父卡没动时出现）；稀少性正是提醒的价值，如实标：不是缺陷。

**与既有体系的关系**：与 S4 状态四档——四档是排序/收起的**输入**（v4 L44「不加一排状态徽章」），显示层显示产生档位的原始数据（相对时间＋分支信号），S4 上线显示层不用改；与「徽章≤2」——分支点是唯一新增徽章类（异常才现），相对时间不进徽章，守得住；与 .dot 类型色点——尺寸沿用但新立 `--c-branch` 语义色，不扩 .dot 语义（10-07「色点没人懂」教训：新点自带 tooltip 解释）。
