用户 2026-10-07 00:13 三条当场裁定确立方向（最高优先级）：①不加任何工具上限（维持 10-02 拆闸）；②所谓「人肉桥」根本不是病（那是模型虚构的对话事件，已取证作废认账）；③**重点＝三席模型后置到工具结果出来之后再思考**——主模型先带工具查事实 → 工具结果出来 → 注入三席输入 → 三席踩着事实出观点 → 统合交付。方向本源（10-06 22:35 用户逐字）：「主模型先查，只在最后交付环节，走三模型席位先出观点，主模型统合」。

## 二、位置与接口规范（改在哪、对外契约）

**核心落点**：`simple_service.py` 编排层（后置的编排逻辑），配合 `routes.py` 现有工具循环的衔接点。

- **探查段（事实收集）**：复用 `routes.py:424` 现有 `while True` 工具循环——工具调用、`begin_round` 入槽、`append_tool_result` 回喂、`L537` 续跑全部沿用，**不新造第二套 while**（防两套嵌套打架）。探查收敛点＝`L475` 无 `tool_calls`。
- **三席段（后置后触发）**：探查收敛后，把该轮累积的工具结果打包成新入参传给 simple 的三席段；三席仍 `tools=None`（10-02 零工具裁定不变）、输入＝中性上下文＋用户问题＋**工具事实段**。
- **统合段**：三席观点拼进统合官输入；统合段不再带工具（`call_main(tools=None)`）——**第三步后再发工具会使三席观点过时，这是后置成立的关键**。
- **合同不动**：`call_main` 合同不动；`BASE_PROMPT_VERSION` 自 t12-1 递增；三席 `tools=None` 不动；`VIEWPOINT_HEADER` 逐字不改；`VIEWPOINT_TASK_NOTE` 因指错对象（「三份分析…回答上面用户问题」在探查替代用户问题后失效）须改写为新契约，工具事实段按【结论】＋【依据】折叠形态（用户 10-05 裁定）。

## 三、可复核预期效果（交付后该看到什么）

1. **顺序反了**：同一轮里，工具查证先发生、三席观点后发生（过去是反的）——机器可断言（运行时打点顺序）。
2. **三席手里有事实**：三席输入里包含本轮查回的工具事实段；无工具结果的轮（纯对话）行为与现状一致、不退化。
3. **无任何闸**：工具循环仍 `while True` 不设封顶；新增改动须证明未引入轮次上限/max_tokens/墙钟。
4. **三席 tools=None 不变**、统合官 `call_main` 合同不变（可断言）。
5. **统合在最后**：三席观点出完、统合官才交付；统合段不带工具（交付不再发新工具）。
6. **成本口径待用户拍**：每轮皆三席后置（成本≈5-6 次/轮）vs 仅指定轮触发（省成本、部分轮无三席交叉）——方案不代办，端上桌。
