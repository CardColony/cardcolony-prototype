## 9. ⚠️ 任务书未覆盖、执行方自行取值的地方（逐条待您裁定）

### 9.1 【必修】`stream.js` 终止事件不再关流——否则逐字流**恒不可见**

**现象（实测）**：新发一条消息时，`/stream` 的 `from=0` 会先重放**上一轮**全量事件（含 `done`）；
旧 `finish()` 收到 `done` 即 `stopES()`，把刚连上的 `/tokens` 逐字流**一并关掉**。
实测：修前 `EventSource` 探针 `tokens.msgs=0`、逐字正文峰值 **0**；修后 `msgs=59`、峰值 **96**。
**该缺陷在改动前的代码里同样存在**——旧过程卡在「同卡第二条消息」上本来也拿不到逐字流。

### 9.2 `MAX_EVENTS` 一并删除（T4 未列，V7 要求）
V7 原文「`MAX_EVENTS` 仅残留于过程卡且随 T3 退场」⇒ 终态应为不存在。执行方按 V7 终态判，
主通道 300 条环形弹出（同属「丢最前步骤闸」）**一并删除**；`docs/_gen_event_manifest.py` 连带同步。

### 9.3 保留**非尺寸**的序列化兜底 `_jsonable`（替代 `_truncate`）
`_truncate` 原本兼任「不可 JSON 序列化 → `_note`」的兜底，删掉会让 SSE 生成器 `json.dumps` 抛错断流。
故只删**尺寸截断**，保留零尺寸约束的 `_jsonable`。**它不是闸**。

### 9.4 队列满「不静默丢」策略**同时**用于主通道
T4③ 只点了 `subscribe_tokens`；但 `emit()` 的 `q.put_nowait` 同样静默吞（同文件同病），
统一进 `_fanout()`（丢最旧中间帧 / 保最新 seq / 打 warning）。

### 9.5 `workspace.js` 的三处小改（T5 未列，V4/T1 需要）
- `appendMessage(role !== "user")` **就地接管** `.msg.assistant.live` 正文条目（不再撤换重建）

### 9.10 ★【13:3x 次序铁律】流式信息**不得停在正式回复下面**（＋修掉两个连带缺陷）
**用户裁定**：「dsh 这样的成熟 agent 是你做成的那样吗？**流式信息会他妈停留在正式回复下面？**」

复查后确认：这不只是位置问题，我这条线上还有**两个真 bug**（都在本包改动内引入或放大）——
1. **`dropText` 会删掉已结算的正式回复**：正文条目被 `appendMessage` 就地接管后不再是 `.live`，
   而 `run_start` 的 `dropText` 仍把它当临时条目 `remove()` ⇒ **同一页面连发第二条时，上一轮的回复气泡从对话里消失**；
2. **`clearRows` 会清掉上一轮的过程行**：新一轮 `run_start` 波及同一 `rows` 数组 ⇒ 上一轮的行被撤掉；
3. 刷新的重放把行 append 在 `renderChat` 之后 ⇒ **行落在回复下面**（上包 §10 曾列为「待令小改」）。

**改法（三处）**：
- **每轮自成一组**：`beginGroup()` 在新一轮开场时先把上一轮的 `rows` 数组与正文引用**封存/解绑**（DOM 原地不动），
  使 `clearRows`/`dropText` 只作用本轮；`dropText` 另加 `classList.contains("live")` 守卫，双保险。
- **端序保证（次序铁律）**：①生成期——新环节行落下就把**非空**正文条目推到队尾（正文恒在最新行之下）；
  ②结算——`appendMessage` **就地接管**（行原地不动）；③刷新重放——`replayTrace` 收流时调 `anchorRows()`，
  把本轮过程行**整块移到该轮回复（最后一条 `.msg.assistant`）之前**。
- **修 `replayTrace` 兜底计时器误关新流**：页面刚打开就发消息时，3s 兜底计时器会把**新一轮刚连上的**
  `/stream`、`/tokens` 一起关掉（实测丢过整轮过程行）⇒ `close()` 加 `st.es !== es` 守卫，已被取代即什么都不动。

**实测（真浏览器，连发两条 ＋ 刷新；以服务端 `/progress.active` 判每轮收口）**：
三段（发第 1 条 / 同页再发第 2 条 / 刷新）**均 `rowsAboveReply = True`**（末条 `.step-row` 在末条 `.msg.assistant` 之前）；
助手气泡 **1→2→3→4** 逐轮递增（上一轮回复不再被删）；过程行 **14→28→42** 累积（上一轮行不再被清）；容器数恒 **0**。
