## 一、背景与裁定

**病灶**：对话回复只取「不带工具调用的那一轮」的正文——`routes.py`（测试空间，下同）L461-462 `if not tool_calls: final_reply = assistant_content`、L472 `break`；带工具调用的轮次其 `assistant_content` 经 `slot.begin_round`（L483-494）只进轮槽（后台上下文），**不进会话、不进回复**；最终解析、落盘、返回全绑定末轮 `clean_text`（L572 parse、L577 append、L587 reply）。落盘型工作流的分析正文全部写在带工具轮的正文里——**分析结构性上不了屏**。〔锚：routes.py L461-462/L483-494/L572/L577/L587；p1 纪要·现状；对应 T14 条目 R-002/R-003/R-006〕

**用户诉求（原话）**：「我认为它应该是做了分析的，只是我没收到」「我要看到的是那轮综合观点」——分析的交付目的地从「卡片／文件」扩展到「对话」，且不得取代回执。〔条目 R-005〕

**本轮范围（方案裁定在册）**：只改 `routes.py` 一个文件（测试空间 `推演agent_test/src/api/routes.py`）；不设任何闸、不改会话格式、不碰 gateway、前端零改动、`prompt_log.response` 语义不动；三席观点正文本轮不做；三个待裁定全沿用默认（拼接顺序分析在前／超长不折叠不截断／三席观点本轮不做）。〔条目 R-021/R-037/R-038/R-039/R-040/R-041/R-009/R-024〕

## 三、任务分解（全部落测试空间，正式服零触碰）

### 任务 1 · 采集带工具轮的分析正文（改动点 1）〔R-022/R-023/R-024〕

- **1-1 新增局部变量**：在 `routes.py:402` 声明位旁新增 `analysis_parts: list[str] = []`。〔R-022〕
- **1-2 采集接缝（结构性关键）**：在 `routes.py:483-494` `slot.begin_round(...)` 处，将该轮 `assistant_content`（含 `routes.py:449` 抢救处理后的正文）同步追加进 `analysis_parts`。**只读采集**——不修改 `begin_round` 的入参结构、不额外 append 进槽（T11 轮槽的消息条数与配对不变量不得破坏）。〔R-023/R-007〕

### 任务 2 · 拼接「分析在前、回执在后」（改动点 2）〔R-025/R-026/R-027/R-028/R-029〕

- **2-1 落位**：`routes.py` 工具循环结束、日志写（`L540`）**之后**、`parse_proposals`（`L572`）**之前**插入拼接段。**此顺序是命门**：插在日志前会污染 `prompt_log.response` 语义（红线）。〔R-025〕
- **2-2 拼接式**：`delivered = "\n\n".join(analysis_parts + [final_reply])`——分析在前、回执在后、`\n\n` 分隔。〔R-026〕
- **2-3 边界（V7）**：`analysis_parts` 非空且 `final_reply` 空 → `delivered = "\n\n".join(analysis_parts)`；两者皆空 → `delivered = ""`；`final_reply` 非空且 `analysis_parts` 空 → `delivered = final_reply`（纯对话轮原样、回归不变）。〔R-027〕
- **2-4**：拼接后 `final_reply = delivered`。〔R-028〕
