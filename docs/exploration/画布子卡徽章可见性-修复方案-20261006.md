# 画布子卡徽章可见性 · 修复方案（2026-10-06）

**文档性质：report-only 修复方案。不改代码、不改数据。**
**承接：card_016 §十三（徽章被标题裁掉）／§十二（二级卡的子卡不可见）。**

---

## 〇、复核结语

- 现象成立、机制成立：**徽章已渲染进 DOM，但拼在标题之后、被 `.tname` 的裁剪规则切掉**。
- 本方案给出三案（A 推荐 / B / C）。A ＝**纯 CSS 两处、canvas.js 零改动、免重启后端**的最小可感修法。
- 修复目标：`childCount > 0` 的卡，其徽章在**任意 LOD 档位、任意标题长度**下可见、可点。
- 非目标：不改可见集规则（§12.3①）、不改展开态持久化（§12.3②）、不改展开后视野（§12.3③）。

## 一、现象与用户原话

> 用户（2026-10-06）：「不是默认不展开的问题，二级卡片里没有一张上显示有挂子卡片」

用户所指：**画布上根本看不到「这张卡有子卡」的标记**，因此连展开的入口都摸不到。

## 三、病灶与算术

**病灶单句**：状态标记挂在**会裁剪的容器**（`.tname`）的**文本流尾部**，而标题长度不受控 ⇒ 标题一长，标记必被切。

**算术（l1 档，即默认档）**：

- 卡宽 220px〔`style.css:322`〕
- 减左右 padding 24px〔`style.css:224`：`padding: 10px 12px`〕
- 减边框 左 6 ＋ 右 2 ＝ 8px〔类型边框 `border: 2px solid` ＋ `border-left-width: 6px`〕
- 全局 `box-sizing: border-box`〔`style.css:42`〕
- ⇒ `.tname` 可用净宽 **188px**
- 标题「条件·时点：美元走弱、资本从美国市场外溢达成」≈ **22 字 × 13px ≈ 286px**（§十三 记 23 字／299px，口径差 1 字，不影响结论）
- 286 ≫ 188 ⇒ 标题独占并溢出，**排在它之后的 `▸ 16` 落在裁剪区外**

**反向印证**：work_002 `card_007`「布局、信息视觉工程」（9 字）徽章可见（T08 验收留痕）⇒ 可见性由**标题长度**决定，不是「有／无」。

**影响面**：凡标题撑满卡宽者，徽章一律不可见。work_001 二级 6 张里唯一有子卡的 `card_005` 恰是标题最长者 ⇒ 用户所见＝「一张都没有」。

## 四、修复方案

### 4.1 方案 A（推荐）｜徽章脱离文本流、钉右上角

```css
/* style.css:235 改写 */
.card-node .tname {
  font-weight: 600; font-size: 13px; overflow: hidden;
  position: relative;      /* 新增：作为徽章的包含块 */
  padding-right: 56px;     /* 新增：为徽章预留右侧凹槽 */
}

/* style.css:263 改写 */
.kid-badge {
  display: inline-block;
  font-size: 10.5px; color: var(--dim);
  border: 1px solid var(--border); border-radius: 8px;
  padding: 0 6px; cursor: pointer;
  background: var(--bg);
  position: absolute;      /* 改：脱离文本流 */
  top: 1px; right: 0;      /* 改：钉在 .tname 右上角 */
  margin-left: 0;          /* 改：原 6px 由 right 定位替代 */
  z-index: 2;              /* 新增：压在标题之上 */
}
```

- **效果**：标题照旧省略号截断，徽章固定右上角，任意标题长度均可见。
- **改动面**：`style.css` **两处**；`canvas.js` **零改动**；后端零改动。
- **生效方式**：静态文件，**刷新即生效**（建议强刷），**无需重启后端**。
- **不变量**：`.tname` 高度不变（原徽章 `inline-block` 未撑高行盒；脱离流后仍不变）⇒ **布局引擎测得的卡尺寸不变，避让算法不受影响**。
- **`padding-right: 56px` 取值依据**：徽章盒宽 ≈ 42px（文本 ≈27 ＋ padding 12 ＋ border 2 ＋ 与标题间距）＋ 安全余量（子卡数可达三位数）⇒ 56px。
  - l0 档（卡宽 160、内容宽 132）：标题可用 ≈ 76px（约 6 字）——远景档，可接受。
  - t8-deep（`max-content` ≤ 260）：标题可用 ≈ 172px，可接受。

### 4.2 方案 B（备选）｜徽章移出 `.tname`

- 改 `canvas.js` 的 `node.innerHTML`（徽章挪到 `.tname` 之外、挂 `.card-node`）＋ `style.css`（`.kid-badge` 绝对定位，照 `.cross-link-badge` 范式）。
- **优**：与 `.tname` 裁剪**彻底解耦**；t8-deep 的 `max-content` 不再被徽章撑宽（卡宽更贴标题）。
- **劣**：动 JS 模板 ⇒ 两空间共四个文件；`.card-node` 各档 padding 不同，徽章定位需按档微调；回归面 > A。

### 4.3 方案 C（备选）｜`.tname` 改 flex

- 标题包一层 span（`min-width:0; overflow:hidden; text-overflow:ellipsis`），徽章 `flex: none`。
- **优**：语义最正（标题可截断、徽章恒占位）。
- **劣**：改 JS ＋ CSS；flex 改变 `.tname` 内部布局，t8-deep 的 `max-content` 宽度语义随之变化；回归面最大。

### 4.4 三案对比

| | 改哪 | 文件数（含两空间） | 回归面 | 生效 |
|---|---|---|---|---|
| **A（推荐）** | style.css ×2 处 | 2 | 极低 | 刷新即生效 |
| B | canvas.js ＋ style.css | 4 | 中 | 刷新即生效 |
| C | canvas.js ＋ style.css | 4 | 中高 | 刷新即生效 |

**建议 A**：满足全部目标、改动面最小、可一次性回滚。若日后要做「徽章移出 / flex 重构」，B／C 可另立。

## 六、不变量与影响面

- **不动**：`canvas.js`（DOM 结构与事件绑定原样）；可见集规则；展开态；布局引擎（`measureSizes` / `resolveOverlaps`）；后端全部；会话／卡／`canvas.json` 数据。
- **卡尺寸**：不变（§4.1 已论证）。
- **点击行为**：不变（`node.querySelector(".kid-badge")` 仍命中；`stopPropagation` 仍生效）。
- **影响面**：所有 `childCount > 0` 的卡，其徽章在 l0／l1／l2／t8-deep 四档均可见。

## 八、风险与代价（如实列）

1. **l0 远景档标题可用宽收窄**（≈76px、约 6 字）——徽章换来的代价；如不接受，可对 l0 单独免预留（另立）。
2. **三位数子卡数**（≥100）会超出 56px 预留 ⇒ 徽章被裁（本库当前最大 16，不触发；如担心可改 `padding-right: 64px`）。
3. **浏览器缓存**：需强刷才见到新样式。
4. 本方案**只解决「看得见入口」**；「展开后子树落视野外」（§12.3③）与「默认只显两层」（§12.3①）**不在范围**——修好后如期仍觉不便，另立。
5. **未做浏览器实测**（本侧无浏览器）：机制与算术为读码 ＋ 算术推断；**V1–V6 须在真实浏览器见证后方可判「修复完成」**。
