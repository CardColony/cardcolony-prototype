# 卡片对话上下文注入（使命／现状／定论）· 方案

> 归属：card_046「裁定记录 · 卡片对话上下文注入」（父 card_015）
> 性质：方案（report-only）。不含任务分解、不派生实现卡。方案中【提议】未经用户裁定。
> 日期：2026-10-10

## 一、要解决什么

card_015 Q1 已记录「血统链的裁定传承缺位」：中性上下文只给 id·标题·父卡，上级卡正文里写下的裁定（如「零内容预设」「拉取不推送」）下级卡在自己对话里看不到，只能靠人手粘贴。

卡片正文的三块结构已定型：
- `## 使命`：立项定稿，模型不可改。
- `## 现状`：覆盖写的单一快照，只写已核实事实。
- `## 定论`：只追加，条目 `D{nn}【来源】内容`，失效就地标记「→ 被Dnn取代（因……）」。

问题：这三块在**自己对话**里如何进入上下文，**上级裁定**如何被下级拉取，且不破坏「拉取不推送」「不推正文」原则。

## 二、事实基线（实读，本轮未重跑）

1. `context_regions` 的 150 区（current_card）承载当前卡正文。故**本卡自身的三块已随正文进入自己对话**，无需新增机制即可成立；待核的是「三块是否被整体、未截断地送达」。
2. 中性上下文不含任何祖先正文（card_015 §二、card_002 基线）。
3. 权限拓扑已有：`can_read` 覆盖子树＋血统链＋连线＋锚卡（card_005 §四、card_015 候选约束 3）。故「读上级定论」在权限上可行，无需新造。
4. 定论条目带序号 D{nn} 且终身不改、失效标记不删原文（edit_card 规则）。这为「按锚点取回」提供了稳定引用目标。
5. 使命块对模型只读（edit_card 拒改）。使命不会因模型改写而漂移。

## 三、方案选项

**A. 常驻注入血统链全部定论**（推送形态）
- 每轮把所有祖先的定论拼进 system 区。
- 违反「拉取不推送」；定论条数随深度与时间增长，常驻无界；等于开了一条无归属的常设回流通道（card_005 §六已论证此路不可取）。
- 结论：不推荐。

**B. 显式拉取工具 `read_ancestor_rulings(card_id?)`**（拉取形态）【提议，推荐】
- 只返回血统链上级卡「## 定论」区段（不含使命、现状、正文）。
- 缺省：当前卡直接父卡；可指定血统链上任一祖先。
- 载体为工具返回值，进 prompt 日志（可审计，对账可复现「这一轮读了什么裁定」）。
- 纯读，不改被读卡（card_015 候选约束 2）。
- 权限沿用 `can_read`，不越出血统链。

**C. 仅靠人手粘贴**（现状）
- 零改动，承认裁定传承靠人。作为对照基线保留。

**D. 只读使命＋现状的上级摘要**
- 扩大拉取面。使命已定稿、现状是快照，二者对下级的决策价值低于定论，且现状易腐，不推荐首版纳入。

## 四、推荐形态（B）细则【提议】

1. **返回内容**：目标祖先的 `## 定论` 全部条目，原样逐字，含已失效标记行（失效条目不得被静默隐去，否则下级会引用已被取代的裁定）。
2. **不返回**：使命、现状、正文、影子、子树内容。
3. **标注来源**：每条带 `卡id · D{nn} · 来源类别（裁定／决定／收敛）`，便于下级回指。
4. **长度口径**：单次返回设字节上限，超限时按 D 序号从新到旧截取并在返回尾部标注「已截，共 N 条，余 M 条未返回」。截断本身落日志，不静默。
5. **额度**：不设硬闸，记账（拉取次数、目标、返回字节）落 prompt 日志（card_015 Q8）。
6. **工具注册**：走 `card_tools` 的只读白名单（`READONLY_TOOLS`），并须在 BASE_PROMPT 工具清单中登记，属「改基准」动作（参照 card_015 §十三 第 34 条的代价：改 BASE_PROMPT 需同步版本化 V1/V2 比对基准）。

## 五、本卡自身注入规则（不新增机制）

- 本卡三块经 150 区随正文进入自己对话。
- 验收时核：三块逐字送达、无截断、使命块与定论块边界清晰。
- 定论只增不减（追加），故「同一卡多轮之间定论只增」可机械核对。

## 六、验收项【提议】

V1 逐字：拉取返回的定论条目与卡文件中对应行逐字一致（机械比对）。
V2 失效可见：被取代条目在返回中以失效标记出现，不被隐去。
V3 范围：返回内容不含使命、现状、正文字段（断言）。
V4 权限：血统链外的卡拉取被拒，且有 denied 记录。
V5 纯读：拉取前后被读卡 hash 不变。
V6 截断可见：超限时返回尾部含截断标注，日志含截断计数。
V7 可审计：prompt 日志含每次拉取的目标 id、条数、字节。
V8 回归：未调用该工具的轮次，prompt 日志与改动前逐字一致（零行为变化）。

## 七、待用户裁定

1. 是否采纳 B（显式拉取）而非 A（常驻）。
2. 工具名与缺省目标：`read_ancestor_rulings` 缺省取直接父卡，还是缺省取整条血统链？
3. 失效条目是否始终返回（方案推荐：是）。
4. 字节上限取值（方案未定具体数）。
5. 是否同批登记 BASE_PROMPT 工具清单改动，或另开一笔。
6. 本卡「三块随正文入上下文」是否需要单独核验（V-本卡），还是默认成立。

## 八、非目标

- 不推送任何祖先内容进常驻区。
- 不改使命、现状的生成规则。
- 不引入影子进入此通道（影子拉取另归 card_005 §六 的 `read_child_shadows` 议题）。
- 不改 edit_card 的三块规则。
