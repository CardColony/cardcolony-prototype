## 一、为什么做这件事

**S2 是四族中的「渲染地基」**：S1 造好了数据通道（全量 nav＋children＋version、8 字段契约），S2 负责把左侧边栏的渲染模型从「60 秒整树 innerHTML 重绘」换成「按需更新＋折叠即卸载＋diff 刷新＋虚拟滚动＋异步加载」——这是路线图 v3 排定的第二个施工族，是 S3（交互）与 S4（自动组织）的产出依赖。

**它治三样今日实证的病根**：

| 病根 | 现场位置（18:23 实读） | S2 消灭它的结构 |
|---|---|---|
| 渲染全量重写（整树 innerHTML） | `renderNavFromCache` L468-481 `navTree.innerHTML=整树拼接`；`renderCardRows` L521-544 递归全量拼 | R-13 按需更新：结构上不存在「重建整棵树」动作 |
| 状态裸变量堆（无归层/无持久化/刷新即丢） | L420-423 四个模块级裸变量（navData/navProjectsOpen/navOpenCards/navPathAppliedFor） | R-07/08/09 状态三层容器，唯一读写口 |
| 60 秒整树轮询 | L1112 `setInterval(() => { renderNav(); }, 60000)` | R-15+版本号探测：60s 只探测 `version` 单数字，没变零开销 |

**边界**：S2 只做渲染体系，不写 S3 交互组件（吸顶/搜索/徽章/高亮）、不写 S4 自动组织（排序/收起/调位）、不写 R-30 键盘。只留接口（行序列、可视区模型、temp.hover 登记口、prefs 键位、expandedSource 判据）。

## 三、设计（13 条逐条：落点／形态／被否备选／接缝）

### 〇、架构总纲（七硬问题裁决）

**迁移形态：整段重写 workspace.js nav 段（L420-588），M1→M2→M3 为同一套代码的换底步骤；不并行双跑。**
- 为什么不是「并行新建一套再切换」：双跑＝旧路径继续吃资源、两套模板维护、共享数据源时期是 bug 高发期；回退靠 git 不靠保留旧代码在盘。
- 为什么能渐进：三里程碑各自是可用态（M1 状态换底行为等价；M2 渲染换底上线；M3 规模机制终态），各自独立验收判据，可停可验。

**模块划分与数据流**：

```
S1 契约（已生效）→ api.js API（+getNavChildren/getNavVersion）
  → static/esm/state_layers.js（createNavStateStore：临时/偏好/选中/快照四区）
  → static/esm/row_model.js（createRowModel 投影 props(store)）
  → static/esm/nav_virtual.js（可视区切片，混合行高前缀和）
  → static/esm/nav_render.js（mount/unmount/patch 三原语＋diff 跳过交互集）
  → static/esm/nav_async.js（loadChildren 去重＋三态流转）
  → workspace.js nav 段重写为接线器（事件绑定＋probeVersion＋RenderNav 导出保留）
```

**新模块全部落 `static/esm/`**（与现有 api.js/store.js/stream.js 同目录、ESM 生态一致）。

### M2 渲染换底

**R-13 按需更新渲染**
- 落点：新建 `static/esm/nav_render.js`；删除 renderNavFromCache（L468-481）与 renderCardRows（L521-544）的 innerHTML 拼装
- 形态：行 DOM 用 `document.createElement` 构建；mount/unmount/patch 三原语；首次挂载后**无整树重建路径**
- 被否备选：继续 innerHTML 只拼变化段 → 否决：innerHTML 每次重解析整段字符串、事件绑定重来、状态与字符串耦合
- 接缝：`RenderNav` 导出保留（canvas.js 建卡调用 → 走 diff 路径而非全量重绘）

**R-14 折叠即卸载**
- 落点：nav_render.js 的 fold/unfold 路径
- 形态：`fold(row)`=该行 children DOM 全 remove＋临时层 loaded 清 false＋序列孩子段移除；`unfold`=序列重建该段＋异步加载（未 loaded）；折叠即丢（v3 L87 一致性优先：一律重拉，接受毫秒级等待）
- 被否备选：保留全部 DOM 只 display:none → 否决：上千节点 DOM 全在、滚动/查询/内存全扛（v1 L73）
- 接缝：虚拟滚动消费的序列＝折叠即卸载的直接产物

**R-15 diff 刷新**
- 落点：nav_render.js diff 模块；替换 L1112 轮询体（探测见 R-22 后附「版本号探测」节）
- 形态：快照（store.snapshot）与 DOM 分离；版本探测 hit → 重拉 → `diff(oldSnapshot,newSnapshot)` → 三类变化（新增 mount／消失 unmount／字段 patch）→ 只影响变化行；**work 级差分**（by_work 指纹对比，未变 work 的 DOM 不动）
- 被否备选：无版本号、60s 全量重拉全量 diff → 否决：传输+diff 成本照旧（v3 L39 借鉴 ZCode 版本号探测的动机）
- 接缝：探测粒度 work 级→局部 diff

**R-19 diff 跳过交互节点**
- 落点：nav_render.js diff 模块开头（统一裁决，不散落）
- 形态：待更行检查 `store.temp.hover()`/`store.temp.loading()`——在交互集则跳过该行本次 patch（数据已进快照，下次探测覆盖）
- 被否备选：diff 无条件 patch 所有变化 → 否决：悬停 tooltip 被打断、加载中行被覆盖（v1 L103「设计里最实的一个洞」的闭合）
- 接缝：temp.hover 登记口本族补挂（mouseenter/mouseleave），S3 交互事件复用

### M3 规模机制

**R-16 虚拟滚动**
- 落点：新建 `static/esm/nav_virtual.js`
- 形态：`createVirtualList(container, getRows)`——监听 scroll/resize；行序列＝flattenTree 输出（展开入列、折叠出列＝与折叠即卸载咬合）；**可视区按行数组逐行累计偏移（前缀和）计算**（混合行高：项目 30px＋卡 38px）；DOM 数量恒定＝`ceil(容器高/平均行距)＋2 缓冲`，与总行数无关；mock 2000 行 DOM 行数 ≈ 可视区数
- 被否备选：不虚拟全量渲染 → 否决：万级展开 DOM 爆（v1 L102 边界）；v1 曾否虚拟滚动（与折叠冲突）→ v3 L40 实证修正：折叠行不在序列里，冲突不成立
- 接缝：吸顶路径条（S3 R-18）消费同一可视区模型；行高常量与 R-17/R-32 共用

**R-17 固定行高**
- 落点：style.css `.nav-card` 补 `height:38px; line-height:38px`；常量 `NAV_ROW_HEIGHT=38` 进 state_layers 或独立 constants
- 形态：卡行 38px 固定；**项目行保持 30px（现有 L497，不动——避免破坏既有视觉）**；混合行高由 R-16 前缀和消化
- 被否备选：全行统一 38px（含项目行）→ 否决：改项目行破坏现有视感、收益零；行高自适应多行 → 否决：虚拟滚动按行高算可视区，非固定即失效
- 接缝：与 R-32 同一 CSS 链；S3 引导线/徽章垂直对齐以此为基准

**R-32 单行截断**
- 落点：style.css `.nav-ctitle`（L573 已有 ellipsis）补 `white-space:nowrap`
- 形态：标题单行、overflow hidden、ellipsis；悬停 title 显示全称（现有 tip 拼接 L530-532 承担）
- 被否备选：标题两行换行 → 否决：行高恒定破、虚拟滚动失效；逐层缩进+换行＝标题被挤没、视觉即迷宫（v3 L71）
- 接缝：tooltip 三列已由现有 tip 承担

**R-22 异步加载交互**
- 落点：新建 `static/esm/nav_async.js`；api.js API 对象加 `getNavChildren(wid,parent)`、`getNavVersion()`
- 形态：`loadChildren(row)`——模块内 `pendingLoads = Map(cardId→Promise)` 同节点请求去重；三态流转：加载中=行内转圈（`.nav-loading`），失败=行内「加载失败·点此重试」灰字＋复位，空=叶形（`.nav-twist.none` 已存在 L567）；展开未 loaded 节点触发；折叠清数据（loaded 清 false）
- 被否备选：预拉下一层 → 否决：猜错白拉（v3 L62）；折叠不丢数据 → 否决：万级淤积内存=全量拉取没区别（v3 L62）
- 接缝：children 契约＝S1 已生效的 `/api/nav/children`（8 字段同形）；S3 搜索直达临时展开复用 loadChildren

**R-23 默认折叠策略**
- 落点：nav_render.js 首次挂载路径＋store 初始值
- 形态：默认所有项目行收起；当前项目（WORK_ID）展开一层（根卡直系，子层不展）；当前卡祖先路径逐层展开（旧 ensureCurrentPath L451-466 职责移入，偏好层记 source="system"）；**数量兜底**：展开数超阈值（100）自动收起最早的系统展开分支＋提示（v4 L99 C 档雏形；S4 才完整实现，本族只做兜底）
- 被否备选：默认全展开 → 否决：几十项目时一堵墙（v3 L47）；无兜底 → 否决：万级全展开企图无防
- 接缝：source="system" 是 S4 自动收起判据（v4 展开来源分层 L86-91）；当前卡祖先链「绝不收」是 S4 硬禁第一项
