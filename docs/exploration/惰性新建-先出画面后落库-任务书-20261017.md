# 惰性新建（先出画面，首条数据才落库）· 任务书

- 日期：2026-10-17
- 来源：用户原则原话——「别人都是先出画面，并不真的新建，只有在发出对话或者有数据更新后，才真的新建」
- 执行线：按此书施工；验收端独立复核
- 上游依据：性能实测（10-17 00:27 报告：新建项目路径 2.5–3s）+ 本轮现状钉实（下述行号均为 10-17 08:55–09:00 实读）

## 0. 一句话目标

点「新建」（项目/卡）→ **零网络、立即出画面**；此后任何产生数据的动作——发对话、**改标题**、建卡、编辑规则卡、改状态——**发生的那一刻才真正落库**；在此之前离开/刷新 → 草稿蒸发，磁盘零残留。

## 1. 现状与病根（实数）

| 入口 | 现行为 | 位置 |
|---|---|---|
| 左栏＋新建项目 | `await API.createWork("新项目")` 真落库 → `location.href` 整页跳转 | workspace.js:1430-1446 |
| 首页新建项目 | 同病（POST → 跳转） | esm/home.js:27-39 |
| 画布建卡弹窗 | 填标题点创建即 `API.createCard` 真落库 | canvas.js:1767-1778 |
| 卡详情建子卡 | 回车即 `API.createCard` 真落库 | workspace.js:466-480 |
| 左栏＋（建子卡入口） | 走卡详情 childTitle 流程（同上） | data-newchild → 卡详情 |

后端一次新建的落库量：`create_work` = 建目录 + work.json + **根卡** + git 快照（work_store.py:124-179）。

两个病根由此而来：
1. **慢**：新建项目 = POST（~130ms）+ 整页跳转（2.5–3s，性能报告实测）。
2. **脏**：点完不聊 = 留一个空壳项目在盘上（works/ 残留空项目的来源）。

## 2. 设计决策（定死，执行线照办）

**D1 · 草稿项目态，URL = `/work/draft`**
- work 页内点左栏＋：`history.replaceState` 到 `/work/draft`，本页切草稿画布态（**不整页跳转**——顺带治 2.5s）。
- 首页点新建：`location.href = "/work/draft"`（一次页面加载）。
- 后端在 `GET /work/{work_id}` 路由处特判 `work_id == "draft"`：不查库，直接渲染 work.html（约 3-5 行，**这是本任务唯一后端改动**）。
- 刷新 `/work/draft` → work.html 重新加载 → 见 draft 即重新进入草稿空态（草稿蒸发 = 从头再来，语义自洽：草稿里没有已存数据）。
- 浏览器后退 → 回来源真页。

**D2 · 落库触发点 = 一切产生数据的动作（无豁免清单）**
- 统一规则：草稿态下，**任何一个要写数据的动作，发生那一刻先走落库序列，再在真身上执行该动作**。包括：发消息（send）、改项目名/卡名、规则卡编辑保存、状态变更、建卡。
- 判据就是用户原话：「发出对话**或者有数据更新**后才真的新建」。产生数据＝落库，不设白名单、不做任何「这个不算」的自作主张例外。
- 纯浏览动作（展开/滚动/搜索/点看）不产生数据，不触发。

**D3 · 落库时序（防竞态，适用所有触发点）**
1. 任何写动作到达时若在草稿态 → 上「落库锁」（落库中再触发：排队/忽略，不许并发两次 POST）
2. 项目草稿：`POST /api/works`（title=草稿期当前标题，缺省"新项目"）→ 拿 `work_id` → `replaceState('/work/'+wid)`，更新 WORK_ID
3. 卡草稿：`POST /api/works/{wid}/cards`（title=草稿标题、parent、card_type）→ 拿 `cid`
4. 落库成功 → 在真身上执行原动作（send 继续发送流程 / 改名·规则卡保存·状态变更写进真身）
5. 落库失败：toast 报错，**保持草稿态、该动作不执行、现场保留**，可重试。已输入内容绝不丢。

**D4 · 新建卡统一改为「进草稿对话」**（第一档）
- 三个建卡入口（画布弹窗 / 卡详情建子卡 / 左栏＋）统一动线：提交标题 → **不 POST** → 直接进入该卡的草稿对话画面（标题＋「未保存」小标、消息区空、输入框聚焦）→ 首条消息**或任何数据动作（改名/规则卡保存/状态变更）**触发 D3 落库序列（若项目本身也是草稿，先项目后卡）。
- 落库后该卡自然出现在左栏/画布。
- 「画布上先摆草稿卡、之后才聊」是更重形态 → **二期，本任务不做**（见 §7）。

**D5 · 放弃语义**
- 草稿期离开 / 刷新 / 切别的卡或项目 → 草稿蒸发，**无确认弹窗**（成立前提：一切数据动作已即时落库，未落库的只剩未发送输入——零损失）。
- 边界（接受）：草稿对话输入框里**未发送**的文字随蒸发丢失，不拦 beforeunload。
- 左栏**不显示**草稿项目/草稿卡（未落库不是真的）；落库瞬间才出现，避免闪进闪出。

**D6 · 草稿守卫**
- 草稿态下 WORK_ID="draft"：所有以 WORK_ID 打的 API 读口（getCanvas 等）会被守卫拦住——草稿画布不拉数据、显示空画布；`/api/nav` 是全局快照可正常拉。
- 执行前必做核实：`grep -n "WORK_ID" static/workspace.js static/canvas.js` 全消费点清单，逐点标注草稿态行为（跳过/占位/守卫拦截），贴进执行记录。**漏一个就是运行时 404 炸页。**

**D7 · 性能与收益账（验收锚点）**
- 点新建 → 出画面 **<100ms**、网络面板 **零 POST**。
- 首条消息路径：POST works（~130ms）+ POST cards + 正常 send——用户只感知正常发送。

## 6. 红线

1. 动手前查目标文件（workspace.js/canvas.js/home.js/main.py/work.html）无他线在途改动；有则停，交协调。
2. 显式文件名 add，禁 `add -A`；提交面 = 本任务文件清单。
3. 版本戳：内容变即升号，含 work.html 外层引用（上轮双版本病教训）。
4. 不动：POST /api/works 与 /cards 的契约、规则卡机制本身（草稿态只在保存前挂落库钩子，不改规则卡逻辑）、拆页方案文件。
5. 与拆页任务的顺序：本任务先做（小、独立）；拆页阶段 1 开工前重查文件占用即可，两者无代码耦合，但**同一文件先后施工**，禁并行。

## 7. 边界与已知取舍（明示，不隐瞒）

- 未发送输入随草稿蒸发丢失（不拦、不存草稿到 localStorage——二期若用户要再加）。
- 规则卡编辑**不置灰**——保存本身就是数据动作，保存即触发落库（原「置灰」设计废弃，与 D2 统一）。
- 画布「先摆后聊」草稿卡、草稿本地暂存 → 二期。
- 首页新建仍需一次页面加载（到 /work/draft），非 SPA 瞬切——受当前架构所限，拆页后天然一致。
