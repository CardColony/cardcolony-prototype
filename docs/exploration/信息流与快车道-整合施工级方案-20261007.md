## §3 施工任务分解（可派工，含依赖；甲乙同批）

> 全部任务在同一施工批内完成并**同一批部署**（§6 铁则）。任务间依赖：T3 依赖 T1（route 判定产生事件源）、T5 依赖 T3（前端消费 SSE）、T6 依赖前五。

**Task 1 — 快车道路由分流（乙线核心）**
- 动 `routes.py`：新增纯函数 `route(content)->"fastlane"|"chain"`（规则集：建卡/删卡/改卡/查询四类消息形态，含自然语言形态，测试样本「那你倒是删掉一张啊」入回归）；L472 前插 `mode = route(content)`。
- `fastlane` 分支：跳过 three-seat 进场（L552/L555 闸后不调 `run_viewpoints`）与统合官，直接单模型 `model_service.call_main`（传 content＋tools，model_name="main"）带工具走真实落地；动作落地（卡操作经 `card_store.create/update/delete/read_card`）。
- `chain` 分支：调用现状全链，逐字不变。未命中规则自然落 chain。
- **完成标准**：确定性动作请求卷宗模型调用数 ≤1 次；无 `viewpoints` 数组；卡操作真实落盘。
- **依赖**：无（最底）。

**Task 2 — 断点同请求走到底（乙线核心）**
- 动 `routes.py`：L486 `while True` 内，让工具循环持续到产出最终交付（不再在回合边界提前结束等用户续言）；确须结束（如上下文超限型）→ checkpoint 落 `data_snapshot`，用户下条消息从 checkpoint 续。
- L644 占位符：不改其可见性（归信息流线），只确保断点不在「干一半」处把请求结束。
- **完成标准**：带工具消息单请求内工具循环走完、产出交付；日志无「续行/重入」新请求；超限型 checkpoint 落位可查。
- **依赖**：无（与 T1 独立，并行）。

**Task 3 — 事件流后端（甲线核心）**
- 新建 `src/api/event_stream.py`：内存环形事件日志（300 条／单条 8KB 截断，seq 单调）。
- 动 `routes.py`：埋约 18 处事件打点（模型每轮/工具结果/三席观点/上下文装配/建卡/交付/异常，覆盖整合版事件本体论 17 类含快车道 `fastlane_route`/`card_op`）。
- 动 `simple_service.py`：将**已存在的 on_progress 回调**（L104/L121-123）接成 SSE 事件源（非新建回调，接已有）。
- 新增 `GET stream?from={seq}` SSE 端点（刷新 from=0 重放）。
- **完成标准**：SSE 端点通；环形 300 条满则覆盖；事件不进 session/prior/模型输入。
- **依赖**：T1（route 判定产生 fastlane_route/card_op 事件源）。

**Task 4 — 快车道事件并表＋全日志打点（甲乙衔接）**
- 把 T1 的 `fastlane_route`（mode/matched_rule）、`card_op`（op/op_result，delete 应为 `{ok:true,deleted:卡号}` 形态）登记进整合版事件本体论＝17 类；同一卡操作只落一份事件（不另建日志账）。
- 全日志打点（甲乙共用）：路由判定（mode/matched_rule）、卡操作落地（op/op_result）、快车道确认（lane/calls）、断点续跳（resume_kind/no_user_visible）、占位符（placeholder_emitted）——**只写日志、不参与判定、不设闸**（拆闸裁定同口径）。
- **完成标准**：17 类事件 schema 落盘；一类卡操作对应一份事件；日志打点字段机械可查。
- **依赖**：T3。

**Task 5 — 前端展示（甲线）**
- 新建 `static/stream.js`：EventSource 连接＋过程卡渲染器（🧠轮次/🔧工具/💬三席/✚建卡/快车道 mode 事件卡）。
- 动 `static/workspace.js`：`send`/`resend` 并行开 SSE；`attachRunningState` 升级为刷新 from=0 重放。
- 动 `static/style.css`（追加过程卡样式）、`templates/work.html`（挂 stream.js 入口）。
- **完成标准**：请求进行中前端实时可见事件卡；刷新后过程回放重建；SSE 失败降级（等待气泡兜底）。
- **依赖**：T3（消费 SSE）。

**Task 6 — 同批部署＋端到端验收**

## §6 红线与禁止项

1. **POST/T10/T14 零改动**：结果通道、交付链拼接、文本抢救三项契约逐字不动。
2. **事件不进 session/prior/模型输入**：纯展示层，任何路径不得把事件喂给模型。
3. **快车道单模型去三席统合**：fastlane 不调 `run_viewpoints`/统合官；卡操作走 `card_store` 确定性函数，**不得开写侧旁路**（继承 CardDeleteDeniedError：根卡/有子卡拒删）。
4. **simple_service 缺省行为不变**：新增 on_seat 为可选参，缺省路径与现状逐字一致。
5. **`gateway.py` 禁改**（附录 B 警示）：网关流式分支只累积 delta.content、不解析 tool_calls 增量；带工具开 stream=True 会静默丢工具轮——**事件流走 SSE 通道，不触碰 gateway 流式分支**。
6. **不改 works 数据**；`_backups`/data_snapshot 只读对接。
7. **不设闸**：不设任何模型调用轮次上限/墙钟/超时硬掐（拆闸裁定）。
8. **部署走 restart_safe 正式服目录内调用**；判据拦截说明有在跑调用则等其跑完。

## §7 同批部署铁则（本方案核心，不可拆批）

甲乙两线**必须同一批完成、同一批部署**：
- 只上乙（快车道）→ 用户看到「秒回但过程还是黑盒」；
- 只上甲（信息流）→ 用户看到「事件刷屏但还是一次干一段等你推」。
两者独立验收可以，**部署必须同批**。部署顺序＝测试空间前端五任务全绿（T1-T5）→ 端到端（T6）→ 同批同步正式服 → 重启 → 收口。

## 附录 B · gateway 流式坑（警示保留，禁碰）

网关流式分支只累积 `delta.content`、不解析 `tool_calls` 增量、无 `reasoning_content` 兜底、finish_reason 必失败——带工具调用开 `stream=True` 会**静默丢工具轮**。本方案事件流走独立 SSE 通道（§3 T3），与 gateway 流式分支无交，**gateway.py 一字不动**。
