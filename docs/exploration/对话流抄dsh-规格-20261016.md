## 一、架构规格（为什么 dsh 没有我们这些 bug）

### A1. 一条扁平有序节点表——没有"轮容器"、没有"插入"
- 一切可见物＝节点（user / assistant / tool-call / reasoning(Think) / context / error…），每个节点有**稳定 key**＋**可排序 anchorSeq**。
- 渲染序＝anchorSeq 升序，**不存在任何"把过程行插到某条消息前面"的逻辑**——顺序天然由 seq 决定。
  - 依据：`ui-conversation/src/client/chat/ChatView.tsx:382-397`（`order.map(nodeKey => <ChatNodeSeat …>)`）；
  - `chat-snapshot-builder.ts:135-139`（`orderedVisible`: `sort((l,r) => l.anchorSeq - r.anchorSeq || key compare)`）。
- 中断等合成节点用**小数偏移**插进既有 seq 邻域，不搬别人：
  - `conversation-nodes/common.ts:14-19`：`interruptedAssistant: -0.9 / interruptedFollowup: -0.8 / maxTokensNotice: +0.05 / finalizedFollowup: +0.1`。

### A2. 增量装配——事件只碰它自己的节点，永不整表重算
- 节点池＝`Map<key, node>`；`apply(upserts)` 只改传入的 key；**顺序数组只在结构变化时重排，且用 `sameReferences` 判定"没变就保留旧引用"**。
  - 依据：`chat-snapshot-builder.ts:404-427`（apply：`previous === undefined || anchorSeq 变 || visibility 变 || location 变` 才算结构变化）；`:15-17`（sameReferences）。
- **行级订阅**：每行只订自己的 key，助手流式增量/工具生命周期只替换自己那一行，不碰兄弟行。
  - 依据：`ChatView.tsx:11-13` 注释（"Each ChatNodeSeat subscribes to one Node key, so Assistant deltas and Tool lifecycle updates replace only their own row without remounting it"）＋ `ChatNodeSeat.tsx:23`。

### A3. 工具调用＝一个节点两阶段（运行中→终态），call/result 合体
- `tool/call` 建节点（RunningToolCall），`tool/result` 到达**更新同一节点**（root 从 running 换成 result）。
  - 依据：`conversation-nodes/tool.ts:236-269`（match: `tool/call`→start、`tool/result`→同 id update）。
- 子调用挂父节点 subCalls（树形），不是平铺新行。

### A4. Think＝assistant blocks 里的一个 reasoning 块，不是独立通道
- 流式 chunk（reasoning-delta）累积进同一 step 的 blocks[index]；终态 assistant/message 一次给全量。
  - 依据：`conversation-nodes/assistant.ts:93-96`（reasoning-delta 累加）。

## 二、视觉规格（照抄的样式，单位 px 原值）

### B1. 列骨架（`ConversationRoot.module.css:6-45`）
- 内容列宽 **748px 居中**（`--dsh-chat-content-width: 748px`）；输入卡＝内容宽＋32px。
- 列内节拍：**flex column，gap 16px**（一条 16px 节拍贯穿）。
- 滚动容器：`scrollbar-gutter: stable`；`overflow-x: hidden`。

### B2. 用户消息（`MessageItem.module.css:4-29`）
- 右对齐列；气泡 `max-width: min(525px, 82%)`、圆角 **22px**、内距 **10px 16px**、字号 **16px/24px**。
- 无"用户消息也不能超界"复杂机制——列宽统一，右对齐即界。

### B3. Think 行（`ReasoningRow.tsx` + `ReasoningRow.module.css`）
- 默认**折叠**的单行 Disclosure：图标(14)＋标题「Think」＋分隔点(2px)＋**摘要**（跑着=最新一行、完成=第一行，ellipsis 截断，14px/24px 三级灰）。
- 运行中：行上横向扫光动画（300px 渐变条 2.6s 循环）；`prefers-reduced-motion` 时关。
- 展开：正文 **4px 0 4px 22px** 缩进、三级灰、14px/24px、pre-wrap。

### B4. 工具行（`ui-tool/…/ToolRow.tsx` + `ToolRow.module.css`）
- 折叠＝**恒一行**：16px 前导槽（工具图标；运行中=图标+行扫光；错误=红点；中断=琥珀点）＋工具名＋分隔点＋**FILL 截断摘要**（错误时＝错误第一行，红色）。
- 行整体可点展开；展开体＝**IN/OUT 双标签卡片**（输入/输出，max-height 内滚，长输出不占屏）或专用卡（terminal/read/diff）。
- 默认全折叠——一串工具调用保持可扫读。

### B5. 助手正文（`AssistantMarkdown.tsx`）
- 文档流（无气泡无框），blocks 顺序渲染：text→Markdown；reasoning→Think 行；工具头不在此渲染（独立行）；尾随「已停止」标记（中断时）。

### B6. 运行态（`ChatView.tsx:106-140` + `ChatView.module.css:69-101`）
- 整轮**一条**微光扫过的「Deep diving…」行（15s 后才出现计时钟），不逐步闪占位。

### B7. 滚动跟随（`ChatView.tsx:24,187-262`）
- 底部跟随阈值 **24px**；用户滚离即停跟随；右下浮现**回底部圆钮**(34px)；新用户消息强制回底。

## 三、映射到推演agent（怎么落地）

| dsh 规格 | 推演agent 落点 |
|---|---|
| A1/A2 扁平节点表＋增量 | `static/esm/assembler.js`：records→节点（key=身份，anchorSeq=seq±偏移）；render 层维护 Map<key, DOM>，applyRecord 只碰自己的行 |
| A3 工具两阶段合体 | assembler 已有 tool call/result 合体——保留，视觉换 B4 |
| A4 Think 累积 | reasoning_chunk 累积进该 run 的 think 节点；渲染换 B3 |
| B1 列 748px/16px 节拍 | style.css `.msgs`：max-width 748px 居中、gap 16px |
| B2 用户气泡 | `.msg.user`：min(525px,82%)、22px 圆角、10px 16px、16px/24px |
| B3 Think 行 | `.think` 折叠行：摘要+扫光+22px 缩进正文 |
| B4 工具行 | `.tool-row`：单行+扫光/红点+可展开 IN/OUT 卡（默认折叠） |
| B6 运行态 | 单条「思考中…」微光行，挂运行轮 |
| B7 跟随 | 滚动跟随 24px 阈值＋回底圆钮 |
| 用户消息即时上屏 | send() 乐观插入用户节点（key 去重，timeline 记录到达时替换） |

## 四、边界
- 不动后端、不动 timeline 契约（29 类照旧）。
- 旧 run_id 分组渲染退役——由扁平 seq 序替代。
- 既有裁定不踩：容器数 0（扁平列表本身就是无轮容器）、无装饰图标、语义标记在状态位。
