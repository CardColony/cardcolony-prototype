## 一、背景与裁定

**任务**：把「工具卡底座」定稿方案转成可施工的机器——让工具卡这个**类型**（已在册）真正拥有**按步骤自动跑起来**的机制。方案链、任务书链是这八件机器跑起来后拼装的头两份剧本。

**用户当次专项要求（逐字贴入，一条不落）**：
1. 「**不需要代码判定，不论如何都不需要代码判定结果，这他妈是最高原则**」（2026-10-09 12:38）——EC-011
2. 「**产物清单就是文档栏目**」（12:54）——EC-003 / EC-160
3. 「**主卡将没有编辑、写文件的权限，只剩调用工具卡**」（12:54）——EC-004 / EC-063 / EC-161
4. 「**写任务书吧**」（13:08）——本次派工令

**继承的最高原则（凌驾全部实现选择）**——EC-011/012/013/015/016/017/018/019：
- 代码只做四件事：执行、存储、渲染、调起提醒；**一切判断归模型**（`driver.ts` L4-5 逐字）——EC-013
- **代码只能记录"我做了什么"，不能产出"这算什么"**——EC-015
- 分界线：**IO 事实记录可留**（写盘成功没成功）／**判定结果一条不留**（产物在不在、好不好、这步算不算完成）——EC-016 / EC-017
- 质量保障＝**剧本内的复核步骤**（模型自查），不是代码里的判断——EC-018 / EC-019 / EC-150

**已定裁定（不再核、不上桌）**：闸3 owner 放宽为「子项目卡或根卡」系用户本人确认（2026-10-09 11:54）——EC-183。

**本任务书性质**：施工依据（方案 report-only 阶段已结束）；施工本身受红线 R-B 约束——EC-001 / EC-180。
