## 一、背景与裁定

**病灶**：对话回复只取「不带工具调用的那一轮」的正文——`routes.py`（测试空间，下同）L461-462 `if not tool_calls: final_reply = assistant_content`、L472 `break`；带工具调用轮次的 `assistant_content` 经 `slot.begin_round`（L483-494）只进轮槽（后台上下文），**不进会话、不进回复**；最终解析、落盘、返回全绑定末轮 `clean_text`（L572 parse、L577 append、L587 reply）。落盘型工作流的分析正文全部写在带工具轮的正文里——**分析结构性上不了屏**。

**盘上实证**（`works/work_001/sessions/session_025.md`）：同一段分析两个版本——带工具轮被末轮判定丢弃、只落一条回执；重发不带工具轮进 `resp.reply` 上屏且进会话。同一段文字挂在哪一轮，决定它到不到用户眼前。

**用户诉求（原话）**：「我认为它应该是做了分析的，只是我没收到」「我要看到的是那轮综合观点」——分析的交付目的地，从「卡片／文件」扩展到「对话」；且不得取代回执。

**本轮范围（方案裁定在册）**：只改 `routes.py` 一个文件（测试空间 `推演agent_test/src/api/routes.py`）；不设任何闸、不改会话格式、不碰 gateway、前端零改动、`prompt_log.response` 语义不动；三席观点正文本轮不做；三个待裁定全沿用默认（拼接顺序=分析在前回执在后／超长回复不折叠不截断／三席观点本轮不做）。

## 三、任务分解（全部落测试空间，正式服零触碰）

### 任务 1 · 采集带工具轮的分析正文
- **1-1** 在 `routes.py:402` 声明位旁新增局部变量 `analysis_parts: list[str] = []`。
- **1-2 采集接缝（结构性关键）**：在 `routes.py:483-494` `slot.begin_round(...)` 处，将该轮 `assistant_content`（含 `routes.py:449` 抢救处理后的正文）同步追加进 `analysis_parts`。**只读采集**——不修改 `begin_round` 的入参结构、不额外 append 进槽（T11 轮槽的消息条数与配对不变量不得破坏）。
- **1-3 只收带工具轮的正文**：纯对话轮（无 `tool_calls`）走 `L461-462` `final_reply` 分支、不进 `analysis_parts`；`analysis_parts` 全量收集、不限长、不折叠、不截断（待裁定 2：超长回复原样交付，需折叠另立 Phase 2）。

### 任务 2 · 拼接「分析在前、回执在后」
- **2-1 落位**：`routes.py` 工具循环结束、日志写（`L540`）**之后**、`parse_proposals`（`L572`）**之前**插入拼接段。**此顺序是命门**：插在日志前会污染 `prompt_log.response` 语义（红线 8）。
- **2-2 拼接式**：`delivered = "\n\n".join(analysis_parts + [final_reply])`——分析在前、回执在后、`\n\n` 分隔（待裁定 1）。
- **2-3 边界（V7）**：`analysis_parts` 非空且 `final_reply` 空 → `delivered = "\n\n".join(analysis_parts)`（只交付中间轮）；两者皆空 → `delivered = ""`（空回复）；`final_reply` 非空且 `analysis_parts` 空 → `delivered = final_reply`（纯对话轮原样、回归不变）。
- **2-4** 拼接后 `final_reply = delivered`。

### 任务 3 · 日志 response 保持末轮
- `routes.py:540` **本行不动**（`response=final_reply if error is None else None` 保持原样）。因任务 2 拼接插在 L540 之后，此时 `final_reply` 仍是末轮 clean_text——日志 response 自然保持末轮、语义不变。可加一行注释说明「response 保末轮供审计；交付全文（分析+回执）可经会话/prompt 日志复核」。

### 任务 4 · 解析／落盘／返回全走拼接全文
- **4-1 解析（B2，扫描规则定格）**：`routes.py:572` `parse_proposals(final_reply or "")`——扫描输入＝拼接后全文（含分析正文）。**照既有机制运行**（`card_proposal.py:151-159` 双形态提取＋`L141-145` 按 `card-proposal:` 协议头识别＋全局剥离），**不新增筛选逻辑、不设闸**；误扫防护靠既有协议头识别（普通分析正文不含协议头即不命中）。
- **4-2 落盘**：`routes.py:577-578` `append_message(...)`——落盘＝拼接后 clean_text（reply 与落盘同一变量）。
- **4-3 返回**：`routes.py:587-588` `"reply": clean_text`——返回＝拼接后 clean_text。
- **4-4 配对不变**：仍是单次落一条 assistant（一次 append_message），pair_id 原样传入；B3「assistant 条变长但仍一条、配对 1:1」由此保证。
- **4-5 时序约束（不得破坏）**：`L577` 落盘 → `L583` 回合末凝练触发 → `L587` 返回，**顺序不可变**；任务 2 拼接段只于 L540–L572 之间，不得移动或插入到 L577–L587 之间。

### 任务 5 · 回归与兼容防线
- **5-1 不新增字段**：`session_store.append_message` 签名（`model=None, pair_id=None`）不动（复核见待侦察 R3）。
- **5-2 纯对话轮回归**：经任务 2 分支 `delivered = final_reply` 原样，reply 与改造前逐字相同。
