**日期**：2026-10-08
**口径来源**：总工三轴——循环不规范 / 工具不规范 / 信息流混乱。明确不治病历：轮次无上限、main 席重试（"只要在解决问题就没问题"）。
**对标底座**：OpenAI Agents SDK（官方 running-agents 文档 + 源码级资料）、LangGraph（官方指南）、Claude Code Agent SDK（官方 agent-loop 文档）、Cline（开源实现）。
**验证设施**：T-0009 金样本三剧本（tests/_golden/）复用；全量 pytest 基线 108/107/0/1（2026-10-08 时点，带时点引用）。

## 〇、对标的收敛规律（方案全部出自这里，不拍脑袋）

1. **循环**：继续/终止/中断的判定 = 类型化枚举（OpenAI NextStep 四值）；state 可序列化、逐步可 checkpoint（LangGraph checkpointer / OpenAI RunState 恢复）；**取消是一等控制输入**（AbortSignal / interrupt()），**上限只是可选安全网**（max_turns=None 可关）——上限不重要、取消必须有。
2. **工具**：错误作为数据回模型、循环继续（OpenAI `return_error_to_model`，与 rescue 哲学同源）；统一整形点（OpenAI toolErrorFormatter）；中央协调器+注册表+执行前校验（Cline ToolExecutor）；id 全局唯一按 id 配对；**一家只维护一条正式动作通道**。
3. **信息流**：单一条目流/单一 state，消费者全部投影（OpenAI `_generatedItems: RunItem[]` / Claude Code 五类消息一条流 / LangGraph state+reducer）；OpenAI 文档原话：会话状态"选一个策略，混用必重复上下文"。

## 一、现状诊断（按三轴，证据到行）

### 1.1 循环不规范
- `continue` 一种 outcome 混三种续跳（tools_executed / text_rescue / synthesize_needs_tools，message_runner.py:277/377/430）。
- 轮边界靠伪 user 消息维持（"工具结果已返回。" :372；抢救回注 :276；首轮原文 append_plain :294）——user 角色被当控制信号。
- phase 只活在 SSE 事件字段（:221/235/417），循环自身无阶段概念；阶段判定靠 seats_done/mode/rounds 散落分支。
- 轮无规范记录（RoundRecord 不存在）；RunState 不可序列化，崩溃即丢；stop_requested 全库零置位点。

### 1.2 工具不规范
- 结果裸 `json.dumps` 回灌（:365），成败靠 `"error" in result` 嗅探（:338），错误无分类。
- `tool_call_id` 每轮重编 `call_{i}`（:304/364），同一份 messages 多组同 id 配对——违协议，B-07 未实测。
- 动作通道三轨：native tool_calls / rescue 五形态 / fenced card-proposal；create_card 双通道+跨通道去重（:534-559）。

### 1.3 信息流混乱
- 一份工具结果手工抄四份：slot（主模型）/ tool_full_texts（三席）/ tool_events（响应体）/ prompt_log；assistant 正文另抄 analysis_parts。B-17 重复拼接 artifact 即此类病。
- UI 四通道语义重叠（SSE/tokens/progress/HTTP 体），done 靠 setTimeout(2500) 赌（workspace.js:850）。
- 模型面消息靠就地 mutate 共享列表（history_len 快照陷阱 :85-89 为自踩实例）。

## 三、W2 · 工具规范化

### 3.1 结果信封
- 契约：`{ok: bool, data: any, error: {code, message} | null}`。
- 错误码固定枚举：`denied`（权限拒绝）/ `not_found` / `locked`（423 锁超时）/ `validation`（参数错）/ `internal`。模型可程序化区分"换策略"与"可重试"——对应 OpenAI toolErrorFormatter 的统一整形点。
- 落点：`card_tools.execute_tool` 出口统一包信封；`message_runner` 的 `ok` 判定改读信封（:338），回灌模型的文本由信封投影生成（不再裸 dumps 内部结构）。
- 兼容：信封只改模型可见文本的组织方式，不改工具行为本身。

### 3.2 tool_call_id 唯一化
- `call_{run前缀}_{seq}`，run 内单调、跨轮不重号。run 前缀取 pair_id 短哈希，可审计可对账。
- 顺手闭合 B-07（真 API 是否拒绝重复 id 的实测项）：唯一化后该风险结构性消失，实测降为观察项。

### 3.3 通道收敛
- create_card 只留工具通道（正式通道已成熟，文本通道本就定位过渡）。
- 文本 card-proposal 协议块降为 rescue 兼容层：仍解析执行（防旧习惯模型），但每次触发计数落 prompt_log，供后续观察何时可撤。跨通道去重逻辑随之删除。
- **此条改变模型可见协议，属总工裁定项**：点头才动工。

### 3.4 判据
- 契约测试：信封结构 + 五错误码各构造一条用例钉死。
- 金样本：tool 消息文本形态有意变更 → 三剧本重抓重钉（在 manifest 记"协议变更钉"）。
- 全量 pytest 绿数不降。

## 四、W1 · 循环状态机

### 4.1 phase 一等化 + 迁移集中
- RunState 增 `phase` 字段：`assemble / round_main / tool_exec / seats / synth / deliver / error / stopped`。
- 迁移集中为一个纯函数 `next_phase(state, outcome) -> phase`（LangGraph 条件边的对应物）；step/run_seats 不再各自判定阶段，只报 outcome，迁移表一处可读可审。
- SSE 的 phase 字段改从 state.phase 投影（消灭"事件里一套、循环里一套"）。

### 4.2 中止链（取消=一等控制输入，对标 AbortSignal/interrupt）
- run 注册表：`(work_id, card_id) -> RunState`（进程内 dict，和 progress 同层）。
- `POST /works/{w}/cards/{c}/messages/stop`：查注册表置 `stop_requested`。
- `check_control` 消费：发现置位 → 返回 stopped 语义，走 handle_error 正常收口（checkpoint/error 事件/prompt 日志全复用，不落 assistant 条）。
- 前端：发送按钮在跑时变停止按钮（唯一 UI 改动）。

### 4.3 同卡 run 串行（注册表副产品）
- 注册表占坑即锁：同卡第二请求 409 + 明确文案（"该卡有任务在跑"）。不排队（排队是产品决策，标杆也无此物）。
- 消灭 prior 竞态（routes.py:550-575 读历史与追加用户消息之间的窗口）与 SSE 互清。

### 4.4 判据
- 迁移表单测：全状态×全 outcome 的合法/非法迁移钉死。
- 中止用例：模拟 stop 置位，断言下一个 step 边界收口、checkpoint 落、assistant 不落盘。
- 并发用例：同卡双 POST 必有一 409。
- 金样本三剧本 9/9 逐字节一致（W1 不动 wire 投影）。

## 五、W3 · RunJournal 单一事实源

### 5.1 条目流
- `journal: list[RunItem]`，RunItem = `{seq, id, type, payload, ts}`；type 枚举：`user_msg / model_call / tool_call / tool_result / round_boundary / seats_event / deliver / error`。
- reducer 纪律：append-only + 按 id 去重（LangGraph add_messages 的对应物）；任何组件不得绕开 journal 自建副本。

### 5.2 六消费者全部投影化（纯函数，零 IO 在投影内）
| 消费者 | 现状 | 改后 |
|---|---|---|
| 主模型 wire messages | 轮槽就地 mutate | `project_wire(journal, fold_policy)` |
| 三席注入 | tool_full_texts 手抄 | `project_seats(journal)` |
| SSE 事件 | 循环内散落 emit | `project_events(journal_tail)` |
| prompt_log | 多源拼装 | `project_log(journal)` |
| HTTP 响应体 | tool_events 手抄 | `project_response(journal)` |
| session 落盘 | 独立追加 | `project_session(journal)` |

- `tool_full_texts` / `analysis_parts` / `tool_events` 三个手工副本当场删除。
- T14 拼接改为投影规则（分析段=journal 中带工具轮的正文条，回执=deliver 条），拼接逻辑离开循环体进投影函数。

### 5.3 落盘 = checkpoint（对标 LangGraph checkpointer）
- journal 每轮边界追加写 `works/<w>/sessions/.journal/<pair_id>.jsonl`（隐藏子目录，不污染会话文件）。
- 崩溃恢复：重启后若存在未 deliver 的 journal，下一条消息可从最近 round_boundary 续跑（首版只恢复不自动续，恢复动作走确认）。
- data_snapshot 的 run 级 checkpoint 保留（粒度不同：快照管数据，journal 管编排）。

### 5.4 判据
- **同源性测试**：同一 journal 六投影各自重建，交叉对账（wire 里的 tool 结果 ≡ 响应体的 tool_events ≡ 日志的 prior_messages 尾段）。
- 金样本三剧本 wire 投影 9/9 逐字节一致。
- 崩溃恢复用例：模拟中断 → 从 journal 重建 RunState → 续跑 deliver，与无中断路径终态一致。
