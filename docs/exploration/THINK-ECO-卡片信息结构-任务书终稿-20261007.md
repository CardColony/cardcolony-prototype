## 一、背景与裁定

### 1.1 现状：卡片正文的分区结构是继承来的硬编码

卡片正文现用「四区」结构（职责区／结论区／否决记录区／修改历史），系写作 agent 遗产。该结构在代码里硬编码而非可配置：渲染器写死四个区头（`card_store.py:227`／`:230`／`:233`／`:236`），区名→键映射写死（`hash_utils.py:106-111`），读卡固定返回四键（`card_store.py:461-471`）。〔`P-001`〕

结构缺陷两处：**其一**，六类信息只有一个正文落点——模型经 `edit_card` 传入的整篇正文被硬编码塞进 `conclusion` 一个键（`card_tools.py:348-351` 逐字 `{"conclusion": content}`），决定、事实、指针无各自落点；**其二**，权威语义无机械兜底——现状 `update_card` 只消费 `charter/conclusion/rejections` 三键（`card_store.py:540-546`），既无区分字段，也无拦截。〔`P-002`〕

不做会留下两项后果：决定可被静默改写且不可追（`edit_card` 是覆盖写，一次调用即可抹掉既有定论条目）；事件流水与状态快照混住（无任何分区约束阻止时间线堆进主卡）。〔`P-005`〕

**同批线路实测坐标**：权限线**已施工完毕**（`card_tools.py:238-257` 已是全盘放开新态）；信息结构线**零落地**（`status_block|rulings|## 使命|## 现状|## 定论|mission` 在 `src/` 全库零命中）；快车道线**并发进行中**（`routes.py:472` 前新增 `route(content)`）。〔`P-006`〕

### 1.2 目标态：三块新结构替代旧四区

| 块 | 语义 | 写入规则 |
|---|---|---|
| 使命（`mission`） | 本卡作用/目标、授权来源 | 立项定稿；模型改→拒绝，用户可改 |
| 现状（`status_block`） | 当前状况快照 | 覆盖写·单一最新；只写已核实；事实带锚点自指 |
| 定论（`rulings`） | 对本卡事项的决定 | 只追加；失效用就地标记 `→ 被D{nn}取代`；不设已废区 |
| 修改历史 | 系统机械尾 | 机制不动，不设闸、不参与 diff |

**六类信息各有唯一的家**：作用/目标→使命｜当前状态→现状（带锚点）｜决定→定论｜事件/过程/迭代→影子·进度与迭代历史｜文档/代码指针→影子·产物清单（主卡现状块尾一行衔接索引为入口）｜观点/推理/未核实→对话流（不落卡）。〔`P-003`〕

**现状与影子的分工（防流水账侵蚀）**：同一事件两种视图——影子·进度记事件，主卡·现状记态。现状永远是覆盖写快照，不是时间线。〔`P-004`〕

**条目语法**：`D{nn}【来源】内容（日期·依据）`。来源三类——【裁定】用户裁决·带轮次／【决定】本卡取舍·带依据／【收敛】推演收敛·带死过什么。**序号终身不改**（供失效标记引用）。〔`P-069`〕

### 1.3 设计枢纽（一句话）

把「模型改卡」从**键级覆盖**改为**正文级分区写**——`edit_card` 交整篇正文，新旧两份都过拆分器、按分区 diff 判闸，放行才整篇写回。〔`P-029`、`P-030`〕

`update_card` 的键级 `updates` 通道保留（供 HTTP 与内部调用），正文级通道另立（供 `edit_card`）——两者共用同一套拆分/渲染内核，不产生第二套真值。〔`P-031`〕

### 1.4 已裁定事项（含一条明确否决）

- **四期分期**：S1 骨架与说明（零逻辑改动）→ S2 拆分器双表 → S3 写入闸 → S4 死字段清理。〔`P-087`~`P-090`〕
- **S3 依赖 S2**：判据源为分区 diff，由 S2 提供——**S3 不可先于 S2 单独上**；S1／S2／S4 可独立上退。〔`P-089`、`P-091`〕
- **★明确否决项（不得实现）**：**锚点不做机械强制**——方案逐字否决「含锚点才放行」，理由「机械强制会激励伪造锚点，伪证比缺证更伤权威机制」。现状块语义规则（覆盖写·单一最新；只写已核实；事实带锚点自指）**为语义纪律，不做机械校验**。〔`P-058`、`P-059`〕

### 1.5 边界（不属本线，不得扩张）

权限体系（跨卡读影子、管辖判定、访问控制）→ 独立任务，S3 闸不属此列；读侧注入（清单摘要、权威标注入上下文）→ 独立任务；类型退役（`card_type` 词表）→ card_009 域，本设计仅保证 `create_card` 默认骨架不依赖类型字段；`content_hash` 语义 → 不动（理由逐字「只算正文会导致存量哈希一次性全失配」）；`role/status` 字段复活 → 不做。〔`P-084`〕
