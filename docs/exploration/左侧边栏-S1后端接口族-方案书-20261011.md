## 一、为什么做这件事

**第一轮＝后端接口族，是后面三族的地基。**

左侧边栏重做共四族：S1 后端接口 → S2 前端渲染体系 → S3 交互与呈现 → S4 自动组织，严格串行（每条链的产出是下一链的输入）。S1 是全部前端阶段的数据输入源头：

- S2 渲染体系要消费的**行对象字段**（含 work_id、state、child_count、时间戳）来自 /api/nav 契约；
- S2 的异步加载消费 `/api/nav/children`；
- S2 的 60 秒探测源消费 `/api/nav/version`；
- S3 修「点任意卡展开股权财政」bug 要用卡对象的 work_id（前端 L455 裸 id 反查项目是今日 bug 之源）；
- S4 自动层「已归档」档消费卡的 state 字段。

**S1 只造通道与数据，消费切换归 S2/S3/S4 决策**——S1 阶段三通道并存、全部可用、零前端改造。

## 三、设计（六条逐条：落点 / 形态 / 被否备选 / 接缝）

### R-01 契约补 work_id

| 项 | 内容 |
|---|---|
| **落点** | `routes.py` L188 卡对象 dict 加一行（`wid` 已在 L172 循环变量） |
| **形态** | `"work_id": wid`——归属由提供方声明，前端禁止自行推断 |
| **被否备选** | a) 前端从父级遍历推断——**否决**：十个调用点十种猜法，正是今日 bug 根源（workspace.js L455）；b) 全局唯一编号迁移——**否决**：全量迁移画布/连线/会话/台账，而病根不是"不唯一"是"没声明" |
| **接缝** | 只增字段不删不 rename → workspace.js 现有消费忽略多余字段，不崩 |

### R-02 字段克制（成文定格，零代码改动）

| 项 | 内容 |
|---|---|
| **落点** | 零代码改动；契约文档写明字段集合 |
| **形态** | 字段集合＝**8 项**：card_id/title/parent/child_count/last_active_at/branch_active_at/**work_id/state**。克制判据＝「有这个字段就有一个已设计的消费方」（work_id→S3 修 bug；state→S4 归档档；child_count→展开箭头；时间戳→排序/徽章）；没有消费方的字段不进契约 |

### R-06 版本号探测端点（新建）

| 项 | 内容 |
|---|---|
| **落点** | `routes.py` children 端点后新增 |
