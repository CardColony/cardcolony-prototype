## 2. 项目位置与接口规范

### 输入接口

- **快车道输入**：用户消息原文 `content`（生产方=`routes.py:472`，消费方=新路由决策 `route(content)`）。判定对象=这条消息文本本身。
- **断点续跳输入**：断点前已产生的上下文——工具结果以 `role:"tool"` 已在 prior 内回喂，复用具既有 `routes.py:486 while True` 循环，不新建请求。
- **三席/全链输入**：维持现状不动（`simple_service.py` 文件头 L4-6 三席后置、统合官 call_main）。

### 输出接口

- **快车道输出**：单模型 `call_main` 带工具直答——卡操作由模型发工具调用（delete_card/create_card/update_card）**真实落地**，只去三席与统合官，不再「系统代码直接落盘」。卷宗日志可证：模型调用=单模型（无三席 viewpoints 数组）。
- **全链输出**：现有三席+统合交付一字不变。
- **断点续跳输出**：同一请求内把工具循环走到底直到产出来最终交付；确须结束时 checkpoint 落 data_snapshot、下一条消息从 checkpoint 续（§4-B 定案）。
- **不新增存储、不动 `_backups`/git 数据链**（checkpoint 接 data_snapshot）。

## 4. 方案正文

### 设计点 A · 快车道路由分流＋单模型带工具落地（按裁决①修订）

**改动锚**：`src/api/routes.py` L472 用户消息入口（`user_prompt = content` 赋值处）之前；新增纯函数 `route(content)` 本体。

**设计**：
- 新增 `def route(content: str) -> str` 纯函数，返回 `"fastlane" | "chain"`。判定逻辑＝确定性动作规则集（建卡/改卡/删卡/查询，含自然语言形态——「那你倒是删掉一张啊」作 R3 待测样本）。函数纯、无副作用、可单测。
- `routes.py:472` 前插入 `mode = route(content)`。
- **`mode=="fastlane"`**：跳过三席入场（`routes.py:471 seats_done` 之后的 `simple_service.py` `run_viewpoints`）与统合官交付，改走**单模型带工具直答**——单次 `model_service.py:45 call_main`（该带工具就带工具），卡操作由模型发工具调用（delete_card/create_card/update_card）**真实落地**。快车道只有这一个模型，不叫三席、不叫统合官。
- **`mode=="chain"`**：走现状全链，调用流程逐字不变。未命中规则自然落 chain（保守不误判）。
- **为什么这样切**：用户裁「删卡这类活也走模型、但不走三模型」——快车道=单模型直答、卡操作仍走模型工具真实落地，重链里被去掉的只是三席与统合官；快车道比全链省的是 3 个观点席+统合官=4 次调用降到 1 次单模型带工具。
- **不动**：三席进场机制（`routes.py:471/552 seats_done`）、统合交付、`simple_service.py` 现有编排——全链路径一个字节不变。

### 设计点 B · 断点处理（用户裁决②·已由诸葛实查成因定案）

**断点成因（实跑定案，非推测）**：全量扫描今日全部 prompt_*.json 的 error/response 字段——error 字段几乎全量 null（仅 3 条异常：09:37/09:52 两条 `Logger._log() count` 参数 bug〔已修、非断点相关〕、14:09 一条 `ContextWindowExceededError`〔158 万 tokens 超限、已另案〕），response 几乎全量完整落盘。**结论：断点不产生任何服务端错误——它不是故障，是编排层的回合边界与续跳接缝机制**：一条带工具任务被编排成多个回合，回合间以「工具结果已返回。」标记衔接；用户在回合边界停住＝感知「断」；用户续言→新请求→整链（主模型＋工具循环）重走一遍＝感知「从头白跑」。等待久的根是最慢席 109s＋多工具轮串行，不是「断」本身。

**定改法**：
- 让一条任务在**同一请求内**把工具循环走到底直到产出最终交付（`routes.py:486 while True` 骨架已支持、续跳轮 `L498-509` 已同请求内继续），不再在回合边界提前结束请求等用户续言；
- 确须结束时（如上下文超限 14:09 型），**checkpoint 落 data_snapshot 持久化未走完的工具上下文**，用户下一条消息从 checkpoint 续走，而非全链重跑；
- 占位符「工具结果已返回。」的**可见性处理挂起**，归「信息流调整」线（裁决③），本方案不处理其可见性，只改「回合是否提前断」。

**对账记账**：p0 底册 C-16 原「治 R3＋R4c〔断点→真循环重放；六字占位符随断点治理自然消失、中间态不进用户流〕」——因用户裁决③，占位符部分**挂起撤出**（归「信息流调整」线），本方案仅保留「断点不平白重开新请求」一条；**非漏项，系用户裁决收窄**。
