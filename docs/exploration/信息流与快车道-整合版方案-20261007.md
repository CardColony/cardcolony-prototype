**断点真实成因（诸葛 21:03 实跑定案，乙§4-B L59）**：今日全部 `logs/prompt_*.json` 的 error 字段**几乎全量 null**（仅 3 条例外：09:37/09:52 两条 `Logger._log() count` 参数 bug〔已修〕、14:09 一条超长上下文〔单事件〕——都与"断"无关），response 字段几乎全量 LONG（每个请求服务端都正常完成并产出回执）。**结论：断点不是服务端故障（请求失败/超时/网关断开），是编排层的回合边界＋续跳接缝机制**——带工具的活被切成多段，段间停下等你接话。15:24 日志系统内模型自述「编排层的续跑接缝（…）非故障，接得正常」与机器层 error=null 互证：这是机制，不是坏了。

## §4 事件本体论与 Schema（含事件并表）

### A. 事件取代占位符（裁决③的落地）

现状：`routes.py:644` 的 `user_prompt = "工具结果已返回。"` 六字占位符反复出现在用户可见会话流（session_015 三条、session_024 一条），暴露断点、逼用户人肉搭桥（session_019 断点 19 轮、桥 12 次）。

改造：用**结构化事件流**取代占位符——每一步真实状态以事件卡形式展示，用户不再看到黑话占位符，而是看到「🧠 模型第2轮思考中 / 🔧 正在删卡… / ✅ 卡已删除」这类可直接读的过程。（甲§三 L38-47 六断点逐条被事件覆盖）

### B. 事件本体论：15 类＋并入 2 类＝17 类（接口①落实）

甲方案 15 类事件（甲§四 L64-70）：run_start / context / model_round / tool_call / tool_result / seat_enter / seat_opinion / integrate / card_create / card_confirm / delivery / anomaly / resume / fold / done。

**并入乙的 2 类**（乙全日志打点 L72-74）：
- **`fastlane_route`** —— 快车道路由判定结果：字段 `mode`（fastlane/chain）、`matched_rule`（建卡/改卡/删卡/查询/未命中）；
- **`card_op`** —— 确定性卡操作落地：字段 `op`（create/update/delete/query）、`op_result`（如 `{ok:true, deleted:"card_029"}`）。

**为什么并**：同一个删卡动作，若乙打点进审计日志、甲事件进展示流，就落两本账。并表后乙的 `card_op` 即甲展示层的一张卡事件，单一来源、单一呈现。

### C. Schema

每事件：`{seq: 单调递增, ts, type: 17 类之一, data: 字段依类型，正文超 8KB 截断折叠}`。写 `event_stream.py` 环形缓冲 300 条、单条 8KB 上限（甲L76）。Schema 严格随事件类型固定、不自由扩展（甲§四 L72）。

## §5 后端改动

### A. 快车道路由分流（乙§4-A + 裁决①）

- 新增纯函数 `def route(content: str) -> str`，返回 `"fastlane"|"chain"`。判定=确定性动作规则集（建卡/改卡/删卡/查询，含自然语言形态——实跑样本「那你倒是删掉一张啊」作待测样本挂进规则验收）。函数纯、无副作用、可单测。（乙L50）
- `routes.py:472` 前插入 `mode = route(content)`（乙L52；如同一处同时埋 `fastlane_route` 事件——接口①）。
- **`mode=="fastlane"`**：跳过三席/统合入场（`routes.py:471 seats_done` 之后的 `simple_service.py run_viewpoints`），走**单模型 `model_service.py:45 call_main` 带工具直答**——用户让它删卡，仍由模型调 `delete_card` 真实删掉，只是不再叫那三个思考席与统合官（裁决①）。动作落地后一并埋 `card_op` 事件（接口①）。
- **`mode=="chain"`**：走现状全链，一字不变。未命中规则自然落 chain（保守不误判）。（乙L55 不动红线）
- **不动**：三席进场机制（`routes.py:471/552 seats_done`）、统合交付、`simple_service.py` 现有编排——全链路径一个字节不变（乙L55）。

### B. 断点走到底＋checkpoint 续（乙§4-B + 裁决②）

- 保留 `routes.py:486 while True` 同一请求内工具循环骨架（工具结果已 `role:"tool"` 同轮回喂，真凶不在回喂、在回合边界把请求提前结束）。
- 改为**同一请求把工具循环走到底直到产出最终交付**——不再干一段停一段等你推（对应甲的事件源连续性：事件随循环实时推）。
- 确须结束时（如上下文超限 14:09 型）：**checkpoint 落 data_snapshot 持久化未走完的工具上下文**（对接乙L54 既有基线），用户下一条消息从 checkpoint 续、而非全链重跑。
- 占位符「工具结果已返回。」的**可见性**归信息流线（甲）处理——本方案用事件流取代它（§4-A），乙不改其文本、只改"回合是否提前断"。

### C. 过程事件埋点

- 新模块 `event_stream.py`（环形 300 条/单条 8KB，甲L76）。
- `routes.py` 埋点约 18 处（甲L77）＋快车道两处（`fastlane_route`、`card_op`，接口①）。
- `simple_service.py` 增 `on_seat` **可选参数**（甲L78）——缺省行为不变，不破坏乙「一个字节不变」红线。
- `POST`、`T10`、`T14`、审计链路**零改动**（甲§八红线，全文守住）。
