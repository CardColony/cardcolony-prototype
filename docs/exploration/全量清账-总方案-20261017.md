## 〇 · 目标一句话

## 验收总标准（每场战役过三关，缺一不算完）
1. **人类走查关**：真实鼠标键盘把该链从头走一遍，每步操作 ≤300ms 内有可见反馈，全程零静默失败（操作发出、界面无反应、也无报错＝静默失败，最恶劣类）。
2. **对照关**：与真页面/既有正确路径对照，行为不可区分（脚本断言，不靠"像"）。
3. **回归关**：该链 e2e 断言进测试库（以后不依赖任何人的手工探针）。

## 一 · 七场战役（按痛排序）

### 战役1 · 建项目流程重写
- **现状（已走查，实测）**：点＋落地空白画布（0卡+「未保存」标+教学文案）；根卡对话页是假界面——消息 POST 真到后端但气泡永不上屏（显示绑临时板 `new-N`、写入走真板，写的板≠看的板，workspace.js:235-238 vs :894-900）；落库完成时多一次整页二次加载 +2s。
- **依据**：方案v2 已走查落库（建项目流程-重写方案v2-20261017.md）。
- **修法方向**：三入口统一直达根卡对话草稿页；落库后先换绑显示板再走原有发送路径（一字不改）；退役空白画布/未保存标/教学文案（grep 零引用后删）。
- **验收**：草稿页 vs 真项目根卡页跑同一动作序列，脚本断言不可区分；失败注入（mock 500）→ toast、输入保留、重试能成。
- **状态**：方案在库。**首个开工**。任务书待落。

### 战役2 · 性能四刀
- **现状（实测 10-17 00:24–00:27）**：肥卡（263KB 历史）打开 1.0–1.3s；跨项目点卡 2.5–3s（整页重载）；每次点卡全量重拉 25KB 导航 +400ms（version 探测机制在但 open() 不走）；card-messages 被拉两遍 +640ms（workspace.js:1819/1868 两入口）。
- **修法方向**：① 点卡先切视图再填内容（workspace.js:141-165 顺序重排）② open() 导航刷新走 probeVersion ③ 肥卡只建视口内节点或缓存装配结果 ④ 跨项目点卡局部换数据不整页跳（workspace.js:602）⑤ 消息接口去重。
- **验收**：点卡→可见反馈 <300ms；肥卡 ≤0.5s；跨项目 ≤0.5s；Network 断言零重复拉取。
- **依赖**：与战役1同手术区（workspace.js open/send）——**必须排在1后串行，禁并行**。

### 战役3 · 假控件清账
- **现状（实测）**：画布缩放三键（zoomIn/zoomOut/zoomSlider）全仓零 JS 绑定＝纯摆设；「删除项目」后端端点不存在（`delete_work` 零命中）而界面摆着置灰入口；两者与"删除按钮像占位"同病。
- **修法方向**：zoom 三键真绑（画布缩放是真需求，做绑定不做撤除——待用户点头）；项目删除新增后端端点（守卫：非空项目二次确认；与卡删除同款防孤儿纪律）。
- **验收**：页面上每个可见控件点下去有真反应；写一个"有 DOM 无绑定"扫描断言进测试库。
- **待用户定**：zoom 绑定 vs 撤除；项目删除做不做（做＝新增后端能力）。

### 战役4 · 运行中状态补全
- **现状（实测）**：打开 /work/work_002 时左栏看不到 work_002（按活跃排第 11 位在视口外、openPheads=0，"进页自动定位到当前项目"路径未生效）；CancelledError 疑点（继承 BaseException，routes.py:893 的 except Exception 抓不到——客户端断连后"运行中"可能永挂，10-13 报过未验证）。
- **修法方向**：① 进页自动滚到当前项目+撑开当前卡路径 ② 断连场景实测钉死→补终止态写入（except BaseException 或 finally 收尾）。
- **验收**：打开任何项目页，该项目在左栏可见且路径展开；断连后运行中状态 ≤N 秒消失（N 实测定）。

### 战役5 · 数据脏归位
- **现状（实测 10-12）**：93 卡 updated_at 被 refresh_perms.py 顶成同一时刻（10:27–10:28），左栏"最近排序/活跃徽章/时间提示"整体失真至今。
- **修法方向**：从会话文件真实时间（works/*/sessions/*.md 的 mtime 与内容时间戳）回捞每卡真实活跃时刻；修批量脚本不再无条件刷 updated_at（touch 参数化）。
- **验收**：左栏排序与真实最后会话时间一致（抽样 20 卡人工对账）；脚本侧加断言防复发。

### 战役6 · 地基硬化
- **现状（实测）**：31 条既有红测试（19=stream_dual_delta/stream_tool_calls 属 gateway 重写、12=models.yaml 换模型+跨用例污染）；根路径 500（index.html 被改名，GET / 报 FileNotFoundError）；版本戳全靠手工纪律（10-16 至今漏升至少两次，每次都是"我改了你看不到"）；模块口径语法检查不进常规流程（saveRuleSection 事故的盲区）；Temp 下 63 个历史沙箱根（卫生债）。
- **修法方向**：红测试逐条归零（修断言或修代码，逐条归类不搞一刀切）；根路径指回真实首页或重定向；版本戳升号+模块图+语法扫描做成一个提交前检查脚本（一条命令跑全）；沙箱根批量清理+启动脚本自回收。
- **验收**：全量 pytest 0 fail；GET / 200；提交前检查脚本存在且被执行（写进任务书模板红线）。

### 战役7 · 全链人类走查（贯穿性战役）
- **现状**：只有建项目链被完整走查过（一次走查挖出三个问题，其中一个是静默失败）——**建卡、规则卡、删除、搜索、切项目、画布交互、通知，零走查记录**。按此发现密度，未走查链上还有多少问题，没人有资格说"没有"。
- **修法方向**：每条链按建项目链的标准走查（真实鼠标键盘、每步录证据、静默失败专项排查）→ 发现的问题按严重度入战役清单追加战役。
- **验收**：每条链一份走查报告落库；发现的问题全部入账有归属（修复或明示挂账理由）。
- **定位**：不单独排期——**与每场战役的验收关绑定**（打哪条链走哪条），另在建项目+性能两仗打完后做一轮全链普查补盲区。
