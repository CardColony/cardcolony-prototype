## 0. 为什么有 v4（三笔账）

1. **根卡对话在导航里点不进**。T17 规格「根卡不进树」（card_018 §十一.1 任务4）把项目主对话做成了导航死角；实测：导航组头点击绑的是纯折叠/展开（workspace.js 事件委托段），组内也无根卡行。本系统每张卡都是对话，**根卡对话＝项目主对话**（本系统独有的一等公民），必须一键可达。
2. **拿"通用 agent 会话列表"当模板套在树上**——学了列表的皮（分组/高亮/时间戳），丢了本体（树、档案、画布、根对话）。导航只做了"看"，没做"走"（无键盘、无路径、组头点不进）。
3. 前几轮把精力耗在编号/任务书治理上——非设计职责，废止（见 §7）。

## 1. 原生模型与五公理

**模型一句话：每张卡＝一个对话＋一份档案，长在一棵树上；画布是这棵树的空间地图；根卡对话＝项目主对话。**

| 公理 | 含义 |
|---|---|
| A1 无死角 | 任何卡（含根卡）的对话一键可达；界面不允许存在"点不进"的对话 |
| A2 树即导航 | 层级是真实结构，用结构手段表达（缩进/guide/键盘遍历），不伪装成平面列表 |
| A3 读优先 | 对话/档案/画布三个面，读是第一形态；写是显式切换 |
| A4 热度冒泡 | 正在聊的分支浮顶，祖先链跟随——"最近在聊的永远看得见" |
| A5 反馈即时 | 每个可点元素点击必有可见后果；无死行、无纯装饰可点区 |
