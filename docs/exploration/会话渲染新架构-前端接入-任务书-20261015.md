## 三、S1 补缺（按契约逐 type 校准渲染形态）

对 `assembler.js` 逐 type 核对，只修断点：

| type | 渲染形态 | 验收判定 |
|---|---|---|
| user_message | 用户气泡 `{"content"}` | 左对齐、气泡在 |
| assistant_text | 助手文档流 `{"content",model,end}`；**model/end 今天起新消息才有，历史无此键**（历史不补、显示原文） | 正文不被挤出 |
| tool_call + tool_result | **合体**：调用中（呼吸点＋计时）→ 结果原地改终态（✓/✗＋耗时），不新增行 | ★核心之一 |
| reasoning | 可折叠思考块 `{"text"}`＋顶层 model（主模型空→归正文、三席带名→分桶） | 有则渲染、无则不出 |
| seat_end | 三席观点全文入席卡 `{"model",ok,latency_ms,chars,text}` | 观点在席卡内 |
| judgment / plan_created / step_start / step_advanced | 环节行 | 属对应轮 |
| 注入类（context_preamble/context_injection/judgment_protocol/context_seat_identity） | 注入消息 `{"text"}` | 属对应轮 |
| msg_ask / msg_answer / msg_notify | 卡间信 | 正常渲染 |
| revoke | `{"from_seq":N}` 之后全部作废不渲染 | ★必须实现：revoke 段不出 |
| 老卡迁移块 | data 仅 `{"content","behavior"}`——按旧格式显示原文，**不解析补字段** | 历史不崩 |

**核心判据（对仗用户历次追问的③）**：同 run_id 的过程行插在该轮 user_message ↔ assistant_text **之间**——不再「事件堆顶、正文堆底」。

## 四、S2 验收（只在测试服沙箱 5702）

沙箱机制（已核）：`run_test_instance_5701.py` 的 `ECO_TEST_SANDBOX=1` 把全部运行时根搬临时目录（works/、trading-workspace/、logs/ 全隔离），真请求零触碰生产（红线6）；static 与生产同源，改前端当场就是新代码；5702 现活着（PID 15860）可续用。

验收步骤：
1. 沙箱建 work + 卡，发**需工具调用的复杂任务**，生成真实 timeline（含 tool_call/tool_result/multi-run；模型不思考则 reasoning 无——按「有则渲染无则不出」验收，不追）。
2. 拉 timeline 逐条对照契约 §二/§三形态。
3. 本地离线跑装配器，对照期望渲染（分组/排序/合体/revoke/降级）。
4. **全绿 → 才谈生产侧**。生产侧只做文件落地，不拿生产数据验收。

验收清单（逐条，全部沙箱验）：
- ① 过程行左对齐（同一左缘、事件名定宽）
- ③ **同 run_id 过程插在该轮 user↔assistant 之间**（核心）
- ④ 切卡不串（内存按卡存状态，异步回包写自己的状态、碰不到当前视图）
- ⑤ 调用中→终态两态（呼吸点＋计时）
- ⑥ think 有数据则渲染可折叠块、无则不出
- ⑦ 三席观点进席卡（seat_end.text）
- ⑧ 边出边渲染（content_chunk 逐字、收尾终态）
- revoke 段不渲染、老卡降级显示原文
