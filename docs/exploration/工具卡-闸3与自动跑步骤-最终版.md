## 四、自动跑步骤

### 4.1 挂点结论

**不需要新运行时。** 「自动跑步骤」即模型按步骤清单逐步发工具调用，由既有工具循环（第一节第 7 条）自动续跑。映射：
- 探针趟 = 既有 `tool_calls` 分支；
- 交付段 = 既有 `seats` 分支；
- 不新建任何循环。

运行时选型由 session_041 与 card_020 定死：E 探针制，不引入 ZhuGe 的 driver 或 think-tool。

### 4.2 设计点默认值

| 设计点 | 默认值 | 依据 |
|---|---|---|
| 触发方式 | 模型工具调用，不做 UI 按钮 | 与 E 探针制一致；工具循环无轮次闸 |
| 步骤清单存放 | 职责区（卡身不装） | 卡身只写结论 |
| 步骤状态 | 落影子卡进度节 | 影子卡只写过程 |
| 步骤产物 | 经既有协议落卡 | 不新开协议 |

新增的只有两样：步骤清单的格式与存放位置、步骤状态。两者都属于数据与提示词层，不涉及运行时改动。

## 五、完成保障机制（沿用方案链 / 任务书链）

原链不靠运行时闸保证完成，靠下面几件文档制度，逐件实读自以下来源：

1. **逐条对账**（`docs/exploration/THINK-ECO-E-对账-三张表-20261007.json`）：`forward` 把每条原文条目映射到草稿章节；`backward` 把章节反查到依据条目；`conflicts` 检测作废措辞残留。任何条目未落章节即视为漏项。
2. **任务完成判据**（`THINK-ECO-E-任务书终稿-20261007.md` §三）：每个任务挂 p0 条目 id，并写明机械可判的完成判据。
3. **V 系验收**（同文件 §五）：脚本化判据，明令不得 mock 假过（RD-12：必须真跑真实模型）。
4. **红灯账**（`THINK-ECO-T11-红灯账-20261005.json` 终态「无未决红灯」；`THINK-ECO-XX-放行单-任务书-20261003.json` 的 `final_state: 5/5 全消`）：红灯未全消不放行。
5. **放行单**（同上放行单）：用户裁定后才放行，并记录 `release_order` 与 `known_issues`。
6. **回报要求**（任务书终稿 §六）：执行方逐任务回报 file:line／mtime、V 系逐条实测、清理确认。
7. **落盘回读**（RD-09）：凡称「已落盘」，当场回读核验尺寸／行数／锚点。

**反例（说明机制本身要核验）**：放行单 `known_issues` 记录，方案链那一轮的对账表与红灯账始终未补，而其放行单里「已按实补齐并读盘核过」一句不实。文件存在不等于核过，回读是硬步骤。

### 5.1 对自动跑步骤的落地要求

自动跑步骤若要保证模型不断档，每个步骤至少要有上面的对应物：

| 原链机制 | 自动跑步骤对应物 | 状态 |
|---|---|---|
| 逐条对账 | 步骤清单与「步骤→产物→判据」映射表，落职责区 | 待设计稿定格式 |
| 完成判据 | 每步写明机械可判的完成判据 | 待设计稿定格式 |
| 红灯账 | 步骤推进前，上一步判据结果必须已记入影子卡进度节，且结果为通过 | 待设计稿定格式 |
| 放行单 | 步骤链整体完成后，由用户放行（默认保留人工放行） | 默认值，待确认 |
| 回报要求 | 每步产物路径与判据结果写入影子卡产物清单（指针）与进度节 | 待设计稿定格式 |
| 落盘回读 | 每步产物落盘后回读核验，结果记入进度节 | 待设计稿定格式 |

**关键的未决点**：「红灯未全消不推进」在原链里是人工对照文件执行的。自动跑步骤若要它机械生效，需要代码层的推进判据（读影子卡进度节并校验）。这一点设计稿必须定，不能只靠模型自觉。
