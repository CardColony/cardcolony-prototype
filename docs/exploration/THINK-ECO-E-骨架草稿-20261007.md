## 三、方案设计（四段）

### 3.1 编排状态机（改 simple_service.py）
call_simple 从「三席前置＋统合带工具」改为三段：**探查段**(工具收集，复用 routes while) → **三席段**(tools=None、输入含工具事实段) → **统合段**(tools=None 纯交付)。
- 契约：call_main 合同不动；call_simple 签名加「工具结果」入参（内部编排入口，非红线所指合同）；三席 tools=None 不动（R-023）。
- 无第二套 while：探查（事实收集）放 routes 现有 while，三席＋统合收尾不进 while（R-018 防两套嵌套）。

### 3.2 工具事实注入三席（R-017）
- 注入段比照 VIEWPOINT_HEADER 既有做法（逐字不改＋版本化）；BASE_PROMPT_VERSION 自 t12-1 递增。
- 工具事实段按【结论】＋【依据】折叠（用户 10-05 裁定），不设长度限制。
- 消除 VIEWPOINT_TASK_NOTE「三份」硬编码漂移——拆为新契约段落说明（探查事实段＋三席观点段）。

### 3.3 成本与行为口径（R-019，须上桌等用户拍，方案不得代办）
- 选项①每轮皆三席后置＝成本≈5-6 次/轮、每轮三席交叉审；
- 选项②仅指定轮触发＝成本省、部分轮无三席交叉。
- 方案列两选项＋代价，**端上桌等用户拍**，不写死默认。

### 3.4 验收判据（R-020）
- V1 顺序断言：同一轮工具先于三席（打点序）；
- V2 三席输入含工具事实段（构造断言）；
- V3 无闸证明：工具循环仍 while True 无上限；
- V4 三席 tools=None 不变、call_main 合同不变（断言）；
- V5 统合在最后、统合段不带工具（纯交付）；
- V6 纯对话轮（无工具）行为与现状一致不退化；
- 判据机械可判；浏览器类不适用（纯后端编排）。
