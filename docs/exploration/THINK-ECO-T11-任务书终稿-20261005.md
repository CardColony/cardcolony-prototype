**折叠器行为细则（执行方照此实现，不自行设计）**：

1. **折叠单元＝工具轮**：第 r 轮产物＝一条含工具调用的 assistant＋其对应若干条工具返回。
2. **不折红线（三条全部实现）**：首轮用户原文固化、抢救回注、当前轮全文——这三类轮次/内容一律不折。
3. **折叠动作**：保留窗口 K=2（最近 2 轮全文保留）；更早的轮次——`assistant.content` **首版不压**（原样保留）；工具**入参**与工具**返回**各压成【结论】＋【依据】两件套。
4. **两件套定义**：【结论】＝这次调用得到了什么，一句话——折叠发生时由模型压出，**不设任何长度限制**（200B 上限作废）；【依据】＝证据在哪、怎么找回原文（工具名＋参数＋原文位置）——代码机械写，不动脑子、不会编。
5. **产出机制**：装配时对窗口外旧轮次执行一次折叠（请求局部）；【结论】对「该轮工具做了什么、返回了什么」做一次模型压出（独立压缩动作，不改变消息条数与配对结构）；压出结果作为该轮返回正文替身写进轮槽；【依据】代码机械登记；原文在轮槽内释放、需要细节时模型按【依据】重取；边界——【结论】仅是轮槽内压缩替身，不进会话文件、不进证据索引、不推送。
6. **分组协议（硬）**：按轮次分组、**不按调用 id**——id 每轮从 0 重起、跨轮重复；切段按追加顺序；**重复 id 为观察项、首版不改**（真报 400 时第一嫌疑在此，记录为 known issue，不改动）。
7. **只读白名单语义**：只读工具结果可按【依据】重取（card_id/chapter/query/url/path 即重取键）；写工具（尤其全文在入参的三个：`write_file`／`edit_card`／`update_shadow`）必须折入参——只折返回会漏掉最重的一块。

## 四、验收标准（全部机械可判）
