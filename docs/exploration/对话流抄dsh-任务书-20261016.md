## 一、目标（一句话）

把推演agent 对话流的**渲染规格与实现方式整体对齐 dsh**，根治三类已坐实的病：

| # | 病（用户原话/现象） | 根因（已查死） |
|---|---|---|
| P1 | "我的信息怎么能比 run_start/context/judgment_protocol 这几条晚出现" | `send()` 里用户气泡不走本地上屏，走 timeline 回流（workspace.js:1131-1133 注释自认）；过程事件走 SSE 推送毫秒级到，用户气泡等一趟 HTTP |
| P2 | "发一条新信息，前面几条信息突然全部出现在新信息上方" | 重建/回流与实时帧交错，整列重排把历史消息搬位 |

## 二、范围

- **不做**：后端、timeline 接口（已就位，是唯一数据源）、左侧边栏、画布、权限、models.yaml

## 三、dsh 的三条架构铁律（照抄的核心，全部实读自 ChatSnapshotBuilder）

1. **节点模型**：一切屏幕元素＝节点，节点带稳定 `key` ＋ 可排序锚 `anchorSeq`；渲染序＝按 anchorSeq 排序，**插入新节点不搬任何既有 DOM**。
2. **增量装配**：`apply()` 只 upsert 变化的节点；顺序数组用 `sameReferences` 判定——结构没变就保留旧数组引用，**视图层零重排**。绝不整列重算。
3. **单源事实**：快照是唯一渲染依据；实时帧与重放走同一个 `apply()`，不分两套代码。

（推演agent 的 assembler.js 已有 applyRecord/rebuild/snapshot 骨架，架构同构——所以是**校准与补缺，不是推倒重写**。）

## 四、任务清单（每步独立可验收，报一步走一步）

### T1 · 用户消息乐观上屏（修 P1）
- 改 `workspace.js send()`：点发送瞬间，把 `content` 直接作为 user 节点本地 upsert 进装配器（key=本地临时键，pending 标记），**不等 POST、不等 timeline 回流**。
- timeline 回流保留为对账：真实 user_message 落盘记录到达（rebuild 或回流）时，按内容+轮位去重替换临时节点，不产生双气泡。
- 完成标准：点发送 → 用户气泡**第一个**出现（先于 run_start 等一切过程行）。

### T2 · 增量渲染，禁整列重建（修 P2/P3）
- 装配器补 `sameReferences` 语义：结构未变时保留旧顺序数组引用；渲染层收到相同引用直接 return，**零 DOM 操作**。
- 实时帧（/stream、/tokens）一律走 `applyRecord` 单节点 upsert；**删除一切"收到新东西就整列 rebuild"的路径**（这正是 P2 的根：重建时序与实时帧交错导致历史搬位）。
- 完成标准：发新消息后，历史消息 DOM **一个都不动**（节点引用不变）；只有新节点追加。

### T3 · Think 行按 dsh ReasoningRow 规格
- 形态：默认折叠行＝图标＋"Think"标题＋**摘要**（运行中显示最新一行，完成显示首行）＋计时；点击展开全文（灰斜体）。
- 归属：主模型 reasoning（model 空）挂在它服务的输出节点前；三席 reasoning（model 带名）归席卡内。
- 数据现状如实：全库 reasoning=0（主模型未开思考产出），本任务交付的是"**有数据即正确显示**"的渲染能力，验收用构造样本 + 单测，不拿"界面没出 think"当失败（无数据属模型配置域，不在本任务）。
- 完成标准：单测覆盖 reasoning 记录→Think 行（折叠/展开/摘要/归属）；构造数据在沙箱页面可见。

### T4 · 工具行按 dsh ToolRow 规格
- 单条目＝图标＋工具名＋参数摘要＋状态（运行中动画/✓ 耗时/✗ 错误）；结果内容默认展开**首段摘要**，完整内容点击展开（保留 10-15 已做的内容展开，收敛为 dsh 的两段式）。
- tool_call+tool_result 合体为单节点（assembler 已做，校准显示）。
- 完成标准：每个工具调用一眼看到"调了什么、成了没、拿到什么"。

### T5 · 视觉规格对齐 dsh

- 过程行（非工具非 think 的系统类）：统一灰阶单行式，图标+名称+一句说明，不抢正文视觉权重。
- 列宽/滚动：内容列居中、上界维持现行（62em），滚动条已重绘（不动）。
- 完成标准：与 dsh 对照截图逐项过——正文/过程/think/工具四类元素视觉层级分明。
