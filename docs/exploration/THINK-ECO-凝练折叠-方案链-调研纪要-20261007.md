## ④ 存量完整性校验规格（T19 血教训落地，写成分照抄的 fail-closed 五断言）

动三文件（memory_store.py / tool_fold.py / models.yaml），校验五断言、任一不过拒落盘：

1. **新增在场**：新增的 `windowTokenBudget` 切片、`FOLD_EVERY_BATCHES` 归拢触发、`condenser` 席位（`config/models.yaml` 逐字）、`_condense_call` 改指调用，逐字在盘；
2. **存量在场**：memory_store 原有函数一个不少（`condense_turn_end`/`_run_condense_pipeline`/`_condense_call`/`maybe_schedule_turn_end`/`trigger_k_bytes`/`load_memory`/`save_memory`/`ensure_watermark`/`condense_enabled`/`mark` 语义），models.yaml 四席+fallback 原样，tool_fold.py（非本线对象）一字不动；
3. **结构配平**：`py_compile` 两件 py 0 错误；
4. **与备份全量 diff**：改动前备份 vs 改后，diff 区间精确落在「L311 切片段 / _run_condense_pipeline 循环 / _condense_call 模型段 / 新 env 常量」与 models.yaml「condenser 席位」，无意外删改；
5. **字节数锚**：改动前后各文件字节数、行数有预期差，对得上。

任一断言不过 → 拒落盘 → 回退备份。部署正式服后以部署前备份为锚独立重跑一遍（两基线不同、不能拿测试过了当正式过了）。

## 关键判断

1. **部署方式**：四文件两环境逐字节同源 → 整件同步（备份→同步→SHA 比对→存量校验→重启）。
2. **漏搬点**：①②⑤代码级坐实（windowTokenBudget 0 命中 / 无批循环 / 硬编码 main）；③（同口径铁律）随①②一起搬、④（归拢线）整条新增。工具：tool_fold.py 非本线对象（15:11 更正确认其为推演侧自建、不入本线），本线只改 memory_store.py + models.yaml +（可能）model_service.py。
3. **凝练模型位**：call_main 硬编码取 main（model_service L56）——需加参数或直调 gateway；方案落点待定（两选一，属技术细节、诸葛可拍）。
4. **计量口径**：触发线/切片均按代码既有 utf-8 字节口径（2.1 B/token 折算，可推翻）；同口径铁律要求「触发判定与切片装载同一把尺」。
