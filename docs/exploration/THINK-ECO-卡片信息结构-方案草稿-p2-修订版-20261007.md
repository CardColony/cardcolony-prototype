## 1. 功能背景

卡片正文现用「四区」结构（职责区／结论区／否决记录区／修改历史），系写作 agent 遗产——方案对照表旧列逐字标注「旧（写作agent遗产）」（`卡片信息结构改造方案.md:84`）。该结构在代码里是硬编码而非可配置项：渲染器写死四个区头（`card_store.py:227`／`:230`／`:233`／`:236`），区名→键映射写死（`hash_utils.py:106-111`），读卡固定返回四键（`card_store.py:461-471`）。

结构缺陷落在两处。**其一，六类信息只有一个正文落点**：方案规定六类信息各有唯一的家，而模型经 `edit_card` 传入的整篇正文被硬编码塞进 `conclusion` 一个键（`card_tools.py:348-351` 逐字 `{"conclusion": content}`）——决定、事实、指针无各自落点。**其二，权威语义无机械兜底**：方案要求「模型在对话里说"定了""做完了"不算数——收口仪式＝用户确认或验证通过」（`C-18`），而现状 `update_card` 只消费 `charter/conclusion/rejections` 三键（`card_store.py:540-546`），既无区分字段，也无拦截。

**六类信息各有唯一的家**（上级 §一-3 逐条，`C-12`~`C-17`）：

| 信息 | 唯一的家 |
|---|---|
| 作用/目标 | 主卡·使命（`C-12`） |
| 当前状态 | 主卡·现状（带锚点自指）（`C-13`） |
| 决定 | 主卡·定论（`C-14`） |
| 事件/过程/迭代 | 影子·进度、迭代历史（`C-15`） |
| 文档/代码指针 | 影子·产物清单（主卡现状块尾一行衔接索引为导航入口）（`C-16`） |
| 观点/推理/未核实 | 对话流（不落卡）（`C-17`） |

**现状与影子的分工（防流水账侵蚀）**（`C-10` 逐字）：同一事件两种视图——影子·进度记事件（"10-09 跑了回归，全绿"），主卡·现状记态（"回归全绿（锚：reports/x.md）"）。现状永远是覆盖写快照，不是时间线。

不做会留下两项后果：决定可被静默改写且不可追——`edit_card` 是覆盖写，一次调用即可抹掉既有定论条目，而方案要求「条目被删/被改写→拒绝」（`C-08`）；事件流水与状态快照混住——现状无任何分区约束阻止时间线堆进主卡。

同批线路的实测坐标（本次调研实证）：权限线**已施工完毕**（`card_tools.py:238-257` 已是全盘放开新态），其方案文档仍写「五判据」——文档自述落后于代码；信息结构线**零落地**——`status_block|rulings|## 使命|## 现状|## 定论|mission` 在 `src/` 全库零命中；快车道线**并发进行中**（`routes.py:472` 前新增 `route(content)`），上线后模型带工具直答，若走 `edit_card` 将高频触发上述落点缺陷。

## 4. 方案正文（实现设计）

### 4.1 设计枢纽：把改卡从「键级覆盖」改为「正文级分区写」

现状 `edit_card` 把模型传来的整篇正文写进单一键（`card_tools.py:348-351`）。**这是全部矛盾的根**：模型交的是含区头的整篇正文，落点却是一个键——因此「三块各自归位」在物理上不可能发生，S3 要做的「分区 diff」也无从取新旧两份解析结果。

设计：`edit_card` 的落点语义改为**整篇正文覆盖写**——取旧卡正文、取新 content，两份都过拆分器，按分区做 diff 判闸，放行则整篇写回。改动锚 `card_tools.py:333-354`、`:348-351`。条目 `C-22`、`C-47`、`C-62`。

`update_card` 的键级 `updates` 通道保留（供 HTTP 与内部调用），正文级通道另立（供 `edit_card`）——两者共用同一套拆分/渲染内核，不产生第二套真值。条目 `C-44`。

### 4.2 拆分器：双表识别 + 规范键归一 + 形态带出

改动锚 `hash_utils.py:100-123`（`split_body_sections`）、`:106-111`（mapping）。条目 `C-32`、`C-33`、`C-43`。

**双表并存**：现有 mapping 为旧四区（`charter/conclusion/rejections/history_text`，实读 `:106-111`）。新增新区名→新键映射，与旧表并列；识别时按正文实际出现的区头自适应，两套区名混用不报错。条目 `C-43`。

**规范键归一**：旧区头命中时，其内容归入对应的新键——`## 职责区`→`mission`、`## 结论区`→`status_block`、`## 否决记录区`→`rulings`、`## 修改历史`→`history_text`（后者键名不动）。依据即方案对照表（`C-34`~`C-37`）。归一化的目的：**下游消费点只需认一套键**，存量卡与新卡在读侧不分叉。

**形态带出（返回值钉死）**：`split_body_sections(body)` 返回值新增第三键 `"_form"`，取值 `"old"`｜`"new"`｜`"mixed"`，与既有四键并列。`"_form"` **不落盘、不进 `read_card` 的 body**——`read_card` 组装 body 时丢弃（`card_store.py:464-471` 处只取四键）。判定规则：全部区头为旧区名→`"old"`；全部为新名→`"new"`；新旧混用→`"mixed"`。条目 `C-60`、`C-70`。

**读归一／写分叉（须显式写明，防实现误读）**：读侧一律归一到新键（下游只认一套）；写侧保留旧键路径——写旧卡仍走旧键（`C-44`）。两者分属读写两侧，不冲突。

**键名差异须辨明**：拆分器返回 `history_text`，而 `read_card` 组装 body 时转为 `history`（`card_store.py:461-471`）——该转换点须随归一化同步复核，防新旧键名在同一函数内并存。

### 4.3 渲染器：按卡原形态保形输出

改动锚 `card_store.py:205-238`（`_render_card`；区头写入点 `:227`／`:230`／`:233`／`:236`）。条目 `C-30`、`C-31`、`C-45`。

**签名钉死**：`_render_card(meta, charter, conclusion, rejections, history_lines, form: str)`，`form ∈ {"old","new"}`，默认 `"new"`，由 `split_body_sections` 的形态判定结果传入。按 `form` 输出对应区头——新卡输出 `## 使命`／`## 现状`／`## 定论`，存量卡输出原旧区头。**不做隐式迁移**：存量卡在编辑后结构不变。依据 `C-58`。

此设计的必要性由实读支撑：`_render_card` 有**三个**调用点——`card_store.py:369`（`create_card`）、`:553`（`update_card`）、**`:691`（`_append_relation`，实读 `:691-694` 逐字 `content = _render_card(meta, sections["charter"], sections["conclusion"], sections["rejections"], history_lines,)`）**。方案文档只提"改拆分器与 update_card"，未提第三处；漏改即产生新旧混挂。card_027 现存状态即为该症状的现场证据：新三块手写标题与旧三区空标题并存。

### 4.4 create_card：骨架默认值

改动锚 `card_store.py:320-421`（`create_card`）、`:326`（`charter: str = ""`）、`:355-367`（meta 初始化）、`:369`（调渲染器）。条目 `C-26`、`C-39`、`C-42`。

**骨架模板逐字**（依据 `C-04`）：

```
## 使命
（本卡作用/目标、授权来源；≤5行；立项定稿，改动需用户确认）
## 现状
（当前状况快照：做到哪、什么状态、卡在哪；只写已核实；事实条目带锚点自指；覆盖写·单一最新；块尾至多一行衔接索引）
## 定论
（对本卡相关事项的决定；只追加，仅经收口仪式写入）
D01【裁定】……（日期·依据）
D02【决定】……（日期·依据）
D03【收敛】……（日期·死过什么）
→ 被D05取代（因……）
```

**失效条目处置（依据 `C-04` 逐字）**：失效条目**就地一行标记，不保留原文，不设已废区**。即上列模板中 `→ 被D05取代（因……）` 一行的语义——原条目内容被替换为这一行标记，**不另设「已废区」收纳旧文**。该标记行由 `edit_card` 提交、经写入闸判为放行项（`C-50`：行首 `→` 放行）。

**修改历史为机械尾（依据 `C-04` 逐字 `（修改历史）←机械尾，机制不动`）**：`## 修改历史` 区由系统追加（`card_store.py:551` 逐字 `history_lines.append(f"- [{now}] {history_note}")`），**不在本次改造的块语法范围内、不设写入闸、不参与分区 diff**（`C-52`：修改历史区由系统追加，diff 忽略）。骨架模板中该区不出现在 `charter` 默认值内——它由 `_render_card` 固定追加（`card_store.py:236-237`）。

`charter` 参数默认值改为上列模板；新建卡经渲染器输出新形态。**骨架套用须在区头检测之后**：`card-proposal` 接口传入的 content 若已含区头则原样使用，不含区头才套骨架——依据 `C-39` 逐字「content 不含区头时自动套骨架」。该检测落在 `create_card` 内部，`card_proposal.py:191` 的调用点无需改动语义。条目 `C-39`。

连带面：`routes.py:69-75`（`CreateCardRequest` 含 `charter/conclusion`）、`:181-197`／`:322-336`（两个建卡路由）、`work_store.py:143-145`（内部建 work）——均以旧键传参，经归一化后落新形态。

### 4.5 update_card：键扩展与归一

改动锚 `card_store.py:476-566`、`:540-546`（消费键段）、`:553`（调渲染器）。条目 `C-28`、`C-44`、`C-45`。

设计：`updates` 键扩展新增 `mission/status_block/rulings`，旧键 `charter/conclusion/rejections` 保留。两套键在函数内归一后落到同一处存储，**不产生双写路径**。渲染时按卡原形态输出（承接 4.3）。条目 `C-44`。

### 4.6 S3 写入闸

挂点锚 `card_tools.py:333`（`edit_card` 分发前拦截），参照实现锚 `:340-342`（影子写守卫）。条目 `C-47`、`C-22`、`C-23`。**入参校验挂点另在 `card_tools.py:77-87`（`edit_card` 工具注册处的 schema）**——依据 `C-21` 逐字「S3 分区闸挂点（入参校验）」；该处 schema 描述须随闸语义更新（承接 4.10）。

**实现位置钉死**：闸实现为 `card_tools.py` 内独立函数 `_check_block_rules(old_body: str, new_body: str) -> dict`，返回 `{"ok": bool, "rule": str, "message": str}`；`edit_card` 分发段（`:333-354`）在调 `update_card` 前调用。

**判据源**：新旧两份正文的拆分结果（承接 4.1、4.2），逐块 diff。六条规则与方案逐字对应：使命区不等→拒绝 `使命块为立项定稿，修改需用户确认`（`C-48`）；定论区非超集→拒绝 `定论块只追加；失效用就地标记（→被N取代）`（`C-49`）；行首 `→` 的失效标记放行（`C-50`）；现状区 diff 不校验（`C-51`）；修改历史区 diff 忽略（`C-52`）；旧结构卡不校验（`C-53`）。

**第七条机械规则（依据 `C-62` 逐字「写入闸使混淆在机械层被拒」＋`C-12`/`C-14` 归属表）**：现状区内出现 `D{nn}【…】` 形态的整行条目 → 拒绝，报错文本逐字 `现状块不装决定；决定进定论（D{nn} 条目属定论块）`。判据为行首形态匹配（正则 `^D\d{2}【`），机械可判、不依赖模型自述。

该规则与 `C-51`、`C-54` 不冲突，须写明区分（防实现者误判为违反上级）：
- **与 `C-51` 的区分**：`C-51` 说的是「现状区内容变化不做 diff 校验（自由覆盖）」——管的是**内容怎么变**；本规则校验的是**条目形态**——管的是**现状区不得出现定论条目的形态**。二者维度不同，并存不悖：现状区文字可自由重写，但不得整行写成 `D{nn}` 形态。
- **与 `C-54` 的区分**：`C-54` 否决的是「锚点标记（经X报告/Y实测/Z确认）」的机械强制——本规则**不校验锚点**，锚点仍为语义纪律＋事后审计（现状块≤5行，审计成本可控）。

**现状块语义规则（非机械）**（依据 `C-07` 逐字）：覆盖写·单一最新；只写已核实；事实条目带锚点自指（经X报告/Y实测/Z确认）。以上为语义纪律，**不做机械校验**（依据 `C-51`、`C-54`）。

**两处边界必须写明**。其一，**锚点不做机械强制**：方案明确否决"含锚点才放行"的机械校验，理由逐字「机械强制会激励伪造锚点，伪证比缺证更伤权威机制」（`C-54`、`C-80`）——本设计不实现锚点闸。其二，**闸的作用域**：S3 闸执行的是块写入规则，不是访问控制（`C-55`、`C-66`、`C-78`）；且闸只拦模型工具通道（`card_tools.py:333`），**用户经 HTTP PATCH 的通道是"用户确认"的合法来源，不设同一闸**——使命块对用户开放修改，对模型拒绝。此点方案未言明，为本设计的判断，须在复核中受检。

### 4.13 边界：本设计不覆盖的部分

权限体系（跨卡读影子、管辖判定、访问控制）→ 独立任务，S3 闸不属此列（`C-66`、`C-78`）；读侧注入（清单摘要、权威标注入上下文）→ 独立任务（`C-67`）；类型退役（`card_type` 词表）→ card_009 域，本设计仅保证 `create_card` 默认骨架不依赖类型字段（`C-59`、`C-68`）；`content_hash` 语义 → 不动，理由逐字「只算正文会导致存量哈希一次性全失配」（`C-69`）；`role/status` 字段复活 → 不做，生命周期用「现状块文字＋定论收口」表达（`C-70`）。

## 5. 分期与上退

本设计按四期落地，每期可独立上、独立退。

**S1 骨架与说明（零逻辑改动）**：4.4 骨架默认值 ＋ 4.10 prompt 改写。影响面：新建卡正文形态；存量卡零影响。
**S2 拆分器双表**：4.2 ＋ 4.5 ＋ 4.7。影响面：读写键集合；退回后旧键路径原样。
**S3 写入闸**：4.1 ＋ 4.6 ＋ 4.10（schema）。判据源为分区 diff，由 S2 提供——**S3 不可先于 S2 单独上**。
**S4 死字段清理**：4.12。与前三期无耦合。

原方案称「每步可独立上/退」（`C-38` 逐字 `## 三、分期施工（每步可独立上/退）`；`C-77` 逐字 `施工四期：S1骨架与说明→S2拆分器双表→S3写入闸→S4死字段清理`），而 S3 判据源由 S2 提供，故 S3 独立上不成立；本设计明确 S3 依赖 S2，此为据实修正，非违背上级。
