## 一、三处待定项的收敛

### Ⅰ-3（收敛）· 可见集 `visibleIds`

**收敛为**（改 `canvas.js:411-413`）：

```
visibleIds = { viewRoot } ∪ 全部直接子卡
           ∪ 每一张「已展开卡」的全部直接子卡     ← 随展开态递归增长
```

**实现要点**：
- 新增 `computeVisibleIds()`：由 `state.viewRoot` ＋ `state.expanded` 共同算出；
- **默认 `expanded` 为空** → 首次打开 ＝ 根卡 ＋ 全部二级卡（用户第 1 分句）；
- **`state.viewRoot` 不再随点击变化**——这就是「就地」；
- `getVisibleIds()`（`:599-609`）**本方案不用**（它算「一次性全展开」，与增量展开语义不同）；保留原样，其唯一调用点「整理画布」`:835` 不受影响。

### Ⅰ-4（收敛）· 两个旧布局函数的处置

**收敛为：都不删、都不再被 `computeLayout` 调用。**

| 函数 | 处置 | 理由 |
|---|---|---|
| `layoutNarrativeAxis`（`:139-263`） | 保留、不调用 | 删它会牵动 120 余行、增大回归面 |
| `layoutGridMatrix`（`:265-281`） | 保留、不调用 | 同上 |

**处理方式**：`computeLayout` 分派逻辑（Ⅰ-1）改为只走新的树形排布函数；两处调用点移除、函数体保留。
**打点三**（原设计的「旧函数是否仍被调用」）**意义由「待定」变为「验收依据」**——保留原设计不变。

### C-6（收敛）· `▸N` 徽章的新语义

**收敛为：徽章从「下钻入口」改为「展开/折叠开关」。**

| 交互 | 原语义 | 新语义 |
|---|---|---|
| `▸N` 徽章点击（`bindNodeEvents:476-483`） | `setViewRoot` 换视图根 | **展开/折叠该卡子树**；图标 `▸`（折叠）↔ `▾`（展开） |
| 双击卡片（`onDoubleClick:558-567`） | `setViewRoot` | **改为展开/折叠**（与徽章一致，不设两套） |
| 单击卡片（`onSingleClick:554-556`） | 打开工作区 | **不变** |
| 面包屑（`renderBreadcrumb:372-400`） | 下钻路径、可点回上层 | **保留**（视图根不变时退化为静态显示） |

**C-6 可复核判据（替换原「验证方式待定」）**：
> 展开一张有 N 张子卡的卡后，其下方出现 N 张子卡节点，徽章文字由 `▸ N` 变为 `▾ N`；再点一次，子卡消失、徽章变回 `▸ N`。验证：DOM 计数该卡子节点数变化 ＋ 读徽章 `textContent`。

## 二、新增设计点Ⅲ · 折叠树模型

### Ⅲ-1 · 缩略卡渲染（对应「二级卡的缩略标题信息」）

**实读到的两套现成机制（本环节 grep 原文取证）**：

**机制一 · 摘要已在跑**（`canvas.js:730-752`）：

```js
734:       const concl = (card.body && card.body.conclusion) || "";
735:       const firstLine = concl.split("\n").map(s => s.trim()).find(s => s) || "";
736:       const summary = firstLine.length > 120 ? firstLine.slice(0, 120) + "…" : firstLine;
```
摘要 ＝ 卡片结论区第一行非空文字、上限 120 字符；由 `lazyLoadVisibleSummaries()`（`:755-770`）每次渲染后自动填充。

**机制二 · `l0/l1/l2` 三档详略——由缩放档驱动，已完整在跑**（`canvas.js:55-57`／`:63-64`）：

```js
55:   if (zoom < 0.5) return "l0";
56:   if (zoom > 1.2) return "l2";
57:   return "l1";
63:   node.classList.remove("l0", "l1", "l2");
64:   node.classList.add(level);          ← 挂载确实在跑
```
配套：换档防抖（`:71`）、`L0/L1` 悬停 tooltip 显示摘要（`:540`／`:712-717`）、CSS 三档样式（`style.css:293`／`:310`／`:322`）。

**设计（关键：两条规则并行、互不干涉）**：

| 规则 | 决定什么 | 机制 | 本方案 |
|---|---|---|---|
| **可见性**（新） | 这张卡**在不在画布上** | `state.expanded` → `computeVisibleIds()` | **新增** |
| **详略档**（现有，不动） | 它**显示多详细**（`l0`/`l1`/`l2`） | `zoom` → 现有 `l0/l1/l2` 逻辑（`:55-64`） | **一行不改** |

**「二级卡缩略」如何达成**：默认视图下（根＋二级），**当前缩放档为 `l1` 时二级卡即缩略形态**（标题＋类型＋摘要）。**本方案不新增「强制缩略」规则**——理由：现有机制已按缩放给出合理详略，强行叠加第二套档位规则会与现有逻辑打架（这正是本稿上一版写错的地方）。**若用户要求二级卡在任何缩放下都强制缩略**，属新增覆盖规则，**列为待确认项**（文末第 2 条）。

### Ⅲ-2 · 折叠态的数据结构

**新增内存态**（`canvas.js` 的 `state` 内）：

```js
state.expanded = new Set();   // 已展开的卡片 id；默认空
```

**四条硬约束**：

| # | 约束 |
|---|---|
| 1 | **只存内存，不写 `canvas.json`**（红线①） |
| 2 | **刷新即回默认（全部折叠）**（待确认项第 1 条） |
| 3 | **不新增任何持久化载体**——展开态是视图态，不是数据 |
| 4 | **不新增任何写 `canvas.json` 的路径**——现有写路径仅拖拽（`:814-830`）与「整理画布」（`:833-847`），本方案新增为零 |

### Ⅲ-3 · 就地展开的布局重算

**流程（替换现有 `setViewRoot` 换根流程）**：

```
点击卡片或徽章
  → ① state.expanded 增/删该卡 id
  → ② computeVisibleIds() 重算可见集
  → ③ computeLayout() 重跑树形排布（Ⅰ-2 新函数）
  → ④ renderCanvas() 重绘（节点增删＋位置更新）
  → ⑤ renderEdges() 重画线
```

| 关键点 | 说明 |
|---|---|
| **不调 `setViewRoot`** | 视图根不变——「就地」的全部含义 |
| **不调 `fitView()`** | 画布不跳视野（`fitView:579-597` 会强行居中到新内容、打断用户）；其定义保留 |
| **兄弟卡让位** | 由树形排布（Ⅰ-2，按子树宽度分配横向空间）自动完成 |
| **新增 `toggleExpand(cardId)`** | 更新 `state.expanded` → 重跑 ②～⑤ → 更新徽章图标 |
| **重绘粒度** | **保持全量重绘**（`:404` 清空重建）。**判定条件写死**：若实测展开耗时（`performance.now()` 前后差）**> 100ms**，改为增量重绘；否则保留全量。**该阈值是本环节新立的技术判据，非用户要求** |

### Ⅲ-4 · 动效

**实读依据**（`style.css:228`）：`.card-node` 自身已有 `transition: left 0.3s ease, top 0.3s ease, width 0.2s, height 0.2s, padding 0.2s;`——**卡片位置与尺寸变化本来就有平滑过渡**。展开时其他卡让位的位移**自动带 0.3s 缓动，无需新增**。

**需新增两处**：

| # | 项 | 实现 | 依据 |
|---|---|---|---|
| 1 | **新卡淡入** | CSS 加 `.card-node.entering { animation: card-in 0.18s ease; }` ＋ `@keyframes card-in { from { opacity: 0; transform: scale(0.96); } }`；JS 新节点加 `entering`、`animationend` 后移除 | **本环节新立**（现有 CSS 零 opacity 动画） |
| 2 | **连线补间** | **不做**——SVG `<path>` 的 `d` 无法靠 CSS transition 补间，JS 逐帧插值复杂度不成比例。展开时线直接出现在新位置 | **本环节新立（取舍）** |

**四条动效纪律**：
1. **只对 `opacity` 与 `transform` 做动画**（走合成层、不触发重排）；
2. **时限 ≤ 300ms**（与现有 0.3s 一致）；
3. **拖拽时动画必须关闭**——现有 `.card-node.dragging { transition: none; }`（`style.css:234`）**原样保留**；
4. **不得用动画掩盖布局错误**——卡重叠/错位是布局 bug，验收按 C-4 机械判据判，与动画无关。
