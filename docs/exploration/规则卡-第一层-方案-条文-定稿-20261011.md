# 第一层 · 方案

## 这一层是什么

方案不是记录，是拦截。

这套系统里，卡片记已想明白的结论、会话记说过什么、快照记文件变过什么——全是回头看已发生的事。只有方案在动手之前把判断固定下来。

它存在的理由：AI 想错的时候，自己不知道。错在起点的某个前提上，从那个前提往下推，每一步都自洽，通篇挑不出毛病。所以必须把判断外化成一个能被拦的东西。

**判据**：不是读起来顺不顺、全不全——是**一个不了解内情的人，读完能不能发现我错了**。

## 工序：从开工到交稿

**一、固定上游。** 把上游说了什么逐字提成清单，一条不漏。**对不回原文就停**——不许带着对不回的行往下走。这份清单是后面每一次对账的底。

**二、核实现场。** 每条落点钉到真实代码或真实文件。**没读到就不写**——读不到就写"未找到"，不许臆造。这一段只读，不写任何东西。

**三、先定骨架。** 定"分几段、每段管什么"，再填内容。**空着的格子比没有更糟**——下游会把空格看成"这里没问题"，不是"这里还没写"。

**四、逐格填。** 每格写清：基于什么、判断什么。

**五、攻击自己。** 交稿前，用固定清单问"我是不是犯了这几类错"：丢了什么／改写变形了什么／凭空多了什么／哪里自相矛盾。**无证据的裁决等于不通过。** 本系统不走子代理，所以这一场攻击由自己执行，**必须在文里如实标注【非独立复核】**——未消的问题不消失，记下来挂着。

**六、成稿。** 判了要改的，**在正文里逐条落成实际文字**——不许换个说法翻页。只交正文，复核过程另存。

**七、停。** 交出去，不动手。

## 什么算对、什么算错

**一、判断要暴露"基于什么、判断什么"。** 只给结论，别人挑不出错——错在前提出，后面自洽。给全这两样，人才有机会一眼认出前提不对。

**二、双向对账。** 每条设计要追回上游某一条（防自己塞东西）；上游每一条要有下落（防东西丢掉）。**两个方向都要**——少了后一个，有东西会静默消失，而且没人知道它曾经被提过。

**三、定不了就停，不要带着往下走。** 遇到定不了的，停下、上桌，带上：差什么、缺什么证据、有哪些处置选项。**带着未定的岔路往下走，下游只有两条路——停下来等，或者替你定。**

**四、分清哪些该谁定。** 改变"别人看得见的结果"的——是他的；只改变"你怎么做到"的——是自己的。两头错法都出事：该他定的自己定了，**岔路被抹平，事后才发现**；该自己定的端上去问，**烧他的时间**。

**五、写清什么算违反了这份方案。** 动手时一定会撞上写它时想不到的情况——没有这一条，方案会被实现过程追上、越过，然后失效。**只有"无论怎么实现都不许被破坏的约束"能被长期检查。**

**六、先保证决策完备，再如实说把握。** 不许留"到时候再看"的空洞——这是硬门槛；在满足它的前提下，还要标出"我把握不大"。**不许拿"我没把握"当"这条可以不定"的借口。**

**七、方案到"改动图"为止，不写施工单。** 写清改哪里、什么性质、为什么这么切；不写先做什么再做什么的操作流水。**这条界就是这一层和任务书的界。**

**八、写完就停。** 写方案的和动手的是同一个东西，有能力顺手就做——但闸的全部意义就在停这一下。边写边做，判断没被拦住就进了产物，方案退化成事后记录。

## 这一层管不到的地方

这八条治的是"判断没被摊开"，治不了"判断能力不够"。

它想不出更好的路，条文只能逼它把这条穷途如实写出来，变不出一个更好的判断。**规矩能保证判断可见，不能保证判断高明。**前提错了又没人看，错照样往下走——这一层真正的下限，取决于有没有人真的读。
