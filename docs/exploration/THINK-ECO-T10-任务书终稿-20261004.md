## 一、背景与裁定

### 1.1 要解决什么

一次提问与它的回复之间，系统里**没有任何显式的绑定关系**。两条请求同时在途时（重发、长调用期间再次提问），**落盘顺序 ≠ 因果顺序**——用户看到的是「最新那句后面紧跟的回复，答的是旧话」。

现场实证（`works/work_001/sessions/session_005.md` 原文，逐字复核含毫秒）：

```
15:54:20  用户问
16:11:38  用户又问（间隔 17 分 18 秒）
16:15:53  回复 A 落盘（答的是 15:54 那次提问）
16:16:24  回复 B 落盘（答的是 16:11 那次提问）
```

### 1.2 根因与加重项

| 层 | 项 |
|---|---|
| 根因① | **无配对标识**——全库搜 `request_id|message_id|pair_id|reply_to` 命中 **0** |
| 根因② | **写文件无锁**——`aiofiles.open(mode="a")` 直接追加写，真锁 **0 处** |
| 加重③ | 重发重复落盘——前端不重复显示，后端 `routes.py:346` 照写一条 |

|---|---|---|
| **V1** | 每条用户消息与每条回复携带同一个配对标识 | 发一轮 → 读会话文件，用户条与回复条的 `pair_id` 字段值**逐字相等** |
