## 二、parent 语义（R-03）

- parent 是**项目内**引用（裸 card_id）；跨项目定位一律 `(work_id, card_id)` 复合键。
- 现状已符合：child_count 按项目内 parent 计（routes.py get_nav 同款统计）；实现不改代码、不 rename、不迁移。
- 孤儿卡（parent 指向已删卡）：/api/nav 原样返回 parent、前端挂该项目根层末尾（既有契约不变）；**/api/nav/children 任一层均不含孤儿卡**（其父不在树内，无层可挂）——孤儿展示由 /api/nav 全量承担。

## 三、三通道全景（S1 交付的数据面）

```
GET /api/nav            全量。8 字段契约。旧前端继续吃（S3 前不切换）
GET /api/nav/children   单层直系。S2 异步加载消费（展开才拉）
GET /api/nav/version    变化指纹。S2 的 60s 探测源（没变零开销、变了重拉+diff）
```

### 3.1 GET /api/nav/children?work_id=X&parent=C

- 返回 `{"work_id": X, "parent": C, "cards": [...]}`；cards 每项＝第一节同一套 8 字段（`_card_obj` 共用构造，防漂移）。
- `parent` 空串（或缺省）＝**第一层**，实现为根卡直系；根卡本体是分组头、不进树（与 /api/nav 同口径排除）。显式传 `parent=根卡id` 等价同层。
- `parent` 非空＝该卡一层直系（全直系，无深层混入）；叶子层返回空数组。
- 排序与 /api/nav 同款两段稳定排序（card_id 升序收尾→活跃降序，刷新不跳序）。
- 错误：work_id 不存在→404 `{"error":"剧本不存在: …"}`；parent 非空且不存在→404 `{"error":"卡片不存在: …"}`（与既有 404 语义对齐）。
- 无越层参数——只答一层直系，防退化成全量遍历。

### 3.2 GET /api/nav/version

- 返回 `{"version": <全局指纹>, "by_work": {work_id: <该 work 指纹>}}`。
- 指纹定义：该 work 下 `cards/*.md`、`sessions/*.md`、`work.json` 的「相对路径|大小|mtime」全列表 SHA-256（只读遍历，不侵入任何写路径）。增／删／改全部捕捉。
- 全局 version＝各 work 指纹按 work_id 排序复合哈希；确定性、重启可复算。
- work 集合＝`works/` 下含 work.json 的目录（不经 work_store.list_works——其附带活跃度现算，U2 实测 56ms；指纹本体 7 works/158 文件 ≈0.7ms，端点全程 ≈1ms）。
- 用法（S2）：60s 比对 version 字符串——相同→零动作；变化→重拉 /api/nav 做 diff，可用 by_work 判定哪个 work 变了只 diff 哪个。
- **实现层修订记录（对任务书 T6「mtime 取 max」，两笔，如实）**：
  1. max→列表哈希：纯 max 探测不到删卡（删非最新文件 max 不变→侧栏挂幽灵卡）；仿 data_snapshot._fingerprint 同法。响应契约不变，补删卡敏感性断言（test_v6）。
  2. U2 实测两轮：直扫 60.7ms（超 50ms 基准）→ scandir 55.3ms（仍超）→ 定位大头为 list_works 活跃度现算 56ms → 绕开后 **0.9ms PASS**。全程未用缓存、未用墙钟，纯枚举路径优化。
