## 0. 任务定义（一句话）

画布和对话各自成为有独立 URL 的网页：URL 即页面身份，刷新各回各家；终结「一个 URL 双视图叠加、靠 hash 猜状态、两套代码同时加载」的形态。

## 2. 设计原则（四条，全部可机械检验）

1. **URL 即真相**：路径决定页面，刷新不变义；运行时不从残留状态猜「该显示谁」。
2. **单页自洽（判据机械化）**：画布页模块图不含 workspace/stream；对话页模块图不含 canvas。用「入口文件 import 传递闭包」脚本断言，不靠肉眼。
3. **路由只转发**：后端不判业务，只选模板＋注入变量。
4. **共享件真模块**：导航系统、规则面板、api/store/util 独立成模块，两页各自装配；共享件不反向依赖任何一页。

## 3. 终态规格

### 3.1 URL 契约

| URL | 页面 | 刷新行为 |
|---|---|---|
| `/work/{wid}` | 画布页 | 永远画布 |
| `/work/{wid}/card/{cid}` | 对话页 | 永远该卡对话；cid 无效 → 重定向画布页 |
| 旧 `#wid/cid` | 客户端 `location.replace` → 对话页 URL | hash 机制退役（hash 对服务端不可见，兼容重定向只能在前端 boot 做） |

### 3.2 页面构成（DOM 归属表）

| 件 | 画布页 | 对话页 |
|---|---|---|
| 左栏（appNav＋搜索＋⋯＋） | ✓ | ✓ |
| 规则卡 rulePanel（常驻） | ✓ | ✓ |
| toast / notifyPanel | ✓ | ✓ |
| viewport / world / edgesSvg / cardTooltip / zoom 控件 / 整理画布 / 新建卡 / canvas 面包屑 | ✓ | ✗ |
| workspace（chatArea/inputBox/runBtn）/ inspector / 草稿与状态弹窗 / chatCrumb / 返回画布钮 | ✗ | ✓ |

### 3.3 模块归属

- 画布入口 `main.js`：store / api / util / **canvas** / nav_system / rule_panel
- 对话入口 `main_chat.js`：store / api / util / **stream / workspace** / nav_system / rule_panel
- `workspace.js` **保留文件名**（他线在途改动所在，改名=冲突面最大化），终态=纯对话业务（chatArea 渲染/发送/inspector/两个弹窗）。
- 跨页动作只有一个：**跳 URL**（`location.assign`）。

### 3.4 行为规格

- 画布点卡/连线徽章 → `assign(/work/{wid}/card/{cid})`；对话页左栏点卡 → 同一动作（守卫：已在当前卡则不重复加载）。
- 对话页返回画布（面包屑首段/返回钮）→ `assign(/work/{wid})`。
- `home.js` 三处跳转改新路径（:33 免 hash；:80/:100 → `/work/{wid}/card/{cid}`）；recent 键 `nav.recent.v1` 不变，只改 URL 拼法。
- 运行中轮询属导航系统，两页都在场。
- 画布页数据新鲜度：每次页面加载即拉新（现状本就如此），对话页建/删卡**无需**通知画布。

### 3.5 关键决策（已定；方向性的一条供用户可否决）

- **D1 · MPA 整页跳转，不做 SPA 软路由**。理由：web 原生、刷新/后退天然正确、状态零泄漏、改造面最小；代价=切卡一次整页加载（本机 5700 服务，体感可忽略）。用户「网页不该这样」指向即此。**若不接受切卡有整页加载，改 SPA 属方向变更，需用户明示。**
- D2 · hash 彻底退役＋客户端兼容重定向。
- D3 · workspace.js 不改名（理由见 3.3）。
- D4 · 对话页 inspector「加关系」下拉数据源从 `GetCanvasState` 改读**导航快照**（state_layers 已有全树；对话页无画布模块后原路必断）。

## 5. 并发协调与提交纪律（硬规矩，逐条带出处）

1. 每阶段开工前重读目标文件 mtime＋git status；有他线在途即停（beb408c 教训）。
