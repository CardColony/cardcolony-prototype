# THINK-ECO-T19 任务书 · 主界面交互与 UI 可懂性/可读性修复

## 一、背景与依据

**用户原话（2026-10-07 10:12，逐字）**：「蓝的黄的是什么意思，为什么有的能直接点开，有的不能？而且有些字，黑底还用灰字，是准备让人看的吗？你自己复核一遍交互和ui，看看到底优不优秀，好吧？」

**用户点名三问**：
1. 蓝点/金点/灰点是什么意思（含义不明）——无从得知符号语义；
2. 有的卡能直接点开、有的不能（规则不透明、不可预期）；
3. 黑底上用灰字（对比度过低、可读性差）。

**诸葛复核结论（t18 评审档，10-07 10:14-10:18 现场实读钉死）**：
- ① 色点是「树的层级」记号：金=项目（workspace.js:438 / style.css:546 .dot.root）、蓝=有子卡的卡（workspace.js:457 / style.css:547 .dot.mid）、灰=叶子卡（style.css:548 .dot.leaf）。但界面上**无任何图例**；且三色与卡片类型色同值（style.css:18-23：--c-work 金=剧本 / --c-setting 蓝=世界观 / --c-idea 灰=线索）——一种颜色两套含义。
- ② 点开规则不统一：点项目行只展开/收起树（workspace.js:534-539）、不进项目；点卡行进对话（:541-542）；点有子卡的卡的 ▸ 只展开不切对话（:522-529）。**箭头与整行两套行为、视觉无区分**。
- ③ 深底灰字：--dimmer #484f58（style.css:15）落近黑 #010409（--bg-deep:9）上、11px，对比度≈2:1，不可读；--dim #8b949e（:14）≈3.5:1，勉强。用于项目名/数量/时间/note/徽章等次级信息（:496/:504-505/:550/:657/:863-871/:873-879/:737）。

**本批目标**：修主界面的可懂性与可读性——①符号加图例且与类型色解耦；②点开/展开规则显式化、行为统一可预期；③深底次级文字对比度提到可读档。不改骨架风格、不扩大范围到未抱怨区域。
