# 通用级 agent 基础能力缺口盘点（2026-10-20）

> 取证方式：逐条读代码与配置，不引用 README 口径（已核实 README 能力面严重滞后）。
> 取证范围：`src/api/card_tools.py`、`src/api/file_tools.py`、`src/api/prompts.py`、
> `src/api/routes.py`、`src/api/search_tool.py`、`src/api/message_runner.py`、
> `src/storage/memory_store.py`、`src/permissions/policy.py`、`config/permissions.json`、
> `config/models.yaml`、`static/`、`templates/`、`.env`。
> 判定视角：**通用级 agent**（能接真实世界、能干完一件事、能长程自主），不是"推演agent 该不该做"。
> 本文只列缺失与理由，**不含任何实施方案**。

## 零、先纠正三处事实偏差

这三处不是功能缺失，但会让模型自我设限、让后续判断建立在错口径上，故列在最前。

| # | 偏差 | 代码事实 | 后果 |
|---|---|---|---|
| 0-1 | `prompts.py` L156 / L169 的工具自述写「`list_files` 范围限 `D:\AI_station` 下的 trading-workspace 与 推演agent 两个目录」 | `file_tools.py:38-39`：`BASE_DIR = Path(r"D:\AI_station")`，`ALLOWED_ROOTS = (BASE_DIR.resolve(),)` —— **全盘放行** | 模型以为自己只能看两个目录，实际可看整个 `D:\AI_station`；能力被文案自我阉割 |
| 0-2 | README 写「文件能力不设删除」 | `delete_file` 在 `TOOL_REGISTRY` 中，`file_tools` 有删除实现（不可删目录） | 对破坏面判断偏低 |
| 0-3 | README 写「工具层 25 件」「三思考席＋思维链七工具」 | 实跑 `len(TOOL_REGISTRY) == 51`；`src/thinkchain/__init__.py`：`ENABLED=False`、`SEATS_ENABLED=False`，计划六件不注册 | 能力面与运行态不符，据此做的规划会落空 |

补充：README「本地文件能力 4 件」也已过时，实际文件类 11 件（`bash`/`python`/`glob_files`/`delete_file`/`move_file`/`rename_file`/`edit_file`/`list_files`/`read_file`/`search_files`/`write_file`）。

## 一、地基级：缺了就不算"通用 agent"

### 1-1 没有"工作区"概念

- **现状**：`card_tools.py:2038` `_run_subprocess(argv, shell_cmd, cwd=None, timeout)`；`:2050` `run_cwd = str(cwd or file_tools.BASE_DIR)`；`:2098` `_h_bash` 调用时**不传 cwd** ⇒ 所有 shell 命令的当前目录恒为 `D:\AI_station`。
- **缺**：per-work（甚至 per-card）工作目录。`works/<work_id>/` 只存 `cards.db` / `sessions` / `events` / `memory` / `canvas.json`，不是工作区。
- **影响**：多个 work 的 agent 在同一目录写产物，同名文件互相覆盖；模型必须自己拼绝对路径才能不撞；"这个项目的产物在哪"没有系统答案。

### 1-2 没有后台进程与长驻终端

- **现状**：`card_tools.py:1977` `_EXEC_MAX_OUTPUT_BYTES = 50 * 1024`；`:1978` `_EXEC_TIMEOUT_SECONDS = 120.0`；超时走 `_kill_quietly(proc)`。无进程句柄、无 `run_in_background`、无日志尾随。
- **缺**：后台启动 + 输出轮询 + 显式 kill；长驻会话（同一 shell 里保留 cwd/env/变量）。
- **影响**：dev server 起不来、构建/训练/爬虫跑不了、`tail -f` 看不了；所有超过 120 秒的活都干不了，且大输出被 50KB 截断。

### 1-3 没有环境隔离

- **现状**：`_h_python` 把代码写系统临时 `.py`，用 `sys.executable` 执行；无 per-work venv、无依赖清单。
- **缺**：每 work（或每项目）的解释器/依赖隔离。
- **影响**：装依赖污染全局；两个 work 依赖冲突无解；"这个项目跑得起来"不可复现。

### 1-4 没有输入通道

- **现状**：`routes.py` 全文无 `UploadFile` / `multipart` / `/upload`；`static/*.js` 与 `static/esm/**` 无 `type="file"` / `accept=` / `FormData`。`manuscript_store.py` 只是读 `works/<work_id>/manuscript/ch_XXXX.md`（预置只读章节，YAML front matter 只有 title）。
- **缺**：文件上传、对话附件、图片输入（`model_gateway/llm/types.py` 有 `ImageBlock` 注释但标明 "DeepSeek wire 路线 text-only"；`llm_openai_compat/serialize.py:48` 有 image 分支，未接通）、PDF/Office/表格解析。
- **影响**：用户无法把资料交给 agent；只能贴文本，或手动把文件放进 `D:\AI_station` 再让模型用 `read_file` 去读。通用 agent 的"感知"环节基本缺失。

### 1-5 没有交付通道

- **现状**：`static/workspace.js`、`static/canvas.js` 全库无 `download` / `preview` / `iframe` / `openFile` 命中。
- **缺**：产物卡片、在线预览、下载、打包、对话/卡片导出。
- **影响**：产物只能落盘，用户得自己去文件夹翻。闭环断在最后一米。

### 1-6 超窗＝报错收口，不是压缩续跑

- **现状**：`context_regions.py` 装配原则明令"不评价、不裁剪、不截断"；超窗走 `message_runner.py:1227` `handle_error()` → `data_snapshot.snapshot_sync(checkpoint)` + `event_stream.emit("error")`，整轮结束。`memory_store.py:96` `condense_enabled()` 缺省关（`.env` 已设 `CONDENSE_ENABLED=1`，触发线 `CONDENSE_TRIGGER_TOKENS=800000`、窗口 `CONDENSE_WINDOW_BUDGET_TOKENS=300000`），但凝练只管**会话历史**，管不了装配区（卡片清单/子卡现状/依赖关联/记忆区）。
- **缺**：装配层的预算控制；超窗时"压缩后继续本轮"而不是"整轮报错"。
- **影响**：长任务必然撞窗。现在有 checkpoint 能"下条消息从现状续走"，但没有"这一轮还没干完就断了"的恢复路径。

### 1-7 危险操作无审批

- **现状**：`bash` / `python` / `delete_file` / `move_file` / `rename_file` 直接执行；只有 `write_file` / `edit_file` 覆盖前自动备份到 `_backups/`。无"这一步要不要问人"的机制。
- **缺**：破坏性操作的分级审批；只读模式 / 沙箱模式。
- **影响**：自动模式下模型可以 `rm -rf`，全程无人拦。自主度越高，这个洞越大。

## 二、通用性缺口：能干活，但接不上真实世界

### 2-1 无浏览器自动化

- **现状**：`search_tool.py:122` `fetch_web(url)` → `:129` `requests.get(u, headers=..., timeout=30)`，纯静态 HTML。
- **缺**：JS 渲染、点击、表单、登录态、截图、多标签。
- **影响**：大量真实任务在网页后面（要登录的后台、SPA、需交互的站点），现在只能读静态页。

### 2-2 无工具扩展机制

- **现状**：51 件全部写死在 `TOOL_REGISTRY`（单点注册表：schema + handler + readonly 住一起）；全库 `grep -w mcp` 零命中。
- **缺**：MCP 协议接入、外部工具注册、模型自造工具（现有 `run_tool_card` 是"剧本卡"，不是代码工具）。
- **影响**：接不了数据库、SaaS、内部 API。加一件工具＝改代码＋重启＋补测试＋改权限表。

### 2-3 记忆不跨 work

- **现状**：`memory_store` 按 `works/<work_id>/memory`；无历史对话检索、无全局知识库、无用户偏好持久层。
- **缺**：跨项目记忆、按语义检索历史结论。
- **影响**：换个项目就失忆。"上次那个项目怎么解的"查不到。

### 2-4 触发面单一

- **现状**：只有三种触发——人发消息、卡间消息（`inbox` + `schedule_card_message_triggers`）、goal 续轮（`notify_idle` → `requestDrive`）。
- **缺**：定时/周期任务、webhook/外部事件、文件监听、任务完成后的外部通知。
- **影响**：做不了"每天早上跑一遍""文件变了就处理""跑完通知我"。

### 2-5 无成本/用量治理

- **现状**：`model_gateway/gateway.py:328-329` `usage` 仅用于估算（`len(content)//4`），不落库、不聚合、无预算上限。并发有闸（`concurrency.default=3` + `per_model`），成本无闸。
- **缺**：token/金额按卡/按 work 聚合；预算上限与熔断。
- **影响**：自动模式 256 轮 × 多卡 × 多层模型，烧多少只能事后翻日志。

## 三、工程化：单人本地可忍，要做产品就得补

| # | 缺口 | 现状 | 影响 |
|---|---|---|---|
| 3-1 | 无鉴权/多租户 | `routes.py`、`main.py` 无 login/auth/password 相关代码 | 单机单人；一旦要对外提供就无隔离 |
| 3-2 | 无任务级评测 | `tests/` 约 900 条是单元/契约测试 | 改提示词或换模型，无法量化"任务成功率/平均轮次/单任务成本"是升是降 |
| 3-3 | 无断流看门狗 | 10-19 四张卡同一毫秒挂起、静默 57 分钟无检测；已加并发闸，仍无心跳超时 | 长任务静默挂死不可发现 |
| 3-4 | 工具级无重试 | 模型调用有 `retry`（`models.yaml` 按模型配），单工具失败直接进信封交模型 | 瞬时错误（如 Windows `Errno 13` 文件锁）会毁掉整轮 |
| 3-5 | 工具串行执行 | 一轮多个 `tool_calls` 逐个跑 | 多工具任务耗时线性叠加 |

## 四、优先级判断（按"自动模式已开跑"这个前提排）

1. **per-work 工作区 ＋ 后台进程**（1-1、1-2）：自动模式已经在跑长任务，这两条是每天都会撞的墙。
2. **装配层超窗压缩续跑**（1-6）：80 万 token 一到就整轮报错，长程任务的上限被这一条钉死。
3. **产物交付闭环**（1-5）：成本最低、体感最直接，补完才叫"干完一件事"。
4. **输入通道**（1-4）：决定"通用"能不能真成立——没有输入就只能处理模型自己找到的东西。
5. **危险操作分级审批**（1-7）：随自主度上升而变急，不是现在就炸，但是自动模式的必要配套。
6. 其余（浏览器、MCP、跨 work 记忆、触发面、成本治理）：决定天花板，不决定能否成立。

**一句话总判断**：这系统的强项是**决策留痕**（卡片三块、三种线、goal 事件流、prompt 全文），弱项是**与真实世界交互**——它现在更像一台想得很清楚的思考机器，还不是一台能干完活的机器。而"通用"的价值恰恰在干完。
