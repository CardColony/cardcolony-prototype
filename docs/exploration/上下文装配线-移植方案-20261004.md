## 五、轮槽与折叠器（原方案 §五，保留）

### 5.1 作用域

轮槽为**请求局部对象**，**不做全局内存态**——单进程可并发处理不同卡的请求，全局态会跨卡串味。

### 5.2 折叠单元＝工具轮

第 r 轮产物 ＝ 一条含工具调用的 assistant ＋ 其对应的若干条工具返回。
**不折的对象（红线）**：首轮用户原文固化、抢救回注、当前轮的全文。

### 5.3 折叠动作（机械，纯函数）

保留窗口 **K**（最近 K 个工具轮保留全文，**K 缺省 2——本版自拍**），更早的轮次：

- `assistant.content` → **首版不动**（本版自拍）
- 工具**入参** → 压成【结论】＋【依据】两件套
- 工具**返回** → 压成【结论】＋【依据】两件套

**两件套定义（照「已核实结论」常驻机制的做法：一句话结论 ＋ 出处依据）**：

- **【结论】**：这次调用得到了什么，一句话——折叠发生时由模型压出，**不设长度限制**
- **【依据】**：证据在哪、怎么找回原文（工具名 ＋ 参数 ＋ 原文位置）——代码机械写，不动脑子、不会编

**产出机制（两件套怎么落地）**：

- **时机**：装配时，对保留窗口 K 之外的那些旧轮次执行折叠（一次装配一次折叠动作，折叠发生在轮槽内、请求局部）
- **【结论】产出**：折叠发生时，对「该轮工具做了什么、返回了什么」做一次模型压出，得到一句话——独立压缩动作，不改变消息条数与配对结构；压出结果作为该轮返回的正文替身写进轮槽
- **【依据】产出**：代码机械登记（哪一步、哪个工具、参数、怎么重取原文），不动脑子、不会编
- **原文去向**：被折叠轮次的原始返回在轮槽内释放（不再重送）；需要细节时模型按【依据】重取原文
- **失败处理**：压出失败 → 该轮不折、全文保留、留痕记错误条目（同 §5.5，不留白）
- **边界**：【结论】仅是轮槽内的压缩替身——**不进会话文件、不进证据索引、不推送**；与「已核实结论」的区别：后者是长期可对质的证据条目，前者是请求内的体积压缩，两者不互通

**为什么必须两边都折**：写文件／改卡／写影子这三类工具的**全文内容在入参里**，不在返回里。只折返回会漏掉最重的一块。
**只读工具白名单落点**：**落工具定义处（本版自拍）**——白名单是「工具的属性」，属性该跟工具住一起。

### 5.4 协议约束（硬，不可让步）

- **保留配对结构**：工具调用与工具返回**只压内容、不删消息**（删了会触发上游配对校验失败）
- **按轮次分组、不按调用 id**：现状 id 每轮从 0 重起（跨轮重复）；折叠切段按追加顺序。**重复 id 登记为观察项，首版不改**（改它会破坏逐字一致的基准）。**补记：真报 400 时第一嫌疑在此。**

### 5.5 失败处理（划界）

- 任一异常 → 记 `warning` ＋ **该轮不折、全文保留** ＋ 留痕记错误条目（**不留白**）
- **这与「失败必须响亮」不冲突**——折不动 ≠ 机制失败，后果是「没省下」，不是「数据错了」
- **禁止**：因折叠异常改变消息条数或结构；禁止静默跳过而不打点
