## 一、功能背景

### 1.1 要解决的问题（基线 §一 实读）

同一张卡、同一时点，一次调用的 prompt 负载已到 **447,988 字节**（10-04 10:24，card_016）；最大样本 **534,657 字节**（10-04 22:41）。而该卡会话文件仅 4,873 字节——**负载是会话文件的 92 倍**（按现值重算 17 倍）。

44 万字节的全部来源已实读定案（三处 append 机制）：**本轮工具循环内，assistant＋tool_calls ／ 首轮用户原文固化 ／ tool 结果逐轮加长、每轮把整段重送**。工具调用与工具返回从不落盘（`append_message` 全仓库仅两个调用点），历史侧零工具痕迹（投影成 role/content 两键）。

### 1.2 为什么是「移植」（用户 09:28 当场追问）

dsh（`D:\AI_station\ZhuGe\dsh-memory`）已有**完整实现**——区表定义、投影渲染零加工规则、装配拼接动作，外加官方《PORTING-GUIDE》。**方案必须逐件回答「dsh 的哪个构件、搬过来、放哪、怎么接」，分四类：直接搬／适配改／新造／不搬。** 缺这张表，方案就是「借鉴思路的重写方案」，不是移植方案。

### 1.3 范围（用户 23:26＋00:03(1) 当场框定）

- **做**：装配线（区表＋装配器直出分区＋出口 join）＋ 轮槽折叠（旧轮次工具结果折为【结论】＋【依据】）
- **不做**：凝练线（记忆基线/mark/水位/covers）——用户 00:03(1) 怒斥撤出，§十一「不做」清单原样保留
- **不要**：「当前轮」概念——只保留「用户消息排最后」的位置规则，不引入 dsh 轮槽截获机制（推演侧自己拼 messages，本轮消息天然在手上）

### 2.2 与 dsh 构件的逐件对应（本方案核心增量，p2 草稿的骨架）

| dsh 构件 | 推演侧落点 | 动作 | 为什么 |
|---|---|---|---|
| 区表定义（order/类型/readonly/来源） | 推演六区表 | **直接搬** | 组织方式不依赖宿主，结构照搬、内容换皮 |
| 投影渲染规则（原样取、不排序不截断不设预算） | 各区来源渲染 | **直接搬** | 「渲染零加工」是装配机制的灵魂，通用 |
| 装配动作（按 order 收区拼接、不评价不裁剪） | 出口 join | **直接搬** | 拼接逻辑通用 |
| 数据源接缝（从 dsh 存储读区内容） | 换成推演侧既有读取通道（卡片、会话） | **适配改** | 推演侧通道本来就有，改「读什么」不改「怎么读」 |
| 区内容映射（dsh 八区→推演六区） | 六区各自内容来源 | **适配改** | 换皮 |

| 凝练线（mark/水位/covers） | 无 | **不搬** | 用户 00:03(1) 本迭代不做 |
| 折叠器 | 工具轮折叠（请求局部） | **新造** | 工具轮膨胀是推演侧独有、dsh 无可搬对应物；形态照「已核实结论」范式 |

### 2.3 折叠形态（用户 00:03(3)＋00:08＋00:13 明令，p1 实读落地）

- 折叠单元＝工具轮（一条含工具调用的 assistant＋其对应工具返回）；不折红线：首轮用户原文固化、抢救回注、当前轮全文
- 保留窗口 K=2（最近 2 轮全文），更早的：`assistant.content` 首版不动；工具**入参**与**返回**都折为【结论】＋【依据】两件套
- **【结论】**：这次调用得到了什么，一句话——折叠发生时由模型压出，**不设长度限制**（200B 上限作废）
- **【依据】**：证据在哪、怎么找回原文（工具名＋参数＋原文位置）——代码机械写，不动脑子、不会编
- 产出机制：装配时对窗口外旧轮次执行一次折叠（请求局部）；压出结果作为该轮返回正文替身写进轮槽；原文在轮槽内释放、需要细节时模型按【依据】重取；失败→该轮不折、全文保留、留痕（不留白）
- 边界：【结论】仅是轮槽内压缩替身——不进会话文件、不进证据索引、不推送；与「已核实结论」不互通（后者长期可对质、前者请求内体积压缩）

### 2.4 协议约束与失败处理（基线 §五 原样）

- 保留配对结构：只压内容、不删消息（删了触发上游配对校验失败）
- 按轮次分组、不按调用 id：id 每轮从 0 重起（跨轮重复），折叠切段按追加顺序；重复 id 为观察项首版不改（补记：真报 400 时第一嫌疑在此）
- 任一异常→记 warning＋该轮不折、全文保留＋留痕；禁止因折叠异常改变消息条数或结构；禁止静默跳过不打点

### 2.5 观测（基线 §六 原样）

prompt 日志新增两键（均为加法、不改既有键）：`regions`（每区 order/名称/通道/席位/字节数/指纹/条目数——只存指针与指纹不复制正文）、`fold_ops`（每轮折叠原字节/折后字节/结果）。不改 `logs/` 目录结构。

### 2.6 开关与回滚（基线 §八 原样）

装配器分区路径缺省**开**（零行为变化）；折叠总闸缺省**关**（有行为变化，实测后再裁定）；折叠保留轮数=2。落点＝环境变量（本项目既有惯例：MOCK_LLM/SEARXNG_URL/ALIYUN_TOKEN_PLAN_API_KEY/APP_PROFILE 四处）。回滚＝关闸即回旧路，无需数据迁移。
