## 〇 · 病根机制（必读——后面每个动作的"为什么"都在这）

以下全部为 2026-10-17 12:18–12:33 沙箱真机走查实测（真实鼠标键盘、CDP 录证），不是推断：

1. **现状点＋ → `/work/draft` → 空白画布**。落地的是画布页（page-canvas）：0 卡、挂着「未保存」小标、还有教学文案教用户「点右上＋新建卡开始」。用户点「新建项目」要的是开始对话，得到的是一块空地。
2. **建卡/草稿对话页是假界面**——最恶劣的静默失败：页面骨架在（面包屑/工具栏/卡详情都在、`#inputBox` 可见），打字点发送，**POST 真的发出去了、后端真的建了项目**，但用户气泡**永远不上屏、零报错**，刷新后才看得见。
   - 代码根因（钉死到行）：
     - **看板**：草稿进入时显示绑临时板 `new-N`（workspace.js:235-238 附近，`enterDraftProjectChat`/`enterNewCard` 的板挂载段，行号为 13:33 快照，动手前重读）。
     - **写板**：`send()` 里落库完成后，消息走真板 `c:{wid}:{cid}`（workspace.js:894-900 附近，send 的板键派生段）。
     - **写的板 ≠ 看的板** ⇒ 消息写进了用户看不见的板。刷新按真板重建，所以「刷新才活」。
3. **落库完成时多一次整页二次加载**（实测 +2s，走了 location 跳转而非 replaceState 静默换地址）。
4. **对照组证明老链路没坏**：同一发送动作在真卡页（根卡 card_001、子卡各测一遍）——气泡 ≤160ms 上屏、消息流全活、零异常。**坏的只是草稿新链路的板键接错，不是发送系统。修法因此是"接回老路径"，不是重写发送。**

## 一 · 终态定义（改完用户看到什么——所有动作对它负责）

用户视角四步 + 三边界：

| 步 | 用户看到 | 系统事实 |
|---|---|---|
| 1. 点＋（首页/画布页/对话页，三入口同动作） | <500ms 落地草稿对话页：标题「新项目」、空消息区、输入框可见**且已聚焦**、光标在闪 | 零网络请求（不 POST、不拉 /api/works/draft/*——draft 无库可查，拉了就是 404） |
| 2. 打字、点发送 | 气泡 ≤500ms 上屏、回答照常流出——**与真项目根卡页跑同一动作序列，脚本断言不可区分** | 落库（POST /api/works 建项目+根卡）→ 换绑显示板到真键 → 走**原有**发送路径一字不动 |
| 3. 回答完 | URL 已静默换真地址（replaceState，无整页加载）、左栏出现新项目且按活跃排最前、刷新回原位 | 草稿身份退役完毕，从第二条消息起就是普通对话 |
| 边界a：先改名再说话 | 改名那一刻即真建（用用户起的名） | 改名是数据动作，触发落库 |
| 边界b：什么都没干就关页/切走 | 零弹窗、零残留 | 盘上不出现空壳项目 |
| 边界c：落库 POST 失败（断网/500） | toast 报错、**输入框的字还在**、再点发送能走完 | 失败不吞数据、不半建 |

**明确不做**（范围红线）：建卡弹窗 UI 本体不动、规则卡面板不动、画布不动、性能优化不动（那是战役2）。建卡弹窗产出的草稿对话页**吃同一次板键手术的红利**（同一条 send 路径），但不改弹窗自己。

### 阶段2 · 板键三步 → V2 / V3 / V7（本战役的心脏）

背景（必读）：现状 send() 的草稿分支在落库后直接继续走原流程，但显示板还停在 `new-N`——这就是假界面的根因（见〇节第2条）。修法**不是重写发送**，是落库后先把显示板换绑到真键，再让原有发送代码在正确的板上跑。

动作（一个文件：workspace.js F7）：
1. **抽 bindBoard(wid, cid)**：把 open() 里「EventFlow.activate(wid,cid)＋消息容器切到该卡」的板绑定段抽成独立函数 `bindBoard(wid, cid)`，open() 原调用点改调它（行为零变化——纯抽取，先跑测试确认零回归再进下一步）。
2. **send 草稿分支三步化**：现状 `await ensurePersisted()` 之后直接走原流程；改为：
   ```
   await ensurePersisted()          // ① 落库（已有函数，含锁与失败拒绝）
   bindBoard(WORK_ID, realCid)      // ② 换绑显示板到真键（新抽取的函数）
   // ③ 原有 optimisticUser / EventFlow.start / pullUserBubble 一字不动继续执行
   ```
   关键：realCid 从 ensurePersisted 的落库结果取（落库返回的 work_card_id / card_id），不许从旧 DOM 状态猜。
3. **消灭二次加载**：落库成功后的地址更新一律 `history.replaceState`（若现状某处走了 location 跳转/assign，改掉——0.3 走查已录证那 +2s）。
4. 建卡弹窗落地的草稿对话页（`/work/{wid}/card/draft`）走同一条 send 路径，同病同治，无需单独手术——但要在验证里补一条对应断言（见 V2 附注）。
