# 卡片权限机制改造 · proposal p15 三节梳理

- 时间：2026-10-07 11:34

## A · 功能背景（为什么做）

**现状**：模型在某张卡里，读卡片正文受一套"亲属链+连线+锚卡"的限制（自己、子树、上级血统链、自己连线指向、锚定根卡，五项判据）——同级卡、其他分支卡读不到。同时，模型"看得到"全项目所有卡的存在（清单层全给：id·标题·父卡），但读正文拉取时被这套判据拦。

**用户原话（2026-10-07 11:26 逐字）**：
1. 「这个项目，卡片可以全盘查看所有卡片的信息，但不能编辑」
2. 「卡片不能读同级卡片和上级卡片信息，是小说项目才需要的机制」
3. 「写方案吧」

**意图**：①读侧放开到"全盘可读"（全项目任何卡的信息都能查到）；②写侧不放、仍受限；③现行的"按亲属链限制读"机制，是从小说项目（写作 agent）移植来的、为小说项目服务的机制，推演项目不需要它——应去除。

**不做会怎样**：模型在推演树里被亲属链限制卡住，查不到同级分支、旁支卡的事实，推演时"只见自己这一支、不见全局"——读侧限制与"能看清推演过程与结论"的目标相悖。

## B · 位置与接口（改哪里、各判据语义，产品/架构层）

### 读侧（对应原话①前半 + ③）
- **读权限判据**：现行一套"亲属链连通判定"（自己/子树/血缘/连线/锚定根）。目标态＝放开为**全盘可读**：任一卡可读全项目任何卡。
- **读动作携带工具**：读卡片正文、读记忆、读影子、为建连线查目标——四个读性质动作的判据入口集中在一处，放开后应一并放开（范围待 X2 拍定）。
- **与"拉取制"的关系**：上下文组包**不推送**任何卡片正文（模型想看哪张经读动作自己取）——这块**逻辑不动**，读放开只是让拉取不再被判据拦。改的是"拉取时放不放行"，不是"推不推送"。

### 写侧（对应原话①"但不能编辑"——形状待 X1 拍）
- **写权限判据**：现行"自己＋自己的后代"可写、上级/同级/旁支不可写。
- **写动作携带工具**：改正文、删卡。这两者的判据入口也在同一处。
- **不可越界的护栏（不随本线变化）**：剧本根卡不可删、有子卡不可删（删卡的结构护栏）；影子只能由对应正卡写（写侧签名级独占）。

### 受读放开带动的关联点（需逐个确认，不默认）
- 影子卡读侧跟随读判据——读放开是否连带放开读影子，待 X2。
- 记忆读动作跟随读判据——同上，待 X2。
- 建连线现须"可读目标"——读放开后此闸自然放行，建连线是否算"编辑范围"待 X3。

## C · 预期效果（每条机械可判，未拍口径标【待用户拍】）

1. **读放开（待 X2 拍范围后成立）**：模型在任一卡，能读到全项目任何一张卡的正文——不再因亲属链/连通被拒。（判据：对任意卡对，读动作均放行；受限于卡片存在。）
2. **写仍受限（形状待 X1）**：模型不能编辑它无权写的卡——判据按 X1 拍定的边界执行。（判据：越权写返回明确"无权"，不落盘、不改数据。）
3. **删卡护栏不破**：根卡、有子卡仍机械拒删。（判据：这两种删除仍被拒。）
4. **影子写侧独占不破**：影子只能由对应正卡写。（判据：无其他写通道。）
5. **组包与凝练零回归**：上下文组包逻辑、凝练触发时序不受影响。（判据：相关既有行为与改造前一致。）
6. **改动面收敛**：读/写判据改动不波及前/后端其他模块（判据：改动的消费点全部在判据使用方、无跨模块泄漏）。
