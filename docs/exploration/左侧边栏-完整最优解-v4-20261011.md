## 〇 一句话核心

左侧边栏不是静态清单，是**跟着系统状态活着的组织器**——四个新问题是一条闭环：

```
【状态】(机械可算的输入) → 权重→排序(谁排前面) → 自动收起(眼前只有有用的) → 自动调位(正在忙的永远显眼)
```

状态是输入，其余三个是输出；输出反过来让"正在忙的"永远在显眼处。

## 一、【状态】这一维（机械可算，作为一切的输入）

### 三层状态必须分清（不混）

| 层 | 定义 | 数据现状（实读） | 用途 |
|---|---|---|---|
| **A 生命周期** | active / completed（注册表 `allowed_transitions: active→[completed]`，completed 终态不可编辑） | **存储层有闸（gate_4 校验）、数据层未落（卡文件 front matter 实测无 status 字段）、接口未暴露（/api/nav 卡片对象实测无）** | 已归档/完成 → 默认折叠、沉底、可隐藏 |
| **B 活跃度** | 由时间戳机械阈值派生（48h 活跃 / 30d 停滞） | **现算现成**：`activity.py` L5 卡级=max(会话末条, updated_at)；L7 项目级=max(全卡, created_at)；L86-93 branch=该卡+全部子孙 own 的 max，请求时现算绝不入盘（RD-06）；/api/nav 已带 last_active_at/branch_active_at | 排序权重、自动收起的输入 |
| **C 渲染态** | expanded/loaded/loading/error（v3 行对象四态） | 前端 | 渲染与交互，不进本维度 |

### 左侧栏暴露的状态档（机械函数）

| 档 | 判据（全是阈值函数，零语义） | 改变用户的什么动作（不改变动作的删掉） |
|---|---|---|
| 活跃中 | last_active_at 距今 < 48h | 排前面、默认可见、不收起 |
| 分支活跃 | branch_active_at > own 且 branch 距今 < 48h（子树比自身更晚动） | "这下面有新东西"——靠前、给徽章 |
| 停滞 | 48h ≤ 距今 < 30 天 | 自动收起候选、排序下沉 |
| 已归档/完成 | 生命周期 = completed | 默认折叠、沉底、可隐藏（**依赖后端补字段，当前无数据源**） |

### 纪律

1. 状态是机械函数（时间阈值 + 生命周期标志），零语义判断——守住「判断归模型」。
2. 状态是排序/收起/调位的**输入**，不是独立显示维度——不加一排状态徽章（守住 v2 徽章≤2）。
3. 阈值是参数不是代码（48h/30d 进配置）。

## 二、显示排序及权重（可解释、机械、手工优先）

### 现状（实读）

- routes.py L162-199 / work_store.py L50-82：**已在按 last_active_at 降序排 projects 与 cards**（单维、无阈值、无置顶、无二级权重）。
- ZCode 已读 12 份源码**无排序/权重机制**（文件树按字典序惯例）——如实报，不硬造借鉴点。

### 权重函数（全机械可算）

```
score = 手工置顶位(∞，用户钉住恒最前)
      + 状态分(活跃中=100 分支活跃=80 停滞=40 归档=0)
      + 活跃时间分段加权(近 48h 内活动：按距今倒数分段)
      + 最近访问加权(过去 N 次会话出现次数 ×10)
      + 标题字典序(并列兜底，稳定不跳变)
```

- 项目级与卡片级同函数；卡片级只作用于**同级兄弟**（parent 相同），树结构优先于排序，**不跨层排序**。
- 可解释保证：行内轻提示（"3 分钟前活跃"/📌 置顶）——用户永远看得出"为什么它在上面"。

### 四个必须回答的问题

| 问题 | 答案 | 违反会怎样 |
|---|---|---|
| 手动 vs 自动谁赢 | **手工永远赢**（置顶/收藏恒等优先级，自动只作用于未钉区间） | 自动覆盖手动＝整理白费，信任清零 |
| 何时重算 | 三个时机：①数据刷新检测到变化②用户置顶/取消③新建。**绝不在交互中重排** | 用户正点它突然跳走＝不可预期（宪法二） |
| 与最近访问重复吗 | **不重复**：最近访问是树外捷径（我上次去过哪），树内排序是组织逻辑（现在谁值得看），语义不同不合并 | 合并＝树内塞时间维，结构被污染 |
| 位置漂移怎么补偿 | ①当前卡永远可见②平滑过渡（CSS transform，不闪跳）③变化可解释（行内提示）④可关（偏好层「自动排序」开关） | 漂移不可见＝找不到刚看的行，迷路 |

### 被否决备选

纯手动拖拽（万级成本爆炸）／纯活跃单维（现雏形，无解释无置顶）／字典序（文件树惯例不适配活对象）／分组分栏（割裂视野）——各带否决理由，非凭感觉。

## 三、自动收起折叠（只收系统撑开的，绝不收用户亲手展的）

### 第一刀：按展开来源分层（全部设计的地基）

| 来源 | 语义 | 自动收起 |
|---|---|---|
| 用户手动展开 | 用户整理的视野（偏好层记忆） | **绝不收** |
| 系统自动展开（当前卡祖先链／跳转临时展开／搜索命中临时展开） | 系统为定位临时撑开 | **可收** |

### 触发（三类，全机械）

| # | 触发 | 判定 | 作用范围 | 违反会怎样 |
|---|---|---|---|---|
| A 状态驱动 | 停滞/归档（≥48h/30d 或 completed） | 阈值函数 | 分支级（仅系统展开部分） | 冷分支占满视野，找不到正在忙的 |
| B 场景切换 | 切走项目/卡后，旧路径的系统展开节点变冷 | 选中态变化 | 分支级 | 旧路径永远摊着，视野臃肿 |
| C 数量上限 | 系统展开节点超 100（**合并 v3 的 150：只收系统展开，手动展开不入候选**） | 计数 | 分支级 | 万级下无限展开＝成本失控 |

### 时机与安全

- **空闲窗口**：最后交互 ≥5s 无操作、无加载/拖拽/跳转，才执行。
- **批量限幅**：一次 ≤5 个；执行可中断（用户一动即停未执行部分）。
- **可撤销**：每一次自动收起后轻提示「已收起 5 个停滞分支 · 撤销」，一键恢复全部。
- **可解释**：提示带原因（"超 30 天未活动"），用户看得出它不是随机。
- **可关闭**：偏好层「自动整理」开关（默认 on），关后 A/B/C 全停。

### 绝不收走（硬禁五条）

当前卡祖先链／用户手动展开的节点／正在加载中的分支／搜索过滤进行中／最近访问与收藏（不在树内）。

## 四、自动调整位置（分数随时变，位置只能安全地动）

### "位置"的准确含义（先钉死，不糊涂）

- **① 树内排序位置：是（主）**——议题二权重排序的输出。
- ② 分组/分区归属：**否**（v2/v3 已否决分区，不造第二套组织）。
- ③ 滚动与视口位置：**否**——视口是用户领地，系统不改用户视口；但"确保当前卡可滚动到达"是义务。

### 关键分界

**权重重算（分数变化，后台随时）≠ 位置重排（界面顺序，只在安全时机）**——中间隔一道"何时生效"的闸。

### 四道闸（过完才动）

| # | 闸 | 判据 | 违反会怎样 |
|---|---|---|---|
| 1 空闲窗 | 最后交互 ≥5s、无加载/拖拽/跳转（与议题三共用同一套空闲检测） | 用户点着一行它换位＝失去目标 |
| 2 当前卡锚 | 重排后当前卡仍在可视区，滚出则平滑回位；「定位到当前卡」与吸顶路径条不让位 | 正在看的卡被排走、视线丢失 |
| 3 手工优先 | 钉住的行永不参与自动重排 | 自动覆盖手动＝信任清零 |
| 4 批量限幅 | 一次 ≤5 行；远距离移动分步渐进（如一日内） | 整表重排＝乱码闪跳 |

### 两个冲突正面答

- **自动调位 vs 折叠记忆**：**不冲突**——折叠记忆管"哪棵树展开"（形状），调位管"形状内部顺序"。形状按记忆恢复、顺序按最新权重——两个承诺都不破。
- **"我明明放在这里的卡去哪了"**：三重补偿——可解释来源（行内提示"4 小时前活跃，已下沉"）／平滑过渡（transform 动画不闪跳）／可关（偏好层「自动排序」开关与「自动整理」开关相邻但分离）。

## 五、缝合：前四格 × v3 全件（逐处对矛盾，就地解）

| 接缝 | 相容？ | 就地解 |
|---|---|---|
| 【状态】× 行对象四态 | ✓ | 状态＝数据派生字段（meta.state），四态＝渲染字段，共存于行对象不同层，不冲突 |
| 【状态】× 聚合徽章 | ✓ | 同源（时间戳）+ 两个消费端：徽章显示 branch 活跃、状态驱动排序/收起——不冲突 |
| 【状态】× diff 刷新 | ✓（补边界） | 60s 版本号探测带新时间戳 → 前端重算状态分；但"状态分变化"≠"立即重排"（分数随时变、位置安全动） |
| 排序 × 虚拟滚动 | ✓ | 排序决定行序列顺序，虚拟滚动消费该序列；重算只在三安全时机 → 序列不闪跳，固定行高不破坏 |
| 自动收起 × 虚拟滚动 | ✓ | 收起＝折叠（expanded=false），子行退出序列（折叠即卸载），序列缩短＝减负，不冲突 |
| 自动动作 × 「定时刷新绝不碰任何状态」 | **正面补边界** | 自动收起/调位≠定时刷新：定时刷新是无条件不碰状态；自动动作是**有条件的、空闲窗执行的、可撤销可关的主动动作**——不在刷新那条禁区内，但受同等约束（执行前确认空闲、必带提示与撤销、可被关闭）。这条不写清会看起来自相矛盾，现已写清 |
| 自动收起/调位 × 交互宪法二（原子可预期） | ✓ | 空闲窗＋批量限幅＋可撤销＋可关——动作可预期、可中断、可回退，守住宪法二 |
| 自动收起 × 交互宪法四（三问有答） | ✓ | 「我在哪」由当前卡祖先链（硬禁第一项）与吸顶路径条保证；「怎么回去」由收起不触手动展开保证 |
| 状态/排序/收起 × 判断归模型 | ✓ | 阈值函数＋权重函数＋触发条件全机械，无一语义判断 |
| 自动动作 × 状态三层 | ✓ | 展开来源标记（手动/系统）＋展开集＝偏好层；空闲检测、加载态＝临时层；当前卡＝选中层——各归各层，不新开全局裸变量 |

**缝合结论：无结构性矛盾；两处就地补边界（自动动作≠定时刷新、状态分变化≠立即重排），一处依赖声明（生命周期字段）。**

## 附：四个问题的理解（对用户 12:36 问的正面回答）

1. **【状态】**：理解＝生命周期（active/completed，注册表有定义但数据层未落）× 活跃度（时间戳阈值机械派生，现算现成）。不是"加一排状态徽章"，是排序/收起/调位的输入。
2. **显示排序及权重**：理解＝可解释的机械权重函数（状态分+时间分段+访问计数+置顶位），手工永远压自动，重算只在安全时机。
3. **自动收起折叠**：理解＝只收"系统撑开的、变冷的、超限的"，绝不收用户亲手展开的；空闲窗执行，可撤销可关。
4. **自动调整位置**：理解＝权重变化（随时算）过四道闸后平滑移动到新位；与折叠记忆正交（管形状 vs 管顺序），漂移三重补偿。
