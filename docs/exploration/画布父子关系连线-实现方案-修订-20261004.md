## 三处待定项的收敛（原 §4.2 Ⅰ-3／Ⅰ-4／C-6）

### Ⅰ-3（收敛）· 可见集 `visibleIds` 的构造

**原状态**：两组并列改法「随裁定择一」。

**收敛为**（`canvas.js:411-413`）：

```
visibleIds = { viewRoot } ∪ 全部直接子卡
           ∪ 每一张「已展开卡」的全部直接子卡   ← 递归向下，随展开态增长
```

**实现要点**：
- 新增一个函数 `computeVisibleIds()`，由 `state.viewRoot` 与 `state.expanded`（展开态集合）共同算出可见集；
- **默认 `expanded` 为空集** → 首次打开 = 根卡 ＋ 全部二级卡（正是用户第 1 分句）；
- **`state.viewRoot` 不再随点击改变**（就地展开不换根）；
- `getVisibleIds()`（`:599-609`，现有整子树遍历）**本次不用**——它算的是「一次性全展开」，与折叠树的增量展开语义不同；保留原样、不动它（它的唯一调用点是「整理画布」`:835`）。

### Ⅰ-4（收敛）· 两个旧布局函数的处置

**原状态**：「停用还是删除，取决于裁定」。

**收敛为**：**两者都不删、不再被 `computeLayout` 调用**。

| 函数 | 处置 |
|---|---|
| `layoutNarrativeAxis`（`:139-263`） | **保留在文件内、不再调用**（不删除：删它会牵动 120 余行、增大回归面；且它内部有本链未读透的段落） |
| `layoutGridMatrix`（`:265-281`） | 同上 |

**处理方式**：`computeLayout` 的分派逻辑（Ⅰ-1）改为**只走新的树形排布函数**，两个旧函数的调用点移除、函数体保留。**打点三**（全日志打点第三条）恰好用于验证「旧函数确实不再被调用」——**打点保留原设计，意义从「待定」变为「验收依据」**。

### C-6（收敛）· `▸N` 徽章的新语义

**原状态**：「验证方式待定」。

**收敛为**：**徽章从「下钻入口」变成「展开/折叠开关」**。

| 项 | 原语义 | 新语义 |
|---|---|---|
| `▸ N` 徽章（`createNode:456-459`） | 单击 `setViewRoot` 换视图根（`bindNodeEvents:476-483`） | **单击 = 展开/折叠该卡的子树**；图标随态切换（`▸` 折叠 → `▾` 展开） |
| 双击卡片（`onDoubleClick:558-567`） | `setViewRoot` 换视图根 | **同样改为展开/折叠**（与徽章一致，避免两套交互） |
| 单击卡片（`onSingleClick:554-556`） | 打开工作区（`Workspace.open`） | **不变**（本方案不碰工作区联动） |
| 面包屑（`renderBreadcrumb:372-400`） | 显示下钻路径、可回上层 | **保留**（视图根不再变化时，面包屑退化为静态显示；不删） |

**C-6 的可复核判据（替换原「验证方式待定」）**：
> 展开一张有 N 张子卡的卡后，该卡下方出现 N 张子卡节点，且徽章文字由 `▸ N` 变为 `▾ N`；再点一次，N 张子卡消失、徽章变回 `▸ N`。验证方式：DOM 计数该卡的子节点数变化 ＋ 读徽章 `textContent`。

## 新增设计点Ⅲ · 折叠树模型（四项）

### Ⅲ-1 · 缩略卡渲染（对应「二级卡的缩略标题信息」）

**核心事实（本环节实读，两条关键发现）**：

**发现一 · 摘要机制已经在跑**（`canvas.js:730-752`）：

```js
734:       const concl = (card.body && card.body.conclusion) || "";
735:       const firstLine = concl.split("\n").map(s => s.trim()).find(s => s) || "";
736:       const summary = firstLine.length > 120 ? firstLine.slice(0, 120) + "…" : firstLine;
```

摘要 = **卡片结论区的第一行非空文字，上限 120 字符、超长加省略号**；由 `lazyLoadVisibleSummaries()`（`:755-770`）在每次渲染后自动填充。

**发现二 · `l0/l1/l2` 层次样式已经写好、JS 侧从未接上**（`static/style.css`）：

| 行 | 规则原文 |
|---|---|
| `:293` | `.card-node.l0 {` |
| `:304-307` | `.l0 .tname { white-space: nowrap; overflow: hidden; text-overflow: ellipsis; }` ＋ **`.l0 .ttype, .l0 .summary, .l0 .meta2 { display: none; }`** |
| `:310-311` | `.card-node.l1 { width: 220px; height: auto; min-height: 86px; max-height: 170px; }` ＋ **`.l1 .meta2 { display: none; }`** |
| `:319` | `.l1 .tname { 单行省略 }` |
| `:322-323` | `.card-node.l2 { width: 260px; min-height: 120px; max-height: 340px; }` ＋ 单行省略 |
| `:313`／`:325` | `.l1 .summary` ／ `.l2 .summary` 各自独立样式 |

而 `createNode`（`:446-470`）只加 `node.className = "card-node"`（`:449`）——**全文没有任何一处挂 `l0`/`l1`/`l2` 类**（本环节 grep 全文件命中为零）。

**设计（利用现成资产，不新造样式）**：

| 卡的形态 | 挂的类 | 效果（由现有 CSS 决定，本方案不写新样式） |
|---|---|---|
| **一级卡（视图根）** | `l2` | 完整显示：标题 ＋ 类型 ＋ 摘要 ＋ 更新时间（260px 宽） |
| **二级卡（默认可见）** | `l1` | 标题 ＋ 类型 ＋ 摘要（**`meta2` 被 CSS 隐藏**，220px 宽） |
| **更深层（展开后出现）** | `l0` | **只显示标题**（`ttype`/`summary`/`meta2` 全隐藏） |

**依据**：用户「所有二级卡的缩略标题信息」——`l1` 档 + 现有 `summary`（120 字首行）**已完全满足**，不需要新的摘要逻辑、不需要新的 CSS。

**「缩略标题信息」的度**：`l1` 显示「标题 ＋ 类型 ＋ 摘要首行」，`l0` 只显示标题。**本稿按上表分配；若用户要二级卡也只显示标题（更紧凑），把二级卡从 `l1` 改挂 `l0` 即可——一行代码的差别，标为可调项。**

### Ⅲ-2 · 折叠态的数据结构（展开态存哪）

**新增内存态**（`canvas.js` 的 `state` 对象内）：

```js
state.expanded = new Set();   // 已展开的卡片 id 集合；默认空
```

**四条硬性约束**：

| # | 约束 | 依据 |
|---|---|---|
| 1 | **只存内存，不写 `canvas.json`** | 红线①（本方案不得新增任何写 `canvas.json` 的路径） |
| 2 | **刷新页面即回默认（全部折叠）** | 用户 13:16 未要求记忆展开态；**标为待确认项**（见文末） |
| 3 | **换视图（若有）时不清空** | 本稿视图根不变化，无需处理；若后续恢复下钻，需明确清空策略——**列为将来项，本稿不做** |
| 4 | **不新增任何持久化载体** | 与「发号本」（`.card_id_seq.json`）不同：展开态是**纯视图态**，不是数据 |

**依据**：折叠态是**看的姿势**不是**内容**——用户的画布数据（`canvas.json`）里不该出现「我今天打开了哪几张卡」这种噪声。

### Ⅲ-3 · 就地展开的布局重算

**交互流程（替换现有的 `setViewRoot` 换根流程）**：

```
用户点卡片（或它的徽章）
  ↓
① state.expanded 增/删该卡 id
  ↓
② computeVisibleIds() 重算可见集
  ↓
③ computeLayout() 重跑树形排布（Ⅰ-2 的新函数）
  ↓
④ renderCanvas() 重绘（节点增删 + 位置更新）
  ↓
⑤ renderEdges() 重画线（父子线 + 关系线）
```

**关键点**：

| 点 | 说明 |
|---|---|
| **不调 `setViewRoot`** | 视图根不变——这就是「就地」的全部含义 |
| **不调 `fitView()`** | 画布**不跳视野**（`fitView:579-597` 会把视野居中到新内容，展开时跳视野会打断用户）——**保留其定义、展开路径不调用**；「整理画布」等既有调用点（若有）不受影响 |
| **兄弟卡让位** | 由树形排布函数（Ⅰ-2，按子树宽度分配横向空间）自动完成——展开一棵子树后，其右邻兄弟自动右移 |
| **新增函数 `toggleExpand(cardId)`** | 载荷：更新 `state.expanded` → 重跑 ②～⑤；同时更新该卡徽章图标（`▸`/`▾`） |
| **`renderCanvas` 的重绘粒度** | **保持全量重绘**（`:404` 先清空 `nodeMap` 再重建）——理由：树形排布本来就要重算全部坐标，增量重绘的复杂度收益不成比例；性能风险见下 |

**性能风险（如实标注）**：全量重绘在卡片数多时（股权财政那棵展开后约 23 张卡）会有一次同步 DOM 重建。**本稿不预设结论**——**判定条件写死**：若实测展开耗时（`performance.now()` 前后差）超过 **100ms**，则改为增量重绘（只增删变化的节点）；否则保留全量。**该阈值是本次新立的技术判据，不是用户要求**，实施者可据实测调整并在回报中说明。

**一处必须写死的边界**：**展开态变化时，绝不触发任何 `canvas.json` 写入**——现有写路径只有拖拽（`persistCardPos:814-830`）与「整理画布」（`reorganizeBtn:833-847`）两处，**本次新增路径为零**。

### Ⅲ-4 · 动效

**核心事实（本环节实读）**：`static/style.css:228` 逐字：

```css
transition: left 0.3s ease, top 0.3s ease, width 0.2s, height 0.2s, padding 0.2s;
```

**这是 `.card-node` 自身的 transition**（`:219` 是 `.card-node {` 规则块起点）——**卡片的位置与尺寸变化本来就有平滑过渡**。

**所以「展开动效」的绝大部分是白送的**：展开后其他卡让位的位移，会自动带 0.3s 缓动。

**需要新增的只有两处**：

| # | 新增动效 | 实现方式 | 依据 |
|---|---|---|---|
| 1 | **新出现的卡淡入** | CSS 加一个 `.card-node.entering { animation: card-in 0.18s ease; }` ＋ `@keyframes card-in { from { opacity: 0; transform: scale(0.96); } }`；JS 在新节点上加 `entering` 类、`animationend` 后移除 | **本环节新立**（现有 CSS 零 opacity 动画，见 style.css 命中清单） |
| 2 | **连线的补间** | **不做补间**——SVG `<path>` 的 `d` 属性无法靠 CSS transition 平滑变化；若要做需 JS 逐帧插值，复杂度不成比例。**处置：展开时线直接出现在新位置**（与卡片淡入同步，视觉上可接受） | **本环节新立（取舍）** |

**四条动效纪律**：

| # | 纪律 | 理由 |
|---|---|---|
| 1 | **只对 `opacity` 与 `transform` 做动画**，不对 `left`/`top` 之外的布局属性做 | 这两个属性走合成层、不触发重排 |
| 2 | **时限 ≤ 300ms** | 与现有 `:228` 的 0.3s 一致；超过会显得拖沓 |
| 3 | **拖拽时动画必须关闭** | 现有 `.card-node.dragging { transition: none; }`（`:234`）**保留原样**——展开动效不得破坏这条 |
| 4 | **不得用动画掩盖布局错误** | 若展开后卡片重叠或错位，**这是布局 bug，不许靠"慢一点看不出来"糊过去**——验收按 C-4 的机械判据（`layout[child].y > layout[parent].y`）判，与动画无关 |
