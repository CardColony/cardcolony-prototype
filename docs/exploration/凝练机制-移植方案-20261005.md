## 四、路线选择（本方案核心，须用户裁）

**路线甲 · 完整凝练线**（dsh 形态）
新建独立记忆域（chain 节点 ＋ 水位 ＋ 账本字段）＋ 凝练管线（读窗口 → 模型写四栏 → 提交）＋ 常驻投影（200 区）＋ 展开工具。
规模：dsh `condense.ts` 实读 **236 KB**（TS）。推演需重写为 Python。

**路线乙 · 影子升格**（利用推演已有资产）
推演**已有影子卡**（card_005 已上线）：三节、有界结构化、由模型主动写。
把它从「按需拉取」升格为「装配时常驻（200 区）」——即等价于 dsh 的 P4 区；session 原文仍按水位切段（mark）。
优点：**不需要新 chain schema、不需要凝练管线**——因为影子本身已是「模型写的结构化记忆」。
代价：影子是**模型主动记**（card_005 裁定 4），无强制管线 ⇒ 有界性只能逼近，不能保证。

**路线丙 · 甲＋乙**
影子当「轻记忆」常驻，凝练产物当「重记忆」入库。

【提议】**先乙后甲**：乙的成本只是「往 T11 空闲的 200 位插一个区」，可在一期内独立验收；甲的前置（水位／锚点）由乙顺带建成。若乙的实测收益够，甲可以不做。

> **这是本方案与 T11 方案最大的不同**：T11 是「照搬 dsh 的形状」；凝练线**未必要照搬**——因为推演已经长出了自己的记忆器官（影子）。方案的核心判断是：**先问推演缺的是「管线」还是「常驻」**。若缺的是常驻，乙就够。

## 六、分期施工（每期可单独上、可单独退）

### 第一期 · 锚点与水位（纯机械，零模型调用）
1. `read_session` 读侧按块索引编号 seq（第 n 块 = seq n）。
2. 影子 fm 加 `covers`（机械回填）。
3. 建 memory 文件行（`digested_until = 0`）。
- **验收**：covers 区间并集 = 全部消息，无洞、不重叠；seq n 能取回第 n 条原文逐字。

### 第二期 · 常驻投影（路线乙的落地，可独立验收）
1. 区表插 order 200「我的记忆」。
2. 内容 = 当前卡影子三节（常驻）＋ 子树影子**机械指针行**（§五-12 待裁项）。
- **验收**：逐字比对（T11 V1/V2 同法）；日志可复现「这轮看到了哪些子卡、各是几点的」。
- **注意**：此期会让「上下文＝全部历史」这条现状不变式**被改写**（新增常驻记忆区），须用户先裁 §五-11。

### 第三期 · 凝练管线（路线甲，规模最大）
1. 分窗读原文 → 模型写四栏 → 提交 → 推进水位。
2. 触发线 K（待裁）。
- **验收**：失败水位一分不动；幂等提交不产生重复节点；按锚点展开逐字等于 session 原文。

### 第四期 · 归拢折叠（可选，需工具调用能力）
1. 每 5 批触发，三步（判断 → 凝练 → 转填）。
2. **命名必须与 T11 轮折叠区分**（见 §二）。

## 七、红线与冲突（施工方必读）

1. **`gateway.py` 禁止修改** ⇒ 凝练**不能**复用「记忆凝练官」mock 席位；须走 `model_service` 独立调用（先例：T11 的 `_compress_round` 实读 `gw.call("main", …)`）。
2. **T11 的「不新增任何工具」红线，只适用于装配线**。凝练线的展开工具（`memory_expand`）**必须新增**——这是范围声明，不是违反。
3. **T11 的逐字比对基准会被破坏**：`BASE_PROMPT` 常量是 T11 V1/V2 的比对基准；新增工具必须写进 `BASE_PROMPT` 的工具清单 ⇒ **改基准**。
   ⇒ 前置动作：T11 验收基准须**版本化固化**（旧基准存档），改后重新固化。
4. **凝练模型席位**：实读 `models.yaml` **无凝练席位**（dsh 有独立 `zhipu-coding / glm-5.3-flash`）。须裁：复用 main 还是新增席位。
5. **失败哲学划界**（同 card_015 §8.7）：dsh 是「兜底＝癌症」；推演是「机械兜底接住模型产出形态缺陷」。凝练线失败＝**水位不动 ＋ 响亮报错**，不得用兜底接。
6. **无闸代价**：dsh 靠强制管线保证有界；推演无闸 ＋ 影子模型主动记 ⇒ 只能逼近，不能保证。
