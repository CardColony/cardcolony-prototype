### 环节3 · 建卡弹窗 →「根卡对话界面」现状（用户骂的「假界面」）

- 弹窗创建 → sessionStorage 携标题 → 跳 /work/{wid}/card/draft → **后台落库真发了**（POST /api/works + POST /api/works/{wid}/cards，实测网络序列确认）→ replaceState 换真 URL。

- **决定性一验**（walk3，真实选择器 #inputBox / #runBtn）：
  - 真卡页（子卡 card_002、根卡 card_001 各测）：发送 → 气泡立刻上屏（msgRows 1→4）、timeline/stream/tokens 链全活 ✓
  - **草稿卡页：发送 → POST 真发出（消息实际已送达后端）、按钮转 running、但气泡永不上屏、消息区纹丝不动、零 JS 报错——静默死。刷新后一切都在。**
- **根因（代码钉死）**：enterNewCard 给**显示**绑的是临时板 `new-N`（workspace.js:235-238）；落库完成后 send() 拿**真卡号**写真板 `c:{wid}:{cid}`（:883、:894-900 optimisticUser/start/pullUserBubble）——**写的板 ≠ 显示的板**，消息进了没人显示的板。这就是「假界面」的全部机制。

## 三、目标流程（每环节五件套）

### 环节1 · 点「＋新建项目」

- **现状**：三入口 → /work/draft 空白画布（上表）。
- **应该**：不管从哪点，直达**根卡对话草稿页**——看起来就是真对话页：标题「新项目」、空消息区、输入框、**光标已落位**。一次页面加载（本机 <1s），零 POST。
- **差距**：落地页类型错（画布页≠对话页）＋三入口行为不一。
- **修法**：
  1. main.py：`/work/draft` 特判 → 渲染**对话模板**（card.html 形态，注入 `__WORK_ID__="draft"`、`CARD_ID="draft"`）——本方案唯一后端改动；
  2. 三入口统一跳 /work/draft（home.js:33、workspace.js:1535 不变；canvas.js:1764 由 enterDraftProject 改 location.assign）；
  3. main_chat 装配草稿态：IS_DRAFT_PROJECT、根卡草稿（标题「新项目」）、**不拉任何 /api/works/{wid}/** 接口**（draft 无库可查）。
- **证明（V1）**：三入口各测：落地 body=page-chat、#inputBox 可见且聚焦、消息区空、标题=新项目；网络仅模板/静态/nav 类 GET，**零 POST、零 4xx/5xx**。

### 环节2 · 第一条消息（上一版死的地方）

- **现状**：POST 真发出但界面死（P2）。
- **应该**：点发送——气泡立刻上屏、回答照常流出、URL 静默换真、左栏出现新项目。用户全程只做两件事：打字、点发送。
- **差距**：写的板≠显示的板。
- **修法（已定，不甩选项）**：send() 草稿分支（workspace.js:868-875）扩为三步——① await ensurePersisted()（已有）→ ② **换绑显示板到真键**（把 open() 的板绑定逻辑抽成 bindBoard(wid,cid)：EventFlow.activate＋消息容器切换）→ ③ 再走现有 optimisticUser/start/pullUserBubble **一字不动**。气泡延迟＝persist（本机实测 POST /api/works 百毫秒级）＋渲染，合计 ≤500ms，无感。无重复气泡风险（换绑后才落第一条）。
- **证明（V2/V3）**：
  - V2：草稿首条——气泡 ≤500ms 上屏；网络序列恰为 POST /api/works → POST messages →（stream/timeline 常规）；URL 静默换 /work/{wid}/card/{根卡}；左栏新项目排最前。
  - V3 对照：同一动作序列在草稿页与真项目根卡页各跑一遍，气泡时序/上屏行为/网络形态**零差异**（脚本断言「不可区分」——真界面的终极证明）。
