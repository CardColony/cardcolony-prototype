# 画布卡片互斥（不论怎么拖动、永不重叠）· 修复方案

（card_016 §十八 的载体文档 · report-only · 2026-10-06）

## 〇、复核结语
- **需求成立**：§十七已证现状三缺陷（拖过即 pinned → 避让对 pinned `continue` 失明 → 新卡槽位纯树形数学），「重叠」是系统**可达到且反复达到**的状态。用户要求升级为硬不变量：**任何操作后，可见卡两两不相交**。
- **病灶单句**：避让算法看不见 pinned 卡 ＋ 拖拽落点无仲裁 ＋ 新卡落位不看钉子实际坐标——三者叠加。
- **修复取向**：把「重叠」从可达到改为**结构性不可达**（MindManager 式）。

## 一、需求
- **R1（硬不变量）**：任意时刻，画布可见集中任意两卡矩形不相交（含 GAP）。覆盖场景：新建、展开、换档穿越（L0↔L1↔L2）、摘要懒加载回填（卡高变化）、手动拖动松手后。
- **R2（手动位被尊重）**：pinned 语义保留；仅当松手点落在他人身上时做**最小位移**（正在拖的卡让先在场的卡——用户意志时序）。
- **R3（树形列结构尽量保留）**：子树在父右侧；分离**纵向优先**。
- **R4**：纯前端，刷新即生效、零重启；canvas.json 存储格式零改动。

## 二、现状机制（§十七复核 ＋ 本轮补钉）
1. `resolveOverlaps`（canvas.js :359-391）：按初始 y **一维分带**避让；pinned 直接 `continue`（注释自陈「不参与分带、不被移动」）⇒ 钉子在碰撞体系里不存在。
2. `persistCardPos`（:1060-1069）：拖拽松手**无条件** `pinned:true`，**无落点仲裁**——拖到谁身上就落在谁身上。
3. `layoutTree`（:344-368 附近）：槽位纯树形数学（COL_W=340 / GAP_Y=40 / 回退高 86·深层 36），**不看 pinned 实际坐标**。
4. `renderCanvas`（:482-488）：清空 nodeMap 后才 computeLayout ⇒ 首绘分离只能用回退尺寸；摘要回填后 `scheduleReflow`（100ms 防抖）重跑避让——**既有链路，可复用**。
5. 施工前置侦察项（本轮未逐行读，施工第一步先钉）：①`reflowLayout` 本体；②`onDragUp` 行号；③GAP 常量复用点。

## 三、业界借鉴与检索边界（如实标注）
- **检索实况（2026-10-06 双通道）**：SearxNG 失败；备用通道返回改写文本——MindManager 官方文档**未命中**「重叠自动避让」直接原文；Xmind 仅有「大纲拖动重组结构」「AI 重新调整布局」「专区自动调整大小」；MindLine／知犀等均无。
- 故按此类产品**通行设计模式**提炼（非引文）：
  - **P1** 自动布局为常态，手动定位为局部例外（free topic 语义）；
  - **P2** 重叠＝错误状态，系统主动消除——手动放下的卡把自动卡挤开，自动卡永不与自由卡叠；
  - **P3** 一键整理兜底（本系统「整理画布」已有：全 unpin＋重排）；
  - **P4** 拖动过程允许穿过（跟手），定型以**松手**为准。

## 四、修复设计（三组件）

### C1 `separateOverlaps` · 二维分离纯函数（新增约 40 行）
- 输入：`layout {cid:{x,y}}`、`sizes {cid:{w,h}}`（回退 220×86，深度≥2 回退 36）、`pinnedIds: Set`。
- AABB 相交检测（含 GAP）；**MTD 最短轴分离、纵向优先**（`oy <= ox` 推 y，否则推 x——保树形列结构）。
- **pinned 永不被移动**；free–pinned 相交：推 free 全量；free–free：各推 MTD 半量。
- 迭代上限 16 轮；不收敛则截断＋`console.warn`（如实标注可能残留）。
- 双 pinned 相交：不动＋warn（C3 保证**不新增**；历史遗留由「整理画布」清——现盘三张互不相交，无包袱）。
- 挂 `window.separateOverlaps` 供测试（对齐 `resolveOverlaps` 既有暴露模式）；`resolveOverlaps` 函数**保留不删**（观测兼容）。

### C2 接线（改 1 行）
- `reflowLayout` 内避让调用点：`resolveOverlaps` → `separateOverlaps`。
- 首绘回退尺寸参与分离；摘要回填 → `scheduleReflow` → 实测尺寸再分离（既有链路复用，零新增链路）。

### C3 拖拽落点仲裁 `resolveDrop`（新增约 30 行）
- 位置：`onDragUp` 与 `persistCardPos` 之间插入。
- 逻辑：松手点与其余可见卡 AABB 检测；**无相交 → 零改动路径**；有相交 → **最小位移**到不交位（候选：y 向最近空档（同列卡按 y 排序找 ≥卡高+GAP 的间隙）优先，其次 x 向推出；取位移最小者）。
- 仲裁坐标交 `persistCardPos`（`pinned:true` 语义不变）。
- 语义：正在拖的卡让先在场的卡（P1/P2 一致）。

## 八、风险与代价（如实）
1. 二维分离的 x 位移可能弱化树形列对齐（纵向优先缓解，不消除）。
2. 极端拥挤下迭代不收敛：16 轮截断＋warn，可能残留个别相交。
3. 用户硬想叠时系统不让——即需求本意，非缺陷。
4. 分离引起的卡位移可见跳动（沿用既有 100ms 防抖）。
5. `resolveOverlaps` 成死代码（观测兼容所换，不删）。
