## 五、关键风险与处置

### 风险 1（最高）：保存抹掉「拆闸铁律」注释

**处置：`save()` 保头机制——从现有文件逐字提取头部，重新前置。**

```python
import re
_TOP_KEY_RE = re.compile(r"^([A-Za-z_][A-Za-z0-9_]*):", re.MULTILINE)

def _split_header(text: str) -> tuple[str, str]:
    """切出「文件头注释块」与「第一个顶层键起的正文」。无顶层键则整体为头。"""
    m = _TOP_KEY_RE.search(text)
    if not m:
        return text, ""
    return text[:m.start()], text[m.start():]
```

`save(cfg)` 改为：
```python
old = CONFIG_PATH.read_text(encoding="utf-8") if CONFIG_PATH.exists() else ""
header, _ = _split_header(old)
body = yaml.safe_dump(cfg, allow_unicode=True, sort_keys=False)
text = header + body          # 头部逐字保留（含 1-13 行拆闸铁律）
# 原子写：临时文件 → os.replace
```

**行内注释的处置**：不试图保留（无 `ruamel` 做不到），改为**迁移进 `note` 字段**——这也是更好的设计：`note` 能在界面上显示和编辑，比注释更有用。迁移时逐条抄录现有注释语义，**其中 `minimax-m3` 与 `qwen-max` 的「实测」注释必须完整保留语义**（它们解释了为什么关思考）。

**验收**：保存一次后，`diff` 头部 1-13 行必须逐字相同。

### 风险 2：写 `.env` 不刷新 `os.environ`

**处置**：`env_store.set_key()` 写完文件后，**同函数内** `os.environ[name] = value`。
顺序：备份 → 原子写 `.env` → 更新 `os.environ` → 调用方 `reload_gateway()`。

### 风险 3：仓库有并发改动（别的 agent 在动别的文件）

**处置**：
- 每次动手前**重新实读**目标文件（不拿本方案的记忆当磁盘现状）
- 只碰本方案 §三 列出的文件；发现非预期改动**不碰、记录、上报**
- **不执行任何 git 提交**（`git_auto_commit.py` 会 `git add -A`，会把并发改动一起卷走）

### 风险 4：拉模型列表的端点差异（已实测）

| 供应商 | 能拉 | 特殊处理 |
|---|---|---|
| nous | ✅ 422 个 | 直接 `GET {base}/models` |
| minimax | ✅ 9 | 同上 |
| aliyun | ✅ 16 | 同上 |
| zhipu | ✅ 11 | 同上 |
| deepseek | ✅ 2 | 需 `models_url`（无 base_url） |
| opencode | ⚠️ 默认 403 | **需伪装浏览器请求头**（`User-Agent` 等） |

**处置**：拉列表实现里对 opencode 类端点统一带一组浏览器风格头；实现时**逐家重测一遍**，不拿 2026-10-12 的数当永久事实。

### 风险 5：保存顺序错 → 「磁盘已换、内存没换」的半坏态

若先 `save()` 写盘、后构造 gateway，而新配置**能过结构校验却过不了 gateway 构造**（如某供应商 `protocol` 填了不存在的值），就会出现：**磁盘已是新配置、运行中的单例还是旧的**——期间磁盘与内存不一致，直到下次重启才暴露。

**处置：先验后写——「建」必须在「写盘」之前**（顺序见 §6.2 执行顺序）。
- **预检构造**：用 `gateway.build_gateway(new_config)` 构造一个**不换单例的临时对象**；抛错 → 400，**文件一字不动**
- 写盘成功后才 `model_service.reload_gateway()` 重读重建、一步换单例
- 写盘本身失败 → 从备份回滚

（`build_gateway` 是 `src/model_gateway/gateway.py` 的**既有导出**——`model_service.py:21` 正是这么 import 的，直接复用，不新增、不修改该文件。）

`src/api/settings_api.py`：`router = APIRouter(prefix="/api/settings")`

### 6.1 `GET /api/settings/models` — 读全量

响应：
```json
{
  "providers": { "nous": {"protocol":"openai","base_url":"...","api_key_env":"NOUS_API_KEY","models_url":"...","note":"..."} },
  "models":    { "haiku": {"provider":"nous","model":"...","temperature":0.3,"thinking":"auto","note":"...","retry":{...}} },
  "bindings":  { "execute":"haiku", "viewpoint":["minimax-m3","qwen-max","glm-5.3"] },
  "system":    { "default_model":"haiku", "fallback_model":"deepseek-pro" },
  "simple":    { "enabled": true },
  "retry_grading": { "enabled": false },
  "roles":     { "execute":{"display":"执行","note":"...","multi":false} },
  "key_status":{ "NOUS_API_KEY":{"configured":true,"tail":"a1b2"} },
  "meta":      { "path":"config/models.yaml", "mtime":"2026-10-12T16:00:00+08:00" }
}
```
- `roles` 由 `roles.list_roles()` 现读
- `key_status` **只给「是否配置 + 末 4 位」**，明文永不出接口

### 6.2 `PUT /api/settings/models` — 保存（校验→备份→原子写→热重载）

请求体：`{providers, models, bindings, system, simple, retry_grading}`

**校验规则（任一不过 → 拒存、文件一字不动、返回 400）**：
1. `providers` / `models` 非空
2. 每个模型的 `provider` 必须存在于 `providers`
3. 每个绑定值（字符串或数组项）必须存在于 `models`
4. `system.default_model` / `system.fallback_model` 必须存在于 `models`
5. 绑定 key 必须在 `roles.list_roles()` 里（不在 → **警告不拦截**，因为角色侧可能刚加/刚删）
6. 每个供应商必须有 `protocol` + `api_key_env`

响应（成功）：
```json
{ "ok": true, "reloaded": true, "models": ["haiku","deepseek-pro","..."],
  "backup": "models_20261012_161500.yaml", "warnings": ["绑定 'judge' 不在角色表，已忽略"] }
```
响应（失败 400）：
```json
{ "ok": false, "errors": ["模型 'xxx' 的供应商 'yyy' 不存在", "..."] }
```

**执行顺序（六步，见 §五 风险 5——「建」必须在「写盘」之前）**：
1. **结构校验**（本节六条规则）——不过 → 400，**文件一字不动**
2. **预检构造**：`new_config = model_config.compile(cfg)`（新增公开包装，包住现私有 `_compile`）→ `gateway.build_gateway(new_config)` 构造临时对象（**不换单例**）——抛错 → 400，**文件一字不动**
3. **备份**现文件到 `_backups/models_YYYYmmdd_HHMMSS.yaml`
4. `model_config.save(cfg)` **原子写盘**（临时文件 → `os.replace`）
5. `model_service.reload_gateway()` —— 从**磁盘重读重建**并一步换单例（热生效：不重启、不打断在跑调用）
6. 第 4 步写盘失败 → 从第 3 步备份**回滚**，返回 500

（第 2 步与第 5 步各构造一次 gateway：这是**纯内存**操作，无网络、无开销，换取「先验后写」的确定性。）

### 6.3 `POST /api/settings/models/fetch` — 拉模型列表

请求（二选一）：
```json
{ "provider": "nous" }                                   // 已保存的供应商
{ "base_url": "...", "api_key_env": "...", "api_key": "..." }  // 新增供应商、尚未保存
```
响应：
```json
{ "ok": true, "count": 422, "models": [{"id":"anthropic/claude-haiku-5.5","owned_by":"..."}] }
```
- 实现：`httpx.get(models_url, headers={"Authorization": f"Bearer {key}"}, timeout=15)`
- 密钥优先用请求体里的 `api_key`，否则从 `os.environ[api_key_env]` 取
- **不落日志、不回显密钥**

### 6.4 `POST /api/settings/models/test` — 测试连接 / 测试模型

请求：
```json
{ "kind":"provider", "base_url":"...", "api_key_env":"...", "api_key":"..." }
{ "kind":"model", "model_name":"haiku" }
```

## 七、`env_store.py` 设计

```python
def read_keys(path: Path) -> dict[str, str]           # 解析 .env，返回 {名: 值}
def mask(value: str) -> str                            # "sk-abc...xyz" → "····wxyz"（末4位）
def list_key_status(path: Path, names: list[str]) -> dict[str, dict]
def set_key(path: Path, name: str, value: str) -> None # 备份→原子写→os.environ 刷新
```

`set_key` 要点：
- 逐行读、找到 `NAME=` 行则替换，找不到则**追加到末尾**
- **保留其它行与注释原样**（不重排、不删注释）
- 原子写：临时文件 → `os.replace`
- 写前备份到 `_backups/.env_YYYYmmdd_HHMMSS`
- 写后 `os.environ[name] = value`
- 校验 `name` 为合法环境变量名（`^[A-Za-z_][A-Za-z0-9_]*$`），防注入非法键名

### 8.3 「拉取 → 勾选」交互（用户指定核心流程）

```
点「＋ 新增供应商」→ 填名称 / 端点 / 密钥
   ↓
点「拉取模型列表」
   ↓ POST /api/settings/models/fetch（用当前表单值，未保存也能拉）
弹出勾选面板（modal）
   ├ 已存在于 models 的型号 → 置灰标「已添加」，不可重复勾
   ├ 搜索框（422 个时必需）
   └ 多选 checkbox
   ↓ 点「添加选中」
只把勾选的写进 models 段：
   { 键名: 由型号名净化生成（去斜杠/点，如 anthropic/claude-haiku-5.5 → anthropic-claude-haiku-55）,
     provider: 当前供应商, model: 型号原文, temperature: 0.7, thinking: "auto", note: "" }
键名冲突 → 自动加后缀 -2 / -3
   ↓
回到页面，新模型卡已出现（**此时仍未保存，可继续编辑**）
```

### 8.4 保存流程

```
点「保存」
   ↓ 前端收集全部三块 → PUT /api/settings/models
   ├ 400 → 顶部红条列出全部错误，不关页面、不清表单
   └ 200 → 绿条「已保存并生效（N 个模型）」+ 显示备份名
```
