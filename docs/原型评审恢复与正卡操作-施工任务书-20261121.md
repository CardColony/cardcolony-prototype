# 原型评审恢复与正卡操作 · 施工任务书

**目标**　被评正卡能查清当前卡点、继续当前批次的一步，或点名调起一个缺票席位。三种操作共享现有评审状态、席位权限、属主 runner 和干预台账。先恢复评审可用性，评审缩量试点保持关闭。

## 一、正卡的三个操作

建议用 `read_review_status` 和 `resume_review` 两个工具覆盖三个操作。`resume_review` 的可选参数 `seat` 表示点名。两工具都以当前实际调用卡为被评正卡，通过现有伴生关系解析评审卡。系统从运行身份判断权限，任意评审卡号不能作为授权。人工操作可复用同一宿主入口和现有权限。 [伴生关系](../src/storage/review_store.py#L41) · [现有状态读口](../src/api/routes.py#L1401)

| 操作 | 工具行为与回执 |
| --- | --- |
| 查当前卡点 | 返回评审卡、批次、阶段、稿次、各席票及票所属稿次、缺席或过期票、现有下一步、等待的责任方和条件、最近一次续跑的结果与动作编号。分别显示「等待投票」「待正卡修订／定稿」「运行中」「有下一步但派发失败」等事实。读失败显示待核实。读取不触发回合。 |
| 继续当前一步 | 由正卡基于读回的当前批次和稿件身份发起。属主 runner 重新检查最新状态，按现有分类器确定可执行的一步。返回已受理／排队、已在途、等待条件、过期或失败，以及可查的动作编号。后续业务结果由实际动作回执确认。 |
| 点名请某席投票 | 先核对它是本批成员并确实需要表态。由 runner 按现行评审规则判断先请首次发言、补票，或运行已到期的增量确认。定点可以跳过默认的席位挑选顺序，仍须满足该席的阶段条件。只调起所选的一席，席位自行决定通过或否决。 |

点名判据以真票为准。已有当前有效票时返回该票和稿次。已有否决且等待正卡回应时，返回回应缺口。旧版本通过票在正式需要增量确认时按 `confirm` 接续。上一轮是否存在意见按已接受的本批发言和现有材料契约核对，纯占锁失败按未发言处理。 [现有步骤分类](../src/api/review_runner.py#L412) · [真实票态](../src/storage/review_store.py#L815)

## 二、接线顺序

1. **先接好可复查的状态。** 复用 `review_store.status` 和 runner 的步骤分类，补齐等待原因、实际责任方和最近一次动作的回执。状态和步骤引用基于同一批次及草稿原文。展示最近一次有效票和本轮新增票两个事实。续跑不得因为旧票存在就报告当前步骤完成。
2. **复用已有续跑链。** 正卡提交动作后持久登记、异步转给评审卡属主，立即返回受理状态。属主执行前核对评审卡、批次、稿次、指纹和对应步骤。定点席位使用同一套阶段判据，服务端计算该席的实际步骤，避免拿自动挑出的另一席步骤作 `expect`。遇换批、改稿、席位状态变化先对账，旧请求按过期收口。 [属主入口](../src/api/routes.py#L3475) · [现有步骤身份](../src/api/review_runner.py#L1889)
3. **让忙冲突可恢复。** 手工、自动和点名请求对同一实际步骤共用去重身份。忙时复用原动作等待属主释放，保留原因；投递失败保留实际错误和重试办法。恢复前重新核对当前状态。请求已受理、实际起轮、落下新票或推进阶段分别记账。席位启动返回 409 时，发言标记和补票依据不推进。场务普通回合与评审席位保持现有身份划分。 [干预台账](../src/infra/intervention_store.py#L379) · [恢复入口](../src/infra/intervention_runner.py#L768)
4. **先修已知断点，再验操作。** 所有 runner 使用一致的续跑契约，确认 `expect` 从登记经过转发到属主。恢复沿当前批次接上缺失步骤，保留此前有效票、草稿、用户裁定和意见。若当前仍缺席位动作或正卡修订，按对应业务步骤处理。尊重用户停止、暂停和已有等待条件。

| --- | --- |

| `011 → 012` | 场务占锁期间请求一席，记录忙及等待状态。释放后同一安排只兑现一次。首轮启动失败时保留该席未发言事实。 [现场 409](../works/work_073/events/card_012.jsonl#L4570) |

| 并发和控制 | 自动续跑与正卡请求同时到达，重复请求和在途换批均可对账。用户停止或现有等待条件仍有效。恢复后原批证据可回读，过期请求不会作用到新批。 |
