## 0. 一句话结论

**B-03 的真实形态不是"散落的绝对路径"，而是「路径根由代码所在位置决定、不由运行配置决定」**：src 里绝对字面量只剩 1 处，但"项目根"被独立求值 **17** 次、派生出 **40** 个模块级路径常量，运行期同一进程出现 **2 套根**；连带后果是文件工具的缺省落点跨产品错位、备份写进别人的树、打包后数据会落安装目录。
**B-04 的真实形态不是"几个延迟 import"，而是「没有层，只有事实上的共享内核」**：反向边 19 条（2 顶层 + 17 延迟）、包级导入期环 1 个（api→thinkchain→permissions→api）、storage 包内两对互导、跨模块私有符号访问 **90** 处（旧账只算了 import 的 10 处）。

**修到什么线**（四条机械判据，可 grep/AST 复核）：
- B-03：绝对字面量 = 0；`Path(__file__).parents[N]` 求值点 = 0（全部走 `src/paths.py`）；运行期"不同根个数 = 1"；同一语义不得有两份求值。
- B-04：下层→上层反向边 = 0；包级导入期环 = 0；storage 包内互导 = 0；跨包私有符号访问 = 0（同包私有允许）。
- 两条都**不以"清零所有历史包袱"为标准**：B-03 不要求 88 处 `BASE_DIR` 引用全部改名；B-04 不要求本轮就拆 storage→api 的 9 条（要引入事件注册机制，见 §5）。

**第一批切口**：B-03 三刀（file_tools 止血 → 快照根显式化 → 单点求值），B-04 两刀（拆导入期环 → 私有符号升格）。B-04 的两刀不进同一批，顺序见 §5。

## 1. B-03 判定（每条都可在 f822911 上复核）

### 1.1 绝对字面量只剩一处，但"根"有 17 个来源

| 判据 | 实测 | 位置 |
|---|---|---|
| C1 绝对路径字面量 | **2**（1 处真、1 处无关） | `src/api/file_tools.py:38` `BASE_DIR = Path(r"D:\AI_station")`；`src/api/env_store.py:65` 的 `'\\\\'` 是 UNC 前缀判断，**非**路径根 |
| C2 根求值点 `Path(__file__).resolve().parents[N]` | **17** | 见 §7 清单；`src/roles.py:23` 用 `parents[1]`，其余 16 处 `parents[2]` |
| C3 模块级路径常量 | **40** | `BASE_DIR`×15、`WORKS_DIR`×6、`BACKUP_DIR`×2、`CARDS_DIR`×2、`SESSIONS_DIR`×2、`SNAPSHOT_ROOT`×1、`ENV_PATH/LOGS_DIR/CONFIG_PATH/…` 各 1 |

要点：C1 干净不代表问题解决。**"同语义多份求值"才是病**——17 个求值点任意一个写错 `parents[N]`，就会静默指向另一个目录，而没有任何一处会报错。

### 1.2 运行期同一进程存在 2 套根（决定性证据）

`python verify/5713/arch_scan.py --runtime`，子进程 import 12 个模块取 `BASE_DIR`：

- 主仓（`D:\AI_station\推演agent`）：`file_tools.BASE_DIR = D:\AI_station`，其余 11 个模块 = `D:\AI_station\推演agent`
- worktree（`.worktrees\5713`）：`file_tools.BASE_DIR = D:\AI_station`，`env_store/data_snapshot.BASE_DIR = D:\AI_station\推演agent\.worktrees\5713`

⇒ **`C4 不同根个数 = 2`**。这就是"一个进程两套根"的机械形态：文件工具的边界是 **station 根**，数据根是 **项目根**，两者被同一个名字 `BASE_DIR` 混着用。

### 1.3 备份写进别人的树（跨实例污染，盘上实证）

- `src/api/file_tools.py:82` `BACKUP_DIR = BASE_DIR / "推演agent" / "_backups"` —— 目录名 `推演agent` **写死在代码里**

- 后果：5713 实例写 `.worktrees\5713\src\...` 时，备份落到 `主仓\_backups\推演agent\.worktrees\5713\src\...`
- 盘上实证：`D:\AI_station\推演agent\_backups\推演agent\.worktrees\` 下 **117 条**（`5713\` 与 `5713_sandbox\` 两棵），时间戳 2026-10-20 15:56–20:04

### 1.4 数据根不由配置决定（打包即坏的根因）

### 1.5 快照根随目录名（与"数据快照域"交界）

## 4. B-04 判定

### 4.1 反向边 19 条（2 顶层 + 17 延迟）

- **顶层 2 条**：`src/permissions/policy.py:36 → api.prompt_log`、`src/thinkchain/model_pick.py:15 → api.model_config`
- **延迟 17 条**，按包聚合：`storage→api` 9、`goal→api` 4、`storage→permissions` 3、`goal→permissions` 1
- 具体落点（全列）：
  - `storage.card_store` → `api.event_stream:810`、`api.scheduler:1010`、`api.auto_driver:1016`、`api.role_room:1231`、`permissions.policy:175/189/1158`
  - `storage.memory_store` → `api.model_config:413/572`、`api.model_service:413/572`
  - `storage.work_store` → `api.model_config:173`
  - `goal.driver` → `api.auto_driver:179`、`api.message_runner:223`、`api.routes:224`
  - `goal.tools` → `api.role_room:110`、`permissions.policy:201`

**要点**：`card_store` 的写路径本身嵌了广播、调度、角色同步四个上层动作（`_notify_card_changed` :807、`create_card` :1010、`update_card_fields` :1231）。这是"存储层没有事件出口，只能反调上层"的结构后果，不是谁懒。

### 4.2 导入期包级环 1 个 —— 但**模块级无环**（这个区别必须写清）

- 包级 SCC = `{api, permissions, thinkchain}`：`api/card_tools.py:58 → thinkchain/plan_tools.py:35 → permissions/policy.py:36 → api/prompt_log.py`
- 模块级 top-only SCC = **无**
- ⇒ 验收若只写"环 = 0"而不写口径，下一个人既可能把"包级有环"当没修完，也可能把"模块级无环"当已修完。**判据必须是"包级 SCC 全为单点"**，并同时断言"模块级仍无环"（防止拆包级时造出模块级环）。

### 4.3 storage 包内互导 2 对（环存在，靠"局部 import"掩盖）

- `card_store.py:23 → work_store`（**顶层**），`work_store.py:136 → card_store`（函数内，源码注释逐字写着「局部 import，避免与 card_store 形成顶层循环」）
  ⇒ 这是**运行时环 + 导入期无环**：注释自己承认了环的存在，只是把它下沉到函数里
- `card_store.py:989/1322 → shadow_store`（函数内），`shadow_store.py:30 → card_store + data_snapshot`（顶层）——同一手法，方向相反
- `session_facade.py:75 → card_store`（顶层，单向）
- `memory_store.py:413/572 → api.model_config + api.model_service`，注释「延迟导入：storage 装载期不依赖 api（唯一调用点）」——第三种手法：用延迟 import 把反向边"藏"起来（D1 的 17 条 lazy 大半是这么来的）
- ⇒ 我这次用 Tarjan 扫 storage 内 SCC 得到"空"是**假阴性**（延迟边归并丢了方向），本节的 2 对来自**逐文件核对**。`arch_scan.py` 的 D2 只对包级负责 —— 这条偏差如实记下，下一批做 storage 拆分前需先修扫描器，否则会误判"已清零"。

### 4.4 私有契约：90 处访问，不是 14 处

- **跨模块私有属性访问 90 处**，集中在 8 个符号：`_meta_of` 17、`_rel` 10、`_now_iso` 10、`_collect_card_meta` 9、`_spawn_tracked` 5、`_run_message` 5、`_root_project_class` 4、`_credential_excluded` 3
- **跨模块私有 import 10 处**（`_is_placeholder`×4、`session_facade` 锁工具×4、`_now_iso`、`_apply_block_set`）
- 要点：这 8 个符号不是"没注意写了下划线"，而是**事实上的共享内核**：`card_store._meta_of` 有 17 处调用（跨 9 个模块），`file_tools._rel/_resolve` 是 `card_tools` 处理路径的唯一入口（11 处）。判"私有契约外泄"时用 import 计数会低估 9 倍。

## 6. 会波及什么（跨域，按域点名）

1. **测试可信度域（card_010）** —— 最大单点风险。`tests/` 里对路径常量的 monkeypatch **42 处 / 15 个文件**（`conftest.py` 9 处：`BASE_DIR/ALLOWED_ROOTS/BACKUP_DIR/WORKS_DIR/SNAPSHOT_ROOT/LOGS_DIR/TYPE_REGISTRY_PATH/_FINGERPRINT_FILE`）。切3 若做成 import 期快照，这 42 处全部静默失效：**测试全绿但写真实目录**。⇒ 切3 的验收必须包含"注入一处、所有模块跟随"，并要求 card_010 补一条用例（monkeypatch `paths` 后任意模块 `WORKS_DIR` 跟随）。
2. **数据快照域（card_009）** —— `SNAPSHOT_ROOT`(:34) 与 `_FINGERPRINT_FILE`(:44) 都从 `BASE_DIR` 派生；切2/切3 会改这两个值的算法。硬要求：改造前后同一 work 的快照列表逐条相同，`.worktrees\5713_data_snapshots` 仍可索引（否则等于删了存量快照）。
3. **凭证域（card_012/013，已收口）** —— `src/api/credential_guard.py:206` 直接读 `file_tools.BASE_DIR`（station 根）作为采集上界，另有 `project_root()`(:189) 从 `__file__` 自推项目根 ⇒ **已经是第二套根**。paths 落地时它必须改用 `paths.project_root`，否则 B-03 修完仍有一处自算根；但**采集分层（层1 项目先扫、层2 station 后扫且只给零头）是 D12 验收的事实基础**，改动必须保持层1 预算最足，否则等于回退 D11/D12 的结论。
