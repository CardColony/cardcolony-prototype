## 一、做了什么（三文件）

### T1 · `src/storage/card_db.py` 补聚合原语

新增第四个 inbox 原语 `list_inbox(work_id, target_card_id=None)`（含内部
`select_inbox`）：按 work（可选按收件卡）列**全部**消息行——**含 consumed**——
按 `seq` 升序，行转 dict 复用既有 `_inbox_row_to_dict`。

既有三原语（`append_inbox` / `list_pending` / `mark_consumed`）**一字未动**，纯新增。

### T2/T3 · `src/api/routes.py` 数据源切换

`list_card_messages` 重写数据获取，**返回结构逐键不变**：

| 字段 | 新来源 | 映射 |
|---|---|---|
| `id` | inbox `msg_id` | 原样 |
| `ts` | inbox `created_at` | 原样 |
| `seq` | inbox `seq` | 原样 |
| `from_card` | inbox `from_card` | 原样 |
| `from_title` | 经 `iter_card_metas` 取 | 同旧 |
| `to_card` | inbox `target_card_id` | 原样 |
| `msg_type` | inbox `type` | 原样 |
| `type_display` | 注册表 `display_of` | 照旧后端取 |
| `summary` | inbox `content` 剥头行后前 80 字 | 与旧源同语义 |
| `format_ok` | 恒 `true` | inbox 行均结构化写入 |

1. **items ＝ inbox 全量（含 consumed）∪ 旧档案扫描的 card: 块**。按 `ts` 倒序合并、
   `msg_id` 去重（同一 `msg_id` 不会双源出现——旧机制落对话块、新机制落收件箱；
   去重仅作防御）。旧扫描逻辑**保留**为第二源，存量历史因此不丢。
2. **unread_by_card 只看 inbox `status=pending`**，逐卡二值计 1；无 pending 的卡
   **不出现在字典里**。旧机制的 `find_pending` 推导在此退役。
3. **`card_msg_consumed` 打点已移除**：其语义（「端点侧发现信已被处理」）在 inbox 下
   不再成立——consumed 事实已由 `card_db.mark_consumed` 在回合收口落库
   （`message_runner`），端点不必再推断。端点侧 `mark_consumed` / `ops_log`
   调用与相关注释一并删除；**本次是删写、不是加写**，纯读端点更纯。
   `card_msg.mark_consumed` 函数本体保留（退役归化石清理批次）。
4. 排序与截断照旧：`ts` 倒序、`limit >= 0` 时截断。

### V5 的诚实边界

「前端零改动」是**结构契约**判据，不是浏览器实测判据。本批已核对前端真实消费的键：

- `static/canvas.js` `refreshUnread`：读 `d.items` 的 `it.id` / `it.to_card` 与
  `d.unread_by_card`（角标刷新）；
- `static/workspace.js` `renderPanel`：读 `format_ok` / `to_card` / `id` / `ts` /
  `from_title` / `from_card` / `type_display` / `summary`，已读键为 `${to_card}:${id}`；
- `static/esm/api.js` `getCardMessages`：仅拼 URL。

上述键全部在返回结构内、形态未变（`format_ok` 仍为 bool、`ts` 仍是本地 ISO 串、
`summary` 已剥机器头行）。**未做浏览器实点验证**——如需端到端过一遍未读→已读流转，
建议在服务起来后人工点一次确认。

### 性能口径（如实修正任务书预判）

任务书预判「性能净改善」。实测口径需修正一句：**inbox 侧确实更省**（单表索引查询
`idx_inbox_work` / `idx_inbox_target`，一次查全 work），但按 T3 合流要求，**旧的全量
会话扫描仍在跑**（历史源），故**端点总耗时暂未净改善**。两源并存，直到化石清理批次
退役旧源为止（不在本任务）。此项已写进代码 docstring，不留误导。
