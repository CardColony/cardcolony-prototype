# 通用工具调用与真实回执修复任务书

在推演原型完成通用工具调用修复及可复跑取证。所有纳入公共派发链的工具使用同一套调用识别、权限校验、执行取证和回执规则。用真实的查证、搜索、写入和卡间指令做代表性验证。先读 [修复方案](工具调用与真实回执-修复方案-20261119.md) 和 [项目规则](../AGENTS.md)。施工与实跑使用隔离数据和服务实例。现网 5700 重启必须另获用户明确同意。

## 施工顺序

1. **锁定基线。** 对齐 `work_073/card_007` 的 11937–11942、模型调用日志和接收卡 4692、4806。补录至少一例读取或搜索工具的异形调用，优先取原始日志，再用离线构造的原生坏分片、合法 CLI 调用及伪回执覆盖边界。原样记录现有回归的失败、跳过和已启用的兼容路径。
2. **统一调用来源和协议失败。** 盘点当前工具注册表和可产生工具执行或副作用的入口，逐个标出共用派发和仍有特殊处理的路径。从实际适配器传递协议类型与停止证据，追到循环、派发和回执。识别截断、缺名、参数不完整及无可执行调用的相应停因。使用现有执行器和权限。核对 `text_tool_rescue`、模型回退、Harness 的二次唤起及正文建卡等已有路径。在隔离验收模式按协议处置这些入口，保留声明文本协议的 CLI 能力。兼容派发单独标来源。
3. **修正历史存根。** 以结构化执行状态生成成功、失败和未知回执。用真实结果渲染器产生样本，检查最终请求配对、旧会话兼容和 `context_board` 两侧。
4. **实现当前轮提示和回执核对。** 在当前轮区提供实际协议与待执行状态的短提示。循环在当前任务已有执行要求时按对应回执完成，并反馈实际失败原因。无副作用的协议漏调或参数问题可做有限纠正。对回执缺失且副作用可能已经发生的动作保留待核实。同步检查流式界面、最终文本、会话存档和刷新恢复。
5. **按真实入口离线复验。** 使用可控模型输出和隔离落账验证公共链路。对原始漏调案例保留普通用户消息入口。在专用操作入口验证执行要求、目标和回执是否对应。四类工具通过同一流程取证。确需工具特定的验收时，逐项注明所核对的资源和结果语义。

## 确定性验收

每条记录输入、预期、实际、是否匹配及证据位置。允许用模型替身产生协议或正文，成功路径须进入真实工具处理器和隔离资源。源码行号、文件内容和搜索结果使用模型无法从提示词猜到的固定测试数据。

| 场景 | 通过标准 |
| --- | --- |
| 明确要求读取，模型编写调用日志和结果 | 首轮实际调用为零，界面没有通过核实的读取状态。纠正后若真的读了，答案要与测试数据一致。 |
| 真查证与真搜索，搜索分别命中和无匹配 | 验证 `read_card` 与 `search_files` 的请求、执行和回执，结果对应实际资源与查询范围。 |
| 真写入、写入被拒、无关工具成功 | 使用一个现有卡面写工具，核对隔离卡最终状态。受拒和错误目标没有副作用，无关工具回执无法确认写入。 |
| 真下达指令，接收方正常、有记录但运行态未受理 | `direct` 经过原权限和通信线校验。核对接收方指令与验收判据，分别显示落信与运行态状态。验证 `ECO_NO_AUTO_DELIVER` 的作用。 |
| 原生模型用 XML、自由格式 JSON 或陌生标签代替实际调用 | 原始通道和异常可查，无正文触发副作用。纠正时告诉模型真实协议；换成完全无法识别的新写法时，已绑定动作仍显示未执行。 |
| 声明文本协议的端点给出合规调用；相同片段出现在普通引用或代码示例 | 只有合规端点按声明位置提交的调用被派发一次。引用、工具结果内嵌文本和模型推理中的样式保持为数据。 |
| 原生 stop reason 表示工具调用，但调用缺名或参数截断；一批中混有有效和无效项 | 能区分模型未调与网关未得到有效调用。坏项无副作用，重发不会重复执行已成功的项。 |
| 传输中断、模型回退、用户停止或动作被重新处理 | 按实际端点和阶段留证。已有副作用和结果未知均可追查，正常停止有效，重放不会重复写入。 |
| 只拟稿、解释格式、引用旧编号或追问「做了吗」 | 无误派发。已知事项从匹配的执行记录查证，无法关联时明确说明。 |
| 新旧历史投影含正常结果、标准失败、未知状态或残缺调用对 | 状态准确，调用与结果配对完整，凝练与长期上下文保持既有原文预算。 |

用项目方式跑回归。新增专项应经过正常消息入口，至少捕获网关首次请求、调用来源与结果、最终对话状态。能力受限时验证没有误派发。跨 runner 转发要能对上同一请求与回执。

## 超长会话使用观察

弱模型漏调和格式漂移只在超长会话中自然出现。该现象的改善情况按正常使用观察，施工验收以确定性用例为准。当实际会话出现漏调、异形调用或假回执时，按工作、会话和回合查已有日志，核对实际端点、输入体积或历史区读数、首轮输出类型、派发及回执。确认是零调用、协议失败、未派发，还是执行后交付有误。

用现有观测记录留证。遇到正常执行的同类案例时，也记下真实调用和结果。没有可比的自然案例时，弱模型改善记为待观察。
