**为什么要迁（问题的根）**：卡片现在是 `.md` 一坨——机器记账（哈希/权限/工具卡字段）与内容（三块正文）同层；通用文件工具 `read_file`/`search_files` 能直接把它整份读进上下文（含 `## 修改历史` 的 `[外部修改]`/`[权限刷新]` 噪音）。文件本身没有"只取一块"的能力。SQLite 让**区域独立成列**、取什么查什么，且文件工具**够不着**（.db 是二进制，`read_file` 拒读）。

## 1. 新的卡片数据结构怎么搭

### 1.1 库与位置

- **每 work 一个 SQLite 文件**：`works/{work_id}/cards.db`。
- 理由：work 已是现有隔离单位（快照按它、路径按它、测试沙箱按它）；跨 work 查询只有左栏导航一处，循环几个库不影响。
- 备选（全局一个库）未采纳：work 隔离变弱、库膨胀、快照粒度变粗。

**表 `meta`**（key/value，work 级计数等）

- 存编号序列（`seq` / `issued`），替代 `.card_id_seq.json`——**让库自包含**（备份一个文件即完整）。
- 备选：保留 `.card_id_seq.json` 不动（改动面更小，但备份不完整）。**待裁。**

### 1.3 几个关键取舍

1. **第三块一列**：现在盘上区头可能是 `## 定论` 或 `## 需求文档`（后者是 `card_draft` 写完再改盘的补丁产物）。库里克子里只有内容，"叫什么名"由本树 `project_class` 决定（读时决定）。
   → **顺手消灭两处历史包袱**：正文分块的"新旧区头兼容层"（`_detect_form`/`effective_form`/`_section_table`/`OLD_KEY_TO_NEW`），以及 `card_draft._rename_rulings_to_requirements` 那个改盘补丁。
2. **不设 `content_hash` 列**：文件级哈希的唯一用途是"检测文件被人手改"，不留 md、不让手改后失去对象，**退役**。
   （注：起草/确认那套冲突检测用的是**块内容指纹** `card_draft._block_hash`，对块文本算、与文件格式无关，**保留不动**。）
3. **修改历史独立成表**：它是逐条追加的列表，独立成表比塞一列干净，也符合"区域独立"。
4. **列表字段用小 JSON 列**（tags/relations/perms）：它们是短列表、不是"内容区域"，不拆表（避免过度设计）。
5. **区域独立**：使命/现状/第三块/修改历史 在库里是**四个互不相干的地方**；影子三节也是**三处互不相干**。

## 2. 老的数据怎么迁移

### 2.1 迁移对象

- **13 个 work**；约 **94 张正卡 ＋ 93 张影子**（＋各 work 的编号序列）。
- 会话（sessions，约 93 个 .md）**不动**。

### 2.2 步骤（可重入、md 只读）

1. **先备份**：对全部 work 跑一次全量快照（`data_snapshot.snapshot()`）——这是"改之前"的完整副本。
2. **建库建表**（幂等）。
3. **读 md → 写库**：逐 work 逐卡：
   - `parse_front_matter` → 各列；
   - `split_body_sections` 拆三块 ＋ 修改历史 → 各列/各表；
   - 影子文件 → `shadows`；
   - 编号序列 → `meta`。
   - **复用现有解析函数**，保证与旧读侧逐字同口径（尤其存量 `old`/`mixed` 形态卡的保形）。
4. **对账**：逐卡比对——库里读出的三块/字段 与 迁移前 md 读出的**逐字一致**。
5. **切换**：代码切到走库（见第 3 部分）。
6. **验证全绿后**，才删 md。
7. **删 md**：删 `cards/*.md` 与 `shadows/*.md`（确认库＋快照都在）；**保留 `sessions/`**。
8. **再拍一次快照**。

### 2.3 风险与回退

- 迁移脚本**只读 md、只写库，不改 md**；md 的删除是**单独一步、放在验证之后**。
- 回退通道：删 `cards.db` ＋ 从快照恢复 md。→ 故"删 md"必须最后做，且**删前再拍一次快照**。
- `old`/`mixed` 形态存量卡：迁移时按 `effective_form` 保形读入 → 三块内容原样进列，**形态概念消失**（库里不需要形态）。

### 3.2 关键不变量（迁移后怎么表达）

- 原铁律「任何代码路径都不允许删除 `cards\` 或 `sessions\` 下的文件」→ `cards/` 消失；等价护栏＝**删卡只走 `delete_card` 一个口**（现状即如此），**会话文件仍受铁律保护**。
- 「canvas.json 是可重建缓存、卡片文件才是真身」→ 改为「canvas.json 是派生缓存、**库**才是真身」。

### 3.3 实现决策（我已定，写明理由；不同意可推翻）

1. **`read_card()["raw"]` 退役**。理由：`raw` 是"md 整篇文本"，与"区域独立、不留 md"直接相悖；它原本只服务于"整篇覆盖写"与"外部修改检测"，两者都已退役。消费方（`card_tools._h_edit_card`、若干测试）改为直接取 `meta`/`body` 的键。将来若确有"需要整篇文本"的场景，**按需渲染、不常驻字段**。
2. **编号序列进库**（`meta` 表 key/value）。理由：库要自包含——备份一个文件即完整；且发号与建卡可在同一事务内完成，避免并发重复号。
3. **canvas.json / layout.json 保持文件**。理由：属画布线、不在范围②；`layout.json` 是用户数据（拖拽坐标）、`canvas.json` 是派生缓存，与卡片存储正交。仅把 `canvas.json` 的**数据源**从 md 改成库。
4. **会话 sessions 不进库**。理由：会话是"对话历史"本身（进上下文是它该在的地方，不算污染）；范围②未含它。

## 7. 自核：按此方案执行会有什么问题（2026-10-14 自查，附实测数据）

### 7.1 会真出问题的（含修法）

**7.1.1 WAL 会让"变化检测"失灵（真 bug，必须解）**
`/nav/version` 靠 `_work_fingerprint` 扫 `work.json`＋`cards/*.md`＋`sessions/*.md` 的「路径+大小+mtime」算哈希。卡片进库后，SQLite 默认 **WAL** 模式把写入落在 `cards.db-wal`，**主文件 `cards.db` 的 mtime 可能不变** → 指纹不变 → 前端以为"没变"、不刷新。
**修法（我选）**：在 `meta` 表维护单调递增的 `rev`（每次写 +1），指纹直接读它——不依赖文件系统语义。备选：指纹纳入 `-wal` 文件，或 `journal_mode=DELETE`。

**7.1.2 快照改 .db 有两个坑**
- (a) **WAL 下不能直接复制 `cards.db`**（拿到的是不含最新提交的快照）→ 须用 `VACUUM INTO` / `Connection.backup()` / 先 checkpoint。
- (b) **`VACUUM INTO` 每次重写整库**，而 `snapshot()` 是**每次写卡都调**——库大了就是"每写一次卡、重写整个库"。
**修法**：先用 `VACUUM INTO`，**第一步验收时实测单次耗时**；不可接受再改攒批（合并短时间内的多次写为一次快照）。

**7.1.3 并发模型必须先定死（否则会写出"偶发卡死"）**
`sqlite3` 是**同步**库。现在文件 IO 走 `asyncio.to_thread`，库化后同样必须 `to_thread`，否则**阻塞事件循环**；且 SQLite 单写者，多连接会 `database is locked`。
**定法**：每 work 一个连接 ＋ 一把 `asyncio.Lock` 串行化（沿用现有 `_get_lock` 思路），连接 `check_same_thread=False` 且只在锁内使用。

**7.1.4 `_write_gate` 自己也是文件派生的，必须一起改**
闸 3 用 `_card_path(work_id, owner).exists()` ＋ `_meta_of(...)` 判 owner——都是文件操作。库化后不改，**闸 3 直接失效或报错**。（原方案把它笼统算进 card_store，这里点名。）

**7.1.5 新模块的路径常量会让测试沙箱失效**
`tests/conftest.py` 只 patch 了"storage 五件套"的 `WORKS_DIR`。新增存储模块若有自己的模块级 `WORKS_DIR` 常量，**conftest 不会 patch 它** → 测试写进真实 `works/`（违反测试铁律）。
**定法**：新模块**不设模块级路径常量**，一律调用时从 `card_store.WORKS_DIR` 取（项目既有纪律，见 `board.py`「绝不缓存 Path 于模块级」）；conftest 同步显式加 patch。

### 7.2 数据现状里已存在的问题（迁移会把它固化）

- **7.2.1 有 2 张卡没有影子**（实测）：`work_002/card_048`、`work_007/card_001`。→ 迁移时顺手补派生（`derive_shadow` 幂等），否则库里"一正一影"缺两对。

- **7.2.3 无区头的卡：0 张**（实测）——无内容会因"拆不出三块"而丢失。但机制风险仍在：`split_body_sections` 遇无区头正文会三块全空、正文全丢。→ 迁移脚本必须**逐卡断言"三块拼起来不丢内容"**。
