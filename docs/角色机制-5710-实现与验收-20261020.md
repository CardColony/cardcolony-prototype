# 角色机制 · 5710 落地说明（2026-10-20）

## 一句话

角色卡是**离树的观察者**：由根卡组阁、写职责书；工作卡与它连线＝订阅；工作卡每回合收口时系统把新增内容机械同步给它；它被唤醒后自行判断**发言还是沉默**，发言走建议/警报双通道；**每次判断都落账（沉默也落账）**。

## 机制

1. **离树**：`card_type=role`、`parent=""`；不可有子卡（写门显式拒绝）。角色卡不占任务树、不继承父子授权语义。
2. **组阁**：根卡工具 `create_role(title, charter, watch_card_ids)`；也可在根卡右栏「角色（参谋线）」表单直接建。职责书由根卡写入，用户可改。
3. **订阅**：`role_room.link()` 双向写边——角色卡 `links: {target, type:"关注"}`，工作卡 `links: {target:role, type:"角色"}`。建线时游标置为当前末尾，不回灌历史。
4. **同步（机械）**：工作卡回合收口 `role_room.after_turn()` 按会话 `seq` 区间把增量记进角色卡的 `sync.jsonl`（只记区间，不复制正文）；角色回合开始时按区间读源会话拼材料。
5. **巡检（模型）**：调用 `_run_message(role, prompt, append_user=False)`；角色卡使用专用 `ROLE_CARD_BASE_PROMPT`，工具面只有读/沿连线读/影子/发建议/读收件箱/判词/警报/写自己的现状定论。它自行决定发言或沉默，并可自行选择收件卡。
6. **沉默落账**：每次巡检必须调 `record_verdict(decision, reason)`；模型没调时系统机械补记 `silent + auto=true`。台账文件 `roles/<role>/verdicts.jsonl`，同时追加影子卡 `## 进度`。
7. **双通道**：建议 `send_card_message(msg_notify)` 进工作卡收件箱；警报 `raise_alarm(severity,title,detail)` 进 `alarms.jsonl`，左栏项目行红点、角色页警报区、导航铃铛可见。
8. **判例复利**：角色卡自己的 `## 现状` 写「最近看到了什么、判断如何」，`## 定论` 由 `append_ruling` 累积判断标准/判例；同一角色的后续巡检会带着这些沉淀。
9. **防打转**：同一角色两次唤醒最小间隔 2s；角色回合收口后若仍有新同步，冷却后追一次；角色卡之间 v1 不通信。

## 边界（v1 明确不做）

- 角色卡**没有否决/拦截权**：只建议与警报，不改别人卡、不建卡、不调文件命令。
- 角色卡之间不通信；不做跨项目共享角色（先按项目内单例）。
- 不做自动解雇/考核；新增/撤关注由根卡或用户操作。
- 同步节奏＝工作卡回合收口（不按事件逐条推）；单批材料上限 24k 字符。
