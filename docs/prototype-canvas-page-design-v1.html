    ② 关键视觉决策与理由

    每条写：定了什么 → 为什么 → 落到哪个令牌/选择器。可以不同意，改令牌即可，不用改结构。

    1｜明度层级取代描边层级：画布最深、浮层最亮

    bg(#0c1015) → surface(#12171e) → surface2(#171e27) → raised(#1f2731) 四级台阶，每级只差一点明度。 结构靠「谁压在谁上面」表达，不靠加粗描边——这样信息密度高也不会变成一堵线网。 代价：单靠明度不够，所以承载边界信息的描边另走 --stroke-strong（≥3:1）。

    2｜强调色只给三件事：主操作、选中、焦点环

    --accent 不出现在任何卡片底色、标题、状态点上。理由：画布上同时有 7 类卡 × 6 种状态， 强调色一旦用于装饰，用户就无法靠颜色判断「哪里能点、哪里是当前」。品牌蜂蜜金同理，只进品牌标。

    3｜状态色与类型色分两族，永不同时落在一个元素上

    状态只用「色点 + 状态词 + 描边」；类型只用「左条 / 徽标 / 底栏同名格」。同一张卡上两者并排但不争夺同一像素， 所以 7 类 × 6 态也不会串味。四态容器（加载/空/错误/无权限）不复用状态色，避免「错误」与「受阻」被读成同一件事。

    4｜运行中＝呼吸，其余全静止

    只有 data-state="run" 有动效（1.9s 呼吸点）。「还在跑的」会动，「可以看结果的」不动——这是密度极高的画布上唯一需要的动态线索。 reduced-motion 下呼吸降为静态高亮点，状态词仍在，功能不缺。

    5｜三类线两维可区分：颜色 + 线型/端点

    父子线＝中性灰实线正交折线（结构的形状）；通信线＝强调蓝曲线 + 流星虚线流动 + 收件端实心点（信息传递那一下）； 依赖关联线＝紫点线 + 端点菱形（只记关系、不参与通信）。灰度打印或色弱下仍靠线型分得开，矩阵见「自检」页。

    6｜卡片三重重可触知区分，不只靠色相

    结构卡：左条 4/3/2px 表深度 + 实线框 + 压面底色；工作卡：无左条 + 虚线框 + 浮起一号底色（--raised）。 缩到 40% 看不清文字时，粗细与虚实仍在；色相只是第四重确认。

    7｜命中区一律 24px，不靠视觉尺寸撑

    --hit:24px 统一给图标按钮、树行、菜单项、分段书签、缩放钮。视觉上按钮仍可以画得小而精， 但可点范围不小于 24×24——密集布局里这是最容易被牺牲、也最影响使用的一条。

    8｜阴影只表层级，不做装饰

    三级：--shadow-1（卡片悬停/演示坞）、--shadow-2（面板、书签组展开）、--shadow-3（浮窗、命令面板、设计说明）。 卡片常态无阴影——画布上同时几十张卡，每张都投影会糊成一片，层级反而是靠明度台阶说清的。

    9｜中文字体优先，字号阶只给六档

    字体栈 PingFang SC → Hiragino Sans GB → Microsoft YaHei → Segoe UI；数字/编号/原因码走等宽， 避免中文比例字宽把编号挤成不等宽。字号只给 6 档（16/14/13/12/11/10），不出现 12.5、11.5 这种半档—— 半档在中文里读不出差别，只会让实现期各自微调。

    10｜非 active 置灰必须带原因码，不只变灰

    置灰降低饱和（saturate .35 / opacity .62），但状态词改成中性色、不再用状态色；左侧补原因码 （如 R-STEP-08）+ 一句为什么。灰是「它现在不推进」，不是「它不存在」。

    11｜LOD 四档做减法：先减事实、再减字、最后只留图标

    far(<58%) 只留图标型徽标 + 标题 + 状态 + 子卡数；near(58–71%) 补前 2 项事实；full(72–95%) 全量事实； ultra(≥96%) 事实行整行替换成「最近一条说了什么」（同高替换，不撑高）。档位切换在过渡末，缩放途中不跳字。

    12｜动效只服务理解：三段节奏，不改语义

    --t-fast 120ms（悬停/按下）／--t-mid 200ms（面板让位、浮层推入）／--t-canvas 400ms（折叠展开、适配）。 缓动统一 cubic-bezier(.4,0,.2,1)，位移用 (.22,.75,.2,1)。手势永不过渡——过渡会让画面追不上手。

    ④ 自检读数（页内现算，不是自述）

    三组读数在页面加载与切主题时重算：① 文字/非文本对比度（WCAG 2.x 相对亮度公式，逐对列出） ② 命中区（遍历所有可点元素，读 getBoundingClientRect）③ 深浅令牌齐备性（缺一个即红）。 本页读数是什么，报告里就写什么；有红项就如实留着。

    ⑤ 四态两两可区分（含必查对：加载 vs 空）

    态形态与相邻态的区别
    加载骨架条（3 条 shimmer）+「正在取卡片树」有形状、无文字结论——「还没取到」
    空虚线空框图标 + 「数据已取回·一张卡都没有」+ 为什么确知为 0，有说明与下一步——与骨架完全不同形
    错误红边盒 + 502 码 + 就地「重试」+ 保留上次结果带错误码与可执行动作
    无权限中性盒 + E403 + 缺哪个 scope +「申请只读」不用错误红（不是故障），给的是申请路径

    ③ 需要你裁定的视觉选项

    三处我认为有争议的地方，各给候选。点一个即可（页内记住选择，不影响其他任何行为）。

    选项 1｜画布底 vs 面板底的明度关系

    画布是不是该比侧栏更暗？更暗＝内容区沉稳、框架后退；同明度＝界面更平、更像文档工具。

    A 画布最深（现方案）bg < surface B 画布与侧栏同明度bg = surface C 画布略亮bg > surface
    现方案 A：深色 UI 里画布最暗能压住内容、让 44px 框架后退；浅色 UI 里反过来（画布 #f1f2f0 比面板白更灰一档）。 选 B 会让卡片浮起感消失，需要靠阴影补；选 C 会把注意力分给框架。
    选项 2｜「运行中」用什么色

    运行中现在用青绿（#3fc7b4），强调色是蓝（#7aa2f7）。两者分开是为了不让「当前选中」和「正在跑」混淆。

    A 青绿 + 呼吸（现方案） B 蓝（与强调同源，靠呼吸区分） C 中性灰 + 只有呼吸点
    B 更统一但会和选中态撞色；C 最克制但 15 张卡同屏时「运行中」不够跳。
    选项 3｜父子线走向

    父子线现在走正交折线（先横后竖再横），依赖关联线走直线、通信线走曲线。

    A 正交折线（现方案） B 贝塞尔曲线
    A 更像结构图、更好追路径；B 更柔和，但会和通信线曲线撞形——那样三类线就只剩颜色一维可分了。
