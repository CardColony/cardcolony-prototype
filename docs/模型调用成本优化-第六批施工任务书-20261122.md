# 模型调用成本优化 · 第六批施工任务书

**目标**　凝练或归拢中途失败后，保留已通过校验的阶段产物。原文、可见性、选材或阶段契约发生变化时，按实际依赖重新计算。另做一组摘要缩量试验，按原文可找回性和整段任务的实际模型费用口径共同验收。 [总方案第七节](模型调用成本优化-方案与施工任务书-20261120.md)

**顺序**　固定改前样本和出站证据 → 修正归拢现有缓存 → 接入凝练阶段复用 → 验证恢复和发布 → 独立试验缩量。施工和验收使用隔离工作根，生产凝练继续由 condense 属主进程调度。 [凝练触发与调度](../src/storage/memory_store.py#L3170)

## 一、开工基线

1. 固定源码版本、模型绑定、提示模板、原文和记忆链快照。准备普通凝练窗口、跨片巨块、一个需展开原文的归拢组，以及一个出现取材或发布竞争的样本。样本至少包含一条人工裁定、一处被订正的旧结论、一项未完任务和一条带原文锚点的证词。
2. 主回放走 `condense_turn_end → _run_condense_pipeline`，归拢走 `_maybe_fold`，在实际 HTTP 发送边界截取请求并回传脚本化帧。可另用 `_condense_one_batch` 或阶段回调定位故障。改前先录下首次通过、末阶段失败后恢复、发布失败后恢复的实际请求数与提交结果。
3. 记录三类已知缺口。凝练的 `run_two_layer` 每次从 S2a 开始。归拢当前用顶层块号与 gist 生成总指纹，组级局部指纹只含成员块号。归拢目前在解析前写缓存，坏产物可以反复命中。拿本机回放确认各缺口对应的重复请求或陈旧命中。 [凝练阶段](../src/storage/condense_two_layer.py#L501) · [归拢现有缓存](../src/storage/memory_store.py#L2745)

## 二、阶段复用的共同契约

- 建议试点开关 `COST_MEMORY_STAGE_CACHE=1`。开态统一使用带版本的阶段缓存格式，沿用归拢已有的工作/卡目录和调度属主。关态走原路径。新格式与旧文件名分开，开态仅从新版记录取命中。文件实现采用同目录临时文件和原子替换，读损坏、半写入或写失败时按缓存缺失处理，沿原阶段和失败记账继续。阶段产物的寿命与体积须有界，交回实际采用的保留规则。
- **阶段身份由宿主构造。** 组成是工作、卡、原会话、阶段和子片范围、相关材料的有序身份与内容指纹、实际请求模型座及线路配置身份、系统与用户提示的指纹、影响产出的请求选项和阶段校验版本。原文按逐块或逐片结构入指纹，包括真实块号、次序、覆盖范围和影响可见性的宿主字段。阶段实际收到的记忆全景、成员材料和展开正文也算输入。窗口外追加且阶段输入仍逐项一致，允许复用。等长改写、块边界变化、顺序变化和当前阶段依赖的可见性变化，都要能使旧键失效。
- **阶段过校验后再缓存。** 每份记录带阶段、输入版本、产物、校验版本和来源调用编号，命中时用同一机械契约复核。可复用的结果包括合法分组、合规摘要、可核实的显式空结果和合规弃权。超时、断流、截断、解析失败、组数不对、越界锚点与发布失败都按各自状态记账。发布失败前已校验的阶段产物可留作候选，下次仍以现行输入重新核对。首次请求回包若与计算键时锁定的请求材料或线路不符，本次按未命中路径结算并记录错配。
- **缓存产物只是发布候选。** 继续使用 `save_memory` 的版本比较及一致发布。缓存命中仍要通过连续前缀、巨块全片覆盖、真实块号回填和原文复核。归拢展开的语料版本也要在提交时复核。读后改稿、撤销、隔离变更或链已换版时，旧候选停止发布，从当前状态重新取材。水位、链、节点索引、缓存板按现有事务一致变化。 [发布事务](../src/storage/memory_store.py#L305) · [连续前缀和失败账](../AGENTS.md)

## 三、先修归拢，再接凝练

### 1. 归拢的分组、组综合和展开续步

- **S1 分组。** 以 `_render_fold_step1` 实际材料和当前可选成员为准，覆盖子条、状态和排序。先过 `_parse_fold_groups` 及成员校验，再落盘。合法的「无组可并」沿已有 `judge-empty` 发布游标。分组响应不可解析时，保留失败游标，下一次重新请求 S1。
- **S2′ 组综合。** 按实际有序成员、线程标签、组内读取范围和 `_render_fold_group` 的内容构造键。相同块号与 gist 下，成员经过、结果、子条、锚点身份或实际选材改变都要失效。某个组改动只影响依赖该组材料的阶段。通过现有解析和组内锚点校验的合并、弃权、展开请求分别入账。
- **展开续步。** 先用当前成员核对展开坐标，再走 `_expand_for_fold` 的净化回灌。用本次实际展开的版本和回灌正文，与组输入一起定键。即使顶层 gist 不变，展开涉及的旧块有编辑、撤销、缺块或隔离改动，旧展开产物也要失效。走同一套净化视图和有界回灌，继续按每组一次往返结算。 [归拢组综合](../src/storage/memory_store.py#L2815) · [净化原文回灌](../src/storage/memory_store.py#L2414)

### 2. 凝练的 S2a → L1 → L2

- **S2a 定界** 使用当前有序分片及实际注入的记忆全景。通过边界单调、范围和覆盖校验后保存结果。分片键含原块号、分片身份和窗口内位置，保留 `seq=0` 兼容。
- **L1 结论** 按通过校验的分组和本阶段实际正文、全景定键。**L2 细节** 额外绑定实际喂给它的 L1 文本。若重新分组或 L1 换版，下游随实际依赖失效。L2 截断后恢复时，可复用已验证的 S2a 与 L1，只重新发 L2。L2 解析耗尽时沿现有结论发布与细节降级契约结算，留明状态。
- 继续由宿主 `assemble` 回填锚点、覆盖集和原块号。阶段缓存命中按零出站计，重试计数只计这次实际发出的请求。成功发布按数据库水位结算，失败沿 `condense_debt` 与现有退避恢复。 [S2a/L1/L2 校验和装配](../src/storage/condense_two_layer.py#L528) · [批次提交与分片](../src/storage/memory_store.py#L1710)

## 四、单独试验摘要缩量

建议用 `COST_MEMORY_COMPACT_PROMPTS=1` 管理试点，仅在新版阶段缓存启用时生效。用同一输入评估提示里的重复措辞、确定重复的材料和组内按需展开。L1 的关键事实和 L2 的细节职责沿原契约执行，`memory_expand` 的显式原文回读按现行逐字契约验收。阶段模板改动进入各自指纹。 [原文找回](../src/storage/memory_expand.py#L261)

优先比较不改输出上限的 A/B。在至少一组普通窗口和一组长窗口记录输入字节、实际输出 token、可取得的思考量、截断与重试。只有读数支持时才提交单独的上限试验，沿用当前模型配置默认值交付。逐条从原文核对关键事实及其先后、人工裁定、最新有效结论、证词来源、变更原因和未完事项。受控替身回放证明机械契约和出站差异。缩量要进入可用试点，还需提供真实模型样本或已留存的同条件实录做语义复核。证据缺席时，该分支保留关闭。

## 五、必须交回的隔离回放

| 场景 | 可放行的读数 |
| --- | --- |
| 同一输入重复 | 用同一未发布快照回跑，或注入一次发布失败再恢复。第二次命中的阶段实际出站为零，节点、锚点、覆盖集与一次成功基线一致。已正常出版的窗口再触发时，以游标退场另记。 |
| 凝练的中途失败 | L1 失败后 S2a 可命中。单片样本各阶段首次只发一次，首跑在 L2 截断。恢复后关态再发 S2a、L1、L2 共 3 次，开态只发 L2 共 1 次。第一次水位和板保持旧版。另测巨块缺片时旧块仍可见，补齐后水位只越过连续前缀。 |
| 归拢的中途失败 | 用真实阶段入口测坏 S1、坏组产物和合法弃权。坏产物下一轮能重新出站。已有合法展开请求、展开往返失败的样本恢复时只重发失效或未完成阶段。 |
| 原文或可见性换版 | 新块进入窗口、撤销范围内旧块、等长编辑、仅更改隔离状态各跑一组。一个范围外追加作对照。另测归拢子条、时间顺序、展开原文各变一次且顶层 gist 恒定。逐阶段列命中和失效原因。 |
| 阶段与租户边界 | 改 S2a 的定界、改 L1 产物、改阶段模板/模型座各有独立样本。跨工作、卡或原会话用相同文字和块号对照，旧缓存、损坏文件、半写文件都应按未命中结算。 |
| 冷恢复与并发发布 | 新进程或重开缓存与数据库后保住合法阶段产物。装配后换链、发布前撤销或改隔离状态，应拒掉旧候选。注入索引或裁板失败时四面保持同一旧版。 |
| 找回与语义核对 | 按锚点抽查正常块、隔离块、离散覆盖集和归拢合成锚点。显式找回逐字一致，后台回灌只见净化视图。输出及水位对照要能定位每个被保留的事实。 |
| 三组对照 | A 两开关关，B 只开阶段复用，C 再开缩量。B 要在指定失败恢复样本少实发请求并通过语义核对。C 要减少该样本的总输入或输出，保住同等任务证据且截断、重试和缺项均不增加。 |

```powershell
python -m pytest tests/test_batch6_memory_reuse.py -q

```
