## 四、实现决策（施工方定，写明理由；**可推翻**）

| # | 决策 | 理由 |
|---|---|---|
| 1 | 脚本 `scripts/migrate_cards_to_sqlite.py`；**只读 md、只写库**；**幂等**（可重入，重跑前先清该 work 的库或 upsert） | 幂等是回退的前提 |
| 2 | 复用现有解析函数（`hash_utils.parse_front_matter` / `split_body_sections`） | 与旧读侧**逐字同口径**，不另写解析 |
| 3 | 读侧归一照搬：`card_type` 缺 → `"线索"`；`parent` 缺 → `work_card_id` | 与旧 `read_card` 的兜底一致 |
| 4 | **缺影子的 2 张卡补派生** | 否则库里"一正一影"缺两对 |
| 5 | 影子「首个区头之前」的内容 → **丢弃（A 案，用户 2026-10-14 裁定）**，但**不静默**：逐条点名 ＋ 抄录原文；原始字节另存于迁移前快照 | 运行期读法（`split_shadow_sections`）**本就丢弃** ⇒ 迁移不引入新行为；不并入某节（违反「各区域独立、不得混」）；不为畸形内容扩表 |
| 6 | 编号序列进 `meta` 表（`seq` ＋ `issued`） | 库自包含（方案 §三决策 4） |
| 7 | 逐卡断言**"三块拼起来不丢内容"** | `split_body_sections` 遇无区头正文会三块全空 ⇒ 防静默丢字（实测当前 0 张，但机制风险在） |
| 8 | 为**全部 13 个 work 建库**（空 work 建空库） | 形态统一，避免"无库"未定义态 |
| 9 | 迁移期间**服务必须停止** | 消除"旧代码并发写 md ⇒ 库漏掉这次写"的竞态 |
| 10 | 写库走 `card_db.run_write` ＋ `insert_card` / `insert_shadow` / `set_meta_value` / `bump_rev` | 用第一步已交付的库原语，不另造 |
