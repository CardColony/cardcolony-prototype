## 四 生产风险专章（这是与沙箱最大的不同）

### 4.1 「auto＝权限全开」不能照搬

沙箱口径是 `auto_perms()` ＝ **16 码全集 ＋ `perms_version = -1`**。生产上这意味着**一张卡被点开自动，就能改任何卡、写任何文件、删任何卡**。

**建议（待裁）**：
- **方案 A（保守）**：auto 卡 = 该卡类型的 `compute_perms` **超集但带黑名单**——排除 `card_delete`／`file_write`／`rule_edit` 这类不可逆项，其余全开。
- **方案 B（可配）**：`config/auto_perms.json` 显式列出 auto 卡获得的开关集，默认＝A 的口径，运维可改。
- **方案 C（照搬）**：全开，靠"停止按钮 ＋ 沙箱外无此能力"兜底。**生产不建议。**

> 沙箱里"全开"是实验变量；生产里"全开"是事故面。

### 4.2 「无闸」与生产的冲突

沙箱口径：**不设轮次闸／时间闸／token 闸**，唯一兜底是手动停。
生产必须回答：**没人看着的时候它跑一夜怎么办？**

**建议**：保留"无轮次闸"作为默认（符合愿景），但加**两条可观测兜底**（不是闸）：
- 单卡连续 N 轮**无任何工具调用**（空转）⇒ 自动 `pause` ＋ 打点；
- 单卡 `goal_rounds` 超阈值（如 200）⇒ 只**告警**不拦，便于人工介入。

### 4.3 真实数据的不可逆操作

auto 卡若获得 `delete_card`／`write_file` 权限，一次误判就是真实损失。
**建议**：阶段 2 期间 auto 卡对**真实 work** 一律不给删除/写入类开关（用 4.1 方案 A），
等积累足够观察再逐项放开。

| 层级 | 回滚动作 |
|---|---|
| 代码 | 每阶段独立 commit ⇒ `git revert <commit>` |
| 库 | 迁移前的 `cards.db` 三件套备份原样拷回 |
| 运行 | 关掉所有 auto 卡的 `auto_mode`（PATCH `auto_mode=0`）⇒ 行为退回手动 |
| 兜底 | `exec_mode` 切 `serial` ＋ 逐卡 `stop_auto` |

## 五 验收纪律（从移交件提炼，生产照用）

1. **跑一次就下结论＝自证偏差**。自主性验收必须**多跑**（≥3）＋判据覆盖闭环。
2. **判读要等账本稳定**：`answer` 落库可晚于根卡收口；"根卡 complete"≠"故事讲完了"。
3. **闸的判据别用会陈旧的状态**（`status=pending` 依赖对方后续回合收口）——用实质事实。
4. **拒绝必须自带出路**，否则自主模型会换姿势重试，甚至去读源码，烧光预算。
5. **给对方造义务的消息要慎用**：确认类收尾用 `notify`（无回信义务），`ask` 会触发对向调起＋新义务。
6. **120s 工具上限**：等待用"单次快照＋拉大间隔"，别内嵌长睡眠。

## 六 待你裁的五件事

1. **auto 卡权限口径**：方案 A（保守黑名单）／B（可配）／C（照搬全开）？——**建议 A**。
2. **执行模式默认**：`parallel`（云端够用，快）还是 `serial`（稳，但一张卡跑到底会堵住其他卡）？——**建议先 `serial` 灰度，压测后转 `parallel`**。
3. **要不要"空转自动 pause"那条兜底**？——**建议要**（不是闸，是止损）。
4. **阶段 0 是"从 Cardlo 移植"还是"在 dev 上重写"**？——**建议移植后裁剪**（移植能保住已验证的判据与守卫测试；裁剪掉 §二 标 ❌ 的三类）。
5. **auto 卡要不要屏蔽思维链**（判断协议 ＋ 计划六件）？——沙箱是**全拆**（实验口径）。
   **建议生产只拆判断协议**（auto 卡已有 goal，"再判一次直答还是上板"会跟 goal 打架），
   **保留计划六件与计划板**（拆解上板是产品能力，不是脚手架）。

## 七 工作量与顺序建议

```
阶段 0（底座）      ← 必须最先，且非 auto 卡行为必须逐字不变
```

**阶段 0 与阶段 1 之间是硬边界**：底座没跑稳就上协作，会同时调试两层，定位成本翻倍。
