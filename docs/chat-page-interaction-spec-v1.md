# 对话页高保真原型 · 交互方案 v1

## 定版声明

- **定版对象**：`推演agent/docs/prototype-chat-page-v1.html`（单文件、零外链、`file://` 直开；当前 2013 行）。本文档的每一条读数都回查该文件。
- **本版口径**：事件类型一律以 **Cardlo（重构版）** 源码为准——`projection/session.go`、`projection/review.go`、`projection/task.go`、`executor/ports.go`、`protocol/message.schema.json`、`harness/deliver.go`、`webface/stream.go`。旧系统（原型版）的三席、计划板、注入分组**不采用**。
- **范围**：纯交互稿。只定**信息流形态 + 交互行为**，不做视觉设计——无配色（只有黑白灰与线）、无阴影、无渐变、无深度主题切换。状态一律靠**文字与线型**区分（实线／虚线、反白按钮、方框标签）。唯一的形态例外是用户消息气泡的圆角，见 §4.1。
- **本文档不写左栏**。左栏沿用现有原型的 UI 与交互，不属于本方案设计范围。

### 三条验收口径

1. **覆盖层不压正文**：抽屉／评审浮窗／类型索引打开时，正文**让位但不消失**，不盖住正文或输入区；无整页遮罩拦截点击（仅输入型模态可短暂接管，且必须带可见取消）。
2. **每个可进入状态有 ≥1 个鼠标可达出口**：Esc 只是加速键，不是唯一出口。
3. **不设无动作的中间态**：任何可见状态都对应一个可执行动作；点了没反应的控件不许存在。

## 二、信息分层（本页设计的主线）

读者是**一人监督多卡的监工**，不是聊天对象。打开这页做三件事：**扫一眼**（在干嘛、有没有等我决定的事）、**追过程**（出问题找哪一步开始错）、**查细节**（展开某一步看输入输出）。

### 2.1 四层层次（从重到轻）

| 层 | 内容 | 形态 | 位置 |
|---|---|---|---|
| ① 谁在说话 | 用户消息 / 助手回复 / 卡间信 | 用户＝右对齐气泡；助手＝左对齐文档流；卡间信＝左竖线引用块 | 顶格，靠**对齐方向**区分 |
| ② 环境在变化 | 建卡 / 状态变化 / 受阻 / 异常中断 / 交付物送达 / 写闸拒绝 / 评审里程碑 / harness 投递 | 一行小字，11.5px 灰 | 缩进 16px |
| ③ 机器在干活 | 过程组 / 工具行 / IN-OUT | 过程组默认收起，组头是内容摘要 | 缩进 16px，更小更灰 |
| ④ 契约字段 | 类型码 / fact_level / action_id / seq / idem_key | 只在轨迹视图 | 不进对话流 |

### 2.2 分流判据（按序判，唯一一条主问：这条信息帮读者解决什么问题）

1. **是对人说的吗** → 正文，**永不折叠**。
2. **是对环境／状态说的吗** → 一行小字，**永不折叠**（监工不看折叠内部也必须知道「卡建了／卡受阻了／评审出结论了」）。
3. **是机器干活吗** → 过程组，可折叠。
4. **是契约字段吗** → 只属轨迹视图。

### 2.3 与 Codex / DSH 的关系

两家是「一人一 agent」，本页是「一人监督多卡协作」。学的是**原则**，不是事件清单：

- 学：时间轴是唯一组织轴；回复永远可见；过程聚组靠内容摘要；用户输入是节奏锚点。
- 不学：它们的**全部事件域**。本页独有三族必须进流——卡间信（谁在跟我说什么）、harness 投递（**这轮为什么又开始动**）、待确认项（不决则流程停）。判据用「对谁说的」推导，不用「别家有没有」裁剪。

## 三、双视图：对话 chat ＋ 轨迹 trajectory

依据：DeepSeek Harness `docs/subsystems/conversation.md` 的**两个并列 target**（`chat` 给正常人看折叠后的对话，`trajectory` 全量铺开供检视），以及 Codex CLI 的 `history_cell` 单元体系。

**结论**：事件类型全集属于**轨迹视图**，不属于对话流。把 82 项按分组铺在同一根时间线里＝做成图鉴，不是对话——已废弃。

- 顶栏双页签：`对话 chat` ／ `轨迹 trajectory · 82`。默认对话视图。
- 两视图**常驻 DOM**（切换只动 `body.view-traj` 的 class），滚动位置互不干扰。
- 同一数据源：`G`（分组表）→ `ALL`（有序数组）→ `EV`（按 id 索引）。

### 3.1 轨迹视图

82 项按 11 个来源域铺开，组标题＝**组名＋项数**（无编号——编号不承载信息，纯装饰已删）。每行「类型码 ｜ 标题 ｜ fact/process ｜ 样例键」列对齐。**这里承担「类型全不全」的检视职责**，不承担对话叙事。

### 3.2 索引与两视图的关系

顶栏 `事件类型 82` 开索引面板。点索引项 → 先在当前视图找样例（`#cv-*` / `#ev-*`），**对话视图里找不到的样例自动切到轨迹视图**再定位并高亮 1.4s。两视图同一数据源，不会「点了找不到」。

## 四、对话视图（真实时间顺序）

结构：`日期分隔 → 用户输入 → 过程组（收起）→ 回复 → 下一轮`。没有轮框、没有轮编号、没有轮标题条——轮与轮之间靠留白分段。

### 4.1 行模板

| 行 | 类名 | 形态 | 要点 |
|---|---|---|---|
| 用户消息 | `.cv-u` | **右对齐气泡**，`max-width:min(525px,82%)`、圆角 22px、内距 10/16px、`margin-top:16px`、14px | 靠对齐方向与容器区分说话人 |
| 助手回复 | `.cv-a` | **左对齐文档流**，无容器无底色，14px／行高 1.85、`padding-bottom:16px` | **永远可见**，任何折叠都藏不掉 |
| 卡间信 | `.cv-cm` | 左竖线引用块，`margin-left:8px`、`max-width:min(680px,92%)` | 见 §4.2 |
| 系统事件 | `.cv-sys` | 11.5px 灰，缩进 16px，一行 | 不进过程组 |
| harness 投递 | `.cv-hm` | 11.5px 灰，缩进 16px，一行 | 说清「谁因为什么规则叫了它、结果如何」 |
| 过程组 | `.cv-pgrp` | 组头一行（箭头＋内容摘要＋项数·耗时·调用数），默认收起 | 见 §4.3 |
| 工具行 | `.cv-tool` | `工具名 ｜ 参数原文 ｜ ✓/✗/○`，点击展开 IN/OUT | 参数用调用实参，不做语义概括 |
| 审批回执行 | `.decision` | `✔ 你已经批准 …` | 确认动作落定后留在流里 |
| 日期分隔 | `.date-sep` | 居中细线＋日期 | — |

**用户气泡的圆角是唯一保留的形态信号**：22px 圆角＋右侧短宽度是「有人在说话」的第一眼标记（DSH `MessageItem.module.css` 原值）。抹平它，用户消息就退化成与正文无异的矩形块。

**关于 `›` / `•` 前缀（已推翻）**：那是 Codex **终端 TUI** 的写法（终端只有一列，没有排版工具）。网页产品的第一眼信号是**对齐方向与容器形态**。曾经抄过终端前缀（用户与助手都左对齐顶格、只靠字重区分），实测两行 x 都是 92——同列，普通人分不出哪句是自己说的，已改回气泡方案。

### 4.2 卡间信：按语义分五型，不只靠箭头

系统里的卡间消息有五类语义，监工看它们的**关注度完全不同**，因此不能长得一样：

| 类型 `data-mt` | 标签 | 对监工意味着 | 形态 |
|---|---|---|---|
| `directive` | 指令 | 又有活来了，这轮为什么开始动 | 左竖线 **3px 实线**、标签**反白**（黑底白字） |
| `report` | 汇报 | 下级交活了，要判断做没做成 | 左竖线 2px、标签描边 |
| `worker_done` | 完工回执 | 活干完了，要验收 | 同上 |
| `sync` | 同步 | 平级知会，扫过 | 左竖线 **1px 虚线**，正文转灰转小 |
| `notify` | 通知 | 系统告知，扫过 | 同上 |

方向另用字符标：`↓ 收到` / `↑ 发出` / `· 同层`。

每条还可带一行**记要**（`.cm-meta`）：指令带**验收判据**，汇报带**阻塞／待办**，完工回执带**交付物指针**；同步／通知不带（它们本来没要求你做什么）。

**卡间信是对话不是过程**——它在过程组之外，任何折叠都藏不到它。

### 4.3 过程组

相邻过程内容聚成一个组（Codex `ActivityGroup`）：

- **默认收起**。组头＝箭头 ＋ **内容摘要**（如「读取 openai/codex · deepseek-ai/deepseek-harness」）＋ 右侧统计「N 项 · 耗时 · 调用数」。
- 摘要取**内容类别**，不是编号，也不是语义改写（不做「CSS：视图切换」这种要读懂内容才写得出的描述）。
- 轮末统计（耗时／调用数）**并进组头**，不单独成行——避免被误读成助手又说了句话。纯回复轮没有过程组，因此不显示统计，不做「用户说完 → 一行统计 → 助手回复」这种夹心。
- 组内工具行点开可看 `IN {…}` / `OUT {…}`（单条 disclosure）。

### 4.4 折叠层级（只有两层）

1. **过程组**（默认收起，点组头展开）
2. **单条 disclosure**（工具行点开 IN/OUT）

**不做「整轮折叠」**：Codex／DSH 的 scrollback 里没有「整轮」这个视觉单位，回复本来就一直在。上一版自造的轮框、轮编号与折叠钮已删除。

### 4.5 示意数据

就是本卡 2026-11-08 这几轮真实发生的事（调研 → 双视图 → 罗马数字质疑 → 信息流重设计 → 卡间信补全），每轮回复是不同的话；事件类型**带着语境**出现，不是图鉴里的孤立标本。

## 六、输入区

### 6.1 发送 / 停止（同一键两态）

`#flowSendBtn`：空闲＝`发送 ↑`（反白）；运行中＝`停止 ■`（反白反转）。**Enter 发送、Shift+Enter 换行**；**运行中按 Enter 进排队**（不打断当前回合，不触发停止）。停止只能点按钮。

### 6.2 排队条（插话）

运行中发送进 `#queueBar`：`排队 N 条 · 当前回合结束后送达` ＋ 逐条**原文预览**（最多两行 `line-clamp:2`，右侧标字数，`×` 单删）＋ `清空`。停止后排队保留，不丢输入。

**为什么是原文预览不是摘要 chip**：Codex 的 `pending_input_preview` 与 DSH 的 `QueueDock` 都显示待发送内容原文——插话是用户自己的话，摘要有丢信息风险。

### 6.3 模型选择与上下文占用

- `#modelBadgeMount` 紧邻发送键左侧；点开 `#modelMenu`（5 项，当前项打 `✓`，右侧标注适用层级）。
- 菜单**用 JS 定位在按钮正上方**（`getBoundingClientRect`，间隔 8px）——不设固定偏移，避免「菜单离按钮远」。
- `#ctxLen` 在模型键左侧：**本对话最近一次调用的上下文占用**（`ctx 84.2k / 200k`），每次调用返回的 usage 里都有，机械可导。
- 底栏顺序：`弹性空白 → ctx → 模型 → 发送`（模型与发送成组靠右）。

**不设**「需求确定」/「更新现状」按钮；**不设**自动/手动模式开关。

### 6.4 用户确认条（输入框正上方）

`#confirmSeat` → `#confirmBar`，位置在输入框**正上方**，形态仿常见 agent 的确认卡（标题行＋正文＋动作行），**不是整页模态**。

一套形态、五种类型（`CONFIRMS` 表 + `applyConfirm()`）。切换时标题、徽标、正文、说明与按钮文案全部随之变化：

| kind | 主键 | 次键 | 场景 |
|---|---|---|---|
| `acceptance_reply` | 确认正稿 | 驳回 | **根卡无评审卡时直接落到用户** |
| `boundary_change_request` | 同意变更 | 驳回并维持原范围 | 边界扩到范围外 |
| `reconfirm_disposition` | 接受该结论 | 不成立，要求重做 | 结论被标疑 |
| `block_wait` | 继续（给指令） | 就地停止 | 受阻，不会自恢复 |
| `budget_exhausted` | 加轮次上限 | 改目标 | 轮次用尽，只有两条路 |

出口：`×`、`稍后`、`Esc` 三条可达路径。收起只收这条卡，待处置项不消失。
「查看草稿全文」开 `#draftModal`（草稿可编辑，关闭／提出修改／确认正稿三键＋✕）。

## 七、覆盖层

### 7.1 评审浮窗 `#rvWin`（随批次生灭）

**不是按钮、不是与卡详情并列的入口**，而是有在途批次才存在的浮窗：

- **出现条件**：有在途批次才存在；批次转终态（`approved` / `voided`）后**整窗消失**。演示控制在索引面板里，不进产品界面。
- **收缩态（默认 300px）**：占对话列右侧空白带，正文不动。头行 `● 评审 · 2/3 · 画布页 v3 验收 · ⤢ · ×`；下面**事件列表**（time ＋ 事件摘要）；再下面**实时行**（最近一条，占位「等待事件…」）。
- **展开态**：向左长到 `min(560px,46vw)`，正文被**真挤压**。内容＝**评审卡自己的对话页**（同一套行模板：系统条 → 卡间信 → 系统条 → 回复 → 系统条），顶部一行批次摘要。**展开后不再显示收缩态的事件列表与实时行**（不重复同一份内容）。
- **层级**：`z-index:55`，低于卡详情（`8` 之上的抽屉层）。**卡详情展开时评审浮窗整体被推走**（`right:calc(420px + 10px)`），自适应随行——不是被盖住。
- **出口**：`×` 收起、`⤢` 展开／收起、`Esc`（按层级）。

### 7.2 卡详情抽屉 `#inspector`（420px，唯一入口是右缘竖条）

覆盖式，`hidden` 默认；右缘常驻竖条 `#inspTab` 是**唯一入口**（顶栏不放第二个按钮；展开时竖条自身隐藏）。**点击面板外部即收起**（豁免：面板内、入口按钮、弹窗、评审浮窗、覆盖层入口），`Esc` 同效。

内容：

- **使命 / 修改历史**：只读。
- **目标**：带 `✎ 编辑` —— 就地变 textarea（原文回填），保存／取消。
- **现状 / 需求文档**：**折叠预览（两行截断）＋「展开全文」** —— 全文在面板内完整可读，不缩在小框里；md 最简渲染（标题／列表／代码底纹），只保结构。
- **需求文档 · 历史版本**：逐版列出（版本号＋状态＋驳回原因＋「查看」），查看只读。
- **关系**：**全量联系**逐条列出——父／先后／依赖／关联，每条带线型、说明、对方卡可点跳转；`＋` 添加。

它是常驻入口，与评审浮窗（随批次生灭）不同级、不同位、不同生命周期。

### 7.3 事件类型索引 `#idxPanel`

入口 `#idxToggle`（顶栏）。308px，贴左缘。**打开时正文与输入区统一让位**（`body.idx-on`），不压在内容上。面板含：演示控制区（五种待处置类型切换、评审浮窗出现／消失）＋ 11 组 82 项清单。点任一项滚到样例并高亮。

### 7.4 toast

`#toastBox` 保留，用于短反馈；无配色，只有文字与线。

## 八、动效依据（这是规格，不是皮肤）

页面整体是静态交互稿（`animation/transition` 全局清零），**只在「动效依据」这一段开回三类动效**，用更高优先级单独启用。删掉这段，页面回到全静态——动效只在这里成立。

| 动效 | 参数 | 表达什么 |
|---|---|---|
| 入列 | 淡入 + 上移 8px / 220ms | 新内容出现在流末尾，眼睛跟着走 |
| 过程推进 | 运行点脉冲 1.1s；工具行逐条 stagger 140ms | 一条一条地干，不是一次刷出 |
| 生成中 | 回复逐字出现 + 光标闪烁 0.9s | 区分「正在说」与「说完了」 |
| 按钮确认 | 反白闪 0.5s | 动作已被接收 |

完整回合时序：用户消息入列 → 运行条出现 → 工具行逐条落 → 状态变化行 → 回复逐字出现 → 收尾。所有时长集中在这一段，改那里就整体改节奏。
