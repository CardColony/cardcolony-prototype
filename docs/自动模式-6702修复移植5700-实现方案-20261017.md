### 0.2 为什么第 4 项只进一半

文档称"分支实例的 `BASE_DIR` ＝ worktree 根（下无 trading-workspace）"。实测：

- `src/api/file_tools.py:37`（5700）是 `BASE_DIR = Path(r"D:\AI_station")` —— **硬编码**
- 是 `scripts/run_instance_6702.py:72` 把 `file_tools.BASE_DIR` 覆盖成 worktree 的
- 而生产机上 `D:\AI_station\trading-workspace` **确实存在**

⇒ 在生产上，缺省路径本来就能正常工作，"相对 `D:\AI_station` 或绝对"的描述也是真话。那条"路径不存在"的报错只在沙箱里出现。

若照搬成 `str(BASE_DIR)`，生产效果是**把缺省列目录从 `trading-workspace` 扩到整个 `D:\AI_station`** —— 这是视野放宽，不是修 bug。

故取**行为保持版**：

```python
def _default_root() -> str:
    """文件工具缺省根：优先 trading-workspace（生产既有口径），否则用 BASE_DIR。

    为什么要有这个函数（而非直接写死某一个）：``BASE_DIR`` 在沙箱/测试里会被
    覆盖（``run_instance_6702.py:72``、conftest 的 monkeypatch）。写死
    ``BASE_DIR / "trading-workspace"`` 在覆盖后指向不存在的目录（实测沙箱
    连续 4 次报「路径不存在」）；写死 ``BASE_DIR`` 又把生产缺省从
    trading-workspace 放宽到整个 D:\AI_station。两者都各错一半。
    本函数**在调用时求值**（不是 import 时），故对覆盖后的 BASE_DIR 同样成立。
    """
    sub = BASE_DIR / "trading-workspace"
    return str(sub) if sub.is_dir() else str(BASE_DIR)
```

调用点两处：`list_files` 与 `search_files` 的 `path or ...`。

def _is_windows_lock_race(exc: OSError, path: Path) -> bool:
    if os.name != "nt" or not isinstance(exc, PermissionError):
        return False
    winerror = getattr(exc, "winerror", None)
    if winerror in (5, 32):
        return True              # os.replace 撞独占句柄（双路径）
    if winerror is not None:
        return False             # 其它 winerror ⇒ 行为不变
    try:

    except (OSError, AttributeError):
        return False
    return not bool(attrs & _FILE_ATTRIBUTE_READONLY)   # 带只读位＝真无权限，不重试

### P7 · 提示词纠错 ＋ 空转兜底不误伤（**本方新增**）

**改哪里**

| 文件 | 落点 | 动作 |
|---|---|---|
| `src/api/prompts.py` | `_SEC_AUTO`（L157） | **删掉**「只把话说完而不调用 update_goal，系统会当成「还没做完」，自动再起一轮」这句无条件断言，替换为两条准确表述（见下） |
| 同上 | `AUTO_BASE_PROMPT_VERSION`（L59） | `auto-t6` → **`auto-t7`** |
| `src/api/auto_driver.py` | `_idle_stop`（L71） | `tool_n == 0` 分支加早退：`if has_active_child(work_id, card_id): return False`（**不计入、不清零**——让位等待不是空转） |
| `tests/test_auto_mode.py` | 新增钉子 | ①`_SEC_AUTO` 不再含那句无条件断言；②含"直接结束回合"表述；③`_idle_stop` 在有活跃子卡时不计入；④版本断言 → `auto-t7` |

**替换文案（照此写）**

```
- **只要没有在跑的子卡**，只把话说完而不调用 update_goal，系统会当成「还没做完」自动再起一轮。
- **你有正在跑的子卡时，直接结束回合即可**：系统会把你停在原地，等这些子卡全部完工后自动叫醒你
  ——不需要、也不应该用 pause 去表达「我在等子卡」。
```

**为什么必须改**

`will_continue` 的判据是 `auto_mode=1 ＋ goal_state=="active" ＋ 有 goal ＋ 无未终止子卡`。父卡有在跑的子卡时，第四项为假 ⇒ 不起轮 ⇒ **自然停住**；子卡完工后 `after_turn(child)` 递归回父卡 ⇒ 第四项转真 ⇒ 自动恢复。

也就是说：**父卡本来就不需要 pause 等子卡**。是那句无条件断言让模型以为"不说话就会被再起一轮"，才把 pause 当成唯一的"我要等"表达。6702 为此加了两列 DB、一个三值判据、一个活锁计数器、三条提示词规则——**在给自造的坑持续供货**。

**硬判据**

1. `_SEC_AUTO` 不再含"不调用 update_goal ⇒ 自动再起一轮"的无条件断言。
2. `_idle_stop` 在 `has_active_child` 为真时**不增加计数**（用例：连续 5 次 `after_turn(parent, tool_n=0)` 且有活跃子卡 ⇒ 父卡仍 active）。
3. `BASE_PROMPT` sha256 不变（只动 auto 版）。
4. 版本断言 → `auto-t7`；全量失败集差集为空。

**回滚**：`git revert` 单批（P4–P6 不依赖它）。
