# 原型前端性能优化施工方案

在 `D:\AI_station\推演agent` 内实施。目标是让大 work 的开卡、翻历史和画布交互保持跟手，并降低多卡运行时页面的后台请求负担。以 `work_073` 的真实规模为主基线，按下面三批交付。第一批从 `card_007` 开工，每批提交独立的前后读数和行为回归结果。

## 工作范围

- 运行入口是 `templates/card.html` 和 `templates/work.html`，主要代码在 `static/` 与 `static/esm/`。当前任务覆盖原型运行页面。
- 先读 [项目规则](../AGENTS.md)，保留工作区中已有修改。使用隔离副本和独立端口做写入、拖拽、断线、并发事件等测试。涉及 5700 的启停按项目规则单独请示。界面类改动按项目规则先在本地给用户确认，再同步。
- 卡面、对话、工具回执、历史以及线的权威来源沿用当前实现。性能优化可以推迟取正文、缩小当前挂载范围和合并界面更新。原文、会话归属、历史顺序、撤销、权限和运行状态的含义都要保持。
- 既有方案已经处理 web/runner 转发、时序读盘和模型请求装配。浏览器验收继续沿用它的服务端分段数据。本任务只改与首屏载荷、请求扇出和页面更新直接相关的读口。新增或调整读口时，先核对 web 本地白名单、属主 runner、会话隔离和旧入口兼容性。[既有性能方案](原型性能系统优化-方案-20261119.md) · [进程路由](../src/infra/procs.py)

## 第一批 开卡和切卡

1. **统一模块实例和请求生命周期。** 统一 `api.js` 的引用地址，跑过同模块版本契约。查清重复的规则读取和进度读取分别由谁触发。对 work、card、session、参数和数据语义均相同的在途 GET 合并一次。切卡取消失效消费者，保留其他消费者需要的共享请求。晚回包只允许落入发起时的会话，禁止覆盖当前卡及其 Composer。
2. **缩短首屏取数链路。** 沿用 `workspace.open()` 同步挂载画板的行为。冷开时，身份明确后并发读取首屏所需的卡片元数据和最近对话，结果仍经过当前切卡序号、目标标识与失败回滚检查。先核对现有窄读口，按需补上卡片元数据和当前卡生效模型的窄投影。完整卡面、历史详情和模型候选表随对应区域需求读取。确实可见且支持操作的评审、规则、对齐入口仍按现有语义显示，可各自完成加载。完整卡面和旧读口保留原返回契约。
3. **消除首屏回底带来的同步布局。** 核对 `chat-view.toBottom()`、`workspace.scrollChatBottom()` 和 `stream.activate()` 分别在哪些场景测量和写滚动位置。由对话视图统一处理首屏定位、跟随、主动回底和前插保位。合并同批 DOM 更新，单独安排必要的布局读写，每批只做一次滚动校正。热切回继续复用会话数据和视图状态。保留当前无按时间淘汰的常驻语义。

**交付判据** 大卡冷开首批可读内容 P95 较同条件基线缩短至少 30%。复录 Chrome 性能轨迹，指出布局长任务的变化。当前卡徽标无需下载全项目模型覆盖表。热切回已加载卡不重拉完整时序、保持滚动位置。A→B→A 快切、主会话与附加会话互切、取卡失败回滚均通过。[卡片读口与时序路由](../src/api/routes.py#L1302) · [会话视图](../static/esm/flow/chat-view.js)

## 第二批 长历史和实时更新

1. **让前插成本随新增页增长。** 保留现有 `before` 游标、首尾水位和既有排序、撤销口径。前插时只处理新增页及跨页存在关联的节点，避免将已取历史每次完整重放。对话视图用有界的可视窗口，向上和向下均可恢复关联内容，前插后沿用原可见项的稳定键和像素偏移。首屏先渲染最新可读对话，折叠工具结果和推理优先显示类型、状态与预览，展开后可读完整内容。先量 DOM 与装配成本，再决定是否增加可选的时序窄投影。现有原文接口与行为保持。
2. **按数据语义合并实时状态。** 首次进入仍取权威状态快照。把同一 work、同一版本的运行状态更新交给导航与画布共同消费。对不同口径的全局运行总览、项目运行状态、活动历史分别保留边界。确认现有 SSE 实际覆盖的字段后，才把相应的定时查询降为断线、重连或低频校准。重连按水位或已有快照规则补齐，失败保留上次已知状态并正确反映数据新鲜度。合并的是界面补丁和同义读请求，工具事件、状态迁移及原始记录都完整保留。
3. **复核跨 runner 状态的尾延迟。** 分别记录前端排队、web 转发、各 runner 回包和合并时间。把后台请求减少的收益与既有转发优化分开取证。在同一隔离副本重放事件负载，确认 SSE 健康时的请求数、断线期间的退避和恢复结果。[对话分页与流恢复](../static/stream.js) · [画布实时状态](../static/canvas.js#L6639) · [runner 汇总](../src/infra/procs.py#L468)

**交付判据** 连续向上翻 20 页、再回到最新位置，挂载行数有界，锚点保持，旧页还可再次打开。跨页工具调用与结果正确配对。实时回复、撤销及断流重连后，既无重复的显示记录，也无遗漏的最终状态。固定负载下报告每分钟状态请求数、响应字节和延迟。分别验收正常推送、断线和部分 runner 无响应。

## 第三批 大画布

1. **优先收敛交互热路径。** 将滚轮、平移、拖动输入合并到每帧一次画布变换。从 resize 和实际容器变化维护视口几何。保持鼠标锚点、触控板缩放、普通滚轮滚动、框选和拖拽结束后的坐标提交语义。记录交互帧内强制布局、节点变换和绘制耗时。
2. **按视口控制挂载范围。** 在现有逻辑投影上增加视口和预加载余量。全图节点、树、线、坐标及搜索索引继续用于导航，DOM 只挂载需要绘制的卡。搜索和点击导航先定位再挂载目标。需要保留焦点、选中或拖动中的卡按现有操作语义处理。尺寸按已知测量与可靠估算参与布局，避免在相机移动时全表测量。
3. **连线从全量重画改为局部更新。** 按发生变化的端点和视口更新相关边，保留穿过视口的有效连线。普通状态变化更新受影响卡。结构变更继续用现有子树布局入口，整体重排只在投影确实失效时发生。若复测显示整图响应仍压住默认首屏，再拆首屏分支与轻量全图索引。旧画布读口和全图定位保持兼容。[子树渲染](../static/canvas.js#L1594) · [连线渲染](../static/canvas.js#L3850) · [相机交互](../static/canvas.js#L4522)

**交付判据** 同机、同视口、同一全展开图，缩放和拖动的帧间隔 P95 以 25 ms 以内为首轮目标。报告峰值帧间隔和节点挂载数随全图变大的变化。实测全图适配、导航定位屏外卡、框选、连线命中、键盘焦点和重新打开后的坐标恢复。最后单独评估静态模块内容版本与缓存，维持开发刷新后可靠拿到新版本的行为。[静态资源缓存](../src/api/asset_cache.py)
