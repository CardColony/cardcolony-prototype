## 一、背景（为什么做）

卡片现在是 `.md` 一坨：机器记账（哈希/权限/工具卡字段）与内容（三块正文）同层；通用文件工具 `read_file`/`search_files` 能把整份文件读进上下文（含 `## 修改历史` 的 `[外部修改]`/`[权限刷新]` 噪音）。**文件本身没有"只取一块"的能力**——这与本系统"上下文隔离、减少污染源"的根本效果直接冲突。

改为：卡片与影子进 SQLite，**区域各占独立列**，取什么查什么；库是唯一真相，不再留 md。

3. **核心目标**＝上下文隔离、减少污染源（系统读卡走库，读到的只有该读的）。

## 三、实现决策（施工方定，写明理由；**可推翻**）

| # | 决策 | 理由 |
|---|---|---|
| 1 | 库形态＝**每 work 一个库** `works/{work_id}/cards.db` | work 已是隔离单位（快照/路径/测试沙箱都按它）；跨 work 查询只有左栏导航一处 |
| 2 | 会话 `sessions/*.md` **不进库** | 会话是对话历史本身，进上下文是它该在的地方，不算污染 |
| 3 | `read_card()["raw"]` **退役** | `raw` 是"md 整篇文本"，与"区域独立、不留 md"相悖；它只服务于"整篇覆盖写"与"外部修改检测"，两者都退役 |
| 4 | **编号序列进库**（`meta` 表） | 库要自包含（备份一个文件即完整）；发号与建卡同事务，避免并发重号 |
| 5 | `canvas.json` / `layout.json` **保持文件** | 属画布线、不在范围；仅把 `canvas.json` 的**数据源**改成库 |
| 6 | 列名 `rulings`（不叫 `ruling_block`） | 列名＝API 键名，少一层翻译 |
| 7 | `read_card` 返回契约**保留**：`{meta, body:{mission,status_block,rulings,history}}`（`history` 为**行列表**） | 下游（`routes._apply_block_set` 等）基本不用改 |
| 8 | `NEW_CARD_SKELETON` **保留** | 它是"新卡默认三块内容"来源（含 `card_draft._is_placeholder` 依赖的占位符），只是拆进三列、不再渲染 md |
| 9 | 快照改 `VACUUM INTO`，**第一步实测单次耗时** | WAL 下不能直接复制 .db；耗时不可接受再改攒批 |

### 第一步 · 功能（库化代码，不动真实数据）

**1a 地基：`src/storage/card_db.py`**
- 连接：每 work 一个 `sqlite3.Connection`，`check_same_thread=False`，`journal_mode=WAL`；**一把 `asyncio.Lock` 串行化写**；同步调用走 `asyncio.to_thread`。
- DDL：表 `cards` / `card_history` / `shadows` / `meta`（列定义见方案 §1.2）。
- 路径：`works/{work_id}/cards.db`，**调用时**从 `card_store.WORKS_DIR` 派生。
- `rev`：`meta` 表单调递增计数，**每次写 +1**。
- **自检（防误重启致"静默空数据"）**：某 work 目录有 `cards/*.md` 但无 `cards.db` → **明确报错**（"该 work 尚未迁移"），不静默返回空。

**硬判据**：建库建表成功；并发写不报 `database is locked`；`card_db` 内无模块级路径常量（grep 可验）；"有 md 无库"时明确报错可复现。
