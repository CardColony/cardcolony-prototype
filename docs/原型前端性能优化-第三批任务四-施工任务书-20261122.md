## 正常行为与实现约束

| 对象 | 施工时要保住的行为 |
| --- | --- |
| 图数据与呈现 | 全图索引保留卡、父子关系、连线、布局坐标及搜索信息。分别维护逻辑展开集合与实际挂载集合。卡移出视口只释放呈现所需的 DOM 和监听，索引与数据仍能用于定位和后续更新。 |
| 相机、滚轮与输入 | Ctrl/⌘＋滚轮及触控板捏合按指针锚点缩放。普通滚轮按原方向滚动，Shift＋滚轮横移。工具栏缩放、整幅适配、空白拖动等沿用原入口。浮层内容还可滚动时，保留原有滚轮归属。 |
| 拖卡与提交 | 普通拖卡保留横向锁定及吸附反馈。松手落到合法目标时通过现有接口更新 `parent`，子树按新归属渲染。落在空白、自身、后代或服务端拒绝的目标时，回到服务端确认的布局。空白和前端可判的非法目标无需写请求。多选换父逐卡核对服务端实际结果，部分成功时页面以重拉后的权威树为准。 |
| 视图存档 | 相机位置、缩放、展开分组与就地展开卡继续按 work 写入 `projView`。临时拖动位移留在手势状态。用于整理布局的坐标写入仍走原位置接口，按原有口径恢复和回滚。 |
| 实时状态 | 屏外卡的状态变化先进入数据层，进入视口后显示最新值。部分分片回包按属主替换覆盖范围内的状态，缺失分片保留待校准。重连按既有入口补齐，迟到的旧快照不能把已完成的卡重新点亮。 |

连续输入按帧合并时要保住输入顺序及累计位移。只要鼠标在移动，缩放锚点和拖拽落点就要跟随实际手势。容器尺寸、卡高和相机坐标切换后，重新校验可见范围与命中几何。绘制层优先复用已挂载且内容未变的卡，视口边缘留余量。需要保活的焦点、内联展开和拖拽卡有明确的保留与释放条件。持久化前用最新一帧或最终指针位置确认结果。[相机变换](../static/canvas.js#L198) · [拖拽命中](../static/canvas.js#L2319)

更新连线时使用实际路径和边身份判断。区分端点位置改变、视口变换以及增加或删除边。变更普通状态只更新对应卡。展开、折叠和结构变更走原有子树布局出口，刷新后的节点位置、边类型和命中由实测对账。屏外节点的布局可复用已测尺寸及明确的估算，进入视口后修正尺寸时保持正在阅读的位置。[画布渲染](../static/canvas.js#L1427) · [子树布局](../static/canvas.js#L1595) · [连线渲染](../static/canvas.js#L3851)

## 验收用例

验收场景放在同一次交付里。每条记录输入、实际终态及断言结果。页面没有完成对应操作的样本记为失败。已有失败以冻结的改前版本复跑确认，再区分本次引入的变化。

| 场景 | 操作和通过条件 |
| --- | --- |
| 指针锚点与输入归属 | 在画布中部及边缘各做一组连续缩放，比较手势前后同一世界点对应的屏幕位置，偏移符合既有像素取整。真实输入分别触发普通滚轮、Shift＋滚轮、Ctrl/⌘＋滚轮、中键或空格平移。逐项核对缩放值及两轴平移值，检查浮层内部仍可滚动。 |
| 拖卡换父与回退 | 从同一初态分别拖单卡、多选卡到合法目标，核对卡 ID、请求内容、新 `parent` 与子树结构。同样拖到空白、自身和后代，确认原归属及布局回弹。注入一次服务端拒绝，核对提示和重拉后的结构。多选含部分成功时逐卡核对最终归属。 |
| 框选、命中与键盘 | Shift＋空白框选后断言选中 ID 集合。标题、子卡徽标、就地展开、跳转入口各点一次，检查触发的动作和归属卡。用键盘上下左右导航，验证子卡、父卡与焦点行。拖拽结束、取消及失焦后检查高亮和监听状态已释放。 |
| 层级展开与屏外定位 | 分别从搜索、左侧导航和活动入口定位屏外卡，其中至少一张处于折叠祖先下。核对目标 ID、祖先按原规则展开、目标已挂载且落在视口。验证离开视口后再回到原处时，选中与就地展开状态按原行为接续。 |
| 挂载规模 | 跑默认展开、全展开、放大定位、全图适配及更大的固定合成图。分别记录全图卡数、逻辑展开数、视口命中数、在挂卡和 SVG 数，以及保活例外。将合成图新增节点放在视口之外，在相同可见密度下比较峰值和每帧更新量。全图适配按实际可见规模报告。 |
| 穿窗连线 | 构造两端都在视口外、路径穿过视口的边。平移穿越边界、拖动端点并调整缩放。断言边身份、视觉路径和命中结果。同期验证完全离屏的边释放呈现，重新进入视口能按最新端点重建。 |
| 恢复与隔离 | 保存相机及展开状态后普通刷新，对照 `projView` 及首帧临近稳定后的结果。校对服务端父子树与有效坐标，切换到另一个 work 的同号卡并返回，核对各自的视图和状态归属。 |
| 实时状态与重连 | 同时观察一张可见卡和一张离屏卡。离屏时发生变化，再定位回来，应显示最新状态。复用任务三的双分片边界，A 所在片已确认完成就清 A，B 所在片失联则保留 B。状态试验按实际 SSE `open` 划定补读窗口，核对重连后导航与画布都收敛，并验证迟到旧回包无效。 |

## 性能取证与判定

- **固定图和环境。** 使用同一份隔离 `work_073` 快照，固定 Chrome 版本、视口、DPR、相机位置、缩放、展开集合和输入轨迹。默认展开、全展开和合成大图分别登记图指纹、卡数和边数。涉及写入的轮次恢复到同一父子树、坐标及视图初态，或从同一副本复位。按空闲和相同的多卡事件回放负载分别出数。
- **先证明手势发生。** Ctrl＋滚轮用于缩放，空白或中键拖用于平移，真实鼠标或 CDP Input 用于拖卡。每种手势固定轨迹、节奏和作用对象。现有 `canvas_perf.mjs` 只用于冒烟和规模核对，正式探针每轮要核对起止变换、落点或树变化。预定缩放却只触发滚动，或预定合法换父却落到空白时，按失败保留原因。
- **固定计时边界和样本。** 从首个有效输入到最后一帧视觉更新采集逐帧间隔，松手到服务端确认及最终布局另计。缩放、平移、拖卡各报 P50、P95、最慢帧与超过 50 ms 的长任务。核心场景至少 20 对，交替改前、改后顺序。原始记录保留每轮顺序、输入、逐帧样本、终态、长任务、挂载卡及边的峰值。起跑前定好无效样本规则，失败、超时和跳过均留痕。成对轨迹单列强制布局、脚本和绘制，热路径探针避免逐节点同步读布局。
- **按原目标收口。** 同一张全展开图上的缩放、平移、拖卡帧间隔 **P95 ≤25 ms** 为首轮目标。逐项给实际达成情况，重负载和合成大图另列趋势与挂载规模。功能用例有明确错误则修复后复跑。性能未到目标时保留真实读数，指出最长的可归因环节和剩余距离。
