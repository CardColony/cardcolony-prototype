## 一、结论先行（一句话）

「动态调阁」这条生命线在 5713 上**逐环机械成立**：组阁→排他拒撞域→真模型落判词并报警→改职责书升版本（旧版留史）→

过程中挖出并修掉了**三个真实机制缺陷**（正文块变更不入队、无会话块的卡同步不到、停职期间事实丢失），

## 二、三次实跑的现象（按时间，不加解释）

### 跑 1（v1 驱动器，work_008，`evidence_dynamic_cabinet_run1_prerun.json`）

- 组阁成功、撞域被拒（400，点名占域者）、巡检起回合、**真模型判 `silent`、无警报**；改版本 2、停/复/撤、顶空域全部按预期。
- 判据 14/16 true，唯一实质 false 是 `A_alarm_raised_on_conflict`；`E_ledgers_retained` 也 false（判据写死数字，跑 1 只产生了 1 行判词）。
- 追因（逐字读材料）：我给的两张卡示例是 `2026-10-20T08:00:00Z` 与 `2026-10-20 16:00:00`（+08:00）——
  **同一瞬间的两种写法**，模型算出"可换算、可同时为真"，判 silent 是**正确判断**。
  ⇒ 现象记一条：**判据全绿不等于实验成立；材料不互斥时，实验测到的是模型的正确沉默，不是机制缺陷。**

### 跑 2（v2 驱动器，work_010，`evidence_dynamic_cabinet_run2_prefix.json`）

- 材料换成**不可约互斥**：同数字不同基准（08:00Z vs 08:00 本地，差 8 小时）＋契约级相反规定（对外字段一律带时区 vs 一律不带时区）。
- 真模型立刻判 `speak` 并 `raise_alarm(warn)`，理由原文：「同一字面时刻差 8 小时，属『同一数字不同基准/带时区 vs 不带时区』的互斥事实」。
- 17/19 true，剩两项 false：
  - `C_new_fact_queued_while_suspended`：停职期间改卡片现状，`role_sync` **一行都没新增**（直读沙箱库计数 2→2）；
  - `D_resume_new_verdict`：复职后没有新判词——因为停职期间那一段根本没进队，角色看得见的还是旧材料。

### 定位（读源码原文，不是猜）

1. `card_store.update_card`（唯一写门）改 `status_block`/`rulings` 后，**不通知任何角色**；
   角色同步只挂在「工作卡回合收口」`role_room.after_turn`（`routes.py` 回合收口处）。
   ⇒ 直接 PATCH 现状/定论，角色永远收不到。
2. `after_turn` 开头 `last = await _last_seq(...)`、`if last < 0: return`——
   **没有会话块的卡（只有现状/定论的卡）一律不同步**；而这类卡根本没有回合。
3. `manual_check` 里 `if last < 0: last = 0` 的兜底，与 `from_seq = max(baseline, consumed)+1 ≥ 1` 相矛盾，
   `0 >= 1` 恒假 ⇒ **那段兜底从来没生效过**。
4. `roles_watching` 只返回 `duty=active` 的角色 ⇒ **停职期间的事实直接丢失**，复职也补不回来。

## 四、真模型的行为观察（是现象，不是判据）

1. **判词质量**：两次判 speak 的理由都精确引用了材料里的冲突点（"同一字面时刻差 8 小时""带时区 vs 不带时区"），
   并自己选了升级线（`warn` 警报给人、`gap_or_risk` 通知给关注卡），没有"为了说话而说话"。
2. **时延**：D 段真模型回合从起回合到落判词约 **4 分钟**（事件流 900+ 帧，推理很长）。
   v2 首跑把超时设 180s 时它就是 false，改 300s 才通过 ⇒ **「巡检回合可能跑几分钟」必须写进运维预期**，
   不能拿短超时把它判成机制失败。
3. **一次回合只落一条判词**：D 段模型在推理里反复权衡"要不要补一条警报/是否超发言上限"，
   最终只落 1 条判词 + 复用已有 open 警报（未新建第二条）——与 `max_messages_per_wake: 2` 的契约一致。

## 五、排他键纪律（机制事实 + 本次实测）

1. **一域一角色**：同 `exclusive_key` 同时刻只允许一个非 archived 角色（实测两次 400，错误原文点名占域者）。
2. **archived 不占域**：撤岗即释放排他键，新角色可顶（E→F 实测：同一 `interface_contract` 组阁成功）。
3. **改域＝改档而非新设**：`update_profile` 改 `jurisdiction` 走同一唯一性校验（改到别人占着的域会被拒）。
4. **空域要在案**：机制只保证"不重叠"，**不保证"不留空"**——留空是 CEO 的账，每次调阁后要扫「当前在乎的事 − 已组阁域」。

## 六、组阁纪律（从本次实测能立住的部分）

- **何时设**：出现没人认领的责任域，或同一类事故重复 ≥2 次且没有角色会为它开口。
- **何时改档而非新设**：域没变、只是范围/关注/契约要调 ⇒ 改档（版本史留痕，E 段证明旧版不会丢）。
- **何时停而非撤**：短期无材料但要保留判断连续性（撤岗虽留账，但关注全解，复职要重挂）。
- **何时撤**：域消失；或连续多轮全 silent 且写不出触发线（说明它没有判断对象）。
- **防重叠**：设之前先 `GET /works/{wid}/roles` 看现有排他键。
- **写清触发线**：机制只保证"不开口也落账"，**不保证判断得准**——组阁时把"什么算触发"写进职责书，本次两跑已验证差别（silent vs speak）。

## 七、边界与未验（如实标注）

1. **组阁/改档/停复撤的"决策"由实验场景预置**：验的是机械通道与台账，**不是根卡模型的组阁判断力**（那是另一半，另测）。
2. 组阁走 HTTP 面 `POST /works/{wid}/roles`，与根卡工具 `create_role` 同一执行体（`routes.py:1320` 原文），通道等价、只差决策者。
3. 未验：多角色同时关注同一张卡的唤醒互斥/重复；长期运行的冷却与积压；角色间不通信的反面（机制禁止）；
   跨项目共享角色（机制不做）。
4. 既有债（非本实验引入）：工具表字面量断言 32 vs 35、Windows 会话文件锁偶发 `WinError 5`。

### 3. 判据自查：本实验的 19 条判据有没有「关键词探针」同类问题

card_005 的实测教训是：拿「某关键词是否出现在自由文本里」当判据会误报（把真跑通判成没跑通）。
据此逐条自查本实验判据（`dynamic_cabinet_v2.py::_judge`）：

| 判据类别 | 判法 | 是否受探针问题影响 |

| 判词 | 判断簿新行的 `decision ∈ {speak, silent}` | 否（结构化字段，不是读文书） |
| 警报 | 警报簿行数/open 数/severity | 否（行计数） |
| 同步 | 直读沙箱 `cards.db` 的 `role_sync` 行数与 `signals` | 否（库计数） |
| 职责书 | `charter.version == 2`；`history` 中含 v1 **原文前缀** | 否（我提交的原文做恒等比对，不是判模型措辞） |
| 台账保留 | 判词/警报/版本史行数 ≥ 本跑累计数 | 否（行计数） |

⇒ 本实验**没有**「在模型自由文本里找关键词」的判据；唯一涉及文本的 `B_history_keeps_v1` 是与
**我自己写入的职责书原文**做恒等比对，性质是内容存档校验，不是关键词探针。

### 4. 顺手挖到并修掉的一处采集缺陷（值得全树记一笔）

- 现象：第一次补跑（work_028）拿到 19/19，但 `model_observed` 只有 **1** 条，而其实有两段模型回合。
- 追因：**判词在回合中途就落账**（模型先 `record_verdict`，再走收尾），而 **prompt 日志是回合结束时才写**。
  证据在「判词出现」的那一刻采集，就只抓得到 A 段那条日志；D 段那条晚约 60 秒才落盘。
- 修法：D 段等判词之后，再等 pending 排空 + 15s 写入窗口，然后才收证据。
- 一般化教训：**「判词出现了」≠「回合结束了」**。凡是要拿「本轮结束产物」做证据的，都不能以判词落账为采集触发点。
