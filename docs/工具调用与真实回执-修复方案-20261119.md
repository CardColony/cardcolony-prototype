## 通用调用链

在网关进入循环的交界保留每次实际模型尝试的端点、调用协议、停止原因和可核对的调用标识。原生调用、端点声明的文本调用、正文疑似调用、原生协议错误各有来源。经过归一化的调用统一走现有工具注册表、参数校验和权限校验，再进入执行器。正文、推理、代码示例和工具返回的内容各自保留来源。

| 观察到的现象 | 处理方式 |
| --- | --- |
| 收到合法原生调用 | 走正常派发，按真实结果回灌。 |
| 文本端点按宿主声明的协议提交有效调用 | 由该端点适配器产出带来源的调用，走同一派发。只识别声明的调用位置和格式。 |
| 原生端点把调用写进正文，或文本端点输出未声明的格式 | 记录格式不符。验收模式反馈实际调用通道，当前动作仍待执行。旧版正文代执行单列来源和实跑次数。 |
| 端点发送调用分片，最终缺名、参数损坏、截断或引用不完整 | 记录具体协议失败，保留可核对的分片诊断。把未派发的项交给模型按当前协议重发。 |
| 没有调用，也没有已知执行要求 | 按普通对话收口。 |
| 没有调用，但当前任务明确还欠一个操作 | 记录未执行，进入有范围的纠正或返回未完成。 |

处理文本协议时以本次实际端点元数据为准，覆盖模型回退。带引用、代码围栏或嵌入在数据里的调用样式保持为数据。现有的疑似标记识别可以留下诊断。新格式即使无法识别，只要已知动作没有有效调用，循环也会按未执行处理。工具执行器产生的回执才确认执行。兼容路径若已实际执行，应如实报告来源、效果和回执。验收模式的原生通道以标准协议为准，并覆盖当前能通过正文触发的旧入口。纯文本 CLI 保留宿主声明的工作协议。

记录最小关联字段即可，包含工作、会话、回合、调用、工具、目标或资源及实际结果。区分收到请求、实际派发、执行结果和最终效果。对同批有效项和坏项分别处理，失败反馈只请求重发未派发的项。已产生副作用或结果无法核实时先对账，再处理未完成部分。纠正只对当前失败动作启动，正常多工具循环按现有规则推进。同一失败由循环或 Harness 其中一处负责唤回。

## 当前请求怎样给模型正确线索

当前工具循环沿用原生调用与结果配对及体积预算。跨用户轮仅在同一事项被追问或继续办理时，从现有事实投影短状态。历史存根用执行时的结构化状态生成，旧记录明确失败则显示失败，缺乏可信依据则显示未知。模型自己写的回执只作为正文。

利用当前轮装配通道，在最新请求附近给出简短提示。内容随实际端点协议和本次可用工具生成，告诉模型在需要访问外部事实或改变状态时怎样真调，以及哪些结果还未确认。已绑定动作时，带上用户选定的目标、任务范围或材料引用。回执生成后更新当前事实。普通解释、拟稿和讨论继续由模型自主决定是否用工具。提示不承担授予权限或证明已执行的职责。

## 循环怎样判断工作完成

可信的任务步骤、专用操作和明确的结构化参数可以建立可验证的执行要求。存在这种要求时，用与当前动作、资源和请求匹配的回执核对完成条件。工具已派发、工具返回成功、用户要的结果已发生分别检查。一次成功的无关读取无法证明文件已经写入，旧回执也无法说明本次操作完成。

- **查证和搜索。** 回执要来自当前要查的资源和范围。执行成功与有匹配结果分开表达，答复引用实际返回的事实。
- **写入。** 完成状态应对应真实目标上的写入事实；写前拒绝、部分成功和结果待核实分别呈现。
- **卡间指令。** `direct` 先写入接收会话，再请求运行态投递。`delivered=true` 表示起轮或插话已受理，收件方读到、开始执行和完成任务各有自己的证据。

对已绑定动作的回合，流式界面、最终回复和刷新后的历史用同一条系统回执表达进度和结果。模型自由正文和执行事实可明确区分。自由文本尚未绑定动作时，让系统生成的完成状态始终有回执。系统无法仅凭一段自然语言可靠判定所有口头完成声明是否真实。

## 离线验收与超长会话观察

离线验收用历史故障中已经发生的模型输出和确定性用例，经过原入口复验。检查系统能否识别未调用、处置异形调用、认出真实回执，以及正确显示最终结果。同时检查当前轮提示是否随实际协议进入网关请求。通过这些用例可以验收系统行为。

弱模型的漂移只在真实超长会话中出现，按实际使用自然发生的事件观察。若再次出现，沿原回合对齐实际模型及端点、输入体积、调用来源、是否派发、真实回执和用户可见结果。用这些事实判定单次事件发生在哪一层。缺少自然案例时，首调改善记为待观察。
