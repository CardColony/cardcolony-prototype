# 卡片信息结构改造方案（v5.1 施工版 · 统合修订1）

> 定稿依据：card_027 第11-12轮用户裁定（D01-D07）。本方案为该结构的机械落地施工清单。
> 统合修订1（2026-10-09 第13轮）：并入参考交叉两条真增量——现状块锚点自指规则（D09）、衔接索引按用户事实6定案（D08）。
> 边界：只做卡片信息构造。权限体系（管辖/访问控制）、读侧注入、类型退役（card_009 域）不在本方案内。

---

## 一、目标态规格

### 1. 主卡正文三块（＋机械尾）

```
# {title}
## 使命
（本卡作用/目标、授权来源；≤5行；立项定稿，改动需用户确认）
## 现状
（当前状况快照：做到哪、什么状态、卡在哪；只写已核实；事实条目带锚点自指；覆盖写·单一最新；块尾至多一行衔接索引）
## 定论
（对本卡相关事项的**决定**；只追加，仅经收口仪式写入）
D01【裁定】……（日期·依据）
D02【决定】……（日期·依据）
D03【收敛】……（日期·死过什么）
→ 被D05取代（因……）  ← 失效条目就地一行标记，不保留原文，不设已废区
（修改历史）            ← 机械尾，机制不动
```

**条目语法**：`D{nn}【来源】内容（日期·依据）`。来源三类：【裁定】用户裁决·带轮次／【决定】本卡取舍·带依据／【收敛】推演收敛·带死过什么。序号终身不改，供失效标记引用。

**写入规则**：
| 块 | 规则 | 机械约束（S3写入闸） |
|---|---|---|
| 使命 | 立项定稿 | 修改→拒绝（响亮报错，提示需用户确认） |
| 现状 | 覆盖写·单一最新；只写已核实；事实条目带锚点自指（经X报告/Y实测/Z确认） | 自由覆盖（锚点不做机械强制，理由见S3） |
| 定论 | 只追加 | 条目被删/被改写→拒绝；追加与就地失效标记（→被N取代）放行 |

**衔接索引（定案·D08）**：现状块尾至多一行、至多三格（卡id · 文档路径 · file:line）。依据用户事实6「可直接通过卡片找到对应的文档和代码」——入口指针是导航，不是资料明细；资料唯一家仍是影子·产物清单。

**现状与影子的分工（防流水账侵蚀）**：同一事件两种视图——影子·进度记事件（"10-09 跑了回归，全绿"），主卡·现状记态（"回归全绿（锚：reports/x.md）"）。现状永远是覆盖写快照，不是时间线。

### 2. 影子卡三节（机制零改动）

进度＝时间线｜产物清单＝文档/代码指针的**唯一**家｜迭代历史＝改动指针。update_shadow 签名级写、覆盖写、三节边界、三条禁止——全部不动（SHADOW_CARD_RULINGS.md 既有裁定维持）。

### 3. 信息归属矩阵

| 信息 | 唯一的家 |
|---|---|
| 作用/目标 | 主卡·使命 |
| 当前状态 | 主卡·现状（带锚点自指） |
| 决定 | 主卡·定论 |
| 事件/过程/迭代 | 影子·进度、迭代历史 |
| 文档/代码指针 | 影子·产物清单（主卡现状块尾一行衔接索引为导航入口） |
| 观点/推理/未核实 | 对话流（不落卡） |

### 4. 权威语义

事实与决定分离：现状块记「是什么」（事实权威，只写已核实＋锚点自指），定论块记「定了什么」（决定权威，仅经收口仪式）。模型在对话里说"定了""做完了"不算数——收口仪式＝用户确认或验证通过。

## 三、分期施工（每步可独立上/退）

### S1 · 骨架与说明（零逻辑改动，立即生效于新卡）

1. `card_store.py:320` create_card：charter 参数默认值改为三块骨架模板。card-proposal 建卡接口的 content 不含区头时自动套骨架。
2. `prompts.py:33` edit_card 说明改写：三块语法、条目语法（D{nn}【来源】＋日期·依据）、各块写入规则（使命改需用户/现状覆盖写·事实带锚点/定论只追加）、影子产物清单是资料唯一家。
3. `prompts.py:35` update_shadow 说明微调：产物清单节承担「文档/代码指针唯一家」职责的明示。

**验收**：新建卡默认带三块骨架；模型可见的工具说明与新结构一致；存量卡零影响。

### S2 · 拆分器双表（存量旧卡与新版卡并行可读）

1. `hash_utils.py:101-109` 拆分器加新映射表，与旧四区表并存：按卡正文实际区头自适应识别，两套区名混用不报错。
2. `card_store.py:476` update_card 的 updates 键扩展：新增 mission/status_block/rulings 三键，旧键 charter/conclusion/rejections 保留（写旧卡仍走旧键）。
3. `card_store.py:209/233` 四区顺序说明与构造器更新：新区名主用，旧区名兼容读。

**验收**：旧结构卡读写回归全过；新结构卡三块可拆分可更新；content_hash 机制零变化（仍算全文）。

### S3 · 写入闸（机械约束，把「模型不能随意编辑」从约定变成拒绝）

挂点：`card_tools.py:333` edit_card 分发前拦截（参照 :340-342 影子写守卫的实现模式）。

逻辑（按拆分器结果做分区 diff）：
- 新 content 的使命区 ≠ 旧使命区 → 拒绝：`使命块为立项定稿，修改需用户确认`；
- 新定论区不是旧定论区的超集（删条目/改写既有条目）→ 拒绝：`定论块只追加；失效用就地标记（→被N取代）`；
- 就地失效标记（行首→）放行；
- 现状区 diff 不校验，自由覆盖；
- 修改历史区由系统追加，diff 忽略；
- 旧结构卡（无新区头）不校验，S4 逐卡蒸馏时自然收编。

**锚点不做机械强制（D09 裁决）**：曾考虑现状块机械校验「含锚点标记才放行」，否决——机械强制会激励伪造锚点（模型为过闸编锚点），伪证比缺证更伤权威机制。锚点自指是语义纪律＋事后审计：现状块≤5行，审计成本可控；真锚点抽查可证伪，伪造锚点在审计中暴露成本远高于收益。

**S3 与权限的边界**：S3 闸执行的是**块写入规则**（使命不可改、定论只追加——信息结构语法自身的机械执行），不是访问控制（谁能在哪张卡上操作、跨卡管辖）。后者是权限体系，独立任务，不在本方案。

**验收**：改使命被拒且报错可读；删定论条目被拒；现状覆盖成功；追加定论+失效标记成功；旧卡编辑不回归。

### S4 · 死字段清理与收尾

1. `card_store.py:365` meta 初始化中 pending_sync/methodology_refs 删除（v2.1 轮已证全库零读取，删=零风险）。
2. 存量卡不批量迁移；各卡收工时按完成仪式蒸馏为新结构（渐进收编）。
3. 类型退役（card_type）接续 card_009 域，本方案不动，仅保证 create_card 默认骨架不依赖类型字段。

**验收**：全库 grep 无 pending_sync/methodology_refs 写入点；新卡 front matter 干净。

## 四、总验收判据

1. 新建卡：默认三块骨架，一次 edit_card 后结构不散。
2. 权威分离：事实改现状（带锚点自指，抽查可证伪）、决定进定论，写入闸使混淆在机械层被拒。
3. 存量兼容：旧四区卡读写零回归，不需一次性迁移。
4. 影子零改动：三节/签名写/覆盖写/守卫全部原样。
5. 资料唯一家：主卡正文无资料堆积，指针归影子·产物清单（现状块尾一行衔接索引为导航入口）。

## 五、不做项（防扩散）

- 权限体系（跨卡读影子、管辖判定、访问控制）→ 独立任务。S3 写入闸不属此列：它执行块语法，不判定主体。
- 读侧注入（清单摘要、权威标注入上下文）→ 独立任务。
- 类型退役（card_type 词表）→ card_009 域。
- content_hash 语义 → 不动（只算正文会导致存量哈希一次性全失配）。
- role/status 字段复活 → 不做（card_store.py:483 status 二态废除裁定维持；生命周期用「现状块文字＋定论收口」表达，不再造机器字段）。
