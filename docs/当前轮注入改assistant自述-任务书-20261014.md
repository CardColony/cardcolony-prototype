## 2. 精确规格

### 2.1 投影（`src/api/current_turn.py`）

- `INJECTION_ROLE`：`"user"` → **`"assistant"`**。
- `PREAMBLE_MARK`：`"〔上下文注入·固定总领〕"` → **`"〔工作规范〕"`**。
- `INJECTION_MARK`：`"〔上下文注入·当前步骤〕"` → **`"〔当前流程〕"`**。
- `project_message(ev_type, data)` 返回结构不变：`{"role": INJECTION_ROLE, "content": f"{mark}\n{body}"}`。

### 2.2 渲染（`src/thinkchain/step_region.py`、`src/toolcard/step_prompt.py`）

**preamble（工作规范）** —— 自述改写，规则条目与模板一一对应：

```text
我按这套规范推进当前任务：
1. 只做当前步的事，不跨步、不加戏。
2. 需要取证就调工具，不凭想象。
3. 完成判据不满足，就说不满足、不谎报完成。
4. 做完立刻调 step_complete，提交本步成果与判据满足情况。
```

**injection（当前流程 · 思维链）**：

```text
我正在执行「{plan_name}」的第 {index}/{total} 步。
我已经完成：
- 步 {step_id}：{prompt} → 成果：{result 截断 800}
本步要求：{prompt}
完成判据：{criteria}（满足它，这一步才算完成）
产出物：{deliverable}
```

**injection（当前流程 · 工具卡）**：

```text
我正在按「{script_name}」推进，当前在 {step_id}。
本步要求：{prompt 原文}
我已落盘的文件：{artifacts 文件名列表}
```

**硬约束（不变）**：字段取值与来源**一律不变**——仍是 driver runtime / 剧本 JSON / prompt 文件 / artifact manifest / board snapshot。只改人称与标签。

### 2.3 事件层（不动）

`type` 仍为 `context_preamble` / `context_injection`；`data` 键集不变；`source_kind`/`source_ref`/`step_id` 不变；`injection_key` 不变；`EVENT_TYPES` 仍 25 类。

## 3. 验收（严格版）

> **全绿只是最低门槛，不是验收。** 每条都要有**可复现证据**；无证据的判据＝未通过。

### 3.1 证据规则

1. 每条判据附证据：测试名＋断言原文／日志摘录／改前改后 diff。
2. 报告必须给**改动前后对照**，不许只写"已通过"。
3. **未覆盖项必须显式列出**；用"全绿"掩盖未覆盖＝报告不合格。
4. 任一判据失败 → **停手如实报告**，不得"绕过去让它绿"。

| # | 判据 | 证据要求 |
