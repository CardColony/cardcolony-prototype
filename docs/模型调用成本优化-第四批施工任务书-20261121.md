# 模型调用成本优化 · 第四批施工任务书

**目标**　减少普通主对话工具续跳重复携带的文件证据。先做 `search_files` 和 `read_file`。模型要能凭路径和行号读回原文，工具结果可追到真实执行，任务的实际动作和交付判据沿用现行契约。 [总方案第五节](模型调用成本优化-方案与施工任务书-20261120.md#五-第四批-工具轮只回传足够的证据)

**开工顺序**　冻结样本并抓现行出站 → 做成功结果的投影 → 做同回合证据引用 → 验证预算和读回 → 交开关关闭与开启的实际出站对照。

## 一、入口、范围和回退

- 从 `message_runner` 执行工具后的结构化结果接入。`render_tool_result` 仍负责现有结果文本，真实结果事件、台账、会话工具块与全文累积继续使用现有数据。缩量发生在 `ToolTurnSlot.wire_messages` 生成请求副本时。结构化证据元数据随当前轮槽传递，原列表和内层字典保持原样，内部字段留在宿主。 [执行与回执](../src/api/message_runner.py#L2240) · [轮槽](../src/api/tool_fold.py#L125)
- 试点只动普通 `main` 回合这两种工具的成功结果。沿用批二对评审、对齐和代席身份的识别依据 `source.kind`、`act_as`、`ctx_card`，三席及起草沿各自现行路径。沿用既有工具注册、参数契约、路径解析和权限闸。失败回执、写工具和发信回执、任务证据 `rc:`、兼容调用来源与纠正提示沿原链保留。更早回合仍用现有历史存根和隔离投影。 [范围判定](../src/api/task_scope.py#L64) · [文件工具](../src/api/file_tools.py#L253) · [执行权限](../src/api/card_tools.py#L11464) · [历史存根](../src/api/context_regions.py#L1044)
- 新开关用 `TOOL_EVIDENCE_WIRE=1`，缺省走现有投影，开关关闭时出站逐字同基线。第二批 `CONTEXT_SCOPE`、第三批 `REVIEW_CONTEXT_PHASES` 在两组对照里取相同值。生产试点配置及 5700 整组重启另行请示。

## 二、先把两种结果做对

### 1. `search_files` 先给命中坐标

- 按真实结果保留搜索范围、扫描文件数、工具返回的命中数、命中路径与 **1 起行号**、源结果的 `truncated`。命中数取 `len(hits)`，截断时显示为已返回条数。现有上限、正则优先级、排序和实际扫描行为沿用 handler。
- 短结果原样回传。长结果先缩减命中行的 `text`。能从真实命中行定位匹配处时保留附近的逐字片段，明确标为片段。定位不可靠或片段放不下时只给路径和行号，由 `read_file(path, para_start, para_end)` 回读。搜索字段 `text` 已经去掉两端空白，逐字证据以 `read_file` 返回的行内容为准。
- 优先保留已返回的全部命中坐标。预算连坐标也装不下时，保留确定的有序前缀并注明展示多少、共取得多少、如何用更窄的 `path` 继续。工具扫描截断与出站展示省略分别记录。零命中且扫描截断的结果应保留这个限制。

### 2. `read_file` 给所请求的实际原文

- 一次新的短区间读取要把该区间原文完整送入紧接着的模型请求。使用 handler 实际返回的 `path`、`read_lines`、`total_lines`，起止行以实际范围为准。显式请求区间跨文件尾时，定位提示只列实际读到的行。当前入口允许超尾起点返回空正文，结合总行数判断空区间，保留空结果语义。原文匹配按现行 `splitlines` 与换行拼接契约核对。
- 长结果缩减时保留可回读的路径、全文件行数、已读区间、实际保留的行段和省略范围。优先保留完整行，区间提示使用现有 `read_file` 参数。遇到超长单行等现有工具无法按行继续分段的情况，如实显示限制和原记录位置。普通短结果及可能含有关键错误原因的失败回执保留现有表现。

## 三、同一回合只重复发送必要的原文

1. **用执行事实建立引用。** 仅合并同一轮槽内已授权且真实成功的 `read_file` 结果。核对工作、卡／实际执行身份、工具名、同一解析后文件身份、有效参数与实际行区间、读取时获取的文件版本。版本凭据随读取取得。可对该次读取已经取得的文件字节求指纹，无需另读一次。文件大小和修改时间可辅助判断，版本证据缺失、读取失败、换路径、权限变化或范围不符时按各自结果处理。全文件指纹相同仍需回执身份和区间匹配。
2. **减少重复回传，真实读取照常执行。** 本批通过原入参、权限闸和真实 handler 取得每次读取结果，避免预判文件状态导致读到旧内容。保留每个调用自己的 `tool_call_id`、成功或失败状态和来源。相同证据在当前请求内保留一份可核对的原文，其余结果位置给出宿主引用，注明实际路径、行段及那份工具结果的 ID。引用写在对应 `role=tool` 的内容中，使用现有的简短方括号提示。任务证据声明继续绑各自调用。跨回合不建结果缓存，目录搜索不做跨调用结果复用。
3. **预算结算后再核对引用。** 上述引用指向本次实际出站中可用的原文。若原文代表项被缩成另一段、移出或本轮无权使用，引用降级为可执行的行段回读说明。提示区分「之前读取的版本」和「现在重读的文件」，历史旧版按既有档案回看。同一工具结果只经一次去重决定，被本策略接管的位置由这条引用链统一处理。

## 四、预算与保护顺序

- 复用 `WIRE_RESULT_MAX_CHARS`、`WIRE_OLD_RESULT_CHARS`、`WIRE_BUDGET_CHARS` 作为第一轮试点量级，当前默认分别是 **60,000、3,000、300,000 字符**。按续跳出站的实际路由和样本报读数。预算判断含引用、坐标及省略提示，只有投影确实更短才替换。对照组均保留现有的字符限额与旧去重。 [现有预算链](../src/api/tool_fold.py#L55)
- 优先给本跳刚取得的短区间原文、任务锚与必要命中行。先缩搜索预览和更早轮的冗余正文，再考虑老结果的行段定位。按行或字段构造投影后再序列化。每次都保留完整 assistant 调用和成对的 tool 消息、顺序和 ID。错误码与副作用回执沿用既有出站规则。大量保底信息仍超预算时，交回实际超量、原因及现有回退表现，预算数字以真实出站为准。
- 先做确定性投影。工作范围以本轮可信入口、实际工具入参和回执为依据。沿用用户插话、停止、重试和同轮任务交付路径。工具段压缩不能增加一次模型请求来生成摘要或补齐原文。

## 五、隔离验收

在 `tests/conftest.py` 隔离库造文件或从同一冻结副本起跑。每个样本的关闭组和开启组用独立副本、相同提示、相同权限和模型路由。逐字对照时固定宿主生成的标识或单列其差异，保留未处理的原始出站字节。沿 `routes._run_message → execute_tool → 轮槽 → gateway → 适配器` 运行。仅在 HTTP 传输点回放模型帧。用 `OutboundRecorder` 抓真实序列化载荷，工具读、写、权限、会话与事件走真实代码。 [传输探针](../tests/outbound_probe.py#L22) · [续跳发送](../src/api/message_runner.py#L1391)

| 必测样本 | 通过条件 |
| --- | --- |
| **搜索后精读** | 多文件长命中、中文、命中靠行尾、有前导空白。让回放按实际收到的路径和行号生成 `read_file` 参数。保留小结果、关键坐标和扫描截断标志。真实读回完全匹配原文，给出的最终结论和证据一致。分别验无命中、截断和因出站预算少展示的情况。 |
| **同文件重复读** | 同一回合两次请求同版本同区间，再做一轮短读取。逐跳检查引用 ID 在该请求内有完整的有效原文，且两个调用各自有真实回执。分别测同文件不同区间、不同文件同文、并列短结果。已有去重能处理的样本如实报持平。 |
| **写后回读与权限变化** | 先读再用真实 `edit_file`／`write_file` 写入等长不同内容，再读同一区间。另用测试夹具替换同路径文件并尽量保留大小和修改时间，证明两种变更都回到新版本。撤销权限或改到拒绝路径后仍收到原错误。失败位置没有旧文件成功正文，引用也不能把该次调用写成成功。 |
| **预算压力和续接** | 构造多轮大结果、一次短的精读、多字节字符、长单行。核对新鲜原文、保留行号、明确省略区间、被裁代表项的引用处理。通过真实 `steer` 或一次同跳重试核对配对、任务证据、来源与实际请求次数。同一逻辑请求重试时照常复用既有请求体。 |
| **档案和非试点对照** | 按调用查事件、台账、原文块及下一轮历史。结构化数据、归档正文、状态、失败码、调用来源和任务证据与关闭组一致。非试点工具验证一个真实写入或发信回执，评审或非 `main` 对照走原投影。 |

**放行条件**　搜索后精读的代表任务里，开启后续跳工具结果总字节及同一任务的全部请求正文总字节都降低。所有正确性用例均完成，真实模型请求次数无增加。分别报模型请求数、工具派发／成功数与读取 handler 执行次数。单次模型请求变小而任务要靠更多次重读才能结束的样本，按整条任务记账。
