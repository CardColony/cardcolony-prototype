| 00 总纲 | 做什么、不做什么、分几步、怎么算成 | 根卡使命与需求正稿的来源 |
| 01 系统架构设计 | 分层、边界、十二份契约、主链路、技术选型 | 仓库内的架构基线；各卡只引用、不复述 |
| 02 拆卡方案 | 整棵卡树：每张卡的使命、要什么、怎么算做到、依赖谁 | 域卡、单元卡的使命与需求草稿的来源 |
| 03 规范与约束 | 全树都要守的规矩 | 项目规则各分区 |

**效力顺序**：用户当面裁定 ＞ 本方案 ＞ 由本方案转写出的各卡需求正稿 ＞ 其余一切（原型代码、旧文档、模型自己的想法）。卡片认为方案有错，走勘误（R§五），不许悄悄偏离。

## 二、要造的东西

**一句话**：一个给普通用户用的通用操作系统——占的是 iOS、Android 那个位置，但它是为 AI 应用生的。底下是 Linux；让应用「活」起来的引擎是沉在系统里的智能体机制（居民、事件、闸、线）；在这台机器上造应用的工具是 CardColony。

**三件套各归各位**：

- **AI OS（给用户）**：开机进主屏；应用随便什么形态——聊天是它、相册是它、一整个智能体组织也是它。智能体组织是封顶的形态，**不是入门的门槛**：一个不带智能体的应用同样原生。
- **运行时（在系统里）**：卡网络那套机制沉在系统里——居民、事件、闸、线、监督、harness。它是「AI 应用能活起来」的引擎，不绑定任何应用形态。「原生融合 CardColony」融的是这层机制，不是那个产品。
- **CardColony（给造应用的人）**：这台机器的开发工具，相当于 Xcode 之于 iOS——只不过这个开发工具自己就是一个多模型、多智能体的组织。两条造法：你在工作台里把智能体节点**组装**成 work，或描述需求让开发组织替你造；造好的 work **封装**成应用包，装到这台或任何一台同样的机器上。工作台是它的界面——普通用户不装它，就永远见不到。

**源头是你自己说过的话**（2026-11-05 关于 AI OS 的讨论，以及 2026-11-10 的两条确认）。方案里每一块都要能指回其中一句：

| 你的原话 | 在方案里落成什么 |
|---|---|
| 「这套系统的卡片网络，可以组成一个个 AI APP，每一个 app 就是不同的卡片矩阵组合」 | work 包＝应用（A§6·C1） |
| 「你可以下载一整个 work 到自己的 ai os 上，这个 work 自动运行」 | 安装即常驻、重启后自己接着干（A§7 链路三、四） |
| 「不同的节点都可以触发运行，有的节点的触发事件来自网络，有的来自硬件，也可以由用户输入对话来触发」 | 四类触发（A§6·C5） |
| 「harness 就是各种程序逻辑；卡片（自定义的智能体）和程序节点和 harness，就能组成丰富的可组合性」 | 三件积木，各自可换（A§5） |
| 「界面不再是现在这套；work 项目能打包成应用，用户体验就跟用应用一样」 | 系统壳＋应用界面；会话与画布是开发工具的工作台，不是用户界面（A§6·C8） |
| 「背后驱动的，是 N 个智能体……有大模型也有小模型还有本地模型、快速反应模型」 | 模型分档与本地模型（A§6·C6） |
| 「卡网络的节点之一，就可以是某个硬件」 | 设备作为节点（A§6·C4） |
| 「只有算力是租的，组织和数据是你的」 | 数据默认不出机、放行留记录、整包带走（A§6·C6、C7） |
| 「不想做成 docker、windows、linux 上的一个应用，而是直接安装于硬件上的 OS（可以以 linux 为基础）」 | 可启动整机镜像（A§6·C11） |
| 「基于 linux，然后原生融合 cardcolony」 | 三条根原则（本文第三节）与融合映射表（A§3） |
| 「这个 os 要代替的，是 ios、安卓这些通用系统，而不是一个干活的 ai os」 | 定位三件套（本文第二节）：OS 是消费级通用系统，不是工作站 |
| 「cardcolony，是未来开发 ai os 应用的开发者工具」 | 开发工具产品线（K§5·D10）；运行时机制留在系统里 |
| 「用户可以直接组装不同的智能体节点形成 work，封装成 ai app」 | 组装面＋work↔包往返（A§6·C1）；验收 E11 |

**做完以后你手里有什么**：
- 一个镜像文件：写进 U 盘或硬盘，电脑开机直接进这个系统（虚拟机同理），全程不碰命令行。
- 系统里能装应用：选一个 work 包 → 它告诉你它要什么权限 → 同意 → 它出现在主屏，并且从此自己在后台工作。
- 四个小应用，用来证明「网络／硬件／用户输入」三种触发、大小模型混编、硬件当节点、消费级纯界面应用都是真的。
- **开发工具**就在机器上：你——或让 AI 组织替你——能把智能体节点组装成应用、封装、安装。不会写代码也能做出会干活的 AI 应用。
- 一套命令行、SDK 和文档：别人（或别的开发组织）照文档就能做出能装的应用。
- 全部过程文件与验收证据，在仓库和卡面上。

## 三、三条根原则（方案里的一切都从这三条推出来）

**原则一 · 地基租用，语义自有。**
Linux 内核、驱动、基础系统组件只做配置与打包，**一行不改、一个驱动不写**。「这台机器是什么、谁能做什么、发生过什么」全部由卡网络回答。
判据：镜像里没有自编的内核补丁与自写驱动；换一个内核小版本，系统语义不变。

**原则二 · 原生融合＝Linux 只负责执行与强制，事实只有一份。**
进程、cgroup、文件权限、systemd 单元，都只是卡网络做出决定之后的**执行结果**，不是第二份真相。任何 Linux 侧的状态都必须能从事件日志重新推出来；推不出来的，就是设计错了。
判据：把全部派生状态（运行中的单元、挂载、投影缓存）清掉再启动，系统从事件日志恢复到同一读数。

**原则三 · 系统即第一个 work。**
系统自己的服务与第三方应用走同一套接口。系统服务**没有特权通道，只有更大的授权**。
判据：系统服务用到的每一种能力，都能在公开契约里找到条目；找不到＝契约有洞——补契约，不开后门。

## 四、范围

**做（v1 必须）**
1. 可启动整机镜像（x86_64 电脑与虚拟机）：开机直进系统界面；系统分区只读、数据分区独立；A/B 升级、失败自动回退；可安装到本机磁盘。
2. AI 应用包（`.work`）：格式、清单、校验、签名；安装／启动／停用／升级／卸载；数据导出与导入；活 work 的封装导出与手写清单打包，同格式同校验。
3. 应用积木：智能体节点（卡）、程序节点（沙箱里跑的代码）、harness 策略——全部可选可组合；什么都不带的纯界面应用同样成立。
4. 四类触发：用户输入、定时、网络（外部推送进来、定时出去取）、宿主与硬件事件。
5. 宿主融合：沙箱运行体（权限与限额由 Linux 强制）、宿主事实进事件日志、宿主动作经闸、设备作为节点（v1 实做串口类）。
6. 模型分档：反射／工作／审议三档；本地模型运行时；远端模型凭据；按应用槽位绑定。
7. 应用界面：声明式界面组件（可选）＋自带前端包（一等公民）；系统壳（主屏、待办与通知、设置、首启向导）。
8. 授权与同意：安装时、运行时；可撤销。
9. 配额与核算：运行体数、内存与 CPU、存储、模型用量；超限被拦，机器不被拖垮。
10. 数据主权的最小实现：应用数据默认仅本地；「本地卡／可出境卡」划界；放行留授权记录；数据整包导出导入。
11. 开发者工具链与文档；开发工具 CardColony（工作台、组装面、封装、节点目录、开发组织）；四个样品应用；一组反例应用。
12. 整机验收：十条场景、红样本账本、加固套件。

**不做（v1 明确不做）**
- 自写内核、驱动、引导器、图形栈；传统桌面环境。
- 手机与 ARM 镜像；触屏虚拟键盘；语音与摄像头输入。
- 多用户与账号体系、锁屏；应用商店、在线分发、更新服务器。
- 重新实现或重新设计 CardColony（含它尚未收口的部分，见第六节）。
- 给应用预设形态与场景：聊天不是默认界面，工作台不是用户界面——应用的界面归应用自己。
- 程序节点直连网络；第二种节点运行时（如 WASM）；跨应用协作线；多机卡网络；租远端机器跑运行体。
- 事件日志签名、安全启动、全盘加密；NVIDIA 专有驱动与 GPU 加速保证。
- 涌现验证；性能数值门槛；对外发布、宣发、官网。

**留缝（现在不做，但设计上不堵死）**
- 档位、授权种类、动作类型、事件类型、界面组件、运行体驱动、设备类别、触发来源——全部是登记表里的数据，加一项不改核心（A§6·C2）。
- 分区布局不堵安全启动与加密；身份体系不堵多用户；包签名与导出签名不堵日志签名。
- 带完整历史（工龄）的 work 分发：数据级导出先做；事件历史级的迁移，等 CardColony 的项目迁移能力。

### 6.2 基线缺口怎么处置（写死）

- **本项目不替 CardColony 重新设计它没收口的部分**。那些事已有责任卡和已下的裁定，再设计一遍就是造第二个权威。
- 基线缺口＝本项目的外部阻塞：登记在根卡的「基线缺口表」，受它阻塞的单元卡标「挂起·等基线」，**其余照常推进**。不造替身、不走旁路、不拿桩冒充通过。
- 因此阶段关口分两半：不依赖智能体执行的半边（镜像、宿主融合、应用包、程序节点、界面壳）可以先走；依赖 B1–B3 的半边等基线（见第七节）。

### 6.3 建造环境

本机已具备：Go 1.27、Node 24、Python 3.11、Docker Desktop、WSL2（Ubuntu-22.04）、LM Studio。镜像构建与虚拟机测试一律在**专用的 WSL 发行版或容器**里做，不动 Windows 宿主、不动你现有的 WSL 发行版、不碰 5700 服务（R§十一）。

### 6.4 装载时要定的三件事（现在不用定）

① 这次全自动在哪套 CardColony 上跑；② 代码基线取重构版的哪个提交、在哪个分支上干；③ 开跑时机（见第十节第 3 条）。

## 七、阶段路线与关口

**总规矩：镜像先行。** 从 S1 起，任何时候都有一台能开机的机器；之后每一步，都是让这台机器多会一件事。不许各域分头把零件做完、最后再拼——那正是 work_027「零件齐了、整机跑不起来」的来路。

| 阶段 | 做什么 | 出口（全部满足才放行） |
|---|---|---|
| **S0 探针与核验** | 证实关键技术选择在本机环境成立；实读 CardColony 基线；在 Linux 上给持久性重新取证 | 每个探针有绿有红的证据；选型表定稿（不成立的按撤退条件换）；基线读数表与融合面清单在盘 |
| **S1 契约冻结＋曳光弹** | 十二份契约落成机器可读件并冻结；打通最窄的一条整机主干 | 冻结宣布；**T-0a**（无智能体半边）在虚拟机里跑通；**T-0b**（智能体半边）跑通，或按基线缺口如实挂起 |
| **S2 加宽** | 各域按冻结契约把能力补全，持续进镜像 | 各域单元验收；E1–E7 在虚拟机里可跑 |

## 九、整机验收十一条（根卡的总判据，全部站在用户角度）

| 编号 | 用户能做到什么 | 对应原话 |
|---|---|---|
| **E1 开机即系统** | 镜像写进磁盘，开机直接进主屏；第一次开机走完向导（语言、网络、模型）就能用。全程不出现命令行 | 「直接安装于硬件上的 OS」 |
| **E2 装应用像装应用** | 选一个 work 包 → 看到它要的权限 → 同意 → 它出现在主屏、点开即用 | 「work 能打包成应用」 |
| **E3 应用自己会动** | 装好以后不打开界面，事件来了它自己处理并通知你；重启机器后不用任何操作，它仍在工作 | 「这个 work 自动运行」 |
| **E4 三种触发都走得通** | 网络、硬件、用户输入各有一条完整的链：触发 → 卡或程序节点 → 结果 → 界面；每一步在事件里查得到 | 「触发事件来自网络……硬件……用户输入」 |
| **E5 积木可换、组织不是门槛** | 同一个应用同时用到智能体、程序节点、harness；换掉其中一件，另外两件不用动；一个不带智能体的纯界面应用照样安装、调模型、跑通 | 「丰富的可组合性」 |
| **E6 大小模型一起干活** | 同一个应用里本地小模型和大模型同时在用；断网时本地那部分照常，依赖远端的部分如实显示受阻 | 「N 个不同类型的模型一起运作」 |
| **E7 像应用，不像管理台** | 用完应用的主要功能，不需要看见卡树、会话、事件；机器上不装开发工具就没有工作台——普通用户根本没有需要它的场景 | 「普通用户不需要工作台」 |
| **E8 组织和数据是你的** | 应用数据在本机；能整包导出、在另一台机器导入后接着用；标了「仅本地」的数据不出现在任何发往远端的请求里；每次放行都有授权记录 | 「算力是租的，组织和数据是你的」 |
| **E9 硬件是节点** | 一个接在机器上的设备是应用的一个节点：它的数据触发应用；应用经授权可以向它下动作；拔掉它，应用如实显示缺了什么 | 「卡网络的节点之一就可以是某个硬件」 |
| **E10 管得住** | 停用、强制停止立刻且如实生效；越权的应用被拒且留痕；失控的应用被限额拦住、机器仍可用；断电重启不丢已确认的数据；系统升级失败自动回退、组织记忆不丢 | 「组织和数据是你的」的底线 |
| **E11 组装即应用** | 在工作台把几个智能体节点连成 work → 封装成包 → 装到本机（再到另一台机器）→ 能跑；换掉其中一个节点，其余不动 | 「直接组装智能体节点形成 work，封装成 ai app」 |

每条的取证办法、绿样本与红样本见 K§6·D9-U3。

## 十、需要你确认的事

**1. 名字。** 文中暂用「CardColony OS」当工程代号，对外名字你定。

**2. 样品应用——上次我没问清楚，换个说法。**
操作系统做出来以后，得真装上几个应用，才看得出它能不能用——就像做完手机系统，得有个能装能开的 App 才算数。所以方案里安排这次运行顺带做四个小应用当「验收样品」：
- **智能相册**（消费级样品）：一堆照片倒进去，本地模型自动整理、归类、按内容找。全程无对话、无智能体——证明「AI 应用不一定是聊天、不一定是组织」。
- **设备管家**（组织型样品）：盯着这台机器自己——电量、发热、磁盘、网络、插拔设备。有事时本地小模型先判断要不要打扰你，需要时再叫大模型解释；要动机器之前先问你。
- **传感器看板**（硬件样品）：一个接在机器上的串口设备当应用的一个节点，它的数据触发应用。证明「硬件是卡网络的节点」。
- **网页守望**（外部视角样品）：定时去看几个网页、接收外部推送，筛出值得看的告诉你。它由一张**没看过内部设计、只读开发者文档**的卡来做，证明「别人照文档就能做出能装的应用」。

「组装智能体节点→封装成应用」不单设样品，它由验收 E11 现场演示。四个都很小。你更想看到别的应用，告诉我是什么样的，我换。

**3. 什么时候开跑。**
重构版 CardColony 现在还差「卡在正式路径上真跑一轮模型＋工具」这最后一截（work_027 在办）。方案按两种情况都能跑来写：基线到位——全速；没到位——先做不依赖它的那一半，其余挂起等基线。你要定的只是：**等重构版到位再开跑，还是现在就开跑先做一半**。

**4. 目标机器。** v1 只做普通 x86 电脑和虚拟机。手机不在这次范围，设计上不堵。

**5. 我替你先定了的默认值**（全在 R§十三「预裁定清单」，逐条可否）。最要紧的五条：
- 应用数据**默认仅本地**；应用要用远端模型，安装时必须明说并得到你的同意。
- 镜像里**不带模型权重、不带任何密钥**；首次开机的向导引导你配置。
- 没签名的应用包只有打开「开发者模式」才能装；开发者模式默认关。
- v1 没有应用商店：应用从本地文件或一个网址安装；系统更新同理。
- 系统界面用浏览器内核全屏呈现（用户看不到浏览器），没有传统桌面。
- 开发工具默认随系统装在本机——这台电脑能给自己造应用；不装它就没有工作台，壳里没有它的入口。

**6. 真实模型参与测试。** 方案默认用「回放模型」做判据（同样的输入给同样的输出，结果可复核），真实模型只做少量冒烟。真实模型的凭据走部署侧注入、不进仓库与卡面——沿用你在 work_027 批过的口径。这条需要你对本项目再点一次头。

## 十一、术语

- **建造卡／居民卡**：本方案里「卡」有两层意思。**建造卡**＝执行本方案、把系统造出来的那些卡（根卡、域卡、单元卡、worker 卡、UI 卡）；**居民卡**＝造出来的系统里、应用内部的智能体。未加限定词时：02、03 两份里的「卡」指建造卡，01 里的「卡」指居民卡。
- **work 包（应用包）**：打包好的一个 work，一个文件。**应用实例**：装好以后的它，在卡网络里就是一个项目。
- **程序节点**：不持使命、只做计算的节点，跑在沙箱里。
- **触发**：让应用里某个实体开始干活的事件。
- **档位**：模型的分档——反射／工作／审议。
- **宿主事实**：机器自己发生的事（电量变了、设备插上了），写进事件日志之后才算事实。**宿主动作**：对机器做的事（关机、连网、升级），必须经闸。
- **沙箱**：程序节点的运行环境，能碰什么由授权决定、由 Linux 强制。
- **契约**：跨域接口的唯一约定，共十二份（C1–C12）。**冻结**：契约定版，之后改动要走变更通道。
- **探针**：动工前先做的小实验，证实一项技术选择在本机成立。**撤退条件**：出现什么现象就判这项选择不成立、换成什么。
- **融合保护区**：仓库里属于 CardColony 的目录。**融合补件**：为融合而必须对保护区做的改动，只能是通用扩展面，逐件登记（R§七）。
- **系统 work**：系统自己的那个「应用」，系统服务都登记在里面（原则三）。
- **AI 应用**：装在这台机器上的应用的统称，形态不限——聊天、相册、智能体组织都算。
- **work／应用包**：work 是活的组织（智能体节点＋程序节点＋harness）；应用包是它的便携形态。「封装」＝把活 work 冻结成包；「安装」＝把包复活成组织。
- **工作台**：开发工具（CardColony）的界面，给造应用的人看组织怎么运转；普通用户不需要。
- **开发工具**：CardColony 在这台机器上的产品形态——工作台＋组装面＋封装＋节点目录＋开发组织。
- **节点目录**：可组装的智能体节点与程序节点的清单（系统自带／第三方／自己攒过的）。
