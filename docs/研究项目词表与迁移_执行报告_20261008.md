## 七、撞红与处置（§四.5 如实记录）

### 红 1：T3 后回归 32 failed（预期内，已处置）

**现象**：收紧后全量 pytest 32 failed / 75 passed。

**根因（先搞清楚病根）**：conftest 沙箱把 works/logs 等运行时根全部搬进 tmp_path，**唯独漏了 `TYPE_REGISTRY_PATH`**——`load_type_registry()` docstring 明说「路径由模块级常量派生，测试可 monkeypatch 改写（与 WORKS_DIR 同一套隔离手法，见 tests/conftest.py）」，**基座 T2 落地时预告了手法却没做**。收紧前测试靠「线索」`write_blocked=false` 放行才绿；收紧后测试加载**生产真实注册表** → 默认 card_type='线索' 建卡全部被闸1 拒 → 32 红。

**处置**：conftest 补沙箱 patch（`TYPE_REGISTRY_PATH → tmp_path 下不存在文件`）→ `load_type_registry()` 返回 `{}` → 按 card_store 既有设计「无注册表降级放行」（card_store.py 492-495 明文）→ 测试回到收紧前行为 → 三轮 107/107/0/1。**这不是掩盖**：沙箱纪律本就是「测试不依赖仓库真实环境」，与 WORKS_DIR 同一哲学。

**代价（如实记）**：注册表闸逻辑在 pytest 内从此零覆盖——**原本也是零**（tests/ 里没有任何基座用例，grep write_blocked/research_project/topic 零命中）。闸的真实验证靠本报告 §六的自检脚本；**基座测试建设（沙箱内自建注册表 fixture）属后续任务，建议立项**。

### 红 2（方案缺口，登记不修）：收紧后两个建卡入口被拒

**实测**（沙箱）：① 模型工具通道 `card_tools._h_create_card`（不传 card_type）→ 拒；② 前端 UI 通道 `CreateCardRequest.card_type` 默认"线索"（workspace.js 下拉也只有「线索」一项）→ 拒。**收紧生效后，模型建卡与用户 UI 建卡在适配前全部建不出卡。** 文本通道 `card_proposal.py` 同病（不传 card_type）。

**为什么不修**：任务书 §四.4 明确「不做：删剧本残留、**UI 字段渲染**、说明卡建设」——入口适配明确在范围外；且修法有设计选择（模型通道按树映射默认类型？前端下拉按 pc 动态渲染？prompt 教模型显式传类型？），属派发端设计决定，执行方不擅自定。

**修复建议（供拍板）**：最小修＝`_h_create_card` 与 `card_proposal` 按目标树 pc 映射默认类型（research_project→topic、rd_project→sub_project，一行常量复用 LEGACY_MIGRATION_BY_WORK 语义）；前端下拉动态化与 prompt 补教另开小任务。**在适配落地前，若需建卡请直接说，走显式类型通道。**
