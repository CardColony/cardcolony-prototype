## 1. 目标与范围

把两个原型已验收的全部视觉与交互落进生产（`static/canvas.js` / `static/style.css` / `templates/work.html` / 后端配套），共七块＋两项待验收：

1. 卡面重构（根卡/子卡：项目名、三行状况、icon＋数字子卡控件、去类型标签、根卡 360 宽）
2. 新消息气泡（卡内、NEW 红壳、流式、点击开弹窗、卡上无输入框）
3. 快捷回复窗（中央正方、多窗秩序、⇥ 吸附、两段动效、无色无流光）
4. 两状态（运转＝绕框流光；退役＝实体暗灰）
5. 色表与界面灰（类型→色映射为唯一彩色；界面其余全中性黑白灰）
6. 画布导航交互（顶部 −/拖条/＋ 缩放、滚轮滚动、空白拖动平移）
7. 数据路与端点（recent 轻量读、state 放行、SSE/轮询消费、退役拦截）
8.（待验收 D29）退役卡默认折叠＋「完成」徽章
9.（待验收 D30）连线生长动画

**不做**：workspace（对话页）改动（黑白灰范围见 Q3）；旧数据迁移（存量卡 state 为 NULL/active 视作运转中，退役从零标记）；多 work 批量管理；**不动 coder 卡既有 completed 语义**（其 400 拦截照旧，见 §3.4）。

### 3.1 卡面重构（createNode 重写）

新 DOM 与 v2 §3.1 一致（.card-node > .msg-badge + .cbody > (.rcore > .tname+.summary+.subctl) + .bubble），v3 补三处接线细节：

- **data-type 挂真实类型**：`node.dataset.type` 不动（L1135 照旧），CSS 色表选择器换成真实码（§3.5）；legacy 六行选择器替换时**顺手删除**（死代码）。
- **data-state 驱动退役**：`node.dataset.state = card.state || "active"`——completed 即退役态全部样式（暗卡/禁气泡/禁输入/徽章 D29）。NULL/active 同观感。
- **三行状况数据**：canvas.json cards[] **新增 `status_block` 全文派生字段**（F9/F10——SELECT 加列、cards.append 加键；conclusion_summary 契约一字不动，tooltip 照用）；前端 `.summary` 取 status_block 前三非空行、各行省略；无派生字段时回退 getSummary 旧路径（向后兼容）。
- **subctl 替换位**：kid-badge 生成处（L1156）+ updateExpandBadge（L1123）两函数位整体换成 subctl 控件（单 svg 两组、.on 翻面、点击走既有 toggleExpand 路径）；**ttype/meta2 从模板删除**（L1162-1163），test_frontend_readability 的 CANVAS_SEL 类名清单同步（F15）。

### 3.2 新消息气泡

结构/显隐/泡形/对称留白/两行窗与 v2 §3.2 照旧。v3 修正数据接线：

- **内容源＝对话消息**（Q4 待确认）：timeline 过滤 user_message/assistant_text 的**最后一条**为快照正文（模型回的优先——最新一轮=你发完模型回的那条）。
- **懒加载**：画布装载与子树展开后，对**可见卡**批量拉 recent（§4 端点；复用摘要懒加载防抖模式）；卡海保护：仅 .l2 档且视口内。
- **流式（接线修正）**：`/nav/running` 显示某卡运转中 → **仅对该卡**开 `/tokens` EventSource，content_chunk 逐字追加进 btxt＋scrollTop 跟随；回合结束（running 里消失）→ 关连接、recent 重拉定格。**连接数＝并发运转卡数**（常态 1–3），不随卡海膨胀。非运转卡永不流式，只静态快照。
- **NEW 摘除/回归**：点开弹窗即摘（localStorage 记已读键，复用 projMsgRead 模式）；新 user_message/assistant_text 到达（轮询/流式终点发现 last_seq 变化）→ 回归。

### 3.4 两状态（运转/退役）

**退役（v3 重写——state 通用化，零新列）**：
- 数据：**state 列既有**（F1）。标记完成＝PATCH `{state:"completed"}`：routes 白名单 ALLOWED_UPDATE_KEYS **加 "state"**（唯一后端数据改动之一）；闸 4 自动校验（active→completed 合法、completed 不可逆——正合"封存"语义）。
- 拦截：POST /messages 前置判定泛化——`state=="completed"` → **409「卡片已完成（退役），不再接收消息」**（照 coder 先例 L927 的机械判定模式；coder 分支照旧 400 不动，语义区分：coder=任务完结机制、completed=人工封存）。
- 派生：canvas_store.rebuild SELECT 加 state 列、cards[] 加 `state` 键（F9 挂点 L131/L141）；PATCH 后 update_cache 自动刷新 canvas.json（既有机制）。
- 前端：data-state=completed → 实体暗灰卡（#0e0e0e 底/#262626 边/灰左条）、流光熄灭、气泡禁、弹窗输入禁；历史/树照常（D14）。
- 存量：state 为 NULL/active 的卡视作运转中（渲染层归一），**零迁移**。
-（D29 验收后并入）默认折叠＝restoreViewState 之后**从 expanded 剔除 completed 卡**（每装载一次；用户本会话可点开翻阅，刷新回折叠——F11 接线点）＋「完成」灰徽。

**运转中（瞬态）**：
- 信号源＝**轮询 GET /nav/running**（8s；iter_active 纯内存读零成本，F5）＋本页发消息后乐观置位/回查。**不新增 run_state 帧**（侵入 message_runner 写路径不值得——轮询已满足流光的反馈速度需求）。
- 前端：running∩本 work → 挂 st-run 绕框流光（var(--cc) 上色、光环按边框厚度补偿贴合）；从 running 消失 → 摘。

## 8. 风险与边界（v3 补）

- 浏览器实测：手感必须人机过。
