## 二、清理对象与判据

### A. 代码清理（收拢尾巴：文件四件进字面量）

**现状**：`TOOL_REGISTRY` 字面量 15 件 + `_register_file_tools()`（card_tools.py:1169）动态登记 4 件文件工具。

**目标**：文件四件（list_files / read_file / search_files / write_file）**直接写进 `TOOL_REGISTRY` 字面量**，与其他 15 件同构（schema + handler + readonly + switch + domain + status 六字段一处写）。删掉 `_register_file_tools`。

**关键约束（已核实的技术判断，照此执行）**：文件四件的 schema **从来不是真正的「延迟求值」**。实读 HEAD 与收拢后的 `_register_file_tools`：都是 `schemas = {s["name"]: s for s in file_tools.build_file_tool_schemas()}`（**模块加载时求值一次**）＋ `lambda n=name: schemas[n]`（**返回缓存**）。注释里「每次 build 现取」的说法**与实现矛盾，且从 HEAD 起就矛盾**——实际是模块加载时缓存，从未「现取」。

因此进字面量时**直接写静态 dict，不用 lambda**：

- list_files 的 description 用 f-string over `file_tools.ALLOWED_ROOTS`（模块加载时求值，＝现有缓存语义）；
- 其余三件（read_file / search_files / write_file）description 本就是静态字符串，照抄；
- 工具面与收拢后**逐字一致**（都是真实路径缓存），红线「工具面零变化」不破。

连带（同属 A 类）：
- `ToolDef.schema` 类型从 `Union[dict, Callable]` **收窄为 `dict`**；删 `_schema_of` 里的 `callable` 分支（唯一 Callable 用家——文件四件——改 dict 后，Callable 形态整个废弃）。
- 更正 `ToolDef` docstring 里「延迟求值（Callable）」的错误说明（这本身也是一处 B 类注释清理，一并在此处做）。

**连带清理**：
- 删 `src/api/card_tools.py` 的 `_register_file_tools`（含其末尾的 `_register_file_tools()` 调用）。
- 删 `src/api/file_tools.py` 的 `build_file_tool_schemas`（约 L422，进字面量后不再有调用方）。
- **保留** `file_tools.py` 的 `list_files / read_file / search_files / write_file` 四个实现函数（card_tools 的 `_h_list_files` 等薄壳 handler 仍委托它们）——只删 schema 构造函数，不删实现。

### B. 注释清理（只清误导，保留沿革）

**判据一句话：清「改前是什么样」的纯历史描述，留「为什么这么改」的判据。**

- **清理**：只描述「改前 / 收拢前」的实现样貌、且现在已不成立、又不含任何判据价值的注释。例：「改前是 list + build_file_tool_schemas() 追加」「改前是手工 frozenset 字面量」这类。
- **保留**：记录「为什么」的沿革注释。例：「收拢前这里是 TOOL_SWITCH 字典，现下沉进各 ToolDef.switch（一处定义）」——它解释了为什么现在没有 TOOL_SWITCH，删了后来者会误判。凡含「理由 / 判据 / 为什么」的，一律保留。
- **红线**：任何拿不准的注释，**宁留不删**。注释清理不是本任务的硬性门槛，删错了比多留一条更糟。
