# 任务书：三席身份提示词 · 走注入

> 日期：2026-10-14
> 性质：实现任务书。只定义规格、边界、验收；不在本文写代码。
> 用户口径（2026-10-14 13:33/13:36，逐字要点）：
> - 「三席的问题单独处理，它们应该**共享卡片的上下文**，但给它们**单独注入一段提示词**，告诉它们**它们的身份是三席之一**，让它们**给出自己的意见**」
> - 「**用注入的方式，效果最强**」

---

## 0. 一句话规格

三席的 **system 仍是共享的卡片上下文（不动）**；另**单独注入一条身份提示词**（注入消息、`role=assistant`、抬头 `〔三席身份〕`），随三席调用下发，告诉它们"你是三席之一、给出你自己的意见"。

## 1. 现状基线（代码实读）

| 件 | 现状 | 落点 |
|---|---|---|
| 三席 system | `vp_system_prompt` ＝ `build_viewpoint_system_prompt(neutral_context)` ＝ **纯上下文、零指令**（函数体一句 `return context_block or ""`） | `src/api/prompts.py` |

| 三席调用 | `run_viewpoints` → `_call_viewpoint` → `gw.stream_call(seat, system, user, prior_messages=…)` —— **当前不传 `turn_tail`** | `simple_service.py:314-367` |

**结论**：**共享上下文已有、任务说明（三问）已有；缺的只有"身份"**。本任务补这一条，且走注入。

---

## 2. 规格

### 2.1 载体：注入消息（与主模型注入同一条通道）

- 形态：`{"role": "assistant", "content": "〔三席身份〕\n" + 身份文案}`；
- 通道：经 `gw.stream_call` 的 **`turn_tail`** 下发（**不新增机制**——该参数已存在）；
- **不走 system**、**不走 user 位质询文**、**不进 session/prior**。

### 2.2 投递路径（需把 `turn_tail` 参数贯通）

```text
message_runner.run_seats
  → simple_service.run_viewpoints(..., turn_tail=[身份消息])
    → simple_service._call_viewpoint(..., turn_tail=...)
      → gw.stream_call(..., turn_tail=...)
```

- `stream_call` 已支持 `turn_tail`，**不必改 gateway**；
- `run_viewpoints` / `_call_viewpoint` 需各加一个可选参数并透传（缺省 `None` ⇒ 行为逐字不变）。

### 2.3 位置

注入消息**追加在质询文（user 位）之后**——与主模型注入"追加在用户消息之后"同构。

### 2.4 每席一次 · 内容相同

- **三席各拿同一段**（文案不含席号——用户口径是"三席**之一**"，不区分哪一席）；
- 三个并发调用**各自**收到同一条注入。

### 2.5 事件

- 提交轮三席进场时 **emit 一次**：`type="context_preamble"`、`data.source_kind="viewpoint"`、`data.content=<身份文案>`。
- **理由（我定的，可推翻）**：它本就是"固定总领"这一类的注入；复用现成事件类型可少加一类、前端已有 case 能渲染。
- 若你要独立一类（如 `context_seat_identity`），说一声即可改（`EVENT_TYPES` 25→26 ＋ 前端加 case）。

### 2.6 身份文案（**草稿，待你定稿**）

```text
你是本轮的三位观点审议席之一。三席各自独立并行，你看不到另外两席的输出。

你的任务：基于下方共享的卡片上下文，以及本条消息里的执行材料，给出你自己的意见。
- 独立判断，不附和；
- 有依据地说，指出依据在哪；
- 结论明确（通过／不通过、同意／不同意）。
```

**文案定稿前不得施工**（§5-1）。

### 2.7 不动的东西

- 三席 system（`vp_system_prompt`）**逐字不变**——共享上下文照旧；
- 三席 user 位质询文（`REVIEW_TASK_NOTE` 三问）**不变**；
- 观点回流铁则**不变**（观点全文不进 session、不进 prior、只进统合官 user_prompt）；
- 主模型路径**不变**（`turn_tail` 缺省 `None` ⇒ 逐字同旧）。

## 3. 连带面与风险（如实报告）

1. **三席上下文变长**：每次三席调用多一条注入消息。须报告改前/改后三席请求字节数。
2. **并发三席**：三个调用各带一条注入——须确认**不互相串**（内容相同，无串的风险；但须断言"每席都拿到"）。
3. **`turn_tail` 追加在末条**：注入会成为三席请求的**最后一条**（`role=assistant`）。与主模型注入同一形态——**是否触发"续写"（预填）未实测**，只登记为风险，不得据未验证的担心自加机制。
4. **`context_preamble` 的既有消费方**：`source_kind` 新增取值 `viewpoint` 后，检查有无按 `source_kind` 分支的消费方需同步（前端目前按 `type` 渲染，预期不受影响，但须核）。

## 4. 验收（严格版）

> **全绿只是最低门槛，不是验收。** 每条须有**可复现证据**；无证据＝未通过。

### 4.1 证据规则

1. 每条判据附证据：测试名＋断言原文／日志摘录／改前改后 diff／实测字节数。
2. 报告须给**改动前后对照**，不许只写"已通过"。
3. **未覆盖项必须显式列出**；用"全绿"掩盖未覆盖＝报告不合格。
4. 任一判据失败 → **停手如实报告**，不得"绕过去让它绿"。

### 4.2 正向判据

| # | 判据 | 证据要求 |
|---|---|---|
| V1 | 三席调用里 `turn_tail` 含身份注入（`role=="assistant"`、含 `〔三席身份〕`） | 捕获 `stream_call` 的入参，断言 |
| V2 | 三席 `system_prompt` **逐字不变**（＝共享上下文） | 与改前逐字比对 |
| V3 | 注入文案 ＝ **定稿文案**（逐字） | 断言 |
| V4 | **三席各拿到**（3 次调用都有） | 断言调用次数与每次入参 |
| V5 | 事件 emit **一次**：`type=context_preamble`、`source_kind=viewpoint` | 断言事件序列 |
| V6 | 观点回流铁则不破：注入**不进** session/prior；观点**仍不进** session/prior | 会话文件与会话块断言 |
| V7 | 主模型路径**零影响**（`turn_tail` 缺省 `None` ⇒ 逐字同旧） | 主模型调用入参断言 |
| V8 | 回归 | 全量 pytest 与基线逐条对照；列出基线失败名，证明未动 |

### 4.3 负向判据（**最容易糊弄的地方**）

| # | 不许出现 |
|---|---|
| N1 | **不得**把身份写进三席 system（`vp_system_prompt` 不得变） |
| N2 | **不得**把身份写进 user 位质询文（`REVIEW_TASK_NOTE` 等不得变） |
| N3 | **不得**把注入写进 session/prior |
| N4 | **不得**改 `gateway.stream_call` 签名（`turn_tail` 已存在，够用） |
| N5 | **不得**影响主模型调用（缺省路径逐字不变） |
| N6 | **不得**改三席 system 的共享上下文来源与内容 |
| N7 | **不得**改与本任务无关的文件；不整文件 `checkout`/`reset`；不覆盖他人未提交改动 |
