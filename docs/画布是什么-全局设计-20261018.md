# 画布是什么 · 全局设计（2026-10-18 · 第二版）

> 用户要求：站在全局视角看——画布在这个系统里承担什么角色、人在什么场景用它、
> 画布与对话界面的差别、系统的特征、信息够不够、怎么排列体验最好。
>
> 这一版不写施工步骤，只回答"为什么"。

---

## 一、这个系统的特征（决定一切的前提）

从 43 张真实卡、5 天跨度、单卡 3000–40000 字的数据里读出来的六条：

1. **长程** —— 一个项目跨天推进，单卡内容量是一篇长文的 3–10 倍。
2. **分层** —— 根卡＝项目，一级卡＝领域（上下文/UI/工具/思维链/权限…），二级卡＝具体工作。
3. **并行** —— 多个领域同时推进，模型可以在不同卡里同时工作。
4. **结论沉淀** —— 卡内是长对话，但只有结论写进"现状块"，别的卡只读结论。
5. **裁定制** —— 模型提议一律标【待裁定】，用户点头才算数。**这是用户唯一的动作。**
6. **全留痕** —— 每句话、每次工具调用都可回溯，所以"过程"不需要人记，"结论"才需要。

**推论**：用户的时间全部花在"读结论 + 做裁定"。任何不服务于这两件事的界面元素都是成本。

## 二、画布 vs 对话界面：它们不是同一个东西的两种样式

| | 对话界面（card.html） | 画布（work.html） |
|---|---|---|
| 维度 | **时间**（一轮一轮往下） | **空间**（结构、并置、对比） |
| 范围 | 一张卡 | 全部卡 |
| 深度 | 深（完整推理过程） | 浅（每张卡一句结论） |
| 用途 | **想清楚一件事** | **决定先做哪件事** |
| 用户状态 | 沉浸、专注 | 扫视、判断、调度 |
| 不可替代性 | 唯一能改内容的地方 | 唯一能同时看见"全部卡的状态与关系"的地方 |

**所以画布的价值只有三条，多一条都是浪费：**

1. **全局状态** —— 这个项目现在什么状况（多少卡、多少待裁定、多少已结论）
2. **结构与关系** —— 谁属于谁、谁引用谁、谁是地基
3. **调度** —— 我现在该去处理哪一张

画布**不是**用来读长文的，也**不是**用来摆卡片的。它是一张"作战地图"。

## 三、人在什么场景打开画布

按真实使用频率排：

| 场景 | 他要回答的问题 | 现在画布能回答吗 |
|---|---|---|
| **每天开工** | 昨天做到哪、今天先做哪张 | ❌ 看不出"最近动过"和"该做哪张" |
| **批量裁定** | 攒了 74 处待裁定，一条条过 | ❌ 只有数字，没有清单，也没有"按什么顺序过" |
| **找东西** | 我记得讨论过 X，在哪张卡 | ⚠️ 有 ⌘K，但只能搜标题 |
| **看全局** | 这个项目还剩多少、卡在哪 | ⚠️ 有状态条，但没有"节奏/趋势" |
| **做决策** | 两条路选哪条，要对比两张卡的结论 | ❌ 卡片太小，结论读不全，不能并排对比 |
| **回顾/交接** | 这个项目怎么走到今天的 | ❌ 没有时间线 |

**六件事里，只有半件现在能答。** 这就是"信息不够"的实证。

## 四、现在缺什么信息（逐项）

### 4.1 卡片级：缺"这张卡在我心里的位置"

现在有：标题、结论/待裁定条目、被引用数、子卡数、最后更新时间。

缺：

| 信息 | 为什么必须有 |
|---|---|
| **层级**（第几层、属于哪个领域） | 现在只能靠位置猜；缩进/主干才是人能读的 |
| **规模**（现状块多少字） | 3000 字 vs 40000 字，工作量差 10 倍，决定"这张卡要不要现在碰" |
| **活动**（最近有没有在跑 / 多久没动） | 判断"这张卡是活的还是死的" |
| **阻塞来源**（等裁定 / 等别的卡 / 等外部） | "卡住了"和"没开始"是两件事 |
| **对话轮数 / 未读** | 这张卡里有没有我没看的东西 |

### 4.2 项目级：缺"节奏"

现在有：43 卡 / 74 待裁定 / 3 已结论 / 2 未开始。

缺：

| 信息 | 为什么必须有 |
|---|---|
| **时间跨度与节奏**（5 天、43 卡、哪天推进最多） | 判断项目是加速还是停滞 |
| **待裁定的分布**（哪几张卡积压最多） | 决定先处理哪张（积压多的先处理，避免上下文失效） |
| **自动任务状态**（有没有卡在自动跑） | 自动模式是这个系统的核心能力，画布上完全看不到 |

### 4.3 关系级：缺"方向"

现在有：`←11`（被 11 张卡引用）。

缺：

| 信息 | 为什么必须有 |
|---|---|
| **引用方向**（我引用了谁 / 谁引用了我） | `←11` 只说"重要"，不说"依赖谁" |
| **依赖顺序**（谁必须先在） | 决定推进顺序 |

## 五、怎么排列才"人能读"

用户的原话："我是人类，不是机器，我没办法从代码去直接读到卡片关联上下层级。"

**人能读的结构只有三种**：目录（缩进）、时间线（纵向顺序）、地图（空间位置）。

这个系统的数据是**严格的树**（parent 字段），且用户从不手动摆放（43 张卡里只有 2 张有坐标）。
⇒ **正确排列是"目录 + 主干"**，不是自由画布。

```
项目管理agent
│
├─ 上下文记忆系统        ←11   已结论
│  └─ （子卡…）
├─ 影子卡机制（需求定义） ←8    5 待裁定
├─ UI交互                ←7    6 待裁定
├─ 布局、信息视觉工程     ←6    4 待裁定
├─ 卡片                  ←7    2 待裁定
├─ 工具                  ←3    5 待裁定
├─ 思维链                ←1    1 待裁定
├─ 项目管理卡            ←1
└─ 权限管理              ←1
```

**为什么不用分组框**：框只说明"这些是一组"，不说明"读的顺序"和"谁是谁的子卡"。
主干线（一条连续的竖线）才能表达"这些都挂在同一个父卡下"。

**为什么不分列**：分列后"第 5 张"跑到第二列顶部，读者要在两列之间跳。
一列纵向读完 = 目录的读法。

## 六、呈现什么（最终信息架构）

### 第一层：顶栏（3 秒知道全局）
```
项目管理agent │ 43 卡 · 74 处待裁定 · 3 已结论 · 2 未开始 │ 跨 5 天 · 最后活动 2 天前
```
"待裁定"是唯一有颜色的数字。

### 第二层：目录主干（一屏看到全部领域）
一级卡（8 张）一屏内可见，每张显示：
```
├─ UI交互                ←7   6 待裁定
│  · 是否要全局树／大纲导航（树大了的唯一解）
│  · 卡内容搜索是否进 UI
```
**待裁定条目直接列在卡上**——这是用户要裁定的内容，不该藏在卡里。

### 第三层：展开子卡（点开领域后）
子卡缩进一级，显示同样的结构。默认只展开一级。

### 第四层：悬停/选中（按需）
- 引用关系线（我引用谁 / 谁引用我）
- 快速操作（进入对话、展开）

## 七、视觉规则（用户："视觉就是信息呈现"）

1. **每一处视觉差异必须对应一个信息差异**——尺寸差＝层级差，颜色＝状态，位置＝顺序。
2. **同一时刻只有一个颜色在喊"需要你动手"**——橙＝待裁定，其余中性。
3. **不给装饰留预算**——渐变、阴影、圆角、图标装饰全部从简。
4. **文字按用户读它的顺序排**——标题 → 结论/待裁定 → 元信息。
5. **默认缩放必须是"能读"的**——60% 的"全貌"等于什么都没给。

## 八、要删掉的东西（对"读"没有价值）

| 功能 | 为什么删/降级 |
|---|---|
| 拖拽吸附 + 对齐参考线 | 用户不摆卡片，他读卡片 |
| 框选 + 多选 + 整组拖动 | 同上 |
| 小地图 | 43 张卡不需要，需要的是目录 |
| 分组框 | 用主干线替代 |
| 自由平移/缩放的"白板手感" | 改成"滚动阅读"的姿势：滚轮＝纵向滚动，Ctrl+滚轮＝缩放 |

## 九、执行顺序

| 序 | 事项 | 状态 |
|---|---|---|
| 1 | 项目状态条（43 卡 / 74 待裁定 / 3 已结论） | ✅ 已做 |
| 2 | 卡片显示待裁定**条目**（不是数字） | ✅ 已做 |
| 3 | 单列纵向排列（顺序＝建卡顺序＝思考顺序） | ✅ 已做 |
| 4 | 首屏 100% 定位到第一张待裁定卡（不缩到看不清） | ✅ 已做 |
| 5 | **主干线替代分组框**（层级要硬） | 待做 |
| 6 | **滚轮＝纵向滚动**（阅读姿势） | 待做 |
| 7 | 卡片补"规模/活动/层级" | 待做 |
| 8 | 悬停显示引用方向 | 待做 |
| 9 | 待裁定队列（按卡分组，可逐条过） | 待做 |
| 10 | 删/降级白板功能 | 待做 |

# 十、用户提的两个关键问题（本节是设计核心）

## 10.1 画布在并行多线任务上的效率，为什么现在发挥不出来

**用户原话**：画布在处理复杂多线任务并行处理时的效率，一定远高于对话界面切对话，
但现在的画布做不到，从交互到界面全部都做不到。

**画布的并行优势到底是什么**：不是"卡片摆在一起"，而是**信息同时可见 + 操作不用离开**。
对话界面里切一张卡要三步（退出 → 找卡 → 进入），而且切走后上一张卡的上下文就看不见了；
画布本该"一眼看到全部卡的状态，随手切换，切换时上一张卡还在视野里"。

现在有三处**断裂**，每一处都把并行优势抵消掉了：

| 断裂 | 具体表现 | 后果 |
|---|---|---|
| **看见断裂** | 100% 缩放一屏只看 5 张卡，60% 缩到读不了 | 并行前提是"同时看见"，看不见就退化成串行 |
| **阅读断裂** | 单击卡片就跳去对话页，画布消失 | 想看两张卡的结论必须来回跳，等于用画布模拟对话界面 |
| **操作断裂** | 一次只能对一张卡做事（多选只能删除） | 无法"给 5 张卡同时下指令""同时展开 3 个领域" |

**补法（三栏工作台）**：

```
┌────────────┬──────────────────────────┬──────────────┐
│ 目录 320px  │ 画布（结构 + 主干线）      │ 详情 420px   │
│            │                          │              │
│ ▾ 项目      │  ┌────┐                  │ 选中卡的：    │
│  ├ 上下文←11│  │根卡│──┬─ 子卡        │ · 结论全文    │
│  ├ 影子 ←8  │  └────┘  ├─ 子卡        │ · 待裁定条目  │
│  ├ UI   ←7  │          └─ 子卡        │ · 最近活动    │
│  └ 工具 ←3  │                          │ · [打开对话]  │
└────────────┴──────────────────────────┴──────────────┘
```

- **左栏**：全部卡一屏扫完（紧凑行：缩进 + 标题 + 状态 + 待裁定数 + 引用数）
- **中栏**：结构（主干线 + 卡片），点卡不跳页
- **右栏**：选中卡的详情，**不离开画布就能读完一张卡**
- **切换**：点左栏或中栏任意卡，右栏立刻换内容，中栏视野不动 —— 这才是"并行"
- **对比**：选中两张卡时，右栏上下并排显示两条结论（决策场景）

**交互重新分工**：
| 动作 | 语义 |
|---|---|
| 单击卡 / 左栏行 | 选中 + 右栏显示详情（**不离开画布**） |
| 卡上 `↗` 按钮 / 双击 / Enter | 进入完整对话页（明确入口，不靠猜） |
| Shift+单击 | 多选（为批量操作） |
| 多选后 | 批量：同时展开 / 同时折叠 / 批量发指令 |

## 10.2 自动模式怎么用视觉表达

**用户原话**：画布在自动模式下，如何视觉表达，才能让人肉眼清晰看到和跟踪 AI 是如何运用这套系统的。

**现状**：真实项目里 `auto_mode` 全为 0、`goal` 全空、`goal_rounds` 全为 0 ——
自动模式一次都没跑过，所以画布上**完全没有它的表达**。这是最大的信息缺口：
这个系统最核心的能力（AI 自己推进任务）在画布上不可见。

**可用的数据**（cards 表已有）：
`auto_mode` / `goal` / `goal_state` / `goal_rounds` / `toolcard_step` / `toolcard_round` / `toolcard_final`
＋ 实时流 `GET /api/works/{wid}/stream`（SSE）

**要让人"肉眼跟踪 AI 怎么干活"，必须回答四个问题**：

1. **哪几张卡在跑？** → 卡片左侧一条**呼吸的竖条**（透明度脉冲，不用渐变），卡片边框微亮
2. **跑到哪一步了？** → 底栏 `第 3/8 轮 · 读 message_runner.py`（来自 goal_rounds + toolcard_step）
3. **刚刚产出了什么？** → 卡片右上角一个短暂的"刚更新"标记（3 秒后消失），新结论/新待裁定数变化时闪一下
4. **全局在发生什么？** → 画布底部一条**活动流**（横向时间线）：
   `14:32 UI交互 第3轮 读代码 → 14:35 工具 产出 1 条待裁定 → 14:38 卡片 已收口`

**卡间消息**（inbox）：A 卡给 B 卡发消息时，画一条**流动的虚线**（沿线移动的小点），
持续 2 秒。这让人看见"卡之间在通信"，而不是只看到一个未读数字。

**关键原则**：自动模式的活动是**时间性的**，所以视觉必须带时间轴（活动流），
不能只在卡片上挂个"运行中"的静态标记——那看不出"AI 在按什么顺序做事"。

## 10.3 这两条带来的优先级变更

| 序 | 事项 | 原优先级 | 新优先级 |
|---|---|---|---|
| 1 | 三栏布局（目录 / 画布 / 详情），单击不离开画布 | 未列 | **P0** |
| 2 | 自动模式活动指示（呼吸竖条 + 轮次 + 步骤） | 未列 | **P0** |
| 3 | 全局活动流（底部时间线） | 未列 | P1 |
| 4 | 多选后的批量操作 | P4 | P1 |
| 5 | 卡间消息流动虚线 | 未列 | P2 |
| 6 | 待裁定队列（可逐条过） | P2 | P2 |
