## 一、①-3 promote 版本闸 —— 已签，收窄口径

**签字语义**：「全员批准的那个版本，才配叫正稿。」

闸的触发面收窄为三条件**同时成立**，缺一不触发：

1. **只在收口瞬间判**：`promote_draft` 调用时比对，评审迭代中永不打扰；
2. **只对 stale 票**：`approve.draft_ver < 当前 draft_ver` 的席位补确认；pending 席位照常看新稿，不算骚扰；
3. **快速确认形态**：stale 席位只评增量（v5→v7 的条目级 diff，D 编号行可算），不重投全文。

与 10-29 裁定「通过的席位不再被叫」的关系：**不冲突**。原裁定防迭代期骚扰（评审在跑、稿在动时不把已表态者叫回来）；本闸只在收口时、且仅对「批过的版 ≠ 收口版」触发——补上当时未写明的隐含前提：收口版必须人人见过。

**反对并已否掉的备选**：「全员通过后冻结草稿」——堵不住投票途中的版本漂移（先批席位在全员投完前就可能已批在旧版上），不推荐。
