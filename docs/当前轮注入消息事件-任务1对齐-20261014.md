## 一、消息事件底座（工作区未提交改造线）真实结构

**落盘位置**：`works/{work_id}/events/{card_id}.jsonl`，一行一条 JSON，append-only
（`src/storage/event_log.py:61-67`）。

**外层七键定死**（`event_log.py:50` `RECORD_KEYS`）：

| 键 | 含义 | 取值来源 |
|---|---|---|
| `seq` | 单卡文件内单调，从文件尾 +1 续（重启不归零） | `_append_locked` 取号 |
| `card_id` | 卡 | 调用方 |
| `run_id` | **＝现有 pair_id**（一次请求一个） | `event_stream._anchors` 的 pair_id |
| `round` | **＝对话轮 turn**（≠ `message_runner.state.rounds` 工具续调次数） | `_anchors` 的 turn |
| `type` | 事件类型 | 调用方 |
| `data` | **结构化对象**（不是文本 blob） | 调用方 |
| `model` | 仅 reasoning 三席带；其余空串 | 调用方 |

- 软删：`revoke` 是控制类记录（`CONTROL_TYPES`），**不进 timeline 渲染面**（`event_log.py:53,308-331`）。
- fail-open：坏行/缺文件/解析失败只记 warning（`event_log.py:25-34`）。

**现有事件类型集合**（`src/api/event_stream.py:91-98` `EVENT_TYPES`，23 类）：

```
run_start, context, round_start, round_end, rescue,
tool_call, tool_result, seats_enter, seat_start, seat_end,
deliver, proposal, done, error, ping, card_op,
triage_verdict, plan_created, step_advanced, judgment, step_start
+ reasoning_chunk, content_chunk（逐字流）
```

**消息块映射**（`src/storage/session_facade.py:458-473`）：`human→user_message`、`assistant→assistant_text`、`card:*→msg_ask/msg_answer/msg_notify`；`actor=tool` 的环节留痕块**不落事件**。

**三条落盘通道**：
1. 过程事件：`event_stream.emit(...)` → `_persist_log` → `event_log.append_bg`（`event_stream.py:200-216,323-324`）
2. 思考增量：`emit_token(reasoning_chunk)` → 落 `type=reasoning`；`content_chunk` **不落盘**（`event_stream.py:439-444`）
3. 消息块：`session_facade.append(...)` → `_emit_block_event` → 落 `user_message/assistant_text`（`session_facade.py:476-497,594-595`）

**timeline 接口**：`GET /api/works/{w}/cards/{c}/timeline`（`src/api/routes.py:560-586`）＋兼容入口 `GET /api/card/{c}/timeline`（`routes.py:591-595`）→ `event_log.timeline` 合并表（按 seq 升序、跳过 revoke 段）。

**前端渲染**：`static/stream.js` 的 `renderEvent` 按 `switch(evt.type)` 分发（`stream.js:370-501`）；刷新/换卡重放走 timeline（`stream.js:562-600`，`workspace.js:131-134`）。

## 四、当前组装路径与实际链路生产点

主链路（`src/api/routes.py:976-1089` `_run_message_inner`）：

```
① session_facade.append(user 块)            → 落事件 user_message        (routes.py:1038-1042)
② event_stream.emit(run_start)              → 落事件 run_start           (routes.py:1046)
③ message_runner.build_context(state)       → 组装 system_prompt         (message_runner.py:203-258)
     └ context_assembler.build_context_regions → 100 / 150 / [160 否则 165] / 200  (context_assembler.py:57-127)
     └ 全部区都是 channel="system"，拼进 system_prompt (prompts.py:108-112)
④ while: message_runner.step(state)         → 每次模型调用                 (message_runner.py:338-632)
     ├ emit judgment / round_start / step_start / tool_call / tool_result /
     │   plan_created / step_advanced …（过程事件）
     └ model_service.call_main(system_prompt, user_prompt, prior_for_gateway, tools)
          └ gateway.stream_call → messages = [system] + prior_messages + [user_prompt]  (gateway.py:543-546)
⑤ message_runner.finish → session_facade.append(assistant) → 落事件 assistant_text  (message_runner.py:920-924)
```

**两处关键现状**：
- 160/165 现在是 **system 区文本**（`channel="system"`），不是消息事件；
- 当前用户原文经 `user_prompt` 作为**最后一条消息**进模型（`gateway.py:546` 无条件 `messages.append({"role":"user",...})`）。
